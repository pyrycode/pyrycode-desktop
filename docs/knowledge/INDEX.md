One-line summaries of the evergreen docs. The documentation phase appends here.

## Decisions

- [0001](decisions/0001-stack-electron-react-typescript.md) — Stack choice: Electron, React, TypeScript, Zustand, transport in the background process.
- [0002](decisions/0002-remote-head-over-relay-shared-wire.md) — Remote head over the relay, reusing the mobile wire contract.
- [0003](decisions/0003-m3-theme-tokens-css-custom-properties.md) — M3 theme values as CSS custom properties in a single `tokens.css` (dark-only, `system-ui` fallback).
- [0004](decisions/0004-renderer-session-store-reducer-wire-types.md) — Renderer session state: one Zustand store, a pure exported reducer, sealed action union, wire types reused verbatim.
- [0005](decisions/0005-secret-at-rest-safestorage-fail-closed.md) — Secrets at rest via Electron `safeStorage`, fail-closed (no plaintext fallback), over one key-domain-blind byte primitive with injected keychain/filesystem seams.
- [0006](decisions/0006-ephemeral-screen-state-usereducer-not-store.md) — Ephemeral, screen-local state uses `useReducer` + a pure reducer (resets on remount), not the module-singleton store of 0004; the store shape is reserved for app-wide shared state.
- [0007](decisions/0007-content-free-diagnostics-by-construction.md) — Content-free diagnostics by construction: the logger accepts only a typed allowlist of *envelope* fields (event, code, status, bytes, count, host, path, the additive `hash?` a decode boundary uses — #130, the additive **branded** `safeBytes?` a pre-decryption failure boundary uses — #133, and the additive plain-string `appVersion?`/`noiseProtocol?`/`protocolVersion?` a once-per-session startup banner uses — #132), enforced by the type system at every call site — never a runtime scrubber (a denylist that fails open). Grounds Bucket 1 (#126) + the #125/#127/#128/#130/#132/#133 family; #131 extends the same fail-closed allowlist to the untrusted renderer→main IPC boundary (its pin relaxes to `Omit<DiagnosticEvent,'safeBytes'>` after #133's branded field, then extends again for #132's three main-only version fields — proof the `Omit` escape hatch isn't only for branded types); #134 is the first renderer-**state** producer through that boundary, fitting entirely inside the existing `event`/`code`/`count` fields with no allowlist growth. #132 is the last of the five #125 Bucket-1 splits to ship.
- [0008](decisions/0008-thread-timeline-model.md) — Conversation-timeline model: a heterogeneous `ThreadItem` union (`assistantText`/`toolCall`/`turnBoundary`/`userText`) + pure `reduceTimeline` reducer, introduced alongside `sessionStore`'s `MessagePayload[]` (Strangler Fig). Tail-check delta coalescing per turn; a `toolResult` merges into its `toolCall` by `toolUseId`, orphan/duplicate → same-reference no-op; `turn_state` is a scalar `phase` beside `items`, not a timeline row. Foundation for #199 (transport, shipped), #202 (store + bridge, shipped), #203 (render, shipped), #214 (`turn_state` transport, shipped), #217 (`tool_use` transport, shipped), #218 (`toolCall` pending render, shipped), #229 (`tool_result` transport, shipped), #230 (resolved-row render, shipped), and [#179](codebase/179.md) (shipped — the `interactive` flip + the Strangler-Fig cutover). [#245](codebase/245.md) added the fourth member, `userText`, dormant with a placeholder render arm; [#179](codebase/179.md) wired its producer (the composer echo, retargeted from `sessionStore` to `timelineStore`) and its real render row, and in the same commit retired the coarse `MessageThread` — `Timeline` is now the conversation's single thread surface, with `MessageThread`/`MessageBubble`/`selectMessages` kept as dead-but-tested residue. The vertical is complete. [#286](codebase/286.md) added a fifth member, `sessionBoundary` — the `/clear`/idle-eviction/workspace-change delimiter (transport widened by the split-sibling [#285](codebase/285.md)) — wired live end to end (bridge arm + `TimelineRow` render row + a new long-form-relative-time `sessionBoundaryViewModel.ts`) in one ticket, the fifth application of the "new timeline-item kind → bridge arm → render row" pattern. [#317](codebase/317.md) extended the model with a second scalar beside `phase` — `stalled: boolean`, set by a new nullary `stallDetected` arm and self-cleared by the four turn-activity arms (`assistantDelta`/`toolUse`/`toolResult`/`turnState`), carried through unchanged by the three non-activity arms — the `phase`-beside-`items` precedent generalized to a second onset-only scalar. [#493](codebase/493.md) extended the model with a third scalar, `apiRetry: ApiRetryStatus | null` (a record, not a flag, set by a data-carrying `apiRetry` arm) — the deliberate **inverse** of `stalled`'s clearing rule: the four turn-activity arms carry it through unchanged instead of clearing it, since the wire's `api_retry` frame has an explicit falling edge rather than requiring a client-side self-clear.
- [0009](decisions/0009-modal-prompt-model.md) — Modal-prompt model: an id-addressed ordered `ModalPrompt[]` + pure `reduceModal` reducer, introduced alongside `sessionStore`/`threadTimeline` (Strangler Fig, nothing cut over). `shown` is idempotent on `modalId` ([#195](codebase/195.md), shipped: replace-in-place if outstanding, no-op if already `resolved`, append if never seen); `dismissed` removes by `modalId` and records it `resolved` on a genuine removal, unknown/already-dismissed id → same-reference no-op, untouched-`resolved` ordering-edge guard. `class` is `permission | trust` only — no `destructive` wire class. The modal analog of 0008; foundation for the peeled wire/transport/render/answer follow-up. Reconnect-reconcile #196 split 2-way: [#415](codebase/415.md) (shipped) adds a `reconnected` `ModalEvent` arm clearing `outstanding` on every supervisor (re)handshake while preserving `resolved`/`rejections` by reference, letting the daemon's connect-time re-sends repopulate through the existing idempotent `shown` arm; sibling [#197](codebase/197.md) (shipped) applies the same reset contract to the separate [queue store](features/queue-store.md)'s `backlogs` map, via a `resetBacklogs` setter + a `connected`-edge branch in `subscribeQueue` rather than a translator arm, since the queue bridge has no event union to extend. **[#510](codebase/510.md) (shipped, security-sensitive) deliberately reverses #415's `resolved`-preservation**: an answer clicked while disconnected is dispatched optimistically but the send is swallowed by the transport, so the retained `resolved` id suppressed the daemon's genuine re-delivery and let an explicit Allow silently decay into a deny-on-timeout. The daemon's reconcile re-sends only still-outstanding modals, so retaining `resolved` across the reset guarded nothing; the `reconnected` arm now clears both `outstanding` and `resolved`, each behind its own no-change guard, and `resolved` is per-connection memory rather than permanent. The transport slice ([#201](codebase/201.md), shipped) wired the wire types + fail-closed decode + `DaemonEvent` arms this model's `ModalEvent` targets — both existing renderer bridges discard the arms as `null`; the [modal store + bridge](features/modal-store-bridge.md) that actually consumes them shipped in [#223](codebase/223.md).
