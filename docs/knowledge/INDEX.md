# Knowledge Base Index

One-line summaries of the evergreen docs. The documentation phase appends here.

## Decisions

- [0001](decisions/0001-stack-electron-react-typescript.md) — Stack choice: Electron, React, TypeScript, Zustand, transport in the background process.
- [0002](decisions/0002-remote-head-over-relay-shared-wire.md) — Remote head over the relay, reusing the mobile wire contract.
- [0003](decisions/0003-m3-theme-tokens-css-custom-properties.md) — M3 theme values as CSS custom properties in a single `tokens.css` (dark-only, `system-ui` fallback).
- [0004](decisions/0004-renderer-session-store-reducer-wire-types.md) — Renderer session state: one Zustand store, a pure exported reducer, sealed action union, wire types reused verbatim.
- [0005](decisions/0005-secret-at-rest-safestorage-fail-closed.md) — Secrets at rest via Electron `safeStorage`, fail-closed (no plaintext fallback), over one key-domain-blind byte primitive with injected keychain/filesystem seams.
- [0006](decisions/0006-ephemeral-screen-state-usereducer-not-store.md) — Ephemeral, screen-local state uses `useReducer` + a pure reducer (resets on remount), not the module-singleton store of 0004; the store shape is reserved for app-wide shared state.

## Features

- [Conversation shell](features/conversation-shell.md) — the renderer's first screen: a scrollable message thread above a bottom-pinned composer, mirrored from the mobile Conversation Thread design (#1). The thread now renders the live session store — streamed daemon replies appear as they arrive, adapted from wire `MessagePayload` at the store-read boundary via `toMessageViewModel` (#69); the composer is now wired to send with an optimistic echo (#66, see below).
- [Session store](features/session-store.md) — the renderer's single source of truth for the active session's connection status + conversation messages, mutated through a sealed action union; the state seam #3/#19 dispatches into and the conversation thread reads (#2, read side bound in #69).
- [Daemon-event channel](features/daemon-event-channel.md) — the typed background→window event pipe: a sealed `DaemonEvent` union in `src/shared/ipc/`, the single `emitDaemonEvent` send path, and a receive-only `onDaemonEvent` subscription on `window.pyry` (#18).
- [Command channel](features/command-channel.md) — the mirror-image window→background command pipe: a sealed `RendererCommand` union + pure `sendMessageCommand` + `isRendererCommand` boundary guard in `src/shared/ipc/`, a typed `sendCommand` on `window.pyry`, and an `onCommand` receiver seam that validates each command at the untrusted renderer→main boundary (#17).
- [Daemon-event bridge (renderer)](features/daemon-event-bridge.md) — the renderer translation half: pure `translateDaemonEvent` maps each `DaemonEvent` to a `SessionAction`, and the `useDaemonEventBridge` hook pipes `onDaemonEvent → translate → dispatch` into the app-singleton store, unsubscribing cleanly on teardown (#19).
- [Relay connection](features/relay-connection.md) — the background-process connection primitive: `createRelayConnection` opens one `wss://` socket with caller-supplied headers, a 30s/30s heartbeat, a 1 MiB frame cap, carrying raw frames both ways as opaque bytes and funnelling every failure into one terminal `closed` event; semantics-blind, log-free, no reconnect (that's #22). Adds `ws`, the project's first network dependency (#21).
- [Relay supervisor](features/relay-supervisor.md) — the resilience layer over #21: `createRelaySupervisor` wraps `createRelayConnection` by injection so the layers above see a connection that heals itself — re-dials after a retryable close with capped exponential backoff + ±20% jitter (1s→30s), resets the backoff after ≥60s continuously up, treats a fatal close code (`{4401,4421,4426}`, injected) as terminal to block a reconnect-storm DoS, tears down with no dangling timers, and forwards inbound frames byte-for-byte. Main-process only, log-free, no new dependency (#22). Now takes an optional per-dial `resolveConnection` provider: `dial()` is async and every *automatic* re-dial re-sources the connection from it (a null record fails closed with the synthetic `NO_PAIRED_RECORD_CLOSE_CODE = 4000`), fenced against a racing `stop()` by a post-`await` check; the first dial stays on the construction-time snapshot (reload-per-dial, #83).
- [Secure store](features/secure-store.md) — the background-process secret-at-rest primitive: a key-domain-blind `createSecureStore` (`set`/`get`/`delete` over named `Uint8Array` blobs) that encrypts at rest with Electron `safeStorage` (OS keychain), fails closed when the keychain is unavailable (incl. the Linux `basic_text` obfuscation backend) so plaintext never hits disk, and ships its keychain + filesystem edges as injected seams (real adapters: `electronSecretEncryption` base64-bridged over `safeStorage`, `fileSecretPersistence` traversal-safe + atomic). Main-process only, log-free, no new dependency; the foundation #43/#44 consume (#42). The injected `encryption` seam is now chosen at the composition root by `selectSecretEncryption` — the real keychain backend on every path except a non-packaged, opt-in dev path that swaps in a keychain-free backend so `set` stops failing closed headless (#99, see below).
- [Device static keypair](features/device-keypair.md) — the desktop client's stable Noise_IK identity: a device static X25519 keypair generated once and persisted through #42's secure store, so every launch reads the same pair without the private key ever leaving the store or reaching the renderer. `createDeviceKeypairStore` is a pure core over two injected seams (`SecureStore` type-only + a `KeyPairGenerator`, real impl `noiseKeyPairGenerator` over `noise-c.wasm` `CreateKeyPair(NOISE_DH_CURVE25519)`); `ensure()` is generate-once (memoized promise + persisted 64-byte `priv‖pub` blob as source of truth), fail-loud on corruption (never silently regenerates), and log-free. Main-process only, no new dependency; the first consumer of #42, feeding the eventual Noise_IK handshake (#43).
- [Paired-server store](features/paired-server-store.md) — the persisted pairing record: the `{server, relay, token, server_static_pubkey}` QR/paste tuple serialized to one opaque JSON blob and stored through #42's secure store, so the client reconnects and drives the Noise_IK handshake each launch without re-pairing. `createPairedServerStore` is a pure core over one injected `SecureStore` seam (serialization is pure — no second adapter); `save` overwrites (re-pair), fail-closed on keychain-unavailable; `load` returns `null` only on genuine absence — a decrypt failure propagates and a present-but-malformed blob throws `MalformedPairedServerRecordError`, so a tampered record is never silently mistaken for never-paired. `PairedServerRecord` aliases `QrPayload` (wire drift is a type error). Main-process only, log-free, no new dependency; the second consumer of #42 (#44).
- [Wire codec](features/wire-codec.md) — the transport's serialization layer in `src/main/transport/codec.ts`: pure `encode/decodeInnerFrame` + `encode/decodeEnvelope` + strict `base64Std*` + the one default-injecting `makeHelloClientPayload`, producing bytes byte-identical to pyrycode-mobile. Encode is total; the `decode*` functions fail closed with a category-only `WireDecodeError`; `Envelope.payload` stays opaque (`unknown`). Main-process only (structural renderer isolation); tightens `types.ts` optionals to `number | undefined` (never `null`) (#5).
- [Noise session](features/noise-session.md) — the production `Noise_IK_25519_ChaChaPoly_BLAKE2s` session in `src/main/transport/`: `createNoiseSession` performs the IK handshake (injected `hello` on msg 1, `hello_ack` from msg 2) then AEAD-encrypts/decrypts transport frames, fail-closed, over the vetted `noise-c.wasm`. A pure crypto unit — keys injected (raw 32-byte X25519), `hello`/`helloAck` opaque, `NOISE_PROTOCOL` reused verbatim; mirrors the relay-connection `sendFrame`/`onEvent` contract. Promotes the #29/#30-proven harness by `git mv` + rename and adds `noiseLib.ts`, a single hardened wasm loader (bounded `NoiseLoadError` timeout/classify instead of an async-load hang) shared with the device-keypair generator. Log-free, no use-after-close, main-process only; not yet wired to the relay (sibling ticket) (#7).
- [Noise relay driver](features/noise-relay-driver.md) — the composition adapter in `src/main/transport/` that drives the #7 Noise session over the #22 supervisor: `createNoiseRelayDriver` starts a **fresh** handshake on every `(re)connect` (v2 has no session resume), composes the #5 codec between the supervisor's opaque frames and the session's Noise bytes (outbound tagged `noise_init`/`noise_msg`, inbound decoded fail-closed and never `type`-branched), and surfaces `handshake-complete`/`message`/`terminal`/`error` through one typed sink to the background-process consumer above. A `generation` counter fences the async `createSession` against synchronous supervisor events so a stale session can never install or send under a superseded key (the security-load-bearing nonce-freshness guard); the pending buffer is bounded at `MAX_PENDING_FRAMES = 8`. No new crypto — three proven primitives consumed unchanged; keys/`hello` injected from above (#42/#43/#10); main-process only, log-free, no renderer/IPC reach; not yet wired to the renderer (#17/#18/#19) (#50). Now exports `SessionMaterial`/`DialConfig`/`DialConfigProvider` and takes an optional `loadDialConfig`: a `resolveConnection` wrapper is the single per-dial `load()` that feeds the supervisor's connection AND stashes the next `onConnected`'s session from the same record snapshot (so headers and key never split on a mid-session re-pair), catches a thrown reload → returns null (fail closed), and gates the first connect onto `config.session` (reload-per-dial, #83).
- [Pairing-payload gate](features/pairing-payload-gate.md) — the paste-only pairing input gate: a pure, synchronous, log-free `parsePairingPayload` in `src/main/` that parses the daemon's `base64url(JSON)` four-field tuple into a `QrPayload` (imported, not re-declared) with a bounded 8-category typed rejection taxonomy, and validates the `relay` URL (`wss:` only, exact-host match against a single-sourced main-process `RELAY_ALLOWLIST`, no embedded userinfo) — the only place the relay is checked before the transport dials it verbatim. Returns a discriminated `ok`/`reason` result (never throws, never leaks a field value); `server_static_pubkey`/`server`-id kept opaque (the fingerprint visual-verify in #53 is the load-bearing key check). No persistence/crypto/IPC/UI; validated output consumed by #53 (#52). The relay's scheme+host decision is now an injectable `RelayPolicy` (default = production strictness), the seam #97's loopback affordance swaps on the dev path (below).
- [Pairing-confirmation gate](features/pairing-confirmation.md) — the desktop's fingerprint-confirm gate in `src/main/`: `createPairingConfirmation({ store })` whose `prepare(record)` derives a short, human-comparable BLAKE2s-256 fingerprint of a validated record's `server_static_pubkey` (first 8 bytes, colon-separated lowercase hex — byte-identical to the daemon's `internal/pair.Fingerprint`, pinned vector `32:0b:5e:a9:9e:65:3b:c2`) and returns the **one** persist handle bound to exactly that record. Persist is confirm-gated structurally: exactly one `store.save` call site, inside the `confirm` closure, unreachable without `prepare` and **absent** on a malformed-key `ok:false` arm (so a bad key is unpersistable). Strict canonical-standard-base64 guard (re-encode-and-compare) is the first place `server_static_pubkey`'s shape is checked; a frozen snapshot closes the derive→confirm TOCTOU; catches nothing from the injected [paired-server store](features/paired-server-store.md)'s `save` (fail-closed propagates). Pure core, log-free; the human-verify step mobile's paste path skipped (#501). Only the fingerprint (a hash) is safe to surface — that's #54 (#53). The digest now comes from pure-JS `@noble/hashes` `blake2s`, **not** `node:crypto` `createHash('blake2s256')` — which throws `Digest method not supported` under Electron's BoringSSL (no BLAKE2 family), wedging the built app's pairing screen forever in `submitting`; the swap is byte-identical and synchronous, adds a value-free `fingerprint-unavailable` reject reason (collapsed to `invalid-key` at the handler, no new shared reason), and ships a `check:electron-digest` runtime gate vitest structurally can't cover (#101).
- [Pairing IPC channel](features/pairing-ipc-channel.md) — the typed **request/response** pairing pipe (renderer ↔ main), the request/response twin of the fire-and-forget [command](features/command-channel.md)/[event](features/daemon-event-channel.md) channels: `submitPairingPaste(paste)` → display fingerprint or a value-free typed error, then a bare `confirmPairing()` → success/failure — over `ipcRenderer.invoke`/`ipcMain.handle`. `src/shared/ipc/pairing.ts` ships the sealed `PairingRequest` union, the value-free response vocabulary, and `isPairingRequest` (the untrusted-boundary guard, rejecting non-string **and** over-length pastes before parse runs); `src/main/pairingHandler.ts` composes [#52 parse](features/pairing-payload-gate.md) + [#53 fingerprint/confirm](features/pairing-confirmation.md) behind a single handler holding ≤1 prepared pairing (supersede-on-submit + consume-before-await make "persists exactly once" and "no superseded record" structural); `src/main/index.ts` is the composition root that first constructs the real secure-store chain and registers the handler once. "Only the fingerprint or a value-free reason crosses back" (ADR 0002) is enforced by construction — no response arm has a field that could hold the token or server key (#54).
- [Pairing input screen](features/pairing-input-screen.md) — the desktop's paste-only pairing screen (renderer, `src/renderer/src/screens/pairing/`): paste the `pyry pair --print` payload, review the server-key fingerprint, and explicitly confirm — or cancel, discarding the paste. Styled from Figma node `19-54` plus the desktop-specific fingerprint-verify step (#53). A pure, React-free phase machine + IPC effect-runners + `groupFingerprint` formatter (`pairingState.ts`), a pure `PairingView`, and a thin `useReducer`-based `PairingScreen` container that drives the existing #54 preload methods through an injected `PairingBridge`. No secret reaches the renderer (the #54 response arms carry only the fingerprint + value-free reason); the paste is transient/single-use; async is handler-driven (no `useEffect`); ephemeral state resets on remount (`useReducer`, ADR 0006). Mounting/navigation is a later slice (`onPaired`/`onCancel` seams). Adds 3 M3 tokens to `tokens.css` (#55).
- [Hello exchange](features/hello-exchange.md) — the application-handshake envelope layer in `src/main/transport/helloExchange.ts`: two pure functions on top of the [wire codec](features/wire-codec.md) that fill in the opaque `hello`/`helloAck` bytes the [Noise session](features/noise-session.md) and [relay driver](features/noise-relay-driver.md) carry but defer. `buildClientHello` wraps a defaults-injected `HelloClientPayload` (via `makeHelloClientPayload`, never hand-rolled) in a `hello` envelope → UTF-8 early-data bytes, with `id`/`ts` as inputs so it's deterministic; `parseHelloAck` narrows daemon `hello_ack` bytes into a validated, typed `HelloAckPayload`, failing closed via the codec's `WireDecodeError` (never a partial value). `capabilities` is an optional build input (never hardcoded `interactive`) and optional-with-default-`[]` on parse (the daemon marshals it `omitempty`) — treating it as required would silently break a real ack. Category-only errors, zero `console.*`; main-process only, no production caller on merge (the driver wiring is #62) (#10).
- [Daemon connection](features/daemon-connection.md) — the background-process transport consumer in `src/main/daemonConnection.ts` that the [Noise relay driver](features/noise-relay-driver.md) was built for: the first end-to-end path. `createDaemonConnection({deviceKeypair, pairedServer, sink, deviceName, clientVersion})` sources the device static key (#43 `ensure()`), the paired-server record (#44 `load()`), and the `hello` early-data (#10 `buildClientHello`), constructs and drives the driver, and maps its four lifecycle events onto the typed [daemon-event channel](features/daemon-event-channel.md) through one `onDriverEvent` choke point: `handshake-complete` → `connected{ack}` (via `parseHelloAck`), `terminal`/`error` → `failed{static code}`, plus a synchronous `connecting` at connect start. Every failure (no record / malformed record / bad-or-wrong-length server key / rejected keychain / malformed ack) fails closed to a non-connected event — never a crash; the clean `stop()` path emits nothing, and a single `stopped` flag both closes the start/stop race and suppresses the clean-stop terminal. Composition/wiring layer *above* transport (imports the driver **and** the IPC layer, so it lives at top-level `src/main/`, not IPC-free `transport/`); log-free, classify-don't-forward, no secret crosses to the renderer. Wired at the composition root (reuse paired-server store, add device-keypair store, start on `did-finish-load`, stop on `will-quit`) (#62). Now also exposes `reconnect()` — a generation-fenced re-arm of the once-only lifecycle that tears down any live driver and dials fresh, re-sourcing the paired-server record at dial time; the [pairing handler](features/pairing-ipc-channel.md)'s new `onPaired` trigger wires a confirm-success to it so a mid-session pairing connects with no restart (connect-on-pair, mirrors mobile #489; #82). Also constructs the per-dial `loadDialConfig` provider (the extracted record-load + derive) and injects it into the driver, so the supervisor's own *automatic* transient-drop reconnect re-sources the record too — for both the connection headers and the Noise session material — with no stale pre-pairing view surviving in memory (reload-per-dial, mirrors mobile #489; #83).
- [E2E test harness](features/e2e-harness.md) — the Playwright `_electron` harness that launches the **built** app from `out/main/index.js` and drives its renderer window, so later UI scenarios (pairing, send, stream) can assert against the real assembled app. A scenario-agnostic launch/teardown fixture (`e2e/fixtures/electronApp.ts`, `test.extend` → `electronApp` + `page`) that scenarios import, plus one smoke assertion that the [conversation shell](features/conversation-shell.md) mounts (`.conversation` visible). Teardown rides the runner's fixture lifecycle (fires on pass *and* fail — no orphaned Electron process, no manual `afterEach`); `args: ['.']` resolves the built entrypoint via `package.json` `main`; the fixture strips a stray `ELECTRON_RENDERER_URL` so the child always loads the built renderer. `npm run e2e` = `build && playwright test`; two-way separate from the vitest unit run (`testDir: './e2e'` ↔ vitest `include: ['src/**']`). Scaffolding only — UI scenarios are follow-ups (#40).
- [Inbound message decode](features/inbound-message-decode.md) — the untrusted→trusted boundary for a decrypted daemon message: `parseInboundMessage` in `src/main/transport/inboundMessage.ts` turns the relay driver's opaque `message{plaintext}` bytes into a narrowed `messageReceived` / `messagesReceived` `DaemonEvent`, or fails closed. Size guard (`MAX_PLAINTEXT_BYTES`) + `decodeEnvelope` + route by wire `type` + per-field payload narrowing (each of `conversation_id`/`message_id`/`text` a string, `role` exactly `user`/`assistant`, `messages` an array whose every element narrows — one bad element fails the whole chunk); a single `WireDecodeError` covers oversized/malformed/unparseable/mistyped so the consumer's one `catch` drops the frame. Sibling to `helloExchange.ts` / `sendMessageEnvelope.ts`; IPC-free (the [daemon connection](features/daemon-connection.md) `case 'message'` arm does the IPC map); category-only errors, log-free, no dedupe/reorder (that's the store, ADR 0004). Fills the last no-op arm #62 left; feeds the already-complete #18→#19→#2 renderer pipeline (render-binding is #69) (#68).
- [Composer send](features/composer-send.md) — the **renderer half of the send flow** (twin to the outbound send path): the previously-inert conversation composer, now wired. A controlled `<textarea>` + a submit (send button or Enter) that, via the pure React-free `submitMessage` in `composerSend.ts`, mints a `message_id`, emits `sendMessage` over `window.pyry.sendCommand` (guarded — a bridge failure never crashes the window), and appends an optimistic wire `MessagePayload { role: 'user' }` echo to the session store through a new `messageSent` action. The one minted id is reused for both the wire payload and the echo, so the store's `appendUnique` drops the daemon's later same-id echo instead of double-posting (AC3). Ephemeral input in component `useState` (ADR 0006); single milestone conversation via a `MILESTONE_CONVERSATION_ID` constant (#66). The send control is now gated on the live connection status: while `selectStatus` is not `connected` the button is disabled, the Enter path is inert, and a `role="status"` caption names why (`Connecting…`/`Not connected`/`Connection error`) — a pure `composerAvailability(status)` predicate over `ConnectionStatus`'s four arms; a UX affordance over #65+#66's already-safe path, re-enabling reactively on connect (#31).
- [Outbound send path](features/outbound-send-path.md) — the main/transport half of the send flow: a validated `sendMessage` command reaching `onCommand` becomes an encrypted `send_message` envelope on the live Noise relay session. Three pieces — a pure `buildSendMessage` builder (`src/main/transport/sendMessageEnvelope.ts`, sibling to `buildClientHello`, minus default injection), a `send(payload)` entry point on `createDaemonConnection` (id counter continuing from 2 after the hello's id 1; a single `driver === null` guard + a full-body `try/catch` make it an inert no-op when disconnected/pre-handshake/post-terminal and never a throw — parity mobile #490), and the single `onCommand` registration at the composition root routing `sendMessage` → `connection.send`, unsubscribed on `will-quit`. Closes #17's deferred single-registration item; entirely `src/main/`; log-free, classify-don't-forward, no new dependency. The renderer half (composer submit + optimistic echo) is #66 (#65).
- [Pairing-status signal](features/pairing-status-signal.md) — the launch-time "does a stored pairing exist?" answer, served renderer←main over a new request/response channel (`pyry:pairing-status`, `invoke`/`handle`) so the app shell can pick a screen before first paint (#80) instead of inferring pairing state from `daemonConnection`'s late, error-shaped `failed{ code: 'not-paired' }`. A stateless, body-free sibling of the [pairing IPC channel](features/pairing-ipc-channel.md): a channel constant + a sealed three-outcome `PairingStatus` union (`paired` / `not-paired` / `error`, no runtime logic, no request guard — the `events.ts` shape) in `src/shared/ipc/`; a stateless main handler over the already-constructed `pairedServerStore` where `null` is the *only* not-paired path and *every* throw (malformed record OR propagated decrypt failure) is `error` via one type-blind `catch` — never collapsed into not-paired (ADR 0005); a zero-argument preload wrapper. Value-free by construction (no arm carries a field), classify-don't-forward, log-free; pulled (not pushed) so it can't race the connect sequence. Renderer routing that consumes it is #80 (#79).
- [App shell (router)](features/app-shell.md) — the renderer root turned router: `App` consumes the launch-time [pairing-status signal](features/pairing-status-signal.md) (#79) to pick the initial screen and the [pairing screen](features/pairing-input-screen.md)'s `onPaired` seam (#55) to advance in-session, assembling the built screens into the runnable whole the end-to-end milestone (#13) waits on. Three parts (the composerSend/PairingView split): a pure `routeForStatus` where the **fail-safe ternary** structurally guarantees only a genuine `paired` reaches the [conversation screen](features/conversation-shell.md) — `not-paired`, `error`, and a rejected invoke all route to pairing (AC2, ADR 0005, never masking `error` as never-paired); a pure `AppView` route→screen view with an `assertNever`-guarded switch; and the `App` container owning the route `useState` (ephemeral, ADR 0006), the one-shot cancellable launch effect, and `onPaired`→conversation (no restart). The `pending` phase renders `null` so first paint is the neutral dark canvas, never the wrong screen (AC3); `onCancel` is deliberately unwired (cancel stays put — AC5); `useDaemonEventBridge` stays app-level, above the branch. Renderer-only, no main-process code, no new dependency (#80).
- [Live e2e runbook](features/live-e2e-runbook.md) — the **manual operator gate** for the Phase-1 milestone: the full **pair → connect → send → stream** round-trip against the **live** relay + the **real** `pyry` daemon on pyrybox, run only on an operator machine, never under CI. The manual sibling of the automated fake-transport [e2e harness](features/e2e-harness.md) (#40) and the desktop equivalent of mobile's live-e2e runbook (ADR 0002 shared wire). Covers the load-bearing single-host relay-allowlist prerequisite, the numbered build→pair→confirm flow, the `connected`/send/stream UI observables (composer enable + `data-message-role` bubbles), recording the outcome on the ticket, and known limitations. No production code — the deliverable is the runbook; the three ACs are operator actions on the live stack that unblock the Phase-2 hardening + automated-test batch (#35–#41) (#13).
- [Fake relay forwarder](features/fake-relay-forwarder.md) — the **test-only** plumbing half of the round-trip harness: `startFakeRelayForwarder` stands up one in-process `ws` relay on an ephemeral loopback port and splices raw frames **byte-for-byte, opcode-preserving, content-blind** between a `/v1/client` leg (the real client under test) and a `/v1/server` leg (the #91 fake daemon). Generalises the records-only `startRelay` inlined in `relayConnection.test.ts` into an importable two-leg splice (a plain `.ts`, so #91/#89 can import it). Legs routed by upgrade **path** (never frame bytes — content-blindness enforced by the import list: only `ws`); a positive `whenReady` gate closes the 101-before-registration race (the Go `WaitBinary` analog); `close()` is idempotent. No production consumer yet, no new dependency, log-free; runs unconditionally under `npm test` (no Go toolchain, no network) (#90).
- [Loopback relay dev affordance](features/loopback-relay-affordance.md) — a deterministic, **test/dev-only** affordance that lets the built app's main process accept and dial a loopback `ws://127.0.0.1` relay (so the [#90 fake relay forwarder](features/fake-relay-forwarder.md) can stand in for the live `wss://` relay in automated scenarios), while a **packaged build stays byte-identical to today**. The scheme+host decision is an injectable `RelayPolicy` on `parsePairingPayload` (default = production strictness); the dev relaxation + the `isPackaged`-**false-first** `selectRelayPolicy` selector are quarantined in a new `src/main/relayPolicy.ts`; `index.ts` makes the single effectful `app.isPackaged`+`process.env` choice at the composition root. Bounded on three independent axes, all required at once: `!isPackaged` AND `PYRY_ALLOW_LOOPBACK_RELAY=1` AND scheme `ws:`+host exactly `127.0.0.1` (any port; IPv4-canonical forms accepted, `localhost`/`[::1]` rejected). `relay-not-url`/`relay-has-credentials` stay in `parsePairingPayload` and apply on both paths; all eight typed reject reasons preserved; `relayConnection.ts`/renderer/preload/wire untouched. The security-sensitive seam #93 consumes but must not own (#97).
- [Fake daemon](features/fake-daemon.md) — the **test-only, content-aware** responder half of the round-trip harness (the deliberate inverse of #90's content-blindness): `startFakeDaemon` speaks the responder side of `Noise_IK_25519_ChaChaPoly_BLAKE2s` in-process — reads IK msg1 (recovering the client static + `hello`), writes msg2 carrying `hello_ack`, `Split()`s into transport ciphers, then decrypts inbound frames and streams sealed replies while keeping the session open. Dials the #90 forwarder's `/v1/server` leg; uses the exact `NOISE_PROTOCOL` + the production `codec` (`encode/decodeEnvelope`, `encode/decodeInnerFrame`, `base64Std*`) — no hand-rolled shortcut (a lax fake gives false confidence).
