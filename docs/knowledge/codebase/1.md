## Patterns established

These are the conventions later renderer tickets should follow:

- **Theme tokens are the single source of visual values.** Component stylesheets reference `var(--…)` only; no color/type/spacing/radius literal in a component CSS file. Off-grid design values still get a named token (e.g. `--space-bubble-x: 14px`). Bare structural geometry (`100%`, flex ratios, the `48px` send square) is layout, not theme, and stays literal.
- **`import './tokens.css'` before component styles.** `index.css` imports the token sheet first so `var(--…)` resolves everywhere.
- **Sole-data-source arrays with a `type`-discriminated union.** `placeholderMessages` is the one place data enters the tree; the union on `type` follows the project's sealed-event convention and is forward-compatible with #12's richer message kinds. Swapping placeholder → store data is meant to be one line.
- **In-file sub-components until they gain behavior.** `MessageThread`/`MessageBubble`/`Composer` live inside `ConversationScreen.tsx` while static. Extract to their own files when a component gains state (#2: `Composer` + input/send) or a store binding (#12: `MessageThread`). The stable contract is the props/types, not the file boundary.
- **Test hook via `data-*` attribute.** `data-message-role={type}` on each bubble is what the render test counts and asserts — a stable, semantics-free hook that survives styling changes.
- **`renderToStaticMarkup` for static structure; no DOM harness yet.** `ConversationScreen.test.tsx` renders to a markup string via `react-dom/server` (already available) and asserts on substrings/counts. This deliberately defers `jsdom` + Testing Library to #2, the first ticket with real input/click behavior. Keep explicit `import { describe, it, expect } from 'vitest'` (no `globals: true`), matching the existing wire-types test idiom.
- **`vitest.config.ts` mirrors `electron.vite.config.ts` aliases.** TSX tests won't resolve `@renderer`/`@shared` imports otherwise; the react plugin supplies the automatic JSX runtime so components need no `import React`.

## Lessons learned

- **`min-height: 0` is the flexbox footgun for independent scroll.** A `flex: 1 1 auto` scroll region refuses to shrink below its content's height unless it also gets `min-height: 0`; without it the whole window scrolls instead of the thread region. This is the single rule the AC1/AC5 scroll behavior rests on. Its sibling is `.composer__input`'s `min-width: 0`, which lets the input shrink below its content width on narrow windows.
- **`border-radius` shorthand is TL TR BR BL** — worth stating explicitly, since the two bubble variants clip *opposite* bottom corners (user → bottom-right, daemon → bottom-left) and it's easy to transpose.
- **Three deliberate divergences from the mock**, because desktop stretches a phone design and the ticket forbids fixed pixel widths: bubbles use `max-width: min(680px, 75%)` instead of the mock's fixed `330px`; the mock's `44px` outer screen radius is a phone-frame artifact and is dropped; and the mock's upper-message `opacity: 0.5` presentation fade is not reproduced (all bubbles render at full opacity). These are spec'd divergences, not fidelity gaps — noting them so a future fidelity review doesn't "fix" them back.
- **Foundation ported ahead of consumers.** Several tokens (`tertiary`, `success`, `outline*`, `title-large`/`body-small`/`label-small`, `--font-mono`) and the app bar / status row / tool chips have no consumer this ticket — they're intentionally deferred to #2/#12. The Figma node is only partially realized on purpose.
