# #10 — Hello and hello-ack exchange

**Shipped:** 2026-07-04 · **Size:** S · **Scope:** background transport only (`src/main/transport/`) · greenfield leaf module, **no production caller on merge**, zero consumer cascade · **no new dependency**.
**Spec:** `docs/specs/architecture/10-hello-and-hello-ack-exchange.md` · **PR:** [#63](https://github.com/pyrycode/pyrycode-desktop/pull/63).

The **application-handshake envelope layer**: two pure functions that sit on top of the [#5 wire codec](5.md) and fill in the opaque `hello`/`helloAck` `Uint8Array`s the [#7 Noise session](7.md) and [#50 relay driver](50.md) carry but explicitly defer — *"building them is #10's job."* `buildClientHello` turns device identity + stored token into the client `hello` early-data bytes; `parseHelloAck` narrows the daemon's `hello_ack` early-data bytes into a validated, typed `HelloAckPayload`, failing closed via the codec's `WireDecodeError`. See the [hello-exchange feature doc](../features/hello-exchange.md) for the full contract, fail-closed ladder, data flow, and security properties.

Split from the original #10 into **#10 (this — the exchange module)** + **[#62](https://github.com/pyrycode/pyrycode-desktop/issues/62) (the driver-wiring consumer, blocked by this)**. Auto-connect-on-pairing and per-dial record reload are the later mobile-parity refinement [#34](https://github.com/pyrycode/pyrycode-desktop/issues/34).

## Reconciliation — the ticket body was stale on two points

The ticket body was written against an **earlier draft** of the #5 codec; the architect's spec flagged two contradictions and the implementation follows the spec, not the stale AC wording. Both are intentional deviations, documented here so the record is clear:

1. **`interactive` capability.** The AC said the payload carries "the `interactive` capability" and that `makeHelloClientPayload` injects `capabilities:['interactive']`. **It does not** — since [#27](https://github.com/pyrycode/pyrycode-desktop/issues/27) hardened the codec, `capabilities` is a caller argument defaulting to `[]` (`codec.ts:157-174`), and `codec.test.ts` actively pins `capabilities:[]` / `not.toContain('interactive')`. So `buildClientHello` threads `capabilities` as an **optional input** (omitted → codec's `[]`) and never hardcodes `interactive`. Rationale: the desktop event pipeline models only the coarse `message`/`message_chunk` types, so advertising `interactive` would make the daemon fan out envelopes this client cannot render.
2. **`last_event_id` → `last_seen_ts`.** The Technical Notes referenced `last_event_id`, a field removed from the wire types. The codec now takes `lastSeenTs?: string` (RFC3339) → `HelloClientPayload.last_seen_ts`. `buildClientHello` threads it as an optional pass-through; not load-bearing until backfill-on-reconnect (#34).

## Patterns established

- **Consumers validate the opaque payload at their own edge — this is that edge.** The #5 codec deliberately keeps `Envelope.payload` as `unknown`; `parseHelloAck` is the semantic narrowing layered on top of `decodeEnvelope`'s structural boundary. The pattern: let the codec own the structural fail-closed (UTF-8 / JSON / envelope shape), add only the payload-field narrowing, and **reuse `WireDecodeError`** so the consumer catches one type for both structural and semantic failures. No new error class — the codec already owns this boundary signal.
- **`omitempty` on the wire ⇒ optional-with-default on parse, not required.** A field the daemon marshals `omitempty` is *absent* (not `null`) when empty, so a legitimate response omits it. Validating it as required would fail-closed on a real response. The normalized post-parse type still always carries the field (here `capabilities: string[]`, possibly empty) — the wire's `omitempty` and the type's always-present shape are two different views, and the parse function is where they reconcile. **This is the load-bearing correctness point of the ticket** (see Lessons learned).
- **Deterministic builder via injected `id`/`ts`.** Taking the envelope `id` and `ts` as inputs rather than reading a wall clock / counter inside the function makes the builder byte-reproducible and trivially unit-testable (a "two identical calls → byte-identical output" test pins it). The clock/id-source abstraction, if ever wanted, is the consumer's (#62) call — this module stays agnostic by taking the resolved values.
- **Fixtures round-trip through the real serializer.** Ack bytes are built via `encodeEnvelope(wrap('hello_ack', payload))`, not hand-typed JSON, so a test can never assert against a wire form the codec doesn't actually produce. Same idiom as `codec.test.ts`.
- **Category-only errors + zero `console.*`, pinned by a spy.** Every thrown message names the failure category (a field *name* is a protocol constant, never a value); a six-method `console`-spy test asserts zero calls across the happy paths and every reject branch. Inherited verbatim from the codec's discipline.

## Lessons learned

*Lifted from the PR body's "Lessons learned" section.*

- **The daemon's `hello_ack` sends `capabilities` as `omitempty`** — absent, not `null`, when empty (confirmed in `protocol-mobile.md` § hello_ack; the daemon's `v2-session-manager` marshals only `ProtocolVersion`/`ServerID`/`ConnID`). Treating `capabilities` as a required field would fail-closed on a real ack and silently break the handshake — the exact silent-failure class this whole layer exists to prevent. Only `protocol_version`, `server_id`, and `conn_id` are required. The normalized post-parse type still always carries `capabilities: string[]`, so the shared wire type needs **no change** — `omitempty` lives on the wire only.

## Deferred / carried forward

- **Driver wiring (#62, blocked by this).** No production caller on merge. #62 feeds `buildClientHello(...)` output into `NoiseRelayDriverConfig.session.hello` and the driver's `handshake-complete{helloAck}` bytes into `parseHelloAck(...)`, sources the token/device/version (paired-server store `load()` + app identity), and emits the completed-handshake status to the renderer.
- **`capabilities` policy.** Withheld (default `[]`) until the structured interactive stream (`turn_state`, deltas, tool use/result, `turn_end`) is modeled; a future interactive-stream ticket passes them in explicitly.
- **`lastSeenTs` backfill (#34).** Threaded as an optional pass-through but absent for the milestone round-trip; only exercised once backfill-on-reconnect lands.
- **`WireDecodeError` reuse vs a dedicated `HelloAckDecodeError`.** Reused deliberately — #62 needs a single catchable type for both "envelope malformed" and "ack semantics wrong" (both are "daemon sent something we can't trust" → same connection-failure handling). If #62 later needs to distinguish them, a subclass is a non-breaking addition.
