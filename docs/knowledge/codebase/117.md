## What it does

Adds `saveDebugBundle(dir, bytes): Promise<string>` — a pure `node:fs/promises` leaf that writes reassembled opaque `.tar.gz` bytes **verbatim** into an injected directory under a collision-free, owner-only (`0o600`) filename, and resolves the **absolute** path written. That is the whole slice: producing the bytes (#116 reassembly) and invoking this after a successful reassembly (#118 command) are the siblings and are **not** here. Everything is `src/main/`; the module carries no `electron` import, creates no directory, emits no logs, and never puts `bytes` into an `Error`.

## What shipped

## The load-bearing decision — exclusive-create, the *inverse* of the precedent

`fileSecretPersistence.ts` was the named precedent (same shape: sensitive bytes → disk), but the requirement here is its **inverse**, so the mechanism inverts — the developer deliberately did **not** copy temp-then-`rename`:

- **`flag: 'wx'` (`O_CREAT | O_EXCL | O_WRONLY`), not temp-then-`rename`.** The precedent overwrites the *same* name in place, so it needs `writeFile(tmp)` + `rename(tmp, target)` for an atomic *replace*. This module must **never** overwrite and must pick a **fresh** name, so exclusive-create is the right primitive: a single syscall that is **both** the no-overwrite guarantee **and** the collision-race close, with **no `existsSync`-then-write TOCTOU gap**. Temp-then-rename would (a) *reintroduce* a clobber race (pick next-free name → `rename` through the gap) and (b) litter a `.tmp` sibling into the *user-visible* downloads folder.
- **No `mkdir`/`chmod` on the directory.** The downloads folder pre-exists and is user-owned; the `0o600` **file** mode is the confidentiality control, not a dir mode. A non-existent `dir` must **reject** (`ENOENT`/`ENOTDIR`), never be silently created — pinned by the "does not create the dir" test.
- **Accepted tradeoff:** a crash mid-write can leave a partial `.tar.gz` at the visible name. Accepted because the bundle is never read back by the system — a partial file is a **re-triggerable broken download**, not a corrupted secret store. No crash-mid-write failure has been observed, so per evidence-based fix selection temp-then-rename is *not* added to defend it.

## Patterns established

- **Mirror-and-invert a precedent, don't copy it.** When a new module shares a precedent's *shape* (sensitive bytes → disk) but has the **inverse requirement** (never-overwrite vs overwrite-in-place), copy the small reusable helpers (`isErrnoException` verbatim, the injected-`dir` seam, the `freshDir` + `afterEach` test harness, the `it.runIf(process.platform !== 'win32')` perms guard) but **invert the write primitive** (`flag: 'wx'` vs temp-then-`rename`). Blindly copying temp-then-rename would have been the elegant-looking-but-wrong move — it reintroduces the exact race the inverse requirement forbids.
- **Owner-only-by-mode, called-out-not-worked-around on Windows.** `{ mode: 0o600 }` on `writeFile` is the confidentiality control on POSIX; on Windows the mode is largely ignored and the per-user profile ACL on Downloads is the control. The AC and the doc **call that out**; the perms test is `it.runIf(process.platform !== 'win32')` rather than adding a Windows-specific workaround. (Same posture as the precedent's dir-mode note.)
- **A path segment built from a module constant is structurally traversal-proof.** Because `STEM`/`EXT` are constants (never `bytes`-derived, never a daemon field), no untrusted input reaches a path segment and `resolve(dir, constant)` stays inside `dir` — unlike the precedent, which base64url-encodes an attacker-influenced name to close traversal. `resolve` (not `join`) also makes the returned path absolute even if a relative `dir` is ever passed, and the same resolved string is what gets opened, so the returned path is exactly what was written.
- **A pure leaf with no wiring is complete on its own.** No store slice, no listeners, no sockets, no `AbortController` (a single `writeFile` is not a long-lived task; the end-to-end flow's cancellation lives at #118). Two concurrent calls are safe with **no app-level lock** — `flag: 'wx'` makes the loser observe `EEXIST` and deterministically advance to a fresh name. The interface addition needs no consumer in the same slice (the consumer is #118) — same "additive method needs no wiring" pattern as #115.

## Lessons learned

*Lifted from the PR body's "Lessons learned" section.*

- **The precedent's temp-then-`rename` is the *wrong* tool for a never-overwrite writer.** `fileSecretPersistence` is overwrite-in-place, so it uses temp-then-rename for an atomic replace. This slice is the inverse (never overwrite, always a fresh name), so temp-then-rename would **reintroduce** a clobber race and litter a `.tmp` in the user-visible downloads folder — `flag: 'wx'` (exclusive-create) is the correct primitive instead. The accepted tradeoff is a possible partial `.tar.gz` on crash-mid-write (a re-triggerable broken download, not a corrupted secret store). See § "The load-bearing decision" above.

No React re-render / effect-cleanup surprises — a pure main-process fs leaf: no React, no timers, no listeners, no store. No dependency-version issues (no new dependency; `node:fs/promises`/`node:path` only). Written test-first per CLAUDE.md.

## Carried forward / deferred

- **Code-review `[NIT]` — potential test flake, deliberately NOT applied (non-blocking).** The "no byte values in the rejection" test (`saveDebugBundle.test.ts:74-85`) uses payload `[0x11, 0x22, 0x33]` (decimals `17, 34, 51`) and asserts the rejection text — which contains the full absolute temp path — does **not** include those short 2-digit substrings. Because `mkdtemp` appends random chars (and macOS `/var/folders/…` embeds a hash), a run whose path happens to contain `17`/`34`/`51` could flake. The intent (no byte leak) is sound and the finding was ranked low-probability/non-blocking, so it was left as-is. If this ever flakes: switch to distinctive multi-digit sentinel bytes, or assert against the errno `code`/`dirname` rather than the whole message.
- **#116 — inbound reassembly** (the other `security-sensitive` sibling): produces the `bytes` this module consumes. Not yet landed; independent of this slice.
- **#118 — the renderer command** that computes `app.getPath('downloads')` and calls `saveDebugBundle(...)` after a successful #116 reassembly (which follows a #115 request). Blocked-by this ticket; owns the composition-root `dir`, the user-facing progress/error UI, and end-to-end cancellation.
- **Native save dialog / user-chosen path** — deferred out of scope; a follow-up once there is a demonstrated need. The deterministic downloads-folder target keeps this slice unit-testable.
