# #121 — Introduce the `ThreadItem` conversation-timeline model

Foundational data model for the structured event stream, re-scoped from the original "render
thinking + tool-use / tool-result events" ticket once it became clear that render work had no
data model to land on. Shipped as PR #200 (`a2af1e0`, reworked `342ef2b`), code review **FAIL →
PASS** (one MUST FIX, addressed in rework). Not security-sensitive; no Figma (pure data model, no
rendering). Size S. Per [ADR 0008](../decisions/0008-thread-timeline-model.md).

## Summary

Adds one standalone module, `src/renderer/src/store/threadTimeline.ts` (+ its test) — **zero
existing files touched**, a textbook Strangler Fig alongside `sessionStore`'s flat
`MessagePayload[]` (nothing cuts over, no consumer imports the new module):

- **`ThreadItem`** — a discriminated union on `kind`: `assistantText` (one coalesced, growing text
  bubble), `toolCall` (a tool invocation whose `result: ToolResult | null` starts null and fills
  in place), `turnBoundary` (a turn-end marker). `turn_state` is deliberately **not** a member —
  it is a coarse `TurnPhase` scalar carried beside `items` on `TimelineState`, not a timeline row.
- **`ThreadEvent`** — the renderer-local, camelCase, `conversation_id`-free input union
  (`assistantDelta` | `toolUse` | `toolResult` | `turnState` | `turnEnd`) the reducer consumes.
  The structured wire types don't exist yet (`EnvelopeType` stops at `screen_snapshot`) — this is
  the stable target contract #199's bridge will map wire snake_case onto, the desktop analog of
  `daemonEventBridge` mapping `DaemonEvent` → `SessionAction`.
- **`reduceTimeline(state, event): TimelineState`** — pure, exported, mirrors `reduceSession`
  exactly: `switch` on the sealed union, `assertNever` default, no `...state` spread, same-reference
  returns when nothing changes. Per-arm behavior:
  - `assistantDelta` — tail-check coalesce: if the last item is an `assistantText` for the same
    `turnId`, replace it with concatenated text; otherwise append fresh. `seq` is carried but not
    consulted (arrival order is authoritative).
  - `toolUse` — append a `toolCall` with `result: null`.
  - `toolResult` — correlate by `toolUseId` **and** `result === null`; fill in place. No match
    (orphan or duplicate) → **same `state` reference returned**, a deterministic non-throwing no-op
    (AC4), not a synthesized recovery item.
  - `turnState` — set `phase`; no-churn if unchanged (same reference).
  - `turnEnd` — append a `turnBoundary`; does **not** touch `phase` (the daemon emits `idle`
    separately).
- `initialTimelineState` const + pure selectors `selectItems`/`selectPhase` — the same read surface
  shape as `sessionStore`.

17 new vitest cases in `threadTimeline.test.ts` (node env, no React/JSDOM) cover append order,
coalescing (+ breaks on tool-interleave, + breaks on new turn), correlation, orphan/duplicate
no-ops (`toBe` reference assertions), phase no-churn, turn boundary, and purity. 712 tests total
pass, typecheck + build green.

## Patterns established

- **A tool result merges into its tool call in place, rather than existing as a second appended
  item.** This is what makes AC4's "documented, deterministic outcome" concrete: the reducer has
  one lookup (`toolUseId` + `result === null`) with one no-match branch, instead of pushing
  correlation to render time. Any future wire event that "completes" an earlier item (not just
  appends) should reach for this same find-and-replace-in-place shape, not a second item kind.
- **Drop-and-document beats synthesizing a recovery item for an unobserved failure mode.** The
  orphan/duplicate `toolResult` outcome is a same-reference no-op, not a rendered error row —
  evidence-based: the structured stream isn't even receivable yet (desktop withholds `interactive`
  until #179), so no orphan has been observed. Revisit only if #199's reconnect replay is shown to
  produce them.
- **Codebase-wide: no unchecked `as` in `src/**` production, even when the cast is locally
  provably safe.** Code review FAILed the first submission over `items[index] as
  Extract<ThreadItem, {kind:'toolCall'}>` in `fillResult` — the index lookup made the narrowing
  provably safe, but the codebase bans the escape hatch anyway. The fix: narrow via a `.map`
  callback whose `item.kind === 'toolCall'` guard narrows `item` in place, so the spread
  type-checks with zero assertion. `sessionStore.appendUnique` (the template this module mirrors)
  already does its find-and-modify with zero casts — this ticket brought `threadTimeline` in line
  with it. Apply this same `.map`-narrow shape to any future find-and-replace reducer helper
  instead of an index-cast.

## Lessons learned

None beyond the `as`-cast pattern above (folded into "Patterns established" since it changed the
