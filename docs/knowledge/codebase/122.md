# #122 — Introduce the renderer-side modal-prompt model (pure model + reducer)

Foundation data model for permission/trust prompts, re-scoped from the original "Answer permission,
trust, and destructive prompts from the desktop" ticket once it became clear the render/answer work
had no data model to land on — the modal analog of #121's timeline-model split. Shipped as PR #221
(`fd1b75a`), code review **PASS** with zero findings. Not security-sensitive; no Figma (pure data
model, no rendering). Size S. Per [ADR 0009](../decisions/0009-modal-prompt-model.md).

## Summary

Adds one standalone module, `src/renderer/src/store/modalPrompts.ts` (+ its test) — **zero existing
files touched**, a Strangler Fig alongside `sessionStore`/`threadTimeline` (nothing cuts over, no
consumer imports the new module):

- **`ModalPrompt`** — the held, outstanding prompt: `modalId`, `class` (`'permission' | 'trust'`,
  no `destructive` — there is no such wire class), `title`, `prompt`, ordered `options:
  readonly ModalOption[]`, `defaultOptionId`.
- **`ModalEvent`** — the renderer-local, camelCase, sealed input union (`shown` | `dismissed`) the
  reducer consumes — not the wire types, which don't exist yet and are the peeled follow-up's.
  `shown` carries the same fields as `ModalPrompt` (minus `type`); `dismissed` carries `modalId` +
  `outcome`/`source` (`'remote' | 'local' | 'timeout'`, carried for the follow-up but not consulted
  by the reduce).
- **`ModalState`** — `{ outstanding: readonly ModalPrompt[] }`, an **ordered array, not a `Map`** —
  the id-addressing lives in the correlation mechanism (scan-by-`modalId`), not the container type,
  so the selector stays referentially stable and #195/#196 stay one-arm extensions.
- **`reduceModal(state, event): ModalState`** — pure, exported, mirrors `reduceTimeline` /
  `reduceSession` exactly: `switch` on the sealed union, `assertNever` default, no `...state`
  spread, same-reference returns when nothing changes. Per-arm behavior:
  - `shown` — always appends a fresh `ModalPrompt`. A `shown` for an already-outstanding `modalId`
    (reconnect re-delivery) is **not** defended here — plain append is correct for first-delivery;
    match-and-replace is #195's.
  - `dismissed` — removes by `modalId`. No match (unknown or already-dismissed id) →  **same
    `state` reference**, a deterministic non-throwing no-op (AC4).
- `initialModalState` const + pure selector `selectOutstanding` (returns the array by reference) —
  the same read-surface shape as `threadTimeline`'s `selectItems`.

16 new vitest cases in `modalPrompts.test.ts` (node env, no React/JSDOM) cover install, a `trust`
class round-trip, multiple-outstanding oldest-first order, clear-by-id, unknown-id no-op (both
empty and non-empty sets, `toBe` reference assertions, non-throwing), options/`defaultOptionId`
preservation, `dismissed` keying only on `modalId` (ignoring `outcome`/`source`), purity (old
references intact, new references where a change occurred), and initial-state + selector-by-reference.
`npm test` (68 files, 862 passed / 3 pre-existing skips), `npm run typecheck`, and `npm run build`
all green.

## Patterns established

- **Id-addressing lives in the correlation mechanism, not the container type.** The ticket's "keep
  it id-addressed from the start" goal is met by scanning an ordered array by `modalId`, not by
  reaching for a `Map`/`Record`. This keeps the selector's referential-stability property (the
  array returned by reference) while still making a future match-and-replace (#195) or reconcile
  (#196) a one-arm change. Reach for this shape — plain array + scan-by-id — over a keyed container
  whenever a future consumer is a React selector that needs reference stability and the collection
  stays small.
- **A pure model+reducer foundation ships with zero speculative surface.** No Zustand store, no
  singleton, no React hook, no wire types — all reserved for the follow-up with names already
  chosen (`modalStore.ts`) so the next ticket has zero naming ambiguity. Confirms the #121 precedent
  generalizes: when a render/answer vertical has no data model yet, ship the model alone first.
