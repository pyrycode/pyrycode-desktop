## What it does

Adds a main-process logger whose allowlist is the *envelope* of an event — its name, a static classification code, a byte length / count, and safe connection coordinates (hostname, path, HTTP/WS status) — **never the value inside**. It turns every transport module's "LOG-FREE by construction" (classify the error to a static code, drop the caught object) into "**content-free-log by construction**." A real connection bug now leaves a diagnosable line (`event=relay-dial status=404 path=/` — the 404 hunt that motivated the ticket) instead of a silently classified-and-dropped error. The what/why and the full API live in the [diagnostic-log feature doc](../features/diagnostic-log.md); the allowlist-not-scrubber decision is [ADR 0007](../decisions/0007-content-free-diagnostics-by-construction.md).

## The load-bearing decisions

- **Allowlist the envelope, enforced by the type — not a runtime scrubber.** The content-free guarantee is *structural*: `DiagnosticEvent` has no field capable of carrying a secret, so a scrubber (a denylist that fails open) is never needed and never used. Promoted to [ADR 0007](../decisions/0007-content-free-diagnostics-by-construction.md) because it grounds the whole Bucket-1 diagnostics family (#125/#127/#128). Backed by *both* a runtime assertion (planted token/key/plaintext never reach the sink) and a compile-time negative (`@ts-expect-error` on secret-carrying fields, validated by the QA-gate `typecheck`).
- **Reuse `fileSecretPersistence`'s disk patterns, invert its write shape.** The file sink copies the injected-`dir` seam, `mkdir …{ mode: 0o700 }`, the `isErrnoException` typed-errno guard, open/stat-then-handle-ENOENT (no `existsSync`, no TOCTOU), and `0o600` file mode — but **not** the precedent's whole-file temp-then-`rename`. A log sink **appends and rotates** (append → size-check → rename-shift → reopen), a different write shape, and uses the **sync** `fs` variants so `event()` is ordered, non-interleaving, and race-free. Same shape-reuse-but-invert-the-primitive move as [#117](117.md)'s `saveDebugBundle`.
- **Sync fs is the deliberate choice.** `event()` fires from deep inside transport error handling; sync `appendFileSync`/`renameSync` give per-call completion (records in `seq` order, no rotation race, no buffered tail lost on `app.quit`). Async `fs/promises` (as in `fileSecretPersistence`) would need a serialization queue for no benefit — the write shape differs, so the reuse is the *patterns*, not the async-ness.
- **Construct-and-hold the singleton at the root — the #127/#128 decoupling seam.** One process = one logger; built once at the composition root and injected into `createDaemonConnection` (the one point the whole transport stack hangs under). Both consumers read the *same* instance, so neither owns construction and neither is `blocked-by` the other. Deferring construction to "the first consumer" would serialize them — the exact thing the split forbids. Mirrors [`secureStore`](../features/secure-store.md)'s construct-once-consume-many idiom.
- **Rotation guard `size > 0 && size + byteLength(entry) > maxBytes`.** So a lone entry larger than `maxBytes` still lands (rotation can't shrink it) and an empty log is never rotated — the bound is on rotated **file count**, not any single record. Byte accounting is `Buffer.byteLength(entry)` (not `.length`).

## Patterns established

- **A security property realized as a *type*, pinned by the build.** When the deliverable is "X can never reach Y," prefer a typed shape that structurally omits the X-carrying field over a runtime scrubber that strips it. The excess-property check plus `tsconfig` coverage of the test dir turns "no secret field is assignable" into a QA-gate failure — a `@ts-expect-error` compile-time negative is a real regression guard, not just documentation. (Contrast a runtime denylist, which fails open and is untestable for the unknown case.)
- **Construct-once-at-the-root to keep sibling consumers independent.** When a split intends two consumers to stay unblocked-by-each-other, build the shared dependency at the composition root and inject it — do **not** let the first consumer own construction (that forces the second to depend on it). The optional-interface-field + root-injection is the whole seam; the call sites are the consumers' work.
- **Mirror-and-invert a precedent's *write shape*, reuse its *safety patterns*.** `fileSecretPersistence` is whole-file-atomic-replace + async; this sink is append-and-rotate + sync. The reusable parts (dir seam, errno guard, modes, no-`existsSync`, temp-dir test harness) transfer; the primitive (temp-then-rename vs append/rename-shift) and the async-ness do not.

## Lessons learned

*Lifted from the PR body's "Lessons learned" section.*

- **The `@ts-expect-error` compile-time negative in the `.test.ts` is a real regression guard.** `tsconfig.node.json` includes `src/main/**/*` (test files too), so `npm run typecheck` fails the moment a secret-carrying field ever becomes assignable to `DiagnosticEvent` — the allowlist *is* the enforcement, and this pins it. (Verified independently by code review.)
- **The file sink rotates only when `main.log` already holds content AND the pending entry would cross the cap** — so a lone entry larger than `maxBytes` still lands (rotation can't shrink it) and an empty log is never rotated. The bound is on rotated *file count*, not on any single record.

No React re-render / effect-cleanup surprises — a pure main-process service: no React, no timers, no listeners, no store (the sync sink means there's not even a long-lived async task to tear down). No dependency-version issues (no new dependency; `node:fs`/`node:path`/`JSON` only). Written test-first per CLAUDE.md.

## Carried forward / deferred

- **Code-review `[NIT]` — `JSON.stringify` sits *outside* the try/catch (`diagnosticLog.ts:88`), deliberately NOT applied (non-blocking).** `DiagnosticSink.write` and `DiagnosticLog.event` both promise "never throws." For all *typed* callers this holds — the record is flat `string`/`number` scalars, which `JSON.stringify` never throws on. But a mis-cast caller (the confused-caller residual) that widened a field to a `bigint` would make `JSON.stringify` throw *out* of `event()` and crash the transport it observes — the exact failure the module exists to prevent. Moving the line inside the existing `try` would fully honor the contract at zero cost. Left as-is (typed call sites are safe today, no observed failure); revisit if #127/#128 ever surface a non-scalar field. Evidence-based: no defense shipped for an unobserved failure mode.
- **Code-review `[NIT]` — runtime shape is the spread, not strictly the allowlist (`diagnosticLog.ts:83`).** `{ ...fields, seq, ts }` serializes whatever enumerable properties `fields` carries; the guarantee is a *compile-time* (call-site) one, not a runtime scrub. This is **deliberate and correct** — #125's additive optional fields slot in automatically without touching the serializer, which a hand-written field-pick would foreclose. Noted so the **#127/#128 code reviews apply the call-site checklist**: static literals for `event`/`code`, `new URL(u).hostname` / `.pathname` for `host`/`path`, **never** `url.href` / `url.search`.
- **#127 — relay-leg wiring** (threads `diagnosticLog` down through `NoiseRelayDriverConfig` to the relay connection; captures the WS close reasons / codes / frame `.length`). Also captures the relay's `/v1/client` 404 (the "no 404 seen today" caveat from [[ticket-124-conn-logging-split]]).
- **#128 — daemon-leg wiring** (uses `deps.diagnosticLog` directly in the `daemonConnection` event choke point; feeds the `not-paired` / `malformed-hello-ack` / `connection-closed` / `connect-failed` codes). Both #127 and #128 edit `daemonConnection.ts` → their architect runs must apply the file-overlap check and serialize if concurrent.
- **#125 — the broader Bucket-1 log** (state-store transitions, payload `hash + length + type`, shared correlation id). Out of scope; the record shape accepts them as additive optional fields (see ADR 0007 § Consequences).
