## What it does

Extends `daemonConnection`'s "LOG-FREE by construction" to "**content-free-log by construction**": the module already classifies every caught error into a static category code and drops the caught object (a codec/keychain error could echo the token or transcript bytes), but that classification — the *reason* a connection never reached `connected` — was recorded nowhere. Now the three daemon-composition lifecycle boundaries shadow onto the injected [#126 logger](../features/diagnostic-log.md) as content-free records:

- `daemon-dial` — the coordinate-free dial anchor, the daemon-side "connecting → connected/failed" window opening.
- `daemon-connected` — the load-bearing "the Noise handshake finished" signal.
- `daemon-failed { code }` — every classification the single `emitFailed` choke point funnels (`not-paired`, `malformed-hello-ack`, `connect-failed`, `connection-closed`, and the driver's own `error` reason).

The single highest-value case is the **not-paired** one: the relay socket never opens, so [#127](127.md) (the relay leg) logs *nothing* — yet `daemon-dial → daemon-failed{not-paired}` gives the operator a complete daemon-side window regardless. The what/why lives in the [daemon-connection feature doc](../features/daemon-connection.md) § *Diagnostic logging*; the allowlist-not-scrubber contract is [ADR 0007](../decisions/0007-content-free-diagnostics-by-construction.md).

## The load-bearing decisions

- **Three pre-existing seams, no new choke point.** `daemonConnection` already funnels every failure through the single `emitFailed`, every success through `onDriverEvent`'s `handshake-complete` case, and every dial through `dial()`'s `connecting` emit. So the diff is exactly three log lines plus the header comment — no new local, no new type, no refactor. `deps.diagnosticLog?.event({ … })` at each site.
- **Log the classification, not the socket code — the leg division vs [#127](127.md).** The same socket close flows through *both* layers. #127 (`relayConnection.ts`) logs the **socket code** — `relay-closed { status: terminal.code }` (the numeric WS close code) — plus the connection **coordinates** (`host`/`path`). #128 logs the **classification** — `daemon-failed { code: 'connection-closed' }` — and nothing else. `emitFailed` logs only its `code` argument; its `message` argument (which interpolates `…(code ${event.code}).`) is never logged, so the numeric close code stays out of the daemon record *by construction*. The daemon leg carries **no** `host`/`path`/`status`.
- **`daemon-dial` is coordinate-free and fires before `bootstrap`.** At the dial seam the paired record is not yet loaded, so the relay host/path are not even available — and they are #127's regardless. Logging unconditionally at the `connecting` transition (before `bootstrap(gen)`) means the not-paired case still anchors: `daemon-dial → daemon-failed{not-paired}`, a complete daemon-side window even when the relay leg is silent (no socket → no `relay-*` record).
- **`daemon-connected` is event-name-only — the "did the handshake finish" signal.** Logged on the success path after the ack parses; it records *that* the Noise handshake completed, never the `hello`-ack bytes (`event.helloAck`). Distinct from #127's `relay-open`, which is the WS socket opening and *precedes* the handshake. No `bytes` field — the signal is binary (finished / didn't).
- **The log is a faithful shadow of the gen-fenced event stream (AC4).** All three sites log *after* the corresponding `emitDaemonEvent`, inside the pre-existing generation fence, so no stray record leaks from a superseded dial: `daemon-failed` fires only inside `emitFailed` (reached only under a current-gen guard); `daemon-connected` sits inside the gen-fenced `onEvent` wrapper; `daemon-dial` runs once per `start()`/`reconnect()`. A clean `stop()` suppresses both event and record for free — the `terminal` case returns on `if (stopped)` **before** reaching `emitFailed`, so a quit-driven `terminal{1000,'stopped'}` logs nothing.

## Patterns established

- **Consume an already-injected DI seam directly — the cheapest possible observability add.** [#126](126.md) constructed the singleton at the root and added `deps.diagnosticLog?` accepted-unused; #127 threaded it down the relay config blob. This ticket is the pure consumer case: `deps` is already in scope in every closure, so three `deps.diagnosticLog?.event({ … })` lines at existing seams is the entire production diff. No wiring, no new type, no fixture cascade — the `?.` no-op path keeps every pre-existing test green untouched.
- **Split a cross-cutting concern by *what each layer knows*, not by file.** Both legs edit `daemonConnection.ts` and both log a connection's death, but the division is semantic: the relay leg owns the **socket facts** it can see (coordinates, numeric close code); the daemon leg owns the **classification** it computes (the static category code). Neither re-logs the other's field. The rule that keeps them from colliding — "log only `emitFailed`'s `code`, never its `message`" — is a one-line call-site discipline, not a type boundary.
- **Apply the [#126](126.md) call-site secret-safety checklist at every log site.** `DiagnosticEvent.event`/`code` are `string` and cannot be *type*-forbidden from holding a secret (the #126 security-review residual). Code review's job on a diagnostics-consumer ticket is to confirm each site passes only static literals / closed-enum values for `event`/`code` and never a caught object, banner text, ack bytes, or `event.code`. #136's review confirmed all three sites clean (see below).

## Lessons learned

No PR-body "Lessons learned" section — a clean, mechanical S-ticket with no surprises to flag. Two points worth recording for the next diagnostics-consumer:

- **The `RelaySessionErrorReason` enum is what makes `emitFailed(event.reason)` safe to log.** The `error` case routes the driver's own reason through `emitFailed` as the `code`. That reason is typed `RelaySessionErrorReason` — a *closed set of static strings* documented "never carries key/token/frame/plaintext bytes" (`noiseRelayDriver.ts:48-52`). A malicious relay can select *which* classification fires but cannot inject bytes into it. The peer-supplied `terminal.reason` string (attacker-controlled) is a *different* type, already dropped by the existing `terminal` case, and never reaches `emitFailed`'s `code` — so the daemon record is content-free even under a hostile relay.
- **Adversarial "absence" assertions carry the security guarantee, not the presence checks.** The AC3 `connection-closed` test emits `terminal{ code: 4426, reason: 'noise-handshake-secret-detail' }` and asserts the serialized records contain **neither** `'4426'` (the #127-owned numeric close code) **nor** the peer reason string **nor** the banner text `'The connection to pyrybox was closed'` — the three things that must *not* leak. The AC2 `not.toContain('conn-1')` check is non-vacuous because `validHelloAck()` embeds `conn-1`. These negative assertions are the ones that would catch a regression that widened a record; the positive `toContainEqual({ event: 'daemon-failed', code })` checks only prove the happy path.

No React re-render / effect-cleanup surprises — a pure main-process composition layer (no React, no store; it only *emits* into the renderer's session store via IPC). No dependency-version issues (no new dependency; reuses the #126 logger). The three added calls are synchronous, non-throwing side-effects (the sink swallows its own errors, `diagnosticLog.ts:89-95`) and add no try/catch — the module still never throws. Written test-first per CLAUDE.md.
