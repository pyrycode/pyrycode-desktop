# #131 — Content-free renderer→main diagnostics log channel

**Shipped:** 2026-07-08 · **Size:** S · **Scope:** add the missing seam Bucket 1 of the Diagnostics design needs — a **one-way renderer→main IPC channel** that carries an allowlisted, content-free record from the sandboxed React window to the [#126](126.md) main-process logger, re-validated at the untrusted→trusted boundary before it reaches the logger. Renderer-side surfaces (the state store [#134](https://github.com/pyrycode/pyrycode-desktop/issues/134), later the render layer) can now land in the same one-click debug bundle as the transport logs, **without ever giving the renderer a path to emit a secret**. Four production files (two new, two one-ish-line edits); a faithful copy of the [command channel](../features/command-channel.md) with **one deliberate deviation** (§ *The load-bearing decisions*). `security-sensitive`; architect self-review **PASS**, code review **PASS** (one non-blocking NIT). No consumer wired beyond a test emitter — that is [#134](https://github.com/pyrycode/pyrycode-desktop/issues/134).
**Spec:** `docs/specs/architecture/131-renderer-main-diagnostics-channel.md` · **PR:** [#138](https://github.com/pyrycode/pyrycode-desktop/pull/138). Split from [#125](https://github.com/pyrycode/pyrycode-desktop/issues/125) (Bucket-1 diagnostics). See [[ticket-131-renderer-main-diag-channel-refined]] and [[ticket-125-bucket1-diagnostics-split]].

## What it does

The [#126 content-free logger](../features/diagnostic-log.md) lives in the main process; the renderer is sandboxed and cannot call it directly. Bucket 1 wants "state-store transitions and interface errors" in the bundle — both happen in the renderer. This ticket adds the pipe: `window.pyry.sendDiagnostic(record)` (renderer) → `ipcRenderer.send` (preload) → `ipcMain.on` → `onDiagnostic` (main) → **project at the boundary** → `diagnosticLog.event(projected)` — the SAME logger instance the transport writes to. One-way and side-effect-free from the renderer's view: `sendDiagnostic` returns void, no reply, no throw path back into the window.

The what/why lives in the new [renderer→main diagnostics channel feature doc](../features/diagnostics-channel.md); the allowlist-not-scrubber contract it extends to the renderer boundary is [ADR 0007](../decisions/0007-content-free-diagnostics-by-construction.md).

## The load-bearing decisions

- **A single validate+project function, NOT the command channel's guard+forward-raw.** This is the one deliberate deviation from the mirrored [command channel](../features/command-channel.md). `onCommand` forwards the *validated raw object* to its handler — safe there, because the handler only reads `command.payload`. Here the record reaches `logger.event()`, which **spreads its argument** (`{ ...fields, seq, ts }`, [`diagnosticLog.ts:87`](../features/diagnostic-log.md)): forwarding a raw renderer object would spread any planted extra field (`token`, `text`, `__proto__`, …) straight onto the log line. `projectDiagnosticEvent` returns a **freshly built object literal** with only allowlisted fields; a function that has **no code path returning its input** makes "forgot to project, forwarded raw" structurally impossible. This is the load-bearing reason AC2/AC4 exist.
- **Projection is a fail-closed allowlist, enumerated by name — not a denylist scrub.** The output is built by copying named fields, so any unnamed field is structurally absent (fails *closed*), matching #126's own stance ([ADR 0007](../decisions/0007-content-free-diagnostics-by-construction.md)). A wrong-typed optional (`status: 'x'`) is **omitted, not fatal** — a bogus optional must not discard an otherwise-valid `event`; `event` missing/empty/non-string gates the whole record to `null`.
- **`RendererDiagnosticEvent` is defined in `shared`, not reached in from `src/main`.** `commands.ts` and `events.ts` each *define* their record type in `shared/ipc` and never import from `src/main` — `src/shared` is a clean leaf. The mirror's field-for-field identity with #126's canonical `DiagnosticEvent` is instead pinned by a **compile-time equality assertion** in the main-side test, so a future field added to #126 (a correlation id — the [#125](https://github.com/pyrycode/pyrycode-desktop/issues/125) roadmap) surfaces as a `typecheck` failure, not a silent capability gap. This is the deterministic net that lets the security audit trust **one** allowlist across the IPC boundary.
- **The typed `record` param is ergonomics; `projectDiagnosticEvent` is the enforcement.** `RendererDiagnosticEvent` on `sendDiagnostic` is the compile-time half of the allowlist (it makes the correct call obvious at #134's site), but it is **erased at runtime** and gives zero guarantee against a compromised renderer. The runtime projection at the untrusted boundary is what actually enforces it — belt-and-suspenders, different fabric (an ergonomic/stochastic type paired with a deterministic runtime net).
- **Reuse the SAME `diagnosticLog` instance from the composition root — do not build a second.** One main process = one logger (one `seq` counter, one file). The registration reuses the instance already built at `index.ts:153` and injected into `createDaemonConnection`, so renderer records interleave in `seq` order with the transport records in one `main.log`.
- **Strip the `IpcMainEvent` first arg.** It exposes `.sender`/`.senderFrame`/`.ports`, a capability leak downstream — identical to `onCommand`. Only the projected record reaches the logger.
- **Swallow every listener-body fault (AC3).** `logger.event` already swallows sink throws internally ([#126](126.md)); the receiver's outer `try/catch` is the belt-and-suspenders net so a diagnostics fault cannot crash the window it observes. The swallow hides a *fault*; it never *widens* what is logged.
- **The channel is inert until #134.** Registered once for the app lifetime; a record arriving before any consumer is simply a logged line, so no gating is needed. Only a test emitter drives it on merge.

## Patterns established

- **The fourth `DiagnosticLog` consumer shape — and the first from the *renderer* boundary.** [#127](127.md) logs the relay socket's coordinates + close code; [#128](128.md) the daemon composition layer's classification; [#130](130.md) a decode outcome (type + size + hash). #131 does not log anything itself — it opens the pipe so a *renderer* surface can. It is the first producer to reach the single logger instance across the untrusted IPC boundary rather than from inside the main-process transport stack.
- **Extend a boundary-validated renderer→main channel to a spread-consuming sink by projecting, not guarding.** The [command channel](../features/command-channel.md)'s guard+forward-raw is safe only when the downstream reads specific fields. When the downstream **spreads** its argument, the safe shape is a single validate+**project**-to-a-fresh-object function — no code path returns the input, so a raw-forward is structurally impossible. Reusable for any future renderer→main channel feeding a spread.
- **Pin a shared mirror to its canonical source with a compile-time type-equality assertion, placed on the side that can legally cross the boundary.** `Equals<A, B>` collapsing to `const _pin: true = false` on drift, in the **main-side** test (the only project spanning `src/main` + `src/shared`) — the deterministic net that lets a security audit trust a mirrored allowlist. Reusable for any `shared`-leaf mirror of a `src/main` type.
- **Assert the content-free guarantee end-to-end over a real logger, past the spread.** AC4's key test plants a secret and drives the listener through a **real** `createDiagnosticLog` over a capture array, asserting the serialized JSON line carries no secret — the guarantee checked where the bytes actually serialize (past the `{ ...fields }` spread), not on a mock's arguments. Same reusable shape [#130](130.md) established, now applied across the IPC boundary.

## Lessons learned

From the PR body's **Lessons learned** section (a clean S-ticket otherwise implementing the spec precisely):

- **A cross-boundary compile-time type-pin must live in a `src/main` test, not a `src/shared` test.** `src/shared/**` is typechecked by **both** tsconfigs, and the composite `tsconfig.web.json` deliberately **excludes** `src/main` — so a `src/shared` test importing `src/main/diagnosticLog` fails with **`TS6307`** ("not listed within the file list of project") under the web project. The `receiveCommand.test.ts` precedent works only because it lives in `src/main` (the node project, the only one spanning both `src/main` and `src/shared`). **Keep `src/shared` tests pure leaves; put any cross-boundary type-pin main-side.** This is why the pure `diagnostics.test.ts` does *not* import the canonical `DiagnosticEvent`, and the pin lives in `receiveDiagnostic.test.ts`. Related to project memory `@shared alias not in main/preload` and the `e2e/ not typechecked` note — all three are the same "which tsconfig sees which file" hazard family.

No React re-render / effect-cleanup surprises — the renderer surface here is only the preload method signature; the logic is a pure `src/shared` function + a `src/main` receiver (no React, no store, synchronous). No dependency-version issues (no new dependency; reuses the [#126](126.md) logger and the existing IPC scaffolding). Written test-first per CLAUDE.md.

## Carried forward / deferred

- **#134 — the first consumer (state-store transition logging).** This ticket ships the channel + a test emitter only; #134 wires the store to emit `store-transition` records over it. It was `blocked-by` #131 and is now unblocked.
- **The 128-char string cap is sized for today's fields** (64-hex hash is the longest). If #134 or a later consumer needs a longer legitimate field, raise the cap there rather than removing it (spec Open Questions). Non-blocking.
- **Code-review NIT (non-blocking):** the truncation test exercises only `event` and `code`; `host`/`path`/`hash` share the same `capString` helper so coverage is adequate, but a one-line assertion on one more string field would make the cap universal on its face. Not fixed; left as a note.
- **The broader Bucket-1 log** ([#125](https://github.com/pyrycode/pyrycode-desktop/issues/125)): a version banner (#132), pre-decryption raw bytes (#133), and a daemon↔client correlation id (needs a daemon twin) remain. The [#126](126.md) record shape accepts the correlation id as another additive optional field; the type-pin here guarantees the renderer mirror moves with it.
