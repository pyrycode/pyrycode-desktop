# #141 — Channel List home screen: two-tier Channels / Recent discussions

Mirror of mobile #312. Lineage: [#139](139.md) (transport decode) → [#208](208.md) (store observer) →
**#141** (this screen), replacing the throwaway `PlaceholderList` from [#140](140.md)'s `list` arm.
Shipped as PR #239, code-review **PASS** (one non-blocking a11y NIT). Not security-sensitive — pure
renderer of already-decoded, already-untrusted-flagged daemon strings; no keys, sockets, or transport
code added. Size S: one new screen directory (2 prod files + CSS) + a single-arm `PairedShell.tsx` swap.

## Summary

Replaced `PlaceholderList` (a single "Open conversation" button) with the real Channel List home
screen — a pure render slice over the already-shipped [#208 `conversationListStore`](../features/conversation-list-store.md),
read via `useConversationListStore(selectConversations)`. No transport, IPC, store, wire, or bridge
code was added (AC1).

- **New `src/renderer/src/screens/channels/channelListViewModel.ts`** — framework-free `.ts`, mirroring
  `messageViewModel.ts`. Three pure exports: `UNNAMED_LABEL = 'Untitled'`; `titleFor(name)` (guards
  `null` **and** blank/whitespace-only → `UNNAMED_LABEL`, never a blank row — AC3); `partitionByPromotion(rows)`
  (two order-preserving filters on `is_promoted`, no re-sort — the daemon's array order is authoritative,
  AC2); `formatLastActivity(iso, now)` — a bucketed relative-time formatter with **injected `now`** (pure,
  deterministic under test, never `Date.now()` inside). Buckets: malformed/non-RFC3339 `iso` → `''`
  (row renders title only, no `NaN ago`); negative delta (clock skew) → `'just now'`; <1min → `'just now'`;
  <1h → `Nm ago`; <24h → `Nh ago`; <48h → `'Yesterday'`; <7d → `N days ago`; older → a UTC-derived
  `Mon DD` short date (timezone-independent — never `toLocaleDateString`).
- **New `src/renderer/src/screens/channels/ChannelList.tsx`** — container (`ChannelList`, reads the
  store slice + captures `Date.now()`, its only two impurities) + pure view (`ChannelListView`),
  mirroring the #203/#218 container-reads/pure-view split. Always renders a stable
  `<section className="channel-list" aria-label="Conversations">` root (the test hook, present in
  every state):
  - `conversations === null` (not-yet-loaded) → wrapper only, no rows, no empty state (AC4 — the
    neutral first-paint posture, #203's `Timeline` null-on-empty precedent).
  - `conversations.length === 0` (loaded-zero) → one centered `<p className="channel-list__empty">`
    ("No conversations yet") — AC4.
  - non-empty → `partitionByPromotion`, then each non-empty section as a `<header>` + its rows, with
    `.channel-list__divider` only between two present sections. A zero-row section renders no header
    (AC2). Each row: `<button onClick={onOpen}>` with `titleFor(row.name)` and
    `formatLastActivity(row.last_message_ts, now)` as auto-escaped React children (never
    `dangerouslySetInnerHTML`). React key is `row.id` (a real stable identity, unlike the timeline's
    array-index keying).
- **`onClick={onOpen}` on every row is deliberate and interim** — per the ticket's Out of Scope,
  opening a *specific* tapped conversation needs a select-and-load transport path that doesn't exist
  yet, so every row invokes the shell's existing conversation-agnostic `onOpen` (opens the single
  active conversation via `sessionStore`), preserving #140's list→thread round-trip with no new
  transport (AC1's "no regression"). A future select-and-load ticket changes only what `onClick`
  passes; the seam is already the row.
- **New `channels.css`** — token-only (every color/type/space value is a `var(--…)` token; opacity is
  the de-emphasis device, the #218 precedent, not a color literal). Deviates from the architecture
  spec's `.channel-list { flex: 1 1 auto }` — see Lessons learned below.
- **`tokens.css`** — added the missing `--text-title-medium-*` quad (16px/24px/0.15px/500) the row
  title needed; sourced from the exact M3 values in Figma node 15-8, not approximated from
  `body-large`.
- **`PairedShell.tsx`** — `case 'list'` now returns `<ChannelList onOpen={props.onOpen} />`; the
  `PlaceholderList` function is deleted entirely. The reducer, `onOpen`/`onBack` seams, and every
  other arm are untouched.
- **Fixture moves (from #140):** `PairedShell.test.tsx`'s `LIST_MARKER` and `App.test.tsx`'s
  placeholder assertion both moved from `'Open conversation'` to `'aria-label="Conversations"'` (the
  new always-present wrapper marker); both server-render without seeding the store, so the wrapper is
  present but empty — a stable assertion.

`npm test` (982, +23 new), `npm run typecheck`, `npm run build` all green.

## Patterns established

- **A render slice over an already-shipped store needs zero data-layer code — the whole ticket lives
  in one new screen directory plus a single switch-arm swap.** #139 (transport) and #208 (store)
  had already done the data-layer work; #141 only reads `selectConversations` and derives view state
  from it. Mirrors #218's "single-arm switch swap" pattern one level up — here the swap is the
  `PairedShellView` case, not a `TimelineRow` case.
- **A screen-owned scroll column that mounts directly under `#root` needs `height: 100%`, not
  `flex: 1 1 auto`.** See the height-deviation lesson below — this is now the second documented
  instance (`.conversation` was the first), so a future screen mounted the same way (a direct
  `PairedShellView`/`AppView` case, no flex wrapper in between) should default to `height: 100%`
  and treat `flex: 1 1 auto` as the thing to double-check, not the default.
- **When a wire type carries no field a design mock wants, collapse the two visually-distinct mock
  rows to one honest row shape rather than fabricating the missing data.** Figma's avatar-bearing
  channel row and preview-bearing discussion row both became the same title+time row here, because
  `ConversationSummary` has no message text. Flag the gap to the human (`@Juhana` in the ticket) and
  defer the richer render to a wire-change follow-up, rather than inventing a substitute value.

## Lessons learned

(From the PR body's own "Lessons learned" section.)

- The paired shell mounts `ChannelList`'s root directly under the block-level `#root` — there is no
  flex wrapper between them. The architecture spec's `.channel-list { flex: 1 1 auto }` is inert in
  that position (it wouldn't fill the window — a dark seam below a short list — nor scroll
  internally). Fixed to `height: 100%; box-sizing: border-box`, mirroring `.conversation`'s proven
  direct-child-of-`#root` pattern; documented in a code comment in `channels.css` and called out
  explicitly in code review as a legitimate, well-reasoned deviation from the spec.

## Open questions carried forward

- **Section `<header>` vs `<h2>` (code-review NIT, non-blocking).** The spec prescribed sibling
  `<header>` elements for "Channels" / "Recent discussions"; a real heading element would give
  screen-reader users navigable section landmarks that two sibling `<header>`s inside one `<section>`
  don't. Flagged as a future a11y pass, not gated on here.
- **Archived rows.** `ConversationSummary.is_archived` exists but is not filtered — every row the
  store holds renders, partitioned only by `is_promoted`. Correct if the daemon already excludes
  archived conversations from the `conversations` response; if archived rows do arrive and should be
  hidden, that's a scoped one-line filter follow-up, not a change to this slice.
- **Relative times don't tick** — `now` is captured once per render at the container; a live-updating
  interval is a deferred enhancement.
- **Per-row opening of a specific conversation, the top app bar (logo/title/settings gear), monogram
  avatars, "See all discussions (N)", and the new-discussion FAB** are all out of scope — see the
  ticket body. The FAB is [#142](https://github.com/pyrycode/pyrycode-desktop/issues/142); the
  select-and-load path and the Settings screen are each their own future ticket.
