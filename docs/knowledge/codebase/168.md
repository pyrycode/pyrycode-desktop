## What it does

Ships the **typed IPC contract** for the debug-bundle download — inert but fully typed. The renderer gains one bare `requestDebugBundle` command to trigger the download; the main process gains three `DaemonEvent` members (`debugBundleProgress`/`debugBundleSaved`/`debugBundleFailed`) to report progress and the terminal result back. Nothing emits the new events yet and the command is an unhandled no-op (`src/main/index.ts`'s `onCommand` switch has no `default` arm) — the orchestrator that wires request → reassemble → save → emit is #169. Both new surfaces ride the **existing** `sendCommand`/`onDaemonEvent` channels — no new IPC channel, no new preload method in either direction.

## Why this had to be its own slice

`translateDaemonEvent`'s `switch` ends in `default: return assertNever(event)` — any unhandled `DaemonEvent` variant is a compile error. Adding the three new members to the union therefore fails `npm run typecheck` (the build/QA gate) until this **one** switch grows matching cases. That forced-consequence is the entire reason the contract has to ship as a single unit rather than commands/events landing independently: the moment `events.ts` gains a member, `daemonEventBridge.ts` must change in the same commit or the repo doesn't build. Everything else in the diff is genuinely additive and touches nothing else — `App.tsx`/`PairingScreen.tsx` only call the bridge hook, `emitDaemonEvent.ts`/`daemonConnection.ts` only construct events, `sessionStore.ts`'s own `SessionAction` exhaustiveness is untouched because the three new events map to `null`, not a new action arm.

## Patterns established

- **A payload-free union member's guard case is a bare `return true`.** `isRendererCommand`'s `sendMessage` arm validates a payload shape; `requestDebugBundle`'s arm has nothing to validate — a well-formed `type` is complete acceptance. Structural-minimum acceptance (extra fields tolerated) stays consistent between the two arms.
- **`SessionAction | null` is the return-type shape for "this IPC event exists but drives no store action."** Rather than inventing a no-op `SessionAction` member (which would force `sessionStore`'s own reducer to grow a dead arm), the translation layer's return type absorbs the "no action" case directly, and the one production call site (`useDaemonEventBridge`) gets an explicit `if (action)` skip. This keeps two independently-exhaustive unions (`DaemonEvent`, `SessionAction`) from being forced into 1:1 correspondence forever.
- **Comment touch-ups on an invariant-bearing docblock should be revised, not just appended to.** Both `commands.ts` and `events.ts` had file-header claims ("every member reuses a wire payload type verbatim") that became literally false the moment a heterogeneous member landed. The fix was to restate the claim precisely (which members reuse wire types, which don't) while keeping the actual security invariant — never a token/key/raw frame/bundle bytes — stated unconditionally. A stale but directionally-true comment is worse than no comment on a file whose whole point is a written invariant.

## Lessons learned

*Lifted from the PR body's "Lessons learned" section.*

- **Widening a single-member union to two forces a narrowing touch-up wherever the old single-shape was accessed structurally.** `commands.test.ts` had `expect(command.payload).toBe(fields)` directly off `sendMessageCommand`'s return type; once `RendererCommand` is a real union, `command.payload` isn't accessible without narrowing on `command.type === 'sendMessage'` first. This is the same mechanical consequence the spec called out for the six `daemonEventBridge.test.ts` call sites (`dispatch(translateDaemonEvent(...))` breaking under the `SessionAction | null` widening) — expect it any time a previously-single-member IPC union gains a second member; it's a compile-time signal, not a design smell to work around.

No React re-render / effect-cleanup surprises — the only React-adjacent file (`daemonEventBridge.ts`) changed a pure function's return type and added one `if` before an existing `dispatch` call inside an unchanged `useEffect`. No dependency-version issues. Written test-first per CLAUDE.md (RED against the unimplemented contract, then GREEN).

## Deferred / carried forward

- **#169 — the orchestrator.** Wires `requestDebugBundle` (renderer command) → `daemonConnection.requestDebugBundle(consumer)` (#116) → `saveDebugBundle` (#117) → `emitDaemonEvent` with the three new events, and maps the transport's 5-value `BundleFailReason` + save errno onto this ticket's coarse 3-value `DebugBundleFailure`. Blocked-by this ticket.
- **#72 — the download button + progress UI.** Consumes `window.pyry.sendCommand({type:'requestDebugBundle'})` and the three new `DaemonEvent`s directly (not through the session store, since `translateDaemonEvent` deliberately maps them to `null`). Re-pointed from #118 to depend on the #168/#169 pair.
- **`src/main/index.ts`'s `onCommand` switch stays non-exhaustive** through this slice — `requestDebugBundle` is a safe dropped no-op until #169 adds a case.
