# #177 — Status sheet shell: the "Run configuration" host modal

The buildable, dependency-free slice peeled from #156 (the full Status sheet) after the operator
committed to full `interactive` support and decomposed the data-bearing sections into #180/#181/
#182/#183 (gated on #179 and, for the context window, on pyrycode/pyrycode#855). Shipped as
PR #184, code-review **PASS** (3 non-blocking NITs).

## Summary

Adds the "Run configuration" host modal — the sheet chrome and its open/dismiss behaviour, with no
live data and no controls. A `StatusRow` trigger renders between `MessageThread` and `Composer`
(Figma node `16-57`): a full-width icon-only button (`aria-label="Run configuration"`,
`aria-haspopup="dialog"`), left summary region intentionally empty, `expand_less` chevron on the
right. Clicking it flips a single `sheetOpen` boolean (`useState`, ADR 0006) in `ConversationScreen`,
rendering the exported pure `StatusSheet` (Figma node `20-100`) as the last child: drag handle,
title row (`Run configuration` + `×` close), and an empty `overflow-y: auto` body follow-up tickets
populate section by section (#181 Model/Effort/YOLO, #182 Context window, #72 Log data).

The sheet is an absolutely-positioned overlay **inside** `.conversation` (now `position: relative`),
not a React portal — no App-level wiring. A dedicated `.status-sheet-overlay__scrim` div (separate
element, not the overlay's own background) sits behind the opaque panel and adds backdrop-click
dismissal without dimming the panel itself; the `×` remains the authoritative dismissal path (AC3).
Esc-to-close was left out (optional per spec, unobservable under the server-render harness).

Landing this shell unblocks #72 (Log data download), whose debug-bundle dependencies (#71/#118/#169)
were already closed but had no host modal to render inside.

## Patterns established

- **A fourth in-file sub-component role alongside Composer/UnpairControl/MessageThread**: `StatusRow`
  follows the not-exported, trivial-`useState`-glue precedent (`Composer`'s `text`,
  `UnpairControl`'s phase); `StatusSheet` follows the exported-pure-view precedent (`MessageThread`)
  so its open-state chrome is server-rendered directly without a click harness.
- **A dedicated scrim element, not the overlay's own background**, is the established way to add
  backdrop-dimming without darkening an opaque sibling panel and without introducing a bare
  `rgba()`/`color-mix` literal — `opacity` on a separate `inset: 0` div stays token-only.
- **Overlay-inside-the-screen beats a portal for a screen-scoped modal.** One `position: relative`
  on the screen's root plus `position: absolute; inset: 0` on the overlay is enough when the modal
  never needs to escape its screen's stacking context — no portal machinery, no app-level z-index
  coordination. Reusable for any future screen-local modal that doesn't need to render above route
  changes.
- **Figma fallback-hex swap confirmed a second time** (see [#166](166.md) precedent for the general
  rule): the status-row export cross-assigns `outline-variant`/`on-surface-variant` fallback hexes.
  Trust the variable name, never the exported fallback hex.

## Lessons learned

From the merged PR's own "Lessons learned" section:

- The Figma status-row export cross-assigns its fallback hexes (`outline-variant,#c2c7cf` /
  `on-surface-variant,#42474e`) — swapped relative to this repo's tokens. Trust the variable name,
  not the exported fallback hex: the row's top border is `--color-outline-variant`, muted text/icons
  are `--color-on-surface-variant`.
- Fresh worktrees ship without `node_modules`; `npm install` is needed before `npm test`/`build`. A
  stray `npx vitest` grabbed a global cache and failed on the config's `@vitejs/plugin-react` import
  — always drive through the project's `npm` scripts.

From code review (PASS, 3 non-blocking NITs — none required a follow-up ticket, noted here so a
future section ticket doesn't rediscover them independently):

- **`ConversationScreen.test.tsx`'s `not.toContain('high')` assertion is an over-broad substring
  pin** — sturdy today, but a future class name or composer hint containing `'high'` would trip it.
  A tighter key (`'· high'`, or leaning on the already-asserted `'Opus 4.7'`/`'% used'`) would be
  more robust. Worth tightening if #181 (which owns the real `high` effort value) touches this test.
- **`.status-sheet` rounds all four corners** (`--radius-lg`) as a full-width, bottom-anchored sheet,
  so the scrim shows through the two bottom corners at the window edge — faithful to the Figma
  floating-card shape, but a top-only radius or the max-width centered-card option (spec's deferred
  open question) would read cleaner for a full-width sheet. Deferred to whoever lands the desktop-
  specific layout.
- **No focus management on open/close** (`aria-modal="true"` but no focus-into-dialog / trap /
  restore-to-trigger). Accepted for this essentially-empty shell with a single focusable control;
  worth wiring once #181/#182 populate the body with multiple focusable rows and the modal claim
  needs to hold under keyboard navigation.
