# #179 — Advertise the `interactive` capability + cut the thread over to the timeline

**Prerequisite:** [#245](245.md) (the dormant `userText` `ThreadItem`/`ThreadEvent`, shipped ahead to
keep this within the file-count budget). **Size:** S. **Security-sensitive:** yes (architect
self-review PASS). **Status:** DONE, PR merged `19b25c2`.

## What shipped

The on-switch for the whole structured-stream surface the #199–#230 vertical built dormant. Three
production edits, zero new files, zero new exported types:

1. **The flip** — `daemonConnection.ts`'s `loadDialConfig` now passes
   `capabilities: [CAPABILITY_INTERACTIVE]` to `buildClientHello` (imported from
   `../../shared/wire/types`, never a bare `'interactive'` literal) — the single production call
   site, previously always `[]`. `interactive` is the whole capability vocabulary, so this turns on
   the daemon's v2 structured stream (turn state, deltas, tool use/result, thinking) and the
   `modal_shown` prompts for this connection. `parseHelloAck` already surfaced the daemon's accepted
   set on `connected{ack}` — no production change needed for AC2, only a test asserting it.
2. **The composer echo retargets** (`composerSend.ts`, `ConversationScreen.tsx`) —
   `ComposerSendDeps.dispatch` changes type from `(action: SessionAction) => void` to
   `(event: ThreadEvent) => void`; `submitMessage` now dispatches `{ type: 'userText', text: trimmed }`
   (the [#245](245.md) event) instead of a `messageSent` `SessionAction`. The `Composer` container's
   `dispatch` now reads `useTimelineStore((s) => s.dispatch)` instead of
   `useSessionStore((s) => s.dispatch)`; the send gate still reads `useSessionStore(selectStatus)` —
   two stores in one component, status and content being orthogonal facets. The `message_id` minted in
   `submitMessage` is now used for the **wire** command only.
3. **The render cutover** (`ConversationScreen.tsx`) — `TimelineRow`'s `case 'userText'` (the #245
   dormant `return null` placeholder) now draws the right-aligned user bubble
   (`.message-row--user`/`.bubble--user`, `data-thread-role="user"`, text as auto-escaped React
   children), reusing the coarse thread's user-bubble treatment verbatim. `MessageThread`'s mount and
   the `useSessionStore(selectMessages)` read are removed from `ConversationScreen`, leaving `Timeline`
   the conversation's single thread surface.

## Patterns established

- **The daemon re-echo dedup is fully retired, not just unused.** In coarse mode the daemon re-echoed
  the user's own message as a `message` envelope, deduped by reusing one `message_id` for both the
  wire send and the store echo. In interactive mode the `DaemonEvent` union has no user-message arm
  at all and the coarse fan-out is off (pyrycode #699), so the optimistic `userText` echo is
  structurally the sole source of the user's message — no dedup key is possible or needed. The
  `message_id` on the echo was dropped entirely rather than kept-but-unused. Confirmed against
  `events.ts` before making the change, not assumed from the spec.
- **`MessageThread`/`MessageBubble`/`messageViewModel.ts`/`selectMessages` are retained as
  dead-but-tested residue, not deleted.** The Strangler-Fig discipline that planted the timeline model
  (ADR 0008) alongside the coarse path continues one step further at the cutover: the coarse
  components and their tests stay green and untouched, `sessionStore.messages` stays populated but
  unread, and none of it is deleted here — a deliberate scope boundary, left to a later cleanup
  ticket, not an oversight.
- **AC5 (the fake-daemon structured round-trip) is proven at the renderer-bridge level, not
  transport-level or via a DOM click harness.** `interactiveRoundtrip.test.tsx` drives the real
  `subscribeTimeline`/`subscribeModal` bridges over an isolated store with a spy `onDaemonEvent`
  channel, then server-renders `Timeline`/`PermissionModalView` with `renderToStaticMarkup` — the
  `timelineBridge.test.ts`/`modalBridge.test.ts` precedent, not a jsdom click harness (that's out of
  scope; see #178 for the live real-daemon e2e). This was a deliberate scope boundary flagged in the
  architecture spec's Open Questions and held as designed.

## Lessons learned

- The daemon re-echo dedup rationale (reuse one `message_id` for wire + echo) is fully retired: in
  interactive mode the `DaemonEvent` union carries no user-message arm and the coarse `message`
  fan-out is off, so the optimistic `userText` echo is the sole source of the user message — no dedup
  key needed. This was confirmed against `events.ts` before dropping `message_id` from the echo,
  rather than inferred from the spec's rationale alone — worth re-verifying this kind of claim against
  the actual union/switch when a spec asserts "no arm exists," since the cost of being wrong (a
  duplicated message row) is user-visible.
- `daemonConnection.roundtrip.test.ts` is non-hermetic under the parallel full-suite run: an
  intermittent WS-upgrade 404 from a fake-relay port/server race causes occasional failures, but the
  test passes in isolation and on re-run. The 404 is a WS-layer rejection that precedes any hello, so
  it is unrelated to the `capabilities` change — flagged here so a future flaky-run investigation
  doesn't waste time suspecting this ticket's diff.
