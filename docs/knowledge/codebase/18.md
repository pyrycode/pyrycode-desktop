# #18 — Typed daemon-event channel: shared contract + background emit + preload subscribe

**Shipped:** 2026-07-03 · **Size:** S · **Scope:** shared + background + preload (`src/shared/ipc/`, `src/main/`, `src/preload/`) · greenfield IPC module, zero consumer cascade · no new dependency.
**Spec:** `docs/specs/architecture/18-typed-daemon-event-channel.md` · **PR:** [#20](https://github.com/pyrycode/pyrycode-desktop/pull/20) (review: PASS, no blocking findings).

The **event-pipe half** of the background→window bridge: a sealed `DaemonEvent` union in a new `src/shared/ipc/` module, the single `emitDaemonEvent` path to the renderer, and a receive-only `onDaemonEvent` subscription on `window.pyry`. No transport is wired yet — this is the emit seam #10/#12 will call and #19 will map onto the session store's `SessionAction`. See the [daemon-event-channel feature doc](../features/daemon-event-channel.md) for the full contract, union shape, and data flow.

Split from #16 (the same split produced #17 renderer→main commands, #18 this, #19 events→`SessionAction`). Note: `sessionStore.ts`'s doc comments still say "#3 translates daemon envelopes" — that predates the renumber; read "#3" there as "this channel work."

## Patterns established

- **`src/shared/ipc/` is the IPC-contract module**, mirroring `src/shared/wire/`. Both process sides import from it. Convention for #17: add a sibling `commands.ts` with its own `COMMAND_CHANNEL` rather than editing `events.ts` — two tickets never touch the same file, so they stay conflict-free even run near-simultaneously.
- **AC4 enforced by construction, not convention.** The union references only wire payload types with no secret-bearing field (`HelloAckPayload` / `ErrorPayload` / `MessagePayload`). Token/key/byte-carrying types (`QrPayload`, `HelloClientPayload`, `InnerFrameV2`) are deliberately *not* members — a developer cannot put a secret on this channel because no member has a field to hold one. A deterministic, compile-checked guarantee; the model to follow when adding future cross-boundary contracts.
- **Structural sink over `BrowserWindow` for testability.** Typing the emit helper's parameter as `DaemonEventSink` (`{ webContents: { send } }`) rather than `BrowserWindow` makes it plain-Node testable with a `vi.fn()` fake — no Electron harness, no mocked framework. Typing `send`'s second param as `DaemonEvent` doubles as a type-level backstop against emitting a non-event. Reuse this shape for any main-side helper that needs to touch an Electron object but shouldn't require an Electron test harness.
- **One member per `SessionAction` arm, separately declared per layer.** `DaemonEvent` mirrors `SessionAction` 1:1 in names and payload fields so #19's mapping is near-identity, but the two unions stay in separate layers (`shared/ipc` vs. renderer store) — the correspondence is a convenience, not a coupling.
- **Receive-only, `ipcRenderer`-hidden preload subscription.** Add typed methods to the `api` object; never expose `ipcRenderer`. Strip the `IpcRendererEvent` first arg in the wrapper (it leaks `.sender`/`.ports`); return an unsubscribe that `removeListener`s the exact handler registered. This is the template for future `window.pyry` event subscriptions.
- **No logging in the pipe.** Both the emit helper and preload wrapper stay log-free — a `console.log(event)` would leak `MessagePayload.text` message bodies to stdout / DevTools. Flagged for the developer and code-review as a standing guardrail on this channel.
- **Constant-pinning test for both-sides-shared strings.** `events.test.ts` pins `DAEMON_EVENT_CHANNEL` exactly like `wire/types.test.ts` pins the Noise constant; the emit-helper test asserts the channel via the imported constant (not a literal) so a rename can't silently pass.

## Lessons learned

- **`src/main` and `src/preload` have no `@shared` path alias.** Only `tsconfig.web.json` (renderer) and the `renderer` block of `electron.vite.config.ts` define it; `tsconfig.node.json` (which covers `src/main`, `src/preload`, `src/shared`) does not. So shared modules **must** be imported by **relative path** (`../shared/ipc/events`) from the main/preload sides — `@shared/ipc/events` fails both the node typecheck and the main/preload build. The renderer (#19) and vitest can use `@shared/...`. This is the load-bearing gotcha of the whole ticket, and now also recorded in project memory as `shared-alias-not-available-in-main-preload`.
- **`readonly` on an IPC-crossing array is a compile-time-only signal.** It documents no-mutate intent for consumers but is erased across the IPC structured-clone boundary (the renderer receives a fresh, mutable copy). Harmless, but don't rely on it for runtime immutability.
- **A structural interface is enough to unit-test main-process code without Electron.** The whole reason the emit helper needs no Electron mock is that it's typed against `{ webContents: { send } }`, which a `vi.fn()` object satisfies and a real `BrowserWindow` is assignable to. Prefer this to importing/mocking `electron` in tests.

## Deferred (open questions carried forward)

- **Destroyed-window guard.** `webContents.send` on a torn-down window throws. #18 defers the `isDestroyed()` guard (no live emitter to observe it). Flag when #10 wires the first real `mainWindow` emitter — either guard at the composition root or add an `isDestroyed?()` check on the sink then.
- **`connected.ack` width.** Carries the whole `HelloAckPayload`; narrow to `{ server_id, conn_id }` only if #19/#12 prove the UI needs less.
- **Preload runtime validation.** None added (trusted own-main-process producer); revisit only if a less-trusted producer ever sends on the channel.
- **`sandbox: false` in `src/main/index.ts`.** Pre-existing scaffold value, out of scope for #18 (must not touch that file). The bridge surface is `sandbox: true`-compatible; route the flip to a hardening ticket or fold into #17.
