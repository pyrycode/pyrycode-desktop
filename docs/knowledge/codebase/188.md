# #188 — Run configuration sheet: render read-only Model/Effort/YOLO sections

Render half of [#181](181.md)'s split (data path was [#187](187.md)). Shipped as PR #193,
code-review **PASS** (no blocking findings, three informational notes). Not security-sensitive —
pure renderer, reads [#187](187.md)'s store, writes nothing.

## Summary

Adds the three read-only sections the Run configuration sheet body was missing — **Model**,
**Effort**, **YOLO** — reflecting the session snapshot `RunConfigData` (#187) holds. One new file
plus a three-line mount and one token add, following the established container/pure-view split:

- **`src/renderer/src/screens/conversation/RunConfigSections.tsx`** — `RunConfigView({ model,
  effort, yolo })`, an exported pure view (no store read, no `window.pyry`) composed of three
  in-file, non-exported sub-components (`ModelSection` / `EffortSection` / `YoloSection`), each
  taking its own primitive value prop — the seam #183 makes interactive per sub-section, no
  restructuring. `RunConfigSections()` is the thin exported container: reads
  `useRunConfigStore(selectSnapshot)` and coalesces `null` → `{ model: '', effort: '', yolo:
  false }`, making AC4's two default cases (pre-snapshot `null` and a real all-defaults snapshot)
  literally the same render path.
  - **Model** — a static 3-entry catalog (`MODEL_CATALOG`: Opus 4.7 / Sonnet 4.6 / Haiku 4.5 +
    descriptors), matched by `matchedFamily(model)` — first catalog family whose token is a
    case-insensitive substring of the snapshot's `model` string, else `null`. Handles both short
    aliases (`"opus"`) and full ids (`"claude-opus-4-7"`) with one rule; `''`/unrecognized → no row
    marked (AC4). The filled radio carries `role="img" aria-label="Current model"`; empty radios are
    `aria-hidden`.
  - **Effort** — five fixed segments (`low/medium/high/xhigh/max`), exact-equality match. The
    selected segment carries `aria-current="true"`, which doubles as the CSS selection hook
    (`[aria-current='true']`) — no separate modifier class.
  - **YOLO** — a between-justified row with an `role="switch" aria-checked={yolo}
    aria-readonly="true"` control (not focusable; intentionally inert until #183 drops
    `aria-readonly` and adds `onClick`).
- **`ConversationScreen.tsx`** — one import + `<RunConfigSections />` mounted between
  `<RunConfigData />` and `<LogDataSection />` (Figma top-to-bottom order).
- **`tokens.css`** — `--color-surface-container-highest: #32353a` (M3 dark surface-container-highest,
  the switch's off-track fill; reserved for #182's context-window bar too).
- **`conversation.css`** — ~190 new lines, token-only, appended to the `.status-sheet*` block; reuses
  `.status-sheet__section-header` for all three headers.

## Patterns established

- **`aria-current`/`aria-checked` as both the a11y marker and the CSS selection hook** avoids a
  parallel `--selected` modifier class — one state, one place it's expressed, and it's what the test
  suite asserts on directly (`segmentFor` in the test file splits markup on the row/segment class and
  checks the marker text within each chunk, rather than a fragile index-based match).
- **Coalesce `null` → the same default object the store would hold on a real empty snapshot**, at
  the single container call site, so two AC-distinguished-but-visually-identical states collapse to
  one code path instead of two conditionals that could drift apart.
- **On-state styling for a control whose Figma reference only draws the off state**: reuse existing
  tokens by mirroring the platform's own semantics for the counterpart state (here, M3's on-switch:
  `--color-primary` track, `--color-surface` knob, no new token), and flag it as an open question in
  the spec rather than blocking on a design reference that doesn't exist yet — low-risk when, as
  here, the real state is unreachable until a sibling ticket (#183) lands the write path.

## Lessons learned

From the merged PR body:

- `aria-current` doubling as the CSS selection hook (see above) was called out explicitly as worth
  keeping — the a11y marker and the style stay in one place, and it's what makes each segment
  cleanly split-testable.
- The Figma reference pins only the switch's off state; the on state was built from M3 on-switch
  semantics using tokens already in the palette (`--color-primary` track, `--color-surface` knob) —
  no new on-primary token needed, and low-risk since production data is always `yolo: false` today
  (the write path, #183, hasn't landed).

Code review added no corrections — all three notes were informational (the substring-match
rationale, the intentionally-inert switch, and the unpinned on-state being pre-flagged as an open
question).
