# #19 — Translate daemon events into SessionActions in the renderer

**Shipped:** 2026-07-03 · **Size:** S · **Scope:** renderer only (`src/renderer/src/store/`, `src/renderer/src/App.tsx`) · zero consumer cascade · no new dependency.
**Spec:** `docs/specs/architecture/19-translate-daemon-events-to-session-actions.md` · **PR:** [#23](https://github.com/pyrycode/pyrycode-desktop/pull/23) (review: PASS, no blocking findings).

The **renderer translation half** of the background→window bridge: a pure, total `translateDaemonEvent` mapping each `DaemonEvent` variant ([#18](18.md)) to the matching `SessionAction` ([#2](2.md)), plus `useDaemonEventBridge`, a thin React hook that subscribes `onDaemonEvent → translate → dispatch` into the app-singleton `sessionStore` and unsubscribes cleanly on teardown. This is what makes emitted daemon events land in the store the UI renders — no transport is wired yet, so nothing emits on the channel, but the receive-and-dispatch path is now complete. See the [daemon-event bridge feature doc](../features/daemon-event-bridge.md) for the full contract and data flow.

Split from #16 (the same split produced #17 renderer→main commands, #18 the event channel, #19 this). Note: `sessionStore.ts`'s doc comments still say "#3 translates daemon envelopes" and ADR 0004 says "#3 dispatches into it" — that predates the renumber; read "#3" there as **this ticket**.

## Patterns established

- **Near-identity translation over a deliberately-mirrored union.** `DaemonEvent` was shaped in #18 with the same member and field names as `SessionAction`, so five of six arms pass their payload through **by reference** (`connected.ack`, `messageReceived.message`, `messagesReceived.messages`). The mapping's only real work is the one arm the layers disagree on. This is the payoff of "one member per `SessionAction` arm, separately declared per layer" from #18 — the 1:1 correspondence made this ticket near-trivial while keeping the two unions independently evolvable.
- **The `failed` arm is an explicit three-field copy, not a spread.** `DaemonEvent.failed` carries the wire `ErrorPayload`; `SessionAction.failed` carries the store-owned `ConnectionError`. The translation builds a fresh `{ code, message, retryable }` rather than `{ ...event.error }`, so the store shape stays immune to `ErrorPayload` gaining an unrelated field later. This realizes the exact seam [ADR 0004](../decisions/0004-renderer-session-store-reducer-wire-types.md) reserved `ConnectionError` for.
- **Local `assertNever`, not the store's export.** The exhaustiveness guard is a 3-line copy of `sessionStore.ts:59-61`'s pattern, kept module-local rather than widening the store's public surface. Adding a 7th `DaemonEvent` member with no `case` makes `event` non-`never` at the `default`, so `assertNever(event)` fails `npm run typecheck` — that type error **is** AC1's "adding a variant with no mapping is a compile-time error."
- **The effect returns the unsubscribe handle verbatim.** `useDaemonEventBridge` is a single `useEffect(..., [])` whose body is `const off = window.pyry.onDaemonEvent(...); return off`. Because #18's `onDaemonEvent` unsubscribe removes the *exact* handler it registered, a `React.StrictMode` dev double-mount (subscribe A → unsubscribe A → subscribe B) nets **exactly one** live listener — no duplicated dispatch, no doubled `messageReceived`. Handing the effect the raw handle (not a closure that drops it) is what guarantees this.
- **Dispatch-only into the app-singleton.** The hook writes through `sessionStore.getState().dispatch` — the singleton #12 will read — and reads nothing from `window` beyond `onDaemonEvent`. No `ipcRenderer`, sockets, keys, or raw frames (grep-confirmed across `src/renderer/`), so AC4 ("renderer stays transport-free") holds by construction, inherited from the receive-only bridge #18 built.
- **No logging in the pipe (standing guardrail from #18).** The translate function and hook are log-free — a `console.log(event)` would leak `MessagePayload.text` message bodies to the DevTools console. The local `assertNever` embeds `JSON.stringify(event)` in its throw, but that arm is unreachable for a well-typed `DaemonEvent` and matches the established `sessionStore.ts` idiom.

## Lessons learned

- **Structural return-typing let the developer drop the `ConnectionError` import the spec sketched.** The spec's `failed` arm imported `ConnectionError` and annotated the copy with it. In the shipped code the object literal is checked structurally against `translateDaemonEvent`'s `SessionAction` return type, so no explicit `ConnectionError` annotation (and no import) is needed — TypeScript infers and verifies the shape at the return boundary. A small simplification over the spec: when a factory returns a wide union, let the return type drive field-checking instead of importing every member type to annotate locals.
- **The pure function is the whole test surface; the hook is covered by typecheck.** Following the ticket and #2's idiom, only `translateDaemonEvent` is unit-tested (fixtures + fresh `createSessionStore()` + `dispatch` + assert state). `useDaemonEventBridge` has no Electron/IPC harness, so `npm run build` / `npm run typecheck` cover its wiring (that `window.pyry.onDaemonEvent` is typed and the effect returns a valid cleanup). The `failed → ConnectionError` freshness is asserted with `expect(status.error).not.toBe(wireErr)` — the one behavior worth a runtime check because it's the one non-pass-through arm.

## Deferred (open questions carried forward)

- **`window.pyry` guard for jsdom component tests.** The hook assumes `window.pyry` exists (true under Electron, where preload runs before the window script). If a future test renders `<App />` in jsdom without the preload, the effect throws. No guard added (no such test exists — evidence-based-fix). When `App` first gets a render test, stub `window.pyry` in test setup or inject the bridge. Flag then, not now.
- **Backfill dedupe (inherited from ADR 0004).** `messagesReceived` dispatches unconditionally; a re-delivered backfill batch with repeated `message_id`s would double-append in the store. Out of scope — owned by whichever ticket wires reconnect/backfill. This ticket faithfully translates whatever the channel delivers.
- **Call the hook in exactly one place.** Each `useDaemonEventBridge()` registers its own listener; App calls it once. A second mounting consumer would dispatch every event once per listener — the app-lifetime subscription belongs at the composition root only.
