# #191 — Carry context-window usage (`used_tokens`/`window_tokens`) on `screen_snapshot`

Transport slice of the context-window usage feature, split from [#182](182.md) alongside render
sibling [#192](https://github.com/pyrycode/pyrycode-desktop/issues/192) (blocked on this + #188).
Shipped as PR #194 (`3b2e3fb`), code-review **PASS** (one informational NIT, no corrections).
Security-sensitive (touches the daemon-decode boundary), sized S, not split — the spec argued the
~11-literal test cascade is atomic (adding two required fields to a discriminated-union arm breaks
every construct site at once; no buildable intermediate exists).

## Summary

Extends the [#180](180.md) `screen_snapshot` decode path (PR #185) to carry two always-present
integer usage figures — `used_tokens` and `window_tokens` (pyrycode/pyrycode#857, merged
2026-07-09) — onto the `snapshotReceived` event, so the Run configuration sheet's context-window
gauge (#192) has real figures to render. Four additive production edits along the existing spine,
plus the mechanical AC5 test-literal cascade the spec pre-enumerated by exact file:line:

- **Wire type** (`src/shared/wire/types.ts`) — `ScreenSnapshotPayload` gains `used_tokens: number`
  / `window_tokens: number`, appended after `yolo`, matching the daemon struct's field order (no
  `omitempty` — both always present, mirrors `internal/protocol/snapshot.go`).
- **Inbound decode** (`inboundMessage.ts`'s `parseScreenSnapshotPayload`) — two new
  `requireNumber(payload, field)` calls, the same fail-closed helper the debug-bundle `seq`/`total`
  already use. Missing or non-number throws `WireDecodeError`; `0` decodes as the value `0`, never
  treated as absent (AC3).
- **Event construction** (`daemonConnection.ts`'s `case 'snapshot'`) — the two figures ride beside
  `model`/`effort`/`yolo` in the emitted `snapshotReceived`; `text`/`ts`/`conversation_id` stay
  dropped at the same [content-minimisation seam](../features/screen-snapshot-fetch.md) #180 built.
- **Event surface** (`src/shared/ipc/events.ts`) — `snapshotReceived` extends from three fields to
  five, still a dedicated minimal shape, deliberately not a reuse of `ScreenSnapshotPayload`, so
  `text` structurally cannot leak to the renderer.

`used_tokens` is the current context size on the latest usage-bearing transcript entry (input +
cache-read + cache-creation + output) — **not a running total**; a post-compaction snapshot reports
a smaller figure. `window_tokens` is the context-window size (200000 for current models); `0` is
the daemon's "usage seam unwired/unavailable" signal. This ticket carries both faithfully as
values — it does not normalize, clamp, or interpret them (that's #192's job).

The run-config store ([#187](187.md)) stays three-field: `toRunConfigSnapshot` still maps only
`model`/`effort`/`yolo`, verified by the AC5 regression guard (its OUTPUT assertions are unchanged
even though its INPUT event literals now carry the two ints). Extending the store to hold usage is
#192.

## Patterns established

- **A required-field extension to a discriminated-union arm is a legitimate reason to accept a
  double-digit test-literal cascade as atomic, not split-worthy**, when every edit is the same
  fixed two-field append and the spec enumerates every site up front. The distinguishing test
  against a real split candidate (e.g. #29/#75-style interface renames): zero production call
  sites changed shape here — only value assertions of one already-established shape moved.
- **snake_case wire-field names on an otherwise-camelCase event union member is intentional, not
  drift**, confirmed by code review's own NIT-and-dismiss: `snapshotReceived`'s `used_tokens`/
  `window_tokens` (and pre-existing `model`/`effort`/`yolo`) mirror the wire payload names 1:1
  because the arm is a content-minimised *projection* of `ScreenSnapshotPayload`, not a fresh
  internal type — matching field names keeps the "event = wire payload minus text/ts/
  conversation_id" correspondence auditable at a glance. Reusable precedent for any future
  dedicated-minimal-shape event that mirrors a wire payload.
- **`requireNumber` is the general fail-closed numeric narrower**, not bundle-specific — this
  ticket is the second consumer (after the debug-bundle `seq`/`total`) and needed zero changes to
  the helper itself, only two more call sites.

## Lessons learned

No corrections from code review (PASS, one informational NIT dismissed above) and no "Lessons
learned" section in the merged PR body — the spec's file:line enumeration of the test cascade
(§ "Test-literal cascade — the AC5 regression guard" in the architecture spec) matched the actual
diff exactly, so there was no exploration cost or surprise to record for this one.
