# #192 — Run configuration sheet: render the session's context-window usage

Render slice of the context-window usage feature, split from [#182](182.md) alongside transport
sibling [#191](191.md) (merged first). Also the render sibling of [#188](188.md) (Model/Effort/YOLO)
— both blockers were merged before this ticket started. Shipped as PR #198 (`f7d8769`), code-review
**PASS** (no corrections, two informational notes). Not security-sensitive — pure render of
already-decoded, non-secret integers; no inbound parse, no keys, no sockets. Size S. **Last #182
child** — the split is now fully implemented and reviewed.

## Summary

Widens the held `RunConfigSnapshot` (and the `toRunConfigSnapshot` copy, [#187](187.md)) by the two
usage figures `used_tokens`/`window_tokens` ([#191](191.md) carried them to the renderer) and renders
a fourth read-only section, **Context window**, into the Run configuration sheet — between the YOLO
section ([#188](188.md)) and `LogDataSection` ([#72](72.md)), per Figma order:

- **`runConfigStore.ts`** — `RunConfigSnapshot` gains `usedTokens: number` / `windowTokens: number`,
  both required (parallel to `model`/`effort`/`yolo` — held verbatim, never coerced). The "usage
  unavailable" state is expressed as `windowTokens === 0`, not `undefined`.
- **`runConfigSnapshot.ts`** — `toRunConfigSnapshot`'s `snapshotReceived` arm maps the wire snake_case
  (`event.used_tokens`/`event.window_tokens`) to the store's camelCase, explicit-copy (not spread),
  unconditional — `window_tokens: 0` flows through verbatim like every other untouched field.
- **`RunConfigSections.tsx`** — `RunConfigView` gains the two props and renders the new
  `ContextWindowSection` as its last child. The container's null-default gains `usedTokens: 0,
  windowTokens: 0`, which is the load-bearing move: **the not-yet-loaded default and the daemon's
  "usage unavailable" signal collapse into the same `windowTokens > 0` branch**, so `ContextWindowSection`
  only has one guard to reason about, and the division only ever runs inside it (AC5 — no NaN, no
  Infinity, no divide-by-zero).
  - Available (`windowTokens > 0`): usage line `` `${pct}% used (${abbreviateTokens(usedTokens)} of
    ${abbreviateTokens(windowTokens)} tokens)` ``, a `role="progressbar"` track/fill with the fill's
    width set inline per render, `aria-valuenow`/`aria-valuemin`/`aria-valuemax`/`aria-label`.
    `pct = clamp(round(used/window*100), 0, 100)` — an over-full session clamps to "100% used" and the
    fill can't overflow its track; the raw abbreviated figures stay honest either way.
  - Unavailable (`windowTokens <= 0`): a single muted "Context usage unavailable" line in place of the
    usage line + bar — no `role="progressbar"`, no division. `<= 0` (not `=== 0`) also absorbs a stray
    negative defensively.
  - `abbreviateTokens(n)` — `n >= 1000 ? \`${round(n/1000)}K\` : String(n)` — an in-file, unexported
    one-liner; both it and `ContextWindowSection` stay unexported (0 new public surface).
- **`conversation.css`** — six `.run-config__context-*` rules after the `.run-config__yolo-*` block,
  token-only (`--color-success` fill, `--color-surface-container-highest` track,
  `--color-on-surface`/`--color-on-surface-variant` text, `--radius-full`, `--space-1/2/4`). Zero new
  tokens — both consumed tokens were already ported ahead of time by [#188](188.md).

## Patterns established

- **A container's null-coalesce default doubles as the daemon's own "unavailable" sentinel when both
  map to the same falsy/zero value.** [#188](188.md) established this for `null → { model: '',
  effort: '', yolo: false }`; this ticket repeats it one field further: `windowTokens: 0` is
  simultaneously "no snapshot has arrived yet" and "the daemon says usage is unavailable" — one
  branch (`windowTokens > 0`), not two conditionals that could drift apart. Reusable whenever a new
  snapshot field's "absent" state and its "not-yet-loaded" default happen to coincide.
- **Clamp the displayed percentage, not just the bar width**, when a fill-bar gauge can go over 100%
  of its source range — a `Math.min(100, …)` on the *number shown in text* keeps the copy ("100%
  used") and the visual (a bar that can't overflow its track) in agreement, while the raw abbreviated
  figures ("210K of 200K tokens") stay honest about the overflow. Code review flagged this as the
  spec's chosen resolution of an explicitly open question, not a defect — worth a PO confirmation but
  not a blocker.

## Lessons learned

From the merged PR body:

- `renderToStaticMarkup` escapes apostrophes in text content to `&#x27;` — a "verbatim copy" assertion
  on the explainer string ("claude's") must assert the **escaped** form, not the raw string, or the
  test fails against real output despite the rendered text being correct.

Code review added no corrections — both notes were informational: the percentage-clamp-vs-raw-overflow
choice (above, PO-facing not a bug) and a pre-existing stale comment in `ConversationScreen.tsx`
("#182 prepends the Context-window section... as it lands") now outdated by this ticket's landing —
correctly left untouched per "don't refactor adjacent code," flagged for a future sweep instead.
