# #197 — Queue slice: apply the connect-time `queue_state` snapshot as replacement truth on reconnect

PR #418 (`fe7871d`, spec `8070305`). Split-child B of #196 (2-way split; sibling #415 owns the separate
modal `outstanding` reconnect reset, shipped first). Size S, as estimated. Not security-sensitive
(renderer-only, reacting to an already-typed `connected` event). Not UI-visible — pure store + data-path,
queue render already shipped in #294. Code review: PASS, two non-blocking NITs.

## Summary

Applies the same daemon connect-time reconcile contract #415 applied to the modal slice
(pyrycode/pyrycode#878, wire pyrycode/pyrycode#879) to the renderer's queue store. The relay supervisor
re-emits `connected` on every (re)handshake — v2 has no session resume — and the daemon then re-sends one
`queue_state` snapshot per **non-empty** conversation. Before this ticket nothing reset the queue store's
`backlogs` map across that boundary, so a conversation that fully drained while the user was away kept
showing its stale pre-drop backlog (the daemon doesn't re-send an empty conversation, so there was no
event to correct it).

Two additive production edits, both in [queue store](../features/queue-store.md)'s two files:

- **`queueStore.ts`** — new `resetBacklogs: () => void` on `QueueStore`, alongside the existing
  `setBacklog`. Clears the whole `backlogs` map copy-on-write (`set({ backlogs: new Map() })`), but
  returns the **same state reference** when the map is already empty (`s.backlogs.size === 0 ? s : ...`)
  so zustand's `Object.is` short-circuits — no listener churn on a first connect or a reconnect that held
  nothing. This is the #415 empty-slice no-op twin, adapted from a flat array length check to a map size
  check. Still two named setters, not a discriminated-union action set — #293 deliberately chose direct
  setters for exactly this reason (ceremony not warranted for two operations).
- **`queueBridge.ts`** — `subscribeQueue` widened with a third required parameter, `resetBacklogs: ()
  => void`. The listener gains a leading branch: `if (event.type === 'connected') { resetBacklogs();
  return }`, before the existing `translateQueueState`/`setBacklog` path. `event.ack` is never read — the
  branch checks only the discriminant. `translateQueueState` itself is **unchanged and stays pure** (still
  `queueState` → snapshot, `default: null`) — the reset is a listener branch, not folded into the
  translator, which is the one structural difference from #415 (there, `connected` moved *into* the modal
  translator as a `reconnected` `ModalEvent` arm, because the modal bridge routes everything through a
  reducer-style event union; the queue store has no event union to extend). `QueueData` now passes `()
  => queueStore.getState().resetBacklogs()` as the third argument, alongside the existing `setBacklog`
  closure — one listener still owns both writes, so reset-before-repopulate rides the same in-order
  channel with no new ordering logic.

Repopulation is not new code — it rides the existing `setBacklog` unchanged, exactly as #415's
repopulation rides the idempotent `shown` arm. Because an absent key reads `EMPTY_BACKLOG` (#293), clearing
the whole map wholesale **is** "every held backlog is now empty" — no per-key eviction loop was needed,
and `selectBacklogs` (the whole-map read #293 added "explicitly for #197" anticipating such a loop) ended
up with no production consumer (see Patterns established, below).

Ordering (reset-before-repopulate) is the same transport-level guarantee #415 relied on, not something
this ticket built: `daemonConnection.ts` emits `connected` at handshake-complete strictly before its
inbound loop re-sends `queue_state`, and the single daemon-event channel delivers in arrival order,
dispatched synchronously per event.

New vitest cases: 4 store-level (`resetBacklogs` clears every held backlog; empty-map reset is a
same-reference no-op; reset-then-`setBacklog` repopulates one conversation, replacement truth unchanged;
reference stability across updates) plus seam-level tests proving all three AC4 reconnect outcomes through
the real store — dequeued-while-away does not resurrect, **including the strong fully-drained form** (a
conversation with no re-send after `connected` reads `[]`, not its stale pre-drop backlog); queued-while-away
appears; an untouched backlog reads identically (content-equal, not reference-equal — the re-sent array is
a fresh literal) across a reset-then-re-send round trip. All 7 existing `subscribeQueue` call sites gained
the new third argument. `npm test` (1937 pass, 3 pre-existing skips), `npm run typecheck`, `npm run build`
all clean.

## Patterns established

- **A reconnect reset is a listener branch when the bridge has no event union to extend, a translator
  arm when it does.** #415's modal bridge already routes every `DaemonEvent` through a pure
  `translate…`-to-union-then-reduce pipeline, so `connected` became a new union member there. #293's queue
  bridge is direct-setter, no event union — so #197 branches inside the subscription listener instead of
  inventing a union just to hold one reset case. Same reset contract (bare trigger, one slice cleared,
  same-reference no-op when already empty), two different mechanical homes depending on what the slice's
  bridge already looks like — pick the shape the existing bridge already uses, don't force the other
  ticket's shape onto it.
- **A speculative read surface added "for" a future ticket can go unused once the design lands.**
  #293 added `selectBacklogs` (the whole-map read) explicitly anticipating a per-key eviction loop for this
  ticket; the as-built design clears the whole map wholesale instead and never calls it. Per CLAUDE.md
  ("don't refactor adjacent code while you are there"), the consuming ticket correctly left the unused
  export and its stale doc comment alone rather than retiring them — that cleanup is a separate follow-up,
  not bundled into the ticket that revealed the export was unneeded.

## Lessons learned

From the PR body's Lessons-learned section:

> The reset is a **listener branch, not a translator mapping** — the deliberate structural difference from
> #415, where `connected` moved *into* the modal translator. Keeping `translateQueueState` pure (still
> `queueState`→snapshot, `connected`→null) is pinned by an explicit null-arm assertion, so a future reader
> doesn't "fix" the translator to map `connected`.
