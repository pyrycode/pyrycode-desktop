# #201 — Decode `modal_shown` / `modal_dismissed` into typed `DaemonEvent` arms

Transport slice of the modal vertical (ADR [0009](../decisions/0009-modal-prompt-model.md)), first of
six: **#201 (this, transport)** → #223 (store + bridge) → #224 (interactive render) → #225 (answer
path) → #226 (second-confirm) / #227 (surface rejection). Shipped as PR #228 (`592596f`), code-review
**PASS** (no MUST/SHOULD-FIX). Security-sensitive (adds two wire types decoded from the relay socket);
size S; a near-exact structural clone of [#214](214.md) (`turn_state`) and [#217](217.md) (`tool_use`)
scaled to **two** inbound frames, with two new twists: two closed wire enums instead of one, and a
nested ordered array of objects (`options: [{ id, label }]`) decoded via a per-element narrower.
**No store, no render, no `interactive` flip.**

## Summary

Before this ticket, `modal_shown` / `modal_dismissed` envelopes were unmodeled and fell through
`parseInboundMessage`'s `default → inbound-unmodeled → null`. The renderer-side pure model this
vertical folds into — `reduceModal` / `ModalEvent` — already shipped in [#122](122.md)
([modal-prompt model](../features/modal-prompt-model.md), ADR 0009) with nothing feeding it. This
ticket adds the six thin, additive touchpoints — the architectural floor for any new inbound
`DaemonEvent` once both `assertNever`-guarded bridges exist (established by [#214](214.md)):

- **Wire types** (`src/shared/wire/types.ts`) — `WireModalClass = 'permission' | 'trust'` (**no**
  `destructive` — a stricter-than-wire, deliberate no-drift narrowing; the daemon models `class` as an
  open string), `WireModalSource = 'remote' | 'local' | 'timeout'`, `WireModalOption { id; label }`,
  `ModalShownPayload { modal_id; class; title; prompt; options; default_option_id }`,
  `ModalDismissedPayload { modal_id; outcome; source }` — all fields always present (no `omitempty`).
  `'modal_shown'` / `'modal_dismissed'` join `EnvelopeType`. **No `conversation_id` on either payload**
  — `modal_id` is the sole correlation key (a one-time nonce), the load-bearing fact ADR 0009 fixed.
- **Inbound decode** (`inboundMessage.ts`) — `{ kind: 'modal-shown'; modalShown }` /
  `{ kind: 'modal-dismissed'; modalDismissed }` join `InboundDaemonMessage`. `parseModalOption` is the
  per-element narrower (two required strings, sibling of `parseConversationSummary`).
  `parseModalShownPayload` clones `parseTurnStatePayload`'s **closed three-way→two-way literal
  comparison** for `class` (`cls !== 'permission' && cls !== 'trust'` → throw — **not** `requireString`,
  which would defeat the enum boundary), then `options` array-guard + `raw.map(parseModalOption)` (one
  bad option throws the whole frame closed, empty array tolerated). `parseModalDismissedPayload` clones
  the same idiom for `source` (`!== 'remote' && !== 'local' && !== 'timeout'`); `outcome` stays a plain
  `requireString` (opaque, never enum-checked). Both `case 'modal_shown'` / `case 'modal_dismissed'`
  narrow before logging (`inbound-decoded{code, bytes, hash}`, no decoded field). Every error message
  names the failure category only — never `title` / `prompt` / `options[].label` / `outcome` /
  `modal_id` / `class` / `source`.
- **Consumer emit** (`daemonConnection.ts`) — `case 'modal-shown'` / `case 'modal-dismissed'` in
  `switch (inbound.kind)`, fresh literals with `modal_id`→`modalId`, `default_option_id`→
  `defaultOptionId`; `options` reused **verbatim** (the `conversations` precedent —
  `parseModalOption` already stripped each option to `{ id, label }`, nothing to drop). **No
  `conversation_id` dropped** — none is carried (contrast `turn-state`/`tool-use`, which drop a real one).
- **`DaemonEvent` arms** (`src/shared/ipc/events.ts`) — `{ type: 'modalShown'; modalId; class; title;
  prompt; options: readonly WireModalOption[]; defaultOptionId }` / `{ type: 'modalDismissed'; modalId;
  outcome; source }`. Field names/types mirror `ModalEvent` (#122) so the #223 bridge is a thin rename.
- **Session bridge (no-op)** — `daemonEventBridge.ts` adds `case 'modalShown': case 'modalDismissed':
  return null` (present only for the `assertNever` exhaustiveness proof; the real consumer is #223).
- **Timeline bridge (also no-op)** — `timelineBridge.ts` adds both arms to the **inverse-filter**
  `return null` list (alongside `conversationsReceived`), **not** the owned block — a modal is neither
  a session action nor a timeline event.

`npm test` (901 pass, 3 pre-existing skips), `npm run typecheck`, `npm run build` all green. 6
production files touched, 0 new files (the spec's predicted scope-self-check floor, same as #214/#217).

## Patterns established

- **A second closed-wire-enum field in the same payload reuses the `role`/`state` idiom without
  modification.** `class` and `source` are two independent instances of the single three-way (now
  two-way and three-way) literal-comparison check in one ticket — the idiom scales to more than one
  field per payload, not just one field per ticket (#214 was the idiom's second instance file-wide;
  #201 is its third and fourth).
- **A nested ordered array of objects decodes via a per-element narrower mapped over the array**,
  cloning `parseConversationsPayload`'s `raw.map(parseConversationSummary)` shape exactly:
  `parseModalOption` returns only the known fields, one bad element fails the whole frame, an empty
  array is tolerated. This is the pattern's second use (`conversations` rows were the first) and
  confirms it generalizes to any inbound array-of-structs field, not just top-level list replies.
- **A wire payload with no `conversation_id` is not an omission to flag** — it's the frame's actual
  shape (ADR 0009: the daemon resolves `modal_id` against its own outstanding-modal state, one active
  conversation). The consumer emit correspondingly drops nothing, unlike every prior `DaemonEvent` arm
  in this stream (`turnState`/`toolUse`/`assistantDelta`/`turnEnd` all drop a real `conversation_id`).

## Lessons learned

- No PR-body "Lessons learned" section was written — the implementation tracked the spec exactly with
  no deviation, mirroring #214/#217's zero-correction outcome. The one thing worth flagging forward:
  code review explicitly re-verified (not just trusted the spec) that the shipped decoders use the
  literal `!==` enum comparisons on `class`/`source` rather than `requireString` — the architect's
  security review had called this out as the one place a developer might reach for the familiar
  `requireString` helper and silently weaken the boundary. It shipped correctly; future enum-field
  tickets should expect the same explicit re-verification step in review, not just a spec citation.

## Open questions carried forward

- **`class` value evolution is higher-consequence than #214's `state`.** A future daemon class (SSOT
  #701 names *plan-approval* / *tool-confirmation* as possibilities) fails closed here — the **whole
  modal drops**, and unlike a dropped `turn_state` phase indicator, a modal is a prompt `claude` is
  *blocking on*. Widening is a coordinated 3-touch change: `WireModalClass` (this ticket) +
  `ModalClass` ([modalPrompts.ts](../features/modal-prompt-model.md), #122) + the decoder. #223/#224
  should note this before assuming a wider `class` set is safe to add unilaterally.
- **`default_option_id ∈ options[].id` is not cross-checked at decode** — deferred to render (#224) as
  a harmless degenerate case (pre-highlights nothing; answering still needs an explicit user action,
  #225).
- **Untrusted free text now has a real wire path to the renderer, unconsumed.** `title` / `prompt` /
  each `options[].label` are untrusted `claude`-surfaced strings carried onward by this slice's
  `DaemonEvent` arms (both bridges currently discard them as `null`). #224 must render them as plain
  text, never HTML — the `assistant_delta`/#203 + `tool_use`/#218 React-auto-escape precedent, now
  forwarded a third time.
- **Inner-switch exhaustiveness remains deferred** (`daemonConnection.ts`'s `switch (inbound.kind)` has
  no `default: assertNever`) — now four-tickets deferred (#180, #199, #214, #217, #201). The
  `daemonConnection.test.ts` emit test remains the deterministic safety net.
- **The real consumer — a third bridge + `modalStore` — is still #223.** Both existing bridges only
  prove exhaustiveness; nothing today maps `modalShown`/`modalDismissed` onto `reduceModal`.
