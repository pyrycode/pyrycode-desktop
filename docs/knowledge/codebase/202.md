# #202 — Land the streamed assistant events in a conversation-timeline store

The renderer data-path slice (L2) of the Phase-2 structured-streaming vertical, split from #199
along the transport → store → render seams the snapshot vertical (#180 → #187/#188) proved. Shipped
as PR #210 (`d93f1b2`), code-review **PASS** (no MUST/SHOULD-FIX, two informational NITs). Not
security-sensitive; no Figma (headless, no render surface). Size S.

## Summary

Adds the two renderer pieces the [thread timeline](../features/thread-timeline.md) model (#121) was
missing: a Zustand store wrapping `reduceTimeline`, and a `daemonEventBridge`-shaped translator +
binding that maps the two v2 stream `DaemonEvent` arms (#199's `assistantDelta`/`turnEnd`) into
`ThreadEvent`s and feeds it. Purely additive — **4 new files, 0 existing prod files touched**
(Strangler Fig continues: nothing reads the timeline store yet, the coarse `message` path is
unaffected):

- **`src/renderer/src/store/timelineStore.ts`** — `createTimelineStore(init?)` (vanilla
  `createStore`, DI seam) → `timelineStore` (app singleton) → `useTimelineStore(selector)` (narrow-
  slice hook), mirroring `createSessionStore`'s factory shape (ADR 0004) rather than
  `runConfigStore`'s single-setter shape, since there's a real reducer + event set to wrap. `dispatch`
  is the sole mutation path: `set((s) => reduceTimeline(s, event))`. No `observe?` param — the #134
  diagnostics seam is session-only. Re-exports `selectItems`/`selectPhase` from `threadTimeline.ts`
  (never redefines them) as #203's single import site.
- **`src/renderer/src/store/timelineBridge.ts`** — `translateTimelineEvent(event): ThreadEvent | null`,
  the pure choke point mirroring `daemonEventBridge`'s `translateDaemonEvent`. Owns exactly
  `assistantDelta`/`turnEnd`, each rebuilt as a fresh named-field literal (never `return event`,
  never a spread); every other arm (all 11 of the remaining `DaemonEvent` members) falls through to
  `return null`, then `default: assertNever(event)` — a **hard** exhaustiveness guard, not a
  catch-all `default: return null`, so a future `DaemonEvent` arm is a compile error here until
  handled. `subscribeTimeline(onDaemonEvent, dispatch)` extracts the pure subscription (the
  `subscribeRunConfig` idiom) for spy-testability; `useTimelineBridge()` wraps it in a
  `useEffect(() => subscribeTimeline(window.pyry.onDaemonEvent, e => timelineStore.getState().dispatch(e)), [])`
  returning the off handle as cleanup — StrictMode double-mount nets exactly one live listener,
  mirroring `useDaemonEventBridge`.

This is the mirror image of `daemonEventBridge`: that bridge returns `null` for these two arms and
owns the rest; this one owns exactly these two arms and returns `null` for everything else — two
independent subscribers on the same `onDaemonEvent` channel.

12 new tests (`timelineStore.test.ts` + `timelineBridge.test.ts`): store wiring (initial state,
dispatch-threads-reducer coalesce, `turnEnd` append, DI isolation between two instances);
per-arm translation (both owned arms `.not.toBe(event)` fresh-object check, all 11 other arms
enumerated → `null`); `subscribeTimeline` lifecycle (subscribe-once, translate+dispatch, unowned-arm
no-op, off-handle cleanup); and the spec's AC2 end-to-end test driving two same-turn `assistantDelta`s
through `subscribeTimeline` into a real `createTimelineStore()`, asserting one coalesced
`assistantText` via `selectItems` — no React involved anywhere. `npm test` (776 pass, +12 new),
`npm run typecheck`, `npm run build` all green.

## Patterns established

- **A translator's `null`-return arm belongs to a hard `assertNever` default, not a soft
  catch-all — even in a bridge that owns only two of thirteen arms.** `toRunConfigSnapshot` (#187)
  deliberately uses a soft `default: return null` because it permanently consumes exactly one arm
  forever; `translateTimelineEvent` here uses `assertNever` because a *future* `DaemonEvent` arm
  must force a decision at both stream-consuming bridges simultaneously, not silently degrade to
  `null` at this one. The rule isn't "translators default to null" — it's whether new arms should be
  allowed to silently opt out (soft default) or must be explicitly triaged (hard `assertNever`).
- **Two independent exhaustive/non-exhaustive consumers can coexist on one sealed union without
  merging their concerns.** `daemonEventBridge` and `timelineBridge` are both `assertNever`-guarded
  over the same `DaemonEvent` union, each mapping a disjoint subset of arms to real actions and the
  rest to `null` — proving out the "independently exhaustive" pattern the daemon-event-bridge feature
  doc already named for the debug-bundle arms, now doubled to two full bridges rather than one bridge
  plus a direct-subscriber UI (#72).

## Lessons learned

- `useTimelineBridge` has no dedicated test — a bare hook is untestable without a React renderer
  (none in this repo), exactly as `useDaemonEventBridge` has none. Its behavior is fully carried by
  the pure `subscribeTimeline` spy tests (subscribe-once, translate+dispatch, unowned-arm no-op,
  off-handle cleanup) plus the AC2 end-to-end test through a real store. Stated explicitly in the PR
  body so code review read it as intentional, not a gap — and it did (see code-review PASS above).
