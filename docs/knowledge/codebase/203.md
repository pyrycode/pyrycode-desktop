# #203 — Render the streamed assistant text on the conversation timeline

The render slice (L3) of the Phase-2 structured-streaming vertical: transport ([#199](199.md)) →
store ([#202](202.md)) → **render (#203)**. Shipped as PR #212 (`c304a08`), code-review **PASS**.
Not security-sensitive — pure renderer of already-decoded text; no keys, sockets, or raw bytes. Size
S: three files touched, no new files.

## Summary

Adds the `Timeline` pure view — `MessageThread`'s twin — and mounts it and its feeding bridge, so
[the timeline store](../features/conversation-timeline-store.md) (#202) finally has a reader:

- **`Timeline({ items }: { items: readonly ThreadItem[] })`** — new in-file, exported component in
  `ConversationScreen.tsx`, alongside `MessageThread`. Maps `items` → rows 1:1 in array order inside
  a reused `.conversation__thread` div; empty `items` → `null` (zero layout footprint — AC4's
  pixel-identical requirement, since the store stays empty until #179 flips `interactive`). Per-item
  render by `kind`, via `TimelineRow`, an exhaustive `switch` with **no `default`/`assertNever`**:
  - `assistantText` → `<div class="message-row message-row--daemon"><div class="bubble
    bubble--daemon" data-thread-role="assistant">{text}{cursor?}</div></div>` — text as React
    children (never `dangerouslySetInnerHTML`), discharging #199's untrusted-text handoff.
  - `toolCall` → `null` (no source until #205/#206; a legitimate union member that must not crash the
    switch).
  - `turnBoundary` → `null` (structural only; Figma has no per-turn divider).
- **Streaming cursor** — `<span class="bubble__cursor" aria-hidden="true">▎</span>` (U+258E),
  rendered only when `index === lastIndex && item.kind === 'assistantText'`. Derived structurally
  from array position, never from `selectPhase` (which has no source until #204 — always `idle`
  here). CSS: a 1s step-end opacity blink, guarded by `@media (prefers-reduced-motion: reduce)`.
  Reuses `.bubble--daemon`'s color/size — no new token.
- **React key = array index**, with an inline comment justifying it: the list is append-only with
  tail-mutation and never reorders or inserts mid-list (verified against `threadTimeline.ts`'s
  `appendDelta`/`fillResult`), so index identity is stable per logical item — `turnId` alone would
  collide post-#205 (a tool can split one turn into two `assistantText` items), and any text-bearing
  key would remount the growing bubble on every delta.
- **`ConversationScreen`** — additive: `const items = useTimelineStore(selectItems)`, then
  `<Timeline items={items} />` right after `<MessageThread messages={messages} />`. No adapter —
  `ThreadItem` is already the render model (ADR 0008).
- **`App.tsx`** — `useTimelineBridge()` mounted right after `useDaemonEventBridge()`, both deref
  `window.pyry` only inside their effect so `<App/>`'s server-render test stays `''`.

8 new tests in `ConversationScreen.test.tsx` (`describe('Timeline — the streamed assistant text')`):
empty-is-inert, one bubble with text + treatment, untrusted text escaped (no live `<b>`), cursor
present on an open tail / absent once closed by a `turnBoundary`, order preserved with cursor only on
the tail across two turns, `toolCall` safe no-op (no throw, no bubble), lone `turnBoundary` draws
nothing — plus one container smoke test (`ConversationScreen` against the empty store contributes no
`bubble__cursor`). `npm test` (805 pass), `npm run build` green.

## Patterns established

- **Exhaustive switch with no `default`/`assertNever` is the render-path analog of the reducer's hard
  guard, but degrades instead of throwing.** `TimelineRow`'s switch is exhaustive over today's three
  `ThreadItem` kinds (two returning `null`); a future fourth kind makes it a compile-time "not all
  code paths return" error, forcing a render decision — while `toolCall`, unsourced today but a real
  union member, safely renders nothing rather than crashing the thread the moment #205 feeds one.
  Contrast with #202's `timelineBridge`, which uses a **hard** `assertNever` default because a new
  `DaemonEvent` arm there must be explicitly triaged, not silently dropped — the same union, two
  different consumer-side severity calls, justified by what's at stake on each side (compile error
  either way; the render side additionally can't throw at runtime on an already-shipped kind).
- **Index-as-React-key is safe when the list is provably append-only with tail-mutation and no
  reorder/insert.** Verified against the reducer's actual arms (`appendDelta` grows the tail in
  place, every other arm appends a new tail, `fillResult` replaces in place) rather than assumed —
  documented inline so review reads it as a deliberate, checked exception to the usual index-key
  smell, not an oversight.
- **Cursor derived from array position, never from a phase/status enum that has no source yet.** When
  a spec offers two ways to compute a boolean and one of them (`phase`) is provably always the same
  value in this slice, derive from the data that's actually live (`items` tail-check) rather than
  wiring a dead read that looks correct but never varies.

## Lessons learned

From the merged PR body:

- The exhaustive `switch` over `ThreadItem` with no `default`/`assertNever` compiles today (3 kinds,
  2 returning `null`) and turns a future 4th kind into a compile-time "not all code paths return"
  error — the render-path analog of the reducer's guard, but degrading unknown kinds to nothing
  rather than throwing (safe for `toolCall`, which has no source until #205).
- Verified against Figma node `16:56`: the cursor abuts the text with no stray whitespace inside the
  same `.bubble--daemon` — JSX strips the whitespace-only newline between `{item.text}` and the
  cursor expression, and the glyph on its own line inside the span trims to `▎`.

Code review added no corrections (PASS, no MUST/SHOULD-FIX).

## Open question (flagged for #179, not resolved here)

**Dual-thread layout at the `interactive` cutover.** Today only `MessageThread` has content and the
empty `Timeline` returns `null`, so the layout is pixel-identical (AC4 clean). After #179 flips
`interactive` and the coarse `message` fan-out stops (pyrycode #699), `MessageThread` will render an
*empty* `.conversation__thread` (still `flex: 1 1 auto`) beside the now-populated `Timeline` — a
half-height dead region. #203 does not touch this (flipping/gating here would violate "no
`interactive` flip in this slice"); #179 owns reconciling it, e.g. render one thread or the other off
the interactive flag, or have `MessageThread` return `null` when empty.
