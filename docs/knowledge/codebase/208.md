# #208 — Observe the conversation list into a renderer store slice

The store half of the conversation-list data foundation (mirror mobile #312), split from #139 and
blocked by it (#139 shipped as PR #209). Shipped as PR #211 (`410b896`), code-review **PASS** (no
findings). Not security-sensitive (pure renderer state fed by an already-typed event); no Figma
(headless, no visible surface). Size S.

## Summary

Adds the two renderer pieces the conversation-list data path was missing: a dedicated Zustand store
and a subscription binding that feeds it, mirroring the run-config data path (`runConfigStore` #187 /
`runConfigSnapshot` + `RunConfigData` #181) exactly. Three new prod files, one existing file touched
(~295 LOC total):

- **`src/renderer/src/store/conversationListStore.ts`** (new) — `ConversationListState { conversations:
  readonly ConversationSummary[] | null }`, `null` the distinct not-loaded sentinel (mirrors
  `runConfigStore`'s `snapshot: null`). `createConversationListStore(init?)` (vanilla `createStore`,
  DI seam) → `conversationListStore` (app singleton) → `useConversationListStore(selector)`
  (narrow-slice hook, first consumer is #141) → `selectConversations`. A **single setter**
  (`setConversations`), not a reducer — there is exactly one mutation, "record the latest list," so a
  discriminated-union action set would be a one-member union. Replaces the whole array unconditionally
  (most recent wins, no merge, no dedupe); no coercion, no validation. Rows are held **verbatim in
  wire snake_case** — unlike `runConfigSnapshot` (which remapped `used_tokens → usedTokens`), this
  reuses `ConversationSummary` as-is, so the slice needs zero per-field transform and stays drift-free
  against the mobile wire contract. No derivations baked in: no `kind` enum, no "unnamed" flag — #141
  derives those from `is_promoted`/`name === null` at its own read boundary.
- **`src/renderer/src/store/conversationListBridge.ts`** (new) — three React-free helpers plus the
  headless binding:
  - `translateConversationsEvent(event): readonly ConversationSummary[] | null` — a `switch` with one
    `case 'conversationsReceived': return event.conversations` and `default: return null`. Uses the
    **soft** `default: null`, not `assertNever` — deliberate, mirrors `toRunConfigSnapshot`: this path
    permanently consumes only `conversationsReceived`, so a third `assertNever` on the `DaemonEvent`
    channel would make every future arm a compile error in three files for no benefit. Returns
    `event.conversations` directly (a filter, not a rename — no fresh-literal reconstruction needed,
    unlike `translateTimelineEvent`'s owned arms).
  - `requestConversationList(sendCommand)` — `sendCommand({ type: 'requestConversations' })`, a bare
    inline literal, no new command or builder (#139 already wired the main side).
  - `subscribeConversations(onDaemonEvent, setConversations)` — subscribes, translates, and writes on
    `list !== null` (not `if (list)` — the explicit `!== null` check makes "an empty list is a real
    write, loaded-zero not not-loaded" unmistakable to a reviewer); returns the off-handle.
  - `ConversationListData(): null` — a headless component with two effects: (1) subscribe on mount
    (deps `[]`), off-handle as cleanup, StrictMode-safe one listener; (2) request on the rising edge to
    `connected` (deps `[isConnected]`, `isConnected = useSessionStore(s => s.status.type ===
    'connected')`), guarded by a `useRef(false)` that resets to `false` while disconnected and fires
    exactly one request per connection episode (StrictMode double-invoke included).
- **`src/renderer/src/App.tsx`** (mod, ~10 lines) — wraps the existing `<AppView/>` return in a
  fragment and mounts `<ConversationListData/>` as a sibling, app-level, alongside
  `useDaemonEventBridge()`. A **component**, not a hook called directly in `App` — isolates the
  `useSessionStore` connected-gate read in the leaf so a status flip re-renders only the leaf, not
  `App` (whose inline `onPaired`/`onUnpaired` arrows are unstable and would otherwise cascade a
  re-render into `ConversationScreen`).

20 new tests across `conversationListStore.test.ts` (9) and `conversationListBridge.test.ts` (11):
store not-loaded start, setter records/replaces (most-recent-wins), empty-list-is-loaded-zero,
verbatim-snake_case-row-including-`name:null`, DI independence, stable setter reference; bridge
per-arm translation (owned arm + a sample of unrelated arms → `null`, including empty-list →
`[]`-not-`null`), `requestConversationList` calls `sendCommand` exactly once, `subscribeConversations`
write/no-op/cleanup, and the AC5 not-loaded→loaded integration test wiring a real
`createConversationListStore()` through `subscribeConversations`. `ConversationListData`'s effect
timing is not unit-tested (mirrors `RunConfigData`'s precedent — untestable without a React renderer);
`App.test.tsx`'s `renderToStaticMarkup(<App/>) === ''` neutral-paint test stays green. `npm test` (796
pass, +20 new), `npm run build` clean.

## Patterns established

- **A per-connection-episode request trigger, not fire-once-ever.** The `useRef` guard resets to
  `false` on every transition away from `connected`, so a reconnect gets a fresh list and a request
  lost to a mid-flight disconnect recovers on the next connect — a natural extension of `RunConfigData`'s
  one-shot-per-mount idiom to a lifecycle that repeats. The whole-list-replace setter makes each
  re-request's arrival idempotent, so no additional bookkeeping is needed to make repeated requests
  safe.
- **Isolate a store-read gate in a headless leaf, not the app-root component.** Confirmed as the
  general answer to "where do I read a store inside App.tsx without cascading re-renders": `App` itself
  subscribes to no store (only `useState` + effect-only `useDaemonEventBridge`), so any component that
  needs a live store read for its own gating logic belongs in its own headless leaf, not inlined into
  `App`'s body.

## Lessons learned

- The `ConversationListData` binding is a **component**, not a hook called in `App`: its connected-gate
  `useSessionStore` read must be isolated in a headless leaf, otherwise status flips would subscribe
  `App` and cascade a re-render into `ConversationScreen` through `App`'s unstable inline
  `onPaired`/`onUnpaired` arrows. This diverges from `timelineBridge`'s hook form (`useTimelineBridge`)
  because no list render-component exists yet to host a hook — a dedicated headless mount is the
  app-level equivalent.
- The filter uses `default: null` (the `toRunConfigSnapshot` precedent), not `assertNever` — this path
  permanently consumes only `conversationsReceived`, so a third `assertNever` on the channel would make
  every future arm a compile error in three files without benefit; a rename of the arm is still caught
  (a `case` label that no longer overlaps the union is a type error either way).
- Rows are held **verbatim in wire snake_case** — unlike `runConfigSnapshot` (which remapped
  `used_tokens → usedTokens`), reusing `ConversationSummary` as-is keeps the slice drift-free against
  the mobile contract with zero per-field transform.
- `cwd` is untrusted daemon-supplied opaque display text (carried forward from #139's security
  review): stored/read as a string only here, but #141 (or any later "open workspace" feature) must
  boundary-check it (`path.resolve` + known-root prefix) before any filesystem access.
