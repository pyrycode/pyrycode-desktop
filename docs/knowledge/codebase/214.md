# #214 — Decode the daemon `turn_state` stream into the timeline coarse `phase`

Transport slice of the Phase-2 structured-streaming vertical (ADR 0008), split from #204. Wires the
missing wire → transport → bridge chain that feeds the coarse `phase` scalar `reduceTimeline` (#121),
`selectPhase`, and the `timelineStore` singleton (#202) already reduce and expose. Shipped as PR #216
(`914199e`), code-review **PASS** (no MUST/SHOULD-FIX). Security-sensitive (adds a wire type decoded
from the relay socket); size S; a near-exact structural clone of [#199](199.md) scaled to one event,
plus one new twist — `state` is a closed wire enum, decoded with the `role` single-enum-check idiom
rather than a `requireString`. **No render** — the "thinking…" indicator that reads `phase` is the
sibling slice, blocked on this one. **No `interactive` flip.**

## Summary

Before this ticket, a `turn_state` envelope was unmodeled and fell through `parseInboundMessage`'s
`default → inbound-unmodeled → null`. The downstream (`reduceTimeline`'s `turnState` arm, `selectPhase`,
the `timelineStore` singleton) already existed from #121/#202 with nothing feeding it. This ticket adds
the six thin, additive touchpoints the architect's spec identified as the architectural floor for any
new inbound `DaemonEvent` once a second bridge (`timelineBridge`, #202) exists — one file more than
#199's five, because #199 shipped before the timeline bridge did:

- **Wire types** (`src/shared/wire/types.ts`) — `WireTurnState = 'thinking' | 'responding' | 'idle'`
  (mirrors `WireRole`: a plain string on the daemon side, no named enum) + `TurnStatePayload
  {conversation_id, state}`, both fields always present (no `omitempty`); `'turn_state'` joins
  `EnvelopeType`.
- **Inbound decode** (`inboundMessage.ts`) — `{ kind: 'turn-state'; turnState: TurnStatePayload }`
  joins `InboundDaemonMessage`; `parseTurnStatePayload` does an `isRecord` guard, `requireString` on
  `conversation_id`, then the **closed three-way literal comparison** cloned from
  `parseMessagePayload`'s `role` check (`state !== 'thinking' && state !== 'responding' && state !==
  'idle'` → throw) — narrows to `WireTurnState` with no cast, covers non-string and unknown-string
  alike, category-only error message. `case 'turn_state'` narrows before logging, then emits
  `inbound-decoded{code:'turn_state', bytes, hash}` — no decoded field logged.
- **Consumer emit** (`daemonConnection.ts`) — one `case 'turn-state'` in the `switch (inbound.kind)`,
  a fresh literal `{ type: 'turnState', state: inbound.turnState.state }`; `conversation_id` dropped
  (single active conversation).
- **`DaemonEvent` arm** (`src/shared/ipc/events.ts`) — `{ type: 'turnState'; state: WireTurnState }`,
  importing `WireTurnState` alongside the module's existing wire-type imports.
- **Session bridge (no-op)** — `daemonEventBridge.ts` adds `turnState` to the `assistantDelta`/`turnEnd`
  fall-through `return null` group (present only for the `assertNever` exhaustiveness proof).
- **Timeline bridge (real mapping)** — `timelineBridge.ts` adds `case 'turnState': return { type:
  'turnState', state: event.state }` to the owned block. `event.state` is `WireTurnState`; the
  `ThreadEvent` arm expects `TurnPhase` — the same literal union, so this is a rename, not a
  re-validation, with no cast and no cross-layer import.

`npm test` (831 pass), `npm run typecheck`, `npm run build` all green. 6 production files touched, 0
new files (exactly the spec's predicted scope-self-check floor).

## Patterns established

- **A second `assertNever`-guarded bridge doubles the compile-forced touch surface for any future
  `DaemonEvent` arm, and this ticket is the first one to pay that cost.** #199 hit its floor at 5 files
  because `timelineBridge` didn't exist yet; #214 hits 6 because it now does — both the session bridge
  and the timeline bridge are independently `assertNever`-guarded over the same `DaemonEvent` union, so
  a new arm is a compile error in *both* until each decides its mapping (mirrors the "independently
  exhaustive consumers" pattern [#202 established](202.md)). Expect every future `DaemonEvent` arm
  (`toolUse`/`toolResult` next, per ADR 0008) to cost at least these same 6 touchpoints.
- **The enum-on-the-wire idiom (`role`) generalizes cleanly to a second field.** `parseTurnStatePayload`
  clones `parseMessagePayload`'s `role` check verbatim in shape (single three-way `!==` chain, no
  `requireString`, no cast, category-only error). This is now a two-instance precedent inside the same
  file — a third closed-enum wire field should reach for this idiom by default rather than reinventing
  it or reaching for `requireString` (which the spec explicitly flagged as the wrong tool: `requireString`
  would accept any string and defeat the enum boundary this ticket exists to defend).

## Lessons learned

- The PR body called out that the two `assertNever` guards (`daemonEventBridge` + `timelineBridge`)
  turned the new `turnState` arm into a compile error in both subscribers until each decided its
  mapping — the exhaustiveness proof worked exactly as designed, catching the unhandled arm at build
  time before any test ran. Not a surprise so much as a confirmation that the #202-established pattern
  holds under its first real load: a second `DaemonEvent` arm addition after the second bridge existed.

## Open questions carried forward

- **Inner-switch exhaustiveness** (`daemonConnection.ts`'s `switch (inbound.kind)` still has no
  `default: assertNever`) is now three-tickets deferred (#180, #199, #214). The `daemonConnection.test.ts`
  emit test remains the deterministic safety net. Not adopted here per the architect's explicit scope
  call — flagged again for the eventual cleanup ticket.
- **`state` value evolution.** The daemon enum is closed to three values today. A future fourth state
  fails closed here (dropped frame) until this decoder, `TurnPhase`, and `reduceTimeline` are widened
  together — the correct fail-closed posture for a wire enum (CLAUDE.md no-drift).
- **The render consumer is a separate, still-open slice.** `selectPhase` now has a real source for the
  first time, but nothing in the renderer reads it yet — the "thinking…" indicator is the sibling
  ticket, blocked on this one landing. `Timeline`'s streaming cursor in [#203](203.md) still derives
  from array position, not `selectPhase`.
