# #217 — Decode the daemon `tool_use` stream into a timeline `toolCall`

Transport slice of the Phase-2 structured-streaming vertical (ADR 0008), split from
[#205](https://github.com/pyrycode/pyrycode-desktop/issues/205). Wires the missing wire → transport →
bridge chain that feeds a pending `toolCall` `ThreadItem` (`result: null`) into `reduceTimeline` (#121),
`selectItems`, and the `timelineStore` singleton (#202) already reduce and expose. Shipped as PR #220
(`6fb4954`), code-review **PASS** (no MUST/SHOULD-FIX), security review **PASS**. Security-sensitive (adds
a wire type decoded from the relay socket); size S; a near-exact structural clone of [#214](214.md)'s
`turn_state` chain across the same six touch points. **No render** — the tool row that displays the call is
the sibling slice [#218](https://github.com/pyrycode/pyrycode-desktop/issues/218), blocked on this one.
Correlating a later `tool_result` to this call by `toolUseId` is [#206](https://github.com/pyrycode/pyrycode-desktop/issues/206).
**No `interactive` flip.**

## Summary

Before this ticket, a `tool_use` envelope was unmodeled and fell through `parseInboundMessage`'s
`default → inbound-unmodeled → null`. The downstream (`reduceTimeline`'s `toolUse` arm, `selectItems`, the
`timelineStore` singleton) already existed from #121/#202 with nothing feeding it. This ticket adds the six
thin, additive touchpoints — the same six #214 established, since the timeline bridge already exists:

- **Wire types** (`src/shared/wire/types.ts`) — `ToolUsePayload{conversation_id, turn_id, tool_use_id, name,
  input_summary}`, all five fields plain strings, always present (no `omitempty`); `'tool_use'` joins
  `EnvelopeType`. **No new wire enum** — unlike #214's `WireTurnState`, this adds exactly one exported
  type.
- **Inbound decode** (`inboundMessage.ts`) — `{ kind: 'tool-use'; toolUse: ToolUsePayload }` joins
  `InboundDaemonMessage`; `parseToolUsePayload` clones `parseTurnEndPayload`'s idiom exactly: `isRecord`
  guard, then five `requireString` calls, returning only the five known fields (extra server keys
  tolerated, not copied). **No enum check** — unlike #214's three-way `state` comparison, the fail-closed
  defence here is required-string presence alone. `case 'tool_use'` narrows before logging, then emits
  `inbound-decoded{code:'tool_use', bytes, hash}` — no decoded field logged.
- **Consumer emit** (`daemonConnection.ts`) — one `case 'tool-use'` in the `switch (inbound.kind)`, a fresh
  literal `{ type: 'toolUse', turnId, toolUseId, name, inputSummary }`; `conversation_id` dropped (single
  active conversation).
- **`DaemonEvent` arm** (`src/shared/ipc/events.ts`) — `{ type: 'toolUse'; turnId: string; toolUseId:
  string; name: string; inputSummary: string }`. No new import (every field is a bare `string`).
- **Session bridge (no-op)** — `daemonEventBridge.ts` adds `toolUse` to the
  `assistantDelta`/`turnEnd`/`turnState` fall-through `return null` group (present only for the
  `assertNever` exhaustiveness proof).
- **Timeline bridge (real mapping)** — `timelineBridge.ts` adds `case 'toolUse': return { type: 'toolUse',
  turnId, toolUseId, name, inputSummary }` to the owned block — a fresh literal, field-for-field identical
  to the `ThreadEvent` counterpart (a filter + copy, not a remap). `reduceTimeline` folds it into a pending
  `toolCall` (`result: null`) in arrival order, splitting a turn's text into `[assistantText, toolCall,
  assistantText]` (#121's existing split).

`npm test` (850 pass, 3 pre-existing skips), `npm run typecheck`, `npm run build` all green. 6 production
files touched, 0 new files (the spec's predicted scope-self-check floor, verified before implementation).

## Patterns established

- **The required-string-presence idiom is the correct tool when a payload has no closed wire enum, even
  at five fields.** `parseToolUsePayload` resisted the temptation to reach for #214's `state` three-way
  comparison (there is no enum here) and instead scaled `parseTurnEndPayload`'s `requireString` idiom from
  three fields to five with no new helper. A future all-string payload of any width should default to this
  idiom; reach for the closed-enum comparison only when the wire field itself is a closed vocabulary.
- **The timeline bridge's fourth arm is the first to map onto a real content item, not a scalar.**
  `assistantDelta`/`turnEnd`/`turnState` all feed text or a coarse `phase`; `toolUse` is the first arm
  whose `ThreadEvent` counterpart produces a durable `ThreadItem` (`toolCall`) the render layer will bind
  a row to. The mapping stayed a pure filter-and-copy because the `DaemonEvent` and `ThreadEvent` `toolUse`
  shapes were designed field-for-field identical back in ADR 0008 — confirms that keeping the wire-side and
  reducer-side event shapes in lockstep at design time keeps every future bridge arm this thin.
- **Untrusted daemon strings crossing to a future render slice must be flagged where they're decoded, not
  just where they're rendered.** `name`/`input_summary` are opaque daemon-supplied text (the `stop_reason`
  #199 / `cwd` #139 posture) that this slice carries verbatim through IPC into the render slice #218 — the
  wire-type doc-comment, the spec's Open Questions, and this file all state the same constraint (plain text
  only, never `dangerouslySetInnerHTML`, never re-parsed) so #218 inherits it without re-deriving the
  reasoning from scratch.

## Lessons learned

- **Computed-key rest-destructuring for a "field absent" fixture needs `as const` on the key array.**
  `for (const field of ['conversation_id', ...])` followed by `const { [field]: _, ...missing } = TOOL_USE`
  fails `noImplicitAny`'s index-signature check (TS2537) unless the array literal is annotated `as const` —
  without it, `field` widens to `string` and TypeScript can't prove the computed key is a member of
  `TOOL_USE`. Caught by `npm run typecheck`, not `vitest` (esbuild strips types and ran the test anyway) —
  a reminder that the fail-closed-field-enumeration test pattern (also used by #199/#214) needs the `as
  const` from the start, not just when the compiler complains.

## Open questions carried forward

- **Inner-switch exhaustiveness** (`daemonConnection.ts`'s `switch (inbound.kind)` still has no
  `default: assertNever`) is now four-tickets deferred (#180, #199, #214, #217). The
  `daemonConnection.test.ts` emit test remains the deterministic safety net. Not adopted here, per the
  architect's explicit scope call — flagged again for the eventual cleanup ticket.
- **`name`/`input_summary` reach the render slice as free text — binding constraint on #218.** Unlike
  #214's `state` (a closed three-value enum with nothing to sanitize), these two fields are arbitrary
  daemon-supplied strings. #218 must render both as **plain text**, never HTML, and must treat
  `input_summary` as an opaque précis — never re-parsed or re-summarized, even though it looks like it
  might contain structured data.
- **The `toolCall` row itself is still unbound.** This slice proves one `toolCall` item lands on
  `timelineStore` via `selectItems`; nothing in the renderer paints it yet. #218 is the render slice.
  Correlating the eventual `tool_result` into this call's `result` field (currently permanently `null`) is
  #206, still open.
