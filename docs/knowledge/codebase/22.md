# #22 — Reconnect supervisor for the relay connection

**Shipped:** 2026-07-03 · **Size:** S · **Scope:** background transport only (`src/main/transport/`) · greenfield module, zero consumer cascade · **no new dependency** (`ws` already landed in #21; the supervisor never touches `ws`).
**Spec:** `docs/specs/architecture/22-relay-reconnect-supervisor.md` · **PR:** [#28](https://github.com/pyrycode/pyrycode-desktop/pull/28) (review: PASS, no MUST/SHOULD/NIT findings).

The **resilience layer** of the Phase 1 connect–send–stream transport foundation: `createRelaySupervisor` wraps the single-shot [`createRelayConnection`](21.md) (#21) so the handshake and message layers above see a connection that **heals itself** after transient drops instead of dying on the first blip. After a **retryable** close it re-dials with **capped exponential backoff + ±20% jitter**, **resets** the backoff once a connection has stayed up ≥ 60s, treats a **fatal** close code as **terminal** (reconnect-storm DoS mitigation), tears down cleanly with no dangling timers, and **forwards inbound frames byte-for-byte**. See the [relay-supervisor feature doc](../features/relay-supervisor.md) for the full contract, state machine, cadence, and close-code table.

Scope lock held: this is the **supervision half** of the pyrycode Go binary's `internal/transport` shape (its reconnect loop + jittered backoff + stability reset + `FatalCloseCodes`); #21 delivered the single-connection half. **No** Noise decode, **no** framing interpretation, **no** renderer / IPC / preload surface. `relayConnection.ts` is consumed by import only and is **not modified**.

## Patterns established

- **Wrap a lower primitive by injecting its factory, not by importing its socket.** The supervisor takes `createConnection?: (config) => RelayConnection` (default `createRelayConnection`) and drives it entirely through the #21 `onEvent` / `send` / `close` contract — it never imports `ws`. Tests pass a fake factory; production passes the real one. This is the clean seam for any future layer that composes over a transport primitive (the Noise session will do the same over the supervisor).
- **A distinct event type when the semantics shift, even over an identical-looking union.** `RelaySupervisorEvent` is **not** a re-used `RelayEvent`: its terminal member is named `terminal`, not `closed`, because a transient `closed` at the #21 layer is *absorbed* here (re-dialled, surfaced as nothing) while only a fatal code or `stop()` is terminal. Distinct names make the contract self-documenting and guard against the exact bug class this ticket exists for — false-death vs reconnect-storm. Reach for a fresh union (not a re-export) whenever the wrapping layer changes what an event *means*.
- **The whole terminal-vs-retry decision is one set-membership check.** `fatalCloseCodes.has(event.code)` on the code #21 already emits — no per-code branch, no state duplication. This is the Go `#301` lesson applied ("reconnect storms come from layer confusion; the fix is strictly less code, not more"): the classification belongs at the supervision layer, as a single injected-set lookup.
- **Re-used all four #21 patterns verbatim:** factory + injected `onEvent` DI; the **test-only second `timing` parameter** for non-tunable wire-spec cadence (a production caller passing one argument cannot reach it); a **terminal-emitted-once guard + single teardown** (`emitTerminal` clears both timers, releases `current`, emits once); and **log-free by construction** (no `console.*` — a stray log would leak `frame` payload or `connection.headers` identity to stdout). Re-uses `RelayNotConnectedError` (imported, not redefined).
- **Exactly one supervisor-owned timer at a time.** `stabilityTimer` (armed only while connected) and `backoffTimer` (armed only in a backoff gap) are mutually exclusive in time; both are cleared on their phase-exit and unconditionally in `emitTerminal`. Combined with the `terminalEmitted` once-guard and a `stopped` early-return in `onConnEvent`, a late `closed` from a connection the supervisor `.close()`d during `stop()` can produce neither a second terminal nor a reconnect. "Replace, don't stack" — one live connection, ever.

## Lessons learned

*Lifted from the PR body's "Lessons learned" section.*

- **A good fake connection must replicate #21's `send`-throws-when-not-OPEN contract, not just record calls.** The supervisor's `send` only checks `if (!current) throw` — the "throws before first connect / during a backoff gap" behaviour (a real AC) actually depends on the *underlying* connection's `send` throwing `RelayNotConnectedError` while CONNECTING. The test fake tracks a `live` flag (true on `connected`, false on `closed`/`close`) and throws accordingly; without it the send-guard test would pass **vacuously** against a fake that always accepts sends. When faking an injected primitive, replicate the failure-mode contract, not just the happy path — or a guard test proves nothing.
- **Fatal-vs-retryable is strictly less code, not more.** The reconnect-storm mitigation is one set-membership check on the code #21 already emits — no per-code branching, no state duplication (the Go `#301` lesson).
- **`2 ** attempt` saturates to `Infinity` for a permanently-failing connection, but `Math.min(…, maxDelayMs)` clamps it** — there is no overflow path in the backoff, confirmed by review. The un-jittered sequence is `1000, 2000, 4000, 8000, 16000, 30000, 30000` (the cap bites from `n = 5`).

## Deferred (open questions carried forward)

- **Non-terminal `disconnected` / `reconnecting` event.** Transient drops are absorbed silently (only `connected` on re-dial, `terminal` at the end). When the desktop UI needs a visible "reconnecting…" indicator, add a `{ type: 'disconnected' }` member then — evidence-based, mirroring #21's deferred `error` member.
- **`4404` classification.** Kept **retryable** (transient binary-offline is the common case; capped backoff bounds a wrong-server-id to ~2 dials/min). Promote to the fatal set if field data shows a bad-pair-record `4404` storm — already injectable config, no supervisor code change.
- **Send buffering across reconnect.** `send` throws during a backoff gap; frames are not queued. Acceptable — v2 has **no session resumption** (each reconnect is a fresh Noise handshake from `noise_init`), so the handshake layer re-establishes and re-sends. Revisit only if an observed loss motivates a bounded outbound queue.
- **Stability reset: timer vs. duration.** Implemented via a `stabilityTimer` armed on `connected` (fires at ≥60s while up), reusing the single injected-scheduler seam. The Go mirror instead measures serve-loop duration at drop time; the two are observably equivalent for the ACs.
- **Composition-root wiring.** Nothing constructs `createRelaySupervisor` yet; `src/main/index.ts` stays untouched. Wiring it (with the real relay URL/headers from the pairing/config layer) into app startup is a later ticket.
