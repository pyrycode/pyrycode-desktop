# #223 — Modal store + bridge (DaemonEvent → ModalEvent)

The missing middle of the modal vertical (ADR [0009](../decisions/0009-modal-prompt-model.md)),
fourth of six: [#201](201.md) (transport) → **#223 (this, store + bridge)** → #224 (interactive
render) → #225 (answer path) → #226 (second-confirm) / #227 (surface rejection). Shipped as PR
[#231](https://github.com/pyrycode/pyrycode-desktop/pull/231) (`f843d29`). Not security-sensitive
(pure renderer state over already-typed, renderer-local events); no Figma (headless, no render
surface). Size S — a piece-for-piece clone of [#202](202.md) (`timelineStore` + `timelineBridge`).

## Summary

Adds the two renderer pieces the [modal-prompt model](../features/modal-prompt-model.md) (#122) was
missing: a Zustand store wrapping `reduceModal`, and a translator + binding that maps the two
`modalShown`/`modalDismissed` `DaemonEvent` arms ([#201](201.md)) into `ModalEvent`s and feeds it.
Purely additive — **2 new production files, 2 new test files, 0 existing files touched**
(Strangler Fig continues: `daemonEventBridge.ts` and `timelineBridge.ts` keep nulling the two modal
arms, unedited):

- **`src/renderer/src/store/modalStore.ts`** — `createModalStore(init?)` (vanilla `createStore`, DI
  seam) → `modalStore` (app singleton) → `useModalStore(selector)` (narrow-slice hook), mirroring
  `createTimelineStore`'s DI-factory → singleton → hook shape. `dispatch` is the sole mutation path:
  `set((s) => reduceModal(s, event))`. No `observe?` param — the #134 diagnostics seam is
  session-only. Re-exports `selectOutstanding` from `modalPrompts.ts` (never redefines it) as #224's
  single import site.
- **`src/renderer/src/store/modalBridge.ts`** — `translateModalEvent(event): ModalEvent | null`, the
  pure choke point mirroring `translateTimelineEvent`. Owns exactly `modalShown`/`modalDismissed`,
  each rebuilt as a fresh named-field literal; every other arm (all 15 remaining `DaemonEvent`
  members) falls through to `return null`, then `default: assertNever(event)` — a hard exhaustiveness
  guard, not a catch-all. `subscribeModal(onDaemonEvent, dispatch)` extracts the pure subscription for
  spy-testability; `useModalBridge()` wraps it in a
  `useEffect(() => subscribeModal(window.pyry.onDaemonEvent, e => modalStore.getState().dispatch(e)), [])`
  returning the off handle as cleanup — StrictMode double-mount nets exactly one live listener.
  Dormant: exported but not mounted anywhere in this slice — [#224](https://github.com/pyrycode/pyrycode-desktop/issues/224) mounts it.

This is the **third** independent subscriber on the `onDaemonEvent` channel: `daemonEventBridge` owns
the session arms, `timelineBridge` the stream arms, this one owns exactly the two modal arms — each
returning `null` for what it doesn't own.

14 new tests (`modalStore.test.ts` ×5 + `modalBridge.test.ts` ×9): store wiring (initial state,
dispatch-threads-reducer append, dismissed-empties, unknown-id no-op same-reference, DI isolation
between two instances); per-arm translation (both owned arms `.not.toBe(event)` fresh-object check,
all 15 other arms enumerated in one `null`-return assertion, including `assistantDelta`/`toolUse`
explicitly since those are arms `timelineBridge` owns but this one must null); `subscribeModal`
lifecycle (subscribe-once, translate+dispatch, unowned-arm no-op, off-handle cleanup); and two
store-integration tests (no React) driving `modalShown` → `modalDismissed` through `subscribeModal`
into a real `createModalStore()`, asserting `selectOutstanding` goes `[1 prompt]` → `[]`, and the
unknown-id no-churn case. `npm test` (918 total green, +14 new per the PR body), `npm run typecheck`
(both sides), `npm run build` all green.

## Patterns established

- **The discriminant tag can rename across the `DaemonEvent → ModelEvent` boundary even when every
  field name stays identical.** Every prior bridge arm in this codebase (`assistantDelta`, `turnEnd`,
  `turnState`, `toolUse` in `timelineBridge`) kept the same `type` tag on both sides of the
  translation. This bridge is the first counter-example: `modalShown` → `type: 'shown'`,
  `modalDismissed` → `type: 'dismissed'`. The translator tests pin `translated.type === 'shown'` /
  `'dismissed'` (not `'modalShown'`) specifically to catch a blind clone of the identical-tag
  assumption.
- **A third independent `assertNever`-guarded subscriber can coexist on the same sealed
  `DaemonEvent` union without merging concerns**, extending the two-subscriber pattern
  [#202](202.md) established (`daemonEventBridge` + `timelineBridge`) to three. Each bridge is
  independently exhaustive over all 17 arms; a future arm is a compile error in all three files until
  each decides its mapping.

## Lessons learned

From the PR body (`f843d29`, verified against the shipped diff):

- Cloning `timelineBridge` blindly would have carried the wrong discriminant tag, since every arm
  `timelineBridge` owns keeps an identical tag on both sides. The spec flagged this explicitly as "the
  one non-obvious detail — do not clone timelineBridge blindly here," and the implementation and its
  tests (`translated.type === 'shown'`/`'dismissed'`) followed the flag exactly — no deviation.
