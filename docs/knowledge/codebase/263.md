# #263 — Send `set_session_settings` with the omitempty presence contract

Outbound send path for a per-session model / reasoning-effort / YOLO change, split from #255 (which
welded #180's outbound shape to a #254-shaped inbound decode arm). This slice is the **send path** only;
the sibling `session_settings_updated` decode arm is #264 (blocked by this ticket via file overlap on
`daemonConnection.ts` and the wire `EnvelopeType` union). Shipped as PR #265 (`6aaffd9`), code-review
**PASS** (no findings). Security-sensitive; architect self-review **PASS** (no findings). Sized S. Ships
**dormant** — its caller is the interactive Run-config controls (#257), exactly as #236 shipped ahead of
its render consumer. No Figma (pure transport, no renderer surface this ticket).

## Summary

Five production files (2 new, 3 additive edits) plus their tests — the identical shape #180
(`requestSnapshot`) proved as one atomic `size:s`, recorded in the spec's § Scope determination as a
false-positive trip of the ≥5-file commit gate:

- **`src/shared/wire/types.ts`** — added `'set_session_settings'` to `EnvelopeType` (outbound group,
  next to `'request_snapshot'`) and the `SetSessionSettingsPayload{session_id, model?, effort?, yolo?}`
  interface, field-for-field with the daemon's `SetSessionSettingsPayload{SessionID; Model, Effort
  *string; YOLO *bool}` (pyrycode #844/#845). The doc comment states the presence contract in full
  (absent = leave unchanged; present-at-zero = set to this value; never a literal `null`).
- **`src/main/transport/setSessionSettingsEnvelope.ts`** (new, main-only) — `buildSetSessionSettings`,
  the one piece beyond a mechanical `requestSnapshot` clone. Constructs a fresh payload literal:
  `session_id` always assigned, each of `model`/`effort`/`yolo` assigned **iff `!== undefined`** (never
  a truthiness test — `if (payload.model)` would wrongly drop `''`, `if (payload.yolo)` would wrongly
  drop `false`). Wraps the result in a `set_session_settings` `Envelope`, `encodeEnvelope`s it, may
  throw `WireEncodeError` over `MAX_PLAINTEXT_BYTES`.
- **`src/shared/ipc/commands.ts`** — added the `setSessionSettings` `RendererCommand` union member
  (eighth member; reuses `SetSessionSettingsPayload` verbatim), the `isRendererCommand` switch case, and
  the module-internal `isSetSessionSettingsPayload` guard: `session_id` present-and-string required;
  each optional, *when present* (`in` check), must be correctly typed; an absent optional is accepted.
  Structural minimum — an extra field is not rejected here (the builder's fresh literal bounds the wire).
- **`src/main/daemonConnection.ts`** — added the `setSessionSettings(payload)` interface decl + method,
  a faithful `requestSnapshot` twin: `if (driver === null) return`; build via `buildSetSessionSettings`
  in a `try`; advance `nextEnvelopeId` only on success; `driver.sendMessage(bytes)`; `catch {}` drops any
  throw with no log/event (the caught object could echo the payload). Shares the single monotonic
  `nextEnvelopeId` — no second counter. **No empty-`session_id` guard** (AC4, Evidence-Based Fix
  Selection): an empty/unknown id is the daemon's `session.not_found` to reject, mirroring how
  `requestSnapshot` leaves an empty `conversation_id` to `conversation.not_found`.
- **`src/main/index.ts`** — added `case 'setSessionSettings': connection.setSessionSettings(command.payload); return` to the `onCommand` switch, mirroring `case 'requestSnapshot'`.

`npm test` (1128 passed, 3 pre-existing skips), `npm run typecheck`, `npm run build` all green.
Test-first: the builder's golden test exercises the full present-zero-vs-omitted matrix (`yolo:false`
alone, `model:''` alone, all-four-present, all-three-omitted), an anti-smuggling case (an extra field
cast through the type is absent from the decoded output), and an over-cap `WireEncodeError`. The command
guard and connection-method tests extend the existing `requestSnapshot`-shaped suites.

## Patterns established

- **The presence-contract builder is the one place a `send`-twin slice earns more than a mechanical
  clone — and it's worth naming precisely where that logic lives.** Unlike `createConversation`/
  `answerModal` (which build their fresh anti-smuggling literal in the *connection method* and keep a
  dumb wrapper builder), this ticket co-locates the fresh literal **and** the omitempty presence contract
  in the *builder*, because the golden test targets the builder (AC2) and the conditional-key
  construction *is* the presence contract — pulling them apart would split one concern across two files
  for no benefit. The connection method stays a 100%-faithful `requestSnapshot` twin as a result. This
  divergence was called out explicitly in the spec for code review, and code review confirmed it as
  deliberate, not an oversight.
- **`!== undefined`, never a truthiness test, is the load-bearing correctness discipline for any
  omitempty-shaped payload.** The one trap this slice's entire golden test matrix exists to pin: `if
  (payload.model)` silently drops `''`, `if (payload.yolo)` silently drops `false` — both real,
  daemon-distinguished "set to zero value" cases, not "unset." Any future ported type carrying `*T
  omitempty` daemon-side needs the same explicit-presence-check discipline, not a truthiness shortcut.
- **A "5 production files" commit-gate trip is a false positive for this exact shape, and the spec's own
  § Scope determination is the right place to record why** rather than resolving it live during
  implementation. #180/#236/#241 are the same 5-file outbound-send-path/command-lockstep family, all
  shipped clean as one `size:s`; the recorded quantitative check (LOC, new exports, call sites, ACs,
  reject branches) is what actually gates, not the raw file count.

## Lessons learned

None beyond what's captured above — this ticket is a close structural clone of #180 with one genuinely
novel piece (the presence-contract builder), and shipped with zero code-review findings. The PR body

## Open questions carried forward

- **#257 (later)** is the actual consumer: the interactive Run configuration controls will construct and
  dispatch this `setSessionSettings` command, addressing whichever `session_id` the [session-id
  store](../features/session-id-store.md) (#259) currently retains. Until then, the command surface and
  connection method are live but unreachable from any renderer code path.
- **#264 (decode arm)** and **#261 (correlation)** are both still open, blocked-by/dependent-on this
  ticket. Until #264 lands, a real `session_settings_updated` daemon reply to a request sent by this
  method is decoded by nothing — the driver's inbound switch defaults it to a dropped/unmodeled frame,
  the same permissive default every unshipped `EnvelopeType` gets.
- Daemon field names (`session_id`, `model`, `effort`, `yolo`) were confirmed against pyrycode #844/#845
  in the prior split analysis (#255); no drift found this ticket.
