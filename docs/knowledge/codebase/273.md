# #273 — Wire `promote_conversation` through the transport → `conversationUpdated` daemon event

Transport half of the "save a discussion as a channel" vertical (split from #143). The
renderer-facing Save-as-channel dialog is #274; the live-list reflection that flips a row from
discussion to channel is #275 — both consume what this slice introduces and are blocked by it.
Shipped as PR #284, code review **PASS** (no findings), architect self-review **PASS**.
Security-sensitive (a new outbound frame + a new inbound decode on the internet-exposed
relay/Noise surface, plus a new untrusted renderer→main command member); size S; the direct twin
of #241 (`create_conversation` → `conversationCreated`).

## Summary

The daemon speaks a fire-and-forget/broadcast pair, not a request/reply: the client sends
`promote_conversation{conversation_id, name, cwd}` (all three **required** strings — the daemon
struct has no pointers, no `omitempty`) and the daemon confirms by **broadcasting**
`conversation_updated` to every client on the server-id, not via `in_reply_to`. Ten production
files, one new (`promoteConversationEnvelope.ts`):

- **Wire types** (`src/shared/wire/types.ts`) — `'promote_conversation'`/`'conversation_updated'`
  join `EnvelopeType`; `PromoteConversationPayload` (`conversation_id`/`name`/`cwd`, each plain
  `string` — the deliberate *opposite* of `CreateConversationPayload`'s nullable trio) and
  `ConversationUpdatedPayload` (`id`, `is_promoted`, `name: string | null`, `cwd`, `last_used_at`)
  — field order `name` **before** `cwd`, the intentional reordering vs.
  `ConversationCreatedPayload`'s `cwd`-before-`name` (spec #274 flags it).
- **Command** (`src/shared/ipc/commands.ts`) — a ninth `RendererCommand` member,
  `promoteConversation{payload: PromoteConversationPayload}`, guarded by
  `isPromoteConversationPayload` — cloned from `isSendMessagePayload` (present-and-string ×3), not
  `isCreateConversationPayload`: a literal `null` is rejected here, unlike create. No constructor:
  the render side (#274) builds the literal inline.
- **Builder** (new `src/main/transport/promoteConversationEnvelope.ts`) — `buildPromoteConversation`,
  a payload-carrying builder cloned from `createConversationEnvelope.ts`/`sendMessageEnvelope.ts`,
  simpler than create's since all three fields are required strings (no explicit-`null`
  preservation concern). Main-process only, never re-exported to a renderer barrel.
- **Connection method** (`daemonConnection.ts`) — `promoteConversation(payload)`, the `send` twin
  (inert no-op when `driver === null`, shares the one `nextEnvelopeId` counter, never throws —
  parity #490). Builds a **fresh literal** naming exactly the three modeled fields before calling
  the builder — never a spread of the caller's `payload` — the deterministic net bounding the wire
  regardless of what the structural-minimum guard let through (the #236 fresh-literal posture). A
  new `case 'conversation-updated':` in `onDriverEvent` emits `conversationUpdated` as a verbatim
  passthrough (the `conversation-created` precedent — nothing to drop), emitted **unconditionally**
  on decode since there is no correlation to gate on.
- **Inbound decode** (`inboundMessage.ts`) — `parseConversationUpdatedPayload`, fail-closed, in the
  reply's own field order: three required strings (`id`/`cwd`/`last_used_at`) + one required
  boolean (`is_promoted`, `false` decodes as a value) + one required-but-nullable string (`name`,
  reusing #139's `requireStringOrNull`). Narrows **before** logging so a malformed broadcast throws
  first and leaves no diagnostic record; the content-free log reuses the existing `{event, code,
  bytes, hash}` shape, deliberately no `count`.
- **Event arm** (`src/shared/ipc/events.ts`) — `conversationUpdated{conversation}` joins
  `DaemonEvent`, reusing the wire type verbatim. Its doc-comment carries the untrusted-display-text
  warning forward for #275 — `name`/`cwd` are daemon-supplied strings that must render as plain
  text, never HTML — since this ticket has no DOM sink of its own.
- **Routing + exhaustive consumers** — `main/index.ts`'s `onCommand` switch gains one case
  (`connection.promoteConversation(command.payload)`); all three `assertNever`-guarded
  `DaemonEvent` consumers (`daemonEventBridge.ts`, `timelineBridge.ts`, `modalBridge.ts`) gain a
  one-line `case 'conversationUpdated': return null` / fall-through — the compile error from a
  missing case *is* the coverage, caught by `npm run build`.

`npm test` (1276 passed, 3 pre-existing skips), `npm run typecheck`, `npm run build` all clean.

## Patterns established

- **The "≥5 production files" split gate is structurally unsatisfiable for any new `DaemonEvent`
  arm, and neither this ticket nor #241 tried to force a split anyway.** Any inbound-only or
  outbound-only child still touches 5–7 files because the three `assertNever` bridges + the emit
  site + `events.ts` + `inboundMessage.ts` + `types.ts` must change in the same commit — the ticket
  body pre-empted this exact objection by citing #241's identical accepted footprint.
- **A required-string request guard is a clone of `isSendMessagePayload`, not
  `isCreateConversationPayload`.** When a wire payload's fields are genuinely required (not
  server-defaultable), reach for the `sendMessage` guard shape (present + typed, reject `null`) —
  the nullable-and-present shape (`isCreateConversationPayload`) is for the opposite contract and
  would silently let a `null` field through here.
- **An unsolicited broadcast reply needs no correlation memory, unlike a request/reply pair.**
  Confirmed as a real (not hypothetical) simplification: this slice adds zero outstanding-request
  state, in contrast to the `pendingSettings` map #261/#269 needed for `set_session_settings`'s
  correlated reply. The event is emitted unconditionally on every successful decode.

## Lessons learned

From the merged PR's own "Lessons learned" section:

- **`types.test.ts` stays at plain object-shape assertions; real codec round-trips live in the
  transport tests.** Reaffirms the #241 boundary: importing `src/main/**`'s `encodeEnvelope`/
  `decodeEnvelope` into a `src/shared/**` test would drag main's codec into the renderer typecheck
  program. The round-trip coverage (including `name: null`) lives in
  `promoteConversationEnvelope.test.ts` and `inboundMessage.test.ts`, where the codec is already
  imported.
- **10 production files at `size:s` is now twice-precedented, not a one-off.** The four additive
  one-line no-op cases (three bridges + the routing seam) are the exhaustiveness-guard tax on any
  new `DaemonEvent` arm, not separable work — identical to #241's accepted footprint, now confirmed
  a second time on an independent verb.
