# #274 — Save-as-channel dialog: name a discussion and promote it

The naming half of Figma 19:24, split from #143 alongside the transport half
([#273](273.md), shipped) and the list-reflect half ([#275](275.md), shipped). Adds a per-row
"Save as channel" affordance to Recent (unpromoted) rows and a dialog that collects a name and
dispatches `promoteConversation`, keeping the discussion in its current `cwd`. Shipped as PR #289,
five production files (three modified, two new). Not security-sensitive — renderer-only,
dispatching an already-typed command through the existing preload bridge. Size S.

## Summary

- **New `SaveAsChannelDialog.tsx`** — pure `SaveAsChannelDialogView` (overlay/scrim/`role="dialog"`
  chrome mirroring `PermissionModalView`, a controlled Name field prefilled via `titleFor`, Save
  disabled while `name.trim() === ''`) + pure `requestPromoteConversation(sendCommand, row, name)`
  (an inline `RendererCommand` literal, `name` trimmed before send, no redundant blank guard since
  the view already gates it).
- **`ChannelList.tsx` `Row` restructure** — the old single `<button className="channel-list__row">`
  became a flex wrapper with two sibling children: `.channel-list__row-open` (the old button, now
  `flex: 1 1 auto; min-width: 0`) and an optional icon-only `.channel-list__save` affordance
  (`aria-label="Save as channel"`, a Material bookmark glyph). Recent rows pass `onSaveAsChannel`;
  Channels rows pass none, so the affordance is structurally absent on promoted rows (AC1).
- **`ChannelList.tsx` container** — gained `useState` for `saveRow: ConversationSummary | null` and
  `name: string`, the transient per-interaction dialog state (not the store — the `PermissionModal
  pendingOptionId` posture). Opening seeds `name` from `titleFor(row.name)` in the same handler
  that sets `saveRow`. The container returns a fragment: the list view, then the dialog as a
  sibling when `saveRow !== null`. `window.pyry` is dereferenced only inside the `onSave` closure;
  the dialog is absent on first paint, so the SSR smoke test stays green.
- **`channels.css`** — `.channel-list__save` (icon-only, de-emphasized, round hover/focus target)
  and the full `.save-as-channel*` dialog chrome (overlay, scrim, panel, title, field, actions),
  mirroring `conversation.css`'s permission-modal styles token-for-token. See Lessons learned for
  the two Figma-vs-spec deviations found and resolved during implementation.
- **Tests** — new `SaveAsChannelDialog.test.tsx` (view chrome/prefill/disabled-state assertions,
  `requestPromoteConversation` spy test including the trim case); extended `ChannelList.test.tsx`
  with `SAVE_MARKER` presence/absence assertions (AC1) and a `noop` `onSaveAsChannel` threaded into
  the shared `render` helper.

`npm test` (1293 pass, 3 pre-existing skips), `npm run typecheck`, `npm run build` all clean.

## Patterns established

- **A command/event pair whose subscription half already shipped in a sibling ticket gets a bare
  dispatch function co-located with its caller, not a `store/*Bridge.ts` module.**
  `conversationCreatedBridge.ts` (#242) bundles dispatch + subscription + a React hook because
  create owns both halves. Promote's subscription half is #275's `conversation_updated` re-request,
  already living in `conversationListBridge.ts` — so `requestPromoteConversation` needed no
  subscription of its own and stayed in `SaveAsChannelDialog.tsx` next to its sole caller. The
  decision rule going forward: bridge module only when the same ticket owns both dispatch and
  subscription; otherwise co-locate the dispatch helper with its feature.
- **An interactive control cannot nest inside a `<button>`, so a row gaining a second affordance
  restructures the row into a flex wrapper around two sibling buttons** — the `.channel-list__row`
  → `.channel-list__row` (wrapper) / `.channel-list__row-open` (old button) split. This is the
  reference shape for any future per-row secondary affordance in this codebase (the `flex: 1 1
  auto; min-width: 0` on the primary action is what keeps the title ellipsis working).
- **A dialog overlay hosted inside a scrolling container needs `position: fixed`, not `absolute`,
  and a `z-index` above any sibling `position: sticky` element** — confirmed a second time (after
  `PermissionModal`, whose host isn't a scroller) as the fix whenever the dialog's screen-level
  ancestor is itself `overflow-y: auto` with a sticky affordance floating in it (here, the FAB at
  `z-index: 1`).

## Lessons learned

From the merged PR's own "Lessons learned" section:

- **A spec's CSS note can drift from the Figma node it cites — follow the node, not the prose.**
  The architecture spec's CSS section said "Cancel is leading (`margin-right: auto`)", carried over
  from the `PermissionModal` leading-dismissive-Cancel pattern, but Figma node 19:39 lays the
  action row out `justify-end` with **both** Cancel and Save trailing — which the spec's own Design
  section ("right-aligned action row") also states, so the CSS note contradicted the spec's own
  Design section. Followed the Figma screenshot as the source of truth; both actions trail, with a
  code comment on `.save-as-channel__actions` recording the resolution. Worth flagging note↔node
  mismatches like this back into the spec for future dialogs that cite the same permission-modal
  precedent.
- **A `position: fixed` dialog overlay needs an explicit `z-index` check against every `position:
  sticky` sibling in its screen, not just its immediate DOM neighbors.** `.channel-list` is the
  `overflow-y: auto` scroll column and the FAB is `position: sticky; z-index: 1` in its own
  stacking context. The permission-modal precedent's `position: absolute` overlay doesn't apply
  here (its host isn't a scroller) — an absolute overlay would scroll away with the rows, and a
  fixed overlay with no `z-index` set would still paint under the sticky FAB. `z-index: 2` on
  `.save-as-channel-overlay` resolved it. Future dialogs hosted inside a scrolling screen with any
  sticky sibling should check both properties together, not just reach for `position: fixed` alone.
