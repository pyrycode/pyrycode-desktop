# #277 — Empty-thread state: pre-first-message copy + visual

Split child of #148 (Figma-gap sibling of #276/#278/#279). Size XS, not security-sensitive (pure renderer).

## What shipped

`Timeline`'s `if (items.length === 0) return null` (#203 AC4) became `return <EmptyThread />`. `Timeline`'s return type tightened from `JSX.Element | null` to `JSX.Element` — the only production caller (`ConversationScreen.tsx:59`) never depended on the `null`.

`EmptyThread` (new, unexported, in-file beside `TimelineRow`/`ThinkingIndicator`):
- `<div className="conversation__empty">` — flex-fills the middle region (`flex: 1 1 auto; min-height: 0`), centers content on both axes. **Distinct class from `.conversation__thread`, no `data-thread-role`** — load-bearing, see below.
- A decorative inline SVG chat-bubble glyph, `aria-hidden="true"`, 48px (the file's existing inline-SVG idiom, same structural size as `.composer__send`).
- `<p className="conversation__empty-copy">{EMPTY_THREAD_COPY}</p>`.

`EMPTY_THREAD_COPY = 'Send a message to get started'` — a module-level string literal. `Timeline` receives only `items`, so AC3 ("no daemon-supplied string in the empty state") is a structural guarantee, not a runtime check — the same idiom `ThinkingIndicator`'s label already established.

Three new token-only CSS rules in `conversation.css`: `.conversation__empty`, `.conversation__empty-icon`, `.conversation__empty-copy`. Every color/space/type value is a `var(--…)` token; the 48px icon square is the one bare literal (the `.composer__send`/`.status-sheet__handle` precedent for structural geometry).

## Patterns established

- **Structural client-owned-string guarantee.** Same shape as `ThinkingIndicator`: a component whose prop surface makes it *impossible* to render a daemon-supplied string, rather than a convention to not do so. Reusable whenever a spec calls for "no daemon string here."
- **Distinct-class discipline for co-located empty/populated surfaces.** The container test guard at `ConversationScreen.test.tsx:443` (renamed from #203's "renders exactly one thread surface" wording is preserved) asserts `not.toContain('conversation__thread')` / `not.toContain('data-thread-role')` against the *empty* render — meaning any future empty-surface addition on this screen must keep using a name that isn't a substring of `conversation__thread` and must not carry `data-thread-role`. This guard was deliberately left untouched by this ticket (it's not in AC5's update scope) and stayed green, proving the new class didn't leak into the thread's identity.

## Test changes (AC5)

Two #203-era tests flipped from asserting emptiness to asserting the empty-state block:
- The pure `Timeline` empty test (`toBe('')` → `toContain('conversation__empty')` + copy text + `not.toContain('data-thread-role')` + `not.toContain(CURSOR)`).
- The container "mounts the empty timeline" test — kept `not.toContain('bubble__cursor')`, added `toContain('conversation__empty')`.

The split-brain guard and all populated-`Timeline`/`interactiveRoundtrip` assertions were untouched and stayed green (AC2, AC4-via-distinct-class).

## Lessons learned

Code review flagged a non-blocking NIT worth carrying forward to #278 (the workspace-chip sibling that renders on this same surface): `EmptyThread` and `ThinkingIndicator` can theoretically co-render in one transient window — a fresh thread whose `turn_state{thinking}` arrives while `items` is still empty. This can't happen in the single-client happy path (the composer's optimistic `userText` echo lands synchronously on send, so `items` is non-empty before any daemon thinking event), but it's reachable in a multi-client/observe-only conversation, which is out of scope for the current milestone. Not fixed here — flagged so #278 (and any future ticket touching this surface) accounts for it if that scope ever changes.

## Open seam

#278 (blocked by this ticket) pins a workspace-chip pill to the *top* of this same empty surface pre-first-message. `EmptyThread`'s centered icon+copy is structured so a top-anchored chip can be added as the surface's first child without disturbing the centering — not built here.
