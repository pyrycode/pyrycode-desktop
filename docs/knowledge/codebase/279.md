# #279 — Disconnected connection banner in the conversation thread

Split child of #148 (Figma-gap sibling of #276/#277/#278). Size XS, not security-sensitive — pure
renderer, a third read of the existing `sessionStore` `ConnectionStatus` slice; no transport, crypto,
or socket code touched. PR #282, code review PASS (no MUST/SHOULD FIX).

## What shipped

Mirrors the `RepairPrompt`/`RepairControl` split ([#167](167.md)) exactly. `composerSend.ts` gained two
exports beside `composerAvailability`/`shouldOfferRepair`:

- **`CONNECTION_BANNER_COPY`** — a client-owned string constant (`'Cannot reach pyrybox — your
  messages will not send until the connection is back.'`), the banner's entire text. Never derived from
  `status`, so "no daemon-supplied string reaches the banner" is structural, not conventional — the
  `EMPTY_THREAD_COPY`/`ThinkingIndicator` idiom.
- **`shouldShowBanner(status): boolean`** — `status.type !== 'connected'`; true for
  `disconnected`/`connecting`/`error`, false for `connected`. Deliberately **not** an exhaustive
  switch/`assertNever` (the `composerAvailability` shape) — every non-connected arm maps to the *same*
  behavior, so "show unless connected" is the honest shape, and a hypothetical future 5th
  `ConnectionStatus` arm defaults to *showing* the banner (the safe direction over silently hiding it).

`ConversationScreen.tsx` gained:

- **`ConnectionBanner({ status })`** — exported pure view, `null` unless `shouldShowBanner(status)`,
  else a `role="status"` `<p className="conversation__banner">` holding only `CONNECTION_BANNER_COPY`.
  `status` is a prop (not a store read), so the present/absent matrix is server-rendered directly.
- **`ConnectionBannerControl()`** — in-file, unexported container reading
  `useSessionStore(selectStatus)`, mounted between `UnpairControl` and `Timeline` — the top of the
  thread, below the header row.

`conversation.css` gained `.conversation__banner`, token-only, following the `.modal-rejection` (#249)
error-accent idiom — `--color-error` left border over `--color-surface-container-high` — sized to
body-medium, a step up in prominence from `.composer__hint`'s muted body-small caption. `flex: 0 0 auto`
so it pushes the thread down rather than overlaying it.

## Patterns established

- **Third independent read of one `ConnectionStatus` union.** Same slice, three distinct jobs and copy
  registers: the composer hint (terse, inline, gates Send), the #149 two-dot indicator (always-on,
  compact, separate ticket), and this banner (prominent, disconnected-only). No new store state, no new
  wire arm — reusable shape whenever a status needs a second/third UI surface without duplicating logic.
- **`!== 'x'` predicate over an exhaustive per-arm switch, when the fail-mode matters.** Contrast with
  `composerAvailability`, which must enumerate every arm since each maps to distinct copy.
  `shouldShowBanner` collapses three arms to one behavior, and picking the negated-equality form over an
  enumerated switch makes the safe direction (show-by-default) the one a future arm falls into for free.

## Lessons learned

From the PR's own "Lessons learned" section: the spec's recommended copy ("Can't reach…won't send") was
reworded to an apostrophe-free "Cannot reach…will not send" — this repo's `renderToStaticMarkup`-based
tests escape `'` → `&#x27;`, so an apostrophe in a copy constant breaks a literal `toContain` assertion.
`EMPTY_THREAD_COPY` and `ThinkingIndicator`'s `"Thinking…"` already avoided apostrophes for the same
reason (undocumented until now); this is a real, recurring trap for any future client-owned UI-copy
constant tested via server-render `toContain` — default new copy to apostrophe-free (or spell out
"cannot"/"will not") unless there's a reason not to.

Code review flagged one non-blocking NIT: "…until the connection is back" mildly implies a prior
connection when read during the very first, never-yet-connected `connecting` state. The spec had
already reconciled this — "back" was chosen over "restored"/"lost" as the least-temporal option honest
across all three non-connected arms — so it wasn't changed; copy stays PO-tunable.
