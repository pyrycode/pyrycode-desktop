# #288 — Save-as-channel dialog: choose the channel location

PR [#406](https://github.com/pyrycode/pyrycode-desktop/pull/406) (merged). Size S, not
security-sensitive (renderer UI only, consumes already-guarded transport). Split from
[#274](274.md) (the naming half, shipped) and blocked on [#397](397.md) (round-trip store) +
[#398](398.md) (create-folder dialog UI), both merged first. Spec:
`docs/specs/architecture/288-save-as-channel-dialog-location-choice.md`. Figma node
[19-24](https://www.figma.com/design/g2HIq2UyPhslEoHRokQmHG?node-id=19-24) (the same node #274
partially built — this ticket adds the radios + preview it deferred).

Adds the two-option location choice from Figma 19:24 to the dialog #274 built: "Move to dedicated
channel folder" (default) and "Keep in scratch". No new wire verb or command — a pure consumer of
`createWorkspaceFolder`/`workspaceFolderCreated`/`workspaceFolderRejected` (#381/#396) and
`promoteConversation` (#273), orchestrated through #397's `newFolderStore` round-trip.

## Summary

Three files modified, no new production file — everything lands in the #274 dialog:

- **`SaveAsChannelDialog.tsx`** grows from two exports to three, cloning #398's
  `CreateFolderDialog` container shape (create → observe → act) and swapping its tail:
  - `SaveAsChannelDialogView` gains `location: ChannelLocation` (`'dedicated' | 'scratch'`) and
    `roundTrip: NewFolderRoundTrip` (#397) as **injected** props, plus `onLocationChange`. Two
    native radios share one `name` attribute so exactly one is ever checked (AC1); the dedicated
    radio's preview line (`` `${CHANNELS_PARENT}/${slugForChannel(name)}/` ``) renders only while
    `location === 'dedicated'` and updates live with `name` (AC2). `busy = roundTrip.status ===
    'in-flight'` disables the Name input and both radios; `rejected` renders a single generic,
    apostrophe-free `.save-as-channel__error` line (AC5) — no daemon error text, since
    `workspaceFolderRejected` is bare (#396).
  - `requestPromoteConversation` is **widened**: `cwd` becomes an explicit fourth parameter
    instead of being read off `row.cwd` internally, so the dedicated branch can pass the
    daemon-returned path instead.
  - `requestCreateChannelFolder` (new) — the `createWorkspaceFolder` dispatch, distinct from
    #398's version because this one pins `parent: '~/pyry-workspace/channels'` and slugs the
    channel name so the folder created and the folder previewed are the same string.
  - `slugForChannel` (new, exported, pure) — kebab-cases the channel name; any run of
    non-alphanumerics collapses to one hyphen (kills `/`, `..`, whitespace in one pass), edge
    hyphens trim, and an empty result (e.g. a punctuation-only name) falls back to `'channel'` —
    guaranteed to pass the daemon's single-clean-element name-shape guard (#887) for any input.
  - `SaveAsChannelDialog` (new container) — owns `name` (seeded from `titleFor(row.name)`) and
    `location` (`'dedicated'` default) as `useState`, reads `useNewFolderStore(selectNewFolderRoundTrip)`,
    mounts `<NewFolderData />` dialog-scoped, and holds two effects: a reset-to-idle unmount
    cleanup (the single mechanism covering Cancel / scratch-save / created / Escape) and a
    `roundTrip.status === 'created'` effect that promotes with `roundTrip.path` **verbatim** then
    calls `onPromoted`. `onSave` branches on `location`: scratch promotes immediately with
    `row.cwd`; dedicated dispatches `createRequested` then `requestCreateChannelFolder` — the
    promote happens only in the created-effect, never inline.
- **`ChannelList.tsx`** — the `name` `useState` and its seed-on-open handler move out of the
  container into `SaveAsChannelDialog` itself; `ChannelList` now mounts `<SaveAsChannelDialog
  row={saveRow} onDismiss={...} onPromoted={...} />` in place of the bare
  `SaveAsChannelDialogView` + `requestPromoteConversation` call it used to own.
- **`channels.css`** — five new rules alongside the existing `.save-as-channel*` block:
  `.save-as-channel__location` (column, `--space-2` gap), `.save-as-channel__option` (row,
  `--space-3` gap, top-aligned), `.save-as-channel__radio` (`accent-color: var(--color-primary)`
  — the codebase's first radio input), `.save-as-channel__option-body` /
  `.save-as-channel__option-label` (body-large typography tokens), `.save-as-channel__preview`
  (monospace, `--color-on-surface-variant`, **`overflow-wrap: anywhere`** — a deliberate deviation
  from the Figma's `nowrap` so an arbitrarily long slug wraps instead of blowing out the panel),
  and `.save-as-channel__error` (cloned from `.create-folder__error`).

`npm test` (125 files, 1866 pass / 3 pre-existing skips), `npm run typecheck`, `npm run build` all
clean. View/slug/dispatch tests written RED-first; the container proven by composition (the #398
posture, node test env, no jsdom interaction harness).

## Patterns established

- **The two-verb create → observe → promote dance is now proven twice** (#398 for
  change-workspace, #288 for promote) as the reusable shape for "act on the daemon's returned path,
  never a client-templated one": dispatch `createRequested` → fire `createWorkspaceFolder` → an
  effect keyed on `roundTrip.status === 'created'` fires the tail action with `roundTrip.path`
  verbatim → close. Any future dialog needing a fresh dedicated folder before its own action
  should clone this shape rather than re-deriving it.
- **Widening a dispatch helper's implicit read into an explicit parameter, rather than
  branching inside it, keeps the helper single-purpose.** `requestPromoteConversation` used to
  read `row.cwd` itself; externalizing `cwd` as a parameter let two call sites (scratch vs.
  dedicated) supply different sources without the helper knowing which branch it's in.
- **A radio group's preview/derived-state line is computed inline in the view from the same
  `name` prop the input already controls**, not threaded through a separate prop — keeping the
  preview trivially assertable against the same `name` value a test already sets.

## Lessons learned

From the PR body's "Lessons learned" section:

- **`promoteConversation`'s `cwd` and `createWorkspaceFolder`'s `parent` take different daemon
  code paths.** `parent` is tilde-expanded server-side; `cwd` is `EvalSymlinks`-resolved (no `~`
  expansion, rejects a non-existent path). This is *why* the dedicated branch must promote with
  the daemon-returned `path`, never a client-templated `~/…` string — the two fields look
  symmetric but are policed completely differently.
- **The slug is entirely client-owned.** The daemon (#887) only *validates* that `name` is a
  single clean path element — it does not normalize or slug it — so `slugForChannel`'s kebab
  output is the literal on-disk folder name. A future canonical mobile slug algorithm, if one
  surfaces, is a one-function swap with zero wire impact (the promote always uses the
  daemon-returned path regardless of what the slug looked like).
- **`.save-as-channel__preview` deliberately uses `overflow-wrap: anywhere` instead of the
  Figma's `whitespace-nowrap`**, so a long slug wraps inside the panel rather than blowing out its
  width — documented in a CSS comment at the rule site.

Code review (PASS) flagged two non-blocking NITs, left unapplied: the rejection `<p>` has no
`role="alert"`/`aria-live` (mirrors the same pre-existing gap in #398's `.create-folder__error`,
so cloning it was the consistent call); and the `overflow-wrap: anywhere` deviation is
acknowledged as deliberate, not a defect.

## Security

Not security-sensitive, confirmed by code review: `parent`/`name`/`path` cross as opaque strings,
the renderer performs no `os.homedir`/`path.resolve`/fs I/O, the preview and the daemon-returned
path render as plain auto-escaped text (never `dangerouslySetInnerHTML`), and neither is
`console.log`ed. Both new commands (`promoteConversation` widened, `createWorkspaceFolder` reused)
match their existing `*Payload` shapes field-for-field — no wire drift.
