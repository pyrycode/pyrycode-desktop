# #29 — Noise spike (1/2): select a JS Noise library and prove `Noise_IK_25519_ChaChaPoly_BLAKE2s` conformance

**Shipped:** 2026-07-03 · **Size:** S · **Scope:** throwaway de-risking spike, transport-adjacent (`src/main/transport/`); **not** wired into app composition — the vitest run is the only execution path · **adds `noise-c.wasm@0.4.0`** (the project's first Noise dependency).
**Spec:** `docs/specs/architecture/29-noise-ik-library-spike.md` · **PR:** [#29 commit `a3d61c0`](https://github.com/pyrycode/pyrycode-desktop/issues/29) (review: PASS, one forward-looking NIT for #7, no MUST/SHOULD).

The **library-selection half** of the Noise proving work. It retires the sharpest unproven risk before any downstream Noise work: the daemon speaks exactly `Noise_IK_25519_ChaChaPoly_BLAKE2s`, a mismatch **fails the handshake silently** (see [decision 0002](../decisions/0002-remote-head-over-relay-shared-wire.md)), and **most pure-JS Noise libraries hash with BLAKE2b or SHA-256, not BLAKE2s** — so a library can look correct, pass its own tests, and still be unusable here. This spike proves — deterministically, credential-free, no socket/daemon/renderer — that a chosen library drives the **IK** pattern under the exact suite with **early-data**, then records the selection findings for #30 and #7 to build on.

Nothing here is production code. #30 is the first consumer: it swaps the JS↔JS loopback for the real relay transport with **zero change** to the initiator, then adds the Go interop proof, the live-daemon round-trip, the mismatch-fails-silently negative, and the final recommend/reject verdict. #7 is the production session module (real key storage via `safeStorage`, electron-vite wasm bundling, re-key, store wiring).

## Findings note (library-selection half — AC4; the durable record #30/#7 read)

- **Selected library: `noise-c.wasm@0.4.0`** (resolved in `package-lock.json`) — an Emscripten/WASM build of **rweather/noise-c**, the reference C implementation of the Noise Protocol Framework. **Vetted, not hand-rolled**: the cryptography is the reference C library and the wrapper is a thin binding; the suite is chosen by the exact protocol-name string, so there is no room for a silent hash substitution. The three pure-JS candidates the ticket names — `noise-protocol`, `noise-handshake`, `@chainsafe/libp2p-noise` — all hash with BLAKE2b/SHA-256 (and libp2p-noise is XX, wrong pattern too): the exact trap.
- **BLAKE2s support: yes.** Proven directly against the library (mode 1, no harness): (a) the exact suite constructs as both IK roles; (b) a bogus hash token (`…_BLAKE2z`) is rejected with `UNKNOWN_NAME`, so the name is genuinely **parsed, not defaulted**; (c) a completed IK handshake yields a **32-byte** channel-binding hash identical on both sides, while the same suite with `BLAKE2b` yields **64** — so the `…BLAKE2s` name is **not** silently BLAKE2b (the ticket's #1 risk), and the 256-bit width rules out BLAKE2b/SHA-512.
- **Handshake-role / prologue / early-data ergonomics:** `lib.HandshakeState(name, role)` with `NOISE_ROLE_INITIATOR | NOISE_ROLE_RESPONDER`; `Initialize(prologue, s, rs, psk)` takes nullable 32-byte `Uint8Array`s and derives the local static public from the private; a zero-length prologue is passed as `null` to match the daemon's empty-prologue handshake exactly. Early-data rides natively: `WriteMessage(payload)` carries it, `ReadMessage(msg, true)` returns the peer's. **The device token rides the `hello`** as the payload of IK message 1 — mode 2 asserts the responder recovers it byte-for-byte.
- **Post-handshake AEAD:** `HandshakeState.Split()` returns `[send, recv]` **already role-adjusted for both roles** — unlike the Go `flynn/noise` wrapper's raw `(cs1, cs2)`, noise-c collapses the asymmetry itself, so neither side swaps. `EncryptWithAd(emptyAd, pt)` / `DecryptWithAd(emptyAd, ct)` with a zero-length AD; the 64-bit counter nonces are library-owned (the harness never constructs or reuses one).
- **Runtime note for #7:** WASM in the Electron **main** process (Node/WASM, no DOM). The base64-embedded wasm loads in Node/vitest with no bundler asset plumbing (one benign Emscripten streaming-compile fallback warning at first load, from the library, not the harness). electron-vite **bundling** of the wasm for the *packaged* app is unproven here — **#7's concern**. `CreateKeyPair` draws from `crypto.getRandomValues` (CSPRNG); verifying a production static key's entropy source remains a **#7 gate**.
- **Vector obtainability (a finding, not a blocker):** no **published** `Noise_IK_25519_ChaChaPoly_BLAKE2s` handshake vector was obtainable credential-free in this sandbox — the npm package excludes its `tests/` dir and web fetch is unavailable. A self-generated "vector" was deliberately **not** fabricated (it would prove nothing about hash correctness). `noiseSpike.vectors.json` instead pins the BLAKE2s **primitive** by its RFC 7693 Appendix B known-answer (provenance-tagged), verified against the runtime's reference BLAKE2s. The byte-exact **cross-implementation** match that alone distinguishes BLAKE2s from SHA-256 *by value* at the Noise layer is deferred to **#30**, where the Go `flynn/noise` responder emits reference bytes the JS initiator must match — a stronger proof than a static file.

## The harness contract (the deliverable #30 consumes unchanged)

`createNoiseInitiator(config): Promise<NoiseInitiator>` mirrors `createRelayConnection`'s send-out / event-in shape so #30 is a drop-in:

- **Config:** `staticPrivateKey` / `remoteStaticPublicKey` (raw 32-byte X25519), `prologue`, `hello` (early-data for msg 1, carrying the token), `sendFrame` (outbound raw-frame sink — in #30 this is `relay.send`), `onEvent` (typed sink).
- **Handle:** `start()` writes msg 1 exactly once; `onFrame(frame)` feeds one inbound frame; `sendMessage(plaintext)` AEAD-seals a post-handshake frame; `close()` frees the wasm handshake + cipher states, idempotent.
- **Events (sealed union on `type`):** `handshake-complete` (carries the recovered `helloAck`), `message` (decrypted post-handshake plaintext), `error` (a **static reason only, never bytes**).
- **Error reasons (closed set):** `handshake-read-failed` (msg 2 failed MAC / malformed / wrong suite), `transport-decrypt-failed`, `unexpected-frame` (a frame in the wrong state).
- **#30 mapping (trivial):** relay `{type:'connected'}` → `start()`; relay `{type:'message',frame}` → `onFrame(frame)`; harness `sendFrame` = `relay.send`.

## Patterns established

- **The factory is async and does not send; sending is a separate `start()`.** `createRelayConnection` dials on construction (its inbound cannot arrive before the sync constructor returns); here the JS↔JS loopback is synchronous, so a send inside the async factory would **race the peer's wiring**. `createNoiseInitiator` awaits the wasm load, constructs and `Initialize`s the handshake, and returns the handle idle — then `start()` writes msg 1. Reuse this split wherever an async-constructed transport handle feeds a synchronous peer.
- **Classify-don't-forward for a caught crypto-library error.** A wasm-library error string can echo transcript bytes, so a caught error is **mapped to the matching static reason and dropped** — never `reason: e.message`, never logged. This mirrors `relayConnection.ts`'s `pending`-reason discipline and is the security-relevant invariant for the whole transport layer.
- **Log-free by construction as the security control.** Zero `console.*` anywhere in `noiseSpike.ts`; every diagnostic travels as a typed `error` event with a static reason. A test spies all six `console` methods across handshake + transport + error paths and asserts none fire. (The one-time Emscripten streaming-compile warning is warmed away in `beforeAll` before the spies install, so the assertion measures the harness alone.) Same posture as #21.
- **No use-after-free past `close()`.** `close()` sets state to `closed` and frees the per-handshake / per-cipher-state wasm objects; every entry point (`start`/`onFrame`/`sendMessage`) then guards on `state === 'closed'` / nulled handles and is **inert** — no call into a freed wasm object (a real heap-corruption vector). On a handshake read/write error the library **auto-frees the handshake state before it throws**, so the catch nulls `hs` to stay in step. `Split()` likewise consumes+frees `hs`.
- **Single memoized wasm instance at module scope.** `loadNoiseLib()` memoizes one `Promise<NoiseLib>` so the initiator and the test responder share one wasm init — closer to #7's single-instance model and avoids a double-init in the test. `close()` frees per-handle objects, never the process-lived shared lib.
- **Reuse the load-bearing suite constant, never retype it.** The harness passes `NOISE_PROTOCOL` from `src/shared/wire/types.ts` straight to `HandshakeState`; the string is defined once. `src/main` imports shared types via a **relative** path (`../../shared/wire/types`) — the `@shared` alias is not wired for main/preload.

## Lessons learned

*Lifted from the PR body's "Lessons learned" + findings note and the code-review comment.*

- **`noise-c.wasm`'s `Split()` is role-adjusted `[send, recv]` on *both* sides.** The JS layer needs no `(cs1, cs2)` swap that the Go `flynn/noise` wrapper ([`internal/noise`, pyrycode #433](https://github.com/pyrycode/pyrycode)) performs on the responder — noise-c collapses the asymmetry itself. The mode-2 round-trip is the structural pin. Carry this into #30's interop wiring so the two stacks aren't double-swapped.
- **Handshake-hash *length* is the cheap, deterministic distinguisher for the "silently BLAKE2b" trap** (32 bytes vs 64), and it survives random ephemerals. Cross-suite hash *value* comparison does **not** — the ephemerals differ per run. This is why the mode-1 proof asserts width + both-sides-agree rather than a fixed hash value.
- **The published-vector KAT the spec's mode 1 wanted was unobtainable credential-free — and that is a documented finding, not a failure.** The npm package ships no `tests/` and web fetch is denied in this environment (a recurring env constraint — see the memory note on denied external-research tools). The right move was to **not fabricate** a self-generated vector (proves nothing about hash correctness), pin the BLAKE2s *primitive* via RFC 7693, and defer the by-value cross-implementation match to #30's Go interop. Future crypto-conformance spikes in this sandbox should assume published vectors may be unreachable and lean on empirical elimination + a downstream cross-implementation proof.
- **`noise-c.wasm` is CJS with an embedded base64 wasm and no types.** A default import (`import createNoise from 'noise-c.wasm'`) plus a minimal ambient `.d.ts` resolves cleanly under `moduleResolution: Bundler` + vitest — **no `createRequire` needed**. Reuse this import shape in #7; the open question there is electron-vite *bundling* the wasm for the packaged app, not the import interop.

Harmless for this throwaway spike (the only path is the vitest run, where the wasm loads), but the production session module should add a load-failure/timeout surface.
