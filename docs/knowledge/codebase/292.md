# #292 — Observe `queue_state`: decode the queued-backlog snapshot into a typed event

Split from #145 (5-way: **#292 decode** / #293 store / #294 render / #295 command / #296 drop). No
blockers. Shipped as PR [#297](https://github.com/pyrycode/pyrycode-desktop/pull/297), code review
**PASS** (no findings), architect self-review **PASS**. Security-sensitive (a new inbound decode on
the internet-exposed relay/Noise surface); size S; structurally identical to #201 (modal), #214
(`turn_state`), #229 (`tool_result`), #241 (`conversation_created`), #273 (`conversation_updated`).

## Summary

The daemon emits `queue_state` **unsolicited** whenever a per-conversation queued-message backlog
changes — not a reply to any request. This slice adds only the inbound decode: `queue_state` → a
typed `queueState` daemon event carrying the conversation id and the ordered backlog, threaded
through the transport → IPC boundary. **No app state, no UI** — the real consumer is #293's
still-unbuilt store. Seven production files touched, zero created (the same atomic-fan-out floor as
every prior `DaemonEvent`-arm ticket):

- **Wire types** (`src/shared/wire/types.ts`) — `'queue_state'` joins `EnvelopeType`; two new
  exported interfaces, `QueuedItem{queued_msg_id: number, text: string, ts: string}` and
  `QueueStatePayload{conversation_id: string, queued: QueuedItem[]}`, mirroring the daemon SSOT
  (pyrycode #720, `docs/protocol-mobile.md` § Queue) field-for-field. `queued_msg_id` is documented
  as a plain per-conversation counter (integer ≥ 1) that decodes as a **number**, never a string —
  the decoder narrows the type but does not police the range (a daemon guarantee, not desktop's to
  enforce).
- **Decode** (`src/main/transport/inboundMessage.ts`) — `parseQueuedItem` (`isRecord` guard,
  `requireNumber` for `queued_msg_id` + two `requireString` calls) and `parseQueueStatePayload`
  (`requireString` for `conversation_id`, an `Array.isArray` guard on `queued`, then
  `raw.map(parseQueuedItem)`) — the `parseConversationSummary`/`parseConversationsPayload` row +
  array template. `queued: []` maps to `[]` cleanly (AC3: empty is a value, not an error). The
  `case 'queue_state'` decode arm narrows **before** logging (the `tool_result` narrow-before-log
  discipline) so a malformed frame throws first and leaves no diagnostic record; the content-free
  log carries only `{event: 'inbound-decoded', code: 'queue_state', bytes, hash}` — never `text`,
  `queued_msg_id`, or `conversation_id`.
- **Emit** (`src/main/daemonConnection.ts`) — one `case 'queue-state':` in the `switch (inbound.kind)`
  (not `assertNever`-guarded — required for AC2/AC5, not compile-forced), a fresh literal
  `{ type: 'queueState', conversationId, queued }`. Unlike `toolUse`/`toolResult` (which drop
  `conversation_id`), this arm **keeps** it — the snapshot is replacement-truth and #293's store
  keys its held backlog by conversation.
- **`DaemonEvent` arm** (`src/shared/ipc/events.ts`) — `{ type: 'queueState'; conversationId: string;
  queued: readonly QueuedItem[] }`, reusing the wire `QueuedItem` row type verbatim (the
  `conversationsReceived` precedent — no snake→camel remap on array items).
- **Three exhaustive bridges (compile-forced no-op)** — `daemonEventBridge.ts`, `timelineBridge.ts`,
  `modalBridge.ts` each gain a `case 'queueState': return null` (or fall into the existing null
  group). `timelineBridge.ts`'s comment states the load-bearing reason explicitly: `queue_state` is
  daemon *state* per #720, not a turn-stream item, so it is deliberately **not** folded into
  `reduceTimeline` even though the bridge owns five other arms.

`npm test` (1339 passed, 3 pre-existing skips), `npm run typecheck` (validates the compile-time
`queued_msg_id: number` no-drift pin), `npm run build` all green.

## Patterns established

- **A `JSON`-string counter is rejected by `requireNumber`'s `typeof` check alone — no extra
  integer/range validation is added even though the SSOT documents `queued_msg_id` as "integer ≥
  1."** The spec explicitly calls this out as the evidence-based-fix line: the range is a daemon
  guarantee, and policing it here would defend an unobserved failure mode (the
  `parseSessionTransitionPayload` no-cross-validate posture, now reaffirmed on a third field
  family).
- **`queueState` is the first `DaemonEvent` member to carry `conversationId` where its `toolUse`/
  `toolResult`/`turnState` siblings all drop it** — the tell for *why* is whether the event is a
  replacement-truth snapshot (needs a key) versus a delta scoped to "the one active conversation"
  (doesn't). Future daemon-state snapshot arms should default to keeping the id; future turn-stream
  deltas should default to dropping it.
- **A pure inbound-decode slice with a real, wired producer can still have zero observed live
  traffic.** Same as `turnState`/`toolUse`/`toolResult`/`modalShown` before it, `queueState` is
  proven only by unit tests driving `daemonConnection` and all three bridges directly — no `#178`
  e2e run has yet exercised a real `queue_state` frame. Unlike those four, its traffic is not known
  to require the `#179` `interactive` capability flip (queue backlog is daemon state, not part of
  the turn stream), so the gate may simply be "no live daemon build sends it yet," not a capability
  precondition — flag when #178 first observes one.
