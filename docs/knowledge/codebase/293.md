# #293 — Hold the queued backlog in app state (replacement-truth queue store)

Split from #145 (5-way: [#292](292.md) decode / **#293 (this, store)** / #294 render / #295 command
/ #296 drop). Blocked by and shipped after #292 (merged). Shipped as PR #298, code review PASS. Not
security-sensitive (pure renderer state fed by an already-typed, already-decoded event; no
crypto/sockets/tokens). No Figma (headless, no render surface). Size S.

## Summary

Adds the two renderer pieces the queued-backlog data path was missing: a `conversationId`-keyed
Zustand store and a reactive-only subscription binding that feeds it, mirroring the
`sessionIdStore`/`sessionIdBridge` slice field-for-field. Three production files touched (two new,
one additive edit), ~350 total LOC including tests:

- **`src/renderer/src/store/queueStore.ts`** (new, 98 lines) — `QueueState { backlogs:
  ReadonlyMap<string, readonly QueuedItem[]> }`, a key absent from the map meaning "no snapshot
  seen for that conversation yet" (AC3, surfaced as `[]` via the selector, never as a missing key
  check at the read site). `createQueueStore(init?)` (vanilla `createStore`, DI seam) →
  `queueStore` (app singleton) → `useQueueStore(selector)` (narrow-slice hook, first consumer is
  #294). A **single setter** (`setBacklog`), not a reducer — there is exactly one mutation, so a
  discriminated-union action set would be a one-member union. Copy-on-write per key (the
  `runSettingsWriteStore` `ReadonlyMap` idiom): clone the map, `set(conversationId, queued)`,
  replace — never mutate in place. `queued` held **verbatim by reference**, wire snake_case, no
  camelCase remap, no coercion (the `conversationListStore` posture). Unconditional write: an empty
  `queued: []` sets that key to `[]` (a real replacement, not a delete) — stale-key eviction is left
  to #197 via the new `selectBacklogs` whole-map read surface. `selectBacklogFor(conversationId)`
  is a selector *factory* returning `s.backlogs.get(id) ?? EMPTY_BACKLOG`, where `EMPTY_BACKLOG` is
  a module-level stable `[]` reference so the "not yet seen" default never churns re-renders, and a
  write to a *different* key never breaks reference-equality for an existing key's watcher.
- **`src/renderer/src/store/queueBridge.ts`** (new, 73 lines) — `translateQueueState(event):
  QueueSnapshot | null`, a `switch` owning exactly `case 'queueState'` (rebuilt as a fresh
  named-field literal, the `modalBridge` idiom — never `return event`) and `default: return null`.
  Soft `default: null`, not `assertNever`: this is the *fourth* independent subscriber on the
  `onDaemonEvent` channel (`daemonEventBridge`, `timelineBridge`, and `modalBridge` all already
  no-op `queueState` from #292), not one of those three typecheck-gating exhaustive bridges.
  `subscribeQueue(onDaemonEvent, setBacklog)` guards on `snapshot !== null` (not truthiness), so an
  empty `queued: []` snapshot is never dropped as falsy, and returns the `onDaemonEvent` off-handle
  as its cleanup. `QueueData(): null` is the headless container — one subscribe effect (deps `[]`)
  on mount, `window.pyry` dereferenced only inside the effect so it server-renders to `''` without
  a bridge mock (the `SessionIdData` invariant). Reactive-only: unlike `conversationListBridge`,
  `queue_state` is daemon-pushed unsolicited, so there is no request half and no connected-edge
  trigger.
- **`src/renderer/src/App.tsx`** (mod, +6 lines) — imports `QueueData` and mounts `<QueueData/>` as
  a fourth headless sibling alongside `<ConversationListData/>` / `<SessionIdData/>` /
  `<RunSettingsWriteData/>`, with an inline comment explaining the app-level always-listening
  rationale: a `queue_state` snapshot can arrive before #294 is ever mounted, and (per daemon
  #878/#879) several for different conversations can arrive back-to-back on reconnect. Purely
  additive — App's server-render-to-`''` invariant is preserved.

26 new tests across `queueStore.test.ts` (11) and `queueBridge.test.ts` (11, plus the `QueueData`
server-render check): initial-empty with the stable `EMPTY_BACKLOG` reference (AC3); verbatim
by-reference recording (AC1); replacement — most-recent-wins including the removed-entry case
(AC2); clear-on-empty (AC2 clear case); keyed independence across two conversations, both the value
check and a reference-stability check proving a foreign-key write doesn't re-render an existing
key's watcher (the #878/#879 correctness proof); `selectBacklogs` whole-map read; DI isolation
between two `createQueueStore()` instances; bridge per-arm translation (owned arm + a sample of six
unrelated arms → `null`); the `!== null` guard on an empty snapshot; the off-handle cleanup; two
seam tests driving a real `createQueueStore()` end-to-end through `subscribeQueue`, including the
two-different-conversations non-clobber case; and `QueueData`'s `renderToStaticMarkup(...) === ''`
neutral-paint check. `npm test`, `npm run typecheck`, `npm run build` all green.

## Patterns established

- **A selector *factory* (`selectBacklogFor(id) => (state) => ...`), not a bare selector, is the
  right shape for a per-key read into a keyed store.** Every prior store in this codebase
  (`conversationListStore`, `sessionIdStore`, `runConfigStore`) exposes one flat value and a bare
  `selectX(state)`. `queueStore` is the first keyed-by-external-id store, and its selector needed a
  parameter — closing over `conversationId` and returning the narrow selector keeps the
  `Object.is`-reference-stability property (a write to a foreign key must not break an existing
  key's memoized selector) intact without the caller re-deriving it. Future per-conversation (or
  otherwise externally-keyed) renderer state should follow this factory shape, not a flat selector.
- **A `ReadonlyMap` copy-on-write setter is now proven twice** — first in
  `runSettingsWriteStore`'s reducer, now in `queueStore`'s single setter — confirming the idiom
  (clone-set-replace, never mutate in place) generalizes independent of whether the store around it
  is reducer-shaped or single-setter-shaped.
- **A fourth independent `onDaemonEvent` subscriber coexists cleanly** alongside
  `daemonEventBridge`/`timelineBridge`/`modalBridge`, extending the three-subscriber precedent
  (#223) to four: each bridge stays independently scoped to the arms it owns, and a channel member
  can go un-owned by every *exhaustive* bridge (all three already null `queueState`) while still
  having a real, independent, non-exhaustive consumer.
