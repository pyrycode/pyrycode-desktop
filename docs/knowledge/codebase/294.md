# #294 — Render the queued backlog distinctly in the thread

Split from #145 (5-way: [#292](292.md) decode / [#293](293.md) store / **#294 (this, render)** /
#295 command / #296 drop). Blocked by and shipped after #293 (merged PR #298). Shipped as PR #301,
code review PASS (one non-blocking NIT). Not security-sensitive (render-only, reads app state, no
transport/`window.pyry`/IPC). Figma N/A-with-justification (the mobile file draws only the
populated/delivered thread — the documented #148 gap; anchor node 16-8 confirms layout only). Size S.

## Summary

Adds the render surface over #293's queue store: a pure `QueuedBacklog` view plus a thin
store-bound `QueuedBacklogControl`, both added inside the existing `ConversationScreen.tsx` (no new
file — the `ThinkingIndicator` / `ConnectionBanner`+`ConnectionBannerControl` container/view
idiom). Two production files touched, no new production file:

- **`src/renderer/src/screens/conversation/ConversationScreen.tsx`** (+54 lines) —
  `QueuedBacklog({ items }: { items: readonly QueuedItem[] })`: empty → `null` (the
  `ThinkingIndicator` posture, no region/no chrome, AC4); non-empty → one row per item in array
  order (= enqueue order) inside a `.conversation__queued` wrapper, each row
  `message-row message-row--user` / `bubble--user` (the delivered user-bubble treatment, reused
  verbatim) carrying its own `data-thread-role="queued"` — distinct from delivered
  `data-thread-role="user"`, the AC2 hook. `item.text` renders as auto-escaped React children,
  never `dangerouslySetInnerHTML` (the wire type's own doc comment mandates plain-text render).
  React key = `item.queued_msg_id`, a real per-conversation-unique integer. `QueuedBacklogControl`
  is an in-file, unexported container: `const selectMilestoneBacklog =
  selectBacklogFor(MILESTONE_CONVERSATION_ID)` hoisted to module scope (created once), then
  `useQueueStore(selectMilestoneBacklog)` — a pure store read, no effects. Mounted in the render
  tree after `<ThinkingIndicator/>` and before `<StatusRow/>`, so queued rows read as the tail below
  the delivered thread and the working indicator.
- **`src/renderer/src/screens/conversation/conversation.css`** (+18 lines) — one new region rule,
  `.conversation__queued`: `flex: 0 0 auto` (the `.conversation__thinking` non-growing precedent,
  never the thread's `1 1 auto`), column + `--space-3` gap + `--space-4` inset (mirrors
  `.conversation__thread`), and `opacity: 0.5` — the single load-bearing "waiting / not yet run"
  signal, reusing the `.tool-row` pending-dimming precedent rather than a new token or color
  literal. No new bubble/row modifier class — the region-level dimming *is* the "queued" modifier.

Reads the single active conversation's backlog via `MILESTONE_CONVERSATION_ID` (from
`composerSend.ts`, the same constant the composer sends under) rather than threading a
conversation id through nav — the architecture spec explicitly ruled out adding nav plumbing for
this slice, since `ConversationScreen` has no conversation id in scope and `PairedShell` is
conversation-agnostic.

4 new tests in `ConversationScreen.test.tsx`, added to the existing `QueuedBacklog` pure-view
describe block plus one container-smoke line in `ConversationScreen — store binding`: empty → `''`
(AC4); two-plus items in enqueue order with both texts present (AC1); region + `queued` role
present, `bubble--user` reused, delivered `user` role absent (AC2, distinctness); `<b>x</b>`
fixture → escaped `&lt;b&gt;x&lt;/b&gt;`, never live markup (load-bearing, apostrophe-free per the
`renderToStaticMarkup`-escapes-`'` desktop lesson); container smoke against the empty queue store
asserts `not.toContain('conversation__queued')`, which also keeps the pre-existing #179 AC4
split-brain guard (`not.toContain('data-thread-role')` / `not.toContain('conversation__thread')`)
green untouched. `npm test` (1365 pass / 3 pre-existing skips), `npm run build` both clean.

## Patterns established

- **A fourth render slice ships with zero new production files**, extending the
  `ThinkingIndicator` (#215) / `ConnectionBanner`+`ConnectionBannerControl` (#279) precedent: a
  pure exported view + an in-file unexported store-bound container, both living inside
  `ConversationScreen.tsx`, is now the default shape for "one more region reading one more store
  slice" — reach for a new file only when the view/container pair grows real internal structure.
- **A selector factory hoisted to module scope, called once at import time**, is the right way to
  bind a keyed selector (#293's `selectBacklogFor`) to a fixed id for the module's lifetime — one
  more data point (after #293 itself) that `selectX(fixedArg)` at module scope, not per-render, is
  how this codebase avoids re-creating a selector function on every render.

## Lessons learned

From the PR body's own "Lessons learned" section: the `data-thread-role="queued"` seam appears
only in the populated pure-view tests — against the empty queue store, `QueuedBacklog` returns
`null`, so the pre-existing #179 AC4 split-brain guard stays green *untouched* (no edit needed to
those assertions), because the region class `conversation__queued` deliberately never contains the
`conversation__thread` substring. Worth flagging forward: any future render slice that adds a new
region class near the thread should keep checking it doesn't collide with that substring, since
nothing enforces it structurally beyond naming discipline.

Code review raised one non-blocking NIT (not actioned, by design): region-level `opacity: 0.5`
dims `bubble--user` text along with the rest of the row, which measurably lowers legibility for
content the user may want to keep reading — unlike the transient `.tool-row` chip this precedent
was borrowed from. Not a gate: it matches the shipped precedent, sits within the documented Figma
gap, and the spec already flagged region-vs-bubble dimming as an open question for #296 to revisit
(moving `opacity` from `.conversation__queued` onto a future `bubble--queued` modifier is a one-line
relocation if #296 wants a per-row override, e.g. for a cancel-pending state).
