# #296 — Drop a queued message: drop affordance on queued rows

Split from #145 (5-way: [#292](292.md) decode / [#293](293.md) store / [#294](294.md) render /
#295 command (re-split into [#299](299.md)/[#300](300.md)) / **#296 (this, drop)**). The last
remaining slice of the queue-drop family — blocked by and shipped after both #294 (render) and
#300 (command), both merged. Shipped as PR #313, spec `71732fe`, code `279a6f2`. Not
security-sensitive (pure renderer wire-together — no new IPC channel, no preload change, no
main-side work, no wire-type change; the untrusted renderer→main boundary guard already lives
main-side in #300). Figma N/A-with-justification (the same documented #148/#294 gap — the mobile
file draws only the delivered thread, node 16-8). Size S.

## Summary

Wires the merged render (#294's `QueuedBacklog`) to the merged command (#300's
`dequeueMessageCommand`). Two production files touched, one new:

- **`src/renderer/src/screens/conversation/dropQueuedMessage.ts`** (new) — a pure, React-free
  guarded-send helper, `dropQueuedMessage(conversation_id, queued_msg_id, { sendCommand })`. A
  strict subset of `cancelPrompt` (`modalResolution.ts`): the same `try { sendCommand(...) } catch
  { console.error }` guard, but **no** local dispatch (AC3 forbids optimistic removal — dropping
  never mutates the queue store) and **no** camelCase→snake rename (the wire fields are already
  snake_case). Calls `dequeueMessageCommand({ conversation_id, queued_msg_id })` from
  `@shared/ipc/commands` (#300) and passes the result straight to the injected `sendCommand`.
- **`src/renderer/src/screens/conversation/ConversationScreen.tsx`** (+56 lines) — `QueuedBacklog`
  gains a **required** `onDrop: (queuedMsgId: number) => void` prop (the `PermissionModalView` "a
  view that cannot answer is a bug" rule), rendering an icon-only `<button>` as a **leading sibling**
  of `.bubble--user` inside each queued row (`.message-row--user` is right-aligned, so the leading
  position sits the button at the row's inner edge). The button carries a client-owned
  `aria-label="Drop queued message"` (an icon-only control needs an accessible name — the
  `.composer__send` / `.status-sheet__close` idiom) and an inline `aria-hidden` SVG "×" glyph;
  `onClick={() => onDrop(item.queued_msg_id)}`. `QueuedBacklogControl` binds `onDrop` to
  `dropQueuedMessage`, closing over `MILESTONE_CONVERSATION_ID` (the conversation-id wall —
  `QueuedItem` carries no `conversation_id`, so the container supplies it, not the view) and
  dereferencing `window.pyry.sendCommand` **only inside the click closure**, never during render —
  the `Composer.handleSubmit`/`PermissionModal` discipline, keeping the container's empty-backlog
  smoke test bridge-free.
- **`conversation.css`** (+36 lines) — `.queued-row__drop` reuses the `.status-sheet__close`
  icon-button treatment (transparent background, round hover surface, `:focus-visible` outline, all
  tokenized). It inherits the region's 50%-dimmed `.conversation__queued` opacity — a child
  `opacity: 1` cannot escape a parent opacity compositing group — so the open question the #294 spec
  left open (region-dim vs. full-opacity control) resolved to "leave it dimmed"; see Lessons learned.

No optimistic removal: the row leaves only when the daemon's next `queue_state` snapshot replaces
the backlog and the existing #293/#294 live subscription re-renders — `dropQueuedMessage` never
touches `useQueueStore`. AC4/AC5 (affordance only on queued rows, delivered rows unaffected) are
**structural**, not conventions: the button exists only inside `QueuedBacklog`; `Timeline` draws the
delivered rows and this ticket does not touch it.

New `dropQueuedMessage.test.ts` (2 cases: right ids → right command via an exact `toEqual` on the
decoded command shape; a throwing `sendCommand` does not propagate). `ConversationScreen.test.tsx`'s
existing `QueuedBacklog` describe block cascade-updated (4 existing render calls gain a no-op
`onDrop`) plus one new case asserting exactly one `.queued-row__drop` button and one
`aria-label="Drop queued message"` per queued row. `npm test` (1398 passed, 3 pre-existing skips),
`npm run build` both clean.

## Patterns established

- **A drop-style effect helper is `cancelPrompt` minus the dispatch, not a new shape.** Every guarded
  outbound send in this codebase (`submitMessage`, `answerPrompt`, `cancelPrompt`, `runUnpair`, now
  `dropQueuedMessage`) is a co-located, React-free, injected-`sendCommand`, `try/catch`-swallowed
  function — the only axis that varies is whether it also performs a local optimistic dispatch.
  `dropQueuedMessage` is the first of this family to *omit* the dispatch entirely, confirming the
  shape scales down cleanly when an AC explicitly forbids optimism, not just up when one requires it.
- **A required injected-effect prop is what forces the render-call test cascade**, not a design
  accident — making `onDrop` required (rather than optional-with-a-noop-default) is what turned an
  un-updated `<QueuedBacklog>` call site into a compile error, the intended signal per the spec.

## Lessons learned

From the PR body's own "Lessons learned" section:

- `.conversation__queued`'s region-level `opacity: 0.5` cannot be overridden back to full brightness
  by a child element's `opacity: 1` — a parent `opacity` less than 1 creates a stacking/compositing
  context a descendant's own opacity cannot escape. The #294 spec's open question ("leave the drop
  button dimmed with the region, or bump it back to full opacity for affordance clarity?") resolved
  itself: bumping it would require restructuring #294's dimming (e.g. moving `opacity` onto a
  `bubble--queued` modifier instead of the region), which was out of scope for this pure
  wire-together. Shipped dimmed — the hover surface + focus outline carry the affordance instead.
  Any future ticket wanting a brighter drop control needs to revisit #294's region-vs-bubble opacity
  placement first, not just this button's own CSS.
- Counting a class in server-rendered markup needs the closing quote in the match
  (`class="queued-row__drop"`), not a bare substring — `queued-row__drop-icon` (the SVG's class)
  shares the `queued-row__drop` prefix and double-counts a substring match.
