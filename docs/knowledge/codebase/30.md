## Verdict for the #7 session module (AC4) — **RECOMMEND**

`noise-c.wasm@0.4.0` interoperates with the real Go `flynn/noise` stack. **There is no Go↔JS interop wall** for the production session module to fear; #7 can build on the #29 harness contract as-is.

- **Interop result: achieved.** A byte-identical IK handshake completed across the two independent stacks, and a post-handshake AEAD frame round-tripped (`sendMessage(P)` → Go `recv.Decrypt` → Go `send.Encrypt` → JS `message` with `plaintext === P`). Reaching transport state across **two independent hash implementations** is the by-value **BLAKE2s-vs-SHA-256/BLAKE2b** proof #29 explicitly deferred here: a divergent hash MAC-fails before any frame opens. The negative twin confirms it — a `--hash blake2b` responder MAC-fails reading msg 1 and never reaches transport.
- **Gotchas encountered vs anticipated — no surprises.** The mobile team's Kotlin↔Go interop needed zero byte-level debugging; this one did too. Framing (base64-std agrees Go↔JS; the live adapter composes the #5 codec's `{v:2,type,data}` inner frame unchanged), early-data (`hello` on IK msg 1, `hello_ack` on IK msg 2 — recovered byte-for-byte in **both** directions), nonce/counter (library-owned per-`CipherState` 64-bit counters on both sides; the harness never constructs, resets, or reuses a `(key,nonce)` pair), empty-AD (`Encrypt(nil,nil,pt)` ↔ `EncryptWithAd(EMPTY_AD,pt)`), and empty prologue (noise-c `null` ↔ flynn nil `Config.Prologue`) all held as documented.
- **The `Split()` asymmetry held exactly as #29 flagged.** See the dedicated section below — it is the one load-bearing interop line, and it passed on the first correct wiring.

## The `Split()` asymmetry — the one load-bearing interop line

This was #29's headline carried-forward risk and the single most likely interop failure mode. It held exactly as documented:

- **noise-c (JS initiator):** `Split()` returns `[send, recv]` **already role-adjusted for both roles** — the JS side does **no** swap.
- **flynn/noise (Go responder):** the split rides the final handshake call, not a separate method — `WriteMessage`/`ReadMessage` return `(out, cs1, cs2, err)` where **`cs1` carries initiator→responder and `cs2` carries responder→initiator, for both roles**. So the responder maps **`recv = cs1, send = cs2`** (the swap pyrycode's `internal/noise` wrapper does inside its responder path). See `noiseSpikeResponder/main.go:107`.
- **Net:** each side swaps at most once; crossing them completes the handshake but MAC-fails the *first transport frame*. That is exactly why **AC1's AEAD round-trip — not "no error thrown" — is the structural pin**: a double-swap sails through the handshake and only detonates on the first sealed frame.

## Patterns established

- **Interop proofs need the real peer library, not a second copy of ours.** A JS↔JS responder (as #29 used) re-proves conformance; it cannot expose a Go↔JS framing/Split wall or distinguish BLAKE2s from SHA-256 *by value*, because both ends share one implementation. The interop proof therefore runs the daemon's *actual* library (`flynn/noise`) as a throwaway loopback responder — same library, same suite, so a byte-identical handshake there is real cross-stack evidence, and it stays credential-free, offline, and deterministic.
- **Reaching transport state is the by-value hash proof; a live subprocess is mandatory, not a fixture.** IK message 1 carries the initiator's random ephemeral, so a canned transcript is impossible — value-comparisons don't survive random ephemerals (a #29 finding). The proof that survives is *behavioural*: complete the handshake and round-trip one AEAD frame. Divergent hash choices MAC-fail before any frame opens, so simply reaching transport state across two implementations is the distinguisher.
- **The Go child is owned by its test and killed in `finally`.** Build the binary once at module load (see the lesson below), spawn a fresh child per test over a line protocol, and `kill('SIGKILL')` it via `afterEach` cleanup — no child outlives its test, no orphan process. The initiator's `close()` and the live relay's `close()` are likewise `finally`-scoped.
- **Bounded waiters keep negatives deterministic.** A notify/`check()` waiter resolves (never rejects) on the awaited event *or* a ~2 s deadline inside vitest's 5 s default, so a negative test that must observe "no completion" terminates cleanly instead of hanging — the same convert-hang-to-timeout posture the #22 supervisor and #21 connection use.
- **Consume the upstream primitives literally unchanged.** The #29 initiator, #21 `createRelayConnection`, and #5 codec appear in the diff only as imports. The initiator's `sendFrame`-out / `onEvent`-in shape (deliberately mirrored on `createRelayConnection` in #29) made the live path a thin framing adapter: relay `{type:'connected'}` → `start()`, relay `{type:'message',frame}` → decode → `onFrame`, `sendFrame` → `relay.send`. This is the drop-in #29 was designed to enable.
- **Log-free by construction extends across the process boundary.** The JS harness reuses #29's six-method console-spy assertion over handshake + transport + error paths; the Go child emits only tagged base64 frames (synthetic bytes) and static `ERR` reasons — never key material, plaintext, or `flynn` error text (a flynn error string can echo transcript bytes, so it is mapped to a static reason and dropped, the same classify-don't-forward discipline as the JS side).
- **The live credential lives only in `process.env`.** The device token/server-static/relay-URL/server-id are read at runtime, never logged/echoed/committed, and the token rides *inside* the encrypted `hello` (Noise early-data), never a relay-readable header (the `X-Pyrycode-Token` header is present-but-ignored under relay v2).

## Lessons learned

*Lifted from the PR body's "Lessons learned" + the findings verdict and the code-review comment.*

- **`flynn/noise` returns its cipher states from the final handshake call, not a separate `Split()`.** `WriteMessage`/`ReadMessage` return `(out, cs1, cs2, err)`; for IK the responder gets its states from `WriteMessage` (msg 2), the initiator from `ReadMessage` (msg 2). `cs1` = init→resp, `cs2` = resp→init for **both** roles, so the responder maps `recv=cs1, send=cs2`. This is the swap #7 must mirror if it ever speaks to a raw `flynn/noise` peer — noise-c hides it, flynn exposes it.
- **Gate `describe.skipIf` on a flag resolved at *collection* time, not in `beforeAll`.** vitest evaluates `skipIf` conditions when the block is defined, before `beforeAll` runs. So the Go build is done synchronously at module load (`execFileSync`) and `goAvailable` is known before the skip decision — a build inside `beforeAll` would leave every Go-dependent test *permanently* skipped. The toolchain-absent fallback (`goAvailable=false` → static skip warning) is the graceful degradation, and the operator-gated live path then carries the real-Go proof.
- **A wrong peer-static in IK surfaces at the *responder's* `ReadMessage`, not the initiator's.** With a wrong `remoteStaticPublicKey`, the initiator's `es`/`ss` DH outputs disagree with the responder's, so the encrypted static in msg 1 fails its MAC on the *responder* side — the JS initiator simply never receives a msg 2 (it never completes rather than surfacing `handshake-read-failed`). Useful when classifying live-path failures: a Noise-layer key mismatch shows up as a 4426 close, not a local decrypt error.
- **The benign Emscripten streaming-compile warning is stderr, not `console.*`.** It fires once at wasm load and is warmed away in `beforeAll` before the spies install, so the log-free assertion still measures the harness + adapter alone — same posture as #29.
- **Two non-blocking NITs the review flagged, correct as-is for a throwaway `*.test.ts`:** event narrowing via `as { … }` casts after a `.find(e => e.type === …)` (a `.type ===` type-guard would narrow without the cast; safe by construction), and one deliberate `console.warn` at module load surfacing the Go-toolchain-absent skip (byte-free, outside the console-spy scope, and better than a silent skip).
