# #300 — Send `dequeue_message`: `dequeueMessage` command + IPC + connection method

Command-path half of the queue-drop path, blocked on [#299](299.md) (the wire type + frame builder,
merged 2026-07-12). Split from [#295](https://github.com/pyrycode/pyrycode-desktop/issues/295) along
the #235/#236 seam (see the [#145 split record](145.md) in memory). Shipped as PR
[#309](https://github.com/pyrycode/pyrycode-desktop/pull/309), spec `61a530b`, code `5823077`.
Security-sensitive (constructs and dispatches an outbound frame on the internet-exposed relay path,
and owns the untrusted renderer→main boundary guard); size S; a structural clone of `createConversation`
(#241) / `answerModal` (#236) minus the token mint. **Scope boundary — command path only, no UI**: adds
no renderer surface. The drop affordance that calls this command is a separate later slice (#296).

## Summary

Wires #299's `DequeueMessagePayload` + `buildDequeueMessage` to the renderer→main command path. Five
production files, none new:

- `src/shared/ipc/commands.ts` — a tenth `RendererCommand` member,
  `{ type: 'dequeueMessage'; payload: DequeueMessagePayload }`, reusing the wire payload **verbatim**
  (no `Omit`-derivative, unlike `answerModal`'s token-excluded payload — dequeue is ungated, so there
  is no token to strip). Pure constructor `dequeueMessageCommand(fields)` clones `sendMessageCommand`.
  `isRendererCommand` gains `case 'dequeueMessage'`, guarded by a new module-local
  `isDequeueMessagePayload` — `conversation_id` present-and-string, `queued_msg_id`
  present-and-**number**, a `typeof` check only (no integer/positive/range check, matching the
  `requireNumber`-alone posture of the #292 decode guard). Structural minimum: a smuggled extra field
  is not rejected here. The union's header doc comment updated "Nine members today" → "Ten".
- `src/main/daemonConnection.ts` — `dequeueMessage(payload)`, the `send`/`createConversation` twin:
  inert no-op when `driver === null`, builds a **fresh literal** naming exactly the two modeled fields
  (never a spread of `payload` — the deterministic anti-smuggling net, #236's posture), shares the one
  monotonic `nextEnvelopeId` counter (no second counter, incremented only after a successful build),
  `try/catch` classify-don't-forward (the caught object is dropped — never logged, since its message
  could echo the payload), never throws out of the module (parity #490). Ungated fire-and-forget: no
  reply is expected, so there is no correlation memory to leave dangling.
- `src/main/index.ts` — a `case 'dequeueMessage'` in the `onCommand` switch, forwarding directly to
  `connection.dequeueMessage(command.payload)` — no orchestrator, no facade (mirrors `requestSnapshot`).

Two test files: `commands.test.ts` gains the constructor pass-through test plus positive (well-formed,
and well-formed-with-extra-field) and negative (missing payload, `payload: null`, `payload: {}`,
non-string `conversation_id`, non-number `queued_msg_id`) guard cases. `daemonConnection.test.ts` gains
a new describe block (template = `createConversation`'s): no-op before `start()`; AC5 — an exact
`toEqual({ conversation_id, queued_msg_id })` on the decoded payload after `dequeueMessage(...)`, which
is what actually proves no answer-token and no nonce were added; shares the id counter with `send`
(`sent[0].id === 2`, `sent[1].id === 3`); strips a smuggled extra field (cast through
`as DequeueMessagePayload` to get it past the compiler); no-throw when the driver throws (parity #490).

`npm test` (1381 passed, 3 pre-existing skips), `npm run typecheck`, `npm run build` all green.
Architect self-review verdict **PASS** (all threat categories covered); code review verdict **PASS**,
no findings.

## Patterns established

- **An ungated outbound command is `createConversation`'s shape minus the token, not a new shape.**
  The full quintet — sealed union member reusing the wire payload verbatim, pure constructor, a
  `typeof`-only boundary guard, a `driver === null` no-op connection method with a fresh-literal build
  sharing the one envelope-id counter, and a one-line `index.ts` switch case — repeats unchanged from
  #241/#236. The only axis that varies between an outbound command's siblings is whether the payload
  needs an `Omit`-derivative (gated, token present) or the wire type verbatim (ungated, no token) — the
  scaffolding around it is otherwise identical.
- **The AC5-style exact-`toEqual` assertion is the test that actually proves "no token added,"** not a
  code read. Because `dequeueMessage` fresh-literal-constructs the frame from exactly two named fields,
  asserting the decoded payload equals `{ conversation_id, queued_msg_id }` with `toEqual` (not
  `toMatchObject`) fails on any extra key — the same technique #236/#241 established, reused here to
  demonstrate the *absence* of an `answer_token` rather than the presence of one.
