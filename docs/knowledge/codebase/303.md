# #303 — Decouple `saveDebugBundle`'s no-byte-leak assertion from `mkdtemp` temp-path noise

**Shipped:** 2026-07-12 · **Size:** XS · **Labels:** `bug`, `security-sensitive` (the assertion guards a content-blindness invariant, so the fix's teeth were audited, not just its flake removal). **Scope:** one file, `src/main/saveDebugBundle.test.ts` — a single assertion + comment + one added positive-control line. `src/main/saveDebugBundle.ts` (production) untouched.
**Spec:** `docs/specs/architecture/303-savedebugbundle-noleak-assertion.md` · **PR:** [#304](https://github.com/pyrycode/pyrycode-desktop/pull/304). Not a split.

Fixes a flaky assertion in the [Save debug bundle (persistence)](../features/save-debug-bundle.md) test suite (#117) that intermittently failed on unrelated, clean PRs. First observed 2026-07-12 during QA on PR #302 (#299), whose diff has zero import-graph overlap with `saveDebugBundle` — confirming the flake was pre-existing, not PR-caused.

## What shipped

The failing test (`saveDebugBundle.test.ts:74`, "rejects (catchably) when dir does not exist, with an errno code and no byte values") writes `bytes = new Uint8Array([0x11, 0x22, 0x33])` (decimals **17, 34, 51**) and provokes a rejection via a non-existent directory. The old guard:

```ts
for (const b of bytes) expect(text).not.toContain(String(b))   // bare "17" / "34" / "51"
```

`text` embeds the full failing path, which is built from `mkdtemp(join(tmpdir(), 'pyry-bundle-'))` — a 6-character `[0-9A-Za-z]` random suffix. When that suffix (e.g. `pyry-bundle-34GTBc`) coincidentally contained one of the 2-digit substrings, the assertion fired on path noise, not a real leak.

The fix replaces the per-byte loop with a check against the array's natural string coercion:

```ts
expect(text).not.toContain(String(bytes))   // String(bytes) === "17,34,51"
```

`String(bytes)` is the exact output a `${bytes}` template interpolation would produce — comma-delimited. `mkdtemp` suffixes are alphanumeric-only, so a comma-bearing needle can never collide with OS-generated path content. A one-line positive control was added immediately after, proving the predicate is non-vacuous:

```ts
expect(`bundle bytes: ${bytes}`).toContain(String(bytes))
```

`npm test` (1371 passed / 3 pre-existing skips), `npm run typecheck`, `npm run build` all green (per PR).

## Design in one paragraph

The root defect was the *representation* being checked, not the byte values themselves: any single-byte decimal (1–3 digits, all `[0-9]`) is a strict subset of the `mkdtemp` charset, so no per-byte decimal check is structurally immune to collision — "widen the prefix" and "pick different byte values" both fail for the same reason. Immunity requires a rendering that carries a delimiter a temp-path segment can never contain. `String(bytes)`'s comma-joined form is that rendering, and it also happens to be the *exact* shape of the leak the test is meant to catch (a naive `${bytes}` interpolation into a thrown error) — so tightening the assertion strengthened its fidelity to the real threat model at the same time it removed the flake.

## Patterns established

- **A no-leak assertion's needle must be evaluated for representation-level collision risk against its surrounding noise, not just cardinality.** A per-element bare-decimal check reads as more thorough than a single whole-value check, but here it was strictly worse: it multiplied the collision surface (3 independent 2-digit substrings vs. one comma-delimited string) against the exact charset (`[0-9A-Za-z]`) the noise source uses.
- **When narrowing a security-sensitive regression guard, pair it with a positive control.** Because the ticket's whole risk was "fix the flake while silently gutting the guard," a one-line assertion proving the same predicate fires on a synthetic leak turns "we reasoned the guard still has teeth" into a checked, deterministic fact — the "different fabric" belt-and-suspenders move for a stochastic-agent-authored test fix.
- **Evidence-based fix selection stops scope creep on a flaky-test ticket.** The spec explicitly declined to add speculative hex- or space-joined-rendering checks: the AC-named leak shape is the `${bytes}` coercion, not a hypothetical `.toString('hex')` that has never been observed in this codebase.

## Testing

- Rejection is still asserted to be an `Error` with a truthy errno `code` (unchanged).
- `message + " " + code` no longer contains `String(bytes)` — the decoupled no-leak guard, immune to `mkdtemp` suffix content by construction.
- Positive control: a synthetic string embedding `${bytes}` does contain `String(bytes)`, proving the negative assertion isn't vacuous.
- No other test in the suite carries the bare-per-byte-decimal pattern (`grep "not.toContain(String" src/` → single hit, confirmed pre-fix by the ticket and post-fix by code review).
