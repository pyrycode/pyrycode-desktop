# #306 — Send the `interrupt` control frame from the background process (command + IPC)

Command-path slice of the stop-a-running-turn feature, blocked on [#305](305.md) (the wire type +
frame builder, merged). Split from [#146](https://github.com/pyrycode/pyrycode-desktop/issues/146)
(interrupt-running-turn), slice 2 of 3 (memory: `ticket-146-interrupt-turn-split`). Shipped as PR
[#314](https://github.com/pyrycode/pyrycode-desktop/pull/314), spec commit `724bec3`, code commit
`3a90c5f`. Security-sensitive (constructs and dispatches an outbound control frame on the
internet-exposed relay path, and owns the untrusted renderer→main boundary guard); size S; a
three-file clone of the bare-member `requestConversations` + fire-and-forget `dequeueMessage`
siblings. **Scope boundary — command path only, no UI**: adds no renderer surface. The composer
stop-state affordance that will call this command is a separate later slice, [#307](https://github.com/pyrycode/pyrycode-desktop/issues/307).

## Summary

Wires #305's `buildInterrupt` builder to the renderer→main command path. Five files touched (three
production, two test), none new:

- `src/shared/ipc/commands.ts` — an eleventh `RendererCommand` member, the bare `{ type: 'interrupt' }`
  (no `payload` — mirrors `requestConversations`/`requestDebugBundle`, not the payload-bearing
  `dequeueMessage`). Pure zero-arg constructor `interruptCommand(): RendererCommand`. `isRendererCommand`
  gains `case 'interrupt': return true` — load-bearing: without it the member falls through to
  `default: return false` and is silently rejected at the boundary. Header doc updated to name the bare
  member and reaffirm AC5 (no field on the member can hold a token/key/raw frame).
- `src/main/daemonConnection.ts` — `interrupt(): void`, a line-for-line clone of `requestConversations`:
  `driver === null` inert guard, `buildInterrupt({ id: nextEnvelopeId, ts: now() })` (**no** payload
  block — `buildInterrupt` takes no payload arg), shares the one monotonic `nextEnvelopeId` counter
  (advanced only on a successful build), `catch {}` silent drop (parity #490, classify-don't-forward
  #62). Fire-and-forget: no reply is expected, so no correlation memory is recorded or left dangling.
- `src/main/index.ts` — one `case 'interrupt'` in the `onCommand` switch, forwarding directly to
  `connection.interrupt()` — no orchestrator, no facade (mirrors `requestConversations`). The switch has
  no `assertNever`/`default`, so this arm had to be added by hand; omitting it would let a validated
  `interrupt` command reach the dispatcher and silently drop.

Two test files, both cloning existing sibling blocks: `commands.test.ts` gains the factory round-trip
(`interruptCommand()` returns exactly `{ type: 'interrupt' }`, no `payload` property), the bare-guard
acceptance test (with and without a tolerated extra field), and a compile-time union-membership proof.
`daemonConnection.test.ts` gains a new describe block (template = `requestConversations`'s): no-op
before `start()` (no driver, nothing forwarded, no throw); after handshake forwards exactly one
envelope with `id: 2`, `ts: FIXED_TS`, and `payload` deep-equal `{}` (the present-empty-payload
assertion, proving the #305 builder's shape survived the round-trip); shares the one id counter with
`send` (`send` → id 2, `interrupt` → id 3); does not throw when the driver's `sendMessage` throws
(parity #490).

`npm test` (1405 passed, 3 pre-existing skips), `npm run typecheck`, `npm run build` all green.
Architect self-review verdict **PASS** (all threat categories covered — see `## Security review` in
the spec); code review verdict **PASS**, no findings ("textbook clone… ships as-is").

## Patterns established

- **A bare, fire-and-forget command's structural twin is chosen the same way a bare wire builder's
  is (#305): by payload shape, not by feature-family proximity.** The ticket body again pointed at
  `dequeueMessage` as the mirror (same #146 feature area), and again the correct twin was the
  payload-free sibling (`requestConversations`) because `interrupt` carries nothing to validate or
  forward. This is the second time in the #146 split that a bare frame's command-layer twin needed
  the same correction as its builder-layer twin — worth checking payload shape before trusting a
  ticket's named "mirror," at both the transport layer and the command layer.
- **The dispatcher's missing `assertNever` is a known, accepted gap, not a regression to fix here.**
  `src/main/index.ts`'s `onCommand` switch has no exhaustiveness check (unlike the renderer-side
  `DaemonEvent` switches), so every new `RendererCommand` member — `interrupt` included — needs its
  dispatcher arm added by hand and verified by code review rather than by the compiler. The spec calls
  this out explicitly rather than silently living with it; future command members should expect the
  same manual-verification step, not a `default: assertNever(command)` guard that doesn't exist yet.

## Lessons learned

None — the ticket built exactly to the spec's three-file clone, mirroring `requestConversations` +
`dequeueMessage` with no surprises. The spec's file-count estimate (three production files, two test
files) held exactly, and the "bare, not payload-bearing" correction was already anticipated by the
spec (carried over from the #305 lesson), not discovered mid-implementation.
