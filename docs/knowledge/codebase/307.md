# #307 — Interrupt a running turn from the conversation thread (render slice)

The render slice of the stop-a-running-turn chain, split from
[#146](https://github.com/pyrycode/pyrycode-desktop/issues/146) (interrupt-running-turn), slice 3 of
3 — and the **last** slice: [#305](305.md) (wire+builder) and [#306](306.md) (command+IPC) merged
first. Shipped as PR [#319](https://github.com/pyrycode/pyrycode-desktop/pull/319), spec commit
`52f9f61`, code commit `d13d6bc`. Size S, not security-sensitive (pure render + a guarded-send helper
over an already-reviewed command; no new transport surface). Adds the on-thread interrupt affordance
and closes out the #146 chain end-to-end: pair → thread → stop.

## Summary

Five files touched, all new or additive, none of them the transport:

- `src/renderer/src/screens/conversation/sendInterrupt.ts` (new) — the injected guarded-send effect,
  a strict simplification of `dropQueuedMessage.ts`: `sendInterrupt({ sendCommand })` calls
  `sendCommand(interruptCommand())` in a `try/catch`, `console.error`s and swallows a throw, and posts
  **no local dispatch** — AC3 forbids optimistic "stopping" state, so the only state change this
  helper causes is the outbound frame itself.
- `src/renderer/src/screens/conversation/ConversationScreen.tsx` — three additions, mirroring the
  `ThinkingIndicator` / `QueuedBacklog` + `QueuedBacklogControl` idiom already in the file:
  - `isTurnRunning(phase: TurnPhase): boolean` (exported) — `phase === 'thinking' || phase ===
    'responding'`. The one subtle piece of the ticket: **broader** than `ThinkingIndicator`'s gate
    (`phase === 'thinking'` only), because a turn is "running" in either phase.
  - `InterruptButton({ isRunning, onInterrupt })` (exported, pure) — `null` when not running (zero
    layout footprint, structural AC1); otherwise an icon-only `<button aria-label="Stop the running
    turn">` with an inline M3 `stop` glyph (filled square). Takes `isRunning: boolean`, never `phase`,
    so no daemon-supplied string can reach the view.
  - `InterruptControl()` (in-file, not exported) — the store-bound container: reads the existing
    `useTimelineStore(selectPhase)` (no new subscription), derives `isTurnRunning(phase)`, and binds
    `onInterrupt` to `sendInterrupt({ sendCommand: window.pyry.sendCommand })`. `window.pyry` is
    dereferenced only inside the click closure, never at render, so the server-rendered container
    smoke tests never touch the bridge. Mounted as `<InterruptControl />` immediately before
    `<Composer />`.
- `src/renderer/src/screens/conversation/conversation.css` — `.conversation__interrupt` (clone of
  `.conversation__thinking`, but `justify-content: flex-end` to sit over the composer's send side) and
  `.interrupt-button` (+ `:hover`/`:focus-visible`/icon rule), a verbatim clone of `.composer__send`'s
  48px round M3 icon-button ruleset — neutral colour, token names only, no bespoke "stop" colour (the
  mobile Figma has no stop/interrupt component to draw from).
- `sendInterrupt.test.ts` (new) + `ConversationScreen.test.tsx` (extended) — see Testing below.

No transport, store, or IPC change. This slice is 100% render + one guarded-send helper over the
command #306 already shipped.

## Patterns established

- **A gate predicate can be intentionally broader than a sibling indicator's, and that's worth
  extracting as its own named export rather than inlining a wider boolean expression at the call
  site.** `isTurnRunning` and `ThinkingIndicator`'s implicit `phase === 'thinking'` read the same
  `phase` scalar but answer different questions ("is a turn running" vs. "should the thinking bubble
  show"); keeping them as two named things (one exported predicate, one indicator prop) rather than
  merging or shadowing prevented a subtle under-gating bug (an interrupt control that only showed
  during `thinking` and vanished the moment the daemon moved to `responding`).
- **A control that "retracts on daemon state" needs no new client-side state if it gates on a scalar
  the store already exposes.** No `useState`, no "stopping" flag, no timers — the existing `phase`
  subscription is enough; re-render is idempotent because `InterruptButton` is a pure
  function of `isRunning`. This is the fourth slice in the #146 chain area (`dropQueuedMessage`,
  `QueuedBacklogControl`, now `InterruptControl`) to lean on "read the existing store slice, don't
  invent a new one" as the default answer to "how do we reflect this async lifecycle."
- **`window.pyry` dereferenced only inside the click closure, never at render**, keeps the container
  itself store-only and bridge-free for the smoke test — the fourth sibling (`Composer.handleSubmit`,
  `QueuedBacklogControl.onDrop`, `RepairControl`) to hold this line.

## Lessons learned

- The interrupt gate is deliberately **broader** than the thinking indicator: a turn is "running" in
  both `thinking` and `responding`, so the gate had to be its own exported `isTurnRunning` predicate
  rather than a reuse of `phase === 'thinking'`. Extracting it kept AC1 a store-free unit test instead
  of a store-mounted render assertion.
- The design source really was a dead end for this ticket — the mobile Figma file draws the composer
  only in its steady send state and has no stop/interrupt component in the design system at all
  (N/A + justification, not a lookup miss). The control was derived from `.composer__send` plus a
  generic M3 `stop` glyph, kept neutral-coloured on purpose; a bespoke stop/error visual is a deferred
  follow-up, flagged to Juhana rather than invented here.
