# #31 — Disable the composer send control while the daemon session is not connected

**Shipped:** 2026-07-07 · **Size:** S · **Scope:** renderer-only (`src/renderer/`) · 2 production files + 1 CSS modified, 2 test files · no new files, no new store slice, no transport / preload / IPC / dependency change.
**Spec:** `docs/specs/architecture/31-composer-disabled-when-disconnected.md` · **PR:** [#75](https://github.com/pyrycode/pyrycode-desktop/pull/75). Refines [#11](https://github.com/pyrycode/pyrycode-desktop/issues/11); the last surviving concern of the old mobile-#490 "guard every relay command" sweep — its *crash* half already shipped in deterministic code ([#65](65.md) main/transport no-op, [#66](66.md) AC4 renderer guard). Blocked-by / guards-on-introduction the composer send control [#66](66.md) built.

The **visible** half of the send-safety story. [#65](65.md) makes `daemonConnection.send()` an idempotent no-op with no driver and [#66](66.md)'s bridge swallows a failed send — so a send issued while not connected was *silently* dropped, the keystroke going nowhere with no feedback. This ticket reads the session's connection lifecycle at render time and reflects it in the composer: while `selectStatus` is not `connected`, the send control is disabled and a lightweight inline caption says *why*. It re-enables reactively when status flips to `connected`, no reload.

**This is a UX affordance, not a safety net.** The belt (never crash / never emit on a dead send) is [#65](65.md) + [#66](66.md)'s deterministic code; this is the suspenders the user can see. Per the ticket's Technical Notes, **no second safety guard** is added in the renderer beyond #66's existing `sendCommand` try/catch — the gate is purely a render-time read that governs the UI affordance.

## Patterns established

- **The pure-predicate gate: one status read → one source of truth for two facts.** The load-bearing decision — *can we send, and if not, why?* — is a total mapping over `ConnectionStatus`, extracted into the same React-free `composerSend.ts` as `submitMessage` (the [pure-logic / thin-container split](../features/composer-send.md), now its fourth instance alongside `pairingState.ts` and `messageViewModel.ts`). Both the boolean and the caption derive from the **single** `selectStatus` read, so there is exactly one truth and the caption can never disagree with the disable.
- **`assertNever` exhaustiveness on a sealed union.** The `default: return assertNever(status)` arm makes adding a fifth `ConnectionStatus` arm a compile error until a case is written — the union-consumer discipline the store's reducer already uses, applied to a view predicate.
- **Native `disabled` + handler early-return: two render outputs, one source of truth — not a redundant safety net.** A disabled button fires no `onClick` (platform-blocked); the `handleSubmit` early-return blocks the Enter path. Both read the same `canSend`; neither is a defensive no-op layered on the other. The *authoritative* gate is the early-return (it covers both paths); the native `disabled` is the visible affordance.
- **`role="status"` polite live region for the "why" caption.** The hint is a polite live region, so a screen reader announces the status change (AC2/AC3) without stealing focus. On connect, `hint` is `null`, the `<p>` unmounts, and the button re-enables — no announcement needed for the recovery.
- **A CSS column-stack restructure that is visually transparent when connected.** Wrapping the two existing elements in `.composer__row` and turning `.composer` into a column keeps the connected baseline pixel-identical (single child, `.composer`'s `gap` inert with one child; the row carries the former `flex`/`align-items: flex-end`/`gap`). The disabled state and hint are net-new UX with no Figma design — derived from theme tokens (M3 muted-content convention, not a raw `opacity` literal).
- **The out-of-scope boundary encoded as a test.** The `error` hint is a short generic label and deliberately does **not** embed `status.error.message` — that `ConnectionError.message` ("for the banner") is a distinct surface, explicitly out of scope. A pure test builds an `error` status with a sentinel message and asserts the hint excludes it, pinning the boundary so a future edit can't quietly leak the banner's job into the composer.
- **Re-render seam stays narrow.** `Composer` now selects `status` **and** `dispatch`; `selectStatus` returns the stable `s.status` reference and the reducer leaves `status` untouched on message actions, so message-only changes don't re-render the Composer, and the thread (which selects only `selectMessages`) doesn't re-render on status change. Narrow-slice selection (ADR 0004) preserved — the reactive re-enable-on-connect (AC3) rides the same store→UI mechanism [#69](69.md) uses for the thread.

## Lessons learned

*Lifted from PR [#75](https://github.com/pyrycode/pyrycode-desktop/pull/75)'s "Lessons learned" section.*

- **The connected/enabled composer branch is not smoke-testable in the container test.** Under `renderToStaticMarkup` (node env, no jsdom), zustand v5's `useStore` reads `getInitialState()`, never `setState`-mutated state — and the initial store state is `{ status: disconnected, messages: [] }`. So the container smoke test *always* sees the disconnected branch; forcing a connected render via `setState` won't take. The enable path is covered by the `composerAvailability(connected)` **pure** test instead — the same deferred-DOM-interaction boundary [#66](66.md)/[#69](69.md) carry forward.
- **The `error` arm's hint must not surface `ConnectionError.message`.** That message is the connection banner's distinct surface (out of scope for #31); leaking it into the composer would duplicate the banner's job. A pure test builds an `error` status with a sentinel message and asserts the hint excludes it — the boundary is pinned by a test, not just a comment.
- **The Figma node (16-61) has no designed disabled state or "why" hint.** Both are net-new UX this ticket introduces, derived from theme tokens (`--color-on-surface-variant`, the body-small type scale); the enabled composer markup #66 built is preserved verbatim — this PR only adds a `disabled` attribute, a conditional hint element, and their styles.

No React effect/cleanup or dependency-version surprises: the gate is a synchronous render-time read — no `useEffect`, no subscription, no timer, no async task, nothing to tear down.

## Deferred / carried forward

- **DOM interaction is still untested** (consistent with [#66](66.md)/[#69](69.md)). The send/no-send *decision* is fully covered by the pure `composerAvailability` test; the container's use of it — the `disabled` attr rendering, the runtime `disabled`-button click suppression, the `handleSubmit` early-return actually inerting an Enter keypress — is thin glue over that tested predicate and has no runtime-event test. Closing this needs the jsdom / Testing-Library harness #66/#69 deferred.
- **The connection banner is a separate surface, still unbuilt.** `ConnectionError.message` ("for the banner") is deliberately *not* surfaced here. A global connection banner that shows the error detail is a distinct, unfiled follow-up.
- **Per-message delivery state remains out of scope.** Marking an already-echoed message as "not delivered" needs a send ack the fire-and-forget path doesn't have (a larger transport change) — carried forward from [#66](66.md), likely landing with the reconnect/status choreography ([#34](https://github.com/pyrycode/pyrycode-desktop/issues/34)/[#35](https://github.com/pyrycode/pyrycode-desktop/issues/35)).
- **Hint copy is provisional.** `'Connecting…'` / `'Not connected'` / `'Connection error'` are short sentence-case labels; the Figma node has no designed copy for these states, so the exact words can be tuned later without design churn.
