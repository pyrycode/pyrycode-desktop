# #315 — Decode the daemon `stall` frame into a `stallDetected` event

Transport slice of the stall-signal vertical, split from #147, peer of the `turn_state` transport
(#214). Shipped as PR #320 (`76f155c`), code-review **PASS** (no MUST/SHOULD-FIX). Security-sensitive
(adds a wire type decoded from the relay socket); size S; a near-exact structural clone of #214 with
one further twist — `StallPayload` is `TurnStatePayload` scaled down to its single always-present field,
so the decoder has no enum to close over, and the emitted event is **nullary**. **No render** — the
on-thread indicator and the client-side self-clear on next turn activity are the sibling slice #317,
blocked on this one.

## Summary

The pyry daemon detects a stalled turn (claude gone quiet mid-turn, or the screen-parser degrading) and
emits an onset-only `stall` frame on the v2 interactive stream (pyrycode #638 wire vocab, #639 fan-out),
fanned out only to `interactive`-capable clients. Before this ticket the frame was unmodeled and fell
through `parseInboundMessage`'s `default → inbound-unmodeled → null`. This ticket adds the six thin,
additive touchpoints the #214 template established for a new inbound `DaemonEvent` once two exhaustive
bridges exist, this time forcing a third (`modalBridge`, added since #214 shipped):

- **Wire type** (`src/shared/wire/types.ts`) — `'stall'` joins `EnvelopeType`; `StallPayload
  { conversation_id: string }`, the frame's one always-present field, no `turn_id` (not turn-scoped), no
  clearing/recovery field.
- **Inbound decode** (`inboundMessage.ts`) — `{ kind: 'stall'; stall: StallPayload }` joins
  `InboundDaemonMessage`; `parseStallPayload` is `parseTurnStatePayload` minus the enum: an `isRecord`
  guard then a single `requireString(payload, 'conversation_id')` — no cross-field validation, no
  nullable. `case 'stall'` narrows before logging, then emits `inbound-decoded{code:'stall', bytes,
  hash}` — no decoded field logged. Returns a fresh `{ conversation_id }` literal, never a spread of the
  incoming payload — prototype-pollution-safe by construction, matching every peer decoder.
- **Consumer emit** (`daemonConnection.ts`) — one `case 'stall'` in the `switch (inbound.kind)`, a fresh
  **nullary** literal `{ type: 'stallDetected' }`; `conversation_id` is never referenced. Not
  compile-forced (this inner switch has no `assertNever` default) — the round-trip test is the guard,
  same posture #214 established.
- **`DaemonEvent` arm** (`src/shared/ipc/events.ts`) — `{ type: 'stallDetected' }`, a nullary arm since
  `StallPayload`'s one field is dropped at the emit and it has no other field to carry.
- **Three exhaustive bridge no-ops** — `daemonEventBridge.ts`, `timelineBridge.ts`, `modalBridge.ts` each
  add `case 'stallDetected': return null`. All three are compile-forced by their `assertNever` default —
  the fourth ticket (after #241, #229, #254) to force a case in all three at once.

`npm test` (1426 pass / 3 pre-existing skips), `npm run typecheck`, `npm run build` all green. 13 files
touched (7 production, 6 test), 0 new files.

## Patterns established

- **A nullary `DaemonEvent` arm is the strongest content-minimisation shape available in this
  vocabulary.** Every prior transport slice (`turnState`, `toolUse`, `toolResult`, `sessionTransition`,
  …) carries at least one decoded field across IPC, even after dropping `conversation_id`. `stall` is
  the first arm where the *entire* decoded payload is the field that gets dropped, so the emitted
  literal has nothing left to carry — zero untrusted daemon bytes cross main→renderer IPC for this
  frame, a stronger posture than #214's own `state`-carrying arm. Future onset-only/liveness-style wire
  signals with no render payload of their own should reach for this shape by default: decode
  fail-closed, drop everything at the emit, ship a bare `{ type }` literal.
- **A single-field wire payload only needs `TurnStatePayload`'s shape minus the enum.** `StallPayload`
  confirms the `parseTurnStatePayload` template generalizes cleanly down to one field with no
  cross-field or enum check — `isRecord` + one `requireString`, nothing else. A third payload
  this thin (after `SessionSettingsUpdatedPayload`, #264) should reach for the same minimal template
  rather than re-deriving it.

## Lessons learned

- The nullary-arm variant is even stronger than #214 on the security posture: because `StallPayload`'s
  only field (`conversation_id`) is dropped main-side, **zero** untrusted daemon data crosses the
  main→renderer IPC boundary — the emit is a fresh `{ type: 'stallDetected' }` literal with no argument
  to validate. (From the PR body.)
- Fresh worktrees arrive without `node_modules`; `npm install` was needed before `npm test`/`npm run
  build` would run — guard against `npx` grabbing a stray vitest from cache. (From the PR body.)

## Open questions carried forward

- **Inner-switch exhaustiveness.** `daemonConnection.ts`'s `switch (inbound.kind)` still has no
  `default: assertNever` — now four tickets deferred (#180, #199, #214, #315). The round-trip test
  remains the deterministic safety net.
- **The render consumer is a separate, still-open slice.** #317 owns both the on-thread stall indicator
  and the client-side self-clear on next turn activity (there is no "stall cleared" wire frame — the
  daemon emits onset-only). Nothing in the renderer reads `stallDetected` yet; all three bridges
  discard it as `null`.
