# #317 — Stall indicator: show on `stallDetected`, self-clear on turn activity

Render slice of the four-way split from #147, the last of the stall-signal vertical (transport #315,
merged; this ticket). Shipped as PR #322 (`aea4141`), code-review **PASS** (no MUST/SHOULD-FIX). Not
security-sensitive — pure renderer, no keys/sockets/raw bytes, and the daemon frame carries no content
to render in the first place (#315's nullary emit). Size S: five files touched, all edits, no new
files. Built with **zero deviation** from the architecture spec (`docs/specs/architecture/317-stall-indicator.md`).

## Summary

#315 decoded the daemon's one-shot `stall` liveness frame into a nullary `stallDetected` `DaemonEvent`
but shipped it dormant — all three exhaustive renderer bridges discarded it as `null`. This ticket gives
it a consumer: an on-thread stall indicator, `ThinkingIndicator`'s exact twin, that appears on onset and
self-clears client-side on the next sign of turn activity (there is no daemon "stall cleared" frame —
the daemon sends onset-only, mirroring mobile's ADR-025 Phase 2 self-clear contract).

- **`threadTimeline.ts`** — `TimelineState` gained a third scalar, `stalled: boolean`, beside `items`/
  `phase` (the `phase`-beside-`items` precedent from [ADR 0008](../decisions/0008-thread-timeline-model.md)
  extended to a second scalar, not a `ThreadItem`). A new nullary `ThreadEvent` arm, `{ type:
  'stallDetected' }`, sets it true (same-reference no-op if already true). The four turn-activity arms
  — `assistantDelta`, `toolUse`, `toolResult`, `turnState` — clear it to `false`; the three
  non-activity arms — `turnEnd`, `userText`, `sessionBoundary` — carry it through unchanged (a
  boundary/echo/rotation is not turn activity). `selectStalled` joins `selectItems`/`selectPhase`.
- **The two same-reference no-op guards widened, not branched.** `toolResult`'s orphan/duplicate
  no-op and `turnState`'s same-phase no-op each already returned `state` unchanged on their own
  condition; both widened to `&& !state.stalled` — an orphan result or an idle-when-already-idle
  `turnState` is still turn activity and must clear a live stall, but from `initialTimelineState`
  (`stalled` already `false`) both still return the exact same reference, so the pre-existing
  `.toBe(initialTimelineState)` regression assertion (`threadTimeline.test.ts:165`, pre-#317) stays
  green without modification.
- **`timelineBridge.ts`** — moved `stallDetected` out of the inverse-filter `null` group into an owned
  arm: `case 'stallDetected': return { type: 'stallDetected' }`, a fresh literal (never `return event`).
  Now six owned arms, not five. `screenSnapshotReceived` (#316) stays in the null group unchanged — the
  comment there was revised to stop describing `stallDetected` as dormant without touching the
  `screenSnapshotReceived` sentence.
- **`timelineStore.ts`** — one-line re-export widened to add `selectStalled`.
- **`ConversationScreen.tsx`** — new exported `StallIndicator({ isStalled: boolean })`, mounted as
  `<ThinkingIndicator>`'s sibling right after it. `isStalled === false` → `null` (zero layout
  footprint); `true` → a client-owned copy constant (`STALL_COPY = 'The turn seems to have stalled…'`
  — apostrophe-free, U+2026 ellipsis, the standing desktop lesson) in a `.conversation__stall` wrapper
  + `.bubble--stall` bubble. Boolean prop, not the store type — the AC4 "no daemon-supplied string is
  ever rendered" guarantee is type-level, not conventional (same posture as #215's `ThinkingIndicator`).
- **`conversation.css`** — `.conversation__stall` clones `.conversation__thinking`'s `flex: 0 0 auto`
  wrapper shape; `.bubble--stall` reuses `.bubble--daemon`'s fill/radius but diverges to the error role
  (`color: var(--color-error)` + a leading `border-left: 4px solid var(--color-error)` accent) — no new
  design token, `--color-error` is the only error-role token on desktop.

`npm test` (1446 pass, 3 pre-existing skips), `npm run build` (typecheck + electron-vite) both green.
Reducer, bridge, and render tests all extended per the spec's testing strategy — including the
idle-`turnState` case a naive guard would miss and the orphan-`toolResult` regression guard, both
called out explicitly in the test file.

## Patterns established

- **Adding a required scalar to a reducer's state is the moment to audit every same-reference
  short-circuit, not just the return-literal shape.** Every arm's object literal needed the new field,
  which is mechanical; the real risk was the two *conditions* that decide whether to skip the object
  literal entirely (`toolResult`'s orphan check, `turnState`'s same-phase check) — each needed widening
  to `&& !state.stalled` or it would silently fail to clear a live stall on an orphan/idle event. A
  scalar addition to any `TimelineState`-shaped reducer should grep for every `return state` /
  `=== state` no-op guard, not just every object-literal return.
- **A nullary `ThreadEvent` arm mirrors a nullary `DaemonEvent` arm one-for-one when the render slice
  has nothing to carry either.** `stallDetected`'s `ThreadEvent` and `DaemonEvent` shapes are
  byte-identical (`{ type: 'stallDetected' }`); the bridge case is arm-selection only, no field
  mapping — the natural conclusion of #315's "zero decoded daemon data crosses IPC" posture carried one
  layer further into the store.

## Lessons learned

From the PR body: the two same-reference no-op guards (`toolResult` orphan/duplicate, `turnState`
same-phase) had to widen with `&& !state.stalled` rather than gain a new branch — an orphan result or
an idle-when-already-idle `turnState` is still turn activity and must clear a live stall, but from
`initialTimelineState` (stalled already false) both still return the exact same reference, keeping the
existing `.toBe(initialTimelineState)` churn-discipline assertion green. Adding a required scalar to a
reducer's state is a good moment to audit every same-reference short-circuit, not just the return
literals.

## Open questions carried forward

- **Stall + concurrent thinking indicator.** Both `ThinkingIndicator` (`phase === 'thinking'`) and
  `StallIndicator` (`stalled`) can render at once if a stall onset arrives mid-`thinking`. Accepted as
  correct (adjacent flex rows, distinct facts — "working" vs. "may be stuck"); no mutual-exclusion
  coordination was built. A follow-up only if the design later wants them exclusive.
- **No dedicated Figma node.** The mobile file draws only the populated steady-state thread
  (`g2HIq2UyPhslEoHRokQmHG` node `16-8`); every transient thread-chrome overlay (#215, #277, #279,
  #305, and now this one) ships N/A-justified. A dedicated stall visual is a Figma-side follow-up for
  Juhana if wanted.
- **Exact stall copy** (`'The turn seems to have stalled…'`) was the developer's call within the
  spec's constraints (client-owned, apostrophe-free, U+2026 ellipsis, problem-state tone) — not
  verified against mobile's ADR-025 wording.
