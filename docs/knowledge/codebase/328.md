# #328 — Relay-link status transport: surface the relay-socket leg to the renderer

Transport slice 1 of 3 toward the two-dot connection-status indicator, split from [#149](149.md):
this (relay-leg transport) → [#329](https://github.com/pyrycode/pyrycode-desktop/issues/329) (renderer
relay-link store + bridge) → [#330](https://github.com/pyrycode/pyrycode-desktop/issues/330) (two-dot
render). Shipped as PR #331 (`0f6bde1`), code-review **PASS**. Security-sensitive; size S, not split —
the documented `DaemonEvent`-arm exception to the ≥5-file gate ([#241](241.md) precedent: an arm without
its producer, and a producer without the arm, are each dead on their own).

## Summary

Desktop's renderer previously saw only the **combined** daemon session status (`sessionStore`'s
`connecting`/`connected`/`error`), which conflates two hops: dialing the relay socket and completing the
end-to-end Noise handshake. This ticket ports mobile's split (`RelayLinkStatus`, mobile #391 — learned
in live testing 2026-06-08 that a combined signal shows a "false green") to desktop, but only the
**relay leg** — the daemon leg is already honest (`sessionStore.connected` fires only after
`handshake-complete`), so no daemon-leg work was needed. Ships **dormant**: a new `relayLinkChanged`
`DaemonEvent` arm exists end-to-end but nothing consumes it yet.

A four-layer producer chain, each layer dead without the next:

- **`relaySupervisor.ts`** — `RelaySupervisorEvent` gains `{ type: 'relay-closed'; code: number }`.
  `onConnEvent`'s `case 'closed'` **retryable** (`else`) branch now emits it, **after** arming the
  re-dial (`backoffTimer = setTimer(...); attempt++`) so a misbehaving sink can never strand recovery.
  The fatal branch (`emitTerminal`) is unchanged. Corrects the doc comment that said a transient close
  is "never surfaced" — it is now surfaced (but still absorbed and re-dialled).
- **`noiseRelayDriver.ts`** — `RelaySessionEvent` gains `{ type: 'relay-link-up' }` and
  `{ type: 'relay-link-down'; code: number }`. `onSupervisorEvent`'s `case 'connected'` now emits
  `relay-link-up` **before** calling the existing `onConnected()` (AC2's "in addition to" — one signal,
  two consumers); a new `case 'relay-closed'` forwards `relay-link-down{code}` verbatim, unclassified —
  the driver stays a thin forwarder, matching how `terminal{code}` is forwarded raw. No generation
  fencing needed (driven directly by a supervisor event, exactly like `terminal`).
- **`daemonConnection.ts`** — the single `RelaySessionEvent → DaemonEvent` choke point
  (`onDriverEvent`) gains two cases: `relay-link-up` → `relayLinkChanged{status:'connected'}`;
  `relay-link-down` → classify `event.code === RELAY_NO_DAEMON_CLOSE_CODE (4404)` → `'daemon-absent'`,
  else `'offline'` → `relayLinkChanged{status}`. This is the **untrusted→trusted boundary**: the raw WS
  close code (relay-controlled) is classified into the closed enum and dropped here — only the category
  crosses IPC. `RELAY_NO_DAEMON_CLOSE_CODE` is a local const (its only consumer); promote it next to
  `DEFAULT_FATAL_CLOSE_CODES` in `relaySupervisor.ts` if a second consumer ever appears.
- **`events.ts`** — new closed enum `RelayLinkStatus = 'connected' | 'offline' | 'daemon-absent'`
  (the `DebugBundleFailure` precedent) and the new arm `{ type: 'relayLinkChanged'; status:
  RelayLinkStatus }`. Content-free by construction (ADR 0007): no token, key, frame, close code, or
  payload byte — only the category.
- **Three bridges** (`daemonEventBridge`, `timelineBridge`, `modalBridge`) — one `case
  'relayLinkChanged': return null` each, joining the existing dormant-arm no-op group (the
  `stallDetected`/`screenSnapshotReceived` precedent). The `assertNever` guard in each makes this a
  compile error until all three exist, so `npm run build` gates AC4.

**Deliberately excluded:** fatal closes (`4401`/`4421`/`4426`) do **not** emit a relay-leg event — a
fatal close is a session-level rejection delivered *through* a relay that was reachable, so mapping it
to `offline` would be dishonest. They stay on the existing `terminal` → `failed` (daemon-leg) path;
after a fatal close the relay leg is left at its last value. No `Reconnecting`-countdown category either
— the supervisor exposes no remaining-backoff, so desktop cannot honestly emit one (named as future work
in `events.ts`, not built).

`npm test` (1490 pass, 3 pre-existing skips), `npm run typecheck`, `npm run build` all green. New tests
at every layer: `relaySupervisor.test.ts` (4404 retryable + ordinary retryable-drop + fatal-has-no-emit),
`noiseRelayDriver.test.ts` (connect→link-up-and-handshake-still-starts, closed→link-down), `daemonConnection.test.ts`
(up/4404/offline classification + the emitted object is exactly `{type,status}`, no `code`), and one
`toBeNull()` case per bridge test.

## Patterns established

- **Surfacing a previously-absorbed event without changing its absorption is "arm recovery first, emit
  second."** The supervisor's retryable branch already scheduled a re-dial before this ticket; adding
  the `relay-closed` emit *after* that scheduling (not before, not instead) means a hypothetical
  throwing sink can never prevent the reconnect it doesn't participate in. Apply this ordering whenever
  a signal is added alongside an existing recovery action, not replacing it.
- **A raw wire code is forwarded unclassified through every layer until the one choke point that already
  owns classification.** The driver does not interpret `event.code` — it forwards it exactly as it
  already forwards `terminal{code}`. Classification (the untrusted→trusted boundary) happens exactly
  once, at `daemonConnection.onDriverEvent`, alongside the existing `4401`/`4421`/`4426` handling. Don't
  classify at an intermediate layer even when it looks like a one-line shortcut.
- **"In addition to," not "instead of," when a new signal piggybacks an existing trigger.** `case
  'connected'` still calls `onConnected()` unchanged; the new `relay-link-up` emit is a second,
  independent consumer of the same event, ordered before the existing behaviour but not replacing it —
  confirms the `stallDetected`/#317 precedent that a dormant arm never perturbs the behaviour it rides
  alongside.

## Lessons learned

From the merged PR body: a fresh worktree had no `node_modules`; `npm install` was needed before
`vitest`/`build`. Running `npx vitest` without installing first silently resolves a global cached
`vitest` against the wrong config — always run the project's installed binary (`npm test`, not `npx
vitest` in an uninitialized worktree).

## Open questions carried forward

- **Terminal-state relay-dot presentation is #330's call.** After a fatal close the relay leg stays at
  its last value (`connected`) rather than flipping — #330 holds both legs and decides whether to
  suppress/override the relay dot when the daemon leg is `failed`. No transport change needed here.
