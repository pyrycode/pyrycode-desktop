# #33 — Pin the close-during-handshake safety invariant with regression tests (mobile #497 parity)

**Shipped:** 2026-07-07 · **Size:** XS · **Scope:** test-only (`src/main/transport/noiseSession.test.ts`) · **zero production changes** · no new files, no new production surface, no dependency change.
**Spec:** `docs/specs/architecture/33-noise-close-during-handshake-regression.md` · **PR:** [#77](https://github.com/pyrycode/pyrycode-desktop/pull/77). Mirror of mobile #497 — the **invariant**, not the fix. Pins the [Noise session](../features/noise-session.md)'s no-use-after-close guarantee ([#7](7.md)) with a named regression fixture. The rekey-recovery half of the original #33 was carved out to **#76** (staged in Inbox — its base mechanism, an in-session rekey responder, is entirely unbuilt on desktop, so it cannot be hardened yet).

The invariant pinned: **a `close()` during the handshake leaves every session entry point inert** — no entry point (`start` / `onFrame` / `sendMessage`) can re-enter freed `noise-c.wasm` cipher/handshake state after teardown. Security-sensitive because freed wasm pointers can be reused: if a future refactor ever slips an `await` into an entry point, today's synchronous safe structure would become a real use-after-free. This ticket turns that silent hazard into a red test.

## Why test-only, and why no synchronization primitive

Mobile #497 synchronized handshake-phase crypto against a socket close racing on **another thread** (Kotlin coroutines). Desktop's session is **single-threaded with synchronous wasm crypto** and has **no `await` inside any entry point**, so `close()` cannot interrupt a `WriteMessage` / `ReadMessage` / `Split` / `Encrypt` / `Decrypt` mid-flight in one event-loop turn — the threaded interleaving mobile defended is structurally impossible here. Porting mobile's mutex/lock would defend a non-race: **pure make-work forbidden by *Evidence-Based Fix Selection*.** The only async surface is the wasm load in `createNoiseSession`, before any handle exists, and a supersede-during-load is already fenced by the [driver](../features/noise-relay-driver.md)'s generation counter ([#50](50.md)).

The production guards (`noiseSession.ts:99-183`) already enforce the invariant — so the ticket adds tests, not runtime code. Expected (and actual) diff: the test file only. Green with zero production change *is* the pass.

## What shipped

It reuses the file's `collector` / `initErrors` / `handles`+`afterEach` conventions and defines **block-local** `loneInitiator` / `pair` fixtures mirroring the `describe`-scoped originals (they aren't module-level; the transport-decrypt test already inlines its own pair wiring — so local fixtures match the file idiom and keep the change purely additive).

| Case | Scenario (state → closed) | Distinguishing signal asserted |
|---|---|---|
| AC1 | `close()` **before** `start()` (idle → closed) | `start()` doesn't throw; **no frame** pushed, **no event** — absent the close, `start()` would `WriteMessage` msg 1 and push exactly one frame. Guard: `state !== 'idle' \|\| hs === null`. |
| AC2 | `close()` while **awaiting the handshake reply** (after `start()`, before msg 2) | a garbage frame doesn't throw, pushes no frame, emits no event, and `initErrors` does **not** contain `handshake-read-failed` — absent the close, `hs.ReadMessage` on that garbage would MAC-fail and emit `handshake-read-failed`. | AC3 | `close()` **after** `handshake-complete` (transport → closed) | `onFrame(garbage)` emits no `transport-decrypt-failed` (guard short-circuits before `recvCipher.DecryptWithAd`); `sendMessage` seals nothing (the paired responder's `message` count is unchanged). Guards: `state === 'closed'`, `state !== 'transport' \|\| sendCipher === null`. |
| AC4 | idempotent **double-close** | neither `close()` throws — the second returns at the `state === 'closed'` guard before `freeAll()`, and `freeAll()` itself guards each `obj?.free()` in try/catch, so a double-free is structurally impossible. ## Patterns established

- **Garbage/arbitrary frames are the complete use-after-free tripwire — a valid frame adds zero coverage.** `close()` → `freeAll()` sets `hs` / `sendCipher` / `recvCipher` to `null`, so *any* post-close entry into the crypto path (valid input or garbage) manifests identically: a null-deref throw caught by `not.toThrow()`. The scarier "reused freed pointer returns valid data" form cannot occur here because the reference is **nulled, not dangling**. A valid-msg2 / valid-transport-frame harness is strictly more setup for no extra regression power — don't build it (*Simplicity First*).
- **The distinguishing signal = the specific event the pre-close path would have emitted, and post-close must not.** Each test proves *close short-circuited* vs. *close was a no-op* by asserting the pre-close path's observable effect is **absent**: the `{ no new event / no new frame } ∧ { does not throw }` pair. Without the "specific reason absent" half, the assertions would be no-op theater (a no-op `close` also wouldn't throw).
- **Pin the invariant, not the ported fix, when the platform makes the fix moot.** Mobile parity here means carrying the *safety property* into a regression fixture, while explicitly declining the *runtime defense* (the mutex) because the single-threaded synchronous model makes its race impossible. Reuse this split whenever mirroring a mobile hardening ticket onto desktop's different concurrency model.
- **Block-local fixtures over cross-block reach.** New top-level `describe` blocks define their own `loneInitiator`/`pair` mirrors rather than hoisting the `describe`-scoped originals to module scope — additive, no churn to sibling blocks, matches the file's existing idiom.

## Lessons learned

*Lifted from PR [#77](https://github.com/pyrycode/pyrycode-desktop/pull/77)'s "Lessons learned" section.*

- **Coverage boundary — green here is NOT "concurrent close proven safe."** These tests use **close-then-call** ordering: `close()` runs to completion, then a *fresh* entry point is invoked. They **cannot** reproduce a true mid-flight interleaving (`onFrame` starts → yields at an `await` → `close()` frees → `onFrame` resumes into freed state), because the current synchronous code has **no yield point to interleave at** — you cannot force an interleaving the code's synchronicity forbids. What they pin is the **post-close short-circuit guards themselves** (`state === 'closed'` / `handle === null`): the mechanism that keeps a future async refactor from re-entering freed wasm. Regression value: drop or weaken a guard and a post-close `onFrame`/`sendMessage` would reach `null.ReadMessage` / `null.DecryptWithAd` / `null.Encrypt` and throw, failing the `not.toThrow()` assertions. This is a genuine tripwire on the guards; it is **not** a proof that a hypothetical async entry point is race-free. **The test comments say this in a `COVERAGE BOUNDARY` note** — a maintainer must not read green as race-freedom.
- **`loneInitiator`/`pair` are `describe`-scoped, not module-level.** The new top-level block defines local fixtures mirroring them rather than reaching across blocks — matching the file's existing idiom (the transport-decrypt test already inlines the pair wiring) and keeping the change purely additive.

No React / effect-cleanup / dependency-version surprises: this is a pure main-process unit-test addition with no runtime surface.

## Deferred / carried forward

- **Rekey recovery → [#76](https://github.com/pyrycode/pyrycode-desktop/issues/76)** (staged in Inbox). The other half of the original #33 / mobile #497. Its base mechanism — an in-session rekey responder — is entirely unbuilt on desktop, so there is nothing to harden yet; it lands with the rekey feature, not before.
- **True mid-flight close/resume interleaving is not (and cannot be) tested here** — see the coverage-boundary lesson. If an entry point ever gains an `await`, that refactor must add its own interleaving test; today's fixture is a guard tripwire, not an async-race proof.
- **Sink reentrancy is a distinct, unpinned invariant.** A synchronously-reentrant `sendFrame`/`onEvent` sink seeing consistent state holds today (the code sets `state` *before* invoking any sink, `noiseSession.ts:131-132`, `166-168`), but it is a separate property from close-during-handshake, has no observed failure, and pinning it would exceed this ticket's XS scope. Deferred with no owner ticket (no observed need — *Evidence-Based Fix Selection*).
- **Broader socket-lifecycle shutdown** (close racing an in-flight relay socket, not the crypto unit) belongs to the driver/supervisor ([#50](50.md)/[#22](22.md)), not this pure Noise unit.
