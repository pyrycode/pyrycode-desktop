# #330 — Two-dot Relay/Pyrycode connection-status indicator (render)

The final slice of the two-dot connection indicator, split from [#149](149.md):
[#328](328.md) (relay-leg transport) → [#329](329.md) (renderer relay-link store + bridge) → this
ticket (render). Shipped as PR #338, code-review **PASS**. Size S, not split — one production file
(`ConversationScreen.tsx`) plus its stylesheet and a theme token, the `ConnectionBanner`/#279 shape.

## Summary

[#328](328.md)/[#329](329.md) landed a content-free `RelayLinkStatus` all the way to a renderer
store (`relayLinkStore`), but nothing read it — the store was dormant. This ticket is that first
read: two labelled, colour-coded dots on the persistent conversation Status row, mirroring mobile's
`ConnectionStatusLine` (mobile #397/#398, a code-era addition authored after the Figma file locked
on 2026-05-08 — the two-dot line itself is not drawn in Figma). All new code landed in
`ConversationScreen.tsx` (the `ConnectionBanner` file, per the ticket), mirroring its established
pure-view/container/predicate trio:

- **`relayLeg(status: RelayLinkStatus | null): ConnectionLeg`** and **`daemonLeg(status:
  ConnectionStatus): ConnectionLeg`** — exported pure mapping functions (the `isTurnRunning`
  precedent), each an exhaustive `switch` with an explicit `ConnectionLeg` return type and no
  `default`, so a future union member trips TS2366 (the standing exhaustive-switch guard). `relayLeg`
  handles `null` (the store's not-yet-connected sentinel) before the switch. `daemon-absent` maps to
  `up`/"Relay Reachable" — a distinct label, since the missing daemon is the daemon leg's story, not
  a relay failure. `connecting` maps to `in-progress`/"Pyrycode Connecting" — the relay leg has no
  in-progress arm of its own; that category is exercised only by the daemon leg.
- **`ConnectionStatusIndicator({ relay, daemon })`** — exported pure view. A `role="group"
  aria-label="Connection status"` span wrapping two `.conn-leg` spans (relay leg first, then daemon),
  each a `.conn-dot--{category}` (`aria-hidden`, decorative) plus a `.conn-leg__label` text span. A
  static group, not a live region — the banner (#279) already announces disconnect transitions.
- **`ConnectionStatusIndicatorControl()`** — in-file, unexported container. Two independent narrow
  selectors — `useRelayLinkStore(selectRelayLinkStatus)` and `useSessionStore(selectStatus)` (the
  `ScreenSnapshotControl` two-store precedent) — mapped through `relayLeg`/`daemonLeg` and passed to
  the pure view. No `window.pyry`, no IPC, no effects, so the server-rendered smoke test never
  touches a bridge.
- **`StatusRow`** — the previously-empty, self-closing `<span className="status-row__summary" />`
  (reserved for #181/#182's collapsed run-config text) now holds `<ConnectionStatusIndicatorControl
  />` as a child, and the slot became a flex row (`gap: var(--space-3); min-width: 0`) so the dots
  and that future text can coexist rather than one claiming the slot exclusively.
- **`tokens.css`** — new `--color-warning: #ffca45`, after `--color-error`. M3 has no warning role
  and the design-system file has no such variable (the two-dot line post-dates the 2026-05-08 Figma
  lock); a dark-scheme warm amber in the same tone band as `--color-error`, colour-separable from
  both `--color-success` and `--color-error`.
- **`conversation.css`** — `.status-row__connection` / `.conn-leg` / `.conn-dot` /
  `.conn-dot--{up,in-progress,down}` / `.conn-leg__label`. The dot is an 8px circle — structural
  component geometry (the `.run-config__context-bar` precedent), not a spacing token. The
  category→colour contract: `up` → `--color-success`, `in-progress` → `--color-warning`, `down` →
  `--color-error`.

**Independent legs, never reconciled (AC4) — this is structural, not a convention.** After a fatal
session close (`4401`/`4421`/`4426`) the relay store's status is left at its last value (typically
`connected`, per #328's forward decision), so relay = up while daemon = down is a legitimate,
intended render. A retryable `daemon-absent` (4404) close leaves the daemon leg at `connecting`
(in-progress, never down) while the relay leg reads up/"Reachable". `relayLeg` and `daemonLeg` take
only their own leg's status as input — there is no code path by which one could reference the other.

`npm test`, `npm run typecheck`, `npm run build` all green. New tests in
`ConversationScreen.test.tsx`: the full `relayLeg`/`daemonLeg` matrix (no render, plain function
calls), the pure-view category→dot-class matrix, the AC4 independent-legs render (relay up + daemon
down coexisting), `aria-hidden` on dots + `role="group"` on the wrapper, and the existing container
smoke test updated to expect two "Offline" dots in the initial-store-state render instead of an
empty summary span.

## Patterns established

- **A dormant store's first reader is a mapping-function pair plus a pure view, not a fold into the
  store itself.** `relayLinkStore` stayed exactly as #329 shipped it (single setter, no reducer);
  all the render-time logic — classification into `{category, label}`, colour, layout — lives in the
  consuming screen. Keeps the store a thin, wire-shaped cache and the presentation logic where the
  other leg's presentation logic (`daemonLeg`) already lives, so both legs are reviewable side by
  side in one place.
- **Baking the leg name into the label, not deriving it from a prop, keeps a pure view dumb.**
  `ConnectionStatusIndicator` never sees "relay" or "daemon" as data — `relayLeg`/`daemonLeg` already
  produced the full string ("Relay Connected", "Pyrycode Offline"). The view renders exactly two
  things per leg (a category-classed dot, a label string) and cannot itself introduce a
  daemon-supplied string, the same structural guarantee `ConnectionBanner`'s `CONNECTION_BANNER_COPY`
  established for #279.
- **A slot reserved for a future ticket becomes a flex row, not a single-child span, the first time
  anything mounts into it.** `status-row__summary` was reserved for #181/#182's run-config text;
  rather than that ticket later having to restructure a single-child span, this ticket made the slot
  a flex container up front so the two-dot indicator and the eventual text are siblings from day one.
