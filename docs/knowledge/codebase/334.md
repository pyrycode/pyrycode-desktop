## Patterns established

- **A dedicated module, not an in-file container, for a store-bound row that has its own test seam.**
  The #330 precedent keeps `ConnectionStatusIndicator`/`Control` in-file inside `ConversationScreen.tsx`;
  this ticket instead gives the pure view + container their own `ServerRow.tsx`. Reasonable when the
  parent screen (`SettingsScreen`) is meant to stay a thin, server-renderable composition point and the
  row's populated/null matrix needs its own focused test file rather than sharing the parent's.
- **Mounting a previously-dormant one-shot loader is itself the acceptance criterion, not a side effect.**
  #340 shipped `ServerInfoData` with zero consumers by design (a documented "boundary ahead of consumer"
  shape); this ticket is the first to close that gap, and the spec called out explicitly that without
  the mount, the row can never populate — the row and the mount are inseparable in one slice.
- **The zustand-v5 SSR gotcha (`useStore` reads `getInitialState()`) pushes the populated/null matrix
  onto the pure view, tested with injected props — the container's populated branch is untestable under
  `renderToStaticMarkup`.** Same discipline as [#69](69.md)'s original pure-view/container split and
  #330's `ConnectionStatusIndicator` tests; this is now the third ticket to hit and document this same
  constraint, reinforcing it as the house pattern for any store-bound view tested via server-render only
  (no jsdom in this codebase's renderer test setup).

## Lessons learned

- **A fresh worktree ships without `node_modules`.** `npm install` was required before `npm
  test`/`npm run build` would run; `npx vitest` alone grabbed a mismatched cached binary and failed on
  config resolution. Worth checking for a `node_modules` directory before reaching for `npx <test-tool>`
  directly in a new worktree.

## Carried forward / deferred

- **The two-dot host slot (`settings__server-status-slot`) stays empty.** A future ticket drops #330's
  `ConnectionStatusIndicator` into it; this slice deliberately carries no `aria-label="Connection
  status"` to avoid colliding with #330's existing marker in the `thread` view (the collision hazard
  #333's developer flagged is why this constraint is explicit rather than assumed).
- **No trailing chevron.** Mobile's `17:16` navigate-to-server-detail affordance is omitted — desktop
  has no server-detail screen, so a chevron would be dead UI.
- **Remaining Settings preference rows** (#151) and the "pair another server" sub-flow (#152) are still
  unblocked follow-ups on #333, unrelated to this ticket's scope.
