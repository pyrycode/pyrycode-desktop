# #346 — Outbound `unarchive_conversation` wire command (transport)

**Shipped:** 2026-07-14 · **Size:** S (arguably XS) · **Scope:** `src/shared/wire/`,
`src/shared/ipc/`, `src/main/transport/`, `src/main/daemonConnection.ts`, `src/main/index.ts`.
**Spec:** `docs/specs/architecture/346-unarchive-conversation-transport.md` · **PR:** #357.
Split from [#153](153.md) (transport half; the screen is #347; the restore row that first calls

Ships **dormant** — fully tested, no consumer. Field-for-field clone of the `promote_conversation`
outbound verb ([#273](273.md)) across five mirror sites, with the payload reduced to a single
required `conversation_id: string`.

## Summary

The daemon shipped `archive_conversation` / `unarchive_conversation` in pyrycode/pyrycode#881: one
shared `ArchiveConversationPayload{ConversationID string}` serving both verbs, a parameterized
handler that clears the durable archived flag, persists eagerly, and confirms by **replying** to
the requesting client with a `conversation_updated` record reflecting the restored (active) state.
This slice wires only the `unarchive_conversation` half, outbound-only:

- **Wire type** (`src/shared/wire/types.ts`) — `'unarchive_conversation'` joins `EnvelopeType`
  beside `'promote_conversation'`; `UnarchiveConversationPayload{conversation_id: string}` — one
  required value-string, no pointer, no `omitempty`, mirroring the daemon's shared struct.
- **Builder** (new `src/main/transport/unarchiveConversationEnvelope.ts`) — `buildUnarchiveConversation`,
  a byte-for-byte clone of `buildPromoteConversation`, simpler still: one required string means no
  explicit-`null` preservation concern. Main-process only (imports `./codec`'s `Buffer` use), never
  re-exported through a renderer barrel.
- **Connection method** (`daemonConnection.ts`) — `unarchiveConversation(payload)`, the `send` twin:
  inert no-op when `driver === null`, builds a **fresh literal** naming only `conversation_id`
  (never a spread of `payload` — the anti-smuggling net), shares the one monotonic
  `nextEnvelopeId` counter with `send`/`promoteConversation`/`requestSnapshot`, never throws out of
  the module (parity #490) — the caught object is dropped, no log, no event.
- **Command** (`src/shared/ipc/commands.ts`) — a new `RendererCommand` member,
  `unarchiveConversation{payload: UnarchiveConversationPayload}`, guarded by
  `isUnarchiveConversationPayload` — cloned from `isRequestSnapshotPayload` (single present-and-string
  check, structural minimum — an extra smuggled field is accepted here and stripped later by the
  connection method's fresh literal). No constructor helper: #348's renderer builds the command
  literal inline, same as `promoteConversation`.
- **Dispatch** (`src/main/index.ts`) — a `case 'unarchiveConversation':` in the `onCommand` switch,
  direct to `connection.unarchiveConversation(command.payload)`, no orchestrator (a fire-and-forget
  request has no consumer/reassembler) — the exact shape of the `promoteConversation` arm.

**No inbound change.** #881 also added `is_archived` to `conversation_updated`, but the existing
decoder already tolerates unknown server keys (forward-compat), and #348 reads restored state from
the full re-list (`ConversationSummary.is_archived`, already present from [#139](139.md)) rather
than from a correlated reply — so no decode edit was needed.

**Scope guard honored.** The symmetric `archive_conversation` verb was deliberately *not* wired —
desktop has no caller for it; only #348's restore/unarchive row will call this one.

`npm test` (1590 passed, 3 pre-existing skips), `npm run typecheck`, `npm run build` all clean.

## Patterns established

- **A single-required-string outbound payload's guard clones `isRequestSnapshotPayload`, not
  `isPromoteConversationPayload`.** Both are "reject missing/null/non-string", but the one-field
  shape reads more directly off the `requestSnapshot` precedent than off promote's three-field
  present-and-string trio — worth reaching for when a future verb similarly narrows to one id.
- **Reaffirms (third instance, after #273/#236) that a security-sensitive outbound command's
  connection method must build a *fresh* literal, never spread the caller's payload** — the
  deterministic net that bounds the wire regardless of what the boundary guard's structural minimum
  let through. A test now pins this directly: sending a payload with a smuggled `is_archived` key
  asserts the serialized wire bytes never contain it.
- **A verb strictly simpler than its precedent (one field vs. three) still costs the same five
  mirror-site edit set.** No file was saved versus #273 — only the payload shape and prose shrank.
  Confirms the "≥5 files is the irreducible atomic minimum for one outbound verb" pattern first
  noted at #241/#273 holds even at the small end.

## Lessons learned

None outside the patterns above — this ticket was a near-mechanical clone of #273 and turned up no
new React/timing/dependency surprises (it is main-process/shared only, no renderer code).
