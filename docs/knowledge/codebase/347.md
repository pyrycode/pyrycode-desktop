  a required `onOpenArchive` prop threaded into the `list` case's `<ChannelList>`; the container adds
  `onOpenArchive={() => dispatch({ type: 'openArchive' })}`. Both `assertNever` defaults (route and nav)
  force these additions at `npm run typecheck`.
- **`screens/channels/ChannelList.tsx`** — `ChannelList`/`ChannelListView` gain a required
  `onOpenArchive` prop; a new in-file `ArchiveButton` (Material `archive`-box glyph, `aria-label="Archive"`)
  joins the existing `SettingsButton` inside a new `.channel-list__actions` flex-row cluster — the one
  bit of #333-adjacent structural change the task genuinely needed, since two independent sticky
  top-right children would have stacked awkwardly. Archive leads, gear trails (conventional
  gear-rightmost); `channels.css`'s old `.channel-list__settings` sticky/positioning rules moved onto the
  new `.channel-list__actions` wrapper, leaving `.channel-list__settings` with only its 48px box +

  scaffold: a container/pure-view split (`ArchiveScreen` holds `useState<ArchiveTab>('channels')`;
  `ArchiveScreenView` is the pure `({ selectedTab, onSelectTab, onBack })` renderer), an in-file
  `BackControl` cloned verbatim from `SettingsScreen`'s, client-owned `ARCHIVE_COPY` constants, and a
  two-tab `role="tablist"` segmented header whose selected-tab indicator is driven entirely by
  `aria-selected="true"` (no separate modifier class or indicator node). The tab panel

Matching test files: `pairedRoute.test.ts` (+2 cases), `PairedShell.test.tsx` (+1 route case + 1

## Patterns established

- **A chrome-only scaffold ticket is one indivisible unit — route + entry + screen — not three
  separately-mergeable pieces**, the same call #333 made. A route with no screen, or a screen with no
  route, is dead code.
- **A second top-right list entry needs a shared cluster wrapper, not a second independent sticky
  child.** `.channel-list__actions` (flex row, sticky, `align-self: flex-end`) now owns the positioning
  that `.channel-list__settings` used to own alone; the two button rules keep only their 48px
  box-and-presentation styling. This is the reusable shape for any *future* third top-right entry too —
  add it to the same cluster, don't invent a new sticky wrapper.
- **The active-tab indicator is driven off `aria-selected`, not a parallel `selected` prop or CSS
  modifier class.** `.archive__tab[aria-selected="true"]` is the single source of the underline; since
  `tab.key === selectedTab` drives the label, the click payload, *and* `aria-selected` from one map
  iteration, the visible indicator and the interaction glue cannot drift apart structurally — a pattern
  worth reusing for any future segmented/tab control in this codebase.
- **A second nav arm reusing an already-absolute `back` needs no new transition logic**, cashing the same
  bet #333 first proved: `nextPairedRoute`'s `back` arm was written `current`-independent from #140
  onward specifically so future routes like `settings` and now `archive` wouldn't need a matching new
  `back` case.

## Lessons learned

None outside the patterns above — like #346, this was a near-mechanical clone of an established
precedent (#333) and turned up no new React/timing/dependency surprises. The one genuinely novel piece
(the two-tab segmented header) had no prior in-codebase control to clone, but its design — deriving
everything from `aria-selected` — avoided introducing any new interaction-state bug class.

## Carried forward / deferred

- **Both tab bodies ship empty.** [#348](../codebase/348.md) mounts live counts (the "Channels (N)" /
  "Discussions (N)" labels) and restore rows into `.archive__tab-panel`, reading the already-shipped
  [conversation list store](../features/conversation-list-store.md) (`is_archived`, partitioned like
  `channel-list.md`'s `is_promoted` split) and calling [#346](346.md)'s now-no-longer-dormant
  `unarchiveConversation` transport.
- **No stack-aware back.** `archive → back` is the same absolute `list` landing every other route's
  `back` uses, per the existing #333-established limitation.
- **Entry glyph is a developer choice, not a Figma-pinned asset** — no Figma node pins the
  desktop-invented `ArchiveButton`/`.channel-list__actions` cluster, mirroring `SettingsButton`'s own
  precedent.
