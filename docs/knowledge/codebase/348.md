## Patterns established

- **A restore/undo round-trip needs zero new wiring when the daemon confirms via the same broadcast
  the list bridge already re-lists on.** Because `conversationListBridge`'s `refreshOnChange` already
  re-requests the full list on any `conversation_updated`, and `unarchive_conversation`'s daemon-side
  reply *is* that broadcast, restoring a row needs no new subscription, no optimistic removal, and no
  local mutation — the row's departure and both tab counts' recompute are just the next render of the
  same derived `partitionArchived` over the next `setConversations` call. This is the same free-recompute
  shape #275 proved for promote's `is_promoted` flip; #348 is the second cash-in.
- **Index a derived partition by the same union that drives the UI's own keys**, so two independently-
  looking concerns (a tab's live count, a tab's rendered body) cannot desync. `partitionArchived`'s
  return keys (`channels`/`discussions`) are exactly the `ArchiveTab` union members; the view does
  `partition[tab.key]` for both, rather than two parallel derivations that could silently disagree after
  a future edit to one but not the other.
- **A composed-string helper that could double a suffix needs an explicit non-doubling test, not just a
  happy-path one.** `archivedSubtitle`'s test suite pins the exact string (not just "contains 'Archived'")
  and asserts the absence of "ago ago" — the failure mode a naive `` `Archived ${rel} ago` `` would have
  produced, since `formatLastActivity` already appends "ago" itself.

## Lessons learned

- `.archive__title` was already taken by the #347 scaffold's topbar `<h1>` (title-large). Cloning the
  Channel List's title token set into the same stylesheet under that name would have silently collided
  with the existing topbar rule instead of failing loudly, so the row title uses a distinct
  `.archive__row-title` (title-medium) — worth checking existing class names in a stylesheet before
  cloning a token set into it, not just trusting the source component's naming.
