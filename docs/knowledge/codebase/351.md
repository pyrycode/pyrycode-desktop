## What shipped

- **`conversationListStore.ts`** (+8 lines) — a new pure selector, `selectArchivedCount`, alongside the
  existing `selectConversations`:
  ```ts
  export const selectArchivedCount = (s: ConversationListState): number | null =>
    s.conversations === null ? null : s.conversations.filter((c) => c.is_archived).length
  ```
  `null` (list not yet loaded) passes through as `null`; a loaded list — including `[]` — resolves to the
  count of `is_archived === true` rows. The primitive `number | null` return gives zustand's `Object.is`
  equality a narrow re-render seam: a list replacement that leaves the archived count unchanged does not
  re-render the row.
- **`ArchivedCountRow.tsx`** (new, 50 lines) — the `ServerRow`/`ServerRowControl` two-part shape (#334)
  verbatim:
  - `ArchivedCountRow({ archivedCount: number | null })` — pure, props-in/markup-out. Always renders the
    "Archived conversations" label; renders the em-dash placeholder (`—`, U+2014) when `archivedCount` is
    `null`, else `` `${archivedCount} archived` ``. No trailing chevron (mirrors the Server row's own
    omission — no archive screen to navigate to yet, that's #347).
  - `ArchivedCountRowControl()` — reads `useConversationListStore(selectArchivedCount)` and hands it to
    the pure view. No effects, no `window.pyry`, no IPC.
  - Copy owned as module constants (`ARCHIVED_ROW_LABEL`, `ARCHIVED_ROW_PLACEHOLDER`), the
    `SERVER_ROW_LABEL`/`EMPTY_THREAD_COPY` idiom.
  - **Pluralization is an invariant, not a branch:** "archived" is a past-participle state, not a
    countable noun — the count line is uniformly `` `${n} archived` `` for every `n` including 0 and 1,
    matching the AC's concrete examples and Figma's "11 archived". The only conditional is

## Patterns established

- **A selector added to an existing store, not a new store.** `selectArchivedCount` sits beside
  `selectConversations` in `conversationListStore.ts` — the store stays the single owner of its read
  surface, and a purely-derived value (a count over an already-held list) doesn't earn its own store. The
  same call #334's spec made for `selectConversations` itself.
  See [conversation-list store](../features/conversation-list-store.md).
- **`null`-vs-loaded-`[]` is a recurring store contract worth defending explicitly in every derived
  selector.** `conversationListStore` already documented this distinction for `selectConversations`; this
  ticket is the second selector to preserve it rather than collapsing `null` to `0` for convenience. Any
  future selector over this store's `conversations` slice should follow the same passthrough.
- **A primitive-returning selector is a deliberate re-render optimization**, not just a type convenience:
  narrowing `conversations: T[] | null` down to `number | null` before it reaches `useConversationListStore`
  means an unrelated list mutation (e.g. a title edit re-list) that leaves the archived count unchanged
  causes no re-render of this row — better than selecting the array and counting inside the component.
