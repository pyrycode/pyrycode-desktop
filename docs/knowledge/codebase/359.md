# #359 — Outbound `rename_conversation` wire command (transport)

**Shipped:** 2026-07-14 · **Size:** S · **Scope:** `src/shared/wire/`, `src/shared/ipc/`,
`src/main/transport/`, `src/main/daemonConnection.ts`, `src/main/index.ts`.
**Spec:** `docs/specs/architecture/359-rename-conversation-transport.md` · **PR:** #362.
Split from [#154](154.md) (transport half; the Rename dialog is [#360](360.md)). Security-sensitive
(architect self-review PASS, no findings).

Ships **dormant** — fully tested, no consumer. Field-for-field clone of `unarchive_conversation`
([#346](346.md)) / `promote_conversation` ([#273](273.md)) across five mirror sites, with a
**two-field** payload `{ conversation_id: string, name: string }` (both required strings — promote's
shape minus `cwd`, a deliberate non-reuse).

## Summary

The daemon shipped `rename_conversation` (client → daemon) in pyrycode/pyrycode#820: a verb carrying
a conversation id + new name, updated via a single locked `Registry.Update`, persisted eagerly, and
confirmed by **replying to the requesting client** with a `conversation_updated` record (correlated
by `in_reply_to` daemon-side — irrelevant here, since desktop doesn't correlate it). This slice wires
the outbound verb only:

- **Wire type** (`src/shared/wire/types.ts`) — `'rename_conversation'` joins `EnvelopeType` beside
  `'unarchive_conversation'`; `RenameConversationPayload{conversation_id: string, name: string}` —
  two required value-strings, no pointer, no `omitempty`, **deliberately not** a reuse of
  `PromoteConversationPayload` (which carries a third required `cwd` that rename neither has nor
  means; #820).
- **Builder** (new `src/main/transport/renameConversationEnvelope.ts`) — `buildRenameConversation`,
  a byte-for-byte clone of `buildUnarchiveConversation`: two required strings means no explicit-`null`
  preservation concern, the payload serializes verbatim. Main-process only (imports `./codec`'s
  `Buffer` use), never re-exported through a renderer barrel.
- **Connection method** (`daemonConnection.ts`) — `renameConversation(payload)`, the `send` twin:
  inert no-op when `driver === null`, builds a **fresh literal** naming only `conversation_id`/`name`
  (never a spread of `payload` — the anti-smuggling net), shares the one monotonic `nextEnvelopeId`
  counter with `send`/`promoteConversation`/`unarchiveConversation`, never throws out of the module
  (parity #490) — the caught object is dropped, no log, no event (`name` is user content and must
  never reach a log call on this path).
- **Command** (`src/shared/ipc/commands.ts`) — a new `RendererCommand` member,
  `renameConversation{payload: RenameConversationPayload}`, guarded by `isRenameConversationPayload` —
  cloned from `isPromoteConversationPayload` with the `cwd` check dropped: both fields present-and-
  string, type checked not emptiness (an empty-string `name` passes; the daemon's trim-guard and
  #360's Save-disable handle blank). Structural minimum — a smuggled extra field is accepted here and
  stripped later by the connection method's fresh literal. No constructor helper: #360's renderer
  builds the command literal inline, same as `promoteConversation`/`unarchiveConversation`.
- **Dispatch** (`src/main/index.ts`) — a `case 'renameConversation':` in the `onCommand` switch,
  direct to `connection.renameConversation(command.payload)`, no orchestrator (fire-and-forget, no
  consumer/reassembler) — the exact shape of the `unarchiveConversation` arm.

**No inbound change.** The reply is `conversation_updated`, already decoded (#273) and reacted to by
re-requesting the conversation list (#275) — the list reflection is #360's AC, not this ticket's.

**Thread has no title surface.** Renaming a conversation needs no "reflect in the thread" — the
thread chrome draws no conversation title; that reflection concern is out of scope for the whole
#154 line, not deferred.

`npm test` (1633 passed, 3 pre-existing skips), `npm run typecheck`, `npm run build` all clean.

## Patterns established

- **A two-required-field outbound payload's guard clones the closest *field-count* twin, not the
  closest *verb* twin.** Rename clones `isPromoteConversationPayload` (both required-string fields)
  and drops the third (`cwd`) check, rather than starting from `isUnarchiveConversationPayload`'s
  single-field shape and adding one — confirms the #346 note that guard cloning is driven by field
  arity, not by which verb feels most related.
- **Reaffirms (fourth instance, after #273/#236/#346) that a security-sensitive outbound command's
  connection method must build a *fresh* literal, never spread the caller's payload.** A test pins
  this directly: a smuggled extra key never reaches the serialized wire bytes.
- **A verb one field richer than its simplest precedent (#346, one field) still costs the same five
  mirror-site edit set, not six.** Confirms the "≥5 files is the irreducible atomic minimum for one
  outbound verb" pattern (#241/#273/#346) holds regardless of payload width, at least up to three
  fields (promote).

## Lessons learned

None outside the patterns above — this ticket was a near-mechanical clone of #346's plumbing plus
#273's guard shape, main-process/shared only, no renderer code, no new React/timing surprises.
