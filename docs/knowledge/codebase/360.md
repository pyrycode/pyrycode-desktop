# #360 — Rename dialog: prefilled name, dispatch, free list reflection

The UI half of #154 (transport half [#359](359.md), merged PR #362). Adds a Rename dialog
(Figma 19:14) — a token-identical twin of the Save-as-channel dialog ([#274](274.md)) whose Name
field is prefilled with the row's current title, plus a per-row pencil affordance on saved
(promoted) Channel rows that opens it. Shipped as PR #369, two new files and three modified. Not
security-sensitive — renderer-only, dispatching the already-shipped `renameConversation` command
through the existing preload bridge. Size S.

## Summary

- **New `RenameConversationDialog.tsx`** — pure `RenameConversationDialogView` (the
  `SaveAsChannelDialogView` clone: overlay/scrim/`role="dialog"` chrome, a controlled Name field,
  Save disabled while `name.trim() === ''`) + pure `requestRenameConversation(sendCommand, row,
  name)` — the `requestPromoteConversation` twin **minus `cwd`**: `sendCommand({ type:
  'renameConversation', payload: { conversation_id: row.id, name: name.trim() } })`.
- **`ChannelList.tsx` container** — a second, fully independent `useState` pair (`renameRow: 
  ConversationSummary | null`, `renameName: string`), not shared with the save-as pair. No
  mutual-exclusion logic needed: an open dialog's `position: fixed; inset: 0` overlay covers the
  row affordance behind it, so the two dialogs can never both be open. `onRename` seeds
  `renameName` from `titleFor(row.name)` in the same handler that sets `renameRow` — the save-as
  seed idiom repeated verbatim.
- **`ChannelList.tsx` `Row` / `renderBody`** — `Row` gained a second optional sibling affordance,
  `onRename?: () => void`, rendered as `.channel-list__rename` (24px Material pencil glyph,
  `aria-label="Rename"`) alongside the existing `.channel-list__save`. The two affordances are
  disjoint by section: `renderBody` passes `onSaveAsChannel` only to `discussions.map(...)` (Recent
  rows) and `onRename` only to `channels.map(...)` (saved Channel rows) — symmetric counterparts,
  so no row ever carries two trailing buttons.
- **`channels.css`** — `.channel-list__rename` (+`:hover`/`:focus-visible`/`-icon`) cloned from
  `.channel-list__save`; the full `.rename-conversation*` dialog chrome cloned from
  `.save-as-channel*` (overlay, scrim, panel, title, field, actions) — token-for-token, per the
  code review's explicit verification that every rule uses a theme variable.
- **Tests** — new `RenameConversationDialog.test.tsx` (accessible-modal chrome, prefill,
  Cancel/Save presence, blank/whitespace-disable + non-blank-enable, escaped-markup inertness
  (`Tom & Jerry` → `Tom &amp; Jerry`), single-dispatch with the right payload, an explicit
  `not.toHaveProperty('cwd')` guard, and the edge-whitespace trim); `ChannelList.test.tsx` gains a
  `RENAME_MARKER` present-on-Channel / absent-on-discussion pair (the save-as marker pair's mirror,
  sections swapped) plus `onRename={noop}` on the shared `render` helper's props.

`npm test` (1645 pass, 3 pre-existing skips), `npm run typecheck`, `npm run build` all clean. Code
review: **PASS**, no blocking findings; visual fidelity against the Figma 19:14 screenshot
confirmed a token-identical twin of the save-as dialog.

## Patterns established

- **A second per-row trailing affordance on the same `Row` component gets its own fully
  independent `useState` pair in the container, not a shared "which dialog is open" union.** With
  only two mutually-exclusive dialogs and a full-screen `position: fixed` overlay guaranteeing they
  can never overlap, a second `useState<Row | null>` + `useState<string>` pair is simpler than
  introducing a discriminated "open dialog" state — confirms the #274 flex-wrapper-of-siblings
  shape scales to N affordances by literally repeating the pattern, not by generalizing it
  prematurely.
- **A command whose payload is a subset of a sibling command's payload (rename ⊂ promote, minus
  `cwd`) gets its dispatch helper written as an inline literal that drops the field, with an
  explicit negative test (`not.toHaveProperty('cwd')`) guarding against a copy-paste carry-over.**
  The clone-and-trim approach (copy `requestPromoteConversation`, delete the `cwd` line) is exactly
  where a stray field is most likely to survive a review pass by inspection alone; the negative
  assertion is what actually catches it in CI.

## Lessons learned

From the merged PR's own "Lessons learned" section:

- **A fresh worktree ships without `node_modules`.** `npm install` was needed before `npm
  test`/`npm run build` would run. Not a code issue — a pipeline/worktree provisioning note for
  future tickets landing in a freshly-created worktree.
