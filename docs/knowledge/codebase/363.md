## Summary

Desktop shipped the restore (unarchive) path first, without its archive counterpart — so there was
no outbound `archive_conversation` verb even though the daemon has spoken it since pyrycode#881
(merged, same shared Go `ArchiveConversationPayload{ConversationID string}` struct that already
backs `unarchive_conversation`). This slice fills that gap, outbound-only:

- **Wire type** (`src/shared/wire/types.ts`) — `'archive_conversation'` joins `EnvelopeType` beside
  `'unarchive_conversation'`; a new, **distinct** `ArchiveConversationPayload{conversation_id: string}`
  — deliberately not an alias of `UnarchiveConversationPayload`, so each verb keeps its own
  five-site wire surface and the two can evolve independently if the daemon ever forks them.
- **Builder** (new `src/main/transport/archiveConversationEnvelope.ts`) — `buildArchiveConversation`,
  a byte-for-byte clone of `buildUnarchiveConversation`: one required string, no explicit-`null`
  concern, main-process only (imports `./codec`'s `Buffer` use), never re-exported through a
  renderer barrel.
- **Connection method** (`daemonConnection.ts`) — `archiveConversation(payload)`, the `send` twin:
  inert no-op when `driver === null`, builds a **fresh literal** naming only `conversation_id`
  (never a spread of `payload` — the anti-smuggling net), shares the one monotonic
  `nextEnvelopeId` counter with `send`/`unarchiveConversation`/`promoteConversation`, never throws
  out of the module (parity #490) — the caught object is dropped, no log, no event.
- **Command** (`src/shared/ipc/commands.ts`) — a new `RendererCommand` member,
  `archiveConversation{payload: ArchiveConversationPayload}`, guarded by
  `isArchiveConversationPayload` — cloned from `isUnarchiveConversationPayload` (single
  present-and-string check, structural minimum — a smuggled extra field is accepted here and
  stripped later by the connection method's fresh literal). No constructor helper: #366's renderer
  will build the command literal inline, same as `unarchiveConversation`.
- **Dispatch** (`src/main/index.ts`) — a `case 'archiveConversation':` in the `onCommand` switch,
  direct to `connection.archiveConversation(command.payload)`, no orchestrator (a fire-and-forget
  request has no consumer/reassembler) — the exact shape of the `unarchiveConversation` arm.

**No inbound change.** The daemon confirms by setting the durable archived flag, persisting
eagerly, and replying with the same `conversation_updated` record `unarchive_conversation` uses;
the existing decoder ([#273](273.md)) already tolerates unknown server keys, and the archived row
leaving the active list comes free downstream from the existing re-list ([#275](275.md)), owned by
#366's AC — not this ticket.

`npm test` (1650 passed, 3 pre-existing skips), `npm run typecheck`, `npm run build` all clean.

## Patterns established

- **A verb's mirror-image twin (archive vs. unarchive) costs the same five mirror-site edit set as
  the original, even though only the flag direction and the doc prose actually differ.** Confirms
  the "≥5 files is the irreducible atomic minimum for one outbound verb" pattern (first noted at
  #241/#273, reaffirmed at #346) holds for a same-shape twin too, not just a smaller payload.
- **A structurally-identical payload sharing the daemon's one Go struct still gets its own distinct
  TypeScript type on desktop, never an alias.** `ArchiveConversationPayload` and
  `UnarchiveConversationPayload` are field-for-field identical but kept separate so each verb's
  command member / builder / method / guard stays independently evolvable — worth reaching for
  whenever a future verb pair shares one daemon struct.
- **Reaffirms (fourth instance, after #273/#236/#346) that a security-sensitive outbound command's
  connection method must build a fresh literal, never spread the caller's payload.**
