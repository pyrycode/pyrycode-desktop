# #364 — Outbound `delete_conversation` wire command (transport)

**Shipped:** 2026-07-14 · **Size:** S · **Scope:** `src/shared/wire/`, `src/shared/ipc/`,
`src/main/transport/`, `src/main/daemonConnection.ts`, `src/main/index.ts`.
**Spec:** `docs/specs/architecture/364-delete-conversation-transport.md` · **PR:** #371.
Split from [#155](155.md) (transport half; the sheet shell is #365; the Delete action + confirm
that first calls this is #367). Security-sensitive (architect self-review PASS, no findings). Code
review PASS after one rework round (below).

Ships **dormant** — fully tested, no consumer. Field-for-field clone of the archive/unarchive
outbound slice ([#363](363.md) / [#346](346.md)) across the same five mirror sites, narrowed to the
same single required `conversation_id`, differing only in the envelope `type` string and — unlike
either sibling — in the reply contract.

## Summary

The daemon added a **permanent hard-delete** verb, `delete_conversation`, in pyrycode#822 (merged,
PR #884). Desktop had no outbound delete verb. This slice wires it, outbound-only:

- **Wire type** (`src/shared/wire/types.ts`) — `'delete_conversation'` joins `EnvelopeType` beside
  `'archive_conversation'`/`'unarchive_conversation'`; a new, **distinct**
  `DeleteConversationPayload{conversation_id: string}` — not an alias of either sibling payload, so
  the verb owns its own five-site wire surface.
- **Builder** (new `src/main/transport/deleteConversationEnvelope.ts`) — `buildDeleteConversation`,
  a byte-for-byte clone of `buildUnarchiveConversation`: one required string, no explicit-`null`
  concern, main-process only, never re-exported through a renderer barrel.
- **Connection method** (`daemonConnection.ts`) — `deleteConversation(payload)`, the `send` twin:
  inert no-op when `driver === null`, builds a **fresh literal** naming only `conversation_id`
  (never a spread of `payload`), shares the one monotonic `nextEnvelopeId` counter with
  `send`/`archiveConversation`/`unarchiveConversation`, never throws out of the module (parity
  #490) — the caught object is dropped, no log, no event.
- **Command** (`src/shared/ipc/commands.ts`) — a new `RendererCommand` member,
  `deleteConversation{payload: DeleteConversationPayload}`, guarded by
  `isDeleteConversationPayload` — an exact clone of `isUnarchiveConversationPayload` (single
  present-and-string check, structural minimum). No constructor helper: #367's renderer will build
  the command literal inline.
- **Dispatch** (`src/main/index.ts`) — a `case 'deleteConversation':` in the `onCommand` switch,
  direct to `connection.deleteConversation(command.payload)`, no orchestrator — the exact shape of
  the `unarchiveConversation` arm.

**The one deliberate divergence from the clone: the reply contract, not the plumbing.** Archive and
unarchive both confirm via the existing `conversation_updated` broadcast, which the [conversation
list store](../features/conversation-list-store.md) already re-lists on for free. Delete does not:
the daemon replies with a **distinct, new** record `conversation_deleted { id }` (no
name/cwd/last_used survives a deleted row), correlated to the requester by `in_reply_to`, with **no
broadcast**. So delete gets **no free re-list reflection** — the requester's row leaves the list
only on an explicit re-list #367 must trigger itself. No inbound decode of `conversation_deleted`
is added here; that, and the explicit re-list, are #367's job. See [conversation
delete](../features/conversation-delete.md) for the full contract and data-flow diagram.

`npm test`, `npm run typecheck`, `npm run build` all clean.

## Patterns established

- **A third instance of a same-shape outbound-verb clone (after archive↔unarchive) still costs the
  full five-mirror-site edit set even when the payload is byte-identical to two existing
  siblings.** Reaffirms "≥5 files is the irreducible atomic minimum for one outbound verb"
  (#241/#273, reaffirmed #346, #363) a third time.
- **A verb can clone a sibling's plumbing exactly while diverging on the reply contract, and the
  spec explicitly calls out "do NOT copy the reply doc-comment verbatim" as the one deliberate
  break from the clone.** Worth flagging in future clone-shaped tickets: when the daemon-side
  contract differs even slightly (broadcast vs. correlated-only, `conversation_updated` vs. a
  distinct new record), the doc-comments must be rewritten to match, not copy-pasted — a
  copy-pasted comment here would have told a future reader to expect a free re-list reflection
  that does not exist for this verb.
- **Reaffirms (fifth instance) that a security-sensitive outbound command's connection method must
  build a fresh literal, never spread the caller's payload** — pinned again by a
  connection-method test asserting the serialized wire bytes never carry a smuggled extra field.
- **The destructive-action gate for a permanent verb is the caller's user-facing confirmation, not
  a second factor at the transport layer.** The architect's self-review makes this explicit:
  `isDeleteConversationPayload` is identical to the non-destructive siblings' guards on purpose —
  the transport layer has no deterministic gate to add and no caller yet; the #226 second-confirm
  pattern belongs to #367.

## Lessons learned

- **The initial PR shipped with only the builder test (`deleteConversationEnvelope.test.ts`) and
  was missing coverage for the two other new decision points: the `isRendererCommand`/
  `isDeleteConversationPayload` boundary guard and the `deleteConversation` connection method.**
  Code review flagged both as MUST FIX — a spec or PR claim that "the four additive edits are
  covered by `npm run typecheck` and the existing command-boundary tests" is not the same as those
  edits having their **own** dedicated test blocks, and for a security-sensitive guard + a
  fresh-literal anti-smuggling net, structural typecheck coverage alone is not sufficient evidence.
  Fixed test-only in a follow-up commit (c8d879f): a `commands.test.ts` accept/reject block
  (valid id; empty string passes the type-not-emptiness guard; missing/null payload and
  missing/null/non-string `conversation_id` all rejected) and a `daemonConnection.test.ts`
  connection-method block (no-throw disconnected; one envelope with the right id/ts/field when
  connected; shared envelope-id counter; `sendMessage`-throw swallowed; the fresh-literal
  anti-smuggling assertion the Security review PASS actually rests on) — both cloned from the
  #346/#363 sibling test files. **For a future same-shape clone ticket:** when the spec's testing
  strategy says a new guard/method is "covered by the existing command-boundary tests" or by
  typecheck alone, verify a same-shape sibling test file actually has a dedicated block for the
  new case before treating that AC as satisfied — don't rely on structural coverage claims for a
  security-sensitive boundary or a fresh-literal net.
