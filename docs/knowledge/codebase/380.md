# #380 — `recent_workspaces` transport: request + decode

PR #388 (merged 6b8aff8). Size S, security-sensitive (PASS, no MUST FIX). Split from #157. Blocks #382 (renderer store + Workspace Picker UI).

## What shipped

The transport half of the daemon's new `recent_workspaces` read verb (pyrycode/pyrycode #888): a pure bare-request builder plus a fail-closed decode of the inbound `recent_workspaces_list` reply into a typed, sealed `recentWorkspacesReceived` `DaemonEvent`, wired end-to-end through the emit path. No renderer store, no UI — both land in #382.

This is a near-exact clone of the #139 (`list_conversations` → `conversations`) vertical, transposed to a two-string row type `{ path, last_used_at }`. Code review found no deviations from the #139 pattern.

### Wire contract
- Request `recent_workspaces`: bare, `payload: {}` (never `null`/omission — same "never emit null on the wire" posture as `list_conversations`).
- Reply `recent_workspaces_list`: `{ workspaces: Array<{ path: string, last_used_at: string }> }`, correlated by `in_reply_to`. `workspaces` is always present (`[]` when empty, never absent/null).
- Field is `path`, **not** `cwd` — do not confuse with `ConversationSummary.cwd`. `last_used_at` is an opaque RFC3339 string, decoded but deliberately left **unparsed** (relative-time formatting is #382's job).

### Files touched (10 production, all additive — see "Scope" below)
- NEW `src/main/transport/recentWorkspacesEnvelope.ts` — `buildRecentWorkspaces({id, ts})`, line-for-line clone of `buildListConversations`.
- `src/shared/wire/types.ts` — new `EnvelopeType` members `'recent_workspaces'` / `'recent_workspaces_list'`; new `RecentWorkspace` row type and `RecentWorkspacesPayload` reply type beside `ConversationSummary`/`ConversationsPayload`.
- `src/main/transport/inboundMessage.ts` — new `InboundDaemonMessage` arm `{ kind: 'recent-workspaces', recentWorkspaces }`; `parseRecentWorkspace`/`parseRecentWorkspacesPayload` narrowers (reuse the existing `requireString` — no new helper, unlike #139's `requireStringOrNull`); new `case 'recent_workspaces_list':` with a content-free log (`{event, code, bytes, hash}` — **no `count`**, matching the `conversations` posture, since a workspace count is more identifying than a message-batch size).
- `src/shared/ipc/events.ts` — new `DaemonEvent` arm `{ type: 'recentWorkspacesReceived', recentWorkspaces: readonly RecentWorkspace[] }`, reusing the wire row type verbatim (snake_case, no remap).
- `src/main/daemonConnection.ts` — `requestRecentWorkspaces()` interface + impl (the `requestConversations` send-twin, inert when `driver === null`, shares the single monotonic `nextEnvelopeId`, never throws — parity #490); new `case 'recent-workspaces':` in the inbound-emit switch (this inner switch has **no `assertNever`**, so the case is not compile-forced — the `daemonConnection.test.ts` round-trip test is what guards it); exported alongside `requestConversations`.
- `src/renderer/src/store/daemonEventBridge.ts` / `modalBridge.ts` / `timelineBridge.ts` — the three forced `default: assertNever(event)` bridges each got a one-line `case 'recentWorkspacesReceived': return null` (mechanical no-op; real consumer is #382). The other seven `*Bridge.ts` files use `default: return null` and silently absorbed the new arm untouched.
- `src/shared/ipc/commands.ts` / `src/main/index.ts` — bare `requestRecentWorkspaces` `RendererCommand` arm + `isRendererCommand` `return true` case + `onCommand` dispatch. Ships **dormant** — nothing sends it until #382 wires the trigger. It lives on this sec ticket (not #382) because it adds an arm to the untrusted renderer→main IPC boundary — the #139→#208 precedent.

## Patterns established / reaffirmed

- **The TS-exhaustive-union-atomicity exception now has a second precedent.** #380 shipped at 10 production files (above the architect's own §4 ≥5-file split-gate), justified by the same reasoning #139 used at 8 files: a `DaemonEvent` arm and its `assertNever`-guarded bridge consumers must compile together, so splitting "decode half / bridge half" across tickets would leave one half non-compiling — worse than one honest S ticket. The gate count grew from 8→10 purely because two more `assertNever` bridges (`modalBridge`, `timelineBridge`) now exist than did at #139's time, not because the vertical itself grew.
- **Outbound command plumbing for a not-yet-built consumer belongs on the security-sensitive transport ticket, not the future renderer ticket.** Confirms the #139→#208 split precedent: any new `RendererCommand` arm touches the untrusted renderer→main boundary regardless of which ticket triggers it, so it ships (dormant) alongside the decode/emit work.
- **Reuse `requireString` before adding a new narrower.** `RecentWorkspace`'s two fields (`path`, `last_used_at`) are both plain required strings — no nullable/boolean/enum — so no new decode helper was needed, unlike #139's `requireStringOrNull` for `ConversationSummary.name`.
- **Category-only decode error messages for path-shaped untrusted fields.** `parseRecentWorkspace` never interpolates `path` into an error message (it can echo `$HOME`/username/project name) — same posture as `ConversationSummary.cwd`.

## Security

Label-gated review, verdict PASS. `path` is decoded as opaque display text only — never passed to `fs.*`/`path.resolve`/any filesystem API, never logged (the content-free log emits exactly `{event, code, bytes, hash}`, no `count`, no `path`). `last_used_at` stays an unparsed string — no date parser is fed untrusted input. The new bare `requestRecentWorkspaces` RendererCommand carries no payload, so `isRendererCommand`'s `return true` is complete acceptance (no smuggling surface). Carry-forward constraint for #382 (the render consumer): `path` must render as plain text, never `innerHTML`/`dangerouslySetInnerHTML`, and must never be resolved into a local filesystem operation (it's a *remote* daemon-side path).
