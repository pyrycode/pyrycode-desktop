# #382 — Recent-workspaces renderer store + bridge

PR #390 (merged 2d8f88c). Size S, not security-sensitive, code-review **PASS** (no findings). Split
from #157. Blocked by #380 (transport, shipped PR#388); unblocks the not-yet-built Workspace Picker
UI (#157's remaining split-child).

## What shipped

The renderer half of the recent-workspaces slice: a dedicated Zustand store holding the wire
`RecentWorkspace` rows verbatim (`null` = not-yet-loaded, distinct from a delivered `[]`), and a
headless bridge that subscribes to the `recentWorkspacesReceived` daemon event and fires a
de-duplicated one-shot `requestRecentWorkspaces` command. Two new production files plus their tests
(~404 LOC), no other file touched:

- NEW `src/renderer/src/store/recentWorkspacesStore.ts` — near-exact clone of
  `conversationListStore.ts`, minus the `selectArchivedCount` derived selector (no analog).
- NEW `src/renderer/src/store/recentWorkspacesBridge.ts` — a **hybrid**: the subscription half
  clones `conversationListBridge.ts` (translate filter, one-listener subscribe, off-handle cleanup)
  with the `refreshOnChange` machinery dropped (no broadcast counterpart for this slice); the
  on-demand one-shot half clones `serverInfoLoader.ts`'s "mounted on demand, not app-level" lifecycle
  shape, using `ConversationListData`'s `useRef` dedup mechanism rather than `serverInfoLoader`'s
  `active` promise-cancellation flag (nothing awaited here — the command is fire-and-forget).

Ships **dormant** — `RecentWorkspacesData` has no consumer in this ticket; the Workspace Picker
wires the mount point on its own ticket. Consumes the event + command #380 already shipped; adds no
wire/command/event/type plumbing.

See [recent-workspaces store](../features/recent-workspaces-store.md) for the full design and data
flow.

## Patterns established

- **A bridge can be a hybrid of two established shapes rather than a pure clone of one.** The
  subscription lifecycle (`conversationListBridge`) and the request lifecycle (`serverInfoLoader`)
  are independent concerns; this ticket combined them cleanly by taking each half's precedent
  verbatim rather than inventing a third shape. The dedup mechanism, however, was chosen per-shape
  from a third source (`ConversationListData`'s `useRef`, not `serverInfoLoader`'s `active` flag) —
  the deciding question was "is there an awaited invoke to cancel?", not "which file did the rest of
  this hybrid come from?".
- **A slice can drop `refreshOnChange` outright, not just leave it unused.** `conversationListStore`'s
  refresh-trigger machinery exists because `conversation_updated`/`conversation_deleted` broadcasts
  need to re-request the list mid-connection. Recent-workspaces has no such broadcast, so
  `subscribeRecentWorkspaces` was written with a strictly smaller signature (two params, not three)
  rather than accepting and ignoring a third — confirms the project's function-signature-mirrors-need
  discipline over blind structural cloning.

## Security

Not security-sensitive — pure renderer state fed by an already-typed event, no keys/sockets/raw
bytes. The untrusted-boundary work (decode, outbound command) already shipped on #380. Code review
confirmed `path` is never rendered to HTML and never resolved to a filesystem path at this layer (no
DOM sink exists yet — that constraint carries forward to the picker ticket).
