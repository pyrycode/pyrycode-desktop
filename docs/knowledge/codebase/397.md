# #397 — Create-workspace-folder round-trip store

PR [#401](https://github.com/pyrycode/pyrycode-desktop/pull/401) (merged). Size S, not security-sensitive
(pure renderer state, no IPC/transport/keys/sockets/bytes), no UI (headless store + bridge). Split-child B
of [#384](384.md) (Create-folder dialog), blocked-by [#396](396.md) (merged), blocks
[#398](https://github.com/pyrycode/pyrycode-desktop/issues/398) (dialog UI, Figma 19-44). Spec:
`docs/specs/architecture/397-create-folder-round-trip-store.md`.

Ships **dormant** — purely additive, zero edits to any existing file. Nothing mounts the bridge or
dispatches a request until #398 wires the dialog.

## Summary

`create_workspace_folder`'s two typed daemon replies — success `workspaceFolderCreated{path}` (#381) and
the bare rejection `workspaceFolderRejected` (#396, merged) — reached the renderer with no consumer: every
exhaustive bridge (session / modal / timeline) no-ops them. This slice adds that consumer: a dedicated
renderer store holding the round-trip status as a discriminated union nested under a `roundTrip` field
(`idle` / `in-flight` / `created{path}` / `rejected`), plus a dedicated inbound-only bridge
(`newFolderBridge.ts`) that folds the two daemon events into it.

Two new files, both under `src/renderer/src/store/`:

- **`newFolderStore.ts`** — `NewFolderRoundTrip` union, `NewFolderEvent` sealed event set, `reduceNewFolder`
  pure reducer (`assertNever`-guarded default), `createNewFolderStore` DI factory, `newFolderStore`
  singleton, `useNewFolderStore` hook, `selectNewFolderRoundTrip` sole read surface.
- **`newFolderBridge.ts`** — `translateNewFolderEvent` (switch → `NewFolderEvent | null`, `default: null`
  permanent filter), `subscribeNewFolder` (forwards translated events **unconditionally** — the store, not
  the bridge, gates), `NewFolderData` headless leaf (dormant, no consumer in this ticket).

**Reducer transitions** (four arms, two gated):

| Event | Precondition | Result |
|---|---|---|
| `createRequested` | any status | → `in-flight`, ungated (dialog-driven; a rejected→in-flight retry works) |
| `folderCreated` | `in-flight` | → `created{path}` |
| `folderCreated` | any other | unchanged — same state reference (gate, AC3) |
| `folderRejected` | `in-flight` | → `rejected` |
| `folderRejected` | any other | unchanged — same state reference (gate, AC3) |
| `reset` | any status | → `idle`, ungated (dialog-driven, AC4) |

The in-flight gate lives in the reducer, not the bridge, per the architecture spec's explicit direction.
Because `workspaceFolderRejected` is bare (no correlation key, #396), this gate is the **sole** guard
against a stale or unsolicited reply flipping state — the renderer-side companion to #396's main-side
`pendingCreateFolders` correlation.

`npm test` (29 new cases across `newFolderStore.test.ts` / `newFolderBridge.test.ts`: reducer transitions,
the gate's same-object-reference no-ops, a real-store integration seam proving the gate end-to-end, the
bridge's translate/subscribe/unconditional-forward/off-handle cases, a server-render sanity check for
`NewFolderData`), `npm run build` (typecheck + electron-vite) clean. 124 test files, 1840 passed, 3
pre-existing skips.

## Patterns established

- **Nest the union under a field; never intersect it flat onto the store.** `roundTrip: NewFolderRoundTrip`
  is a store field, not `State & NewFolderRoundTrip`. This is load-bearing, not stylistic: only `created`
  carries `path`, and zustand's `set` shallow-merges a partial patch onto existing state by default — a flat
  shape would leave a stale `path` key sitting on the object after a `created → idle` transition, since a
  shallow merge only overwrites keys present in the patch, never deletes absent ones. Nesting under one
  field means every transition replaces that field's value wholesale, so no stale key can survive. The
  `modalStore`/`serverInfoStore` precedent this ticket's spec pointed at.
- **A single value, not a `Map`, is the right shape when there is no correlation key.**
  `runSettingsWriteStore` (the closest structural analog) keys a `Map<changeId, …>` because several config
  writes can be outstanding at once. A create-folder round-trip has none of that — only one dialog is ever
  open — so the simplification from `Map` to one discriminated-union value is correct, not a missing
  feature.
- **The gate lives in the reducer; the bridge forwards unconditionally.** `subscribeNewFolder` dispatches
  every translated event with no precondition check at all — `newFolderBridge.test.ts` has an explicit case
  asserting this (`dispatch` still called with a spy that has no store to gate against). All conditional
  logic is testable in one place, the pure reducer, without needing a live store or a mounted bridge to
  exercise it.

## Lessons learned

- Nesting the union under `roundTrip` (vs. intersecting it flat onto the store) is load-bearing: only
  `created` carries `path`, so a flat shape under zustand's shallow-merge `set` would leak a stale `path`
  across a `created → idle` reset. Swapping the whole union object wholesale is what guarantees no key
  survives a transition. (From the PR body's Lessons learned section — this is the one non-obvious surprise
  worth flagging for future store-shape decisions: zustand's default merge behavior is a silent trap for any
  union-valued store field.)

## Security

Not security-sensitive per the ticket's own framing, and nothing in the implementation contradicts that:
pure renderer state, no IPC channel, no transport, no keys/sockets/raw bytes. The one adversarial input this
slice touches — a stale or unsolicited `workspaceFolderCreated`/`workspaceFolderRejected` — is handled
deterministically by the in-flight gate (reducer returns the same state, event dropped, no re-render). The
security-sensitive correlation of the untrusted rejection frame (forged/duplicate `in_reply_to`) already
shipped main-side in #396; this store's gate is a renderer-side defense-in-depth companion, not a
replacement for it.
