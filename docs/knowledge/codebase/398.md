## Summary

Two production files changed, one new:

- **NEW `src/renderer/src/screens/conversation/CreateFolderDialog.tsx`** — a near-clone of
  `RenameConversationDialog.tsx`, retitled "Create workspace" with the field labelled "What should this
  workspace be called?" and Cancel/Create actions. Three exports:
  - `CreateFolderDialogView` — pure, props-in/markup-out, SSR-testable. Takes the round-trip status
    (`NewFolderRoundTrip`, #397) as an **injected** prop rather than reading the store itself (the
    RepairPrompt/ConnectionBanner discipline), so all four union states are server-renderable. Create is
    `disabled={blank || busy}` (AC2 blank-name, AC3 in-flight); the input is `disabled={busy}` (AC3). A
    `rejected` status renders a single generic, apostrophe-free failure line
    (`CREATE_FOLDER_ERROR_COPY = 'Could not create that folder'`) — no daemon error text, since
    `workspaceFolderRejected` is bare (#396).
  - `requestCreateWorkspaceFolder` — the dispatch helper (the `requestChangeWorkspace`/
    `requestRenameConversation` twin): `sendCommand({ type: 'createWorkspaceFolder', payload: { parent,
    name: name.trim() } })`.
  - `CreateFolderDialog` — the in-file interaction container (the ChannelInfoSheet-mounts-
    RenameConversationDialogView idiom). Owns the controlled `name` `useState`, reads the round-trip
    store, mounts the **dormant** #397 bridge (`NewFolderData`) dialog-scoped so the daemon reply actually
    resolves, and owns two effects: the created-outcome switch (reads `roundTrip.path` **verbatim**, never
    a client-reconstructed `parent + '/' + name` — the #288 EvalSymlinks lesson — then calls `onCreated`)
    and an unmount-cleanup that unconditionally dispatches `reset` (→ idle), the single mechanism covering
    every close path (Cancel, created, abandon-mid-flight).
- **MODIFY `src/renderer/src/screens/conversation/WorkspacePickerSheet.tsx`** — the "Create new folder…"
  placeholder label becomes parent-specific (`WORKSPACE_PICKER_CREATE_PREFIX + activeCwd`, e.g. "Create new
  folder under ~/alpha") whenever `activeCwd !== null`; falls back to the generic label with no active
  conversation. `onCreateFolder` is supplied only for a non-null conversation (the `onChoose` gating
  precedent) and just opens the dialog — `const [createFolderOpen, setCreateFolderOpen] = useState(false)`.
  The dialog mounts picker-scoped as a sibling; `onDismiss` closes the dialog alone (AC2, picker stays
  open), `onCreated` is the picker's own `onClose` — closing the picker unmounts the whole tree, so "both
  the dialog and the picker close" (AC4) is one call. `ConversationScreen.tsx` is untouched.
- **`conversation.css`** — `.create-folder*` block cloned from `.rename-conversation*`, plus a
  `.create-folder__error` line using `--color-error`/`--text-body-medium-*` (the `.bubble--stall`
  error-text precedent). Token-only, no new CSS token.

`npm test` (125 files, 1853 passed / 3 pre-existing skips; new `CreateFolderDialog.test.tsx` + two added
`WorkspacePickerSheet.test.tsx` cases), `npm run build` (typecheck + electron-vite) both clean. Written
test-first (RED → GREEN).

## Patterns established

- **Injected round-trip state, not a store read, on the pure view.** `CreateFolderDialogView` takes
  `roundTrip: NewFolderRoundTrip` as a prop; the container is the only place calling
  `useNewFolderStore(selectNewFolderRoundTrip)`. This is the same split #397's own spec pointed at
  (RepairPrompt/ConnectionBanner) and keeps all four union states (`idle`/`in-flight`/`created`/`rejected`)
  directly server-renderable in tests with no store mock.
- **Reset-on-unmount as the single mechanism for every close path.** Rather than resetting the store
  separately on Cancel, on the created outcome, and on abandon-mid-flight, one `useEffect(() => () =>
  dispatch({type:'reset'}), [])` cleanup covers all three — because every close path unmounts the
  container. Avoids duplicating the same dispatch at three call sites.
- **Read the returned path verbatim; never reconstruct it client-side.** The created effect uses
  `roundTrip.path` (the daemon's own value) to call `requestChangeWorkspace`, not
  `` `${parent}/${name}` `` or a `~/`-templated guess — carrying forward the #288 lesson that a
  client-built path fails the daemon's `EvalSymlinks` check because it doesn't exist yet from the
  daemon's point of view until the create round-trip completes.
- **Reuse an existing dispatch helper across sibling files rather than duplicating or hoisting it.**
  `CreateFolderDialog` imports `requestChangeWorkspace` straight from `WorkspacePickerSheet.tsx` instead of
  copying it — see Lessons learned below for the import-cycle consequence and why it's safe as written.

## Lessons learned

- **The dialog↔picker reuse of `requestChangeWorkspace` creates a benign module import cycle** —
  `CreateFolderDialog.tsx` imports it from `WorkspacePickerSheet.tsx`, which imports `CreateFolderDialog`
  back to mount it. It typechecks and builds clean because both references are lazy: the function is
  called from inside a `useEffect`, and the component is referenced only in JSX, so neither is touched
  during module evaluation — ES-module live bindings resolve fine by the time either runs. Flagged in code
  review as a NIT, not a fix: worth knowing before a future maintainer "cleans this up" by hoisting either
  reference to module-eval scope, which would turn it into a genuine TDZ trap. (From the PR body's Lessons
  learned section.)
- **A spec-added UI element (not cloned from an existing dialog) is exactly where an a11y gap slips in.**
  Code review flagged (SHOULD FIX, non-blocking) that the rejected-state error `<p>` has no `role="alert"` /
  `aria-live`, so a screen-reader user isn't notified when creation fails while focus stays on the
  re-enabled Create button (WCAG 2.1 AA 4.1.3). Every other element in this dialog is a clone of
  `RenameConversationDialog`'s already-reviewed chrome; the error line is the one genuinely new piece of UI
  the ticket added, and it's the one that missed the accessibility bar. Worth checking live-region
  semantics specifically on any newly-authored (not cloned) status/error UI going forward — this fix was
  left unapplied (non-blocking, PASS) and is a candidate for a follow-up ticket if it recurs elsewhere.

## Security

Not security-sensitive per the ticket's own framing, confirmed by code review: renderer UI only, no
keys/sockets/raw bytes. `createWorkspaceFolder`'s payload (`{ parent, name }`) matches
`CreateWorkspaceFolderPayload` and passes `isCreateWorkspaceFolderPayload` at the main boundary — no wire
drift. Both fields are renderer strings the daemon polices server-side (#381/#887); the blank-name disable
in the view is the only client-side gate — no separator/`..`/absolute-path check was added, by design (a UX
mirror, not a security boundary).
