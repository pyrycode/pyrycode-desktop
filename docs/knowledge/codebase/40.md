# #40 — E2E test harness that launches and drives the built Electron app

**Shipped:** 2026-07-04 · **Size:** S · **Scope:** test infrastructure only (top-level `e2e/` + `playwright.config.ts`) · no `src/` change, no runtime code · adds one dev-dependency (`@playwright/test`).
**Spec:** `docs/specs/architecture/40-e2e-electron-harness.md` · **PR:** [#61](https://github.com/pyrycode/pyrycode-desktop/pull/61) · review: **PASS**.

The end-to-end harness those later UI scenarios (pairing, send, stream) will hang off. Playwright's `_electron` API launches the **built** app from `out/main/index.js`, a reusable launch/teardown fixture exposes the main window/`page` to test bodies, and one smoke assertion proves the app shell ([ConversationScreen](../features/conversation-shell.md)) mounts in the real launched window. **Scaffolding only** — the actual UI scenarios are follow-ups. See the [e2e harness feature doc](../features/e2e-harness.md) for the fixture contract, the built-renderer launch path, and how scenarios import the primitive.

Cross-project prior art: pyrycode `#68` shipped the same spawn+cleanup harness-primitive + one-smoke shape (Go), with scenarios as separate tickets; this mirrors it in TypeScript/Playwright.

## What shipped

| File | New/mod | Role |
|---|---|---|
| `playwright.config.ts` | new (root) | `testDir: './e2e'`, `workers: 1` + `fullyParallel: false` (one Electron process at a time), `reporter: 'list'`, CI-gated `forbidOnly`/`retries`. No `projects`/`browserName` — Electron launches its own binary, so no `npx playwright install`. |
| `e2e/fixtures/electronApp.ts` | new | The reusable, scenario-agnostic launch/teardown primitive. `test.extend` adds `electronApp` (`ElectronApplication`) + `page` (`Page`) fixtures; re-exports `expect`. ~44 LOC. |
| `e2e/smoke.spec.ts` | new | The single smoke test: `expect(page.locator('.conversation')).toBeVisible()`. ~11 LOC. |
| `package.json` | mod | +`"e2e": "npm run build && playwright test"` script; +`@playwright/test` dev-dependency. |
| `vitest.config.ts` | mod | +`include: ['src/**/*.{test,spec}.{ts,tsx}']` — scopes the unit run to `src/`. |
| `.gitignore` | mod | +`test-results/`, +`playwright-report/` (Playwright's default output dirs). |

`npm test`: `src/` unit suites pass, smoke test not collected. `npm run e2e`: build (typecheck + electron-vite) clean, then 1 smoke test passes against the launched app in ~3s, no unit tests collected. `npm run typecheck` / `npm run build`: clean (scoped to `src/`; does not cover `e2e/`).

## Patterns established

- **The launch fixture is the reusable primitive; scenarios import it, not `_electron` directly.** Follow-up e2e specs do `import { test, expect } from './fixtures/electronApp'` and take `page` as a fixture arg. Keep the fixture scenario-agnostic — per-scenario setup belongs in the spec, not the fixture. This is the same "one small spawn+cleanup primitive, scenarios as separate tickets" shape as pyrycode `#68`.
- **Teardown rides the runner's fixture lifecycle, never a manual `afterEach`.** The code after `use()` in the `electronApp` fixture (`app.close()`) fires on **pass and fail** alike, so a failing test cannot orphan an Electron process. With `workers: 1` apps launch serially and each is torn down before the next launches. Playwright owns the process handle — no `AbortController`.
- **Launch the built app by `args: ['.']`, not a hard-coded path.** `.` resolves through `package.json` `main` → `out/main/index.js`, so the harness follows the real entrypoint with no path math and no drift if `main` moves.
- **`npm run e2e` chains the build.** `npm run build && playwright test` — e2e never runs against a stale `out/`. A silently-stale build is a worse failure than a slower run.
- **Two-way separation from vitest is structural, both directions.** Playwright only scans `e2e/` (`testDir`); vitest only scans `src/` (`include` glob, which **replaces** — not extends — the default). Neither runner can pick up the other's files. This is the AC4 guarantee encoded in config, not convention.
- **The DOM anchor is the shell's existing class, `.conversation`.** The smoke asserts on the [ConversationScreen](../features/conversation-shell.md) root that `App.tsx` already mounts — no test-only markup added to `src/`. Playwright's locator auto-waits, absorbing React's async mount after `DOMContentLoaded`.

## Lessons learned

*Lifted from the PR body's "Lessons learned" section.*

- **`_electron.launch` uses the project's own `electron` binary — so no `npx playwright install`.** The bundled-Chromium download that a normal Playwright browser project needs is dead weight here; skipping it keeps the dev-dependency install light. There is deliberately no `projects`/`use.browserName` block in the config.
- **Playwright creates `test-results/` even on a passing run.** Both `test-results/` and `playwright-report/` were added to `.gitignore` so harness runs don't leak artifacts into commits.

Harness-specific gotcha worth carrying forward (surfaced in the spec, load-bearing in the fixture):

- **Strip `ELECTRON_RENDERER_URL` from the child env or the smoke test hangs.** Under `electron.launch` the app is not packaged, so `createWindow`'s built-vs-dev choice hangs purely on that env var (`src/main/index.ts:54`). If it leaks from a dev shell, the window `loadURL`s a non-running dev server instead of `loadFile`-ing the built renderer, and `firstWindow()`/the locator time out. The fixture launches with `{ ...process.env }` minus `ELECTRON_RENDERER_URL` — one line that prevents a confusing intermittent failure. This is the one non-obvious coupling between the harness and app code.

No React re-render / effect-cleanup / dependency-version surprises — no `src/` runtime code changed; the deliverable is test-side only.

## Deferred (carried forward)

- **UI scenarios.** Pairing / send / stream flows driven through `page` are the follow-ups this primitive exists to carry; each is its own ticket that reuses `e2e/fixtures/electronApp.ts`.
- **E2E type coverage.** `e2e/` and `playwright.config.ts` are transpiled by Playwright but not type-checked by `npm run typecheck` (scoped to `src/`). Add an `e2e/tsconfig.json` folded into `typecheck` only if type errors there start biting — do not widen the tsconfig now.
- **CI / headless Linux.** No CI today; Electron e2e on headless Linux will need `xvfb-run`. macOS runs headful with no extra setup. The `forbidOnly`/`retries` knobs are CI-gated and inert until then.
- **`e2e:fast` variant.** A build-skipping run is deferred until re-building on every `npm run e2e` becomes real iteration pain (evidence-based — no observed pain yet).
