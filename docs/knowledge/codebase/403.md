# #403 — Default workspace for new conversations: persist and apply on create

PR [#407](https://github.com/pyrycode/pyrycode-desktop/pull/407) (open, pending merge). Size S, not
security-sensitive (a user-chosen workspace path is not a secret/credential/token, never touches the
Noise handshake / relay socket / frame routing). No UI — this is the **data half** of the Figma
"Default workspace" setting (17:56); the Settings row that lets the user *change* the default is
[#404](https://github.com/pyrycode/pyrycode-desktop/issues/404) (blocked-by this ticket). Split from
[#352](352.md). Spec: `docs/specs/architecture/403-default-workspace-persist-apply.md`.

## Summary

Introduces a client-owned "default workspace" preference, persisted locally, and wires the
new-discussion FAB to honour it. Three production files (1 new, 2 modified):

- **NEW `src/renderer/src/store/defaultWorkspaceStore.ts`** — a dedicated Zustand store (the
  `serverInfoStore` DI-factory → singleton → hook → selector idiom) holding `string | null`, hydrated
  once at construction from an injected `WorkspacePrefStorage` port and set-through via
  `setDefaultWorkspace` (persist-then-record). `localStorageWorkspacePref()` is the real backend, key
  `pyry.defaultWorkspace` — the first `localStorage` key in the app — guarded by `typeof window ===
  'undefined'` for `node`/SSR import safety. No new IPC command/event, no preload wiring, no
  `isRendererCommand` guard: renderer-local `localStorage` was chosen over a main-process preference
  file specifically to stay within S. See [Default-workspace store](../features/default-workspace-store.md)
  for the full design.
- **MODIFY `src/renderer/src/store/conversationCreatedBridge.ts`** — `requestNewConversation` widens
  from one parameter to two: `requestNewConversation(sendCommand, defaultCwd: string | null)`. The
  dispatched payload's `cwd` becomes `defaultCwd` (was the hardcoded literal `null`). `defaultCwd` is
  **required**, not defaulted — the one caller must state its intent explicitly. No wire/command change:
  `create_conversation` already carries `cwd` as nullable-and-present.
- **MODIFY `src/renderer/src/screens/channels/ChannelList.tsx`** — reads
  `useDefaultWorkspaceStore(selectDefaultWorkspace)` reactively (mirroring the existing
  `useConversationListStore(selectConversations)` read) and passes it into the FAB's
  `requestNewConversation(window.pyry.sendCommand, defaultWorkspace)` call.

`npm test` covers: persist-then-restore round-trip (two stores over the same injected fake, the second
hydrates what the first wrote — proves survival across a simulated restart with no DOM), fresh-install
`null` start, `setDefaultWorkspace` recording + persisting (including the `null`-clears-to-daemon-default
case), DI isolation between independent fake instances, and `requestNewConversation`'s two dispatch
shapes (`cwd: null` unchanged-behavior case, `cwd: '<path>'` verbatim-passthrough case).

## Patterns established

- **A non-secret, renderer-only preference belongs in `localStorage` behind an injected port, not a
  main-process preference file.** The mechanism decision itself is the reusable precedent: a value only
  needs to cross the transport boundary (main-process persistence, IPC, preload wiring) when it's
  secret or when main-process code needs to read it directly. A workspace path is neither — renderer-
  local `localStorage` keeps the whole change renderer-contained and is the size-preserving choice. The
  existing `pairedServerStore.ts`/`secureStore.ts` precedent (main-process, encrypt-at-rest) is for a
  genuine secret and is deliberately heavier than a non-secret preference needs.
- **`localStorage` access must sit behind an injected port, never called directly from store code**,
  because the vitest runtime is `node` (no jsdom, no `window`, no `localStorage`). The
  `WorkspacePrefStorage` interface — `read()`/`write(value)` — is the seam; the real
  `localStorageWorkspacePref()` implementation is wired only at the singleton composition root, and
  tests inject an in-memory fake. This is what makes the persist-then-restore round-trip testable
  without a DOM harness, and is the template for any future renderer-local persisted preference.
- **Widen a dispatch helper's parameter list rather than reaching into a store from inside it.**
  `requestNewConversation` stays React-free and store-free — it takes `defaultCwd` as a plain parameter,
  and the caller (`ChannelList`, which already reads stores) is responsible for sourcing the value. Keeps
  the helper trivially testable with a plain spy, no store to mock.
- **A required (not defaulted) new parameter forces every caller to state intent.** `defaultCwd: string
  | null` has no default value even though `null` reproduces prior behavior — this keeps the widen
  honest (a caller that doesn't think about the default can't silently inherit `null` by omission) and
  matches the ticket's explicit direction.

## Security

Not security-sensitive per the ticket's own framing, confirmed by code review: a user-chosen workspace
path is not a secret/credential/token, and this ticket adds no new IPC surface, no boundary guard, no
transport code. `cwd` is renderer-supplied text the daemon resolves server-side (`create_conversation`'s
existing contract, unchanged) — the desktop never filesystem-resolves the stored value, neither reading
it back from `localStorage` nor dispatching it.
