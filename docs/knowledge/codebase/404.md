## Summary

Adds the "Default workspace" row of a new "Defaults for new conversations" section (Figma 17:37 header),
inserted between the existing Connection and Storage sections in `SettingsScreen`. One new file, two
modified:

- **NEW `src/renderer/src/screens/settings/DefaultWorkspaceRow.tsx`** — three symbols:
  - `DefaultWorkspaceRowView` (exported, pure, server-renderable — the tested seam) — a native
    `<button type="button" className="settings__default-workspace-row">` with a two-line text column
    (label "Default workspace" over the current value, or the client-owned `'scratch'` placeholder
    constant when `defaultWorkspace === null`) and a trailing `aria-hidden` chevron SVG. No `aria-label`
    — its text content is its accessible name (AC4), the `PairAnotherServerRow` (#152) posture, since
    this is the *interactive* variant of the row idiom (a `<button>` opening a picker), not the static
    `ServerRow`/`ArchivedCountRow` variant.
  - `DefaultWorkspaceRowControl` (exported, store-bound container) — reads
    `useDefaultWorkspaceStore(selectDefaultWorkspace)` and owns the picker's open-state via
    `useState(false)` (transient UI state, ADR 0006). Renders the view alone at rest; mounts
    `DefaultWorkspacePickerSheet` only while open.
  - `DefaultWorkspacePickerSheet` (in-file, not exported — untested glue, the #383 `WorkspacePickerSheet`
    container analog minus its conversation coupling) — mounts only while open, so "fresh fetch per open"
    falls out of mount/unmount: a fresh `RecentWorkspacesData` (#382) per open fires one
    `requestRecentWorkspaces`, and the Escape-to-close `useEffect` (the #383 lines verbatim) attaches on
    mount / detaches on cleanup with no `open` flag. Renders `WorkspacePickerSheetView` (#383's pure view)
    with `activeCwd` = the current default (so the matching row carries the picker's built-in "default"
    pill) and `onChoose = (path) => { defaultWorkspaceStore.getState().setDefaultWorkspace(path); onClose() }`
    — the sole write path, dereferencing the store setter inside the callback, never at render. No
    `onCreateFolder` is supplied (out of scope — #398's `CreateFolderDialog` is conversation-scoped), so
    the picker's "Other → Create new folder" entry renders disabled.
- **MODIFY `src/renderer/src/screens/settings/SettingsScreen.tsx`** — adds `defaults: 'Defaults for new
  conversations'` to `SETTINGS_COPY` and inserts a new `<section className="settings__section">` between
  the Connection section's closing tag and the Storage section's opening tag, mounting
  `<DefaultWorkspaceRowControl />` alone in its body (no loader to mount — the row reads the store
  directly, and the picker mounts its own `RecentWorkspacesData` while open).
- **MODIFY `src/renderer/src/screens/settings/settings.css`** — five dedicated, token-only rules cloning
  `.settings__pair-another-row`'s button-reset/hover/focus shell fused with `.settings__server-row-text`'s
  two-line column: `.settings__default-workspace-row/-text/-label/-value/-chevron`. No new token.

`npm test` (new `DefaultWorkspaceRow.test.tsx` covering the null→placeholder / path→verbatim / button /
decorative-chevron matrix on the pure view; four new `SettingsScreen.test.tsx` cases for the section
heading, the mounted row in its placeholder branch, the picker closed-by-default, and section placement),
`npm run typecheck`, `npm run build` — all clean per the commit.

## Patterns established

- **The interactive-row idiom (`PairAnotherServerRow`) is the template for any future Settings row that
  opens a picker/dialog, not the static `ServerRow`/`ArchivedCountRow` idiom.** A native `<button>` with
  no `aria-label`, a trailing `aria-hidden` chevron, and the label text alone carrying the accessible
  name — this is the second row to follow that shape after #152, confirming it as the standing pattern
  for "row + chevron + opens something" rather than a one-off.
- **A picker/dialog container that only exists while open is written as an in-file, non-exported
  component mounted behind `{open && <X/>}`, not a flat inline fragment.** Making it its own component
  (rather than spreading the `RecentWorkspacesData` mount + `useEffect` + view call directly inside the
  `{open && …}` block) is what makes "fresh fetch/listener per open" fall out of React's own mount/unmount
  lifecycle for free — each open is a new instance with a new `useRef`/effect run, no manual re-fetch
  wiring needed. Mirrors #383's own `WorkspacePickerSheet` container shape.
- **Reusing a pure view across two different write destinations.** `WorkspacePickerSheetView` (#383) is
  now consumed by two distinct containers with different `onChoose` semantics — #383's own container
  dispatches a daemon `change_workspace` command against a live conversation; this ticket's
  `DefaultWorkspacePickerSheet` writes a renderer-local store and sends nothing over the wire. The pure
  view stayed generic enough (`onChoose?: (path: string) => void`) to serve both without modification —
  confirms the #383 view/container split was cut at the right seam.

## Security

Not security-sensitive per the ticket's own framing: renderer-only, no new wire types, no new IPC/daemon
command (the sole daemon traffic in the flow is the pre-existing `requestRecentWorkspaces` fetch on picker
open, #380/#382). `defaultWorkspace` and each picker `row.path` are rendered whole and opaque as
auto-escaped React children — never split, basenamed, or filesystem-resolved, the `WorkspacePickerSheet`
`row.path` posture carried through unchanged.
