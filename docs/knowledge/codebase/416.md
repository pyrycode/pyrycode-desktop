# #416 — Reconnect-capable fake harness + genuine-reconnect modal-reconcile e2e

PR #419 (`de0c5aac`, spec `06f47dc`). Split-child B of #196 (2-way split; sibling #415 — shipped — owns
the renderer reconcile this ticket proves end-to-end). Size S, as estimated, not split. Security-sensitive
(fake Noise responder handshake + relay-socket splice); architect self-review PASS, code review PASS, no
findings. Not UI-visible — pure test infrastructure, zero production LOC.

## Summary

#415 taught the renderer to clear the outstanding modal slice on every supervisor (re)handshake and let
the daemon's connect-time re-sends repopulate it, but that reconcile was only proven at the
bridge/reducer level — nothing exercised a *genuine* reconnect (a mid-session relay drop, a real
supervisor re-dial, a fresh Noise responder handshake). The in-process fake harness
([fake relay forwarder](../features/fake-relay-forwarder.md), [fake daemon](../features/fake-daemon.md))
had zero reconnect capability: the forwarder terminated any client re-dial instead of re-splicing, and
the fake daemon routed a reconnect's fresh `noise_init` into `handleTransport`, where it MAC-failed. This
ticket builds that reconnect path — modal-agnostically — then adds the e2e on top.

**Forwarder (`fakeRelayForwarder.ts`, AC1)** — two additive, content-blind capabilities:
- A `close` handler on each leg socket nulls that leg's slot, **identity-guarded**
  (`clientLeg === socket`) so a late close of an already-superseded old socket can't clobber a freshly
  re-spliced new leg. A subsequent `/v1/client` dial re-fills the slot and re-splices to the still-
  connected server leg.
- `dropClientLeg(): void` on the returned handle — `clientLeg.terminate()`, forcing an abnormal 1006
  close that a supervised client treats as retryable (auto-reconnect). No-op when no client leg is
  connected; the server leg is never touched by a client-leg drop.

**Fake daemon (`fakeDaemon.ts`, AC2/AC3)** — `onMessage` now captures the whole decoded `InnerFrameV2`
(not just `.data`) so its `.type` is visible for routing: in `transport` state, a `noise_init` routes to
a new `handleReconnect` instead of `handleTransport`. `handleReconnect` composes `handleMsg1`'s
hello-recovery/validation + real `hello_ack` (the reconnect is a full IK handshake carrying `hello` —
matching the real driver's fresh `createNoiseSession` per reconnect, **not** an empty-early-data rekey)
with `handleRekeyInit`'s atomic cipher swap (install both new ciphers, free both old, nothing fallible
between). A malformed/wrong-suite reconnect msg1 fails closed to `handshake-read-failed` with both old
ciphers still installed. Two new pieces round it out: `pushFrame(plaintext)` seals a plaintext under the
*current* send cipher and streams it (the `initiateRekey` seal-and-stream pattern minus the state
transition — the server-initiated push AC3 needs to raise a modal mid-session), and
`reconnectResendFrames?: Uint8Array[]` (new `FakeDaemonOptions` field, default `[]`) streams a fixed,
ordered list of envelopes under the *new* send cipher immediately after the reconnect `hello_ack` —
generalizing `rekeyResumeMessage` to N frames. Streaming after `hello_ack` is what guarantees the client
processes `connected` (→ reset) before any re-sent frame repopulates. The module header was narrowed per
the architect's SHOULD-FIX: "the inner `type` is NOT branched on" → "consulted for **routing only**";
transport-frame interpretation still rests solely on the Noise state machine + AEAD, and a hostile
`noise_init` fails closed rather than misrouting or downgrading.

**The e2e (AC4/AC5) split across a project boundary the spec didn't anticipate.** The spec's literal
instruction — wire the real `subscribeModal`/`reduceModal` into `daemonConnection.roundtrip.test.ts` — is
infeasible: the composite `tsconfig.node.json` walls `src/main` off from `src/renderer` (verified: a
`src/main` test importing any renderer file fails typecheck with TS6307 + TS2307, independent of the
`@shared` alias gap — see
[src/main cannot import src/renderer](../src-main-cannot-import-src-renderer-composite-boundary.md)). The
spec pre-authorized this call ("the architect decides the exact seam ... extend the round-trip test vs. a
new spec"), so AC4 split along that boundary instead:
- **`daemonConnection.roundtrip.test.ts`** proves the genuine reconnect at the **`DaemonEvent` sink** —
  extends `standUpRoundTrip` to return the `forwarder` handle and thread `reconnectResendFrames`, then
  two new `describe` cases: variant 1 (a still-held modal, re-pushed after the reconnect, surfaces
  exactly once with the same `modalId`, matching `expectedModalShown`, and the reconnect ack equals the
  initial ack) and variant 2 (a resolved-while-away modal, not re-pushed, produces no post-reconnect
  `modalShown`). Both pin `connected`-before-`modalShown` ordering via `kinds.lastIndexOf(...)` and assert
  no `failed` event.
- **`modalBridge.test.ts`** proves the **renderer-store** half — the exact ordered `connected`/
  `modalShown` sequence a genuine reconnect emits, folded through the **real** `subscribeModal` (not a
  reimplementation) into `ModalState.outstanding` via `selectOutstanding`, for both variants.

The two files are joined only by the fact that the single in-order daemon-event channel delivers the same
sequence to both layers in production — the DaemonEvent-sink assertion is a stand-in for "what the IPC
channel delivers to the renderer, in order," and the renderer-store assertion is what actually happens to
that sequence once it lands.

`fakeDaemon.test.ts` also gained a primitive-level reconnect self-test: complete the initial handshake,
`daemon.pushFrame` a canned envelope (proving the push path), `forwarder.dropClientLeg()`, then drive a
**fresh** `createNoiseSession` on a re-dialled `/v1/client` leg to prove the reconnect handshake completes
with the same `hello_ack` and a post-reconnect round-trip succeeds under the new keys — reusing
`driveClient`'s built-in transient re-dial (no timing hack: if the reconnect dial lands before the dropped
leg's `close` nulls the slot, it retries until the re-splice succeeds). Log-free assertion
(`vi.spyOn(console)`) across the reconnect path.

5 files, +448/−13. `npm test` (1942 pass / 3 pre-existing skips), `npm run typecheck`, `npm run build` —
all clean.

## Patterns established

- **A reconnect harness capability stays modal-agnostic by construction, not by discipline alone.**
  `dropClientLeg`, the close-null, `handleReconnect`, `pushFrame`, and `reconnectResendFrames` carry zero
  modal references — only `Uint8Array` envelopes in and out. Only the consuming e2e crafts a modal frame.
  This is what lets a future queue-reconnect e2e (the store-level twin already built in #197, which
  scoped its own e2e out — see #197's codebase notes) reuse `standUpRoundTrip` + `dropClientLeg` +
  `reconnectResendFrames` unchanged, swapping only the crafted frame and the asserted store.
- **A reconnect is the initial-handshake shape plus the rekey path's atomic-swap discipline — not a
  third, novel handshake.** `handleReconnect` is a direct composition of two already-cited precedents
  (`handleMsg1`'s hello/hello_ack, `handleRekeyInit`'s atomic cipher swap), reusing the same responder
  static across the reconnect (correct IK behavior — the static is the long-term identity; only the
  ephemerals, and therefore the derived ciphers, are fresh per handshake).
- **When a spec's literal seam crosses a compile-enforced project boundary, split the assertion along
  that boundary rather than routing around it.** The spec anticipated the possibility ("the architect
  decides the exact seam ... extend vs. a new spec") without predicting the specific wall
  (`tsconfig.node.json`'s composite-project isolation). The fix wasn't a workaround (e.g., duplicating
  reducer logic in a `src/main` test) — it was proving each half at the layer that can actually import
  the code under test, joined by the shared invariant (one in-order channel) rather than shared code.

## Lessons learned

From the PR body's Lessons-learned section:

> - `tsconfig.node.json` / `tsconfig.web.json` are **composite** projects with disjoint `include`s: a
>   `src/main` file (test or otherwise) importing **any** `src/renderer` file fails typecheck (TS6307),
>   independent of the `@shared`/`@renderer` alias gap. Cross-layer "wire the real renderer code into a
>   main test" seams must live on the renderer side.
> - The fake daemon's `handleReconnect` is `handleMsg1`'s hello-recovery + `handleRekeyInit`'s atomic
>   swap — but unlike a rekey it carries the client `hello` early-data and a real `hello_ack` (the
>   reconnect is the *initial* handshake shape, not empty-early-data), because the real driver builds a
>   fresh `createNoiseSession` per reconnect.
> - `driveClient`'s built-in transient re-dial makes the self-test reconnect race-free without any timing
>   hack: if the reconnect dial lands before the dropped leg's `close` nulls the slot, it's retried until
>   the re-splice succeeds.
