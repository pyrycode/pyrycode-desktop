# #420 — E2E fixture: extract the real-daemon spawn recipe from `real-claude.spec.ts`

**Shipped:** 2026-07-15 · **Size:** S · **Security-sensitive:** no (test infrastructure only, zero production LOC) · **Scope:** one new file, `e2e/fixtures/realDaemon.ts`; `e2e/real-claude.spec.ts` shrinks to imports + streaming selectors + the `test(...)` body; `playwright.config.ts` + `playwright.real-claude.config.ts` widen their `real-*` partition.
**Spec:** `docs/specs/architecture/420-real-daemon-spawn-fixture.md` · **PR:** [#438](https://github.com/pyrycode/pyrycode-desktop/pull/438), code review PASS, two non-blocking NITs. Split from #421; unblocked by #433 (the `e2e/fixtures/` convention). Foundation for the coming tier-2/tier-3 real-* specs (real-daemon-actions, real-claude interrupt/queue, permission modal).

## Summary

`e2e/real-claude.spec.ts` (#252) was the only real-stack e2e — the whole spawn recipe (binary resolution, skip-gating, `seedRegistry`, spawn args, `waitForDaemonReady`, process-group reap) lived inline. This ticket is a pure code move of that recipe into `e2e/fixtures/realDaemon.ts`, the real-daemon sibling of #433's `launchPairedApp.ts`, so the coming tier-2/tier-3 real-* specs reuse it instead of re-transcribing the harness. No behaviour change; the unchanged spec staying green (skipping cleanly on a machine without `pyry`/`claude`/credentials) is the whole proof.

## What shipped

- **`e2e/fixtures/realDaemon.ts`** — the entire `relay → daemon → page` `base.extend<RealDaemonFixtures>` chain (renamed from `RealClaudeFixtures`, now shared beyond one spec) plus every transitive helper it calls: `resolveOnPath`, `resolvePyryBin`, `runPyryPair`, `isRecord`, `decodePairFields`, `seedRegistry`, `dialUnixSocket`, `delay`, `waitForDaemonReady`, `killGroup`, `reapDaemon`, and the constants `BOOTSTRAP_UUID`, `BOUND_CONVERSATION_ID`, `DAEMON_READY_TIMEOUT_MS`, `PAIR_TIMEOUT_MS`. Moved character-identical (verified block-by-block in code review) except for `export` keywords and the one required edit below.
- **Export surface:** `test` (the composed fixture), `expect` (re-export), `encodePairingPayload` (the pure leaf encoder the pairing drive needs), plus the `RealDaemonFixtures`/`SpawnedDaemon` types. Everything else stays file-private.
- **The one real edit — import-depth shift.** The fixture sits one directory deeper than the spec did, so all four `../src/…` imports became `../../src/…` (`fakeRoutingRelay`, `relayPolicy`, `secretBackend`, `shared/wire/types`) — flagged in the spec as the ticket's single highest-risk line; code review verified all four.
- **`e2e/real-claude.spec.ts`** shrank to: the new fixture import (`test`, `expect`, `encodePairingPayload`), the streaming selectors (`ASSISTANT_ROW`, `CURSOR_CHAR`, `CURSOR_SELECTOR`), the spec-body timeouts, `nonEmptyAssistantCount`, and the `test(...)` block (including the pairing drive, which AC1 deliberately scoped out of the fixture — see below).
- **Config widen (AC2), both halves together.** `playwright.real-claude.config.ts`'s `testMatch` and `playwright.config.ts`'s `testIgnore` both moved from `/real-claude\.spec\.ts$/` to `/real-.*\.spec\.ts$/` in the same commit — widening only one would leave the `real-*` partition inconsistent (a future `real-daemon-actions.spec.ts` would leak into the daemon-less default `npm run e2e`). `real-claude.spec.ts` still matches both, so the operator's pre-ship gate is unchanged.

## Patterns established

- **Extract-on-second, not extract-on-first — but a spawn recipe is not the DOM drive.** The pairing drive (paste → Pair → Confirm → wait-for-Send) stayed in the spec; only the *spawn* recipe (AC1's explicit scope) moved. Mirrors how `launchPairedApp` itself was extracted only after both #93 and #94 existed — a shared `pairRealDaemon(page, relay, daemon)` helper is deferred to the second real-* spec.
- **Whole-fixture-chain moves are atomic.** Playwright fixtures compose within one `test` object — `daemon` can't be split from the `relay` it depends on or the `page` that depends on it. The unit of extraction is the entire `base.extend` block, not individual fixtures.
- **`e2e:real-claude` returning `1 skipped` is the load-time proof for a fixture-file move.** A wrong import-depth fails at Playwright module resolution (spec load, before collection) → the run *errors*, not skips. Seeing `1 skipped` on a machine without the real stack proves the import graph resolved correctly, without needing the real stack itself.

## Lessons learned

*Lifted from the PR body's own "Lessons learned" section.*

- `e2e/` sits outside both tsconfig `include`s, so `npm run typecheck` never catches a fixture-file type error — the load-time proof is `npm run e2e:real-claude` returning `1 skipped` rather than erroring at module resolution. A standalone `tsc` pass over `e2e/` does flag a pre-existing `env: {[k]: string | undefined}` vs Playwright's `{[k]: string}` mismatch, but it also hits the unchanged `electronApp.ts`/`launchPairedApp.ts`/`smoke.spec.ts` — Playwright's own transpiler is lenient there, so it's a known false positive, not a gate (same finding #433 recorded independently).

## Testing

`npm run build` (clean), `npm test` (1942 passed, 3 pre-existing skips), `npm run e2e:real-claude` → `1 skipped` (skip-gate fires cleanly on the agent machine; proves the fixture graph resolved), `npx playwright test --list` under the default config → collects `pair-to-conversation`/`send-and-stream`/`smoke`, correctly excludes `real-claude`. Full green (`1 passed`) remains reproducible only on a machine with `pyry`+`claude`+credentials — the operator's pre-ship gate, unchanged and out of the agent's reach.
