# #423 — fake e2e: save-as-channel promote (scratch + dedicated branches)

Split-family sibling of #451/#452 (the #422 lifecycle-e2e family). Size **S**, not security-sensitive, no
Figma section. PR #455, commit `b2a55c8`.

## Summary

Adds `e2e/save-as-channel-promote.spec.ts` — one new Playwright fake-stack UI e2e spec, **zero production
code**. It rides the same two merged fixtures as #451/#452
([`launchPairedApp`](../features/e2e-harness.md) (#433) and `conversationStateFake` (#434)) and covers the
only client flow with two location branches, previously under no e2e:

1. **Scratch branch** — "Keep in scratch" + Save fires `promote_conversation` with the row's existing
   `cwd` in place.
2. **Dedicated branch** (the dialog default) — Save drives the two-verb dance
   `create_workspace_folder` → `workspace_folder_created { path }` → `promote_conversation` with the
   daemon-**returned** path, never the client-templated preview slug (#288).

Both branches are asserted the same way: the seeded row moves from the "Recent discussions" section header
to the "Channels" section header (a zero-row section renders no header, so this substring-locator trio is a
sound section-membership proxy — see `ChannelList.tsx:243-281`).

## Patterns established

- **Two isolated `test()` blocks, not one sequential drive.** Promotion is one-way and strips the
  `.channel-list__save` affordance (Recent-discussions-only), so one seeded row can't drive both branches.
  `launchPairedApp` also clicks a **strict single** `.channel-list__row-open`, so a two-seed single launch
  strict-violates at launch. Each test gets its own launch + its own single non-promoted seed — the only
  realizable shape given those two constraints (confirmed by code review).
- **Single-consumer test infra composes over the shared fake rather than forking it.**
  `conversationStateFake`'s default arm returns `[]` for `create_workspace_folder` (a realizability gap:
  the dedicated round-trip would hang in-flight forever). The spec-local `promoteFake(seed)` wrapper peeks
  the decoded envelope's `type`, answers `create_workspace_folder` with a canonical
  `workspace_folder_created { path: DEDICATED_PATH }`, and delegates every other verb (including
  `promote_conversation`'s broadcast-then-relist) to the untouched shared fake. This stayed in-spec per the
  single-consumer test-infra rule — no fixture change, no split.
- **The section-move trio doubles as end-to-end proof of the create-folder reply.** For the dedicated
  branch, if `promoteFake` didn't answer `create_workspace_folder`, the store would hang in-flight and the
  "Channels" header would simply time out — so the same assertion used for the scratch branch also proves
  the realizability gap is closed, with no separate wire-level assertion needed.
- **`DEDICATED_PATH` is a fixed literal deliberately distinct from the templated preview slug**, proving
  structurally (not via a DOM assertion — cwd isn't surfaced in the Channel List) that the client promotes
  with the daemon-returned path verbatim, never a client-side template.
- **The dedicated radio's accessible name is a substring match against a label containing a live
  slug-preview span** (`getByRole('radio', { name: 'Move to dedicated channel folder' })`) — the substring
  still resolves unambiguously since neither radio's label text contains the other's.
