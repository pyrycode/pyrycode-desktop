## What it covers

`e2e/stall-snapshot-bundle.spec.ts` — the three reliability affordances an operator reaches for when a session misbehaves, none of which had e2e coverage though all three already ship end-to-end: the stall indicator (#315 transport / #317 render), the "Show daemon screen" screen snapshot (#316/#180 transport, #323 store, #324 action+display), and the debug-bundle download (#116 reassemble, #169 orchestrator, #72 render). Covered together because each exercises a distinct daemon-interaction shape — a pure server push, a request→reply, and a chunked reply stream — in **one** `test()` block on **one** launch (the #425/#427 precedent: none of the three carries one-way-per-launch state).

- **Stall** — `daemon.pushFrame(stallFrame(SEEDED_ROW.id))` (a server push, not a reply arm). Asserts `.conversation__stall` visible and `.bubble--stall` contains `'The turn seems to have stalled…'`. No sheet — the control sits on the main thread. Nothing later in the spec emits timeline turn-activity, so the indicator persists through the remaining steps (asserted first, once).
- **Screen snapshot** — clicks `.screen-snapshot__request` ("Show daemon screen"), proves the outbound `request_snapshot { conversation_id: SEEDED_ROW.id }` via `expect.poll`, then asserts the scripted `screen_snapshot` reply's `text` (`'DAEMON SCREEN 428'`) renders into `<pre className="screen-snapshot__screen">`. Asserted **before** the Run-config sheet opens.
- **Debug-bundle download** — opens the Run-configuration sheet, clicks `.log-data__download`, proves the outbound bare `request_debug_bundle` (`payload: {}`), then asserts `.log-data__status` (`role="status"`) reads `'Downloading… 3 chunks received'` after three scripted `debug_bundle_chunk` frames round-trip. No `debug_bundle_done` is sent.

## Patterns established / reused

- **Stall is a `daemon.pushFrame`, never bundled onto a reply.** Same correction shape as #426/#427's stale-premise fixes: the wire event is unsolicited, so it belongs in the test body, not in a `buildReplyFrames` arm.
- **The screen-snapshot overwrite trap.** The screen-snapshot store is a global most-recent-wins store, and opening the Run-config sheet fires `RunConfigData`'s own `request_snapshot` on mount. Defused two ways together: the capturing factory answers **every** `request_snapshot` with the same `SNAPSHOT` payload, and the `<pre>` assertion runs **before** the sheet opens. A future scenario that also opens the Run-config sheet and asserts the snapshot text needs both defenses, not just one.
- **`text` reaches the `<pre>` — unlike the #425 run-config baseline.** #425's `screen_snapshot` reply used `text: ''` because that spec only needed the sheet's own precondition satisfied. This spec is the first to assert the snapshot `text` is actually surfaced, confirming the #316/#323 `screenSnapshotReceived` path is distinct from (and keeps `text`, unlike) the #180 run-config path.
- **Chunked reply stream without a terminal frame.** `debugBundleProgress` fires per accepted chunk, so streaming `debug_bundle_chunk` frames alone (no `debug_bundle_done`) is sufficient to drive the progress caption to its final count — the first #422-family spec to prove a chunked-stream verb this way.
- **No save-dialog exists.** The pre-split draft assumed `dialog.showSaveDialog` needed stubbing; it doesn't — `saveDebugBundle` (#117) writes deterministically to `app.getPath('downloads')`. Since the fixture isolates `--user-data-dir` but not `~/Downloads`, scripting `debug_bundle_done` would leak a real archive onto the developer's machine. The spec deliberately stops at the progress caption and leaves the "Saved to `<path>`" terminal state as a noted, out-of-scope residual — no downloads-isolation seam was added.
- **No session-id precondition needed.** Unlike #425's run-config controls, neither the snapshot button (gated only on `connected`) nor the download button (daemon-global, no session addressing) needs a `session_transition` push — simpler setup than the run-config skeleton it otherwise clones.

## Lessons learned

- The standalone-tsc temp config used to typecheck `e2e/` specs must include the `src/**` globs (needed for `noise-c.wasm`'s ambient `.d.ts` to resolve) — without them, `tsc` reports a residual `env` error at `launchPairedApp.ts:152` that is pre-existing baseline noise, not something this spec introduced. Worth checking against the temp-config's `include` before treating that specific error as a regression.
