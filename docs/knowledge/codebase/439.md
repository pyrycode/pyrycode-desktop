## Summary

Ships the **credential-light real-daemon e2e tier**: a real spawned `pyry` daemon on the content-blind
[fake routing relay](../features/fake-routing-relay.md), gated on the `pyry` binary **alone** — no
`claude`, no Anthropic credential, no `.claude.json`. This is the tier that would have caught the
`promote_conversation` gap (pyrycode/pyrycode#949): the daemon defined the type, payload, and registry op
but registered no handler, so the real wire answered `unsupported` while the entire fake-daemon suite
stayed green (a fake answers anything). The registry-backed user actions — rename, archive, restore,
delete, recent-workspaces, create-folder, change-workspace, session-settings, dequeue — are pure registry
ops daemon-side and never touch claude, so they can be proven against a real daemon deterministically and
cheaply, without the credentials [`real-claude.spec.ts`](../features/real-claude-liveness-e2e.md) needs.

This ticket ships the reusable harness plus one liveness proof (rename): pair against a claude-less
spawned daemon, wait for the seeded promoted conversation's Rename pencil to render (the readiness gate),
rename it through the product UI, and assert the new title renders in the channel list while the old one
is gone.

## What shipped

- **Two additive Playwright option fixtures** on the existing `test.extend` in `realDaemon.ts`:
  `spawnClaude` (default `true`) and `seedPromoted` (default `false`). Defaults reproduce the prior
  behavior byte-for-byte — `real-claude.spec.ts` sets neither option and is unaffected.
- **`daemon` fixture branches on `spawnClaude`.** `pyry` is resolved and skip-gated unconditionally;
  `claude`, the `ANTHROPIC_API_KEY`/`CLAUDE_CODE_OAUTH_TOKEN` pair, and `.claude.json` seeding are
  resolved and skip-gated **only** inside `if (spawnClaude)`. Claude-less mode never skips on a missing
  claude binary or credential — the whole point of the tier.
- **`-pyry-claude` placeholder.** Claude-less mode writes `<daemonHome>/noop-claude.sh` (`#!/bin/sh` +
  `exit 0`, mode `0o755`) and points `-pyry-claude` at it, rather than omitting the flag — the
  credential-light invariant is "no real claude binary or credential required," not "flag absent."
  Cleaned up for free with the rest of `daemonHome`.
- **Post-`--` claude args dropped in claude-less mode.** `--model haiku
  --dangerously-skip-permissions` are spread in only `...(spawnClaude ? [...] : [])` — no claude turn
  ever runs in claude-less mode, so passing claude flags to a non-claude placeholder would be misleading.
- **`seedRegistry` gains an `isPromoted: boolean` param**, threaded from the `seedPromoted` option,
  replacing the hardcoded `"is_promoted":false` literal in the seeded `conversations.json`. Everything
  else in the seed (bootstrap session UUID, the `'default'` binding, `0o600` modes) is unchanged.
- **New spec `e2e/real-daemon-rename.spec.ts`.** `test.use({ spawnClaude: false, seedPromoted: true })`
  at file scope. Readiness gate is `.channel-list__rename` becoming visible (stronger than a bare
  row-visible check — it proves handshake complete → session connected → `list_conversations` returned
  the seeded row → it rendered **promoted**, in the Channels section). Drives pencil → dialog → fill a
  per-run-nonce title → Save, then asserts the new title renders in `.channel-list` and the old
  (`"Untitled"`, read from the DOM rather than hardcoded) is gone.
- **Filename convention.** `real-daemon-rename.spec.ts` matches the existing `/real-.*\.spec\.ts$/`
  `testMatch`/`testIgnore` pair (widened by #420) — no config change needed; it runs under `npm run
  e2e:real-claude` and is excluded from the default `npm run e2e`.

## Patterns established

- **Option fixtures over a factory, when the fixture chain's dependency order *is* the teardown order.**
  `relay → daemon → page` LIFO-tears-down so the app closes before the daemon/relay drop (the app's
  supervisor can't churn-reconnect on the loss). A factory fixture (the `launchPairedApp` shape) would
  collapse that chain and force `real-claude.spec.ts` to change its call shape. Playwright option
  fixtures (`test.extend<Options & Fixtures>({ opt: [default, {option:true}], ... })`) are purely
  additive — an unmodified consumer gets the exact old defaults — so this is the shape to reach for
  whenever a shared fixture chain's *ordering* is load-bearing and a new mode must not perturb existing
  consumers.
- **A placeholder executable, not flag omission, for "swap out the real binary."** When a harness needs
  to make a subprocess-spawning daemon flag credential-free, point the flag at a harness-owned no-op file
  under the harness's own temp dir (auto-cleaned with it) rather than trying to omit the flag or rely on
  the daemon's fallback resolution — the daemon's default resolution could still find and depend on a
  real binary on a machine that has one but not the credential. Precedent: `docs/lessons.md`'s
  `/bin/sleep`-style fake-claude binaries in the daemon's own multi-session e2e.
- **A UI-rendered gate over a raw list-length gate.** The readiness assertion (`.channel-list__rename`
  visible) doubles as a semantic proof (promoted echo, not just "a row exists") — cheaper and stronger
  than asserting row count then separately checking promotion.

## Lessons learned

*Lifted from the PR body's own "Lessons learned" section; all three resolve the spec's Open Questions.*

- The `#!/bin/sh` + `exit 0` no-op `-pyry-claude` placeholder boots the real daemon fine and it registers
  on the relay — the daemon spawns claude lazily on the first `send_message`, so the immediate-exit
  placeholder is never invoked and is not treated as a boot crash. The long-lived `sleep` fallback (Open
  Question 1) was not needed. **Resolves OQ1.**
- The rename round-trip works against a real #820-inclusive daemon: `rename_conversation` persists and
  the `conversation_updated` broadcast fires, driving the desktop's `shouldRefreshList` re-list. The
  daemon also echoes `is_promoted:true` on the seeded row, so the readiness pencil rendered. **Resolves
  OQ2 and OQ3.**
- A machine with `pyry` + `claude` but no credential runs the claude-less tier green while
  `real-claude.spec.ts` skips cleanly at its credential gate — a concrete, on-machine demonstration that
  the credential-light tier exercises what the credentialed tier can't.

## Testing

`npm test` (1942 passed), `npm run build` clean, `npx playwright test --config
playwright.real-claude.config.ts --list` collects the new spec under `e2e:real-claude` and confirms the
fixture change compiles (`e2e/` isn't typechecked by either project tsconfig, so `--list` is the load-time
proof, same as #420). Ran **green end-to-end against a real daemon** on the operator's machine (`pyry` +
`claude` present, no credential) — deterministic across repeats — while `real-claude.spec.ts` still skips
cleanly at its credential gate on the same machine.
