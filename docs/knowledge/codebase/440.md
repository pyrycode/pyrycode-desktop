## Summary

Real-daemon twin of the merged fake-stack spec [#452](452.md): the same archive → restore → delete chain
on one FAB-created conversation, driven against a real spawned `pyry` (`spawnClaude:false`,
`seedPromoted:true`) on the [fake routing relay](../features/fake-routing-relay.md) instead of the
`conversationStateFake`. This is the credential-light tier ([#439](439.md)) that would have caught the
`promote_conversation` gap (pyrycode/pyrycode#949): the daemon defined the type but registered no handler,
so the real wire answered `unsupported` while the entire fake-daemon suite stayed green. Archive,
unarchive, and delete are pure registry ops daemon-side (never touch claude), so they prove against a real
daemon deterministically and cheaply.

The spec grafts #452's assertion surface onto the [#439 realDaemon fixture](../features/real-daemon-credential-light-e2e.md)
field-for-field: pair (from `real-daemon-rename.spec.ts`'s explicit drive) → readiness gate
(`.channel-list__rename` visible) → baseline Archive view `(0)/(0)` → FAB create-nav → Archive → Restore →
re-enter → Delete via two-step confirm → assert gone from both the active Channel List and the Archive
view.

## Patterns established

- **Real-daemon seed name-collision forces affordance-scoped selectors over title-scoped ones.** The
  fixture's `seedRegistry` writes no `name` field, so the promoted seed renders `titleFor(null)` =
  "Untitled" — identical to a name-less FAB-created conversation. #452's fake twin could scope its
  re-entry click and post-delete survivor assertion by title (`hasText: UNTITLED`, its seed was uniquely
  named); here both rows read "Untitled", so this spec instead scopes by **section affordance**: the
  promoted seed carries `.channel-list__rename` (Channels), the non-promoted created row carries
  `.channel-list__save` (Recent discussions). `.channel-list__row.filter({ has: '.channel-list__save' })`
  isolates the created row unambiguously; the post-delete survivor assertion is
  `.channel-list__rename` count 1 + `.channel-list__save` count 0, never a title-text count. Generalizes
  #452's lesson: prefer count-delta/affordance assertions over title text whenever a fixture's seed and a
  test-created row could render the same display string.
- **No opening back button when the real-daemon path lands on `route='list'`.** Unlike #452's
  `launchPairedApp` (which starts inside the seed thread), the real-daemon pairing drive lands on the
  Channel List post-handshake — so a `.channel-list__rename` readiness gate (proving handshake complete →
  session connected → `list_conversations` round-tripped → the seeded promoted row rendered) replaces
  the fake twin's opening `.conversation__back` step. Same pattern #439's rename spec established, reused
  here unchanged.

## Lessons learned

*Lifted from the PR body's own "Lessons learned" section.*

- Both architect open questions confirmed against a live `pyry dev` build (2.8s run): the FAB create stays
  claude-less (the fixture's `exit 0` `-pyry-claude` placeholder sufficed — no `exec sleep` fallback
  needed) and `cwd:null` → daemon default resolves without a claude turn. All four handlers
  (`create_conversation`/`archive_conversation`/`unarchive_conversation`/`delete_conversation`) are
  registered on this build, so no #949-class gap was found here — the tier did its job and came back
  clean.
- The real-daemon seed being name-less (vs. #452's uniquely-named fake seed) is itself worth flagging
  forward: any future real-daemon spec that needs to distinguish a seed row from a created row must not
  rely on title text — use section affordance or another structural signal instead.

## Code review note (non-blocking)

One NIT: the create-nav assertion (line 221, `overflowTrigger.toBeVisible()`) uses Playwright's default 5s
timeout while every other round-trip assertion in the spec uses `ROUNDTRIP_TIMEOUT_MS` (15s) — inconsistent
with the tier's own philosophy that "a timeout = a genuine daemon gap," making this the one spot a slow-but-
functional daemon could false-positive as a missing handler. Not fixed in this PR (the fake twin #452 also
uses the default there); left as a candidate cleanup for whichever sibling spec (#441–#443) next touches
this assertion shape.
