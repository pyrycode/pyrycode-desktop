## Summary

Tier-3 real-claude twin of the fake-stack interrupt wiring (#307 render, #427 chain): proves
interrupt-mid-turn against a **genuinely running** turn — a real daemon's turn lifecycle plus real
claude's streaming plus the client's non-optimistic quiesce — rather than a scripted
`daemon.pushFrame`. Clones `real-claude.spec.ts`'s precondition verbatim (pairing, FAB-created
conversation, connected gate) and swaps only the turn body: send a deliberately long haiku prompt
("Count from 1 to 300, one number per line"), gate on the interrupt affordance becoming visible (and,
as a strengthening, on the streaming cursor appearing — proving `responding`, not merely `thinking`),
click interrupt, then assert a two-signal quiesce (`interruptButton` count-0 from `turn_state{idle}`,
`.bubble__cursor` count-0 from `turn_end`) before capturing a settled assistant-content baseline and
proving it stays flat over a 3s window.

Sets no `test.use(...)` — inherits `spawnClaude:true` (haiku) and the full skip-gate (`pyry` + `claude`
+ credential resolved before any resource is created) for free from the #420 fixture. Auto-discovered
by `playwright.real-claude.config.ts`'s `testMatch: /real-.*\.spec\.ts$/`; excluded from the default
`npm run e2e` by the matching `testIgnore`.

## Patterns established

- **The settled baseline must be captured *after* both quiesce signals, never at the click.** The
  daemon may emit a trailing chunk after the interrupt lands; reading `nonEmptyAssistantCount()` before
  the two-signal gate (`interruptButton` count-0 **and** `.bubble__cursor` count-0) would race that
  trailing chunk. Capturing strictly after both signals fire makes the "content stops growing" check
  race-free without needing to inspect frame content.
- **Two independent DOM reflections of the same server-side event, asserted together, is the
  real-daemon belt-and-suspenders idiom for "the turn genuinely ended."** The button retracts from
  `turn_state{idle}`; the cursor clears from `turn_end` — different wire events, same underlying daemon
  action. Asserting both (rather than either alone) generalizes #441's "assert on daemon-derived state
  with two independent signals when only one wire event is asserted elsewhere" caution one step further:
  here both signals are asserted, not substituted for each other.
- **Proving a negative ("no further growth") over a bounded window has no event to await — a fixed
  `waitForTimeout` + re-read is the correct and only tool**, not a design smell. Kept deliberately short
  (`SETTLE_MS = 3_000`) since it is pure overhead once the quiesce gate has already fired.
- **A real-wire DOM-only spec cannot prove causation, only liveness.** The architecture spec calls this
  out explicitly (OQ-a): a turn that finishes naturally also retracts the affordance, so the mitigation
  is a deliberately long prompt (count-to-300) that makes natural completion within the interrupt
  window implausible, not a stronger assertion. This is an accepted, permanent property of the tier-3
  liveness net, not a gap to close later.
