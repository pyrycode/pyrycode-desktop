# #451 — fake e2e: conversation create + list render + Channel-info sheet rename

Split from #422. Size **S**, not security-sensitive, no Figma section. PR #453, merged as `6872c03`.

## Summary

Adds `e2e/conversation-create-rename.spec.ts` — one new Playwright fake-stack UI e2e spec, **zero
production code**. It rides the two merged fixtures ([`launchPairedApp`](../features/e2e-harness.md)
(#433) and `conversationStateFake` (#434)) on a single launch and covers three flows that had no e2e
guard:

1. **FAB create-nav** — `.channel-list__fab` → `create_conversation` → `conversation_created` →
   navigation into the created thread.
2. **Channel-info sheet rename** — thread overflow menu → "Channel info" → the sheet's `Rename` pill
   (one of three `.channel-info__action` buttons) → `RenameConversationDialogView` → `rename_conversation`.
3. **Grown two-row Channel List** — the rename's `conversation_updated` broadcast triggers a re-list that
   lands both the seeded row and the renamed created row, split across the "Channels" (promoted) and
   "Recent discussions" (non-promoted) sections.

The sibling entry point, list-row rename (`.channel-list__rename`), stays owned by
`e2e/conversation-state-fake.spec.ts` (#434's demonstrator) and is deliberately not re-proven here.

## Patterns established

- **Gap A (create issues no re-list) is asserted around, not against.** `conversationListBridge`'s
  `shouldRefreshList` returns `false` for `conversationCreated`, so a FAB-created conversation never enters
  the active Channel List at create time. The spec asserts navigation into the thread instead
  (`.conversation__overflow-trigger` becoming visible — absent on the list, present on a thread, so its
  auto-wait doubles as the create-nav gate), not list membership.
- **`.channel-info__action` is not a unique selector.** The sheet renders three action pills (Rename /
  Archive / Delete) sharing the class. Target by accessible name instead:
  `page.getByRole('button', { name: 'Rename', exact: true })`.
- **The FAB-created row starts unnamed.** `requestNewConversation` sends `name: null`; the rename dialog
  opens prefilled "Untitled", and `.fill()` replaces the prefill.
- **The observable reflection surface for a rename is the re-listed Channel List, not the open
  thread/sheet.** `activeConversationStore` is not rewritten by `conversation_updated`, so the thread's own
  title may lag; assert the rename landed by navigating back and reading `.channel-list`.

## Lessons learned

- **The Channel-info sheet is a full-surface overlay whose scrim blocks the back button.**
  `.status-sheet-overlay` is `position: absolute; inset: 0` with a click-intercepting scrim, so
  `.conversation__back` is unclickable while the sheet is open — a direct back-click fails Playwright's
  actionability check. Close the sheet first (`.status-sheet__close`), *then* click `.conversation__back`.
  The architecture spec's drive sequence didn't anticipate this (it navigated back directly after Save);
  the developer added the close-first step during implementation. This applies equally to #452 (the
  archive → restore → delete sibling), which also opens the Channel-info sheet.

`npm run build` clean; `npm run e2e` green (5/5, new spec ~1.2s).
