# #456 — fake e2e: workspace picker (recent-pick + create-folder)

Split-family sibling of #451/#452/#423 (the #422 lifecycle-e2e family). Size **S**, not
security-sensitive, no Figma section. PR [#458](https://github.com/pyrycode/pyrycode-desktop/pull/458),
commit `947e5b2`. Blocks #457 (the default-workspace spec reuses the `recent_workspaces` fake answer
this ticket adds).

## Summary

Adds `e2e/workspace-picker.spec.ts` — one new Playwright fake-stack UI e2e spec, **zero production
code**. It rides the same two merged fixtures as #451/#452/#423
([`launchPairedApp`](../features/e2e-harness.md) (#433) and `conversationStateFake` (#434)) and covers
the `WorkspacePickerSheet`'s (#383) two wire round-trips, neither under e2e before this ticket:

1. **Recent-pick** — the picker mounts `RecentWorkspacesData` (fires `recent_workspaces`), renders
   `.workspace-picker__row` per seeded reply row; choosing one emits `change_workspace
   { conversation_id, cwd }` with the row's path and closes the picker.
2. **Create-folder** — "Create new folder" opens `CreateFolderDialog`, which sends
   `create_workspace_folder { parent, name }`; on the `workspace_folder_created { path }` reply the
   created-effect auto-chains `change_workspace` with the daemon-**returned** path verbatim (never a
   client-reconstructed preview — the #288 lesson), then the whole picker tree unmounts.

`conversationStateFake` (#434) answered `change_workspace` already but fell to `default: return []`
for `recent_workspaces` and `create_workspace_folder`. This ticket adds a `recent_workspaces` answer
to the shared fixture (reused by split sibling #457) and keeps `create_workspace_folder` spec-local
(single consumer — #457's picker has that entry disabled).

## What shipped

- **`e2e/fixtures/conversationStateFake.ts`** (additive) — a new optional
  `recentWorkspaces?: RecentWorkspace[]` option (default `[]`, captured as a plain `const recents`
  since `recent_workspaces` has no mutation verb, unlike the mutable `list`), one new switch case
  (`case 'recent_workspaces': return [recentWorkspacesListFrame(recents)]`), and one new frame
  builder mirroring `conversationsFrame` — `recentWorkspacesListFrame` encodes a broadcast-shaped
  `recent_workspaces_list` (no `in_reply_to`, matching `conversation_updated`; the app consumes it via
  the correlation-free `recentWorkspacesReceived` event and the decoder needs no correlation). No
  existing spec sends `recent_workspaces`, so the change is purely additive.
- **`e2e/workspace-picker.spec.ts`** — two isolated `test()` blocks (the #423 shape), each its own
  `launchPairedApp` launch, its own single `is_promoted: false` seed, and its own capture array. A
  spec-local `capturingWorkspaceFake(seed, recents, captured)` composes over `conversationStateFake`
  the same way #423's `promoteFake` does: decode every inbound into the spec-held `captured: Envelope[]`
  before delegating, and intercept `create_workspace_folder` with a canonical
  `workspace_folder_created { path: CREATED_PATH }` reply (`in_reply_to: env.id`) — everything else
  (`recent_workspaces`, `change_workspace`, `list_conversations`) delegates to the shared fake
  untouched.
- **The realizability precondition (#448) is asserted, not assumed.** `WorkspaceChip` self-gates to
  null unless `isEmpty && conversation !== null && !conversation.is_promoted`
  (`ConversationScreen.tsx:436`). Since #448, `PairedShell`'s row-open sets the active conversation
  before navigating, so a `launchPairedApp` landing on an `is_promoted: false` seed satisfies the gate
  with no message sent. Both blocks assert the "Change workspace" button is enabled before proceeding
  — a regression that stops row-open from setting the active conversation fails there, not downstream.
- **Assertion target is the outbound wire frame, not a DOM reflection.** `change_workspace`'s reply is
  `conversation_updated`, a no-op for `activeConversationStore` (only `conversation_created` and,
  since #448, a row-open write it — see the corrected note in
  [Conversation workspace change](../features/conversation-workspace-change.md)); the chip's
  snapshotted `cwd` never updates and the channel-list row never renders `cwd`. So "the list reflects
  the new workspace" is the same unrealizable trap that routed #440 back — the spec instead
  `expect.poll`s `captured.find(e => e.type === '…')?.payload` against the exact wire payload.
- **`CREATED_PATH` is a fixed literal deliberately distinct** from the client-reconstructable preview
  (`SEED.cwd + '/' + FOLDER_NAME`), proving the chained `change_workspace` carries the daemon-returned
  path verbatim (the #288 proof, same pattern #423 uses for its dedicated-branch path).

## Patterns established

- **A shared-fixture read-only answer vs. a spec-local mutating one, decided by consumer count.**
  `recent_workspaces` went into the shared `conversationStateFake` because #457 (blocked-by this
  ticket) reuses it verbatim; `create_workspace_folder` stayed spec-local because #457's own picker
  variant has that entry disabled. The rule applied here: promote to the shared fixture only when a
  second real consumer is already known, not preemptively.
- **Two isolated `test()` blocks, each its own launch + seed + capture array** — the #423 shape,
  reused here for the same reason: keeping each flow's poll/assertion crisp with no cross-flow array
  bookkeeping, at the accepted cost of a second pairing launch.
- **The captured-envelope compose-over is now a repeatable idiom**, not a one-off: #423's `promoteFake`
  and this ticket's `capturingWorkspaceFake` both (a) decode every inbound into a spec-held array
  before delegating, (b) intercept exactly one verb the shared fake doesn't answer, and (c) delegate
  everything else untouched. A third occurrence would be a signal to consider extracting a shared
  `capturingFake(stateFake, captured)` wrapper in the fixture — not done here (only two occurrences,
  evidence-based, no premature abstraction).

## Lessons learned

*Lifted from the PR body's own "Lessons learned" section.*

- `e2e/` is in neither project `tsconfig`, so `npm run typecheck` and Playwright's type-stripping
  loader both skip it — validating fixture/spec type additions needs a standalone `tsc` pass over
  `e2e/**/*` (plus `src/main`/`src/shared` for the `noise-c.wasm` ambient shim). That pass surfaced
  pre-existing latent `process.env` (`string | undefined` vs `string`) type errors in the existing e2e
  fixtures (`launchPairedApp.ts`, `electronApp.ts`, `realDaemon.ts`, `smoke.spec.ts`); left untouched
  (out of scope, test-infra, non-blocking at runtime). This is the same pre-existing gap already
  documented in [E2E test harness](../features/e2e-harness.md)'s "Not type-checked" edge case — no new
  gap, just a second data point confirming its shape.
