# #457 — fake e2e: default-workspace preference reaches create_conversation cwd

[Ticket](https://github.com/pyrycode/pyrycode-desktop/issues/457) · [PR #460](https://github.com/pyrycode/pyrycode-desktop/pull/460) · Spec: `docs/specs/architecture/457-default-workspace-create-conversation-e2e.md` · Size **S** · test-only, zero production code · not `security-sensitive` · no Figma

Split from #424 (the #424 fork's other half is #456, merged). Rides the merged fixtures #433 (`launchPairedApp`) and #434/#456 (`conversationStateFake`, with the `recentWorkspaces` option #456 added). Blocked by #456 — satisfied by the **shared fixture**, not by riding #456's spec.

## What it covers

`e2e/default-workspace.spec.ts` — one new Playwright fake-stack UI e2e spec, one continuous `test()` block, driving the already-shipped chain `DefaultWorkspaceRow` (#404) → `WorkspacePickerSheet` (#383) → `defaultWorkspaceStore` (#403) → the channel-list FAB (#242) end to end:

1. Land in a seeded thread via `launchPairedApp`, back out to the list.
2. Open Settings and assert the `'scratch'` placeholder (proves `pyry.defaultWorkspace` started unset — free from `launchPairedApp`'s fresh `mkdtemp --user-data-dir`).
3. Open the Settings "Default workspace" picker, assert one `.workspace-picker__row` per seeded `RecentWorkspace` (the `recent_workspaces` → `recent_workspaces_list` round-trip), choose one by its unique path text.
4. Assert the store write landed (`.settings__default-workspace-value` flips to the chosen path) and the picker closed — **no wire traffic** on the choose (`onChoose` only calls `setDefaultWorkspace`).
5. Back to the list, create via the FAB (`requestNewConversation` reads the store and sends `create_conversation`).
6. **Primary assertion** — `expect.poll` the spec-captured inbound frames for `create_conversation`, `.toEqual({ is_promoted: false, name: null, cwd: CHOSEN })`.
7. **Nav proof** — `.conversation` visible (the fake's `conversation_created` reply drove `useConversationCreatedNav`).
8. **Negative guard** — `captured` contains no `change_workspace` frame, placed after the primary poll so the single in-order Noise channel makes the absence race-free.

## What shipped

- **`e2e/default-workspace.spec.ts`** only — no fixture edit. `capturingDefaultWorkspaceFake(seed, recents, captured)` composes over `conversationStateFake({ conversations: [seed], recentWorkspaces: recents })` the #423/#456 way: `decodeEnvelope(inbound)` → `captured.push(env)` → delegate. **Strictly simpler than #456's `capturingWorkspaceFake`**: every verb the drive sends (`list_conversations`, `recent_workspaces`, `create_conversation`) is already answered by the shared fake, so the wrapper adds zero spec-local verb handling (#456 needed one, for `create_workspace_folder`).
- **One `test()` block**, not two. The drive is linear (set a default, then create once) — one launch keeps one throwaway `--user-data-dir`, so `localStorage` stays empty for the `'scratch'` baseline with no reset step. Contrast #456's two blocks, needed there because promotion is one-way.
- **`RECENT_A`/`RECENT_B`** are fixed, mutually-non-substring paths (the #423 substring caution) so the `hasText` row locator resolves `CHOSEN` (`RECENT_A.path`) uniquely.

## Patterns established / corrected

- **Seed promotion is irrelevant here — a correction vs #456.** #456's `is_promoted:false` seed constraint exists because the thread `WorkspaceChip` self-gates on it. This spec never touches that chip: it drives the Settings picker, which gates on nothing beyond a non-empty recents list. The seed only needs to be a single clickable row so `launchPairedApp` can land in a thread.
- **The captured-envelope compose-over idiom (#423 → #456) now has a third occurrence, this time with zero spec-local verb handling** — the strongest evidence yet that the shared-fixture-vs-spec-local split (#456's own "Patterns established") is working: promoting `recent_workspaces` to the shared fake in #456 paid off immediately for its very next consumer.
- **A frame-ordering argument makes a negative wire-assertion race-free.** Because Noise carries frames over one in-order channel, asserting "no `change_workspace` was ever sent" is safe to check *after* polling for `create_conversation` — any earlier frame the choose might have emitted is already in `captured` by the time the later frame is observed. Reusable whenever a negative wire guard needs sequencing after a positive one on the same channel.

## Lessons learned

*Lifted from the PR body's own "Lessons learned" section.*

- The `create_conversation` `cwd` has no DOM surface at all (the #440/#456 unrealizable-active-list trap applies here too) — the load-bearing assertion has to be the outbound wire frame, captured spec-locally; there is no DOM-only way to write this spec.
- `localStorage` determinism for the `'scratch'` baseline comes free from `launchPairedApp`'s fresh `mkdtemp --user-data-dir` — this is the first e2e spec to drive a `localStorage`-backed store, and no extra reset step was needed.
- The negative guard (no `change_workspace` emitted on the Settings choose) is race-free only because it's placed *after* the `create_conversation` poll, per the frame-ordering pattern above.
