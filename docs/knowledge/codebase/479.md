# #479 — Operator gate: fail on zero-executed real-* e2e

**Shipped:** 2026-07-16 · **Size:** S · **Security-sensitive:** no (test tooling only, zero production LOC) · **Figma:** N/A (CLI exit-code gate, no UI surface).
**Spec:** `docs/specs/architecture/479-e2e-real-gate-zero-executed.md` · **PR:** [#484](https://github.com/pyrycode/pyrycode-desktop/pull/484), code review PASS, no findings.

## Summary

`npm run e2e:real-claude` exits **0** when every `e2e/real-*.spec.ts` spec skips for a missing prerequisite (`pyry`/`claude`/a credential) — correct and load-bearing for the pipeline (a clean skip is the agent smoke check that the fixture graph resolved, per [#420](420.md)), but a trap for an operator: an under-provisioned machine gets the identical green exit as a genuine live pass. This ticket adds a **separate** operator entry point, `npm run e2e:real:gate`, that runs the exact same specs against the exact same `playwright.real-claude.config.ts` and turns `executed == 0` into a hard non-zero exit — without touching the plain command's behavior at all.

## What shipped

- **`e2e/reporters/zeroExecutedGate.ts`** (new file, new `e2e/reporters/` directory — the repo's first custom Playwright reporter). A `Reporter` implementation with two hooks:
  - `onTestEnd` — increments an `executed` counter for any non-`'skipped'` result; for skipped tests, merges `result.annotations` and `test.annotations` (`type === 'skip'`) into a `Set<string>` of skip descriptions (the fixture's own `testInfo.skip(...)` strings from `e2e/fixtures/realDaemon.ts`, read verbatim — no re-derivation of which prerequisite is missing).
  - `onEnd` — iff `result.status === 'passed' && executed === 0`: writes the deduped skip reasons to stderr (one line each, `zero-executed gate: no real-* e2e ran — <reason>`; falls back to a generic "no skip reason captured" line if the Set is somehow empty) and returns `{ status: 'failed' }`, Playwright's documented mechanism for a reporter to override the run's exit status. Any other status (`'failed'`/`'timedOut'`/`'interrupted'`) or `executed > 0` returns nothing — the gate only ever *upgrades* a clean pass, never masks a real failure.
- **`package.json`** — one new script, `"e2e:real:gate": "npm run build && playwright test --config playwright.real-claude.config.ts --reporter=list,./e2e/reporters/zeroExecutedGate.ts"`. Mirrors `e2e:real-claude` (same `npm run build &&` prefix, same `--config`) with only the `--reporter` flag appended.
- **`docs/knowledge/features/live-e2e-runbook.md`** — § "Automated coverage is deferred" gained a paragraph naming `e2e:real:gate` as the exit-code-safe form of the `real-*` harness, with explicit non-overclaim language: it does not supersede `scripts/live-drive.mjs` (still local relay, not live) and does not resolve the #449 live reply-fan-out gap.

## Design: CLI `--reporter` flag, not a second config or a config edit

The CLI `--reporter` flag **overrides** a Playwright config's `reporter` entirely. Passing `--reporter=list,./e2e/reporters/zeroExecutedGate.ts` keeps the human-readable `list` output *and* adds the gate reporter, against the **same** `playwright.real-claude.config.ts` the plain command uses — satisfying "same specs, same config" (AC1) and "plain command byte-for-byte unchanged" (AC6) simultaneously, with no shared-config edit and no second config file to keep in sync. Editing the config's `reporter` field directly would have leaked the gate into `e2e:real-claude` and broken the pipeline's load-bearing green-on-all-skip.

## Patterns established

- **Enforcement-only reporters attach via the CLI flag, not the config.** When a variant behavior must exist alongside an unchanged baseline command that shares the same config file, add the variant through a CLI override on a new npm script rather than forking or editing the shared config.
- **Reuse fixture skip annotations instead of re-deriving prerequisite state.** The gate does no prerequisite detection of its own — it reads the same `testInfo.skip()` strings the fixture already authors, so the two can never drift.
- **The "upgrade-only" guard (`status === 'passed'`) makes AC4 structural, not just tested** — a non-passed result is inert to the reporter by construction, not by a case the developer remembered to write.

## Lessons learned

*Lifted from the PR body's own "Lessons learned" section.*

- On `@playwright/test@1.61.1`, `Reporter.onEnd` is typed `Promise<{ status? } | void> | void` — a **synchronous** `return { status: 'failed' }` does not type-check; `onEnd` must be declared `async` (so it returns a `Promise`) to satisfy the override signature. `e2e/` sits outside both tsconfig `include`s ([#420](420.md)), so nothing but actually running the gate catches this.
- `testInfo.skip()` fired during fixture setup surfaces its description on `result.annotations`; reading **both** `result.annotations` and `test.annotations` (verified empirically, since `e2e/` isn't typechecked) is the robust way to capture the string without assuming which field carries it.
- **This agent machine is not zero-prerequisite** (both the architecture spec and prior ticket memory assumed it was): `pyry` and `claude` are both on `PATH`; only the Anthropic credential is absent. A natural `npm run e2e:real-claude` run here executes and passes the 4 `real-daemon-*` specs (gate on `pyry` alone) and skips only the 4 `real-claude-*` specs (need credentials) — `executed > 0`, so the gate is inert on a natural run. To reproduce the all-skip RED proof (AC5), the developer forced `PYRY_BIN=/nonexistent` (an override path that does *not* fall through to `PATH`) to make all 8 specs skip. This is relevant to every future `real-*` e2e ticket that assumes a prereq-less agent machine — see [#439](439.md).
- The machine's natural partial run (4 executed+passed, 4 skipped) incidentally proved AC3 (`executed > 0` → exit 0) reproducibly on the agent machine, which the spec had assumed was operator-only.

## Testing

`npm run build` clean; `npm test` 1951 passed / 3 pre-existing skips. Gate behavior verified live (all agent-reproducible):
- **AC5/AC2 (RED→GREEN):** forced all-skip (`PYRY_BIN` unresolvable) → `e2e:real-claude` exits 0 (the trap); `e2e:real:gate` exits 1, prints the fixture's `` `pyry` not found `` reason exactly once (Set dedup confirmed).
- **AC3:** natural partial run (4 real-daemon-* pass, 4 real-claude-* skip) → gate exits 0, inert.
- **AC4:** a temporary genuinely-failing spec (deleted after) → run exits 1 from the failure itself, gate stays inert.
- **AC6:** `e2e:real-claude` exits 0 on both all-skip and partial runs — unchanged.

AC3's fully-provisioned live-green path (a real reply actually streaming) remains operator-only, like every `real-*` spec.
