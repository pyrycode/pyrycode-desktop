## Summary

The 2026-07-16 first full `npm run e2e:real-claude` run (5 passed / 3 failed) flipped the gate docs stale in two opposite directions at once: `README.md` overclaimed `e2e:real-claude` as the working gate with no nuance, while the runbook, the feature doc, and the `real-claude.spec.ts` header still called send/stream red on [#449](449.md)'s isolated-HOME reply-fan-out gap — now cured (green, ~7.7s, fixed by the 2026-07-15 daemon repairs). The three specs actually red now are different (`real-claude-interrupt`, `real-claude-queue-drop`, `real-claude-permission-modal`), all on daemon bug `pyrycode#1050`. Root cause of both drifts: current gate state was copied into four places, so any state change strands the copies not touched by that change.

## What shipped

Zero production code — four docs/comment files only, mirroring the architecture spec's per-file plan exactly:

- **`docs/knowledge/features/live-e2e-runbook.md` becomes the single state owner.** New `## Current real-claude gate state` section (placed immediately before "## Automated coverage is deferred") carries the only standalone red/green claim: 2026-07-16 run, 5 passed / 3 failed, #449 send/stream cured, the three named red specs on `pyrycode#1050`. The stale #449-red paragraph, the `e2e:real:gate` tail clause, the `live-drive.mjs` "in place of the still-red harness" framing, and both cross-reference bullets were all reworded to point at this new section instead of asserting their own state.
- **`README.md` § Pre-ship gate loses the overclaim.** Names the gate commands (`npm run build`, `npm test`, `npm run e2e:real-claude`, `npm run e2e:real:gate`), keeps one mechanism sentence (real `pyry` + real `claude --model haiku` through a local content-blind fake relay, skips cleanly when a prerequisite is missing), and adds one runbook pointer. The "one net that catches the real daemon never replied" framing and the "(that is the RED this test exists to catch)" parenthetical are both gone — no red/green/#449 wording survives.
- **`docs/knowledge/features/real-claude-liveness-e2e.md` drops its three stale #449-red callouts** (a blockquote, an edge-case bullet, a Related bullet) and replaces each with a pointer to the runbook's new section. The sibling-spec capability descriptions (lines 33–60) were left untouched — they describe what the specs test, not gate state.
- **`e2e/real-claude.spec.ts` header** — the `TODO(#449) … currently RED` block is replaced with a one-line comment pointing at the runbook section. Comment-only; no behavior change.
- **`scripts/live-drive.mjs` reframed, not retired.** Both the runbook and the feature doc now describe it as the **live-RELAY** gate (built app → production relay → live daemon), a path `e2e:real-claude` never exercises (it dials a local fake relay) — complementary, not a stand-in for a red spec. #449 curing does not retire it.

## Patterns established

- **One state page, N pointers.** When a volatile fact (pass/fail state) is duplicated across files for narrative convenience, the fix is structural: pick one file as the sole owner of the claim, and make every other reference a link to a named section rather than a restated fact. The next state change then touches one file, not N. Same "push responsibility to the single owner" shape as [0007](../decisions/0007-content-free-diagnostics-by-construction.md)'s allowlist ownership.
- **Point at a named section, not a line number or raw anchor.** All three pointers reference "§ Current real-claude gate state" by name so a future heading rename doesn't silently break them.
- **A cross-file consistency doc pass is not a split candidate even at >3 files.** The ticket's own scope note (and the architect spec) treat this as the documented exception to the ">3 files" red line: per-file children would strand exactly the copies the ticket exists to unify.

## Lessons learned

*Lifted from the PR body's own "Lessons learned" section.*

- The AC5 negative grep (`grep -iE 'red|green|...'`) matches the substring inside unrelated words — `cred`ential, `structured`, `registered`, `fired`, `paired`, `cleared`, `captured` all contain `red` or a target token. An AC5 "no state claim survives outside the runbook" grep has to be read hit-by-hit for state-vs-substring, not treated as a raw pass/fail count.
