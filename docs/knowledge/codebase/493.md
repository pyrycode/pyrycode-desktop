# #493 — Api-retry indicator: render the retry status, superseding generic thinking

Render slice of the api-retry-signal vertical, split from #488, consuming the `apiRetry` `DaemonEvent`
#492 landed dormant (`e08f33d`, PR #494). Shipped as PR #497 (`3dd3919`), code-review **PASS** (zero
findings). Not security-sensitive — pure renderer, no keys/sockets/raw frames, and the transport already
type-validated the payload (#492). Size S: 8 files touched (5 production, 3 test), 0 new files — the
documented irreducible shape of a store-scalar render slice (#317's own 8-file/272-insertion precedent),
tripping the ">3 files" self-check for a structurally unsatisfiable reason (see the spec's Scope note).
Built with **zero deviation** from the architecture spec (`docs/specs/architecture/493-*.md`).

## Summary

#492 decoded the daemon's `api_retry` frame into `{ type: 'apiRetry'; active; current; total }` but
shipped it dormant — all three exhaustive renderer bridges no-op'd it. This ticket gives it a consumer:
an on-thread "API error — retrying…" status, `StallIndicator`'s structural twin (#317) with the clear
semantics **inverted**, plus the mutual-exclusion rule #317 explicitly deferred.

- **`threadTimeline.ts`** — `TimelineState` gained a fourth field, `apiRetry: ApiRetryStatus | null`
  (`ApiRetryStatus = { current: number; total: number }`), beside `items`/`phase`/`stalled`. A new
  `ThreadEvent` arm, `{ type: 'apiRetry'; active: boolean; current: number; total: number }`, is
  field-for-field identical to the `DaemonEvent` arm — the `toolUse`/`toolResult` filter-and-copy
  discipline, not `stallDetected`'s nullary arm-selection-only shape, since this event carries data.
  The reducer is the **single** place that translates the wire's edge (`active`) into the state's
  presence-or-absence (`| null`): rising edge (`active: true`) holds `{ current, total }` — a verbatim
  repeat returns the same state reference (no stacking/flicker, AC2); falling edge (`active: false`)
  sets `apiRetry: null` unconditionally, **discarding** any counter on that event — the wire's "falling
  edge repeats the last-known counter verbatim, ignored once inactive" is true by construction, since
  there is nowhere for a stale counter to leak from. `current: 0, total: 0` on a rising edge yields a
  **present** status with both fields zero (AC3: unknown count, not "no retry") — the `null`-vs-zeros
  distinction is exactly the "unknown count" vs. "no retry" distinction.
- **The reducer trap, avoided.** Every one of the nine existing arms now also carries
  `apiRetry: state.apiRetry` through unchanged (compile-forced — the field is required on
  `TimelineState`, so an omission is a type error). Critically, the two same-reference no-op guards
  `#317` widened with `&& !state.stalled` (`toolResult`'s orphan/duplicate check at `:213`, `turnState`'s
  same-phase check at `:225`) were **not** widened with an `apiRetry` clause — `api_retry` has an
  explicit wire falling edge, so turn activity arriving mid-retry must leave the status showing, the
  deliberate inverse of `stalled`'s self-clear. Copying #317's guard-widening pattern here would have
  been a silent behavioural bug; AC4's four turn-activity test cases (`assistantDelta`/`toolUse`/
  `toolResult`/`turnState`) are the tripwire.
- **`timelineStore.ts`** — one-line re-export widened to add `selectApiRetry`.
- **`timelineBridge.ts`** — `apiRetry` moved out of the null fall-through cluster into a seventh owned
  arm, a fresh four-field literal (never `return event`). `daemonEventBridge.ts`/`modalBridge.ts` keep
  no-oping it, untouched, per the spec.
- **`ConversationScreen.tsx`** — the AC5 supersede rule: a named, exported predicate
  `shouldShowThinking({ phase, apiRetry }: ThreadStatus): boolean`, returning
  `phase === 'thinking' && apiRetry === null`, narrows `ThinkingIndicator`'s existing gate rather than
  a container-derived status union — keeping `ThinkingIndicator`'s tested `isThinking: boolean` contract
  untouched and giving #496 a single-field extension seam on `ThreadStatus` (chosen over
  `isTurnRunning`'s bare positional-scalar precedent specifically because #496 is specced to extend it).
  New `ApiRetryIndicator({ retry: ApiRetryStatus | null })` — the `StallIndicator` twin, pure/exported/
  in-file/`null`-at-rest; mounted directly after `ThinkingIndicator` (its supersede peer) and before
  `StallIndicator` (the two may still co-render — AC5 scopes mutual exclusion to *thinking* only, #317's
  "distinct facts" posture for stall is unchanged). Counter shows iff `total > 0` (covers AC3's `0/0`
  omission and an undocumented `N/0`); renders two client-formatted integers, never `current / total`
  (`0/0` → `NaN`, the exact thing #492's security review routed here). `API_RETRY_COPY = 'API error —
  retrying…'` — apostrophe-free, U+2026 ellipsis (the standing desktop lesson).
- **`conversation.css`** — `.conversation__api-retry` clones `.conversation__stall`'s wrapper verbatim;
  `.bubble--api-retry` reuses `.bubble--daemon`'s fill/radius, diverges to `--color-error` text, and
  deliberately omits the left accent bar that is `.bubble--stall`'s distinguishing mark — keeping the
  two problem states visually separable from each other and both from the muted `.bubble--thinking`.

`npm test`, `npm run typecheck`, `npm run build` all green. Reducer, bridge, and render tests extended
per the spec's testing strategy, including the four turn-activity carry-through cases and the
same-reference (`toBe`) idempotency assertion for a repeated rising edge.

## Patterns established

- **A supersede rule between two render indicators is a named predicate over a record, not a
  container-derived status union.** `shouldShowThinking(ThreadStatus)` keeps both `ThinkingIndicator`
  and `ApiRetryIndicator` pure and independently unit-testable, and gives a follow-up ticket (#496) a
  single-field/single-clause extension rather than a second parallel gate. Reach for this shape whenever
  one status render is asked to occlude another rather than co-render.
- **A non-nullary status-liveness `ThreadEvent` arm mirrors its `DaemonEvent` counterpart
  field-for-field (filter-and-copy), the same discipline as `toolUse`/`toolResult` — `stallDetected`'s
  nullary arm-selection-only shape was the special case, not the template**, once the event carries
  data.
- **When a wire signal has an explicit falling edge (not a client-derived self-clear), the store must
  encode "cleared" as a value with nowhere for stale data to hide (`| null`), not a boolean flag beside
  a separately-held counter.** That structural choice is what makes "the falling edge discards the
  counter" true by construction rather than a convention to remember.

## Lessons learned

From the PR body: the reducer's two same-reference no-op guards that #317 widened with
`&& !state.stalled` were a trap for this ticket specifically — the instinct to copy that widening
pattern for the new `apiRetry` scalar had to be resisted, since `api_retry`'s clear semantics are the
deliberate inverse of `stalled`'s. Any future third problem-state scalar on `TimelineState` should ask,
per-arm, whether it clears on turn activity (join the widened guards) or only on its own explicit signal
(carry through unchanged, this ticket's shape) — it is not safe to assume the existing guard set applies.

## Open questions carried forward

- **Exact copy wording** (`API_RETRY_COPY`) was the developer's call within the spec's constraints
  (client-owned, apostrophe-free, U+2026 ellipsis, conveys both "API error" and "retrying") — not
  verified against mobile's wording, the same latitude #317 took for `STALL_COPY`.
- **`total > 0` vs. the AC's literal `current === 0 && total === 0`.** The spec picked the former (it
  subsumes the AC and additionally suppresses an undocumented `N/0`); a one-comparison change if a future
  review prefers the literal reading.
- **Retry + stall co-render** is deliberately still allowed — AC5 scopes mutual exclusion to *thinking*
  only. If the design later wants a full precedence chain, `shouldShowThinking`/`ThreadStatus` is the
  seam it extends.
- **No dedicated Figma node** — the mobile file draws only the populated steady-state thread (node
  `16-8`); a dedicated degraded-state visual is a Figma-side follow-up for Juhana, pairing naturally with
  the compaction status (#496).
- **`ThreadStatus` naming** was chosen for the extension seam #496 consumes; renaming is local to
  `ConversationScreen.tsx` and its test if #496's author finds a better name once `compacting` lands.
