# #495 — Decode the daemon `compacting` frame into a typed `compacting` event

Transport slice of the compaction-status vertical, split from #489, peer of the `api_retry` transport
(#492). Shipped as PR #498 (`93f464e`), code-review **PASS** (zero findings). Security-sensitive (adds a
wire type decoded from the relay socket, widening main→renderer IPC by one boolean); size S; a structural
clone of #492 (`e08f33d`) minus the two counter fields. **No render** — the on-thread "Compacting
conversation…" status is the sibling slice #496, blocked on this one.

## Summary

When claude auto-compacts it goes silent on the content channel for tens of seconds. The daemon detects
this and emits a `compacting` frame on the v2 interactive stream (pyrycode #1074, merged; detector
upstream tui-driver #298, closed), fanned out only to `interactive`-capable clients — desktop already
advertises `interactive`, so the frame reaches us today. Before this ticket the frame was unmodeled and
fell through `parseInboundMessage`'s `default → inbound-unmodeled → null`, which is why the window still
shows a frozen thinking state during a compaction. This ticket adds the same six thin, additive touchpoints
`stall` (#315) and `api_retry` (#492) established, scaled down to a **banner-only** payload — the wire
streams no compaction progress, so there is no counter, percentage, or elapsed time to carry.

- **Wire type** (`src/shared/wire/types.ts`) — `'compacting'` joins `EnvelopeType`, beside `'api_retry'`.
  `CompactingPayload { conversation_id: string; active: boolean }` — both fields always present, no
  `omitempty`. Doc-comment records the three contract traps: banner-only (no counter to invent — a future
  progress field is a wire change with a matching daemon peer, ADR 0002, not a client invention); explicit
  falling edge (`active: false` is compaction finished, not a client-derived self-clear), the same contrast
  with `stall` that `api_retry` already established; conversation-level, no `turn_id`, never opens/closes/
  alters a turn.
- **Inbound decode** (`inboundMessage.ts`) — `{ kind: 'compacting'; compacting: CompactingPayload }` joins
  `InboundDaemonMessage`. `parseCompactingPayload` is `parseApiRetryPayload` minus its two `requireNumber`
  lines — both remaining fields map onto existing helpers, `requireString` (`conversation_id`) and
  `requireBoolean` (`active`, a TYPE check so `false` passes). `case 'compacting'` narrows before logging,
  then emits `inbound-decoded{code:'compacting', bytes, hash}` — no decoded field logged. Returns a fresh
  two-field literal, never a spread of the incoming payload.
- **Consumer emit** (`daemonConnection.ts`) — one `case 'compacting'` in the `switch (inbound.kind)`, a
  fresh **named-field** literal `{ type: 'compacting', active: inbound.compacting.active }` copied by
  name, never a spread of `inbound.compacting` — the anti-smuggling net, same discipline as `api_retry`.
  `conversation_id` is dropped (never referenced). Deliberately stateless: no dedup, no coalescing, no
  timer, no last-value memo — a repeated same-edge frame emits its own event for free. Not compile-forced
  (this inner switch has no `assertNever` default) — the round-trip test is the guard.
- **`DaemonEvent` arm** (`src/shared/ipc/events.ts`) — `{ type: 'compacting'; active: boolean }` — the
  smallest non-nullary status-liveness arm in the file: one boolean and nothing else, since the wire gives
  the render slice #496 no counter to carry.
- **Three exhaustive bridge no-ops** — `daemonEventBridge.ts`, `timelineBridge.ts`, `modalBridge.ts` each
  add a dormant `compacting` arm, one per file's own local idiom (see § Patterns established), rather than
  one shape three times. All three are compile-forced by their `assertNever` default.

`npm test` 611/611 green on the touched files, `npm run typecheck`, `npm run build` all green. 13 files
touched (7 production, 6 test), 0 new files — the commit-time ≥5-production-file self-check trips here
but is structurally unsatisfiable for this shape (see the architecture spec's Scope note): the new
`DaemonEvent` arm compile-forces a case in all three exhaustive bridges, and the transport decode exists
only to feed that arm.

## Patterns established

- **A banner-only status frame (no progress field on the wire) still follows the six-touchpoint shape —
  only the payload shrinks, not the shape.** `stall` (#315) proved the nullary case, `api_retry` (#492)
  proved the multi-field case; `compacting` proves the shape holds even at the minimum non-nullary size
  (one bool). A future status frame that carries neither an onset-only edge nor a counter should still
  reach for this template rather than inventing a shortcut.
- **"Clone the sibling, delete the fields the wire doesn't have" is a safe reduction, not just an
  optimization.** `parseCompactingPayload` is `parseApiRetryPayload` with its two `requireNumber` lines
  removed and nothing else changed — no new helper, no new check, no cross-field validation invented to
  fill the gap. When a wire payload is a strict subset of an already-shipped sibling's, deleting lines is
  the whole task.
- **A transport slice's own architecture spec must re-verify its own ticket body's file:line anchors and
  blast-radius grep before implementation, not just before review.** The ticket body's `timelineBridge.ts`
  anchor (`case 'apiRetry' :118`) and its "13 files, empty skip-list" grep both went stale the moment
  #493 merged (which happened *after* this ticket's body was written but *before* its architecture spec).
  The spec caught both; an implementation that trusted the body verbatim would have destroyed #493's owned
  `apiRetry` arm in `timelineBridge.ts` by editing on its now-stale anchor.

## Lessons learned

- From the PR body: the ticket body's `timelineBridge.ts` clone anchor (`case 'apiRetry' :118`) was stale
  — #493 merged after the body was written and promoted `apiRetry` from a dormant label to an owned arm
  returning a `ThreadEvent`. Editing on that anchor would have destroyed #493's timeline consumer. The
  dormant label belongs after `case 'notificationActivated':`, immediately above the shared comment block.
  The generalisable rule: a transport slice's bridge anchors go stale the moment its sibling render slice
  lands, so re-read the file rather than trusting a line number from the ticket body.
- From the PR body: the body's completeness grep (`grep -rl 'apiRetry\|api_retry\|api-retry' src/` → "13
  files, empty skip-list") also drifted for the same reason — post-#493 it returns 18, with the extra 5
  being render-owned files that are #496's territory, not gaps. `grep -rl compacting src/` returns 14 after
  this change, not 13: the extra hit is a pre-existing forward-pointing comment in `ConversationScreen.tsx`
  that #493 left for #496, not a gap either. Code review independently re-derived and confirmed both
  corrected counts.
- `requireNumber`'s `Infinity`-reachability caveat (#492's lesson) does not apply here at all — this
  payload has no numeric field, so the question doesn't arise rather than being resolved. Worth noting so
  a future reader doesn't go looking for a range check that has nothing to range-check.

## Open questions carried forward

- **Inner-switch exhaustiveness.** `daemonConnection.ts`'s `switch (inbound.kind)` still has no
  `default: assertNever` — now six tickets deferred (#180, #199, #214, #315, #492, #495). The round-trip
  test remains the deterministic safety net.
- **Whether `compacting` supersedes the generic thinking indicator, and how it composes with an
  already-showing `stall` or `apiRetry` status, is entirely #496's call** — not re-litigated here. #496
  must **not** copy #317's `&& !state.stalled` guard-widening pattern: `compacting` clears on its own
  explicit falling edge, never on turn activity, the same inverse-of-`stalled` semantics `apiRetry` (#493)
  already established for itself.
- **A future daemon change adding compaction progress** is a wire change with a matching daemon peer (ADR
  0002) and a new ticket — not a client-side invention, per this ticket's own wire contract.
