## Summary

#495 decoded the daemon's `compacting` frame into `{ type: 'compacting'; active: boolean }` but shipped
it dormant — all three exhaustive renderer bridges no-op'd it. This ticket gives it a consumer: an
on-thread "Compacting the conversation…" status that supersedes the generic thinking indicator while
compaction is live — structurally #493's `ApiRetryIndicator` minus the counter, with the wire's clear
semantics diverging from `stalled` in the same direction #493 already proved.

- **`threadTimeline.ts`** — `TimelineState` gained a fourth scalar, **`compacting: boolean`** (not
  `ApiRetryStatus | null` — there is no counter to hide, so `| null` would invent a third state the wire
  cannot produce). A new `ThreadEvent` arm, `{ type: 'compacting'; active: boolean }`, is field-for-field
  identical to the `DaemonEvent` arm (the `apiRetry`/`toolUse` filter-and-copy discipline, not
  `stallDetected`'s nullary arm-selection shape). The reducer arm collapses both edges into a single
  same-reference-or-fresh-state expression — `state.compacting === event.active ? state : { …, compacting:
  event.active }` — genuinely simpler than `apiRetry`'s two-branch body because there is no counter to
  compare; idempotent by construction on a verbatim repeat of **either** edge. Every other arm carries
  `compacting: state.compacting` through unchanged (compile-forced — the field is required, so an
  omission is a type error). `items` and `phase` are untouched on every path: compaction is chrome, it
  neither opens, closes, nor alters a turn.
- **The reducer trap, avoided a second time.** The two same-reference no-op guards #317 widened with
  `&& !state.stalled` (`toolResult`'s orphan/duplicate check, `turnState`'s same-phase check) did **not**
  gain a compaction term — `compacting` clears only on its own explicit falling edge, the deliberate
  inverse of `stalled`'s turn-activity self-clear, the same posture #493 already established for
  `apiRetry`. Six turn-activity cases (`assistantDelta`/`toolUse`/orphan `toolResult`/filling
  `toolResult`/non-idle `turnState`/idle `turnState`) cover the tripwire positively; the three existing
  `.toBe(initialTimelineState)` churn-discipline assertions stayed green.
- **`timelineStore.ts`** — one-line re-export widened to add `selectCompacting`. No other change:
  `createTimelineStore`'s `init: TimelineState = initialTimelineState` default absorbs the new field —
  cross-file forced fan-out was **0**, verified by grepping every `TimelineState` occurrence in `src/`
  and `e2e/` (no object literal of that type exists outside `initialTimelineState`).
- **`timelineBridge.ts`** — `compacting` moved out of the null fall-through cluster into a **ninth**
  owned arm, directly after `apiRetry`'s (`:92-103`), returning a fresh `{ type: 'compacting', active }`
  literal (never `return event`). `daemonEventBridge.ts` and `modalBridge.ts` keep no-oping it,
  untouched, per the spec — only `timelineBridge` gained a consumer.
- **`ConversationScreen.tsx`** — the supersede seam #493 built by name for this ticket: `ThreadStatus`
  gained one field (`compacting: boolean`), `shouldShowThinking` gained one clause
  (`&& !status.compacting`) — a one-field, one-clause extension, not a second parallel gate or a
  container-derived mutually-exclusive status union. `ThreadStatus` was **not** renamed (#493 flagged it
  as fair game; the name still fits a record of thread-chrome scalars, and renaming buys zero behaviour
  for two files of edits). New `CompactingIndicator({ isCompacting: boolean })` — `StallIndicator`'s
  structural twin, taking a boolean (not the store type or a record) since there are no digits to render,
  which makes AC1's "no daemon-supplied string is ever rendered" a type-level guarantee. `false` → `null`
  (zero footprint); `true` → `<div className="conversation__compacting"><div className="bubble
  bubble--daemon bubble--compacting">Compacting the conversation…</div></div>`. `COMPACTING_COPY` is a
  module-level, exported, client-owned constant — apostrophe-free (the `renderToStaticMarkup` `&#x27;`
  lesson), U+2026 ellipsis, asserted distinct from `'Thinking…'`/`STALL_COPY`/`API_RETRY_COPY`. Mounted
  directly after `ApiRetryIndicator` and before `StallIndicator` — grouping the two thinking-superseders
  (#493, #496) contiguously below the indicator they occlude, leaving `StallIndicator` (the non-superseding,
  co-rendering fact) last. AC4's exclusion is scoped to `ThinkingIndicator` only — compaction may still
  co-render with stall and retry, #493's posture unchanged.
- **`conversation.css`** — two rules appended after `.api-retry__counter`, both after `.bubble--daemon`
  in source order (equal specificity, so source order decides — the `.bubble--api-retry` invariant
  preserved). `.conversation__compacting` clones `.conversation__api-retry`'s wrapper verbatim.
  `.bubble--compacting` deliberately does **not** reach for `--color-error` — both `.bubble--stall` and
  `.bubble--api-retry` use it because both signal a degrading session, but compaction is claude working
  normally. Instead: muted text (`--color-on-surface-variant`, the `.bubble--thinking` treatment) plus a
  leading accent bar in the **primary** role (`--color-primary`, `.bubble--stall`'s bar structure with
  the error role swapped out). That completes a fully separable four-way matrix on two axes (text role ×
  left accent bar): thinking = muted/no-bar, stall = error/error-bar, retry = error/no-bar, compacting =
  muted/primary-bar. No new design token.

## Patterns established

- **A pure-liveness wire scalar with an explicit falling edge is a plain `boolean` on `TimelineState`,
  not a `| null` record.** `apiRetry`'s `| null` shape existed only to make "the falling edge discards
  the counter" true by construction; with no counter to hide, `boolean | null` would invent a third state
  the wire cannot produce. Reach for the record shape only when there is data to discard on clear.
- **A same-reference-or-fresh-state reducer arm can collapse to a single ternary when the state is
  exactly the event's payload** (`state.field === event.active ? state : {…}`) — simpler than a
  two-branch rising/falling split, and only available once there's no auxiliary data (like a counter) to
  carry across the edge.
- **The `shouldShowThinking(ThreadStatus)` supersede seam (#493) is now proven twice**: a second
  problem-state scalar extended it by exactly one field and one clause, with zero new gates. This is the
  seam to reach for whenever a future status is asked to occlude the thinking indicator specifically,
  rather than co-render as an independent fact.
- **The four-way CSS matrix (text role × left accent bar) is now saturated** — every cell distinct,
  no color literal, no new token. A fifth transient status needs a third visual axis (or a real design
  pass) to stay distinguishable; it cannot be added by picking a fourth text/bar combination.

## Lessons learned

From the PR body:

- **Fixture ordering bites when two scalars have opposite clear semantics.** An independence test built
  as `run([stall(), apiRetry(...), turnState('thinking')])` fails on its own setup, because the trailing
  `turnState` is turn activity and clears the stall before the assertion runs. A stall has to go **last**
  in any fixture that needs it live — the same fixture shape reads as correct until the assertion
  disagrees. Worth checking fixture order first the next time a mixed-clear-semantics test fails
  mysteriously.
- **The four-way indicator matrix (thinking / stall / api-retry / compaction) is now saturated on two
  axes only** — text role and left accent bar. `.bubble--compacting` took the last free cell (muted text
  + primary bar). A fifth transient status cannot be made distinct without a third visual axis, or the
  Figma-side transient-status pass #317/#493/#496 have all deferred.

From code review (the one NIT, non-gating): `timelineBridge.test.ts:35`'s describe title `'the two owned
arms'` now covers nine and is stale (accurate at #202, drifted since #217/#229/#286/#317/#493, this
ticket correctly bumped the source-side sibling-count docstring but not the test title) — left for the
next toucher of that file, not worth a rework cycle.

## Open questions carried forward

- **Exact `COMPACTING_COPY` wording** was the developer's call within the spec's constraints
  (client-owned, apostrophe-free, U+2026 ellipsis, reads as work-in-progress-on-the-conversation-itself
  rather than an error or ordinary thinking) — `'Compacting the conversation…'`, not verified against
  mobile's wording, the same latitude `STALL_COPY`/`API_RETRY_COPY` both took.
- **Accent-bar-in-primary vs. another non-error distinguisher.** `--color-tertiary` and
  `--color-outline-variant` remain alternatives if a later visual pass prefers a softer mark — a
  one-token change in one CSS rule.
- **A full precedence chain among thinking/stall/retry/compacting** — AC4 scopes exclusion to the
  thinking indicator only, so the other three may all co-render as stacked rows, the deliberate #493
  posture carried forward again. If the design later wants strict precedence, `shouldShowThinking`/
  `ThreadStatus` is the seam it extends — this ticket is the second proof that the seam grows by one
  field and one clause, and the CSS matrix note above is the reason a plain fourth cell won't serve a
  fifth status.
- **No `aria-live` on any of the four indicators** — a screen reader is not announced when any of
  thinking/stall/retry/compacting appears. House-wide accessibility follow-up, explicitly not a gate on
  this ticket (fixing it here would touch three components this slice otherwise leaves alone).
- **No dedicated Figma node** — the mobile file draws only the populated steady-state thread (node
  `16-8`); a dedicated transient-status visual remains a Figma-side follow-up for Juhana, the same
  request #317/#493 both carried forward.
