# #5 — Wire codec (encode and decode)

**Shipped:** 2026-07-03 · **Size:** S · **Scope:** background transport only (`src/main/transport/`) · greenfield module, zero consumer cascade · no new dependency (Node `Buffer` + `TextEncoder`/`TextDecoder`, already available). `security-sensitive`.
**Spec:** `docs/specs/architecture/5-wire-codec.md` (rev 2) · **PR:** [#26](https://github.com/pyrycode/pyrycode-desktop/pull/26) (review: rev-1 **FAIL** on placement → relocate → rev-2 **PASS**, no MUST/SHOULD findings, 2 NITs).

The **serialization foundation** for the Phase 1 connect–send–stream round-trip: `base64StdEncode`/`base64StdDecode` + `encodeInnerFrame`/`decodeInnerFrame` + `encodeEnvelope`/`decodeEnvelope` + `makeHelloClientPayload` + `WireDecodeError` — turning the shared wire types into, and back from, the daemon's on-the-wire bytes **byte-identical to pyrycode-mobile**. Encode is total; the two `decode*` functions are the network trust boundary and **fail closed** with a single catchable `WireDecodeError`. `Envelope.payload` stays opaque (`unknown`), narrowed by consumers at their edge. See the [wire-codec feature doc](../features/wire-codec.md) for the full contract, the two byte boundaries, and the security posture.

Sits on top of the [relay connection](../features/relay-connection.md) (#21, opaque byte pipe) and under the Noise session (#7), which encrypts the Envelope bytes this codec produces and base64-wraps the resulting Noise bytes into an `InnerFrameV2.data`. This ticket adds **only** the encode/decode; the wire *types* already existed (#21 foundation, `src/shared/wire/types.ts`). No consumer wiring, no UI.

## Patterns established

The template for the transport's serialization layer and the security-sensitive-module placement rule:

- **Structural renderer isolation via placement, not convention.** A `security-sensitive` module that handles the device `token` + message plaintext + Node `Buffer` lives under `src/main/transport/`, so the renderer bundle **physically cannot import it**. This is the load-bearing control — the deterministic (belt-and-suspenders) alternative to the rev-1 placement under `src/shared/wire/`, where isolation rested on the *convention* "don't add a barrel" plus the incidental fact that `Buffer` would break the renderer build. **Rule for future transport/secret-handling modules: place them in `src/main/**`; keep renderer-imported types in `src/shared/` and `Buffer`-free.** This is the same control #21 established (log-free by construction) applied to placement.
- **Thin serializer, no per-payload wrappers.** One configured JSON (de)serializer + base64-std helpers, mirroring mobile's `MobileWireCodec`. `Envelope.payload` stays an opaque `unknown` carrier — decoded but never narrowed here; consumers (#7 and later) validate at their edge. There is **no** `decodePayload<T>` and **no** function-per-payload-type. Resist inflating this surface — every export is part of the #7 consumer contract.
- **Literal types enforce defaults for free; one constructor for the rest.** `InnerFrameV2.v: 2` and `HelloClientPayload.role: 'client'` are literal types — the type system forbids constructing the object without them, so `JSON.stringify` always emits them, **no runtime injector**. Only the non-literal defaults (`protocol_versions`, `capabilities`) need injection, and `HelloClientPayload` is the sole encode-side payload that has them → `makeHelloClientPayload` is **one** constructor, not a per-payload wrapper. Reuse the `PROTOCOL_VERSION`/`CAPABILITY_INTERACTIVE` constants from `types.ts`.
- **Omit-absent-optionals via `number \| undefined`, never `\| null`.** `JSON.stringify` drops `undefined` keys but serializes `null`, so the type must forbid `null` on optionals. Dropping `\| null` makes "absent" the only representation and satisfies AC #3 ("never serialized as null") with **zero runtime scrub**. Faithful to mobile's `explicitNulls = false` (`Long? = null` ≡ `number \| undefined`); zero edit fan-out. Guard optional reads with `typeof … === 'number'` on decode and `input.x !== undefined` on construct (preserves a legitimate `0`).
- **Decode fails closed with one `WireDecodeError`; category-only messages; zero logging.** Every boundary failure — malformed base64/UTF-8/JSON, non-object top level, missing/mistyped required field — throws the single catchable `WireDecodeError`, never a partial value. Messages name the **failure category only** and never echo raw bytes or decoded values (they carry `token`/plaintext); the module has no `console.*`. Narrowing is via `typeof` guards — no `any`, no unchecked `as`, no non-null `!` in production.
- **Strict base64 as a canonical-form check (see Lessons).** `base64StdDecode` = lenient-decode then require `base64StdEncode(decoded) === input`. One comparison; no regex.

## Lessons learned

*Lifted from the PR body's "Lessons learned" (rev 1) + the rev-2 rework comment, reconciled to what shipped (rev 2).*

- **Node's `Buffer.from(s, 'base64')` is lenient on four axes** — it strips non-alphabet chars, accepts url-safe `-`/`_`, tolerates wrong length, and accepts non-canonical final quanta (`'YQ==garbage'` → only `'YQ=='` with no error; `'YR=='` → the same byte as `'YQ=='`). Any of those lets a malformed frame decode to a silently-truncated or off-contract value. The cleanest strict-decode in Node is a **canonical-form check**: lenient-decode, then require `base64StdEncode(decoded) === input`. Node's encoder emits only canonical output, so this **one comparison subsumes** alphabet + length + padding + final-quantum validation — it replaced the rev-1 regex-plus-length approach, which itself missed the non-canonical-quantum case (`'YR=='`) that Go's `base64.StdEncoding` rejects. Go/mobile parity, provably.
- **Renderer isolation of a `src/shared/` file rests on the import graph, not the type system — which is exactly why the codec had to move to `src/main/`.** A `Buffer`-using file under `src/shared/` still **type-checks** under the web tsconfig (both configs glob `src/shared/**` with `types: ["node"]`); it stays out of the renderer *bundle* only because no renderer module imports it. So renderer isolation of a shared file is a *convention* ("no barrel re-export"), verifiable only by grepping the built `out/renderer` bundle. Rev 1 shipped there and passed that grep — but the code review FAILed it: for a token-handling module the safety net must be **structure** (placement in `src/main/**`, where a renderer import is impossible), not a convention a future refactor can undo. Rev 2 relocated it with `git mv`; the grep now holds *for free*. **Takeaway: put the deterministic control (placement) under a security-sensitive module, not a stochastic one (a convention).**
- **`decodeInnerFrame` intentionally discards the inbound `v`.** It tolerates any numeric `v` (do not hard-reject a future version) but returns the literal `{ v: 2, … }` to satisfy `InnerFrameV2.v: 2`. The inbound version is deliberately not preserved — noted so a future maintainer doesn't mistake it for a bug (code-review NIT).

## Deferred (open questions carried forward)

- **Golden byte-fixtures from a live mobile encode.** Test fixtures are transcribed from the spec's wire-field-contract table (itself from the Kotlin models), not captured from a real `pyrycode-mobile` encode. Sufficient here; when the mobile repo is co-located, one captured golden payload per type would additionally guard against silent field-name/order drift (code-review NIT, optional).
- **`QrPayload.server_static_pubkey` → validated-32-raw-bytes.** In scope only as a plain-JSON round-trip; the base64→32-byte-key decode is a **pairing** concern deferred to the QR/pairing ticket.
- **Prototype-pollution reviver.** Not added — `JSON.parse` is pollution-safe on its own and the codec has no merge sink; no wire field is named `__proto__`/`constructor`/`prototype`. The control is the documented consumer obligation: do not naïve-deep-merge the opaque `payload`. Revisit only on an observed failure.
- **Frame-size cap** stays owned upstream by [`relayConnection`'s `maxFrameBytes`](../features/relay-connection.md) (1 MiB); the codec assumes bounded input and adds none of its own.
