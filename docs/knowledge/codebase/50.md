# #50 — Drive the Noise session from the relay supervisor

**Shipped:** 2026-07-04 · **Size:** S · **Labels:** `security-sensitive` · **Scope:** background transport only (`src/main/transport/`) · greenfield leaf module, zero consumer cascade · **no new dependency**.
**Spec:** `docs/specs/architecture/50-drive-noise-session-from-relay-supervisor.md` · **PR:** [#58](https://github.com/pyrycode/pyrycode-desktop/pull/58) (review: **PASS**, no MUST/SHOULD/NIT findings).

The **composition adapter** that ties the transport layer together: `createNoiseRelayDriver` sits between the [#22 supervisor](22.md) (a self-healing byte-pipe with opaque frames) and the [#7 Noise session](7.md) (a handshake+AEAD unit that knows nothing of the socket), starting a **fresh** handshake on every `(re)connect` and carrying frames through the [#5 codec](5.md). It is the "**future Noise-handshake layer**" the #22 doc named as its consumer, and the last transport-layer wiring before the renderer-facing session store (#17/#18/#19) can be fed. See the [noise-relay-driver feature doc](../features/noise-relay-driver.md) for the full contract, the generation model, the data flow, and the security properties.

**No new crypto.** It composes three proven primitives **unchanged** — the #22 supervisor, the #7 session, and the #5 codec — consumed by import only. This ticket productionizes the [#30 spike](30.md)'s `runLive` adapter shape (relay `connected` → `start()`, `message` → decode → `onFrame`, `sendFrame` → `noise_init`/`noise_msg` wrap) over the #22 supervisor, adding the one thing single-shot didn't need: **re-handshake-per-connect with no leaked state**.

## Patterns established

- **The generation counter fences a synchronous event stream against an async factory.** Supervisor events (`connected`/`message`/`terminal`) are synchronous, but `createNoiseSession` is a promise. A `let generation` bumped on every `connected`/`terminal`/`stop`, captured by each session and each per-connection closure, is the whole concurrency model: a stale in-flight `createSession` that resolves after a superseding event sees `gen !== generation`, `close()`s itself **before** `start()`, and no-ops. This is the reusable shape for any adapter that drives an async-constructed unit from a synchronous upstream — check-then-act across the `await` is closed by the gen-guard on **both** `.then` and `.catch`.
- **Single-live-session + fresh-handshake-per-connect is enforced structurally, and it is the nonce-freshness guard.** Close-old-on-`connected` + the gen guard guarantee exactly one live session; because no cipher/`firstFrame`/pending state survives a `connected`, every reconnect is a fresh ephemeral → no `(key, nonce)` reuse across connections (v2 has no session resume). The AC4 "re-handshake, no leaked state" test is therefore both the correctness check and the security invariant.
- **Belt-and-suspenders with different fabric.** Two independent layers stop a superseded session from sending under a stale key: *belt* — a superseded session is `close()`d before `start()` runs, so it never sends a spurious `noise_init`; *suspenders* — the outbound `sendFrame` gen-guard deterministically drops any write a somehow-started stale session emits. Both are deterministic code, not a second stochastic check.
- **Classify-don't-forward at every boundary; the driver classifies, the consumer sets policy.** Each `catch` maps to a static `RelaySessionErrorReason` and **drops** the caught object (a codec/wasm message can echo transcript bytes). The session's `sendFrame` contract forbids throwing back into it, so codec/`supervisor.send` throws are caught in the outbound wrap and surfaced as `outbound-frame-encode-failed`. The driver never decides whether an `error` tears down — it forwards both `error` and `terminal` and lets the consumer act (inherited #5/#7/#22/#30).
- **The inbound inner-`type` label is deliberately not branched on.** `noise_init` vs `noise_msg` on an *inbound* frame is never inspected — the session state machine (`awaiting-handshake-reply` vs `transport`) plus Noise AEAD decide interpretation, so a hostile relay's spoofed `type` cannot misroute. Tagging happens only on the *outbound* side (the per-connection `firstFrame` flag).
- **One teardown path via the supervisor's terminal.** `stop()` → `supervisor.stop()` → synchronous `terminal{1000,'stopped'}` → the driver's single `terminal` handler (close session, emit terminal). No duplicate teardown; idempotent via the supervisor's terminal-emitted-once guard. `NoiseSessionEvent ⊆ RelaySessionEvent`, so session events pass through the sink unchanged.

## Lessons learned

*Lifted from the PR body's "Lessons learned" section.*

- **The generation guard needs both `.then` and `.catch` fenced.** A stale in-flight `createSession` that resolves after a superseding `connected`/`terminal`/`stop` closes itself and no-ops; the same guard on `.catch` stops a stale rejection from surfacing a spurious `session-load-failed`. Fencing only the resolve path leaks the reject path (covered by the "drops a session-load-failed error when the generation has already moved on" test).
- **`firstFrame` must be re-scoped per connection, not a driver-lived field.** A closure-local `let firstFrame = true` created **inside** the `connected` handler resets `noise_init`↔`noise_msg` on every reconnect with no shared mutable state — the correct re-scoping of the #30 spike's module-level `firstOut`. A driver-lived flag would tag the second connection's message 1 as `noise_msg` and break the re-handshake.
- **`MAX_PENDING_FRAMES` set to `8`** (the architect's proposed value). The happy path never buffers — the daemon stays silent until it receives message 1 — so the cap only bounds an anomalous/hostile pre-session flood during the async-create gap. Any small constant works; the value only needs to be a bound, not tuned.

## Deferred / carried forward

- **Renderer-facing wiring.** Nothing constructs the driver yet; `src/main/index.ts` stays untouched. The consumer that owns the sink and bridges it to the renderer session store — over the [#18](../features/daemon-event-channel.md) daemon-event channel + [#17](../features/command-channel.md) command channel + [#19](../features/daemon-event-bridge.md) translation — is a later ticket.
- **Key / `hello` sourcing.** The `staticPrivateKey`/`remoteStaticPublicKey`/`prologue`/`hello` are injected fakes in tests; production sourcing is [#42](42.md) (`safeStorage`) / [#43](43.md) (device static keypair) / #10 (hello/pairing envelope). The driver is self-contained and unit-testable without those landing.
- **Deferred vs immediate connect.** The driver dials on construction (supervisor idiom). If the consumer needs an explicit `start()` to control *when* dialing begins, construct the supervisor lazily in a `start()` method — a trivial future change, flagged in the spec's open questions.
- **No visible "reconnecting…" state.** Transient drops are absorbed by the supervisor and surface as nothing; when the UI needs a reconnecting indicator, it rides the #22-deferred `{ type: 'disconnected' }` supervisor member, then a matching sink member here.
