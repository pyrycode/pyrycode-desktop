## What it does

`sendNoise`, the single outbound chokepoint in `fakeDaemon.ts`, hardcoded `type: 'noise_msg'` on **every** outbound frame — including the three IK handshake replies (initial msg2, rekey msg2, reconnect msg2). The real daemon marshals those three as `TypeNoiseResp` (`internal/relay/v2session_handshake.go:241`, `v2session_rekey.go:146`); only transport frames and the `rekey_request` control envelope carry `TypeNoiseMsg`. Today the drift is invisible — `noiseRelayDriver.onMessage` decodes the inbound frame and keeps only `.data`, discarding `type` entirely — which is exactly why this was cheap to fix now: retagging is behaviour-preserving, no consumer needs editing. #524's review flagged this as the one remaining pre-existing gap in the fake's outbound fidelity; this ticket closes it, ahead of **#507** (the client-side rekey-desync fix), which is expected to start reading the inbound tag.

## What shipped

**`sendNoise` gains a defaulted tag parameter.** `function sendNoise(raw: Uint8Array, type: OutboundInnerType = 'noise_msg')`, where `OutboundInnerType = 'noise_resp' | 'noise_msg'` is a module-local alias — the only compile-time backstop against a typo, since `InnerFrameV2.type` is a bare `string`. `sendNoise` stays pure framing (the AEAD seal always happens at the call site) and synchronous/unbuffered (`handleRekeyInit`'s msg2-then-resume and `handleReconnect`'s msg2-then-resends are ordering-critical). Exactly three call sites pass `'noise_resp'` — `handleMsg1`, `handleRekeyInit`'s reply, `handleReconnect`'s msg2 — and five are left untouched, picking up `noise_msg` from the default: `initiateRekey`'s `rekey_request`, `handleRekeyInit`'s resume frame, `handleReconnect`'s resends, `handleTransport`'s replies, `pushFrame`.

**Why a default, not a required parameter.** A required second argument would make "forgot to tag" a compile error for any future handshake site — a real structural gain — but costs five one-token edits at sites the ticket explicitly ring-fences as untouched, widening a behaviour-preserving diff. The residual risk is bounded: a future handshake site that forgets the tag ships `noise_msg`, and once the client distinguishes the two types that frame fails AEAD and the session fails closed rather than silently downgrading. Flagged in the spec as a trade-off for review to record, not re-litigate — code review did exactly that (see § Deferred).

**The test-side oracle — there is no behavioural one.** `driveClient` gains a passive tap, `peekInnerType`, wired into the relay's `message` handler **above** the existing `#524` hold gate so a withheld frame is still recorded. It is total by construction (a throw would break the relay's event dispatch and hang unrelated tests) and returns a static `'undecodable'` placeholder on a decode failure, recording the `type` string only — never `.data` (the sealed transcript). The harness exposes the result as `inboundTypes: string[]`, and the three existing tests that already reach all eight outbound sites (round-trip, rekey, reconnect) assert the **whole array** with `toEqual` — ordered equality pins both directions at once, so a handshake site regressing to `noise_msg` and a transport site wrongly becoming `noise_resp` fail the same assertion.

**Comment blocks moved with the invariant.** The module header's outbound-tagging claim and the `sendNoise` comment were both rewritten to state the split and cite the real daemon as authority; the four comments naming `noise_msg` for transport-class frames only were left untouched, as the spec required.

**Non-vacuity, run in both directions before the PR opened:** a positive control (the assertions are red against the unchanged fake — 3 tests fail, each on a handshake-reply element) and mutation checks for all three retag sites plus a reverse-direction mutation (flipping `pushFrame` to `'noise_resp'` kills the reconnect test at `first.inboundTypes`), confirming the whole-array assertion catches a transport site wrongly becoming a handshake tag, not just the forward direction.

## Patterns established

- **A defaulted parameter is the right shape when the ticket's constraint is "don't touch the other N call sites,"** but it trades away the compile-time backstop for future sites. A narrow module-local type alias (`OutboundInnerType` here) recovers part of that even though the underlying wire field stays a bare `string`.
- **When a production change is invisible to every consumer, the mutation check must run in both directions.** A forward-only check (does a handshake site regressing to the default get caught?) is not sufficient — the assertion must also fail if a non-handshake site is mistakenly upgraded. Whole-array `toEqual`, not per-index assertions, is what buys this for free.
- **Placing an observation tap *above* an existing gate, not beside it, matters.** `driveClient`'s `#524` hold gate returns early; a tap wired in below it would silently skip every withheld frame and under-report the arrival sequence.

## Lessons learned

*Lifted from the PR body's "Lessons learned" section.*

- A defaulted parameter is the right shape when a ticket's constraint is "don't touch the other N call sites", but it silently trades away the compile-time backstop for future sites — the module-local `OutboundInnerType` alias recovers part of that only because `InnerFrameV2.type` is otherwise a bare `string`.
- When the production change is invisible to every consumer, the mutation check has to run in *both* directions — a forward-only check passes just as happily against an assertion that only pins index 0.
- Placing the observation tap *above* an existing gate rather than beside it matters: a tap below `driveClient`'s hold gate would silently skip every withheld frame and under-report the arrival sequence.

## Deferred / carried forward

Code review passed (0 MUST, 1 SHOULD FIX — under the three-finding rework gate) but the SHOULD FIX was not applied; comment-accuracy only, not behavior:

- **Three cross-reference comments in `fakeDaemon.test.ts` (at `:539`, `:547`, `:585`) now point 22–26 lines off their targets in `fakeDaemon.ts`.** They were already stale by +11 on `main` from #524's own self-inflicted header-expansion drift (see [524.md](524.md)'s § Deferred); this PR's production hunks add a further +14 to every anchor past line 264 (header +7, the `OutboundInnerType` block +4, the `sendNoise` comment +3), compounding the drift rather than introducing it fresh. The fix is mechanical (add 14 to each) and was flagged as a non-blocking follow-up rather than a rework cycle — this repo's memory already tracks self-inflicted anchor drift as a recurring failure mode (now an 8th sighting).
- **Pre-existing, out of scope per the ticket body:** the real daemon treats an *inbound* `noise_resp` from a client as a protocol violation and closes the session (`v2session.go:669-676`); this fake still accepts one as an ordinary transport frame. The fake is lax in the same direction as the client here too, so a client bug that emitted `noise_resp` would pass CI silently — the same shape #524 hit with `driveClient`'s outbound mis-tagging. Recorded by the architect as a PO follow-up ticket, not this ticket's to fix.
