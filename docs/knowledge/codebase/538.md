# #538 — a `reconnected` arm: reconcile the timeline's transient chrome on reconnect

PR #541 (`b771775`, spec `14609cb`). Split from [#509](https://github.com/pyrycode/pyrycode-desktop/issues/509)
(sibling: [#539](https://github.com/pyrycode/pyrycode-desktop/issues/539), pending settings reconcile).
Size XS, as estimated: 2 production files, zero forced call sites (`ThreadEvent` is switched over in
exactly one place, `reduceTimeline`, under `assertNever`). Not security-sensitive. Code review: **PASS**,
0 blocking, 3 NITs (none changed the implementation).

## Summary

`apiRetry` and `compacting` are two-edged `TimelineState` scalars cleared only by their own explicit wire
falling edge — turn activity deliberately carries both through unchanged. Lose the falling edge to a
disconnect (the daemon emits it while the client is offline) and the banner sticks until the app
restarts; `phase`/`stalled` self-heal on the next turn, these two never did. `timelineBridge.ts` also
mapped the `connected` daemon edge into the null fall-through cluster, so the reducer never observed a
reconnect at all.

This is `docs/protocol-mobile.md` § Reconnect / Backfill's Mode B contract (control state resets and
rebuilds from whatever the daemon re-asserts on a fresh handshake), applied to the timeline the way
[`modalStore` already did it in #415](415.md) and `queueStore` in #197. Two production edits, both
additive:

- **`threadTimeline.ts`** — a new nullary `{ type: 'reconnected' }` `ThreadEvent` arm (the second
  non-content arm, after [`reset` #528](528.md)) and a `case 'reconnected'` placed directly after
  `case 'reset'`. Clears `phase`→`'idle'`, `stalled`→`false`, `apiRetry`→`null`, `compacting`→`false` as
  a **hand-written five-field literal**, not `{ ...initialTimelineState, items: state.items }` — the
  explicit literal makes a future sixth `TimelineState` field a compile error in this arm, forcing
  whoever adds it to classify it as Mode A (preserve) or Mode B (clear) rather than getting cleared for
  free. `items` is preserved **by reference** (`items: state.items`). Early-outs to the same `state`
  reference when all four are already clean, so a first connect or a reconnect with nothing live churns
  no subscriber.
- **`timelineBridge.ts`** — `connected` moves out of the null cluster into its own owned case (placed
  before the cluster opens, the `modalBridge.ts:61` shape), returning a payload-free `{ type:
  'reconnected' }` and ignoring `event.ack` (`HelloAckPayload`). The arm-count doc comment corrected
  ten → eleven; the null-cluster comment gained the promoted-arm parenthetical the file already uses
  per arm. `daemonEventBridge.ts` and `sessionStore.ts` are untouched — independent consumers of the
  same `connected` edge, not centralised (AC4).

**Accepted residual, not engineered around:** the daemon's connect-time re-assertion set is the
outstanding modal (#877) and the queued backlog (#878) only — never `api_retry`/`compacting`/
`turn_state`. A retry or compaction still genuinely live across the reconnect shows no banner until the
daemon's next edge. A briefly-missing banner beats a permanently-stuck one.

9 new vitest cases (7 reducer, 2 bridge) — clears all four scalars from a fully-dirty state; `items`
survives `toBe` the same reference (the load-bearing assertion, not `toEqual`); same-reference on
already-clean chrome, both from `initialTimelineState` and from a state dirty only on `items`; idempotent
on a second `reconnected`; a rising edge after the clear sets the status again for both `apiRetry` and
**`compacting`** (the one with teeth — `compacting`'s arm early-outs on `state.compacting ===
event.active`, so a clear that never landed would swallow the re-assert as a same-reference no-op, wrong
in the *other* direction); a live mid-turn transcript delta is untouched by the clear; distinct from
`reset` (keeps `items`, never returns `initialTimelineState`). Bridge: `connected` → payload-free
`reconnected` (fresh literal, not `event`); the `:223` null-cluster pin's `ack` fixture updated with a
placeholder comment, the `modalBridge.test.ts:95` precedent. `npx vitest run` — RED 9 → GREEN 123;
`npm run build` clean.

## Patterns established

- **A hand-written literal beats a spread when "for free" could clear the wrong thing.** `reset` (#528)
  returns the shared `initialTimelineState` constant deliberately — it clears *everything*, so "for
  free" is correct there. `reconnected` clears only the Mode B chrome slice while a Mode A field
  (`items`) must survive, so the file's existing "every arm writes all five fields as an explicit
  literal" idiom is the right default here, not the exception: a future field is only safe to clear "for
  free" when the arm's job is a full wipe.
- **The "rising edge after the clear" test is only proof if the arm being tested early-outs on an
  equality check.** `apiRetry`'s version of this test (AC5) passes even if the clear silently failed,
  because its arm doesn't gate on `state.apiRetry === event value`. `compacting`'s does
  (`state.compacting === event.active`), so that's the assertion that actually has teeth — write the
  data-carrying scalar's version of a "does the clear really land" test on the boolean-liveness-flag
  scalar whose arm early-outs on equality, not on the one that doesn't.
- **This is the third `connected`-edge reconcile arm shape** ([`modalPrompts.ts` #415](415.md),
  `queueStore` #197, now `threadTimeline.ts` #538) — bare event in, one slice cleared, everything else
  spread/preserved through, same-reference early-out. A future slice needing the same Mode B
  reconcile-on-reconnect treatment should copy this shape directly rather than re-deriving it.

## Lessons learned

*(from the PR body)*

- Removing an arm from a bridge's null-cluster pin can strand its fixture: `ack`
  (`timelineBridge.test.ts:15`) was referenced at the `:223` line being deleted and nowhere else in the
  file, and `noUnusedLocals` is off — the strand would have compiled silently with no build failure to
  catch it. Pairing the removal with the positive `connected` → `reconnected` test (which AC4 required
  anyway) kept the fixture live.
- For a two-edged scalar whose reducer arm early-outs on `state.x === event.active` (`compacting`), the
  "a rising edge after the clear still sets it" test is the one with teeth — see § Patterns established
  above.

*(from code review, cosmetic — not applied, left as-is)* The `timelineBridge.ts:130-131` comment inherits
AC4's wording ("a third consumer") verbatim, but by the reviewer's count `connected` already had **three**
renderer subscribers before this ticket — `modalBridge.ts:61` (#415) and `queueBridge.ts:56` (#197), the
two precedents this slice explicitly copies, plus `daemonEventBridge.ts:31` — making `threadTimeline.ts`
the **fourth**, not the third; `sessionStore.ts:113` reduces what `daemonEventBridge` dispatches rather
than subscribing to `connected` independently. The load-bearing half of the comment ("this is not a
centralisation") is correct regardless, so review judged the miscount cosmetic and non-blocking. Worth
knowing before quoting this ticket's own consumer count elsewhere — grep `case 'connected'` rather than
trusting the comment.
