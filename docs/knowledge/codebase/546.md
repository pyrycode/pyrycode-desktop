# #546 — delete the retired `electronApp.ts` e2e fixture

Landed as one commit (`babf769`) inside the bundled PR#557 ("Test-integrity pass: zero-test gate,
retired fixture, and an untrue invariant comment", #547/#546/#516) — three small independent Inbox
items, one commit each, no individual architecture spec. Recorded here retroactively by
[#517](517.md)'s documentation pass, which found the gap while correcting
[e2e-harness.md](../features/e2e-harness.md)'s stale description of this fixture as current.

## Summary

`e2e/fixtures/electronApp.ts` — the harness's original scenario-agnostic launch/teardown primitive
(`electronApp`/`page`, `args: ['.']`, no `--user-data-dir` isolation) — had zero importers. Its own
header still called it "the primitive that follow-up e2e scenarios import", but every scenario since
[#105](105.md) launches through `launchPairedApp.ts` or `realDaemon.ts` instead, both of which add
`--user-data-dir` isolation this fixture never had. #105's spec had said **DO NOT DELETE**, preserving
it for #40 and #93; both shipped without it and are closed. Verified before deleting: 26 specs use the
two replacement fixtures, and no file imports `electronApp.ts` — the only remaining textual mentions
were comments explaining why it is *not* used, plus one unrelated local variable of the same name.

Deleted the file outright (44 lines) rather than leaving it as dead code advertising a contract it no
longer holds. The superseding #105 spec note was updated in place — reason plus the original rule kept
for the trail — rather than removed.

## Patterns established

- **A "DO NOT DELETE" note in a spec is a claim about live consumers, not a permanent rule.** It's
  correct to revisit once every consumer it was protecting has shipped and closed — but only after
  checking for zero importers, not on inference.
- No production/test code changed; `npm test`/`npm run e2e`/`npm run e2e:real-claude` were unaffected
  by the deletion (confirmed in the PR: 2243 unit passed, 22 fake-daemon e2e passed, 9 real-claude
  passed).
