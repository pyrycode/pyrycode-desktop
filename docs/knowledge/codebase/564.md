# #564 — Decode the daemon `background_task_started` frame into a typed `backgroundTaskStarted` event

Transport slice of the background-task-panel vertical, split from #554. First of three sibling frame
slices (#564 → #565 `background_task_updated` → #566 `background_task_roster`); the store that joins all
three by `task_id` is #567, the panel that renders it is #568. Shipped as PR
[#570](https://github.com/pyrycode/pyrycode-desktop/pull/570) (`dbb163e`), code-review **PASS** (zero MUST/
SHOULD, 3 NIT). Security-sensitive (the frame widens what crosses main→renderer IPC to five strings and a
nullable string array, one of which — `description`, for `task_type: local_bash` — is claude's literal
shell command line); size S. A structural clone of `api_retry` (#492, `e08f33d`) end to end, scaled from
four wire fields to six, with two deliberate divergences from that template. **No render** — the event
ships dormant, consumed by none of the three exhaustive renderer bridges.

## Summary

The daemon can report a turn finished (`turn_end` / `end_turn`, `turn_state` → `idle`) while a command
claude started is still running (pyrycode#1240). `background_task_started` is the frame that separates that
case from a genuine finish. Before this ticket the frame was unmodeled and fell through
`parseInboundMessage`'s `default → inbound-unmodeled → null`.

The lane is confirmed as the mobile v2 stream over Noise + relay, not `pyry acp` — the daemon fans all
three background-task frames to `interactive`-capable clients (pyrycode#1394, shipped 2026-08-08), and this
app already advertises `interactive` (#179), so the frame reaches the client today.

Seven touch-points, mirroring `api_retry`'s six-touchpoint shape with one extra (the new field narrower):

- **Wire type** (`src/shared/wire/types.ts`) — `'background_task_started'` joins `EnvelopeType`, after
  `'queue_state'`. `BackgroundTaskStartedPayload { conversation_id, task_id, tool_call_id, description,
  task_type, truncated_fields: string[] | null }` — five required strings plus one required-present
  nullable array, field order mirroring `interactive.go:177`. The wire field is `tool_call_id`, **not**
  `tool_use_id` (the spelling `ToolUsePayload`/`ToolResultPayload` use) — the daemon's own prose invites
  the misreading; the *value* is the same identifier those two carry.
- **Inbound decode** (`inboundMessage.ts`) — a new field narrower, `requireStringArrayOrNull`, added
  directly after `requireStringOrNull`: a literal `null` returns `null`, an array returns a fresh copy
  whose every element passed a bare `typeof === 'string'` check, anything else (including an **omitted
  key**, `undefined`) throws. `parseBackgroundTaskStartedPayload` scales `parseApiRetryPayload` from four
  fields to six — five `requireString` calls plus one `requireStringArrayOrNull` call, no other new check.
  `{ kind: 'background-task-started'; backgroundTaskStarted: BackgroundTaskStartedPayload }` joins
  `InboundDaemonMessage`. `case 'background_task_started'` narrows before logging (a malformed frame leaves
  no diagnostic record), then emits the existing content-free `inbound-decoded` shape — no decoded field
  added.
- **Consumer emit** (`daemonConnection.ts`) — one `case 'background-task-started'` in the
  `switch (inbound.kind)`, a fresh **named-field** literal copied by name, never a spread of
  `inbound.backgroundTaskStarted`. **`conversation_id` is KEPT as `conversationId`** — the one deliberate
  divergence from the `api_retry` template (see below). `truncatedFields` passes the already-narrowed array
  by reference; its `null` is preserved, never coerced to `[]`. Deliberately stateless: no dedup, no task
  map, no correlation memory — the wire's ordering is claude's, not the daemon's (a roster can arrive
  before the `started` for a task it lists), so #567 must join on `task_id` rather than assume order. Not
  compile-forced (this inner switch has no `assertNever` default) — the round-trip test is the guard.
- **`DaemonEvent` arm** (`src/shared/ipc/events.ts`) — `{ type: 'backgroundTaskStarted'; conversationId;
  taskId; toolCallId; description; taskType; truncatedFields: readonly string[] | null }`, placed after
  `compacting`. `description`/`taskType` are untrusted, model-influenced daemon-relayed text; the
  doc-comment carries the render-as-plain-text-never-HTML constraint forward to #568, since this slice has
  no DOM sink of its own.
- **Three exhaustive bridge no-ops** — `daemonEventBridge.ts`, `modalBridge.ts`, `timelineBridge.ts` each
  add `case 'backgroundTaskStarted': return null`. In `timelineBridge.ts` the arm joins the no-op
  fall-through cluster beside `queueState` (**not** the now-owned `apiRetry`/`compacting` arms) — the same
  rationale applies: daemon *state*, not a turn-stream item, since the frame carries no `turn_id` and
  opens/closes no turn. All three compile-forced by their `assertNever` default.

## Patterns established

- **A required-present, nullable-array wire field decodes through a dedicated `require*` narrower, not an
  inline check in the `parse*` function.** `requireStringArrayOrNull` widens `requireStringOrNull`'s "a
  literal `null` is a VALUE, not an absence" semantic from a scalar to an array with no extra guard needed:
  `payload[field]` is `undefined` for an omitted key, which is neither `null` nor an array, so fail-closed-
  on-absence falls out of the shape. Two filed siblings (#565, #566) need the identical contract for the
  same wire field, which is what justified a shared helper over inlining.
- **An array-of-bare-scalars narrower borrows `parseQueuedItem`'s *posture*, not its *shape*.** Every
  existing array narrowing in `inboundMessage.ts` (`parseQueueStatePayload`, message-chunk, modal options)
  maps elements through a record narrower, because their elements are records. For bare-string elements the
  right move is a `typeof === 'string'` check per element (one bad element throws the whole payload closed,
  empty array valid, fresh array out) — inventing a `parseTruncatedField` record narrower would have been
  ceremony around a `typeof` check.
- **`conversation_id` KEEP vs DROP is decided by "turn-stream item, or daemon state?", not by whether the
  frame happens to carry the field.** The codebase has no blanket drop rule — `queue_state` (#720) already
  established the KEEP precedent for daemon-state snapshots a store keys by id. This ticket is the second
  data point for that rule, and the daemon doc's own framing ("its own thread of activity, not part of the
  turn it appeared in") is textually the same characterization `queue_state` got.

## Lessons learned

- `requireStringOrNull`'s "a literal `null` is a VALID value, NOT an absence" semantic widens to an array
  with **no extra check**: `payload[field]` is `undefined` for an omitted key, which is neither `null` nor
  an array, so the fail-closed-on-absence requirement falls out of the shape rather than needing its own
  guard. Worth reaching for whenever a Go `[]T` field carries no `omitempty`. (From the PR body.)
- The nearest array precedent in the codec (`parseQueueStatePayload`) maps elements through a *record*
  narrower because its elements are records. For an array of bare scalars, borrow its posture (one bad
  element throws the whole payload closed, empty array valid, fresh array out) but not its shape —
  inventing a `parseTruncatedField` would have been ceremony around a `typeof` check. (From the PR body.)
- Code review flagged (NIT, not blocking) that five assertions in `daemonConnection.test.ts` reach individual
  fields off `emitted(sink)` via `as Array<{ … }>` casts rather than a whole-object `toEqual`, which widens
  every property to optional and would stop catching a field rename as a compile error in those five spots
  specifically — the shape is still genuinely pinned by the two neighbouring tests that don't cast (a
  whole-object `toEqual` and an `Object.keys(...).sort()` key-set pin). Worth preferring whole-object
  assertions over field-reaching casts when cloning this test file's style forward.

## Open questions carried forward

- **`truncatedFields` must survive into #567's held set unabridged** — a reader that drops it presents
  claude's cut text as complete.
- **Ordering is claude's, not the daemon's.** A roster may arrive before the `started` for a task it lists;
  #567 must join on `task_id`, never assume arrival order.
- **No terminal event exists in this family by design.** "Finished" is a client conclusion drawn from a
  task's absence in a later roster (#566), never something the wire reports directly — #567/#568 must not
  invent one.
- **`task_type` and `truncated_fields`' element names stay open strings, never a closed union** — `local_bash`
  is the only observed `task_type` today and one observation does not earn an enum; a client-side closed set
  would fail-close a valid future frame.
- **Inner-switch exhaustiveness** (`daemonConnection.ts`'s `switch (inbound.kind)` has no
  `default: assertNever`) is now six tickets deferred (#180, #199, #214, #315, #492, #564). The round-trip
  test remains the deterministic safety net.
