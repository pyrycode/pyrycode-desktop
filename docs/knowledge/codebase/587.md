# #587 — Transport: decode claude's announced model into a typed daemon event

The nineteenth additive `model_announced` → `model-announced` extension of the
[inbound message decode](../features/inbound-message-decode.md) boundary, and the corresponding
`modelAnnounced` arm on the [daemon-event channel](../features/daemon-event-channel.md). Shipped on
branch `feature/587` (`e407a7e`), PR #589. Size S, security-sensitive (architect self-review PASS),
code review **PASS with zero findings**. A structural clone of `apiRetry` (#492, `e08f33d`) /
`compacting` (#495) one variant over, plus one extra scalar field. **No render** — the announced-model
store is the sibling slice #588, blocked on this one.

## Summary

claude names the model it resolved for a turn on its `system` / `init` line. pyrycode#1616 declared the
v2 wire shape and pyrycode#1638 put it on the wire; before this ticket the frame fell into
`parseInboundMessage`'s `default:` arm, logged `inbound-unmodeled`, and was dropped. This ticket makes
the frame typed and puts it on the IPC channel, unconsumed.

- **Wire type** (`src/shared/wire/types.ts`) — `'model_announced'` joins `EnvelopeType`, grouped alone
  (not with the `stall`/`api_retry`/`compacting` status cluster) because it is an **identity report** —
  what claude says it *is*, for the turn it says it about — not a turn sub-state. `ModelAnnouncedPayload
  { conversation_id: string; model: string; truncated: boolean }`, all three always present (no
  `omitempty`; the daemon's own `model_announced_zero.json` fixture round-trips `{"","",false}`).
- **Inbound decode** (`inboundMessage.ts`) — `{ kind: 'model-announced'; modelAnnounced:
  ModelAnnouncedPayload }` joins `InboundDaemonMessage`, placed after `'compacting'` in the status
  cluster. `parseModelAnnouncedPayload` is the `parseUnrecognizedMessagePayload` shape (a
  `conversation_id`, a bounded untrusted string, a `truncated` bool) minus its `site`/`message_type`
  fields — every field maps onto an existing `require*` helper, so **no new helper**.
  `requireString('model')` admits `''` (the producer suppresses the event on an empty model, so no
  client-side guard duplicates that); `requireBoolean('truncated')` type-checks so a literal `false`
  passes as a value, never defaulted. `case 'model_announced':` narrows before logging, then emits the
  existing content-free `inbound-decoded{code:'model_announced', bytes, hash}` — no decoded field
  logged.
- **Consumer emit** (`daemonConnection.ts`) — one `case 'model-announced':` in the `switch
  (inbound.kind)`, a fresh **named-field** literal `{ type: 'modelAnnounced', model, truncated }` copied
  by name, never a spread of `inbound.modelAnnounced` (the `assistant-delta` idiom, avoided here so a
  decoder that later grows a field cannot smuggle it across IPC). `conversation_id` is dropped — the
  `turnState`/`stallDetected`/`apiRetry`/`compacting` convention: #588 holds a single value replaced per
  announcement, so nothing downstream keys by conversation. Deliberately stateless: no dedup, no
  coalescing, no timer, no last-value memo — N frames produce N events, including a verbatim repeat,
  which is what tells #588 the value is still current. Not compile-forced (this inner switch has no
  `assertNever`) — the round-trip test is the sole guard.
- **`DaemonEvent` arm** (`src/shared/ipc/events.ts`) — `{ type: 'modelAnnounced'; model: string;
  truncated: boolean }`. The comment names the collision explicit: `snapshotReceived` and
  `runConfigReceived` both already carry a `model: string` meaning the per-session **override** (`''` =
  no override); this arm means what claude **announced**, and the two disagree in the ordinary case.
  `truncated` is load-bearing — a cut identifier always misses #588's exact lookup and so always renders
  verbatim, looking exactly like a legitimate unrecognised model.
- **Three exhaustive bridge no-ops** — `daemonEventBridge.ts` gets a standalone `case 'modelAnnounced':
  return null`; `modalBridge.ts` and `timelineBridge.ts` each join the new arm to their existing
  fall-through no-op cluster, each with one added sentence to the shared trailing comment. All three
  compile-forced by their `assertNever` default.

`npm test` 794 passed (RED first: 21 failures across the six touched files before implementation);
`npm run build` (typecheck + electron-vite) clean. 13 files touched (7 production, 6 test), 600
insertions — the documented irreducible-S false positive for this exact slice shape (see #492/#495).

## Patterns established

- **A payload one scalar richer than its closest sibling needs no new decode idiom** — `truncated`
  isn't a new concept; it's `unrecognizedMessage`'s own `truncated: boolean` field applied to a second
  payload family. The shape reference for "add a bool to an existing string-plus-id decode" is
  `parseUnrecognizedMessagePayload`, not a fresh design.
- **A field that collides by name across two `DaemonEvent` arms with opposite meanings gets the
  distinction written into the newer arm's comment, not a rename.** `model` already means the
  per-session override on `snapshotReceived`/`runConfigReceived`; renaming the wire field here would
  drift from the daemon's own vocabulary (CLAUDE.md, ADR 0002), so the comment carries the disambiguation
  instead — the same move the daemon's own payload doc makes.
- **Verbatim-carry AC coverage needs a sentinel a normaliser would visibly fail, not a realistic-looking
  fixture.** A plain model name (e.g. `claude-opus-5`) round-trips through a lowercasing/trimming/family-
  matching decoder by accident. A mixed-case, punctuation-and-digit-bearing string
  (`Claude-Opus-5_TEST.20260819`) is the shape that actually distinguishes "held verbatim" from "silently
  normalised."

## Lessons learned

(Lifted from the PR body's own "Lessons learned" section.)

- **The `require*` helper trio covers this payload exactly, but only because `requireBoolean`
  type-checks rather than coerces.** `truncated: 0` and `truncated: 'true'` are the two inputs a
  defaulting implementation would silently swallow, and they are the tests that distinguish this
  implementation from one that does.
- **A recognition test that asserts `toEqual({ kind, payload: FIXTURE })` with the same fixture on both
  sides cannot catch a decoder that re-cases or substitutes a carried string.** The sibling `api_retry` /
  `compacting` tests use that form; this slice's AC3 assertions spell the expected literal out instead
  and add the mixed-case/punctuation sentinel above — worth copying for any future arm carrying
  model-authored text.

## Code review

PASS, zero findings. The reviewer independently re-verified the wire contract against
`pyrycode/internal/protocol/interactive.go`/`codes.go` rather than trusting the spec's transcription
(struct order, field names, and the 256-byte `maxModelField` bound in `internal/streamsup/parser.go:338`
all matched), confirmed the blast radius by grepping every `DaemonEvent` discriminator (exactly three
`assertNever`-guarded translators, all three gained the arm; every `default: null` bridge correctly
untouched), and confirmed the spec's open question — desktop already advertises `capabilities:
[CAPABILITY_INTERACTIVE]` (`daemonConnection.ts:1074`), so no capability-gate change was needed.
