# #588 — Renderer: hold claude's announced running model in a store

A dedicated `announcedModelStore` holding claude's announced model identifier verbatim alongside the
daemon's `truncated` report, fed by `announcedModelBridge` — a **fourth independent observer** of the
daemon event stream, structurally identical to `sessionIdStore`/`sessionIdBridge`. Shipped on branch
`feature/588` (`d146751`), PR #591. Size S, security-sensitive (architect self-review PASS), code
review **PASS, one NIT** (see below). Consumes the `modelAnnounced` event [#587](587.md) shipped
dormant. **No render** — the store still ships dormant; [#560](../features/run-config-store.md) is the
consumer.

## Summary

claude names the model it resolved for a turn on its `system` / `init` line; #587 decoded that into a
typed `modelAnnounced` daemon event that crossed IPC unconsumed. This ticket gives the value a renderer
home so the run-configuration sheet can eventually show what is actually running rather than only the
daemon's persisted per-session override, which reads empty on an un-overridden daemon.

- **`announcedModelStore.ts`** (`src/renderer/src/store/`) — `AnnouncedModel { model: string; truncated:
  boolean }`, `AnnouncedModelState { announced: AnnouncedModel | null }` (record-`|`-null, **not** two
  flat fields — the flat form would force `truncated` to carry a value before any announcement exists).
  `null` = "no announcement has arrived yet"; a received `{ model: '', truncated: false }` is a real,
  degenerate announcement held as-is, never collapsed to `null` (the `sessionIdStore` `null`-vs-`''`
  contract, reused). DI factory (`createAnnouncedModelStore`) → app singleton (`announcedModelStore`) →
  React hook (`useAnnouncedModelStore`) → read-only selector (`selectAnnouncedModel`). One setter,
  `setAnnouncedModel`, replaces the whole record unconditionally — no merge, no coercion, **no dedup of
  a verbatim repeat** (a repeat is the daemon's own signal that the value is still current).
- **`announcedModelBridge.ts`** — `translateModelAnnounced` maps the owned `modelAnnounced` arm to a
  fresh named-field literal `{ model, truncated }` (never `return event`, never a spread, so `type`
  never reaches the store), `default: null` for every other arm — including, critically,
  `snapshotReceived` and `runConfigReceived`, whose own `model: string` field means the opposite thing
  (the per-session *override*). `subscribeAnnouncedModel` guards on `announced !== null` — the record's
  presence, never `.model`'s truthiness — so a `{ model: '' }` announcement still writes with its
  `truncated` report intact (the `sessionIdBridge` `id !== null` trap, reused). `AnnouncedModelData` is
  the headless leaf: one `useEffect` subscribe-on-mount, `window.pyry` dereferenced only inside the
  effect, server-renders to `null` without a bridge mock.
- **`App.tsx`** — `<AnnouncedModelData />` mounted as the **eighth** headless leaf, App-level
  always-listening (an announcement rides the turn's `init` line and can arrive before #560's sheet is
  ever opened). No `connected` gate.
- **Three exhaustive bridges untouched** — `daemonEventBridge.ts`, `modalBridge.ts`, `timelineBridge.ts`
  keep their permanent `modelAnnounced` no-ops (present only so their `assertNever` guard makes a new
  arm a compile error). This is the `sessionIdBridge`/`backgroundTaskRosterBridge` shape (an independent
  fourth observer), not the `apiRetry` shape (folding into an owned arm of an existing bridge).

`npm test` 32/32 green on the two new suites (RED first: both suites failed on the missing modules
before implementation); `npm run build` (typecheck + electron-vite) clean. 5 files touched (2 production
modules + 1 edited `App.tsx` + 2 test files, 572 insertions) — under the architect's projected ~420 LOC
ceiling but still under the §4 red lines (3 production files, 4 new exported identifiers).

## Patterns established

- **A record-`|`-null wrapper is the correct shape whenever one of the wrapped fields has a legitimate
  "false/empty is a real value" contract.** The flat alternative `{ model: string | null; truncated:
  boolean }` looks equivalent but silently forces `truncated` to hold a value before any announcement
  exists — the exact "`false` is a VALUE, never an absence" rule this ticket had to preserve. Wrap both
  fields behind one nullable record instead; every field of a present record is then a real
  daemon-delivered value by construction. Reusable wherever a second incoming boolean/scalar joins a
  store that already uses the flat `T | null` idiom.
- **The highest-value negative for a bridge translator with a name-colliding sibling arm is that
  sibling, not a generic "unrelated events" sample.** `announcedModelBridge.test.ts` asserts
  `snapshotReceived`/`runConfigReceived` (both carrying `model: string` meaning the opposite value)
  translate to `null` — pinning that the filter can never mistake the persisted override for what claude
  announced. A generic negative list would not have caught this regression class.
- **A fourth-observer bridge (`default: null`) needs no `assertNever`**, and this remains correct even
  though the store's own `AnnouncedModelState` uses a `Record | null` sentinel elsewhere — the two
  "null means something" surfaces (bridge filter vs. store state) serve different contracts and neither
  constrains the other's shape.

## Lessons learned

(Lifted from the PR body's own "Lessons learned" section, with one correction flagged by code review.)

- **A control character typed directly into a test literal lands as a raw byte in the source file**, not
  an escape sequence — the "held verbatim" AC wants a terminal-escape case, and writing one inline
  embeds a literal ESC/BEL byte in the `.ts` file. **Correction to the PR body's own recipe** (caught by
  code review as a NIT: the PR body suggested `\^[`/`\^G`, which is not a valid JS/TS escape — `\^`
  is a non-escape, so the backslash is dropped and the literal evaluates to the two ASCII characters
  `^[`, not `U+001B`). The shipped code did the correct thing throughout
  (`announcedModelStore.test.ts:79`: `'Claude_Opus.4-5_BETA\u001b[31m\u0007'`) — write control characters
  as `\u001b`/`\u0007`; repair an already-embedded raw byte with `perl -i -pe 's/\x1b/\\u001b/g'`; verify
  with `LC_ALL=C grep -c '[[:cntrl:]]'` (should be `0`) — check the file's bytes, not the rendered test
  name. The same raw byte, if it reaches a PR body, blocks `gh pr create`.
- **The two name-colliding arms are the highest-value negative in the bridge test** — see § Patterns
  established above.
- **The record-`|`-null shape is load-bearing here, not stylistic** — see § Patterns established above.
- **The worktree ships without `node_modules`** — `npm install` is the first step before any vitest run;
  bare `npx vitest` fails confusingly (`Cannot find module 'vitest/config'`) rather than obviously.

## Deferred — the pairing-scoped clear

This store is pairing-scoped (nothing on a fresh pairing re-asserts an announcement) and is
**deliberately absent** from `clearPairingScopedState.ts` — harmless while the store ships dormant, but
it will latch a stale value once #560 renders it. The obligation is recorded in `announcedModelStore.ts`'s
header and `App.tsx`'s mount comment. Recommended (not yet ticketed): fold `clearAnnouncedModel` +
its `ClearPairingScopedStateDeps` entry into #560, since that is the ticket that makes a stale value
observable for the first time.
