## What shipped

`AssistantMarkdown` (#608) gets its first and only importer. One production file, one stylesheet:

- `ConversationScreen.tsx` — the `assistantText` arm forks on the `inProgress` prop `Timeline` already
  derives (`index === lastIndex && item.kind === 'assistantText'`, no new state): the in-progress tail
  renders exactly as before (`{item.text}` + the streaming cursor span, plain text, auto-escaped); a
  settled item renders `<div className="bubble__markdown"><AssistantMarkdown text={item.text} /></div>`.
  `bubble--assistant-text` (`white-space: pre-wrap`) becomes conditional on `inProgress` rather than
  staying on the bubble unconditionally — it now marks the plain-text tail, not "the assistant text";
  the class name is deliberately not renamed (touches four files, no behavioural gain), the CSS comment
  carries the meaning instead. `React.memo` is declined, named as a seam.

  resets only `body` and UA block margins would otherwise add to the flex gap (`margin-block`, not
  `margin`, to keep `<blockquote>`'s 40px `margin-inline` indent — its only visual distinction until
  #624), and `.bubble__markdown pre { white-space: pre-wrap }` so fenced code wraps instead of spilling
  past the bubble's measure (`word-break: break-word` stays inherited from `.bubble`, not restated,
  per #607's precedent). `min-width: 0` on the `pre` rule was written into the e2e overflow assertion
  first and proved unnecessary — not shipped, per the spec's "observe before you add it" instruction.
  #607's rationale comment above `.bubble--assistant-text` is corrected in the same edit: it now governs
  only the still-growing tail, not "the assistant reply's whitespace treatment" generally.

## Patterns established

- **A conditional modifier over a "neutralise it one level down" handoff, when both satisfy the AC.**
  #608 anticipated `white-space: normal` undoing `pre-wrap` inside the new container. The shipped design
  instead makes the modifier conditional on the same boolean that selects the render path, so "markdown
  owns the whitespace" is true by construction — an absent declaration needs no re-verifying when a new
  element type appears inside the container, unlike an override that must be re-checked every time.
- **Observe, then add — don't pre-apply a known CSS remedy.** The spec named `min-width: 0` as a
  plausible fix for flex-item min-content overflow and explicitly said not to ship it until the e2e
  overflow assertion actually failed. It didn't fail. Precedent for treating a "this might be needed"
  CSS fix the same as any other unobserved-failure-mode defense (see [#608](608.md)'s `React.memo`
  deferral for the same posture applied to a different mechanism).
- **A spec's scoped file list bounds what you edit, never what you can break.** The spec's breakage
  list for this fork was exhaustive within its four named files but missed `interactiveRoundtrip.test.tsx`
  (#179's round-trip), which asserted the old settled-bubble markup shape. Code review's blast-radius
  pass (grep the literal markup string across `src` + `e2e`, not just the spec's list) is what caught it.

## Lessons learned (from the PR body and code review)

- **A mutation run must verify the build actually succeeded before trusting a "vacuous" reading.** One
  of the five mutations run against this ticket's assertions failed typecheck, which leaves `out/`
  holding the previous build — Playwright then drives stale output and reports green, a false vacuity
  signal. Redo with a type-valid always-false condition rather than trusting the first red/green result.
- **A blank-line fixture cannot discriminate "plain text with preserved newlines" from "markdown."**
  Markdown renders a blank line as two paragraphs, which is also taller than one line, so a
  `height > lineHeight` assertion passes under both the old and new rendering. Single newlines
  discriminate correctly: CommonMark folds a soft line break, `pre-wrap` does not.
- **"Render the tail through markdown" is two mutations, not one, and testing only one hides the bug.**
  Flipping just the content fork (render markdown) while leaving the bubble's class unconditional means
  `pre-wrap` is inherited straight into the new container — every geometric e2e assertion still passes,
  and only the unit tier catches it. The by-construction whitespace argument for the conditional
  modifier holds precisely because the class and the content fork share the same boolean.
- **`e2e/` sits outside both `tsconfig.node.json` and `tsconfig.web.json`.** `npm run typecheck` does
  not cover Playwright specs — Playwright transpiles them without type-checking, so a type error in a
  spec surfaces only as a runtime failure, not a gate failure. A prior ticket hit this same gap
  independently; this PR is a second, independent confirmation of the same repo-wide fact.
- **A stale module-header comment can survive its own subject changing underneath it.** Code review's
  one SHOULD FIX: `AssistantMarkdown.tsx:25-27`'s handoff note still claimed the module "ships dormant"
  and described the rejected `white-space: normal` neutralisation, after this ticket gave it an importer
  and built the conditional-modifier design instead. Non-gating because the spec's "do not edit
  `AssistantMarkdown.tsx`" trap is scoped to the security *configuration* (plugins/`skipHtml`/prop
  spreading), not to a two-line comment correction — and because the review named the `docs/knowledge/`
  copies of the same stale claim (this file's own predecessor claims, `INDEX.md`) as the documentation
  phase's to fix, not the developer's. Both are corrected in this pass; `AssistantMarkdown.tsx` itself
  is left for whichever ticket next legitimately touches that file.
