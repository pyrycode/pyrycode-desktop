# #610 — Open http:/https: links in assistant markdown in the OS browser

Commit `c3bf917` (spec `bfcef10`, PR #634, code review PASS with one non-blocking SHOULD FIX and one NIT).
Security-sensitive: the ticket's first production edit to `AssistantMarkdown.tsx` since [#608](608.md), the
file that is the whole of #608's security boundary. Architect self-review (11 categories) PASS, one
SHOULD FIX deferred (DNS-prefetch side channel, blocked on `src/renderer/index.html` being frozen by AC5)
and one named-out-of-scope item (visible-text/destination mismatch, inherent to any link surface). Closes
the four-year-old — in this repo's short history — deny-first-links posture from [ADR 0010](../decisions/0010-markdown-renderer-capability-absent-html.md),
opening it to exactly `http:`/`https:`.

## What shipped

Two production files, +128/−22 lines, plus a rewritten unit-test block and a new e2e spec:

```ts
/** The href verbatim when it is an absolute http/https URL carrying an authority; null otherwise. */
function allowedLinkHref(href: string | undefined): string | null
```

Four conditions, each answering a different question and deliberately not fused even though the last two
overlap today:

1. `href === undefined` → null (react-markdown types the prop optional).
2. `new URL(href)` with **no base argument**; a throw → null. This is the reject-without-resolving rule —
   every relative, protocol-relative, empty and unparseable href throws here, so a dev-server build (base
   `http:`) and a packaged build (base `file:`) can never disagree on the same reply.
3. `url.protocol` is `http:`/`https:` — the allowlist itself. `URL` lowercases `protocol`, so this is
   case-insensitive by construction.
4. The **original** string matches `/^https?:\/\//i` — the base-independence guard, not a second scheme
   check. Closes `http:example.com`: a scheme with no authority, so it parses absolutely and passes
   condition 3, but the browser still resolves it against the document base on click (the dev server's
   host vs. the real one when packaged). Also, per code review, fail-closes `new URL`'s normalisation
   divergences the ticket didn't name — a leading space, an embedded tab, `https://\host` — where the
   parsed URL differs from the raw string that would actually render.

Returns the **original href string**, never `url.href` — the parser adds a trailing slash and
punycodes/percent-encodes non-ASCII authorities, and AC1 requires the href unchanged.

The `a` override:

```tsx
a: ({ href, children }) => {
  const allowed = allowedLinkHref(href)
  if (allowed === null) return <>{children}</>
  return <a href={allowed} target="_blank" rel="noreferrer">{children}</a>
}
```

`target="_blank"` is the click mechanism, not decoration: it is what routes the click to
`setWindowOpenHandler` (`src/main/index.ts:56`, unchanged), which hands the URL to `shell.openExternal` and
denies the in-app window on every path including the allowed one. Without it the click is a same-document
navigation that `will-navigate` cancels — the link would look correct and do nothing, with no other tier
able to tell the difference (verified by mutation, see e2e below). `rel="noreferrer"` is belt to that
suspender, not the control. Destructures only `href`/`children` — the file's never-spread rule, unchanged.

`conversation.css` gains the app's first anchor rule, appended after #630's inline-code exclusion:

```css
.bubble__markdown a { color: var(--color-primary); text-decoration: underline; }
```

`--color-primary` is the app's interactive/selected role (four other call sites cited in the rule's
comment); the "status vocabulary" comment above `.bubble--compacting` in the same file is scoped to the
four 4px leading accent bars, not a prohibition on the token. The underline is load-bearing: colour alone
against the surrounding prose (`--color-on-surface`) measures 1.31:1, well under WCAG G183's 3:1 floor for
colour-only link distinction; on the bubble fill it's 8.5:1, comfortably legible. No `:visited` rule needed
(author-normal beats UA-normal regardless of specificity). #630's `code:not(.code-block__body code)` rule
composes unchanged for `<a><code>`, inheriting the anchor's colour at 10.9–11.1:1 on `--color-surface`.

**Tests.** Three existing `AssistantMarkdown.test.tsx` cases (inline link, reference-style, autolink)
rewritten from deny-first to accepted-anchor assertions; the `javascript:` case kept verbatim; one new
`http:` accepted case (AC1 names both schemes); ten `it.each` denied cases each asserting the **exact**
markup `'<p>t</p>'` (stronger than the file's usual `toContain`/`not.toContain` triple, and the one that
fails a transform-only implementation) — `data:`, `file:`, `mailto:`, a custom scheme, relative, protocol-
relative, empty, unparseable (`<not a url>` form, not `not a url`), a bare-URL-as-text regression case, and
`http:example.com` (the sole guard on condition 4). New `e2e/assistant-link-opens-externally.spec.ts`:
streams a reply containing a link, asserts a positive control (anchor + href) before stubbing
`shell.openExternal` via `Object.defineProperty` in the main process, clicks, then asserts the recorded URL,
an unchanged `BrowserWindow` count, and an unchanged `page.url()`.

## Patterns established

- **A base-independence guard is a separate condition from the scheme allowlist, even when one currently
  implies the other.** Fusing "protocol is http/https" with "string starts with http(s)://" into one check
  would make a future allowlist widening silently drop the authority requirement too — keep them as two
  named conditions so a simplifier has to delete the comment explaining why before deleting the code.
- **`target="_blank"` as the enforcement point for a main-process window-open policy is a one-line, easy-to-
  regress dependency and needs its own comment at the override, not just at the handler.** A plain anchor
  produces markup that is byte-for-byte correct and a click that silently does nothing — no unit tier can
  distinguish that failure from success; only a real click through a real BrowserWindow can (see the e2e
  mutation-survival note below).
- **When a denied set spans many distinct fixtures, one exact-markup `toBe` assertion per fixture is
  stronger than a `toContain`/`not.toContain` triple** — it also proves the denied URL string appears
  nowhere in the render, which the triple doesn't, and is what actually fails a `urlTransform`-only
  implementation.

## Lessons learned

*(lifted from the PR body, verbatim where clear)*

- **`urlTransform` blanks a href; it does not remove the anchor.** Measured against the pinned
  `react-markdown@10.1.0`: `javascript:`, `data:`, `file:`, a custom scheme and `[t]()` all reach the `a`
  override with `href=""`, so relying on the transform alone emits `<a href="">t</a>` — an anchor, a click
  target, and the literal string `href`, all three forbidden by AC2. `mailto:` and `./doc.md` arrive
  **unblanked**. [ADR 0010](../decisions/0010-markdown-renderer-capability-absent-html.md)'s line naming
  `urlTransform` as this ticket's mechanism describes a pre-implementation plan the measurement disproved;
  corrected in this documentation pass.
- **A same-document anchor click hangs Playwright rather than failing fast.** Under the
  `target="_blank"`-removed mutation, the click is cancelled by `will-navigate` and the test dies at
  `anchor.click()` waiting for scheduled navigations to finish — not at the recorded-URL poll. Useful to
  know when a future regression on this path presents as a timeout rather than a clean assertion failure.
- **The `/i` flag on the base-independence regex shipped untested** (code review SHOULD FIX, non-blocking,
  not fixed in this PR): `HTTPS://example.com` is an AC1-eligible href — it reaches the override verbatim,
  `url.protocol` normalises to `https:`, and the case-insensitive flag on `ABSOLUTE_WEB_URL` is the only
  reason condition 4 admits it. No test pins this, so a future edit dropping the flag would silently regress
  uppercase-scheme links to inert text with every existing test green. Worth closing with one added
  accepted-case row rather than carrying it forward again.
