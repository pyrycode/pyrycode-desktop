# #62 — Connect the transport: drive the Noise relay driver and surface a completed handshake

**Shipped:** 2026-07-04 · **Size:** S · **Labels:** `security-sensitive` · **Scope:** one new background-process module (`src/main/daemonConnection.ts`) + one composition-root edit (`src/main/index.ts`); no consumer cascade · **no new dependency**.
**Spec:** `docs/specs/architecture/62-connect-transport-and-surface-handshake.md` · **PR:** [#64](https://github.com/pyrycode/pyrycode-desktop/pull/64).

The **background-process transport consumer** the [#50 Noise relay driver](50.md) was built for — the wiring slice that turns the transport chain into a live, authenticated link the window can read. It sources the device static key ([#43](43.md) `ensure()`), the paired-server record ([#44](44.md) `load()`), and the `hello` early-data ([#10](10.md) `buildClientHello`), constructs and drives the driver, and maps its four lifecycle events onto the typed [#18](18.md) daemon-event channel — `handshake-complete` → `connected{ack}` (via `parseHelloAck`), `terminal`/`error` → `failed`, plus a synchronous `connecting` at connect start. The [#19](19.md) renderer bridge + [#2](2.md) store already translate `connected{ack}` into a completed-handshake state — this ticket produces the event that feeds them; **it does not touch the renderer.** See the [daemon-connection feature doc](../features/daemon-connection.md) for the full contract, event mapping, data flow, and security properties.

**Composition, not new crypto.** Everything it drives was already loadable; the driver named this consumer as its missing piece (*"the sink is a plain in-process callback owned by a later background-process consumer"*). One atomic composition — `createNoiseRelayDriver({connection, session, onEvent})` takes the sink as a *required constructor argument*, so sourcing the inputs, constructing the driver, and mapping its events are a single construction site with no Strangler-Fig seam. Split from the original [#10](10.md) (pure envelope functions) into #10 + this wiring slice.

## Patterns established

- **The composition/IPC-bridging consumer lives one level above `transport/`, by design.** A module that imports **both** a `transport/` primitive **and** the IPC layer (`emitDaemonEvent` + `DaemonEvent`) must sit at top-level `src/main/`, because `transport/` is kept deliberately IPC-free (no transport module references the daemon-event channel — [ADR 0002](../decisions/0002-remote-head-over-relay-shared-wire.md)). This placement rule is the reusable shape for every future transport→renderer bridge.
- **One choke point maps a sealed driver-event union to a sealed IPC-event union.** `onDriverEvent` is the *only* place that emits; the `switch` over `RelaySessionEvent` is total by construction, and each arm produces exactly one `DaemonEvent`. Untrusted daemon bytes (`helloAck`) are narrowed at that boundary (`parseHelloAck`, fail-closed) so nothing downstream holds `unknown`.
- **`failed` for every non-clean end; `disconnected` reserved for a deliberate stop.** The clean `stop()` path emits **nothing** (the window is tearing down); every failure-to-establish or authoritative drop maps to `failed{error:{code, message, retryable:false}}` with a **static** category code. This is the minimal status mapping the AC blessed; richer failed-vs-disconnected choreography is [#34](https://github.com/pyrycode/pyrycode-desktop/issues/34)/[#35](https://github.com/pyrycode/pyrycode-desktop/issues/35).
- **Classify-don't-forward, inherited unbroken.** The bootstrap's single `try/catch` **drops** the caught object and surfaces only a static `connect-failed` code — a codec/keychain error message can echo the token or transcript bytes. Same discipline on the `parseHelloAck` catch (`malformed-hello-ack`) and the driver `error` arm (the reason enum is already static). Log-free, pinned by the six-method `console`-spy (inherited [#5](5.md)/[#7](7.md)/[#22](22.md)/[#50](50.md)).
- **`connecting` emitted synchronously, before the first `await`.** Status leaves "connecting" the moment `start()` is called, independent of how long `load()`/`ensure()` take. The async bootstrap is fire-and-forget and never rejects (it catches everything internally), so `start()` stays `void`-returning.
- **The header contract is copied field-for-field from mobile, on purpose.** `X-Pyrycode-Server`/`X-Pyrycode-Token`/`User-Agent`/`X-Pyrycode-Device-Name` mirror `OkHttpRelayTransport.kt`; the relay ignores the token value under v2 (the Noise static-key handshake is the real gate), but a non-empty token is still required and deviating to a placeholder would drift from mobile and risk a silent handshake break (CLAUDE.md no-drift).

## Lessons learned

*Lifted from the PR body's "Lessons learned" section.*

- **The `stopped` flag does double duty** — it is both the start/stop race guard (checked immediately before the synchronous `createDriver`, since JS yields only at `await`, so a `stop()` that interleaved at an earlier await point prevents the driver from ever being constructed) **and** the "suppress the clean-stop terminal" flag (a `terminal{1000,'stopped'}` driven by our own `stop()` is swallowed rather than surfaced as `failed`). One local closes both concerns without a separate `stopping` boolean.

## Deferred / carried forward

- **Auto-connect + per-dial record reload → [#34](https://github.com/pyrycode/pyrycode-desktop/issues/34).** This ticket wires a single explicit connect at composition time (`did-finish-load`); firing automatically on pairing and reloading the record per dial is the mobile-parity refinement.
- **The inbound `message{plaintext}` arm → [#12](https://github.com/pyrycode/pyrycode-desktop/issues/12).** A no-op/TODO stub here; the streamed daemon-message decode/route is out of scope.
- **Per-drop `connecting`/`disconnected` status choreography → [#34](https://github.com/pyrycode/pyrycode-desktop/issues/34)/[#35](https://github.com/pyrycode/pyrycode-desktop/issues/35).** Transient reconnects are invisible here (the supervisor absorbs them); the UI stays on its last status during a gap.
- **Multi-window / macOS re-activation lifecycle → [#34](https://github.com/pyrycode/pyrycode-desktop/issues/34)/[#35](https://github.com/pyrycode/pyrycode-desktop/issues/35).** `app.on('activate')` re-creates a window without re-wiring the connection (pre-existing in `createWindow`, not introduced here).
- **wasm bundling for the packaged app** — flagged forward from [#7](7.md)/#29; the live handshake path is exercised by the operator-gated `noiseSession.interop.test.ts` suite + the [e2e harness](../features/e2e-harness.md) ([#40](40.md)), not this ticket's unit surface.
