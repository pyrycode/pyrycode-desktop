## Patterns established

- **A comment-sweep AC and a positive-rejection-assertion AC can collide on the same string literal.**
  AC5 here banned the name `requestSnapshot` from any comment in the nine edited files; AC1 required a
  new assertion whose literal *is* `{ type: 'requestSnapshot', … }`. The fix was phrasing the
  assertion's explanatory comment around "the shape below" rather than naming the verb directly — the
  code literal on the next line supplies the name without the comment repeating it. Worth checking on
  any future removal ticket that pairs a tree-wide name ban with a "prove it's now rejected" test.
- **Dropping a name from a slash-list comment reflows worse than swapping one.** The eleven
  `nextEnvelopeId`-sharing lists each lost one term and needed the paragraph re-wrapped by hand in most
  cases (a line ending on a bare `/`, or an orphaned trailing clause); the six `index.ts` re-anchors
  (name swap, same length) reflowed for free. A pure drop costs more editing than a substitution of
  equal-or-greater length — budget accordingly when scoping a removal ticket's line count.
- **Verify a "nothing skipped" AC against the base commit's own skip count, not just the post-change
  run.** `roundtrip.test.ts` reports `1 skipped` after this change; that reads as a regression until
  confirmed identical on `HEAD~1` (the pre-existing `describe.skipIf(!live)` live-relay block, orthogonal
  to this deletion).

## Lessons learned (from the PR body)

- **An AC that forbids a name in comments and an AC that requires the name in a code literal can
  collide within the same file.** See Patterns above — this is a general shape for removal tickets,
  not specific to this verb, and is worth checking for on any ticket that both sweeps comments for a
  retired name and adds a rejection test proving the retirement.
- **A pure term-drop from a slash-list comment costs more edits than a same-length re-anchor.** Eight
  of the eleven `nextEnvelopeId` lists needed hand rewrap after the drop; the re-anchors did not.
- **A "nothing skipped" AC needs a base-commit comparison, not just a post-change reading.** The
  roundtrip suite's `1 skipped` count is unrelated pre-existing live-relay gating; confirming this
  required diffing against `HEAD~1`, not just eyeballing the post-change number.
