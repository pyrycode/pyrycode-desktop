## What shipped

Two production files:

- `AssistantMarkdown.tsx` — a fourth entry in the `components` map, `pre`, bound by the file's existing
  "NEVER spread `{...props}`" rule: it destructures `children` only, wraps it in `<div className="code-block">`,
  and precedes it with `<div className="code-block__header">` when a language was found — never on the bare
  `&&` form, so an empty-string language can't render an empty bar. A new module-private helper,
  `fenceLanguage(children): string | null`, reads the `language-*` class react-markdown places on the
  fence's `<code>` child (`Children.toArray(children)[0]`, `isValidElement<{className?: unknown}>`, a
  runtime `typeof className === 'string'` check — the real gate, since the type argument is an unchecked
  claim), token-scans the class (not a whole-string regex, so a second class can't kill the label), and
  truncates to `MAX_LANGUAGE_CHARS = 20`. Fails closed: anything that isn't "a `<code>` carrying a
  `language-…` class" — including a real CommonMark construct the ticket didn't name, an indented
  (non-fenced) code block — returns `null`, which renders the same no-header block AC3 specifies. `code`
  itself stays un-overridden (a languageless fence and inline code are indistinguishable by `className`
  alone; inline code's own treatment is #624's).
- `conversation.css` — `.code-block` (surface fill, 1px outline-variant border, 12px radius, no
  `display`/`width`/`margin`), `.code-block__header` (padding, the four label-small type tokens,
  `on-surface-variant`, `border-bottom` as the divider, `nowrap`+`ellipsis`+`overflow:hidden` as the
  geometric half of the length bound), `.code-block__body` (`margin-block: 0`, padding, the four
  body-small type tokens, `on-surface`), and a `.code-block__body, .code-block__body code` selector list
  for `font-family` — needed because the UA stylesheet's `code { font-family: monospace }` beats an
  inherited `--font-mono` on the `<pre>` alone. Placed immediately after `.bubble__markdown pre`, whose
  comment gained a paragraph explaining the nested `<pre>` is now `.code-block__body`, reached by that
  same descendant selector, and why `white-space` is deliberately not restated on the new class.

## Patterns established

- **The divider hangs on the optional element's trailing edge, not the fixed element's leading edge, when
  Figma draws it on the wrong side for a conditional layout.** Figma draws the header/body divider as
  `border-top` on the body (`16:48`). Porting that literally breaks the no-language case: a languageless
  fence renders the body as the block's only child, and a `border-top` there sits a hair under the block's
  own top border — a doubled edge, which is exactly the "empty bar in its place" AC3 forbids. Moving the
  rule to `border-bottom` on the header makes the divider appear and disappear *with* the header by
  construction, no conditional selector needed. Generalizes past this ticket: when a mock's fixed-order
  chrome (divider between A and B) has to survive A becoming optional, hang the shared edge on the
  optional element, not the element that's always there.
- **An off-grid Figma padding with no nearest token is resolved by this file's own priors, not by
  distance.** Both `6px` and `10px` are exact midpoints between adjacent spacing tokens (4/8 and 8/12).
  "Nearest" is structurally undefined for a midpoint; two existing rules in this same stylesheet had
  already faced the identical 6px and 10px values and rounded both **up** (`--space-2`, `--space-3`) —
  precedent decided it, and rounding up both also happens to preserve the mock's own header-tighter-than-body
  relationship. The one apparent counter-example rounds a `py 10` *down*, but only because that rule
  carries an explicit `min-height` the geometry actually lives in; a box with no height bound (this one,
  per `:369-371`'s established "no max-height, no overflow" posture) has no such escape hatch.
- **A UA element-selector default silently wins over an inherited custom property, and it's invisible in
  both test tiers.** Blink's `code { font-family: monospace }` beats an inherited `--font-mono` set only
  on the `<pre>` wrapper, because a declaration beats inheritance regardless of origin. Neither
  `renderToStaticMarkup` (no computed style) nor a screenshot taken where the two monospace stacks happen
  to render alike catches this — it needs a selector list covering the element that actually holds the
  visible glyphs, decided at spec time by reading the UA sheet rather than by testing.

## Lessons learned (from the PR body and code review)

- **A stylesheet insertion mid-file invalidates every downstream line anchor in specs and later greps.**
  This change added ~70 lines at `conversation.css:382`; every anchor below that point (e.g.
  `.tool-row__summary` cited as a padding precedent) shifted by the same amount. Re-resolve a spec's line
  numbers against the current file before trusting them — never copy them forward.
- **`> *` (direct-child) and a bare `pre` (descendant) selector answer different questions when a
  wrapper element is inserted, and mixing them up either breaks the margin reset or breaks the wrapping.**
  `.bubble__markdown > * { margin-block: 0 }` only reaches the new `.code-block` div (now the direct
  child), so the nested `<pre>` takes back its UA `margin-block: 1em` — the explicit `margin-block: 0` on
  `.code-block__body` isn't decoration, it's closing a gap the direct-child selector newly can't reach.
  `.bubble__markdown pre { white-space: pre-wrap }`, being a descendant selector, needed no equivalent
  fix — it still finds the nested `<pre>` regardless of how deep it's wrapped.
