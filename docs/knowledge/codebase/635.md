## Patterns established

- **Prefer restating the property over swapping in a name (Class B over Class C).** Where a sentence
  already states the cited property in full, a re-anchor adds a name without adding information and
  risks the name being wrong later. Both `inboundMessage.ts` fail-closed docstrings took this path,
  converging on the exact form `parseTurnEndPayload` already had — three call sites now read
  identically instead of citing each other or a fourth, dead one.
- **A positional name/ref pairing needs its ref dropped with its name.** `announcedModelStore.ts:7`'s
  `screenSnapshotStore / runConfigStore precedent, #323 / #187` would have silently mis-attributed
  `#323` (the screen-snapshot ticket) to the surviving name if only the name were dropped.
- **A verb removed from the client's modeling is not the same fact as the verb removed from the
  daemon.** #622 removed this client's decode of `screen_snapshot`; the daemon still emits it. The two
  Class E sites encode daemon behaviour and stay true regardless of what this client models — the
  triage table's fifth class exists specifically to keep a blanket "remove all screen_snapshot mentions"
  rule from deleting real, still-true history.
- **Comment-only sweeps at the tail of a removal series compound with each other's precedent set.**
  This ticket reused #637's case-insensitive grep, byte-identical allowlist assertion, and comment-
  stripped residue diff method wholesale, applying it to a disjoint site set (the store/bridge/wire
  series, #618–#622) rather than #637's outbound-command series (#620). See
  [[comment-stripped diff proves a sweep touched no code]].
