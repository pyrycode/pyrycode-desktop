# #648 — hold the working indicator for the whole running turn

Split from #597. Spec `a5c771e`, shipped `22c59fd`, PR #651. Size S (as estimated), not
security-sensitive (no daemon change), code review PASS (one SHOULD FIX, three NITs, none blocking —
see below).

## Summary

`ThinkingIndicator` (`src/renderer/src/screens/conversation/ConversationScreen.tsx`) gated on `phase ===
'thinking'` since #215. The daemon only emits `turn_state{thinking}` while claude produces thinking
text — the first reply token or the first tool step flips `phase` to `responding`, and no further
`turn_state` arrives until the turn ends (pyrycode `cmd/pyry/interactive_turn_v2.go`). A tool-heavy turn
therefore showed nothing on screen for most of its duration, which the operator hit during the first
real use of the desktop app as a client (2026-08-20). `InterruptControl` already modeled "a turn is
running" correctly via the exported, unit-tested `isTurnRunning` (`thinking || responding`); this ticket
makes the indicator agree, rather than inventing a second predicate.

- **Two exported copy constants.** `'Thinking…'` was an inline JSX literal; hoisted unchanged as
  `THINKING_COPY`, joined by a new sibling `WORKING_COPY = 'Working…'`. Both apostrophe-free with the
  U+2026 ellipsis, matching `STALL_COPY`/`API_RETRY_COPY`/`COMPACTING_COPY`. `WORKING_COPY` is
  deliberately generic (not "Running tools…") because the daemon sends no signal finer than `responding`
  inside the tool loop — a more specific copy would be wrong roughly half the time.
- **`shouldShowThinking` broadens by one clause, not renamed, not restructured.** Its phase comparison
  changed from the literal `status.phase === 'thinking'` to `isTurnRunning(status.phase)`; both supersede
  clauses (`apiRetry === null && !compacting`) are textually untouched. The name stays because the
  component it gates (`ThinkingIndicator`) keeps its name too — the ticket froze all ~40 references to
  `ThinkingIndicator`/`.conversation__thinking`/`.bubble--thinking` as out of scope.
- **A new `workingIndicatorState(status)` composes on top of the gate rather than folding into it.** `null`
  when `!shouldShowThinking(status)`; else `'thinking'` when `status.phase === 'thinking'`, else
  `'working'` (`'idle'` is unreachable in that branch, so no third case, no `assertNever`). This is the
  load-bearing design choice of the ticket — see Patterns established below.
- **`ThinkingIndicator`'s prop widens from `isThinking: boolean` to `state: WorkingIndicatorState | null`**
  (`WorkingIndicatorState = 'thinking' | 'working'`). `null` → `null` (same zero-footprint posture as
  before). Otherwise the same `.conversation__thinking` wrapper and `.bubble--thinking` daemon-bubble
  surface, branching only the label. No CSS change — the wrapper is layout-only, the modifier only mutes
  text colour, and both labels reuse it.
- **The mount** (`:183`, unique production call site) becomes
  `<ThinkingIndicator state={workingIndicatorState({ phase, apiRetry, compacting })} />`, reading the
  same three `ThreadStatus` fields as before — no new store read, no new selector.

## Patterns established

- **Compose on a gate, don't retype it, when a proven predicate's assertions are the AC evidence.**
  `shouldShowThinking`'s `ConversationScreen.test.tsx` describe had 9 assertions proving the two
  supersede clauses hold; folding the show/hide decision and the label choice into one new
  union-returning function would have required retyping all of them. Composing `workingIndicatorState`
  on top instead — delegating the whole show/hide decision, adding only the label discriminant — inverted
  exactly 1 of those 9 assertions (the phase-literal one, which the ticket explicitly meant to invert).
  The other 8 stand verbatim as regression evidence that broadening the gate didn't weaken the supersede
  rules. Generalizes beyond this ticket: when a gate function's test suite is the proof a supersede/guard
  rule still holds, prefer composing a new function on top of it over refactoring the gate itself.
- **A type union on the prop, not the store's own type, keeps "no daemon string reaches this view" a
  type-level guarantee across a widening.** The temptation when a boolean prop needs to carry more
  information is to pass `phase: TurnPhase` directly — that reads as less code, but makes `'idle'`
  representable-but-illegal in the branch that renders, and hands the view a store type it has no reason
  to depend on. `WorkingIndicatorState | null` (two client-owned literals plus null) preserves the
  original guarantee's shape while adding exactly the one bit of information the label needs.

## Lessons learned

(From the PR body's own "Lessons learned" section.)

- **Composing on a gate beat retyping it** (see Patterns established above) — the concrete count was 1
  inverted assertion out of 10 in the `shouldShowThinking`/`workingIndicatorState` test surface.
- **`npm run typecheck` is `tsc node && tsc web`, and `&&` short-circuits** — a node-side error hides the
  entire renderer half. For a renderer-only change, run `tsc --noEmit -p tsconfig.web.json` separately
  rather than trusting the combined script. (Corroborates the same lesson recorded on #644.)
- The one-line e2e comment fix (`e2e/queued-backlog-interrupt.spec.ts:37-38`) was verified comment-only by
  diffing with all `//` lines filtered out (0 non-comment changed lines) — `e2e/` sits outside both
  tsconfigs, so `npm run typecheck` covers nothing there either way.
- The worktree ships without `node_modules`; `npm install` is a required first step before any test run.

PASS. One SHOULD FIX, non-blocking: `isTurnRunning`'s own comment block (`:982-983`, plus the test file's
describe/it titles) still asserted the divergence this ticket closed — "the gate is BROADER than
ThinkingIndicator's" — when after this PR the two gates are identical. The new comment on
`shouldShowThinking` correctly says it is "closing the divergence `isTurnRunning`'s own comment flags",
but the flagged comment itself was never updated, so the file briefly contradicted itself. Left for a
follow-up rather than blocking, since it has no runtime or type consequence.

Three NITs, all deferred: a vacuously-true test assertion (guards against a future refactor, kept
deliberately); a stale surface comment in `conversation.css:753` still naming the affordance "the
transient 'Thinking…' affordance" when it now carries both labels (spec froze the CSS files, so
out of this PR's scope); and an a11y note that the indicator now mutates its label in place mid-turn with
no `aria-live` region — not a regression (none of the four sibling indicators carry live-region
attributes either), raised as input to the deferred Figma-side indicator pass rather than a change to
make here.
