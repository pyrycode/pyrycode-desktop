# #649 — label the working indicator with the open tool call

Split from #597, blocked by #648 (merged `22c59fd`). Spec (architect), shipped `46b6790`, PR #654. Size
S (as estimated), not security-sensitive (renderer-only, no `src/main/` or wire change — the string is
already decoded, stored, and rendered through the same React auto-escaping two rows above), code review
PASS (three NITs, none blocking; one flagged risk, not gated — see below).

## Summary

`ThinkingIndicator` (`src/renderer/src/screens/conversation/ConversationScreen.tsx`) held through the
whole running turn since #648, but its `WORKING_COPY` ("Working…") read identically for a 40 ms file
read and a four-minute build. The timeline already carries the answer: a `toolCall` item
(`threadTimeline.ts:42-50`) holds `name` and starts `result: null`, filled in place when the correlated
`toolResult` arrives — so "a tool is open right now" is a pure read over the `items` slice the container
already selects. No new wire field, no daemon change, no new store state, no new subscription.

- **`openToolName(items)`** — a pure descending scan for the last `toolCall` item (in array order) whose
  `result` is still `null`, returning its `name`, or `null` if none is open. `items` is append-only and
  `fillResult` (`threadTimeline.ts:213`) fills in place without reordering, so array order *is* start
  order — the basis of the "most recently started" tie-break. Lives beside `workingIndicatorState`
  rather than in `threadTimeline.ts`, following the file's own precedent that pure derivations over
  store types live with the view that consumes them (`isTurnRunning` is the same shape). Uses a
  descending `for` loop, not `Array.prototype.findLast` — `findLast` is ES2023 and `tsconfig.web.json`
  pins `lib: ["ES2020", …]`, so it would fail `npm run typecheck`.
- **`toolWorkingCopy(name)`** → `` `Running ${name}…` `` — a function rather than a constant because the
  copy has a hole, but both fixed runs (the leading verb, the trailing U+2026) live inside it, so "the
  fixed copy is client-owned and only the name is daemon-supplied" is true of one readable unit.
  Apostrophe-free, matching `THINKING_COPY`/`WORKING_COPY`/`API_RETRY_COPY`/`COMPACTING_COPY`. Returns
  the name verbatim — no trim, no length cap; escaping is the renderer's job (React auto-escapes the
  text child), and pre-escaping here would double-escape.
- **`ThinkingIndicator` gains a second, required prop: `toolName: string | null`** — not a widened
  `WorkingIndicatorState`. `WorkingIndicatorState`, `ThreadStatus`, `shouldShowThinking` and
  `workingIndicatorState` are all untouched; all five existing `<ThinkingIndicator …>` renders and all
  eight `workingIndicatorState(…)` calls keep their assertions verbatim, growing only by a mechanical
  `toolName={null}`. Precedence inside the view: `state === null` → `null` first (so #493's/#496's
  supersede rules still win over an open tool in either phase); then `toolName !== null` → the tool
  label; otherwise the existing phase-derived copy. The label renders as a **single text child**
  (`{toolWorkingCopy(toolName)}`), not constant-plus-span — one text run ellipsizes as one unit, so
  overflow truncates the client `…` away and replaces it with the truncation's own ellipsis, instead of
  producing two.
- **`.bubble--tool-label`** (`conversation.css`) — `.tool-row__summary`'s one-line bound
  (`min-width: 0; overflow: hidden; text-overflow: ellipsis; white-space: nowrap`), applied only on the
  tool branch. Deliberately *not* `.tool-row__name`'s `flex: 0 0 auto` + `nowrap` — that class only gets
  away with never truncating because `.tool-row__summary` sits beside it absorbing the overflow; the
  indicator has no such neighbour. Named `--tool-label`, not `--thinking-tool`, so it does not contain
  `bubble--thinking` as a substring (a modifier that did would make every existing
  `toContain('bubble--thinking')` assertion pass vacuously even if the base class were dropped). The two
  #648 labels render byte-identical markup to before, so their assertions stand as regression evidence.
- **The mount** (`:189`) becomes
  `<ThinkingIndicator state={workingIndicatorState({ phase, apiRetry, compacting })} toolName={openToolName(items)} />`
  — `items` was already in scope for `Timeline`, so no new subscription.

### The invariant reversal

#648 wrote a type-level guarantee into two comments (`:100`, `:803` pre-#649): the indicator's prop is a
closed union of client-owned literals and `null`, so the view "structurally cannot render a daemon
string." #649 deliberately reverses that, per the operator's 2026-08-20 decision — the tool row two lines
above already renders the same `name` as an escaped inert React child, so the indicator adds no exposure
that is not already on screen. What survives the reversal, and is now what both comments say: the *label
choice* (`state`) stays a closed client-owned union; exactly one, separately-typed `toolName` prop
carries the single daemon string, rendered only as an auto-escaped text child, never through an HTML
sink. See [Patterns established](#patterns-established) below.

## Patterns established

- **A blocker's comment can establish an invariant its own child ticket is designed to reverse — read
  the blocker's comments, not just its diff, before spec'ing a reversal.** #648's `:803`/`:100` comments
  stated the guarantee at type level; #649's PO pass, architect spec and implementation all treat
  reconciling those two comments as an AC-level deliverable, not housekeeping. The resolution pattern:
  add a second, narrowly-typed prop rather than widen the existing union, so the surviving half of the
  old guarantee (closed client-owned label choice) is still literally true and still type-checked.
- **A required prop, not optional, when the only reachable detector is `tsc`.** This repo's container
  tests are all unreachable in the populated branch — zustand v5's `useStore` reads `getInitialState()`
  under `renderToStaticMarkup` and never sees `setState` (`ConversationScreen.test.tsx:1737-1742`). An
  optional `toolName` would let the container silently omit the wiring with zero test coverage anywhere;
  making it required means a missed call site fails `npm run typecheck` instead. Cost: five mechanical
  `toolName={null}` additions at pre-existing call sites.
- **Reuse the CSS class that already holds a lone unbounded untrusted string over the more "semantic"
  one that doesn't.** `.tool-row__name` is the obvious reach for a tool name, but its "never
  shrinks or truncates" comment is true only because `.tool-row__summary` sits beside it absorbing
  overflow — a precondition the indicator doesn't have. `.tool-row__summary`'s four-declaration bound
  (`min-width: 0` + `overflow: hidden` + `text-overflow: ellipsis` + `white-space: nowrap`) is the one
  that holds a single unbounded run on its own, and is reused verbatim rather than inventing a second
  mechanism.

## Lessons learned

(From the PR body's own "Two things worth flagging" section.)

- **A spec's stated CSS rationale can be wrong even when the declaration it recommends is still
  correct — measure before repeating it in a comment.** The architect spec said `min-width: 0` was
  load-bearing because a flex item's automatic `min-content` minimum would otherwise push the bubble past
  `.bubble`'s `max-width: min(680px, 75%)`. The developer built a counterfactual matrix instead of taking
  that at face value: all four `min-width` × `overflow` combinations measured 679px against a 396-char
  name, because a flex item's automatic minimum is itself clamped by a definite `max-width`, which
  `.bubble` already sets — a control with `.bubble`'s `max-width` removed confirmed the probe could see
  the failure, blowing out to 3089px. The declaration was kept anyway, for exact parity with its two
  sibling rules, but the comment was rewritten to state the measurement rather than repeat the spec's
  disproven claim. General lesson: a flex item's automatic content-based minimum is itself clamped by any
  definite `max-width` on that item, so `min-width: 0` is inert whenever a `max-width` already caps the
  same axis — measure with a no-`max-width` control before asserting it's load-bearing.
- **A layout AC with no vitest detector is discharged with a one-off measurement, not a reach
  argument.** Renderer tests are server-render only (no DOM, no layout engine), so AC5 (one-line bound)
  had no automated detector by design. The developer ran a one-off Chromium probe over the real CSS and
  the exact emitted markup (44px tall — identical to the generic label — 679px wide, 3089px clipped in
  the no-`max-width` control, composer unmoved across all three label variants) and reported the numbers
  in the PR body rather than in a committed test or e2e spec.
- The worktree ships without `node_modules`; `npm install` is a required first step before any test run
  (same note as #648).

## Code review

PASS. Three NITs, none blocking: the measured-inert `min-width: 0` kept for sibling parity (see Lessons
learned); two comments citing "the ThinkingIndicator idiom" that a future reader could misread out of
context; and a pre-existing missing `aria-live` region on the indicator (not introduced by this ticket —
#648 already flagged and deferred it).

Two things called out as better than the spec asked for: the `min-width: 0` measurement (see above), and
the escaping assertion being quote-anchored (`/\son[a-z]+="/i`) rather than a bare `not.toContain`, which
avoids a guard that would fail on correctly-escaped output.

**One flagged risk, deliberately not gated.** The spec deferred the stale-open-`toolCall` question
(an interrupted turn can leave a `toolCall` permanently `result: null`, so the *next* turn's indicator
could name a stale tool) as "unobserved." Code review found supporting evidence the spec didn't have:
pyrycode **#1243** specifies that an interrupted turn reports `turn_end{cancelled}`, not a `tool_result` —
so the deferred scenario is plausible, not merely hypothetical. Not gated: AC1 pins the derivation as
written, and the fix is pre-described in `openToolName`'s own comment (stop the descending scan at the
first `turnBoundary` item, scoping it to the current turn) if it's ever observed. Flagged as an operator
watch-item for a future real session, not a follow-up ticket.
