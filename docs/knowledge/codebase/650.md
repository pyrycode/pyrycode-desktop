# #650 — start the working indicator locally on send, and clear it robustly

Split from #597, third child (#648 and #649 shipped ahead of it). Spec (architect), shipped
`bbf4d86` (first round) + `8fddea4` (e2e repair), PR #655. Size S (as estimated), not
security-sensitive (renderer-only, no `src/main/` or wire change — same posture as the
unlabelled #317/#493/#496/#648/#649 render-half family). Code review round 1: **FAIL** (e2e blast
radius, see below). Code review round 2: **PASS**.

## Summary

From Enter until the daemon's first event, the app sat in the `idle` phase left over from the
previous turn — the composer's optimistic echo entered the timeline as a `userText` item but
`phase` stayed untouched, so nothing on screen changed. #648 closed the blank window in the
*middle* of a running turn; this closes the one in *front* of it.

- **`TimelineState` gains a sixth field, `localSendPending: boolean`** (`threadTimeline.ts:197`) —
  the first renderer-sourced chrome scalar; `stalled`/`apiRetry`/`compacting` are all daemon facts
  with a daemon edge, this one is opened by the operator's own act with no daemon involvement.
  `initialTimelineState` and `selectLocalSendPending` follow the existing four-scalar precedent.
- **`phase` stays daemon-only.** `TurnPhase` is a wire mirror (`src/shared/wire/types.ts:275`) and
  `ThreadEvent.turnState` is typed `TurnPhase`, so a renderer-local phase value would open a
  type-level hole. Keeping the signal in a separate scalar also makes AC4 (no interrupt arm) hold
  structurally: `InterruptControl`/`isTurnRunning` read `selectPhase` alone and never see it.
- **`userText` opens the window** (`threadTimeline.ts:365-388`) — `localSendPending: true`. This
  needed no new event: `userText` has exactly one production writer (`composerSend.ts`'s
  optimistic echo), sitting below both of `submitMessage`'s `false` returns and above its
  `return true`, so "the arm fired" and "the composer accepted the submit" are the same fact. A
  refused submit (whitespace-only, no active conversation) runs no code and opens nothing (AC1).
- **`turnState` closes it, unconditionally** (`:340`) — any daemon-reported phase, including
  `idle`, is authoritative from that point (AC2). The no-churn early-out gained a second widening,
  `&& !state.localSendPending`, beside the existing `&& !state.stalled` — without it, the common
  case (window opened at `idle`, daemon's terminal `turn_state` is also `idle`) would early-out
  and the window would never come down.
- **`reconnected` closes it** (`:520-570`) — Mode B chrome, the reconnect hazard in its sharpest
  form: opened with no daemon involvement at all, so if the send never reached the daemon there is
  no falling edge to wait for (pyrycode #1062: an abandoned conversation gets no `turn_state{idle}`
  at all). The five-clause `nothingLive` early-out predicate gained a matching fourth clause,
  `!state.localSendPending` (AC3).
- **`reset` closes it for free** (`:508-519`) — returns the shared `initialTimelineState` const, so
  the sixth field clears with zero new lines (AC5, a conversation switch or unpair).
- **`assistantDelta`/`toolUse`/`toolResult`/`turnEnd`/`sessionBoundary`/`stallDetected`/`apiRetry`/
  `compacting`** all carry the flag through unchanged — the deliberate inverse of `stalled`.
  Content can arrive before any `turn_state` (`phase` still `idle`), so clearing on it would blank
  the indicator mid-turn; `turnEnd` is always paired with a separate `turn_state{idle}` that does
  the actual clearing, so clearing on the boundary itself would regress a send issued while the
  previous turn is still finishing.
- **View side: `workingIndicatorStateWithLocalSend(status, localSendPending)`**
  (`ConversationScreen.tsx:1017-1025`) composes *on top of* the frozen `workingIndicatorState` gate
  rather than extending `ThreadStatus` — measured cost of the rejected alternative was 19 inline
  object-literal call sites in `ConversationScreen.test.tsx` breaking as a pure retyping cascade.
  The daemon's answer wins when non-null; otherwise, if a local send is pending, it re-calls the
  same gate with `phase: 'thinking'` substituted. Re-calling rather than writing a fresh expression
  buys three things for free: #493's/#496's supersede clauses are inherited (a live `apiRetry` or
  `compacting` still returns `null`, no second place the rule lives); the label is `'thinking'`,
  which is both honest and flicker-free (the daemon's first real `turn_state{thinking}` then
  changes nothing at the seam, where `'working'` would have flipped Working → Thinking → Working);
  and `workingIndicatorState`'s own "`'idle'` unreachable in the second branch" claim stays true,
  since the synthetic record never carries `'idle'`. The synthetic `phase` never escapes the
  function — not stored, not passed to a view, never seen by `isTurnRunning`.
- **Mount site** (`:201`) — one argument added:
  `workingIndicatorStateWithLocalSend({ phase, apiRetry, compacting }, localSendPending)`.

`ThreadStatus`, `shouldShowThinking` and `workingIndicatorState` are untouched — all 19 existing
pins in `ConversationScreen.test.tsx` stand verbatim, per plan.

## Patterns established

- **Compile-forced ACs are not separable scope, even past five bullet points.** The ticket carried
  6 ACs and an "and" in the title — normally a split signal — but `reduceTimeline`'s 13 return
  literals each write all six fields out, so a 6th `TimelineState` field is a compile error until
  every arm is classified; an "open it" child could not ship without "clear it" coming along, and a
  "clear it" child would only pin lines the first child was already forced to write. Two of the six
  ACs (the no-interrupt guarantee, the reset) cost zero production lines once the signal is a scalar
  beside `phase` — regression pins, not scope. See [[compile-forced-acs-do-not-mean-split]].
- **Reuse a gate by re-calling it with one field substituted, not by extending its input type.**
  `workingIndicatorState({ ...status, phase: 'thinking' })` inherits both supersede clauses with
  zero duplication and picks the flicker-free label as a side effect — the composition-not-extension
  lesson #648 established on the same surface, confirmed a second time. See
  [[reuse-a-gate-by-re-calling-it-with-a-synthetic-input]].
- **A field whose clear rule differs from every existing chrome scalar earns its own classification
  column, not a fold into an existing one.** `localSendPending` is neither `stalled`'s (clears on
  turn activity) nor `apiRetry`/`compacting`'s (clears only on a wire falling edge) shape — it
  clears on *any* `turn_state`, `reconnected`, or `reset`, and is carried through by every other
  arm. The reducer arm table in the spec, written before implementation, is what kept 13 call sites
  from needing case-by-case re-derivation.

## Lessons learned

(From the PR body's own "Lessons learned" section, round 2.)

- **A mount-*timing* change vacuates e2e assertions on the mount transition, invisibly to every
  gate the pipeline runs.** Same selector, same markup, same copy ⇒ `npm test`, `npm run typecheck`
  and QA's gate are all structurally blind, and `e2e/` sits outside both tsconfigs so nothing
  type-checks it either. Round 1 shipped with the PR body's own "No e2e change… no markup, class or
  copy changes" — true about the selector, and exactly the reasoning that hid the break:
  `toBeVisible()` cannot distinguish "mounted by this frame" from "already mounted." Code review
  caught it (round 1 FAIL): `e2e/thread-scroll-pin.spec.ts`'s primer send pre-opened the indicator
  via the new `userText` → `localSendPending: true` path, so `turn_state{thinking}` at `:269`
  produced byte-identical markup and #601's fourth criterion (the chrome-mount viewport shrink)
  became unreachable while the spec stayed green. `e2e/queued-backlog-interrupt.spec.ts`'s
  delivered-echo plant had the same problem in miniature. Detector: grep `e2e/` for the selector,
  then check which frame types each fake's `buildReplyFrames` actually emits — the vacuity in both
  cases came from a fake that never sent a `turn_state` at all. **Any ticket that changes when an
  element mounts owes this sweep**, and it belongs in a shared setup helper's zero-count gate, not
  a one-off read. See [[mount-timing-change-vacuates-e2e-mount-assertions]].
- **A fake that stops short of the daemon's terminal frame is a latent trap, not a shortcut.** Both
  broken specs' fakes ended a turn without the `turn_state{idle}` a real daemon always sends. The
  fix (append the trailing frame to `buildReplyFrames`) is more faithful to the real daemon *and*
  cheaper than defending the divergence — resolved `8fddea4`.
- **A shared `dirty()` test fixture can go silently clean when a new field's clear rule crosses an
  existing event's, in the fixture builder itself.** Both `dirty()` helpers in
  `threadTimeline.test.ts` built state as `userText, delta, turnState{thinking}, apiRetry,
  compacting, stall` — and `turnState` now clears `localSendPending`, so the reset/reconnected
  suites would have silently proved nothing about the new field while still passing green. Fixed by
  moving the `userText` call to *after* the `turnState` call in both fixtures.

## Code review

**Round 1: FAIL.** The production change was right — both compiler-invisible early-outs widened
correctly, the gate reused by re-calling rather than extending. What blocked merge was e2e blast
radius: `e2e/thread-scroll-pin.spec.ts:269-271` (MUST FIX) silently vacuated #601's fourth
criterion, and `e2e/queued-backlog-interrupt.spec.ts` (SHOULD FIX) had the delivered-echo plant
open the same window, making half of its "thinking mounts the indicator" assertion vacuous, plus a
factual claim (indicator and interrupt control share one gate) that #650 itself made untrue. One
NIT: name the `reconnected` early-out's five-clause condition (now `nothingLive`).

**Round 2: PASS.** `npm test` (288 passed across the two touched suites), `npm run typecheck`
(both configs), `npm run build`, and `npx playwright test` (37/37, the whole non-`real-*` suite)
all green.

## Flagged, not absorbed

Per the spec's open question: `toolName={openToolName(items)}` is untouched. An interrupted turn's
permanently-unresolved `toolCall` (#649's recorded, undefended residual) can now surface a stale
tool name one network round-trip sooner than before, since the indicator can open before the
daemon's first event. Outside this ticket's ACs; the remedy is pre-described in `openToolName`'s
own comment (stop the scan at the first `turnBoundary`). Left for PO to scope as its own ticket.
