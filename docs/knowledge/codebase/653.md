# #653 — archiving the open discussion returns to the Channel List

Split from #596 (found by hand-driving the app against a real daemon). Spec (architect), shipped
`349333d`, PR [#659](https://github.com/pyrycode/pyrycode-desktop/pull/659). Size S (as estimated).
Code review: **PASS**, three NITs (all documentation precision, none blocking) and one NIT carried
forward, not gated. Not filed as `security-sensitive` — renderer-only, no `src/main/` or wire change,
the same posture as #652 and the sibling renderer state-clear tickets #530/#531/#593.

## Summary

Archiving the discussion currently open in the thread used to fire `archive_conversation` and close the
Channel Info sheet, and stop there. The row left the Channel List (#469 fixed that half — `is_archived`
rows are filtered out of `partitionActive`), but the thread stayed open: still rendering the archived
discussion's rows, still accepting input.

This is the archive-side reuse of #652's exit decision, named explicitly in that ticket's own docstring
as the intended second consumer. Only the trigger is new — two production files:

- **`src/renderer/src/store/conversationArchivedBridge.ts`** (new, 146 lines, 3 exports) — the derived
  signal. Unlike `conversationCreatedBridge` and `conversationDeletedBridge`, it owns **no wire arm**:
  there is no `conversationArchived` `DaemonEvent`. The decoded `conversationUpdated` payload carries no
  archive flag (`ConversationUpdatedPayload`, 5 fields, no `is_archived` — `inboundMessage.ts` names it
  a tolerated-but-not-copied key) and fires identically on rename and change-workspace, both reachable on
  the open discussion from inside its own thread — so gating on the event's *occurrence* would trade this
  bug for a worse one (exactly what AC3/AC4 exist to fail). The signal is instead **derived from the
  daemon's authoritative conversation list**: `archivedActiveConversationId(conversations,
  activeConversationId)` returns the active id when that id's row in the list carries `is_archived:
  true`, `null` otherwise (not-loaded, no active conversation, row absent — a delete, owned by #652's
  bridge — or row present but unarchived, the AC3/AC4 arm). `subscribeArchivedActiveConversation` runs
  the predicate against every `conversationsReceived` event, reusing `conversationListBridge`'s exported
  `translateConversationsEvent` rather than re-declaring the same `case`. `useArchivedActiveConversationExit`
  is the `useConversationDeletedExit` shape verbatim (ref-held latest callback, empty-dep subscribe
  effect, off-handle cleanup).
- **`src/renderer/src/PairedShell.tsx`** (modified, +17 lines) — one import, one hook call, directly
  beneath the #652 wiring, reusing `exitConversationDeps` **unmodified** (no new deps object) and its
  `getActiveConversation` as both the bridge's id source and `exitActiveConversation`'s own gate, so the
  two structurally cannot disagree about which conversation is on screen.

`exitActiveConversation.ts` and `ConversationScreen.tsx` are both **unchanged** — the exit decision and
its clear-then-navigate ordering (timeline reset → clear active conversation → clear session id →
navigate) are #652's, reused as-is; `onArchive` keeps firing `requestArchiveConversation(...)` then
closing the sheet exactly as before.

**A level predicate, not an edge — this is what makes AC1 trigger-agnostic for free.** It evaluates on
every `conversationsReceived`, with no notion of "the operator clicked Archive," so a re-list caused for
any reason that reveals the flag fires the exit. That includes the case a click-based design could never
reach: a **second client's** archive. pyrycode#881 settles that `conversation_updated` is delivered via
`c.Reply` correlated to the requester — not a broadcast, despite the doc-comment and `conversationListBridge.ts`
calling it one — so another client's archive produces no event on this client at all; the flag only
surfaces on this client's own next `list_conversations`. The level predicate picks it up then: eventually,
not live, and that is a daemon fan-out gap rather than a client design choice.

**No stale-row window, unlike #652's delete path.** #652 navigates one round trip *before* its re-list,
briefly leaving the deleted row clickable on the Channel List. This ticket navigates *on* the re-list
arrival, and the same `conversationsReceived` event has already written `conversationListStore`, from
which `partitionActive` filters the archived row — so the operator lands on a list that already excludes
it, with both listeners running synchronously in one event dispatch regardless of subscription order.

## Patterns established

- **A bridge can own no wire arm and still follow the `translate* → subscribe* → use*` shape.** The
  docstring says so explicitly — "There is no `conversationArchived` `DaemonEvent` to grep for" — so a
  developer hunting for a matching union member finds the explanation instead of a puzzle.
- **Import a sibling's translate function rather than re-declaring its `case`.** This bridge and
  `conversationListBridge` both key off `conversationsReceived`; `translateConversationsEvent` is
  exported once and consumed twice, so there is exactly one place to update if the arm's shape ever
  changes.
- **A level predicate reused across two independent readers of the same event is safe without an
  ordering contract**, the doctrine `conversationListBridge.ts:78-79` already states for
  `conversationCreated`: this bridge reads the *event*, not the store, so it cannot depend on whether
  `ConversationListData`'s listener ran first.
- **Reuse a deps object across a new call site instead of cloning it.** `exitConversationDeps` needed no
  new fields and no new object — the bridge's id getter and the helper's gate read the same module-scope
  arrow, which is what makes the double-gate (bridge decides, helper re-checks) safe by construction.

## Lessons learned

(From the PR body's own "Lessons learned" section.)

- **The AC4 pin needed a sync point, not just a positive assertion.** Asserting `.conversation` → count 1
  right after the picker closes can pass *before* the `conversation_updated` even arrives, staying green
  against a wrongly-gated implementation. Polling the captured envelopes for an outbound `list_conversations`
  appearing **after** the `change_workspace` index — not merely existing, since the connect-time re-list
  is already in the array — is what proves the renderer actually processed the update before the "still
  here" assertion runs.
- **The architect's correction was right and the count was three sites, not two.** `workspace-picker.spec.ts`
  had two vacuous closing blocks (`:143` and `:196`, the recent-pick and create-folder-chain tests), not
  the one the ticket body named; a shared helper (`expectStillInThreadAfterUpdate`) kept both edits to one
  idiom instead of duplicating the sync-point logic.
- **A bridge test's `off` spy has to actually drop the listener to prove anything.** The sibling fakes
  (`conversationDeletedBridge.test.ts`) use an inert `vi.fn()`, so "the off handle stops further delivery"
  can only be asserted as "the spy was called." Making the fake honour the handle turned that into a real
  assertion for one extra line.
- **Negative controls beat assumed non-vacuity.** The author verified both directions by hand: removing
  the `PairedShell` subscription fails the AC1 delta (`resolved to 1 element` after 34 polls); rewriting
  the bridge to gate on `conversationUpdated`'s bare occurrence fails all three AC3/AC4 detectors
  (`conversation-create-rename.spec.ts:100` and both new `workspace-picker` pins).

## Code review

**PASS.** Three NITs, all documentation precision, none blocking:

- **[NIT]** `conversationArchivedBridge.ts:82-85`'s docstring overstates its own `!== null` guard as
  materially load-bearing "twice over." Only the id-guard half is real (a degenerate `''` id is falsy but
  a genuine value); the empty-`conversations`-array half doesn't apply on this path, since an empty array
  and a `null` array both make the predicate return `null` either way — a truthiness check would behave
  identically here, unlike in `conversationListBridge` where `setConversations([])` is independently
  observable. No behaviour change, doc-only.
- **[NIT]** `e2e/workspace-picker.spec.ts:122-125`'s comment claims the sync point covers the `conversations`
  reply landing; it actually only proves the outbound `list_conversations` was sent, not that the reply
  was processed. The gap is unguarded in name only — a predicate inverted on `is_archived` is already
  caught by the unit arm at `conversationArchivedBridge.test.ts:79` and would fail the archive lifecycle
  spec outright — so nothing is structurally missing, only the comment overclaims.
- **[NIT]** Both lifecycle specs' "Gap B" preamble comments still claim the active Channel List never
  filters archived rows, which #469 already fixed. Pre-existing text, correctly left alone under "don't
  refactor adjacent code while you are there," but this PR's new archive-step comments now sit directly
  beneath it. Flagged as a follow-up, not edited here.
- **[NIT, not gated, carried forward from #652]** The inherited absolute-`back` limitation: `exitActiveConversation`
  gates on the id but not the route, so a confirmation landing while the operator has stepped into
  Settings, Archive or Pair-server yanks them to the Channel List anyway. The window is genuinely **wider**
  on this half than #652's — the signal costs two round trips (archive → `conversation_updated` →
  `list_conversations` → `conversations`), and "archive, then go check the Archive screen" is a natural
  operator flow in a way its delete equivalent is not. Unobserved; every move is a clear, so the fail
  direction is benign. Explicitly out of scope — a fix means a route-aware `PairedNav` arm covering both
  the delete and archive halves together, and would push either ticket past S.

Also verified: no `console.*` in the new module (ADR 0007 held), no new `contextBridge`/`ipcMain` surface,
`codegraph_callers translateConversationsEvent` shows exactly the one pre-existing caller plus this PR's
new second consumer, and `grep -rn conversation__back e2e/` after the edit leaves only comment references
— no other spec clicks Back after an Archive pill.
