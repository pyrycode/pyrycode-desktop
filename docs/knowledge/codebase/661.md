# #661 — e2e: funnel every unpaired-launch pairing drive through one shared arrival step

Split from #658 (scaffolding half; #662 relocates the unpaired entry point and is `blockedBy` this
ticket). Spec (architect, self-reviewed security-sensitive), shipped `a3d5983`, PR
[#663](https://github.com/pyrycode/pyrycode-desktop/pull/663). Size S (as estimated). Code review:
**PASS**, one NIT (a line-anchor reference that will drift, not a defect). Filed
`security-sensitive` despite zero production LOC — the step becomes the single chokepoint every e2e
pairing payload flows through.

## Summary

Ten e2e sites each ran the identical six lines after an unpaired launch — locate
`textarea[aria-label="Pairing code"]`, wait for it, fill it, click `Pair`, wait for
`[aria-label="Server key fingerprint"]`, click `Confirm` — the fake-stack fixture
(`launchPairedApp.ts:213-223`) and nine `real-*` specs, each carrying its own inline copy. Zero
production code changed; the diff is entirely under `e2e/`.

They now reach the form through one shared helper: **`e2e/fixtures/pairingArrival.ts`**, exporting
`pairFromUnpairedLaunch(page: Page, payload: string): Promise<void>`. The six lines moved verbatim,
comments included, with no added timeout, no `test.step` wrapper, and no retuned wait. All ten call
sites now read `await pairFromUnpairedLaunch(page, payload)` instead of re-transcribing the drive.

**The seam is drawn after `Confirm`, not after the fill.** The fingerprint assertion and the
`Confirm` click are part of the common segment — drawing the seam earlier would have left ten
duplicated fingerprint/`Confirm` pairs behind and re-created the exact silent fan-out this ticket
exists to remove. Divergence begins strictly past the seam: the fixture's list→thread row click +
Send-enabled wait, and each `real-*` spec's own readiness gate (a seeded row, a Rename pencil, a
save-as-channel affordance) — none of that moved.

**Why this needed a third home, not an import from either existing fixture.** `launchPairedApp.ts`
and `realDaemon.ts` both call `base.extend(...)` at module scope and each export their own `test`;
importing either into the new module would drag a second fixture extension into specs that must
keep using the other one. `pairingArrival.ts` imports only `@playwright/test` — the
`conversationStateFake.ts` convention for a plain, side-effect-free `e2e/fixtures/` module that is
not itself a Playwright fixture.

`e2e/unpair-repair.spec.ts` is deliberately **not** an eleventh call site and is byte-unchanged
(verified empty `git diff`). It holds the same textarea selector twice, but after a mid-session
unpair flip, used as a teardown proof (count 0 while the thread is live, visible after the flip) —
never to drive the form. #662 pins `App.tsx:133`'s mid-session `onUnpaired` flip as out of scope and
uses this file staying green *and* byte-unchanged as the negative control proving that pin held;
touching it here would have silently removed that downstream control.

## Patterns established

- **A completeness sweep proves itself with grep counts, not just green tests.** Neither e2e gate can
  see whether a call site was scoped correctly — `real-*` specs that only skip resolve the import
  graph but never execute the body. The four selector counts (`Pairing code`, `Server key
  fingerprint`, `'Pair', exact: true`, `'Confirm', exact: true`) before/after the sweep are the
  deterministic proof a half-sweep can't hide behind, and code review re-ran them independently
  rather than taking the PR body's word.
- **A module's own header prose is part of the count it's trying to keep deterministic.** The first
  draft of `pairingArrival.ts` used the literal string "Pairing code" in its own invariant-4 comment,
  which pushed the completeness grep to 6 against a predicted 5. Reworded to "pairing-textarea
  locators" — a lesson for any future shared-step module whose home doc references the very selector
  it's meant to consolidate.
- **On a `pyry`-only machine (no Anthropic credential), a `real-*` gate's tally is stronger evidence
  than its skip count.** `docs/knowledge/codebase/420.md` established that a clean skip proves the
  import graph resolves; here, five of the nine `real-*` specs actually *executed* the moved code,
  turning the load-time proof into a behavioural one for the majority of the sweep, and is what
  surfaced a pre-existing, unrelated failure (below) as pre-existing rather than as damage from the
  extraction.
- **Secret hygiene through an extraction is enforced by what the code omits, not by what it checks.**
  `pairingArrival.ts` never asserts on `payload`'s value (no `toHaveValue(payload)`, whose failure
  diff would print it), never interpolates it into a custom assertion message or a `test.step` title,
  and never logs or attaches it — so Playwright's own timeout output names only the selector and the
  timeout. The header states these as invariants precisely because the module is now the one place
  all ten sites' payloads flow through.

## Lessons learned

(From the PR body's own "Lessons learned" section.)

- **A `real-*` run's tally is a stronger gate than its skip count on a `pyry`-only machine.** Worth
  capturing the actual pass/fail/skip tally as the before/after artifact, not just "it skipped" — it
  converts a load-time proof into a behavioural one for most of the sweep, and is what let the
  pre-existing `real-daemon-session-settings.spec.ts` failure (`selectedRadioIn('Sonnet')` timeout,
  well past the pairing seam, reproducing identically on `main`) be dismissed as unrelated rather than
  investigated as regression.
- **A new module's header comment can silently break the very grep that proves the sweep is
  complete.** When a count is the deliverable's proof, prose in the new file counts too — a
  docstring that happens to name the selector it's describing inflates the "occurrences remaining"
  tally exactly like a missed call site would.
- **The worktree ships without `node_modules`, and a piped command can hide that.** The first
  `npm run e2e` failed at `tsc: command not found`, but piping to `tail` swallowed the non-zero exit
  code. `set -o pipefail` (or no pipe at all) is what makes a build failure visible — the same
  stale-`out/` hazard the spec warns about, one step earlier in the pipeline.

## Code review

**PASS.** One finding, non-blocking:

- **[NIT]** `pairingArrival.ts`'s invariant-1 comment pins a line anchor (`private at
  launchPairedApp.ts:129`) that will drift on the next edit to that file, unlike the issue-number and
  symbol-name references elsewhere in the same header, which age better. Not worth a rework cycle;
  worth knowing when #662 next touches this file.

Also verified independently rather than taken on the PR body's word: all four completeness counts
land exactly on predicted post-sweep values; `git diff -- e2e/unpair-repair.spec.ts` is empty; the
diff touches nothing outside `e2e/` (plus the architecture spec); zero `pasteBox`/`fingerprint`
references remain in any of the nine specs and all still import `expect` for other assertions; the
one dialog-scoped `Confirm` locator in `real-claude-permission-modal.spec.ts` correctly survived; and
— the one thing neither e2e gate could prove, since `e2e/` is outside both tsconfigs and four of the
nine `real-*` specs only skipped — all nine call sites were confirmed by hand to destructure `page`
and declare `payload` in scope ahead of the call, so no out-of-scope argument could have stayed green
through a skip.
