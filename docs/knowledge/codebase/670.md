# #670 — two-pane desktop shell with a fixed sidebar

First ticket of the board-#7 desktop-layout series (Figma node 102-4), replacing the mobile-widened
single-screen router. Spec (architect), shipped across two commits on PR
[#700](https://github.com/pyrycode/pyrycode-desktop/pull/700). Size S (as estimated): three production
files (`PairedShell.tsx`, new `pairedShell.css`, `src/main/index.ts`) plus a comment-only correction in
`channels.css`. Code review: **FAIL → rework → PASS** — round 1 found a real remount/state-leak bug the
spec and PR body had both missed; round 2 passed clean. Not `security-sensitive` — renderer layout plus
one Electron window constraint, no transport/IPC/store/wire change.

## Summary

`list` and `thread` stop being mutually-exclusive alternative screens and become the two arms of one
two-pane shell: a fixed 400px Channel List sidebar on the left, always mounted, beside a chat pane that
holds `ConversationScreen` on `thread` and renders `null` on `list`. `minWidth: 800` was added to the
`BrowserWindow` options as a sibling of `width`/`height`; `webPreferences` stayed byte-identical. The
route model (`PairedRoute`, `nextPairedRoute`) and `PairedShellView`'s props signature needed no edit
beyond one new required prop (below) — `open` still lands on `thread`, `back` still lands on `list`, and
`settings`/`archive`/`pairServer` already returned a full-screen `<section>` that replaces the whole
shell, so they satisfy "still open over both panes" for free.

**Round 1 shipped a real bug: switching conversations no longer remounted the thread.** Before this
ticket the sidebar was unmounted while `thread` was up, so every conversation switch necessarily passed
through `list` and remounted `ConversationScreen`. Mounting the sidebar beside the thread made
switching possible with the route staying on `thread` (`open` is absolute) — React reconciled two
`thread` renders at the same element position by **preserving the subtree**, and every piece of
`ConversationScreen`'s screen-local state that five in-file comments say "resets on remount for free"
carried into the new conversation instead. Most visibly: the composer draft — typed in conversation A,
switch to B, press Send, and **A's draft was sent to B.** Code review caught this as the round-1 MUST
FIX; `activateConversation`'s store-side clear (timeline, session id) stayed green throughout, because
none of the leaking state lived in a store.

**The fix:** `PairedShellView` gained a required `paneKey: string | null` prop, applied as
`ConversationScreen`'s `key`. The container (`PairedShell`) holds it in a `useState` beside the nav
`useReducer` and records it at exactly the two production call sites that change the active
conversation — `useConversationCreatedNav`'s payload (FAB create) and `onOpen`'s argument (a sidebar row
click) — verified by grepping every `setActiveConversation`/`activateConversation(` call site in
`src/renderer/src` down to those two. The nullary `open` (a notification click) deliberately records
nothing: it means "show the conversation that's already active," so the pane's identity hasn't moved.
Nothing clears it on exit either — delete, archive, unpair and pair-another all land on a route where
the pane renders `null`, so the subtree is destroyed and a stale key can't preserve anything. Making the
prop required rather than optional turns "a future call site forgets to pass it" into a compile error —
the exact regression class it exists to prevent.

## What shipped

- `src/renderer/src/PairedShell.tsx` — `list` and `thread` collapsed into one switch arm returning
  `div.paired-shell > (div.paired-shell__sidebar > ChannelList) + (div.paired-shell__pane > (thread ?
  ConversationScreen with key={paneKey} : null))`. `assertNever` still narrows on all five route
  members; combining two `case` labels with no statement between them is not a fallthrough.
- `src/renderer/src/pairedShell.css` (new) — `.paired-shell` is `display:flex; box-sizing:border-box`
  (the renderer sets no global `box-sizing`, so `content-box` would add the 20px padding on top of
  `height:100%` and overflow the window by 40px), `gap`/`padding: var(--space-5)` (20px), `background:
  var(--color-surface)`. `.paired-shell__sidebar` is `flex: 0 0 400px` — the one raw-pixel literal in
  the file, structural geometry AC2 names, not a spacing step. `.paired-shell__pane` is `flex: 1 1 0;
  min-width: 0` — load-bearing, not defensive: without it a wide descendant (an unbreakable `<pre>`
  line) would grow the pane past its share and squeeze the sidebar. Geometry is self-checking against
  the 1280×1024 Figma frame: `20 + 400 + 20 + 820 + 20 = 1280`.
- `src/main/index.ts` — `minWidth: 800` added as a sibling of `width`/`height` on the `BrowserWindow`
  options literal; `webPreferences` untouched (AC3).
- `src/renderer/src/screens/channels/channels.css` — comment-only correction: the header used to assert
  `.channel-list` is "NOT a flex item of a paired-shell area" (true before this ticket); now records
  that since #670 it is the child of `.paired-shell__sidebar`, the shell's fixed-400px flex item, and
  still carries no width rule of its own.
- Six e2e specs touched: three strict-mode collisions fixed by scoping to `.conversation` (below), three
  now-vacuous "list visible after back" assertions re-pointed at `.conversation` `toHaveCount(0)`, plus
  a new `e2e/conversation-switch-remount.spec.ts` added in the rework (below).

## Deferred by design

- **The pane card treatment** (the Figma's `rgba(0,0,0,0.3)` wash + rounded corners on both panes) —
  both `.channel-list` and `.conversation` paint `--color-surface` on themselves, the same colour as the
  shell backdrop, so a wash on the wrappers would be painted over; making it visible means deleting a
  declaration from each screen stylesheet, which would push the ticket to five production files. Lands
  with the sidebar-tree/composer tickets that own each pane's interior.
- **A sidebar Archive entry** and the sidebar's host/workspace tree, status dots, and composer row —
  each its own ticket in the board-#7 series.
- **Duplicate accessible names as a live-UI a11y issue** (a screen-reader user on the thread now hears
  two "Archive" buttons — the sidebar entry and the thread's Channel-info action, plus one "Rename" per
  list row). Routed to the sidebar-chrome ticket, which relocates the gear/archive glyphs per the Figma;
  agreed by both the architect (spec § 9) and code review (round 2).
- **The chat pane is an unlabelled region** ([NIT], round 2) — `.paired-shell__pane` wraps a bare
  `<div className="conversation">` with no `role`/`aria-label`, unlike the sidebar's
  `<section aria-label="Conversations">`. Cheap fix, not gating; can ride the sidebar-chrome ticket.

## Patterns established

- **A layout change that makes two previously-separate screens simultaneously mounted can make an
  interaction reachable that used to be impossible — check every "resets on remount" claim in the
  component being co-mounted, not just the props being changed.** `ConversationScreen` had five
  in-comment claims that its screen-local state "resets on remount for free," written when a remount was
  guaranteed by the router; none was wrong when written, and all five broke the moment the sidebar could
  drive a same-route conversation switch. The fix is a `key` prop tied to the identity that used to be
  implied by a remount, recorded at the actual mutation sites rather than derived from a store read.
- **A store-side clear is not a remount, and its tests staying green is not proof the bug doesn't
  exist.** `activateConversation` clearing the timeline and session id made the store-backed half of
  "never a stale thread" pass; every `useState`/`useRef` inside the screen carried over regardless. The
  composer draft was the right regression observable specifically because it is plain `useState` with no
  store behind it — nothing but the subtree's lifetime can explain a surviving value.
- **Mounting a second screen beside an existing one turns every unscoped exact-name Playwright query
  into a strict-mode collision risk.** Three sites broke: `{name:'Archive',exact:true}` (1→2, the
  always-mounted sidebar `ArchiveButton`), `{name:'Rename',exact:true}` (1→1+N, one per list row), and
  the same `Archive` collision in a `real-*` spec gated out of the default config — the silent-green
  compound also seen at #658. Fix: scope the query to the mounted region (`page.locator('.conversation')
  .getByRole(...)`), and diff accessible names across both screens before merging two mount points.
- **An "is the other screen visible?" assertion after a nav-back click goes vacuous the instant both
  screens are permanently mounted** — three sites asserted `.channel-list` visibility post-`back` and
  now pass unconditionally. One (`thread-scroll-pin.spec.ts:428`) wasn't decoration: its comment named it
  an *unmount gate* before re-entering the same row, so the free pass let re-entry race the unmount.
  Re-pointing at `expect(page.locator('.conversation')).toHaveCount(0)` restores the real signal —
  the same "count-0 is the load-bearing proof, not a visible/hidden read" shape as [#652](652.md).
- **`box-sizing` is not global in this renderer's `index.css`** — any new `height:100%` flex container
  with its own padding must set `box-sizing: border-box` itself or overflow the window by the padding.

## Code review — round 1 FAIL, round 2 PASS

Round 1 MUST FIX: the remount/paneKey bug above, reproduced concretely against five separate
screen-local state owners (composer draft, Channel Info sheet, Workspace Picker, Run config sheet,
scroll pin) and reachable specifically *because* the round-1 diff also moved the thread's overlay scrims
(`.status-sheet-overlay`, `.permission-modal-overlay`) from covering the whole window to covering only
the pane — the sidebar row behind an open sheet became clickable. Round 2 verified the fix by
independently re-deriving the set of activation call sites (not taking the PR body's claim on trust),
confirming the never-clear-on-exit reasoning, and re-sweeping every accessible name and vacuity site
itself rather than trusting the developer's sweep. Two NITs carried, neither gating (the unlabelled pane
region, and one geometry read that isn't `expect.poll`-wrapped like its neighbours).

**Round 2 NOTE for the operator, not a gate:** the overlay-scope change is real and correctly disclosed,
but it exposes a **pre-existing** cross-conversation leak in the modal store: `useModalStore`'s
outstanding-prompt slice is global, not conversation-scoped, and `activateConversation` doesn't touch
it, so a permission prompt raised on conversation A can now be reached and left displayed against
conversation B after a sidebar switch (the answer still routes correctly — it's keyed by `modal_id`, not
conversation — so nothing is mis-sent, only mis-displayed). This was already reachable via
back-then-open-another before #670; what changed is that it no longer requires deliberately leaving the
thread. Flagged as a follow-up, out of scope here (`useModalStore` is a store change, and this ticket's
Out of Scope forbade one).

## Testing

`npm test` full suite green (2650+ tests), `npm run build` clean, full default `playwright test` tier
green **39/39** (up from 38 — `conversation-switch-remount.spec.ts` is new). The new spec drives both
paths that leave the route on `thread` (FAB create → switch, sidebar row → switch) in both directions,
using the composer draft as the observable and `.conversation` `toHaveCount(1)` to prove the switch
happened *through* the thread route rather than via the list. Verified RED before the fix.
