# #68 — Decode inbound daemon-message frames onto the daemon-event channel

**Shipped:** 2026-07-04 · **Size:** S · **Labels:** `security-sensitive` · **Scope:** one new transport-layer decoder (`src/main/transport/inboundMessage.ts`) + one consumer edit (`daemonConnection.ts`) · additive, zero consumer cascade · **no new dependency**.
**Spec:** `docs/specs/architecture/68-decode-inbound-daemon-messages.md` · **PR:** [#70](https://github.com/pyrycode/pyrycode-desktop/pull/70).

Fills the **last no-op arm** the [daemon connection](../features/daemon-connection.md) left behind: [#62](62.md) wired the handshake-status path but stubbed the inbound-message arm (`case 'message'` → `// TODO(#12)`). This ticket fills it — decode one decrypted app-message plaintext, route by wire `type`, narrow the payload per-field, and emit the matching `DaemonEvent`, failing closed exactly like the [`parseHelloAck`](../features/hello-exchange.md) boundary. The **background-process, wire-facing half**; the renderer render is a sibling ([#69](https://github.com/pyrycode/pyrycode-desktop/issues/69), thread render-binding). The renderer pipeline it feeds is already complete end-to-end — the [daemon-event channel](../features/daemon-event-channel.md) ([#18](18.md)) carries `messageReceived` / `messagesReceived`, the [bridge](../features/daemon-event-bridge.md) ([#19](19.md)) translates them, the [session store](../features/session-store.md) ([#2](2.md), [ADR 0004](../decisions/0004-renderer-session-store-reducer-wire-types.md)) appends them. See the [inbound-message-decode feature doc](../features/inbound-message-decode.md) for the full contract, data flow, and security properties. Split from the original [#12](https://github.com/pyrycode/pyrycode-desktop/issues/12).

## Patterns established

- **The inbound decode boundary is a new sibling under `transport/`, not an addition to the consumer.** `inboundMessage.ts` joins `helloExchange.ts` (handshake) and `sendMessageEnvelope.ts` (outbound) — one concern per file. It owns the whole untrusted-bytes→typed transition and stays **IPC-free** (never imports `DaemonEvent` / `emitDaemonEvent`); the consumer arm does only the IPC mapping. This is the mirror of the outbound split ([#65](65.md)) and preserves the placement rule from [#62](62.md): a module that touches both a `transport/` primitive and the IPC layer must live above `transport/`.
- **A single throw type is what makes one `catch` sufficient at the consumer.** `parseInboundMessage` collapses oversized / malformed / unparseable / mistyped into one `WireDecodeError`, so the arm's single `try/catch` covers every failure — exactly the shape `parseHelloAck` uses. `null` (a well-formed but unmodeled envelope type) is deliberately **not** a throw: it is not an error, it is out of scope, so it is `return`ed and distinguished from the fail-closed path.
- **The `role` enum check subsumes non-string in one guard and needs no cast.** `role !== 'user' && role !== 'assistant'` both narrows to `WireRole` (no bare cast — an AC) **and** rejects a non-string `role` in the same line, so no separate `requireString(payload, 'role')` + membership check is needed. Its message is **category-only** (`'missing required field: role'`) — interpolating the offending value would echo user conversation content.
- **Category-only error messages, load-bearing at a message boundary.** Unlike the ack path (whose fields are handshake metadata), this payload is user conversation content — `role` / `text` / `conversation_id`. No `WireDecodeError` message interpolates a field value, pinned by a secret-safety test that asserts the thrown message carries none of them. Defense-in-depth today (the consumer drops the caught object) but load-bearing the moment any caller logs the message.
- **Local `isRecord` / `requireString` copies, not a shared validators module.** The codec's `isRecord` is unexported; copying the two helpers locally (as `helloExchange.ts` already does) keeps this file the edge that validates the opaque `payload`. Deliberately **not** refactored into a shared module — the duplication is ~10 trivial lines and the alternative couples three unrelated boundaries.
- **One bad element fails the whole chunk closed.** `parseMessageChunkPayload` maps every element through `parseMessagePayload`; a single invalid element throws, dropping the entire `message_chunk`. An empty `messages: []` is valid (a zero-length batch, harmless downstream) — array-ness, not non-emptiness, is the check.
- **Classify-don't-forward + log-free, inherited unbroken.** The consumer `catch` drops the caught object and emits nothing; the decoder logs nowhere. Pinned by the six-method `console`-spy + a no-secret-in-events assertion (inherited [#5](5.md)/[#7](7.md)/[#22](22.md)/[#50](50.md)/[#62](62.md)).

## Lessons learned

*Lifted from PR #70's "Lessons learned" section.*

- **`encodeEnvelope` caps on encode** (`WireEncodeError` past `MAX_PLAINTEXT_BYTES`), so the oversized-frame test must build its bytes with a raw `TextEncoder` / `JSON.stringify` — otherwise you'd be exercising the encoder's cap, not `parseInboundMessage`'s size guard. The test asserts `bytes.length > MAX_PLAINTEXT_BYTES` up front to prove the input really is oversized before checking it throws.
- **The `role` enum check does double duty** — `!== 'user' && !== 'assistant'` narrows to `WireRole` without a cast **and** subsumes the non-string case in one guard, so no separate `requireString` is needed for `role`; the category-only message keeps the offending role value out of any surfaced error string.

## Deferred / carried forward

- **The renderer render → [#69](https://github.com/pyrycode/pyrycode-desktop/issues/69).** The conversation thread still renders `placeholderMessages`, not the store — render-binding is the open sibling. This ticket produces the events; #69 makes them visible. ([#12](https://github.com/pyrycode/pyrycode-desktop/issues/12) was the original combined ticket, `NOT_PLANNED`; this arm split out of it.)
- **Dedupe / ordering / `conversation_id` scoping → the store ([#2](2.md) / [ADR 0004](../decisions/0004-renderer-session-store-reducer-wire-types.md)).** This module emits in arrival order and does not dedupe or reorder — two frames with the same `message_id` produce two events; the store's `appendUnique` collapses them.
- **Reconnect backfill (`backfill_since` / `message_chunk` on reconnect) → [#34](https://github.com/pyrycode/pyrycode-desktop/issues/34).** The `message_chunk` arm decodes any chunk the daemon sends today, but the reconnect-and-request-backfill choreography that would drive a large chunk is a later ticket.
- **Empty-`message_chunk` handling** is intentionally permissive (emits `messagesReceived` with `[]`). If the daemon is later found to never send empty chunks, dropping them is a trivial future tightening — not this ticket's concern.
