# #696 — Fork the tool row's render on an expanded flag and draw the result body

Split from #669 (sibling: #697, the toggle/state/e2e). Extracts `TimelineRow`'s `toolCall` arm
(introduced #218, extended #230) into an exported `ToolRow({ item, expanded? })` and reverses #230's
"decline to surface `resultSummary`" decision: with `expanded` true and a result present, a body stacks
under the chip drawing the tool's result text. Ships the **pure view only** — nothing passes `expanded`
yet, so the timeline switch still only ever produces the collapsed form. Shipped as PR #699
(`e61549f`), code-review **PASS** (0 MUST FIX, 1 SHOULD FIX, 2 NIT). Size S; two production files
(`ConversationScreen.tsx`, `conversation.css`) plus the test file, +273/-31 lines.

## Summary

Before this ticket, `case 'toolCall'` drew the pending/resolved/error chip inline in `TimelineRow`'s
switch and never read `result.resultSummary` — a decision #230 recorded explicitly ("the Figma mock has
no result-text slot"). This ticket:

- **Extracts the arm into `export function ToolRow({ item, expanded = false })`** (`ConversationScreen.tsx`,
  after the switch). The switch's `case 'toolCall'` collapses to `return <ToolRow item={item} />` —
  mirroring `case 'unrecognizedMessage': return <UnrecognizedRow item={item} />` exactly. `Timeline`
  and `TimelineRow` signatures are **untouched**: the flag is deliberately not threaded through either,
  because doing so would drag #697's "which rows are expanded" state shape into this slice. `ToolRow`
  is exported specifically so the expanded branch is reachable at all — this repo's server-render test
  tier (`environment: 'node'`, no jsdom) has no click, so nothing could otherwise ever set the flag.
- **One derived value drives both new markup facts:** `const body = expanded ? result : null`. Both the
  wrapper's `tool-row--expanded` modifier and the body element read `body`, so a pending row
  (`result === null`) structurally cannot show a body regardless of the flag — AC3 needs no separate
  assertion to hold. Using the narrowed `ToolResult` rather than a `showBody` boolean means the body's
  two branches (`resultSummary === ''` vs. not) read `body` directly with no second null check.
- **The body is a sibling of the chip, not a child.** `.tool-row__chip` is a single-line `inline-flex;
  overflow: hidden` pill; nesting a stacked body inside it would force a new wrapper around the two
  headline `<span>`s and break AC1's byte-identical collapsed markup. `tool-row--expanded` turns
  `.tool-row` into a `flex-direction: column` so the two stack; `align-items: flex-start` is load-bearing
  (the flex default `stretch` would blow the hug-width chip to full row width).
- **The result text's only sink is React text children**: `<pre className="tool-row__result">{body.resultSummary}</pre>`.
  `white-space: pre` (not `pre-wrap`) — machine output where column position is the information sits on
  the "keep its shape and scroll" side of the `conversation.css:365-371` rule (`.unrecognized-row__raw`'s
  side), not the reflowing prose/code-block side; this also discharges AC2's newline-preservation
  requirement (the same defect class #607 fixed for assistant messages). Bounded `max-height: 240px` +
  `overflow: auto`, copied as a literal from `.unrecognized-row__raw:2538` (no max-height token exists;
  every other one in the file is a percentage).
- **Empty result** (`resultSummary === '' `, exact — never `.trim()`, never a falsy check) renders a
  client-owned `<p className="tool-row__empty">{TOOL_RESULT_EMPTY_COPY}</p>` (`'No output'`), exported
  alongside `ToolRow` so the test asserts the constant rather than a duplicated literal (the
  `UNRECOGNIZED_TRUNCATED_COPY` idiom).
- **Error distinguishability** is a `tool-row__body--error` modifier on the body **container** (driven
  by `result.isError`), kept deliberately separate from the pre-existing `tool-row--error` on the row —
  one styles the chip border, the other the body, so #645/#697 can move the body without dragging a
  `.tool-row--error …` descendant selector along.
- **Two stale comments rewritten**, not just left standing: the arm's #230 comment ("`resultSummary` is
  NOT surfaced…") is replaced with the reversal rationale, and the `ConversationScreen.test.tsx:319-321`
  #230/AC4 sentinel test's comment is re-pointed — its assertion (a sentinel string does not leak into a
  *collapsed* render) is now the **collapsed-default guard**, the one test that will catch #697 silently
  making expansion the default.
- **CSS** — four new rules appended to the `.tool-row*` block, no `tokens.css` change (every value is an
  existing token except the 240px literal): `.tool-row--expanded`, `.tool-row__body`,
  `.tool-row__result` (`.unrecognized-row__raw`'s treatment, with `--radius-sm` in place of its
  `--radius-md` so the body reads as one object with the chip above it), `.tool-row__body--error
  .tool-row__result`, `.tool-row__empty`.
- **Nine new test cases** added to `ConversationScreen.test.tsx`'s existing tool-row `describe`, all
  direct `renderToStaticMarkup(<ToolRow …>)` calls: collapsed-default (AC1), expanded success with
  headline-then-body ordering (AC2), expanded error (AC4), newline preservation (AC2), pending ignores
  the flag (AC3), empty result (AC4), whitespace-only is not the empty state (pins `=== ''` against a
  future `.trim()`), escaping (AC5, no apostrophes in the fixture per the file's existing
  `renderToStaticMarkup` note), and one routed-through-`<Timeline>` case proving the switch still
  delegates and passes no flag. All four pre-existing #218/#230 regression tests and
  `interactiveRoundtrip.test.tsx:66` pass untouched; the three `.tool-row` counts in
  `e2e/thread-scroll-pin.spec.ts` are untouched (the wrapper is still exactly one element per row).

`npm test` 465/465 green, `npm run build` clean.

## Patterns established

- **A component gains an inert, unreachable-by-any-current-caller prop specifically so its branch is
  server-render-testable, and is exported for that reason alone.** `ToolRow`'s `expanded` prop has no
  live caller in this ticket — the whole point is making the branch reachable from a test in a
  DOM-less tier. Exporting a sub-component for direct render is this file's established idiom
  (eleven other sub-components are already imported by name in the test file); `UnrecognizedRow`'s own
  expand branch is the one precedent that stayed unexported and correspondingly untested.
- **Extracting an inline switch arm into its own component is markup-neutral and .css-diff-empty when
  done right**, which is what makes "byte-identical collapsed markup" a *verifiable* AC rather than an
  aspiration: `git diff` shows zero deletions in `conversation.css`, and code review confirmed the
  collapsed JSX is element-for-element what the old inline arm produced. React components emit no
  wrapper element, so extraction alone changes nothing rendered.
- **A single derived value (`body = expanded ? result : null`) that both new markup facts read, rather
  than a `showBody` boolean checked twice, keeps a structural AC structural instead of doubly
  asserted.** Prefer this shape whenever two independent-looking render decisions actually share one
  gating condition.
- **A CSS modifier that separates "the row's outcome" from "the body's outcome"** (`tool-row--error` vs.
  `tool-row__body--error`) even though both are driven by the same `isError` boolean, so a later ticket
  moving one hook doesn't drag a selector referencing the other along.
- **A stale in-file comment recording an earlier ticket's decision must be rewritten, not left standing,
  when a later ticket reverses that decision** — `ConversationScreen.tsx`'s comments are the design
  record for this file, and code review treats a comment that states something the code no longer does
  as a real (if non-blocking) finding, per the SHOULD FIX below.

## Lessons learned

*(from the PR #699 body)*

- **`renderToStaticMarkup` prepends a newline inside `<pre>` only when the child string *starts* with
  `\n`** (the HTML parser eats a leading newline in `pre`/`textarea`/`listing`). A `'line one\nline two'`
  fixture asserts as an exact `<pre …>line one\nline two</pre>` substring, but a `'\n\n'` fixture renders
  *three* newlines — assert on the presence of the class there, not on the literal text.
- **Deriving `const body = expanded ? result : null` beats a `showBody` boolean** — it keeps `ToolResult`
  narrowed, so the wrapper modifier and the body element read the same value with no second null check
  and no `!`.
- **The repo's DOM-less unit tier can still be checked visually without adding jsdom**: server-render
  into a scratchpad HTML file with `tokens.css` + the screen stylesheet inlined, then
  `npx playwright screenshot`. Cheaper than launching the Electron app and needs no paired daemon to
  reach the conversation screen — useful for any future CSS-only or markup-fork ticket in this file.

## Code review — one SHOULD FIX, unresolved by design

`conversation.css:1043-1047` — the comment on `.tool-row__body--error .tool-row__result` claims the
modifier sits on the container "so it reaches the empty note too," but the rule selects only
`.tool-row__result`; nothing styles `.tool-row__empty` under an error body, so `{ isError: true,
resultSummary: '' }` draws "No output" identically to a successful empty result. Not a merge blocker —
AC4's distinguishability still holds in the markup (`tool-row__body--error` is rendered and asserted)
and visually at the row level (`tool-row--error` retints the chip border) — but the comment overstates
what the stylesheet does. Left unresolved at merge; **#645 or #697 should either extend the selector to
`.tool-row__body--error .tool-row__empty` or reword the comment** to say the hook is on the container so
#645's field list can inherit it, which is the true half today. Two NITs also carried forward, both
flagged for #697 rather than fixed here: `.tool-row__result` is a scroll region with no `tabindex`
(Blink won't make it keyboard-focusable, inherited verbatim from `.unrecognized-row__raw`'s own gap —
"#697 should give both `overflow:auto` bodies a `tabindex`" per its own PR body), and a
`toContain('class="tool-row"')` assertion is a prefix match weaker than it reads (consistency with a
pre-existing test at `:316`, not a defect).
