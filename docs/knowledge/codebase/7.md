## The two hardening deltas over the proven harness

Both from #29's carried-forward NIT — the async wasm-load surface:

1. **AC4 — the load hang becomes a bounded rejection.** `createNoise(cb)` has no async error callback, so a wasm instantiation that never fires the callback would hang the memoized promise forever. `noiseLib.ts` races the callback against a `setTimeout(timeoutMs)` deadline (default `10_000` ms; test-overridable) and classifies a synchronous throw — either way rejecting with a category-only `NoiseLoadError`. The timer clears on resolve (no leak); the memo nulls on any rejection so a retry starts fresh (no permanently-poisoned promise).
2. **Consolidation.** Two identical `loadNoiseLib` copies existed — the spike's (exported) and `noiseKeyPairGenerator.ts`'s (private), **both** carrying the same hang gap. Closing AC4 in only one leaves the other open. The fix — earmarked by the keygen file's own `#7 consolidates wasm loading` comment — is a **single shared hardened loader** both consumers import. This also collapses two wasm inits into the one process-lived instance the single-instance model wants.

## Patterns established

- **Promote a proven throwaway by `git mv`, not by hand-rewrite.** The 199-line session moves as a rename so the diff is the rename delta + the AC4 forward, not 199 re-typed lines that could silently drift from the proven state machine. The invariants (`Split()` no-swap, empty-AD, fail-closed decrypt, no-use-after-close, log-free) are carried, not re-derived; the ported tests re-assert them. Reuse this shape whenever a spike graduates to production.
- **Two error surfaces, keyed on whether a handle exists.** Load failure (before any handle) is a **factory rejection** — the idiomatic async shape when no `onEvent` sink is driving frames yet. Runtime failure (handle live) is a **typed `error` event** with a static reason. Don't swallow a load rejection into `onEvent` (no handle exists); don't reject the factory for a runtime frame error (the handle is already the surface).
- **One shared hardened effectful loader beats N private copies.** Two duplicate wasm loaders meant one bug fixed twice or (worse) once. Folding both consumers onto a single `transport/noiseLib` loader fixes the hang in one place, gives one process-lived wasm instance (no double-init; concurrent first callers share the memoized promise), and is the elegant close the duplicate's own comment had earmarked.
- **Reset the memo on failure so a transient load error isn't permanent.** Memoizing a `Promise` is right for a once-per-process init, but memoizing a *rejected* promise poisons every later caller. The `.catch` nulls the module-scope memo before re-throwing, so a later `loadNoiseLib()` retries a fresh load. (Same posture the [#43](43.md) `ensure()` memo takes on a rejecting `generate()`.)
- **Mock the effectful edge in its own test file.** The AC4 loader tests mock `noise-c.wasm` at the module boundary; keeping them in a dedicated `noiseLib.test.ts` avoids colliding with `noiseSession.test.ts`'s **real-wasm** round-trip cases (a session-level wasm mock would break those). `vi.resetModules()` + a dynamic `import()` per case resets the module-scope memo without a production test-seam.

## Lessons learned

*Lifted from the PR body's "Lessons learned" + the code-review comment.*

- **The `NoiseInitiator` → `NoiseSession` `replace_all` renamed the factory for free.** `createNoiseInitiator` embeds the type name as a substring, so one rename pass covered `createNoiseInitiator` → `createNoiseSession` and every `NoiseInitiatorConfig`/`Event`/`ErrorReason` too — no separate factory rename needed.
- **Keep the mocked-loader tests out of the real-wasm suite.** Mocking `noise-c.wasm` at the session level would collide with `noiseSession.test.ts`'s real-wasm round-trip; the dedicated `noiseLib.test.ts` (with `vi.mock` + `vi.resetModules()` per case) keeps both suites clean.
- **Minimal-churn: rename only what the spec named.** The `noiseSpike.vectors.json` fixture and the `noiseSpikeResponder/` Go dir kept their `noiseSpike` names — both resolve by relative URL from the renamed test files, so no reference broke. Renaming them would be needless churn (code review flagged the vectors-file name as a cosmetic NIT, non-blocking — optional follow-up rename).
- **The fold-in needed no `deviceKeypair.ts` edit.** Confirmed on read that `ensure()` already clears its memo on a rejecting `generate()`, so the new `NoiseLoadError` rejection flows through unchanged — the blast radius of the consolidation was exactly the one import swap.
