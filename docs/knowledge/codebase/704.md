# #704 — Collapse a workspace group by clicking its row

Split from #671, sibling of #702/#703/#710. Shipped as PR #720 (`f4fde8e` spec commit + `5e99385`
feature commit), code review **PASS** (0 MUST FIX, 0 SHOULD FIX, 1 NIT, security-sensitive gate
satisfied). Size S; 3 production/test files + 1 new e2e spec, ~435 LOC (~145 TSX, ~43 CSS,
~131 unit test, ~141 e2e).

## Summary

The `WorkspaceRow` #703 shipped as an inert `<div>` becomes its group's disclosure control: a real
`<button type="button">` carrying `aria-expanded`, whose click withdraws that group's conversation
rows from the DOM and does nothing else — no navigation, no conversation created, no change to the
active conversation. A new exported `CollapsibleWorkspaceGroup` holds one `useState` boolean per
rendered group and replaces the keyed `<Fragment>` at both `renderBody` call sites (Channels and
Chats); like the `Fragment` it replaced, it emits no element of its own, so the sidebar's flat
sibling sequence — and every existing row locator's ancestry — is unchanged at launch.

```tsx
export function CollapsibleWorkspaceGroup({
  label,
  defaultExpanded = true,   // mount-time seed, not a controlled prop — production never passes it
  children
}: { label: string; defaultExpanded?: boolean; children: ReactNode }): JSX.Element {
  const [expanded, setExpanded] = useState(defaultExpanded)
  return (
    <>
      <WorkspaceRow label={label} expanded={expanded} onToggle={() => setExpanded((open) => !open)} />
      {expanded && children}
    </>
  )
}
```

**State lives in the component, not a store.** ADR 0006's rule ("lowest scope that resets
correctly") settles it, but the *reason* it resets correctly is non-obvious: `PairedShell.tsx:124`
mounts `ChannelList` at the same element position on both the `list` and `thread` routes on
purpose, so React preserves the sidebar's subtree across that flip instead of remounting it — a
fold therefore survives opening a conversation and coming back, and dies with the renderer on app
start. Both halves of AC4 ("renderer-only, unpersisted") come from that scope choice for free; a
store would need manual clearing to get the second half and would break the first.

**Per-tree independence needs no key engineering.** The Channels and Chats blocks are two separate
sibling lists inside `renderBody`, and React scopes reconciliation per sibling list — so the same
`cwd` appearing in both trees yields two distinct `CollapsibleWorkspaceGroup` instances holding two
distinct `useState` cells. There is nothing to implement for AC3; there is only something to not do
(lift the state into a tree-plus-cwd composite key).

**The four attribute sinks a disclosure control invites are declined by name**, the same four
`ConversationScreen.tsx:657-668` already declines for the tool row, recurring here sourced from the
workspace label and from `group.key`:

- **No `aria-label`.** `Collapse ${label}` would put daemon text in an attribute; the accessible
  name already comes from the text child plus `aria-expanded`.
- **No `aria-controls`/`id` pair.** The obvious id source is `group.key` (= `row.cwd`, a daemon
  string) — forbidden as an attribute value and as a lookup key both. `aria-controls` is optional
  in the APG disclosure pattern and both shipped disclosures ship without it; a future `id` would
  come from `useId()`, never the wire.
- **No `title`.** The label ellipsizes, which makes `title={label}` the natural next edit — the
  exact shape CLAUDE.md's 2026-08-20 ruling forbids and #696's review made a MUST FIX.
- **No log line for the toggle.** Any useful one carries the label or the `cwd`; ADR 0007's
  content-free rule forbids it. Zero log calls in the diff.

**The updater is functional**: `setExpanded((open) => !open)`, never `setExpanded(!expanded)` —
matching both shipped disclosure precedents (`ToolRow`, `UnrecognizedRow`) and avoiding a
check-then-act race against React's batching.

## The `<div>` → `<button>` inheritance trap

Two of the six CSS additions to `.channel-list__workspace` are not cosmetic — they repair
inheritance the element swap breaks, and only one is the obvious one:

- `font-family: var(--font-sans)` — a `<button>` does not inherit it, and the label span sets
  size/line/tracking/weight but not family.
- `color: var(--color-on-surface)` — the trap. The folder glyph is `fill="currentColor"` and used
  to inherit `--color-on-surface` from `.channel-list`; a `<button>` resets `color` to the UA
  `buttontext`, which would mis-paint the glyph visibly in the dark scheme. Every other button in
  `channels.css` (`__save`, `__rename`, `__archive`, `__settings`, `__fab`) already sets `color`
  explicitly for the same reason — that convention *was* the evidence this was load-bearing, not a
  guess.

The remaining four (`appearance`/`border`/`background`/`cursor`/`text-align: left`) are
`.channel-list__row-open`'s button reset, verbatim, plus `border-radius: var(--radius-xs)` — an
exact match for Figma's `rounded-[6px]` (`106:3098`), skipped by #703 because there was no fill for
it to clip. The row is styled identically in both disclosure states (no chevron, no state-specific
Figma treatment); a hover (`--color-surface-container`) and `:focus-visible` outline
(`1px solid var(--color-outline)`) are the file's own interactive-row convention, since the design
pins neither.

## The marker trap #703 left, re-verified rather than assumed safe

`ChannelList.test.tsx:76`'s `WORKSPACE_ROW_MARKER = 'class="channel-list__workspace"'` is an exact
attribute-value substring. The `<div>` → `<button>` swap keeps it matching (JSX prop order is
unchanged), but a collapsed-state modifier class would silently stop matching it and zero #703's
counts rather than fail them. **The class token stays sole in both states** — the Figma draws no
collapsed appearance, so there is nothing to style differently anyway. A future collapsed style
must use the attribute selector `.channel-list__workspace[aria-expanded='false']`, never a second
class; the CSS comment says so.

A new unit test pins this directly rather than trusting the "no modifier added" claim: the
collapsed and expanded opening tags are asserted to differ *only* in the `aria-expanded` value
(`expect(collapsed).toBe(expanded.replace(EXPANDED_MARKER, COLLAPSED_MARKER))`).

## The role-locator hazard — the third one, past class and text

#703 and #710 each closed a class-token hazard and a text hazard (Playwright strict mode: a new
element joining an existing locator's match set fails at launch, not at assertion). Turning an
existing element into a `<button>` opens a hazard those tickets never had: **role locators**.
Re-checked rather than inherited — zero unfiltered `getByRole('button')` or `locator('button')`
anywhere in `e2e/`; every one of the suite's named button queries is scoped to a string that is not
a case-insensitive substring of the accessible name the fake fixtures produce (`workspace`, since
every fixture seeds `cwd: '/fake/workspace'`). The near-miss: `workspace-picker.spec.ts` queries
`{ name: 'Change workspace' }`, which is *longer* than `"workspace"`, so containment runs the safe
direction. `.channel-list__workspace` appears in `e2e/` only in the new spec.

**Zero existing `e2e/` files edited.** Groups render expanded by default, so launch-time markup is
byte-identical; the pre-existing 40-spec default tier passed unchanged, with the new
`e2e/workspace-collapse.spec.ts` (one promoted seed, FAB-minted second row landing in the same
workspace but the other tree — AC3's scenario for free off `conversationStateFake`'s
`DEFAULT_CREATED_CWD`) added beside it.

## Patterns established

- **Every disclosure control ships as a pair: a `default*`-seeded prop plus an export, and a
  Playwright spec for the click.** `vitest` here runs `environment: 'node'` with no jsdom/RTL, so
  `renderToStaticMarkup` never re-renders and a unit test cannot click — `ToolRow` established this
  shape, `CollapsibleWorkspaceGroup` is the second instance of it.
- **An attribute-prohibition assertion must slice the opening tag, not scan the document.**
  `aria-label`/`title` legitimately appear elsewhere in the same render (FAB, gear, Archive,
  Rename, Save-as); a document-wide `not.toContain` is either wrong or silently vacuous.
  `workspaceRowTagsIn` (scan to the marker, then to the next unescaped `>`) is the reusable shape.
- **A marker pinned as an exact attribute-value substring turns a modifier class into a
  silent-green hazard, not a failing one.** Keep the class token sole; style state variants off an
  attribute selector instead.
- **Converting a `<div>` to a `<button>` is a three-part checklist, not a one-line diff**: the
  element, the inheritance repair (`font-family` + `color`, the latter easy to miss when a glyph
  uses `currentColor`), and a fresh e2e role-locator sweep.

verdict PASS across all nine categories; code review independently confirmed both of its two
hand-offs — the attribute assertion slices the tag not the document, and the state updater is the

click handler's entire body is the state flip, so "no other effect" (AC2) is structural.
