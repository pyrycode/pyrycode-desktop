## Summary

The sidebar's non-promoted tree header carried the mobile-era literal "Recent discussions"; the
desktop design (Figma `106:3257`, text child `106:3258`) names it "Chats". The production edit is one
JSX text child, `ChannelList.tsx:270`, with its adjacent comment reworded at `:271`. No CSS changed —
`channels.css:31-39`'s existing `.channel-list__section-header` rule already matched the Figma node's
type, color and opacity exactly.

- **No module-level constant.** The ticket body's Context paragraph called for "a client-owned
  module-level constant"; the architect read the binding half of that requirement as *never a daemon
  string*, which an inline literal satisfies by construction. Naming a const for "Chats" while its
  sibling "Channels" stays inline one JSX block above (`:256`) would have been asymmetric refactoring
  CLAUDE.md forbids. Code review agreed explicitly — flagged as "not a finding" rather than left
  silent, since the ticket body's own wording could otherwise read as a missed requirement.
- **The literal's fan-out was the real work: 31 sites across 8 files**, 28 of them a bare
  `replace_all` (six `ChannelList.test.tsx` assertions, the two promote-spec live locators, and 21
  comments naming the old label). `discussions` identifiers, CSS classes and store fields were
  explicitly out of scope — only the rendered label changed.
- **One assertion strengthened rather than substituted**: `ChannelList.test.tsx:99`
  (discussions-only case) moved from a bare `toContain('Chats')` to the anchored
  `toContain('>Chats<')`. A bare substring check cannot fail in the direction AC1 cares about — it
  would still pass against a header reading "Recent Chats" — and the anchored form is valid because
  `renderToStaticMarkup` emits no comment markers around a single static text child.
- **Three comments were restated, not substituted**, because they argued a conclusion from the old
  literal rather than merely naming it: `save-as-channel-promote.spec.ts:107`,
  `real-daemon-promote.spec.ts:83`, `ChannelList.test.tsx:97` (pre-edit line numbers) each justified
  their locator/assertion as unambiguous because "Recent discussions" does not contain "Channels".
  The restated form: "Chats" and "Channels" share only the prefix "Cha", and neither is a substring of
  the other — case-insensitively too, stated explicitly on the two Playwright comments because
  `hasText` with a string argument is a case-insensitive match, and deliberately **not** added to the
  `toContain` comment, since `toContain` is case-sensitive.
- **The real-tier locator (`real-daemon-promote.spec.ts:88`, pre-edit) is the silent-green hazard in
  this shape.** That spec is skipped by default, so a stale locator there would stay green and the
  run would still exit 0. AC2's grep-clean check (`grep -rn "Recent discussions" src/ e2e/` — no
  output) is the substitute completion signal that covers it, since the real-tier locator is one of
  the 31 occurrences a clean grep proves was updated. `playwright test --config
  playwright.real-claude.config.ts --list` (all 9 real-tier specs still enumerate) is the companion
  compile check for a tier neither the default `npm test` nor the default `npm run e2e` ever loads.
- **`docs/` was correctly left untouched** — nine files there are the shipped historical record of
  #141/#423/#440/#443/#451/#452 and stay as written; AC2's grep was scoped to `src/` and `e2e/` only.

`npm test` (69 passed in the touched suite; 2700 passed repo-wide), `npm run build`, and
`npx playwright test e2e/save-as-channel-promote.spec.ts` (2 passed) all green. Code review re-grepped
`.channel-list__section-header`'s live consumers independently (4 sites: `ChannelList.tsx:256,270`
plus the two `hasText` pairs) and confirmed the Figma node via `get_metadata` on `106:3257` (a single
TEXT child reading "Chats", no icon/badge/chevron) rather than trusting the diff.

## Patterns established

- **A locator/assertion comment that argues *why* a substring match is safe must be restated, not
  substituted, when the literal it argues from changes** — the conclusion can survive (as it did here:
  "Chats"/"Channels" share only a prefix) while the argument's premise (the old pair's non-overlap)
  no longer holds without re-deriving it against the new pair.
- **A skipped-by-default e2e tier turns "grep is clean" into the completion signal**, not a shortcut
  taken in its place. Any string-literal rename that touches a locator gated behind a real-daemon/
  real-claude tier should pair its production-code test with a repo-wide grep for the old literal,
  since the tier itself cannot fail red to catch a miss.

## Lessons learned

*(from the PR #711 body, lightly edited)*

- `toContain('Chats')` cannot fail in the direction AC1 cares about — it passes against a header
  reading "Recent Chats". The anchored `toContain('>Chats<')` is a genuine exact-text pin here because
  `renderToStaticMarkup` emits no comment markers around a single static text child (confirmed against
  the RED run's received markup, not assumed).
- The real-tier locator is the silent-green hazard in this shape: `real-daemon-promote.spec.ts` is
  skipped by default, so a stale locator there leaves the run exit-0. A grep-clean assertion is the
  only completion signal that covers it. `--list` against the real-claude config is a cheap compile
  check for specs the default run never loads.
- `hasText` with a *string* argument is a case-insensitive substring match. Worth stating in the
  comment rather than leaving the reader to assume case-sensitivity, since the new pair ("Chats"/
  "Channels") is a much closer near-miss than the old one ("Recent discussions"/"Channels").
