# #710 — Head each sidebar tree with a host row

Split from #702 (sibling of [#709](709.md), the "Chats" relabel). Shipped as PR #715
(`cad13f6` spec commit + `444a725` feature commit), code review **PASS** (0 MUST FIX, 0 SHOULD FIX,
1 NIT). Size S; 3 files, ~110 LOC (~35 TSX, ~25 CSS, ~50 test).

## Summary

Each sidebar tree — Channels and Chats — now renders a host row directly below its section label
and above its conversation rows, naming the machine the tree's conversations live on (Figma
`106:3094`, first child of `Host container` `106:3104`). The row is a new module-local, nullary
`HostRow()` in `ChannelList.tsx`, rendered a second time — once per tree, inside each existing
`length > 0` gate (`:254`/`:265`/`:268` unchanged) — so "a tree with zero rows renders neither
label nor host row" holds by construction, no new condition added. It's a plain non-interactive
`<div className="channel-list__host">` holding a 12px inline Material `dns` glyph (the file's
sixth inline glyph, alongside `SettingsButton`/`ArchiveButton`/`NewConversationFab`/rename/save)
and a `<span className="channel-list__host-label">`. Three new CSS rules in `channels.css`, every
value a token except the 12px icon box (structural geometry, the FAB's 56px-square precedent).

**The visible copy is `'Server'`, a client-owned module constant (`HOST_ROW_LABEL`)** — never
`serverInfoStore`'s `serverId` (which `ServerRow.tsx:37` legitimately renders in Settings, a
details surface, but would read as an invented machine name here) and never the Figma node's own
placeholder text ("Pyrybox", a real machine name standing in for the operator-typed label #688
will supply). "Server" was picked over the design's "Host" because it's already the app's
user-facing word for this machine (`SERVER_ROW_LABEL`, "Pair another server" in Settings), so the
sidebar and Settings → Connection read as one concept. The *structural* naming (`HostRow`,
`.channel-list__host`, `HOST_ROW_LABEL`) deliberately stays "host" — the design's word, and what
#672 (status dots)/#688 (operator label)/#703 (workspace grouping) stack onto — so the asymmetry
between code vocabulary and shipped copy reads as intentional.

**No store, no IPC, no props.** `HostRow` reads nothing and is not exported (the
`SettingsButton`/`ArchiveButton` posture) — proven only through `ChannelListView`. Not interactive:
no `<button>`, no `onClick`, no `aria-label` (collapse is #704; the two connection dots are #672
and get no pre-rendered slot).

## The two selector hazards this ticket exists to avoid

Both promote specs locate their section headers as `.channel-list__section-header` + `hasText`
(`save-as-channel-promote.spec.ts:109-113`, `real-daemon-promote.spec.ts:86-89`) then assert
`toBeVisible()`, which is Playwright strict-mode checked (AC4). Separately, `launchPairedApp.ts:224`
clicks an *unfiltered* `.channel-list__row-open`, ridden by 28 specs at fixture launch (AC5) — a
much larger blast radius, since a violation there fires at launch across every one of those specs
rather than as an assertion failure in two.

Both are closed by construction, independently:

- **Class-token guard.** `channel-list__host`/`__host-icon`/`__host-label` share no class token
  *and no substring* with `channel-list__row`, `__row-open`, `__section-header`, or any other
  existing selector in the file — so even a hypothetical `[class*=…]` selector would miss it.
- **Text guard.** The shipped label ("Server") contains neither "Channels" nor "Chats", case-folded
  either direction — `hasText` with a string argument is a case-insensitive substring match.

**Zero files under `e2e/` were edited.** The existing default-tier suite (`npm run e2e`, 40/40)
going green *unchanged* is the real proof for AC4/AC5; the six new `ChannelList.test.tsx` cases are
the unit-level mirror, not a substitute — see the `bothTrees()` fixture and the
`countOf`/`hostLabelsIn` helpers added there, which count exact `class="…"` attribute-value
substrings against `renderToStaticMarkup` output (no comment markers, so a closing quote is what
keeps `channel-list__host` from also matching `channel-list__host-icon`).

## Patterns established

- **A repeated per-section heading element belongs *inside* the same `length > 0` gate that
  decides the section header**, not beside it — that's what makes the zero-row-renders-nothing
  invariant hold for free, and what keeps the promote specs' "zero-row section → no header" proxy
  valid for a second, distinct element added under it.
- **When Playwright locators run in strict mode, a newly added sibling element is a *launch-time*
  hazard, not merely an assertion hazard, if it joins an existing unfiltered locator's match set.**
  The guard has two independent halves — no shared class token/substring, and no text overlap — and
  both are cheap to satisfy deliberately rather than discovering the violation via a fixture crash.

## Lessons learned

*(from the PR #715 body)*

- Exact-substring counting over `renderToStaticMarkup` output is a precise structural assertion
  because it emits no comment markers — and the closing quote is load-bearing:
  `class="channel-list__row"` does not match `class="channel-list__row-open"`, and
  `class="channel-list__host"` does not match `__host-icon`/`__host-label`.
- Placing the row inside the existing `length > 0` gate rather than beside it satisfies "a zero-row
  tree renders neither label nor host row" with no new condition, and keeps intact the promote
  specs' use of a zero-row section as their proxy for "the row moved sections".
- The `--text-label-large-*` token set (14/20/0.1/500) is an exact match for the design's M3
  title-small, so the type mapping needed no nearest-neighbour note despite the token names
  differing from the Figma layer names.

## Code review — PR #715, PASS (0 MUST FIX, 0 SHOULD FIX, 1 NIT)

- **[NIT]** `ChannelList.test.tsx`'s AC4 text guard hardcodes the lowercased needles `'channels'`/
  `'chats'` rather than deriving them from the headers actually rendered in the same markup — a
  future header rename (the #709 shape) would leave the guard passing while no longer guarding the
  new word. Not blocking; the independent class-token guard closes AC4 on its own. Left unfixed —
  a defense-in-depth cleanup on a passing test, not a correctness gap.

Visual fidelity was checked arithmetically against `get_metadata`/`get_variable_defs` on Figma
`106:3094`/`106:3104` (row height, padding, icon↔label gap, glyph box, type, colour), not eyeballed
— exact match on every measured axis. AC5's blast radius was independently re-grepped (the
`.filter({ has: … })` chains and `toHaveCount` assertions in the archive-lifecycle specs, plus
`section[aria-label="Conversations"]`) rather than taken from the spec.
