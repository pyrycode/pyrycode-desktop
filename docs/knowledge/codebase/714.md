## Summary

The wire's `ModelAnnouncedPayload` has always carried `conversation_id`, and
`parseModelAnnouncedPayload` (`inboundMessage.ts`) has always required it as a string — but the
transport's `model-announced` emit discarded it, on the same single-active-conversation assumption
#724 retired for `turnState`, #732 for `stallDetected`, #737 for `apiRetry` and #742 for
`compacting`. **This is the fifth and last arm in the family.** No daemon change, no wire-type
change, no visible behaviour change; the announced-model store keeps holding a single value
replaced per announcement. The per-conversation consumer is #588 / #674.

`DaemonEvent`'s `modelAnnounced` arm (`src/shared/ipc/events.ts:257` post-diff) gains
`conversationId: string`, required, not optional — an optional routing key would invite
`?? activeConversation` fallbacks in the eventual #674 consumer:

```ts
| { type: 'modelAnnounced'; model: string; truncated: boolean; conversationId: string }
```

The emit (`src/main/daemonConnection.ts:704-709` post-diff) copies it **by name** off the
already-decoded payload, alongside `model` and `truncated`, never a spread:

```ts
emitDaemonEvent(sink, {
  type: 'modelAnnounced',
  model: inbound.modelAnnounced.model,
  truncated: inbound.modelAnnounced.truncated,
  conversationId: inbound.modelAnnounced.conversation_id
})
```

The id **stops at the announced-model bridge**. `translateModelAnnounced`
(`src/renderer/src/store/announcedModelBridge.ts:39-45`) still rebuilds a fresh `{ model,
truncated }` literal read by name; `announcedModelBridge.ts` and `announcedModelStore.ts` are
untouched by this diff — neither appears in `git diff --name-only`. That seam's existing
expected-*output* assertions in `announcedModelBridge.test.ts` needed no edit: `toEqual` fails on
an extra own enumerable property, so leaving them alone **is** the AC4 proof, confirmed by
measurement — the whole bridge suite ran 15/15 green with the 11 input literals widened and every
output assertion left at two fields.

### The security argument this arm had to rebuild, not patch

`model-announced`'s doc comment argued safety **arithmetically**: dropping the id left "exactly one
untrusted string crosses IPC on this arm rather than two." Adding a string makes that sentence
numerically false, and the tempting repair — changing "one" to "two" — would be the worst available
outcome, since it would assert `conversationId` is untrusted text of `model`'s kind, which the
ticket's security note explicitly denies. The rebuilt block (`events.ts:240-256`,
`daemonConnection.ts:692-703` post-diff) replaces the count with the routing-key argument the
family already established: a daemon-asserted routing key, not operator or model-influenced text;
never markup, a filename, a cache key, a lookup path, an attribute or a URL; reaches no log sink;
stops at the announced-model bridge. It names the retirement explicitly — the count argument "used
to be ARITHMETIC … REPLACED, not renumbered" — the same self-naming shape #742's rebuild used for
`compacting`'s absence-based claim. `model`'s own untrusted-text warnings are kept in full and
stated as distinct from the id's.

Three drop-claims retired, not two — the ticket body's own earlier draft undercounted this by one:
`daemonConnection.ts` (the arithmetic clause), `events.ts` (the arm doc), and
`inboundMessage.ts` (the decode-side paragraph, comment-only — `parseModelAnnouncedPayload` itself
is byte-identical). Every sibling arm that still truthfully drops the id (`toolUse`, `toolResult`,
`unrecognizedMessage`) keeps its claim; no cross-reference was repointed at a sibling, since this is
the last arm in the family and there is no still-dropping status neighbour left to name.

## Patterns established

- **A count-based security claim cannot be retired by re-counting.** "Exactly one untrusted string
  … rather than two" is arithmetic, not absence-based like `compacting`'s retired claim was — the
  tempting repair (one → two) is actively wrong, since it asserts a false equivalence between the
  routing key and the untrusted text. Naming the retired argument in the past tense and repudiating
  it in the same breath ("used to be ARITHMETIC … REPLACED, not renumbered") states the rule and
  forecloses the repair simultaneously. A `git diff --word-diff=porcelain` removed-token multiset is
  the cheap confirmation that the argument was replaced rather than softened.
- **The last arm in a five-ticket family needs no neighbour to compare against, and forcing one in
  would make the prose wrong on arrival.** #724/#732/#737/#742 each justified their crossing partly
  by contrast with a sibling that still dropped the id; #714 has no such sibling left among the
  turn-stream-adjacent arms, so its prose states the rule (identity report, no `turn_id`, opens and
  closes no turn) on its own terms rather than reaching for a comparison that would go false the
  moment it landed.
- **A count-to-zero retirement gate can return a non-zero, correct result**, and the fix is grading
  the prose against a positive claim list rather than trusting the gate's arithmetic. The gate here
  returned two blocks on the first re-run — one a true, adjacent `truncated` claim
  (`daemonConnection.ts:690`) sitting two lines from the false one, the other a widened input
  literal's four-line window brushing a pre-existing truthiness-guard comment
  (`announcedModelBridge.test.ts:171`) — both correctly left standing. Driving either to zero would
  have deleted a true claim.
- **A `replace_all` rename hazard, flagged by the previous ticket, resolved by hand.** #742's review
  predicted that renaming `daemonConnection.test.ts`'s "N modeled properties" test name from three to
  four would collide with two pre-existing "four" instances; it did, and line-by-line editing (not
  `replace_all`) is what kept `compacting`'s own "three" instance untouched.
- **`toEqual` earlier in a test hides the assertion below it, again.** The round-trip test's
  `not.toContain('conv-1')` leak guard never surfaced as a failure during the RED phase, because the
  `toEqual` above it threw first — the same trap #742 hit. Inverting the guard had to be a
  deliberate edit, verified by re-running after the `toEqual` was fixed and confirming the guard
  then failed on its own.

## Lessons learned

*(from the PR #745 body, verbatim)*

- **A count-based safety claim cannot be retired by re-counting.** The clause here was arithmetic —
  *"exactly one untrusted string crosses IPC on this arm rather than two."* Changing "one" to "two"
  satisfies grammar and asserts something false: that `conversationId` is untrusted text of
  `model`'s kind. Naming the retired argument in the past tense and repudiating it
  (`used to be ARITHMETIC … REPLACED, not renumbered`) states the rule *and* forecloses the tempting
  repair. A `--word-diff=porcelain` removed-token multiset is the cheap confirmation that the
  argument was replaced rather than softened.
- **A zero-returning retirement gate can be unreachable by construction, and that is not a
  failure.** Driving this one to zero would have required deleting the true `truncated` claim two
  lines above the false one, because the gate's window only tests co-occurrence of a subject
  anchor, a drop-word and the id token. Grading claim-by-claim against a positive list is what
  distinguishes "retired" from "deleted" — a gate that rewards deletion cannot be the only check.
- **Re-wrapping a comment silently creates the orphan the previous ticket was NIT'd for.** The first
  pass on `inboundMessage.ts` left a 22-char stub line — byte-for-byte the shape #744's review
  flagged. Nothing catches it: no formatter is configured, and typecheck and vitest are both blind
  to comment shape. An `awk '{print length}'` scan of the edited region is what caught it.
- **`announcedModelBridge.ts:30` cites `daemonConnection.ts:686` by line, and that citation is
  live.** Keeping the two lines above the edit region line-count-neutral preserved it for free; the
  four `announcedModelStore.ts` citations into `events.ts` were already ~26 lines stale before this
  ticket, so neutrality there would have bought nothing.
- **The `'…N modeled properties…'` test-name family now has three members reading "four"** (this
  arm's plus two pre-existing). The spec measured and accepted this; the collision costs nothing
  further because this is the family's last arm, but any future edit to those names must be by
  line, never `replace_all`.
