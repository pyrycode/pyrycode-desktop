## Summary

Each sidebar host row (#710) now ends with two 6px, label-less connection dots at its trailing
edge — the host (daemon) leg first, the relay leg second, 6px apart, inside the row's existing
16px right inset. Both legs already existed and so did the mapping that turns them into a display
state: #330 shipped `relayLeg`/`daemonLeg`/`ConnectionLeg`/`LegCategory` plus a category → colour
CSS contract, rendering the pair as two *labelled* dots on the conversation status row. This
ticket is a second presentation of that same mapping, not a new indicator — nothing crosses IPC,
no wire type moves, no store is added.

`ChannelList.tsx` gains two new components:

- `HostConnectionDots({ host, relay }): JSX.Element` — **exported** pure view. Renders
  `<span className="channel-list__host-status">` holding two
  `<span className="channel-list__host-dot conn-dot--{category}" role="img" aria-label={leg.label} />`,
  host first. Exported for the same reason `ConnectionStatusIndicator` is: the only seam through
  which the unit tier reaches the full category × label matrix.
- `HostConnectionDotsControl(): JSX.Element` — module-local, store-bound. Reads
  `useSessionStore(selectStatus)` → `daemonLeg` and `useRelayLinkStore(selectRelayLinkStatus)` →
  `relayLeg` through their shipped narrow selectors, and passes the mapped legs down. Mounted as
  `HostRow`'s last child, so a relay flap re-renders the four dots and not a single conversation
  row.

`relayLeg`/`daemonLeg`/`ConnectionLeg` are imported unchanged from
`conversation/ConversationScreen.tsx` — the established cross-screen-import idiom in this
codebase (`ArchiveScreen`, `WorkspacePickerSheet`, `DefaultWorkspaceRow` all do the same). No
import cycle: `ConversationScreen.tsx` reaches back into `channels/` only for
`channelListViewModel` and `RenameConversationDialog`, neither of which imports `ChannelList.tsx`.

## Patterns established

- **A shared mapping's reuse contract can exist at two levels, and "no second copy" has to be
  checked at both.** #330 already split the TypeScript mapping (`relayLeg`/`daemonLeg`) from its
  CSS colour binding (`.conn-dot--up/--in-progress/--down`, separate from the 8px `.conn-dot`
  geometry base). This ticket reused the TS half by cross-screen import and the CSS half by
  wearing the colour modifier *without* its geometry base — `.channel-list__host-dot` in
  `channels.css` supplies 6px geometry only. `grep -rn "color-success" src/renderer
  --include='*.css'` proving exactly one match is the check that both levels stayed single-copy.
- **A modifier class worn without its base class reads as a mistake unless the CSS says so out
  loud.** The rule needs a comment stating the colour is intentionally sourced from another file's
  modifier and must not be re-declared locally — otherwise a future reader "fixes" the apparent
  oversight into a second copy of the contract.
- **A cross-file CSS dependency introduced this way is invisible to a node-environment unit
  tier.** `npm test` asserts markup, never computed colour, so a class rename or deletion in
  `conversation.css` would silently make the sidebar dots render at 6px with no background. The
  mitigation is a comment on the source rules naming the new consumer — belt (defensive comment)
  and suspenders (the TS import already makes the CSS import module-graph-enforced, since
  `ConversationScreen.tsx` imports `./conversation.css`) are different fabric here: one is a human
  note, the other a build-time guarantee.
- **`aria-label` on a bare `<span>` is dropped by the accessible-name computation.** A name needs
  a role to land on; `role="img"` is the ARIA-in-HTML-legal host for a non-interactive graphic.
  Silent failure mode: the criterion reads as satisfied in code review and fails only in a screen
  reader.
- **A `className` combining two classes defeats an exact-substring test marker built for
  one-class attributes.** `ChannelList.test.tsx`'s established idiom pins
  `class="channel-list__host"` including the closing quote, which is what stops it from also
  matching `__host-icon`. A dot emitting `class="channel-list__host-dot conn-dot--down"` makes
  that one-class form match **zero**, not fail loudly — the fix is to pin the *full* attribute
  value per category, which is a strictly better assertion (it pins the geometry class and the
  colour binding in one marker) rather than a workaround.
- **When a shipped call site's argument order is the reverse of the design's, pin the order with
  a test.** `ConnectionStatusIndicator(relay, daemon)` takes the legs relay-first; this ticket's
  design wants host-first. Both props share one type (`ConnectionLeg`), so a developer copying the
  existing call site swaps the legs silently — no type error, no lint, nothing but a wrong render.

## Lessons learned

*(from the PR #723 body)*

- A two-class `className` silently defeats this file's marker idiom (see "Patterns established"
  above) — pin the full attribute value, not a one-class prefix.
- `aria-label` on a bare `<span>` is dropped by the accessible-name computation; a name needs
  `role="img"` (or another ARIA-legal host) to land on.
- Reusing a CSS modifier without its base class makes the cross-file dependency invisible to the
  test tier — mitigate with a comment on the source rules naming the new consumer, since the
  import graph making the CSS import unavoidable is necessary but not sufficient (nothing stops
  someone deleting the *rule* while the *file* still gets imported).
