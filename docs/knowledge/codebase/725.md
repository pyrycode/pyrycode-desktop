## Summary

#724 gave the `turnState` `DaemonEvent` arm a `conversationId`, which retired the precedent twenty
other comments across four files (`src/main/daemonConnection.ts`, `src/shared/ipc/events.ts`,
`src/main/transport/inboundMessage.ts`, `src/main/daemonConnection.test.ts`) appealed to as
justification for their own arm still dropping `conversation_id`. Three of the twenty had gone
outright false ("unlike turnState … which drop it" — `turnState` had just started keeping it), and
two cited `turnState` as the single-field-emit exemplar it stopped being the moment it gained a
second field. This is a comment-only chore: every arm keeps its own factual claim that it drops
`conversation_id`, and every arm's own security claim ("no token, key, raw frame … can ride an arm
with no string field on it") survives untouched — only the cross-reference to the now-retired
`turnState` precedent goes.

The deletion contract that made this checkable rather than a matter of taste: delete exactly the
substring naming `turnState` in each site — the cross-reference and its joining punctuation — never
re-flow the surrounding paragraph. None of the twenty deletion substrings contains `token`, `key`,
`raw frame`, `untrusted`, `secret`, `fail-closed`, or `never`, so the arm's own safety claim cannot be
weakened by construction. One site needed more than a deletion: `events.ts:411`'s sibling list
dropped from three names to one, so `drop` → `drops` to keep subject-verb agreement.

Four two-line sites needed the wrap point re-joined rather than a bare in-line deletion
(`daemonConnection.ts:666-667`, `inboundMessage.ts:131-132`, `inboundMessage.ts:185-186`,
`events.ts:466-467`) — `inboundMessage.ts:186` is the one line actually removed (a whole parenthetical
retired, not left as a bare `*`). One site was invisible to every phrase grep because the appeal
wrapped mid-line rather than matching any of the four named phrases: `events.ts:149-150` reads
`...matching\n  // turnState / stallDetected / apiRetry)`, so `grep "matching turnState"` never
touches line 150.

Because #728 / #729 / #730 / #714 had not yet landed when this ran, this ticket ended up editing all
twenty sites in one pass rather than the twelve the split table predicted as its share — a landing
order the ticket explicitly allowed for ("a missing site means already handled, not you mis-grepped").
Sibling cross-references that are still true today (`stallDetected` / `apiRetry` / `compacting` named
alongside the retired `turnState`) were deliberately left in place per the ticket's own non-goal —
those tickets rewrite their own arm's comment when they land, and stripping the reference here first
would delete prose they need.

## Patterns established

- **A comment-only precedent-retirement is verified with a two-sided census, not a phrase grep.**
  `grep -rn "turnState" src/ | grep -E ':\s*(//|\*|/\*)' | wc -l` went 34 → exactly 14, and the 14
  survivors had to be byte-identical to the spec's do-not-touch list. Above 14 means a site was
  missed; below 14 means an out-of-scope comment was damaged — a one-sided "no phrase remains" check
  can't see the second failure at all. The four phrases named in the ticket body (`turnState
  convention` / `rule` / `matching turnState` / `unlike turnState`) found only 17 of 20 in-scope
  sites and one false positive; the census, not the phrases, was the gate.
- **A deletion contract discharges a `security-sensitive` AC by construction.** Naming the exact
  forbidden substrings (`token`, `key`, `raw frame`, `untrusted`, `secret`, `fail-closed`, `never`)
  and proving none appears in any deletion substring turns "don't weaken the security claim" from a
  read-every-line ask into a mechanical check — the code review ran it as
  `git diff --word-diff`, balancing the removed-token multiset against the added one to confirm a
  cross-reference was *cut*, not that a clause got silently *moved* out from under the claim.
- **A stale precedent citation isn't only a code-comment problem — a doc that reproduces the same code
  sketch goes stale with it.** `docs/knowledge/features/inbound-message-decode.md` carried three of
  its own "the turnState convention" appeals (two in prose narrating the `stall` and `model_announced`
  kinds, one in a reproduced code excerpt of the `stall` case) that this documentation pass retired to
  match. The code review flagged one of the three (`:499`, the code-sketch one) as a NIT pointer for
  this phase; the other two were the same staleness pattern, just in prose rather than a fenced block,
  and weren't separately flagged.

## Lessons learned

*(from the PR #731 body, verbatim)*

- **`npm test 2>&1 | tail` masks a non-zero exit.** On a fresh worktree `vitest` was not installed, so
  the baseline run printed `sh: vitest: command not found` and still reported `exited with code 0` —
  the pipe makes `tail`'s status the command's status. A "green" baseline captured that way is a
  phantom. Read the output body, never the exit code, when a test invocation is piped. Same shape as
  the documented real-claude trap in CLAUDE.md (all-skip exits 0), recurring here through the pipeline
  rather than through skips.
- **The census count is a two-sided gate only because every deletion removes the token itself.** All
  twenty edits strip the literal `turnState` from their line, so the post-edit comment-hit count must
  be *exactly* 14: above means a site was missed, below means an out-of-scope comment was damaged. A
  one-sided "no phrase remains" check cannot detect the second failure at all.
