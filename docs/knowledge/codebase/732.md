# #732 — Carry the conversation id on the `stallDetected` IPC arm

Split from #728 (sibling: #733, the borrowed-citation sweep, blocked by this ticket). Shipped as
PR #735 (`93d9343` spec commit + `41f889d` feature commit), code review **PASS** (0 MUST FIX,
0 SHOULD FIX, 1 NIT — cosmetic only). Size S, `security-sensitive`, refined S+sec, architect
self-security-review PASS; 7 files, 61 insertions / 34 deletions.

## Summary

The wire's `StallPayload` has exactly one field, `conversation_id`, and the decoder
(`parseStallPayload`, `inboundMessage.ts:589-599`) has always required it as a string — but the
transport's `stall` emit discarded it, so `stallDetected` reached the renderer as a **nullary** arm
carrying nothing at all. That drop encoded the same single-active-conversation assumption #724
already retired for `turnState`: the operator ruled on 2026-08-21 that a chat must keep working
while he looks at a different one, and the sidebar must show each chat's own state. This ticket
moves the id one layer — decoded payload → IPC event — and stops there, exactly as #724 did. No
daemon change, no wire-type change, no visible behaviour change; the per-conversation consumer is
#674.

`DaemonEvent`'s `stallDetected` arm (`src/shared/ipc/events.ts:145`) gains `conversationId: string`,
required, not optional — an optional routing key would invite `?? activeConversation` fallbacks in
the eventual #674 consumer, the exact misattribution this work exists to remove:

```ts
| { type: 'stallDetected'; conversationId: string }
```

The emit (`src/main/daemonConnection.ts:634-637`) copies it **by name** off the already-decoded
payload, never a spread — the house idiom at every emit in the file:

```ts
emitDaemonEvent(sink, {
  type: 'stallDetected',
  conversationId: inbound.stall.conversation_id
})
```

The id **stops at the renderer timeline bridge**. `translateTimelineEvent`
(`src/renderer/src/store/timelineBridge.ts:96-101`) still rebuilds a fresh `{ type: 'stallDetected' }`
literal; `ThreadEvent.stallDetected` (`threadTimeline.ts:136`) and the reducer are byte-unchanged.
That seam was already covered by an existing assertion — `timelineBridge.test.ts:193`'s
`expect(translated).toEqual({ type: 'stallDetected' })` — which needed no edit and no new test:
`toEqual` fails on an extra own enumerable property, so leaving that line alone **is** the AC3 proof
that the id didn't leak past the bridge.

### The security argument this arm had to rebuild, not patch

`stallDetected` was the one arm whose doc comments turned the drop into a security argument: no
token, key, raw frame or conversation content *could* ride an arm with no payload — true by
construction, because there was no field to ride. Adding `conversationId` made that argument false
as written, so it was replaced rather than softened, with the one #724 had already written for
`turnState`: a daemon-asserted routing key is not untrusted text, is never markup, a filename, a
cache key, a lookup path, an attribute or a URL, and reaches no log sink (`emitDaemonEvent.ts`
is log-free by construction; the decode-side content-free log at `inboundMessage.test.ts:3469`
pins that independently and shipped untouched).

## Patterns established

- **A second routing-key widening in the same arm family confirms #724's pattern generalises rather
  than being `turnState`-specific.** Same required-not-optional ruling, same by-name-copy-never-spread
  idiom, same "id stops at the bridge, `ThreadEvent` stays nullary" seam, same free `toEqual` leak
  guard reused with zero edits. A future arm in this family (`apiRetry` #729, `compacting` #730,
  `modelAnnounced` #714) that needs the same widening can follow this ticket and #724 as the two
  worked examples rather than rederiving the shape.
- **A drop-to-security-claim conversion is a trap this pattern's *second* instance exposed that its
  first didn't.** `turnState`'s pre-#724 doc never claimed "nothing can ride this arm" — it just said
  the id was dropped. `stallDetected`'s did, because a nullary arm can make that claim by construction
  in a way a `state`-carrying arm can't. Widening it doesn't just add a field; it retires an argument
  that was true and must be replaced with a different one, not deleted.
- **A contrast clause breaks by inference, not by name.** `apiRetry`'s "Unlike stallDetected this arm
  is NOT nullary" (`events.ts:133-134`) couldn't be fixed by deleting the name — once neither arm was
  nullary, the sentence's *comparison* was what went false. The code review flagged this as the
  finding it most expected to have to write, and confirmed it was repaired correctly: the contrast
  was dropped and `apiRetry`'s payload restated positively, without re-anchoring the contrast onto
  `compacting` (also not nullary). The three neighbouring *drop lists* were the opposite shape — there
  a bare name deletion left a true sentence, and the review confirmed that shape was left alone.
- **A borrowed citation's line number moves even when a sibling ticket owns it.** The ticket named the
  trap line as `inboundMessage.ts:112` (measured on pre-ticket `main`); this ticket's own paragraph
  rewrite two lines above pushed it to `:114` in the shipped file. The review re-measured rather than
  trusting the ticket's number, confirmed the `:112-119` (now `:114-121`-shaped) paragraph was
  untouched, and independently re-ran #733's repo-wide gate to confirm it still reads **8** — a
  borrowed citation being correctly left alone is a claim worth re-verifying by running the gate, not
  by diffing line numbers against a spec.
- **The bare-token census moving 22 → 16 is not "14 removed."** Several CHANGE sites (the arm literal
  itself, the test construction sites) keep the literal `stallDetected` token — only the *comment
  prose around* the token changed. Gating on the census delta rather than re-running the classification
  table would have been the wrong signal; the review ran both and reported them separately for exactly
  this reason.

## Lessons learned

*(from the PR #735 body, verbatim)*

- **A `&&`-chained typecheck hides the far half of a cascade.** `npm run typecheck` is
  `tsconfig.node.json && tsconfig.web.json`, so the single main-side emit error masked all four
  renderer errors. The first clean run came only after the emit was fixed — one clean run is not
  evidence the cascade is enumerated; you have to see the second half fail and then pass.
- **A doc comment can be falsified by its inference rather than its facts.** `apiRetry`'s "Unlike
  stallDetected this arm is NOT nullary" listed a true name; what broke was the contrast, once
  neither arm was nullary. Deleting the name leaves broken prose asserting a comparison that no
  longer exists — the repair is to state the arm's own payload positively. The three neighbouring
  *drop lists* had the opposite shape: there the sentence survives a plain name deletion.
- **A scope boundary can also be a log-sink boundary.** `threadTimeline.ts:229` stringifies a
  `ThreadEvent` into an `assertNever` error. Because the id stops at the bridge, that sink is
  unreachable for it — a second, independent reason not to widen `ThreadEvent` to make a blind
  `replace_all` compile.
