# #737 — Carry the conversation id on the `apiRetry` IPC arm

Split from #729 (sibling: #738, the borrowed-citation sweep, blocked by this ticket). Shipped as
PR #740 (`0e5ef09` spec commit + `c5e9d79` feature commit), code review **PASS** (0 MUST FIX,
0 SHOULD FIX, 1 NIT — non-blocking). Size S, `security-sensitive`, refined S+sec, architect
self-security-review PASS; 7 files, 108 insertions / 47 deletions.

## Summary

The wire's `ApiRetryPayload` has always carried `conversation_id`, and `parseApiRetryPayload`
(`inboundMessage.ts`) has always required it as a string — but the transport's `api-retry` emit
discarded it, on the same single-active-conversation assumption #724 retired for `turnState` and
#732 retired for `stallDetected`. This ticket is the third and largest instance of that same
widening: unlike `stallDetected`, which was nullary, `apiRetry` already carried three fields
(`active`, `current`, `total`), so its own safety argument — "no string field on it, nothing can
ride it" — was narrower and had to be replaced with the routing-key argument rather than simply
losing a sentence. No daemon change, no wire-type change, no visible behaviour change; the
per-conversation consumer is #674.

`DaemonEvent`'s `apiRetry` arm (`src/shared/ipc/events.ts:172`) gains `conversationId: string`,
required, not optional — an optional routing key would invite `?? activeConversation` fallbacks
in the eventual #674 consumer:

```ts
| { type: 'apiRetry'; active: boolean; current: number; total: number; conversationId: string }
```

The emit (`src/main/daemonConnection.ts:653-659`) copies it **by name** off the already-decoded
payload, alongside the three existing fields, never a spread:

```ts
emitDaemonEvent(sink, {
  type: 'apiRetry',
  active: inbound.apiRetry.active,
  current: inbound.apiRetry.current,
  total: inbound.apiRetry.total,
  conversationId: inbound.apiRetry.conversation_id
})
```

The id **stops at the renderer timeline bridge**. `translateTimelineEvent`
(`src/renderer/src/store/timelineBridge.ts:102-113`) still rebuilds a fresh four-field
`ThreadEvent` literal read by name; `ThreadEvent.apiRetry` and `timelineBridge.ts` are untouched
by this diff — `git diff --name-only` names neither it nor `threadTimeline.ts`. That seam's
existing assertions (`timelineBridge.test.ts:207`, `:216-221`) needed no edit: `toEqual` fails on
an extra own enumerable property, so leaving them alone **is** the AC3 proof.

### The security argument this arm had to rebuild, not patch

`apiRetry` already carried three fields, so its doc's safety claim was sharper than
`stallDetected`'s: "no token, key, raw frame, or conversation content can ride an arm with **no
string field on it**." Adding a string falsified that specific claim by construction. The
rebuilt block (`events.ts:146-171`) replaces it with the routing-key argument #724 and #732
established — never rendered as markup, never a filename/cache key/lookup path/attribute/URL,
reaches no log sink — restated in this arm's own voice, plus the "turn-stream item, or daemon
state?" test as the reason it crosses at all. The emit's own doc
(`daemonConnection.ts:639-652`) mirrors it and additionally states that no state is added *keyed
by the new id either* — closing the § Security review [6] concern (a per-id memo at the emit
would open an unbounded-map surface keyed by an attacker-chosen string) directly in the code
comment, not just in the spec.

## Patterns established

- **A third widening in the same arm family is the one that proves the pattern generalises to a
  non-nullary arm, not just a nullary one.** `turnState` (#724) and `stallDetected` (#732) both
  widened an arm with nothing (or one scalar) to lose a "nothing can ride it" claim over; `apiRetry`
  already carried three fields, so this ticket is the one that tests whether the routing-key
  argument survives contact with an arm that has real content sitting next to the new field. It
  did, unchanged in substance — the security shape (daemon-asserted key, no sink, stops at the
  bridge) does not depend on whether the arm was nullary before.
- **The "state the rule, not the neighbour" contract paid off across a whole family, not just this
  ticket.** The three `daemonConnection.test.ts` comments this ticket repaired
  (`:1877`/`:2030`/`:2217`, "the deliberate inverse of api_retry's `not.toContain`") state
  "Daemon state keyed by id, not a turn-stream item" rather than re-pointing at `compacting` or
  `modelAnnounced` — both of which go non-dropper in turn at #730/#714. A rewrite naming a sibling
  arm as the contrast would have gone false again within two tickets, reproducing the exact defect
  this repair retires.
- **A single-line grep gate over prose cannot prove its own AC when the claims it hunts wrap across
  lines — re-running it wrap-tolerant, in both directions, is what makes the count trustworthy.**
  Six of this ticket's falsified sites put the arm name and the drop vocabulary on different
  physical lines. The file-scoped gate still went 3→1 and the repo-wide one 6→4 as predicted, but
  only a bidirectional multiline sweep confirmed no falsified claim survived unmatched by the
  single-line regex.
- **A test *name* can be the same `replace_all` hazard as a type literal.** "emits exactly the N
  modeled properties" is shared verbatim by seven tests across the arm family, one per arm with a
  different `N`; only the api-retry instance needed to move four→five. The ticket's own census
  covered the `{ type: 'apiRetry' }` literals but not test names — anchoring the edit on the
  preceding `toEqual` block, not the name text, is what kept the other six untouched.
- **Line-count-neutral is a preference to check, not a target to force**, once a rewritten clause
  carries strictly more content than the one it replaces. The `inboundMessage.ts:114-117` clause
  grew by 2 lines to add the daemon-state reason and the #674 cite, matching the `stall` template
  five lines above it; review confirmed no downstream citation (#738's `events.ts:114`, #739's
  `inboundMessage.ts:100-102`) sits below the shift, so the 2-line growth cost nothing measurable.

## Lessons learned

*(from the PR #740 body, verbatim)*

- **A single-line grep gate cannot prove its own AC when the claims it hunts wrap across lines.**
  Re-running it wrap-tolerantly (`rg -U -o` for the arm name plus the next 3 lines, then filtering
  for the drop vocabulary, and again in the reverse direction) was what confirmed the 3 → 1 result
  was real rather than an artefact of the regex missing wrapped text. The sweep surfaced three
  `inboundMessage.ts` hits the single-line gate never sees — all three correctly left standing,
  since they belong to the compacting / model-announced / unrecognized-message paragraphs near an
  `api-retry` contrast list, not claims about `apiRetry` itself.
- **A test name can be shared verbatim by sibling arms, making it the same `replace_all` hazard as
  a type literal.** "emits exactly the four modeled properties, never a spread of the decoded
  payload" appears three times in `daemonConnection.test.ts`, one per arm; the census covered the
  `{ type: 'apiRetry' }` literals but not the names. Anchoring the edit on the preceding `toEqual`
  block disambiguated it. Worth checking test *names* for duplication whenever a ticket renames one.
- **The `&&`-chained `typecheck` script hides half the cascade.** Running
  `tsc -p tsconfig.node.json` and `tsc -p tsconfig.web.json` separately is what showed the node
  half passing and then exactly 7 web errors at the enumerated sites — and, negatively, zero errors
  in `timelineBridge.ts`, the compile-level evidence that a filter-plus-fresh-literal bridge absorbs
  a widened source arm with no edit.
- **This repo has no Prettier or ESLint** — no config file, no devDependency — so "format with the
  project's config" has no wired command here. Comparing each touched file's maximum line width
  before and after (counting characters, since byte-counting inflates the em-dashes these comments
  use heavily) was a usable substitute: all seven files' maxima are unchanged.
