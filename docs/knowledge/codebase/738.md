## Summary

Three `DaemonEvent` arms now carry a `conversationId` their `ThreadEvent` counterpart does not —
`turnState` (#724), `stallDetected` (#732) and `apiRetry` (#737, merged `c5e9d79`) — but six
comments across `timelineBridge.ts`, `threadTimeline.ts` and `wire/types.ts` still described the
pre-#724 world, where every owned bridge arm was field-for-field identical on both sides. This is
the same seam #725 fell through: it retired the `turnState` cross-references but missed these,
because #725 shipped before #737 existed to falsify them.

Six comment-block repairs, comment-only:

- `timelineBridge.ts:27-30` (the file-level blanket) — no longer enumerates which arms are
  identical. States the rule instead: the bridge is a filter, not a rename; an arm may carry
  fields its `ThreadEvent` deliberately drops; rebuilding from named fields is what makes each drop
  explicit and stable as arms widen. Same sentence also drops the already-stale
  `daemonConnection.ts:289` pointer for a bare file reference — `:289` had drifted into a
  `set_session_settings` doc block, and a bare file reference cannot drift the same way.
- `timelineBridge.ts:103-107` (the `apiRetry` case) — no longer claims identity. States that the
  DaemonEvent carries `conversationId` (#737) beside the four render fields, and the id **stops
  here** — a filter + fresh literal, never a pass-through. Shape borrowed from `:81-84`
  (`sessionTransition`), the closest existing template for an arm that drops a field.
- `threadTimeline.ts:137-138` (the `apiRetry` arm doc) — no longer claims identity with the
  DaemonEvent. States that #737 widened that daemon event with `conversationId`, which the bridge
  drops. The `(the toolUse / sessionBoundary discipline)` parenthetical survives verbatim — both of
  those arms are still genuinely identical, so it remains a true pointer.
- `wire/types.ts:419-420`, `:466-468`, `:587-589` (the three background-task doc blocks) — no
  longer name `api_retry` / `turn_state` as the contrast for why the frame keeps
  `conversation_id`. Each now points at the "turn-stream item, or daemon state?" test
  (`events.ts`, named by a bare file reference, not a line number) instead of a neighbour-arm list
  that goes stale on the next widening. Three separate edits, not one substitution — `:468` and
  `:589` are byte-identical lines but their lead-in sentences differ ("the reason the" vs "Hence").

Nine already-true identity claims (`toolUse`, `toolResult`, `sessionTransition`'s scoped claim,
`compacting` ×2, `unrecognizedMessage` ×2, and `apiRetry` named as a discipline exemplar rather
than a subject at `threadTimeline.ts:144-148`) were left standing, verified by reading each block
for what its identity claim takes as its *subject* — an arm named as a contrast or an exemplar is a
different claim from the arm named as the thing being asserted identical.

## Patterns established

- **A count-to-zero grep gate rewards deleting the comment it counts, so it cannot be the sole
  proof of a comment-repair ticket.** AC1's gate returns 0 whether the six blocks were rewritten to
  state the id-stops-here rule or simply deleted outright — deletion would erase the security
  argument (§ Security review). The spec closed this with a positive must-claim list per site, and
  review re-read all six for the replacement claim rather than trusting the gate alone.
- **Line-count neutrality is checked per hunk, not per file.** Ten in-repo comments cite these
  three files by a specific line number, several sitting *between* two edit sites in the same file
  (`types.ts:474-485` sits between the Site 5 and Site 6 wire/types.ts edits). A `+1`/`-1` pair
  that cancels in `git diff --numstat` would still have shifted a citation sitting between the two
  hunks; `git diff -U0` checked each `@@ -a,b +c,d @@` for `b == d` individually.
- **A rewrite that names a rule survives longer than one that names a sibling arm.** The three
  `wire/types.ts` blocks previously contrasted `api_retry` / `turn_state` as arms that drop the id;
  #730 (`compacting`) and #714 (`modelAnnounced`) will widen the two arms still dropping it next,
  which would have falsified a rewrite phrased as "unlike `compacting`, which still drops it."
  Naming the test instead (`events.ts`, restated at five call sites) survives both future widenings
  unedited — the same shape #737's own review lesson already established for this arm family.
- **Classify a claim by what its identity sentence takes as its subject, not by whether an arm's
  name appears in it.** `apiRetry` as the subject of "field-for-field identical" is false;
  `apiRetry` named as a discipline exemplar ("the `apiRetry` discipline") is true and had to
  survive untouched. `threadTimeline.ts:144-148`'s `compacting` paragraph names `apiRetry` twice,
  both true, both left standing.

## Lessons learned

*(from the PR #741 body, verbatim)*

- A count-to-zero grep gate rewards deleting the comments it counts. Verifying this ticket meant
  reading each of the six blocks for the claim it now *positively* asserts — the green gate alone
  would have passed a diff that erased the security argument it exists to protect.
- Line-count neutrality has to be checked **per hunk** (`git diff -U0`, `b == d`), not per file:
  `types.ts:474-485` is cited from `BackgroundTaskPanel.tsx` and sits *between* two edit sites, so
  a `+1`/`-1` pair that cancels in `--numstat` would still have shifted it.
- Rewriting prose inside a fixed line budget can silently widen a file's longest line.
  `threadTimeline.ts` went 111 → 113 chars before a rebalance between the two edited lines; with no
  prettier/eslint wired here, max width is the only formatting check available.
