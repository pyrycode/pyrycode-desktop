## Summary

The wire's `CompactingPayload` has always carried `conversation_id`, and `parseCompactingPayload`
(`inboundMessage.ts`) has always required it as a string — but the transport's `compacting` emit
discarded it, on the same single-active-conversation assumption #724 retired for `turnState`, #732
for `stallDetected` and #737 for `apiRetry`. This is the fourth instance of that widening, and the
last arm in the family whose safety argument rested on the *absence* of a string rather than on the
*nature* of the string: `compacting` carried nothing but the edge (`active`), so its doc comment's
claim — "one bool and nothing else … no string field on it" — was the strongest in the family and
had no weaker fallback to retreat to. No daemon change, no wire-type change, no visible behaviour
change; the compaction banner keeps reading the open conversation and renders identically. The
per-conversation consumer is #674.

`DaemonEvent`'s `compacting` arm (`src/shared/ipc/events.ts:199` post-diff) gains `conversationId: string`,
required, not optional — an optional routing key would invite `?? activeConversation` fallbacks in
the eventual #674 consumer:

```ts
| { type: 'compacting'; active: boolean; conversationId: string }
```

The emit (`src/main/daemonConnection.ts:677-681` post-diff) copies it **by name** off the already-decoded payload,
alongside `active`, never a spread — expanding from a one-line to a five-line literal, since the
single-line form measured 144 characters against the file's 111-character max:

```ts
emitDaemonEvent(sink, {
  type: 'compacting',
  active: inbound.compacting.active,
  conversationId: inbound.compacting.conversation_id
})
```

The id **stops at the renderer timeline bridge**. `translateTimelineEvent`
(`src/renderer/src/store/timelineBridge.ts:114-120`) still rebuilds a fresh `{ type: 'compacting',
active: event.active }` literal read by name; `ThreadEvent.compacting` and `timelineBridge.ts` are
untouched by this diff. That seam's existing assertions (`timelineBridge.test.ts:233`, `:278`)
needed no edit: `toEqual` fails on an extra own enumerable property, so leaving them alone **is**
the AC3 proof — confirmed by measurement, not assumption: the whole bridge suite ran 38/38 green
with the arm widened and no edit applied.

### The security argument this arm had to rebuild, not patch

`compacting`'s doc comment argued safety from the absence of a string: "what crosses IPC is one
bool and nothing else — no token, key, raw frame, or conversation content can ride an arm with no
string field on it." Adding a string falsifies that sentence by construction, and there is no
narrower version of the claim to fall back on the way `apiRetry` (already carrying three fields)
had. The rebuilt block (`events.ts:186-197` post-diff) replaces it with the routing-key argument
#724, #732 and #737 already established, restated in this arm's own voice: a daemon-asserted
routing key, not operator or model-influenced text; never markup, a filename, a cache key, a lookup
path, an attribute or a URL; reaches no log sink; stops at the renderer timeline bridge, `ThreadEvent`
keeping its one bool. It names the rebuild explicitly — "used to rest on the ABSENCE of a string …
now rests on the NATURE of the string" — which review flagged as the strongest form the AC asks for.
Two further cross-references retired their last comparator rather than being re-pointed at a sibling
arm — `events.ts:231` (`modelAnnounced`, drops the "matching compacting" comparator entirely) and
`events.ts:241` (`backgroundTaskStarted`, "unlike toolUse / compacting, which drop it" → "unlike
toolUse, which drops it", singular) — and `daemonConnection.ts:715-717` similarly lost its last
"divergence from compacting" referent and was rewritten to "KEPT **by the rule, not by comparison
with a neighbour**" rather than naming one.

## Patterns established

- **A count-to-zero grep gate rewards deleting the claim it counts — pairing it with a positive
  must-state list is what stops that.** AC4 half one (the retirement gate) and half two (the
  rebuilt-prose checklist) are graded independently; a rewrite that merely deleted the six false
  sites would have passed the gate and failed the criterion, leaving `compacting` the only arm in
  the family with no stated security argument. This is the same shape #738 applied to `apiRetry`'s
  borrowed citations, generalised to a ticket that rebuilds prose rather than only retiring it.
- **The last arm whose claim rests on absence, not nature, has no weaker fallback — verify there
  isn't one before assuming the rewrite is optional.** `apiRetry`'s claim ("no string field on it")
  was already narrower than `stallDetected`'s ("nothing can ride a nullary arm"); `compacting`'s was
  the widest-scope version of the family's retired claim, so this ticket is where the family's
  safety argument finishes its migration from "there is no string" to "the string is safe."
- **`git diff --name-only` naming exactly the predicted file set is the cheapest proof a sweep
  didn't cross its own scope boundary.** Eight files, matching the ticket's table exactly; neither
  `threadTimeline.ts`, `threadTimeline.test.ts`, `timelineBridge.ts`, `wire/types.ts` nor any of
  #743's four renderer comment sites appear in the diff.
- **A test name sharing a byte-identical suffix with six siblings is invisible to both `tsc` and
  the AC gate — only a full-string key and a by-hand check catch it.**
  `daemonConnection.test.ts`'s "emits exactly the two modeled properties, never a spread of the
  decoded payload" (this arm's instance of the seven-strong family) was the one edit no mechanical
  check reached; `tsc` doesn't read test names, vitest doesn't assert on them, and the AC4 gate is
  anchored on `rising-edge compacting`, which this test name doesn't contain.
- **The `&&`-chained `typecheck` script masks the second project's errors until the first is
  fixed — proving the cascade means running both projects separately, not trusting one green
  chained run.** The node-side error from the unwired emit hid all six web-side errors; only a
  separate `tsc -p tsconfig.web.json` run after fixing the emit surfaced them.

## Lessons learned

*(from the PR #744 body, verbatim)*

- **A `&&`-chained `npm run typecheck` hides half the cascade.** The single node-side error from
  the unwired emit masked all six web-side errors until it was fixed. Running
  `tsc -p tsconfig.node.json` and `tsc -p tsconfig.web.json` as separate commands is what proves the
  second half was actually enumerated — one clean chained run is not evidence.
- **A `toEqual` earlier in a test hides the assertion below it.** `daemonConnection.test.ts`'s
  round-trip test had to be fixed twice: the widened `toEqual` throws before the
  `not.toContain('conv-1')` leak guard on the next line ever executes, so that guard does not
  appear in the first failure list. Inverting it has to be a deliberate edit, not a reaction to a
  failure.
- **Line-count neutrality says nothing about character width, and this repo has no formatter.**
  Nothing re-wraps a comment you widen. `awk '{print length}' <file> | sort -n | tail -1` before
  and after is the real format gate; verifying neutrality needs `git diff -U0` (`b == d` per hunk),
  since `--numstat` sums a file and hides a hunk that grew.
- **A gate that counts a claim to zero rewards deleting the claim.** Pairing it with a positive
  must-state list is what stops the security paragraph being "repaired" by removal — worth doing
  whenever a ticket retires safety prose.
