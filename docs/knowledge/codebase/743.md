## Summary

#742 widened the `compacting` `DaemonEvent` arm with `conversationId`, leaving four renderer-side
comments describing the pre-widening world: two asserted field identity between the `DaemonEvent`
and its `ThreadEvent` (`timelineBridge.ts:115-116`, `threadTimeline.ts:144`), and two used "the
frame carries no string field at all" as the stated reason AC1 ("no daemon-supplied string is ever
rendered") holds (`ConversationScreen.tsx:122`, `ConversationScreen.test.tsx:1244`). All four were
false as of `687f961`. The guarantee itself never broke — no test failed, no type changed — but the
*reason* recorded next to it had rotted into an invitation: a reader who believes the frame carries
no string field has no reason to preserve `timelineBridge.ts:120`'s fresh-literal rebuild, and could
collapse it into a pass-through that would carry the id into the reducer silently while the comment
still read as safe.

The repair is a straight rename of the stated boundary, not a deletion: all four blocks now say the
`ThreadEvent` this bridge returns does not carry the id, so **the id stops here** — a filter plus
fresh literal, never a pass-through. `timelineBridge.ts:118-119`'s "the translator stays a pure
rename" tail was also brought in line with the file-level "this is a filter, not a rename" rule
(`:28-30`, #738's wording) two sentences above it — a deliberate, in-scope sub-repair the spec
called out by name, not scope creep.

Zero executable lines changed. `type: 'compacting'` literals: 19 before, 19 after. Every one of the
four hunks is line-count-neutral (`b == d`), which matters here specifically because twenty
in-repo comments cite these four files by line number below the edited blocks — including fourteen
beneath the single `ConversationScreen.tsx:120-124` block alone. A net `+1` on that block would have
minted fourteen fresh stale citations from a ticket whose entire purpose is retiring stale ones.

## Patterns established

- **A count-to-zero grep gate is satisfied by deletion, so it can never be the proof on its own.**
  AC1's gate (4 → 0) is necessary but not sufficient; the actual evidence the repair happened rather
  than the security claim being erased is the *positive* content of the four rewritten blocks (each
  must still assert AC1, or "the id stops here") plus the surviving-hit census: a case-insensitive,
  wrap-tolerant sweep of `field-for-field identical` and `no string field` across the four files
  returns exactly the fourteen pinned true siblings, no more, no less. This is the same shape #742
  and #738 established one arm-family member earlier; this ticket is the fourth confirmation of it
  in this file family.
- **Per-block character budget, not per-file.** With line counts frozen by I2, the only slack a
  five- or six-line comment block has is bytes. Each block's ceiling is its own current maximum
  width, never the file's — `ConversationScreen.tsx`'s file max (203) is 94 characters wider than
  the block being edited (109), and targeting the file max is exactly how #742's own PR (#744) left
  a 22-character orphan line behind. The tightest budget here (`ConversationScreen.tsx:120-124`,
  +53 net characters across 5 lines) needed all five lines re-flowed, not just the one line carrying
  the false clause — minimal line churn was explicitly not the objective, hunk neutrality was.
- **State the rule, never re-point at a neighbour arm's current field set.** The spec forbade
  writing "unlike `modelAnnounced`, which drops it" as the repaired reason, because #714 (already
  in flight at spec time) would widen `modelAnnounced` the same way one ticket later and falsify the
  contrast again. All four repairs instead cite the widening ticket number (`#742`) and the
  `events.ts` "turn-stream item, or daemon state?" test by phrase, never by a `file.ts:NNN` line —
  the same posture #738 and #742 already took.
- **A file-level rule change invalidates arm-block prose written before it, even inside the block
  being repaired.** `timelineBridge.ts:118-119`'s "pure rename" tail predates #738's file-header
  rewrite to "this is a filter, not a rename" (`:28-30`) and had gone unnoticed because #742's own
  diff didn't touch that block. Repairing it here cost no extra line and no extra file, and freed
  ~28 characters against the tight Site 1 budget in the process.

## Lessons learned

*(from the PR #746 body, verbatim)*

- **A count-to-zero gate is satisfied by deletion**, so it can never prove its own AC on its own.
  Here the four comments *are* the security claim, and the check that actually binds is classifying
  each surviving hit against the pinned table — the seven remaining `field-for-field identical` hits
  in the two store files are all true siblings, which is the real evidence, not the `0`.
- **`awk '{print length}'` counts bytes under `LANG=C.UTF-8`**, so an em-dash costs 3 bytes and `→`
  costs 3. Every ceiling in these comment blocks is a byte ceiling; a line budgeted at 104 characters
  with two em-dashes lands at 108. Worth measuring the rewritten region rather than the file max,
  which is set by untouched lines and stays flat while the edit itself overruns.
- **Rewrapping a fixed-line-count block is a character-budget problem, not a wording one.**
  `ConversationScreen.tsx:120-124` had +53 characters of slack across five lines; the natural
  phrasing only fit after re-flowing all five lines rather than editing the one that carried the
  false clause.
