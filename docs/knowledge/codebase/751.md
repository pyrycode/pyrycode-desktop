# #751 — Carry the conversation id on the `assistantDelta` IPC arm

Split from #675 (child A of an 8-way split: #751-754 transport arms / #755 store / #756 bridge /
#757 clears / #758 screen). Shipped as PR #761 (`02114d6` spec commit + `739151c` feature commit),
code review **PASS** (0 MUST FIX, 0 SHOULD FIX, 2 NIT — non-blocking). Size S, `security-sensitive`,
architect self-security-review PASS. 8 files, 102 insertions / 26 deletions, no new files.

## Summary

`AssistantDeltaPayload` has always carried `conversation_id` on the wire, and
`parseAssistantDeltaPayload` (`inboundMessage.ts`) has always `requireString`d it — but the
transport's `assistantDelta` emit discarded it, on the same single-active-conversation assumption
#724/#732/#737/#742 already retired for `turnState`/`stallDetected`/`apiRetry`/`compacting`. This
is the fifth instance of that widening, and the first on a **turn-stream item** rather than daemon
state: `assistantDelta` fires once per text slice, many times a turn, not once per state edge. The
per-conversation timeline consumer is #675; the routing itself is #756.

Two things made this arm smaller than #742 despite being on the fixture-heaviest arm in the family:

- **No decode change.** `parseAssistantDeltaPayload` already required `conversation_id` as one of
  "the four known fields" — `inboundMessage.ts` is not in this ticket's file set at all.
- **No security claim to replace.** `assistantDelta` already carried `text`, the largest untrusted
  string on the union, so its safety argument was never "no string field on it" the way
  `compacting`'s was. The rebuilt prose *adds* the routing-key paragraph rather than rescuing one.

`DaemonEvent`'s `assistantDelta` arm (`src/shared/ipc/events.ts`, post-diff) gains
`conversationId: string`, required, last, matching `turnState`/`apiRetry`/`compacting`:

```ts
| { type: 'assistantDelta'; turnId: string; seq: number; text: string; conversationId: string }
```

The emit (`src/main/daemonConnection.ts:591-598` post-diff) copies it **by name** off the
already-decoded payload, alongside `turnId`/`seq`/`text`, never a spread — no `??`, no default, no
guard, because the decode already makes a missing/non-string id unreachable at this point:

```ts
emitDaemonEvent(sink, {
  type: 'assistantDelta',
  turnId: inbound.delta.turn_id,
  seq: inbound.delta.seq,
  text: inbound.delta.text,
  conversationId: inbound.delta.conversation_id
})
```

The id **stops at the renderer timeline bridge**. `translateTimelineEvent`
(`src/renderer/src/store/timelineBridge.ts:39-40`) still rebuilds a fresh
`{ type: 'assistantDelta', turnId, seq, text }` literal read by name; `ThreadEvent.assistantDelta`
and `timelineBridge.ts` are untouched by this diff — confirmed both by measurement (the whole
bridge suite ran 38/38 green with the arm widened and no edit applied) and by `git diff --name-only`
not naming the file, which is a free, deterministic AC3 proof the spec called out explicitly.

### Why this arm needed no per-arm "drop" note in `timelineBridge.ts`

Three of the four prior widenings (`stall`, `apiRetry`, `compacting`) got a per-arm drop-note in
`timelineBridge.ts`, but those were written by #743, a comment-only sibling ticket — not by the
widening tickets themselves. This ticket has no such sibling: `timelineBridge.ts:39-40`'s bare
`assistantDelta` case carried no comment at all, and the file header's general rule already covers
the asymmetry ("an arm may carry fields its `ThreadEvent` deliberately drops"). Adding a note here
would have put a third production file in the diff to restate what the header already states.

## Patterns established

- **A count-to-zero grep gate rewards deleting the claim it counts — pair it with a positive
  must-state checklist.** Same shape #742 established for `compacting`: the AC4 verification used
  two greps (a "must return 0" retirement check and a "must return exactly 3" scope-boundary check)
  plus a positive list of claims the rebuilt prose had to state (routing-key argument, reaches-no-
  sink, required-never-optional). A rewrite that merely deleted the false sentences would have
  passed both greps and left `assistantDelta` the only widened arm with no stated safety argument.
- **A "measured" AC-verification grep still needs re-running at merge time, not trusted from the
  spec.** Code review found the spec's own AC4 check (a) claimed to return 4 on `main` but actually
  returned 6 — the pattern `only the three known fields` over-matches two unrelated payloads
  (`queue-state`/`modal-dismissed` in `inboundMessage.test.ts`). Harmless here (both are correctly
  untouched) but recorded so the next child of #675 doesn't inherit a stale count.
- **The shared-prose block covering two union arms must state the rule that's actually different
  per arm, not repair itself by pointing at a sibling.** `events.ts`'s block covers both
  `assistantDelta` and `turnEnd`; the rewrite gave `assistantDelta` its own paragraph with the
  routing-key argument and left `turnEnd` a short accurate statement of its own three fields,
  rather than writing "unlike `turnEnd`, which drops it" — a comparison that goes false the moment
  #752 (next in the split) widens `turnEnd` too.
- **The `&&`-chained `npm run typecheck` can mask in either direction, and this ticket inverted
  #742's version of the trap.** With the arm widened and the emit *not* yet wired, the node half
  fails on one error (`daemonConnection.ts`) and hides all eleven web-side cascade errors. Once the
  emit is wired, the node half goes to **zero** — even though two `daemonConnection.test.ts`
  literals are still wrong, because vitest is what reaches those, not `tsc`. A clean node half is
  not evidence the cascade was enumerated.
- **A `toEqual` earlier in a test hides the assertion below it, and inverting is not optional.**
  `daemonConnection.test.ts`'s round-trip test had to be fixed twice: the widened `toEqual` at
  `:1359-1361` throws before the `not.toContain('conv-1')` leak guard on the next line ever
  executes, so the guard doesn't appear in the first failure list. It was inverted to a positive
  `toContain` assertion, never deleted — deleting would remove the only proof the id reaches the
  emitted event at all.
- **`git grep -c` counts files touched, not matches** — called out in the PR's own lessons-learned;
  the AC-verification greps here needed per-line output (`git grep -n`) to be read correctly.
- **Adding a required field to a discriminated-union arm is atomic and cannot be split further**,
  even when the construction-site count (15, per the spec) sits above the usual 10-site gate: every
  intermediate state is a red build across both `tsc` projects, verified by the architect actually
  running the probe (apply the two prod edits, run both halves separately, run vitest, revert)
  rather than projecting it.

## Lessons learned

*(from the PR #761 body, verbatim)*

- The `&&` in `npm run typecheck` inverts its usual masking here: with the arm widened and the emit
  *not* yet wired, the node half fails on one error and hides all eleven web-side cascade errors.
  Once the emit is wired the node half reports **zero** — including for two `daemonConnection.test.ts`
  literals that are still wrong. A clean node half is not evidence the cascade was enumerated; only
  running the web half after it, and then vitest, reaches every site.
- Two of the cascade sites are invisible to `tsc` because `toEqual` is loosely typed, and one of
  those must be fixed twice: the `toEqual` throws before the leak guard on the next line ever
  executes, so the guard's inversion only surfaces on a second run. Worth expecting rather than
  treating as a surprise.
- `git grep -c` counts *files*, not matches. The AC-verification greps here needed per-line output
  to be read correctly.
