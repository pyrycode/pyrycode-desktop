# #756 — write every timeline event into its own conversation's slice

Child F of #675 (siblings: #751-#754 the transport arms, shipped; #755 the holder, shipped; #757 the
clears, open; #758 the reader cutover, open). Shipped as PR #772 (`03eefa6` spec commit + `9af6daa`
feature commit), code review **PASS**, zero MUST, one SHOULD (deferred to a follow-up sweep, not
gating), two NIT. Size S, `security-sensitive`, architect self-security-review PASS. Six files touched,
482 insertions / 25 deletions, 13 RED → 319 green.

## Summary

The keyed holder ([conversation timeline holder](../features/conversation-timeline-holder.md), #755)
shipped with no writer. This ticket gives it one — actually two, since the timeline has exactly two
production writers that add a row and both needed to move together: `timelineBridge.ts`'s
`useTimelineBridge` fan-out, and the composer's optimistic echo in `composerSend.ts`. Both now write the
keyed holder **as well as** the existing flat `timelineStore` (Strangler Fig, ADR 0008) — nothing reads
the holder yet (#758), so this ships as a verified no-op from the operator's side, and the fourth
acceptance criterion ("the flat timeline keeps receiving exactly what it receives today") *is* the design
contract, checked by leaving 19 `translateTimelineEvent` assertions and all 20 `subscribeTimeline` call
sites in `timelineBridge.test.ts` / `interactiveRoundtrip.test.tsx` unedited.

Two pure functions, not one widened return type: `translateTimelineEvent` keeps its exact signature and
body; a new sibling, `timelineTargetFor(event): string | null`, answers a strictly narrower downstream
question — given an event translate already owns, which conversation does it belong to. Eight of the
bridge's eleven owned arms (`assistantDelta` / `turnEnd` / `turnState` / `toolUse` / `toolResult` /
`stallDetected` / `apiRetry` / `compacting` — the whole #675 family) return their own
`event.conversationId`, non-nullable by construction since a missing or non-string `conversation_id`
already fails the decode without emitting. The other three owned arms (`sessionTransition`,
`unrecognizedMessage`, `connected`) return `null` — they are **not** dormant, each still reaches the flat
store, but none of them carries anything to attribute.

`subscribeTimeline`'s injected `dispatch` widened by **arity**, not by a new parameter: `(event) => void`
became `(event, conversationId: string | null) => void`. A function of arity 1 is assignable to a
parameter typed at arity 2, so all 20 real call sites kept compiling and running with zero edits — this
is what let the whole ticket land in one slice instead of a 20-site cascade. `useTimelineBridge` is the
fan-out composition root: it writes the flat store unconditionally and first, then the keyed store via
`dispatchFor(conversationId, event)` guarded on non-null — flat-first so AC4 holds even if the keyed write
were to throw. Both are synchronous zustand `set`s with nothing awaited between them.

The composer's echo (`composerSend.ts`) builds its `userText` `ThreadEvent` once and hands the same
reference to both `deps.dispatch(echo)` and the new required `deps.dispatchFor(conversationId, echo)` —
safe because `reduceTimeline` is pure and always builds fresh arrays. `dispatchFor` is **required**, the
opposite call from `subscribeTimeline`'s arity widening: at 6 deps-object call sites (not 20), requiring
the field cost six mechanical test edits and buys a compile error for "forgot to wire it."

AC3 ("never falls back to the active conversation") is enforced structurally, not by discipline:
`timelineBridge.ts` imports nothing from `activeConversationStore` and nothing from
`src/renderer/src/screens/`, so the `?? activeConversation` fallback #751-#754 were designed to prevent
is unavailable rather than merely avoided — grep-checkable, and grepped by both the developer and the
reviewer.

## Patterns established

- **A routing/attribution concern is a second pure function beside the translator, not a widened return
  type on the translator itself, when the translator already has a wide assertion surface.**
  `translateTimelineEvent` is asserted on at 19 sites; wrapping its return in
  `{ event, conversationId } | null` would have forced all 19 to unwrap, destroying the very no-op
  evidence the ticket exists to produce. One extra `switch` is cheaper than an assertion-surface cascade.
- **Widen an injected callback's arity before reaching for a new parameter, when the call-site count is
  large.** `subscribeTimeline` had 22 injection sites; retyping `(e) => void` to `(e, id) => void` cost
  zero edits because TypeScript assigns a lower-arity function to a higher-arity parameter type. The same
  ticket applied the opposite rule to `ComposerSendDeps` (6 sites → required field, not arity) — the
  cascade size decides which lever to pull, not a fixed convention.
- **`toHaveBeenCalledWith` pins the whole argument list, so an arity widening is not free at the
  assertion level even when it's free at the call-site level.** 20 call sites compiled and ran unedited;
  exactly one spy-level assertion that checked the dispatch's *arguments* had to move. Call-site
  compatibility and assertion compatibility are different properties.
- **A paragraph's placement inside a heavily-cited file has a measurable line-drift cost.** The routing
  and AC3-structural comments were drafted for the module header, which four other modules cite by line
  number (`conversationActivityBridge.ts:7`/`:114`, `announcedModelBridge.ts:11`,
  `announcedModelStore.ts:12`) — a header placement would have shifted all four by ~14 lines onto
  unrelated arms. Moving the same text into `timelineTargetFor`'s own docblock, below every cited anchor,
  drops the drift to the one line the new import unavoidably costs. Measure the anchors below an
  insertion point before choosing where a comment paragraph goes, in any file other modules pin by line.
- **Attribution's `default: return null` is not the catch-all the file's header bans**, and the reason has
  to be stated in the same docblock or a reviewer re-derives it from scratch: `translateTimelineEvent`'s
  ban protects against a *new* `DaemonEvent` arm being silently dropped from the timeline entirely (still
  enforced by its own `assertNever`); `timelineTargetFor` answers a narrower question over arms
  `translateTimelineEvent` already owns, and its `default` is unreachable in production because
  `subscribeTimeline` only calls it on the non-null translation path.

## Code review — PR #772, PASS, 0 MUST / 1 SHOULD / 2 NIT

- Verified the arm census is exact: `timelineTargetFor` enumerates all 11 owned arms as 8+3, and all
  eight id-carrying ones declare `conversationId: string` required (never optional) at their `events.ts`
  sites.
- Verified AC3 is genuinely structural by grepping the whole routing path (`timelineBridge.ts` and
  `composerSend.ts`) for `??` / `||` / `!` / `as` / `in event` / `console.*` — every hit lands inside a
  comment.
- Verified AC4's evidence survived: 19/19 `translateTimelineEvent` sites and 19/20 `subscribeTimeline`
  sites (the 20th is `interactiveRoundtrip.test.tsx:37`) are unedited; exactly one assertion moved, for
  the `toHaveBeenCalledWith` reason above.
- Diffed the test file's `fanOut` helper against `useTimelineBridge`'s real callback side by side — they
  are identical in shape, which is the open question's mitigation for the hook staying untested window
  glue.
- **[SHOULD FIX, deferred]** `activateConversation.ts:44` and `clearPairingScopedState.ts:53` cite
  `composerSend.ts:67` as the echo; this PR moved the echo to `:82`, so the cite is now stale — and unlike
  the pre-existing `timelineBridge.ts:206` staleness the spec deliberately left alone, this one was
  accurate before this diff and became false because of it. Not gating: fixing it needs a 5th/6th
  production file past the spec's own scope gate. Named explicitly for the sweep ticket the architect's
  spec already asked PO to file (alongside the `events.ts` `unrecognizedMessage`/`sessionTransition`
  dormancy-comment sweep — see that spec's Open questions).
- **[NIT]** `timelineBridge.ts:251-253` — an orphan short line splits "That prohibition protects" across

- **[NIT]** `timelineBridge.ts:257-259` — the "failure direction is safe" claim for `default: return null`

  redesign request — the design call (no second `assertNever`) is correct — but worth a clause noting the
  claim expires at #758, or a re-check line in #758's own spec.

## Lessons learned

*(from the PR #772 body, verbatim)*

- **`toHaveBeenCalledWith` pins the whole argument list, so an arity widening is not free at the
  assertion level.** The spec's regression gate expected all 21 existing `subscribeTimeline` sites to
  pass unedited. All 20 real call sites (19 here, 1 in `interactiveRoundtrip.test.tsx` — the spec counted
  21+1) do compile and run unedited, but the one spy-level test that asserted the dispatch's *arguments*
  could not: it now names the id too. Call-site compatibility and assertion compatibility are different
  properties, and only the first falls out of arity-1-assignable-to-arity-2.
- **Where you put a comment paragraph has a measurable cost in a codebase that cites line numbers.** The
  routing/AC3-structural paragraphs were drafted as a module header for `timelineBridge.ts` and would have
  shifted four *accurate* cross-file citations into `translateTimelineEvent`
  (`conversationActivityBridge.ts:7`/`:114`, `announcedModelBridge.ts:11`, `announcedModelStore.ts:12`) by
  14 lines each, landing them on unrelated arms. Moving the same text into `timelineTargetFor`'s docblock —
  below every cited anchor — drops the drift to the single line the new import unavoidably costs. Measure
  the anchors below your insertion point before choosing where a paragraph goes.
- **Residual drift this ticket does cause, deliberately unfixed:** `composerSend.ts:67` (the echo) is
  cited by `activateConversation.ts:44` and `clearPairingScopedState.ts:53` and now sits at `:82`; the two
  cites inside `ConversationScreen.tsx` were re-pinned since that file was already in the diff, but
  re-pinning the other two would add production files past the spec's scope gate. This belongs in the
  sweep ticket the spec's Open questions already ask PO to file, alongside the pre-existing
  `timelineBridge.ts:206` staleness.
