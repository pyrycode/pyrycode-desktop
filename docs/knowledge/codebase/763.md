# #763 — Carry the conversation id on the `toolUse` IPC arm

Code child of the #753 split (arm, `size:s`; sibling #764 owns the comment-only citation sweep in the
three files this ticket deliberately does not open). Shipped as PR #765
(`6909061` spec commit + `52dc0cc` feature commit), code review **PASS** (0 MUST FIX, 2 NIT —
non-blocking). Size S, `security-sensitive`, architect self-security-review PASS. 8 files, 98
insertions / 23 deletions, no new files.

## Summary

`ToolUsePayload` has always carried `conversation_id` on the wire, and `parseToolUsePayload`
(`inboundMessage.ts:978`) has always `requireString`d it — but the `tool-use` emit discarded it, the
same single-active-conversation assumption #724/#732/#737/#742/#751/#752 already retired for the six
arms before it. This is the seventh instance of that widening and the third on a turn-stream item,
landing directly on top of #752: the `toolUse` and `toolResult` blocks sit adjacent with no unchanged
lines between them in both production files (`events.ts:475-497` runs into `:498`;
`daemonConnection.ts:886-903` into `:905`), so this ticket's edit shifts #754's anchors — a
re-measure obligation on #754, not a dependency (nothing here creates or deletes its seam).

**Production change — two files, matching #751/#752's shape:**

- `src/shared/ipc/events.ts` — the `toolUse` arm gains `conversationId: string`, required, placed
  **first** to mirror the wire order (`conversation_id, turn_id, tool_use_id, name, input_summary`).
- `src/main/daemonConnection.ts` — the `tool-use` case's fresh literal gains one line, reading the id
  **bare** from the already-decoded payload: `conversationId: inbound.toolUse.conversation_id`. Copied
  **by name**, never a spread, so a decoder that later grows a field cannot smuggle it across IPC.

**No decode change.** `parseToolUsePayload` already required `conversation_id` before this ticket
existed — the fourth consecutive arm where that held (after #751/#752 and the sub-state arms). AC2 is
a regression guard on the decoder, not new behaviour: both halves were already pinned by shipped tests
(`inboundMessage.test.ts:2609-2614` missing-field loop, `:2616-2626` non-string case), which this
ticket confirmed still pass and wrote nothing new for. An emit-site `?? ''` is unreachable for any
input a test can supply, since `parseToolUsePayload:978` throws first — the `?? ''` ban in AC1 is an
**inspection** criterion for code review, not a test obligation, per #752's precedent finding.

The id **stops at the renderer timeline bridge** exactly as it did for #751/#752:
`translateTimelineEvent` (`timelineBridge.ts:47-67`) rebuilds a fresh `ThreadEvent.toolUse` by name and
is untouched by this diff — `ThreadEvent` carries no conversation id. Proved executably by three exact
`toEqual` expectations in `timelineBridge.test.ts` that must hold **unchanged** field counts while a
`DaemonEvent` fixture eight lines above each one gains the field. Routing lands in #756.

**AC3 census — five production sites, three test sites, all inside this ticket's two files.** The
arm's own comment block, two one-line contrasts on sibling arms (`backgroundTaskStarted`, `queueState`)
that used to say "unlike toolUse, which drops it" and now say "unlike toolResult, which still drops it
until #754", the emit's own comment block, and its `queue-state` twin contrast — plus two test names
and one guard that had to **invert** (`daemonConnection.test.ts:2900`,
`expect(JSON.stringify(events)).not.toContain('conv-1')` → `toContain`). The identically-worded
drop-claims on `toolResult` (#754's) and `unrecognizedMessage` (unrelated) were left untouched and
verified still true — a grep on the phrase alone over-matches by more than this ticket owns; the
census had to match on the **arm**.

## Patterns established

- **An architecture spec's Design-section summary count and its own AC3 census table can disagree —
  the census table is the source of truth, never the summary prose.** Code review's NIT: the commit
  message said "retires the four production comments and three test names", inherited from the spec's
  § Design prose, but the spec's own AC3 census table lists **five** production sites. On a ticket whose
  entire point is retiring stale counts, the commit log importing one from the wrong section of its own
  source spec is the same failure mode one level up — worth checking the census table specifically when
  writing a commit message or PR body count, not the narrative paragraph above it.
- **A deferring comment block should read as a near-verbatim sibling of the arm it defers to, not a
  fresh composition.** The `events.ts` `toolUse` arm comment landed reading almost identically to
  #752's shipped `turnEnd` block — code review called this out as the right outcome ("the arms should
  read alike"), continuing the correction #752's review made to #751's over-long first attempt at the
  same paragraph.
- **A stale one-line contrast comment ("unlike X, which drops it") gets repaired in place, not
  deleted, when X's own widening hasn't landed yet.** `backgroundTaskStarted`'s and `queueState`'s
  contrasts against `toolUse` were rewritten to contrast against `toolResult` instead (true until
  #754) rather than removed — matching #752's precedent of rewriting rather than dropping the point
  the sentence makes.
- **Rewrapping a comment after a text swap can silently blow the column budget, and the fix is to trim
  redundant content, not just rewrap harder.** "unlike toolUse, which drops it" → "unlike toolResult,
  which still drops it until #754" is longer and pushed a line past 108 columns; dropping a redundant
  issue-number reference elsewhere in the same sentence kept the line count and the wrap intact rather
  than cascading the rewrap through the whole paragraph.

## Lessons learned

*(from the PR #765 body, verbatim)*

- A green suite is not proof an inverted guard ran. `daemonConnection.test.ts`'s `toEqual` throws before
  the `not.toContain` below it, so the guard is unreachable on a failing fixture. Mutating the inverted
  guard's needle to a value that cannot appear and confirming it goes red is what shows the guard
  executes and has teeth — not the green run.
- `git checkout <file>` to undo a temporary mutation discards every other edit in that file. Reverting a
  one-line probe mutation that way reset four finished edits to `HEAD`. A mutation applied with
  `perl -i` wants an equally narrow revert, not a whole-file one.
- Edit uniqueness caught the adjacent-line inversion before it landed. `timelineBridge.test.ts:98` (a
  `DaemonEvent` that gains the field) and `:107` (a `ThreadEvent` `toEqual` that must not) share a
  byte-identical field block nine lines apart. `replace_all` would have corrupted the second with `tsc`
  silent; anchoring on `const event: DaemonEvent = {` is what separates them.
- Swapping a stale comment contrast can break the wrap budget. "unlike toolUse, which drops it" →
  "unlike toolResult, which still drops it until #754" pushed a line past 108 columns, and rewrapping
  cascaded through the paragraph. Dropping a redundant issue reference fit the replacement in the
  original line count and left the rest of the block untouched.
