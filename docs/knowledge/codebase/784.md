# #784 — Carry the conversation id on the `unrecognizedMessage` IPC arm

Ninth and last widening of the #675 family — the only arm with a wire `conversation_id` that #766
left dropped, because it isn't a turn-stream or sub-state arm. Also the first widening to land after
`timelineTargetFor` (#756) existed, so it is the one member of the family that moves a `case` label
between that function's two groups instead of only adding a field. Shipped as PR #788 (`d76040d` spec
commit + `ca95deb` feature commit), code review **PASS** (0 MUST FIX, 0 SHOULD FIX, 2 NIT). Size S,
`security-sensitive`, architect self-security-review PASS. 7 files touched, no new files.

## Summary

`UnrecognizedMessagePayload` has always carried `conversation_id` on the wire, and
`parseUnrecognizedMessagePayload` (`inboundMessage.ts:851-869`) has always `requireString`d it at
`:855` — but the `unrecognized-message` emit discarded it, the same single-active-conversation
assumption the other eight arms already retired.

**Production change — three files, two executable lines:**

- `src/shared/ipc/events.ts:425-431` — the `unrecognizedMessage` arm gains a required
  `conversationId: string`, placed first, matching `toolUse` / `backgroundTaskRoster`.
- `src/main/daemonConnection.ts:838` — the `case 'unrecognized-message':` emit's fresh literal gains
  one line, reading the id **bare** from the already-decoded payload:
  `conversationId: inbound.unrecognized.conversation_id`. Copied **by name**, never a spread of
  `inbound.unrecognized` — the discipline this arm needs most, since its payload is unbounded
  daemon-relayed JSON.
- `src/renderer/src/store/timelineBridge.ts:262-291` — `case 'unrecognizedMessage':` moves from
  `timelineTargetFor`'s id-less group into the id-carrying group (a `case` label move, not a new
  branch); the field resolves through grouped-case narrowing with no cast and no probe. Both censuses
  in the function are trued up: nine id-carrying owned arms now, `sessionTransition`/`connected` the
  only two left with nothing to attribute to.

**No decode change.** `parseUnrecognizedMessagePayload` already required `conversation_id` before
this ticket existed — AC2 was already green. An emit-site `?? ''` would be unreachable for any input
a test can supply, since the decode throws first; the `?? ''` ban is an **inspection** criterion for
code review, not a test obligation, per #752/#763/#766's precedent finding.

The id **stops at the renderer timeline bridge** exactly as it did for the other eight arms:
`translateTimelineEvent`'s `case 'unrecognizedMessage':` (`timelineBridge.ts:124-137`) rebuilds a
fresh `ThreadEvent` by name and its returned literal is unchanged — `ThreadEvent` carries no
conversation id. Proved by exact-equality **silence**: `timelineBridge.test.ts:268`/`:288` check the
translator's output with `toEqual` and needed no edit, so a translator that carried the id across
would have gone red without a new assertion.

**The load-bearing comment repair.** `timelineBridge.ts:125-132` used to say the DaemonEvent and
ThreadEvent were "field-for-field identical" and the translator "a pure rename" — true before this
ticket, false after, since the DaemonEvent now carries a field the ThreadEvent deliberately drops.
The repair keeps the "the four render fields ARE field-for-field identical" clause and turns it into
the *reason* the explicit drop has to stay, rather than dropping the clause — the shape #764's spec
asked for and better than the `apiRetry`/`compacting` template it copied.

**Test-side — one new test, one deletion, one probe swap, four files widened.** The `idCarrying`
table in `timelineBridge.test.ts` absorbs the deleted standalone `returns null for
unrecognizedMessage` test as a ninth row under a distinct id (`toHaveLength(9)` makes the absorption
a checked fact, not a silent coverage loss). The no-fallback probe at `:1058-1083` — which had used
`unrecognizedMessage` as its only probe for "an id-less arm leaves an already-held slice untouched by
reference" — swaps to `sessionTransition` rather than being deleted, keeping AC3's only no-fallback
proof alive; `sessionTransition` tail-appends a real row, so it is the stronger probe. One genuinely
new test covers AC3 end-to-end: an `unrecognizedMessage` for `conv-a` lands only in `conv-a`'s
retained slice, `conv-b`'s stays untouched **by reference**, and the flat store still receives both
rows unconditionally (AC4).

**The masked-failure ordering trap, reproduced live.** `daemonConnection.test.ts:2496`'s
`not.toContain('conv-1')` guard sits in the same `it` as a `toEqual` fixture four lines above it —
vitest reports whichever assertion fails first, so wave 1 showed 6 failures and the inverted guard
only became reachable, as a 7th, once the fixture above it was widened. Budget a second wave rather
than reading one run's failure count as the whole set.

## Patterns established

- **A "field-for-field identical" comment needs to name which two shapes it compares, not just
  whether the phrase reads true.** `timelineBridge.ts:125-130` (DaemonEvent ↔ ThreadEvent) goes false
  on a widening; `threadTimeline.ts:151` (ThreadEvent ↔ ThreadItem, both renderer-local and always
  id-free) stays true forever. The two live one file apart and read identically at a glance — sort by
  which two shapes are being compared, never by the sentence's spelling.
- **The family's in-file/out-of-file citation convention held for the ninth time**: this ticket
  repaired only the comments inside its own three-file set (`events.ts`, `daemonConnection.ts`,
  `timelineBridge.ts`'s translator + census); the two citations outside it
  (`inboundMessage.ts:189-192`, `conversationTimelineStore.ts:10-12`) were deliberately left false,
  for #787 to retire — the same split every prior widening in this family used (#725/#733/#738/#743,
  #764-after-#763, #767-after-#766).
- **Deleting a standalone unit test is only safe when a table absorbs it and a length assertion
  proves the absorption.** `toHaveLength(9)` is what converts "we deleted a test" into "we moved a
  test", auditable by the next reader without re-deriving the diff.

## Lessons learned

- The `Object.keys(...).sort()` anti-smuggle guard and the `not.toContain('conv-1')` guard sit in the
  same `it` as a `toEqual` fixture, so vitest masks them behind the fixture's failure — the first run
  reported 5 failures, and the inverted `not.toContain` only became reachable once the fixture was
  widened. Budget the second wave rather than reading a single run's count as the whole set.
- Deleting `timelineTargetFor`'s standalone `returns null for unrecognizedMessage` test is only safe
  because the `idCarrying` table absorbs it; `toHaveLength(9)` is what makes the absorption a checked
  fact rather than a silent coverage loss.
- `timelineBridge.test.ts:268`/`:287` are `ThreadEvent` expectations sitting eight lines below the
  `DaemonEvent` literals that *do* gain the field. tsc is silent on them, and that silence is the
  proof the id stops at the bridge — classify a literal by which union it's checked against, never by
  the spelling of the surrounding comment.
