Adds the first automated end-to-end test of the assembled `createDaemonConnection` (bootstrap → the **real** `createNoiseRelayDriver` → real Noise session → real loopback relay socket). It drives the client at its real entry point through pair, a genuine `Noise_IK` handshake, `send`, and a streamed reply against the in-process fake target — [#90](90.md)'s content-blind forwarder splicing between the real client on `/v1/client` and [#91](91.md)'s Noise responder on `/v1/server` — and asserts the reply reaches the renderer bridge as `messageReceived` / `messagesReceived` with a `connected` event emitted and no `failed`. An opt-in, operator-gated live variant runs the same round-trip against the live relay + pyrybox daemon.

This is the piece the harness was built for: mobile's connection-layer bugs surfaced **only** under a real round-trip through the *assembled* client — never under the per-layer unit tests — so the value is exercising the whole stack at once, not the primitives (which `noiseSession.interop.test.ts` already covers directly).

## Design in one paragraph

Drive `createDaemonConnection` at its real entry point (`start()`) with **`createDriver` omitted**, so the default real `createNoiseRelayDriver` runs the genuine handshake — and fake only the two outer seams `daemonConnection.test.ts` already fakes (`deviceKeypair.ensure()` / `pairedServer.load()`) plus a recording `sink`. `standUpRoundTrip(buildReply)` encodes the load-bearing ordering: `startFakeRelayForwarder()` (ephemeral loopback port) → `startFakeDaemon({ url, buildReply, helloAck })` (its `/v1/server` leg is **open before the client dials**, so msg1 is never dropped) → build the `PairedServerRecord` from the two now-known values (`relay: ${forwarder.url}/v1/client` — the real driver dials it **verbatim**, no scheme seam; `server_static_pubkey: base64StdEncode(daemon.staticPublicKey)`; a synthetic `DUMMY_TOKEN`) → mint a **real** device static keypair via `loadNoiseLib().CreateKeyPair(...)` → `createDaemonConnection({...})` with the recording sink that pushes each event and `notify()`s the waiter → `start()` → `forwarder.whenReady()` (explicit both-legs-spliced checkpoint) → wait for `connected` **or** `failed` (a broken handshake fails fast, not after the full timeout). Each `it` then asserts `connected` + the round-tripped `ack`, calls `connection.send(...)`, waits for `messageReceived`/`messagesReceived`, asserts the payload deep-equals the reply, asserts `daemon.whenSettled()` is `{ ok: true }` (the session stayed open after the single reply), and asserts **no** `failed` ever followed. The reply builder is overridden to return a well-formed `message`/`message_chunk` envelope (see Lessons).

## Patterns established

- **Test the assembled thing at its real entry point; fake only the outer seams.** The value over `noiseSession.interop.test.ts` (which wires `createNoiseSession` + `createRelayConnection` + `codec` directly) is the **layer under test**: this drives `createDaemonConnection.start()` with `createDriver` left at its default, so the real driver → real Noise session → real socket all run. The only injected seams are the two stores + the sink — the exact seams `daemonConnection.test.ts` fakes for its *unit* tests, reused here for the *integration* test. This is the reusable shape for "prove the composed stack works, not just its parts": drive the composition root, leave the internal DI seams at their real defaults, fake only the process-edge inputs (stored keypair/record) and the process-edge output (the IPC sink).
- **A cooperative fake peer's reply builder must speak the *inbound* protocol, not echo.** The fake daemon's default `buildReply` echoes the client's own `send_message` plaintext verbatim; `parseInboundMessage` correctly returns `null` for a `send_message` (it is not a `message`/`message_chunk`), so the client ignores it and no `messageReceived` ever fires. Any round-trip test that wants to *observe* an inbound message must override `buildReply` to return a `message`/`message_chunk` envelope built through the real `encodeEnvelope`. Documented on the [fake daemon](../features/fake-daemon.md) as a limitation; this is the first consumer to hit it.
- **Pin the ack you overrode, not the fake's defaults.** The test passes `helloAck: { server_id, conn_id }` overrides and asserts `connected.ack` deep-equals a hand-built `EXPECTED_ACK`, so the `connected` assertion pins the ack that actually round-tripped through the **real** msg2 read (`parseHelloAck`) to the renderer bridge — rather than silently coupling to the fake daemon's internal defaults. Overriding both halves (build input + expected output) keeps the assertion honest.
- **Assert on event types/counts, never serialized payloads.** `types(events)` renders arrival order for descriptive failures (`expected connected; observed connecting, failed`) with **no** payload bytes — a resolve-on-timeout waiter turns a broken handshake into a readable assertion instead of an opaque vitest timeout. On the live path this is also the credential discipline: the real `PYRY_LIVE_DEVICE_TOKEN` never reaches an event, a log, a failure message, or an `expect(...)`; the live probe reply is deliberately **not** hard-asserted (a live daemon's answer to a synthetic probe is not guaranteed — matches the interop live path).
- **Teardown order is load-bearing; enforce it with LIFO, not comments.** `connection.stop()` must run **before** `forwarder.close()`, else the supervisor sees the leg drop and can emit a spurious `failed` before it is quiesced. The `cleanups` array pushes forwarder → daemon → connection and runs **reversed** in `afterEach`, so `stop()` runs first even on a mid-test throw. A deterministic net (the cleanup array), not a hope.
- **Reuse the operator-gated convention verbatim — do not invent a new one.** The live variant copies `noiseSession.interop.test.ts`'s `PYRY_LIVE_*` env-var names, its `readLiveEnv()` shape, and the `describe.skipIf(!live)` pattern; the gate is encoded in the `describe` **title** so the skipped entry names the required vars in the vitest reporter. (Code-review NIT, non-blocking: the extra module-load `console.info` skip notice is redundant with that title and prints on every run; kept because §5 of the spec mandates it — the interop precedent signals skip via the title alone.)

## Lessons learned

*Lifted from the PR body's "Lessons learned" section.*

- **Teardown order is load-bearing:** `connection.stop()` must run **before** `forwarder.close()`, else the supervisor sees the leg drop and can emit a spurious `failed` before it is quiesced. Implemented as a LIFO cleanup array (push forwarder → daemon → connection, run reversed).
- **The fake daemon's default `buildReply` echoes the client's own `send_message` verbatim**, which `parseInboundMessage` correctly ignores → no `messageReceived`. A round-trip test that wants to observe an inbound message must override `buildReply` to return a `message`/`message_chunk` envelope.
- **This worktree needed `npm install`** (no `node_modules`); the dispatcher's env did not pre-provision it. (Operational note for future runs on a fresh worktree — not a code issue.)

## Testing

Three cases; the first two run unconditionally under `npm test` (fully in-process over loopback `ws` — no Go toolchain, no external network), the third is operator-gated and skips by default:

- **`message` → `messageReceived` (AC1/AC2/AC3) — the primary.** `standUpRoundTrip` with a `buildReply` returning a canned `message` envelope (`{ conversation_id:'c1', message_id:'reply-1', role:'assistant', text:'pong' }`). Asserts, in order: a `connected` event whose `ack` deep-equals `EXPECTED_ACK` (handshake completed, msg2 read); `connection.send({ text:'ping' })`; a `messageReceived` whose `message` deep-equals the reply; `daemon.whenSettled()` is `{ ok: true }` (session stayed open — single-round-trip responder); and **no** `failed` across the whole sequence.
- **`message_chunk` → a single ordered `messagesReceived` (AC2 twin).** The nice-to-have twin from the spec's open question, kept in budget. `buildReply` returns a `message_chunk` envelope carrying a two-element `messages` batch; asserts `messagesReceived.messages` deep-equals the batch, plus the same `whenSettled` / no-`failed` invariants. Covers the second inbound arm.
- **Live round-trip (AC4) — `describe.skipIf(!live)`.** `readLiveEnv()` requires `PYRY_LIVE_RELAY_URL` / `SERVER_ID` / `DEVICE_TOKEN` / `SERVER_STATIC_PUB` (+ optional `DEVICE_NAME`); the record uses the operator's URL as `record.relay` **verbatim**, a **fresh** in-process device keypair completes the handshake (the token in the encrypted `hello` authorizes; IK recovers whatever static the initiator presents), and `now` is the real wall clock. Asserts `connected` present + no `failed` (the session-open outcome is the deterministic assertion); the probe `send` + wait is **best-effort**, never hard-asserted. Skips with an operator-visible reason naming the vars.

Per-layer log-free / malformed-frame / oversized behaviour is already pinned by `daemonConnection.test.ts` and the transport unit tests; this file deliberately proves the **happy assembled round-trip**, not the adversarial branches (keeps scope S). An assembled-path adversarial suite, if ever wanted, is a future ticket.
