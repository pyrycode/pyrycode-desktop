Delivers the reusable **two-leg** forwarder: an importable test module that stands up one in-process `ws` relay on an ephemeral loopback port and splices raw frames **byte-for-byte, opcode-preserving, content-blind** between the `/v1/client` leg (the real client under test) and the `/v1/server` leg (the #91 fake daemon). Generalises the records-only `startRelay` inlined in `relayConnection.test.ts` (single-endpoint, `received()`-only) into a two-leg splice, and lives as a plain `.ts` (not a `.test.ts`) so #91/#89 can import it — the load-bearing AC. See the [fake relay forwarder feature doc](../features/fake-relay-forwarder.md) for the evergreen API contract.

## Design in one paragraph

One idea: a raw two-leg byte pipe. Distinguish the legs by the HTTP **upgrade path** (`/v1/client` vs `/v1/server`, query stripped), never by frame bytes — content-blindness is a property of *frames*, not of the upgrade line, so path routing keeps it while being **deterministic under concurrent dial** (the two legs may dial in any order) and mirroring the client's existing URL shape. On a `'message'` from one leg, normalise with the reused `toBytes` and forward to the *other* leg with the `isBinary` opcode flag verbatim. Close the classic `ws` readiness race with a **positive** `whenReady` gate (a deferred resolved the instant the second leg registers) instead of a sleep. Make `close()` idempotent with a cached `closePromise`. The whole module imports only `ws`; the frame-inspecting Noise responder is a separate, `security-sensitive` ticket (#91).

## Patterns established

- **Content-blindness is enforced by the import list, not by discipline.** The module imports only `ws` + Node built-ins — no `./codec`, no Noise modules, no `@shared` wire type. A reviewer (or a future editor) can verify "this never decodes a frame" by reading the imports, not by tracing every branch. The one byte operation, `Buffer.concat` of a fragmented delivery, is loss-less re-assembly, not inspection. This is the reusable shape for "prove a boundary-crossing component can't peek": make the peeking *unimportable*.
- **Route by the HTTP upgrade path, not by connection order or frame bytes.** Path-based leg identification (`/v1/client` vs `/v1/server`) is deterministic when both legs dial concurrently, gives named legs for teardown assertions, and mirrors production — where order-based pairing would introduce a dial-order ambiguity. Content-blindness survives because the path lives in the upgrade line, not the frame.
- **A positive readiness gate beats a sleep for the 101-before-registration race.** `ws` writes the 101 response (unblocking the dialer's `connect`) *before* the `'connection'` handler registers the socket. Rather than an arbitrary `setTimeout` in every consumer, expose an awaitable that resolves the instant the second leg fills — a deferred settled directly from the `'connection'` handler (no polling ticker; strictly better than the Go harness's 2ms `WaitBinary` map-poll, which Go needs only for lack of a cheap awaitable). Cache it so repeated `whenReady()` calls share one promise, and give it a static-message timeout so a mis-wired test fails fast instead of hanging to vitest's global timeout.
- **Idempotent teardown via a cached promise, not a best-effort flag.** `close()` returns a cached `closePromise`; the first call does the work (reject a pending readiness deferred, clear the timer, `terminate()` both legs, `wss.close`), every later call returns the same promise. Deterministic idempotency (the AC's requirement), mirroring `startRelay`'s close contract — and the belt-and-suspenders rule: the guard is code (a cached promise), not a hope.
- **Type honesty over casts.** `WebSocketServer.address()` is `AddressInfo | string | null`; it is **narrowed** with a null + `typeof === 'string'` guard rather than the `as AddressInfo` cast the older `startRelay` uses (an improvement over the code it generalises). The `deferred<T>()` helper initialises `resolve`/`reject` to no-ops so the synchronous Promise executor can overwrite them without a definite-assignment `!`. No `any`/`as`/`!` in production.
- **No floating promises in a log-free module.** The internal `ready.promise.catch(() => {})` suppresses `unhandledRejection` when a rejection has no external awaiter (e.g. `close()` before anyone called `whenReady`), while external `await`/`then` still observe the rejection. The readiness timer is cleared on settle **and** on `close()`, so no timer leaks past a test.

## Lessons learned

*Lifted from the PR body's "Lessons learned" section.*

- **The module imports only `ws`; content-blindness is enforced by the import list** (no `codec`/Noise imports), and legs are distinguished by the HTTP upgrade **path** — content-blindness is a property of frames, not of the upgrade line.
- **No production `as`/`!`.** `WebSocketServer.address()` is `AddressInfo | string | null`, narrowed with a null + `typeof === 'string'` guard instead of the `as AddressInfo` cast the test file (and the older `startRelay`) uses; the readiness deferred avoids a definite-assignment `!` by initialising `resolve`/`reject` to no-ops before the (synchronous) Promise executor overwrites them.
- **`whenReady`'s "first call's timeout governs" caching** (code-review NIT, non-blocking): a later `whenReady(50)` after an earlier `whenReady()` silently inherits the 1000ms default. Correct per spec and documented in the JSDoc — the #89 round-trip consumer should pass the intended timeout on the *first* call.

## Testing

Eight cases, all driving **two raw `ws` clients** at the byte level (the round-trip through the real `createRelayConnection` is #89's job):

- **Bidirectional, byte-identical, content-blind (AC2/AC3).** Client leg sends boundary bytes (`0x00,0x01,0xff,0x7f,0x80` — neither valid JSON nor a Noise frame, so arbitrary opaque bytes double as the content-blindness assertion) → the server leg receives the exact bytes; a *different* frame the other way arrives exactly. 
- **Opcode preserved — binary and text.** A binary frame then a text frame from one leg; the peer observes the same `isBinary` flag *and* identical bytes for each (guards `{ binary: isBinary }` fidelity).
- **Readiness gate closes the race (AC4).** With only the client leg up, `whenReady()` stays pending after a macrotask tick; dialling the server leg resolves it. Separately, dial both legs and send with **no sleep** after `await whenReady()` → the server receives (the gate held until both registered).
- **`whenReady` timeout.** One leg only → `whenReady(50)` rejects with the static message.
- **`close()` before both legs connect.** A pending `whenReady()` rejects (`closed before both legs connected`); teardown still proceeds.
- **Teardown idempotent (AC5).** After a connected pair, `close()` twice → both resolve, no throw; both leg sockets end up `CLOSED` and a fresh dial to `url` is refused.
- **In-process, ephemeral loopback (AC4).** `url` matches `ws://127.0.0.1:<port>`.
