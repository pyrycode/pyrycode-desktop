# #97 — Main-process test/dev-only affordance: accept + dial a loopback `ws://` relay, inert in packaged builds

**Shipped:** 2026-07-07 · **Size:** S · **Labels:** `enhancement`, `security-sensitive` (it widens the *single* relay-substitution defense, so it was audited in isolation — the reason it was split from #93). · **Scope:** one new module `src/main/relayPolicy.ts` (57 LOC) + its test (114 LOC), a ~30-LOC modify to `src/main/pairingPayload.ts`, a ~10-LOC modify to `src/main/index.ts`, and 5 new cases in `pairingPayload.test.ts`. **No renderer/preload change, no wire-type drift, no new dependency**; `relayConnection.ts` untouched.
**Spec:** `docs/specs/architecture/97-loopback-ws-relay-dev-affordance.md` · **PR:** [#98](https://github.com/pyrycode/pyrycode-desktop/pull/98). Split from [#93](https://github.com/pyrycode/pyrycode-desktop/issues/93); chain is **#97 → #93 (pair→connected through the UI) → #94 (send/stream)**.

Delivers a deterministic gate that relaxes the relay policy to a loopback `ws://127.0.0.1` relay **only** on the non-packaged, explicitly-opted-in dev path, so the [#90 in-process fake relay forwarder](../features/fake-relay-forwarder.md) can stand in for the live `wss://` relay in automated scenarios — while a packaged build's relay validation and dial stay **byte-identical to today**. See the [loopback relay dev affordance feature doc](../features/loopback-relay-affordance.md) for the evergreen contract, and the [pairing-payload gate doc](../features/pairing-payload-gate.md) (updated) for how the gate now delegates its scheme+host decision.

## Design in one paragraph

One idea, expressed as **dependency injection**: the scheme+host decision — the *only* part a test/dev affordance may relax — becomes a pure `RelayPolicy` function injected into `parsePairingPayload`, defaulting to today's production behavior. The URL-parse and credentials checks are deliberately **not** part of the policy: they stay in `parsePairingPayload` and wrap the policy call, so they apply on both paths. The dev relaxation and the effectful *selector* live in a separate `relayPolicy.ts`, keeping `pairingPayload.ts` free of any dev/loopback/env code. The selector is `isPackaged`-**false-first** so a packaged build never even reads the env flag. The single effectful read of `app.isPackaged`/`process.env` happens once, at the composition root, producing an immutable policy closure — nothing async, nothing that could drift the packaged-build path from today's.

## Patterns established

- **Relax a security check by injecting a narrow, type-constrained policy — not by branching inside the gate.** The untrusted→trusted boundary stays the single `parsePairingPayload` function; the affordance doesn't scatter the check. The policy's reject arm is typed to exactly the two scheme/host reasons, so a policy *cannot* invent a novel reason or leak a field value (the type system enforces the "value-free reasons" property across the seam). This is the reusable shape for "make one sub-decision of a validator swappable without weakening the rest."
- **Quarantine the dev affordance in its own module; keep the production file dev-code-free.** `pairingPayload.ts` gains only the seam (the type + the default policy); every `ws:`/loopback/env word lives in `relayPolicy.ts`. A reviewer can confirm "the production gate has no dev path" by reading the gate's imports — the relaxation is *unimportable* from there (same "enforce a property by the import list" move as [#90](90.md)'s content-blindness).
- **`isPackaged`-false-first is the belt-and-suspenders "different fabric."** The "inert in a packaged build" guarantee is a **deterministic code gate** checked before any env is consulted — not a config convention, not a stochastic check. A packaged build is byte-identical to today *regardless of environment*, proven by a test that sets the flag AND `isPackaged: true` and asserts loopback is still rejected.
- **Single-source the effectful read at the composition root.** `app.isPackaged`/`process.env` are read in exactly one place (`index.ts`), passing plain values into `selectRelayPolicy` — which therefore unit-tests without stubbing Electron. Mirrors the existing renderer-URL idiom and the injected-seam posture across `src/main`.
- **Delegate to the default policy so the allowlist stays genuinely single-sourced.** `loopbackDevRelayPolicy` calls `productionRelayPolicy` and only *adds* the loopback acceptance; it never re-checks `RELAY_ALLOWLIST` itself, so the allowlist has exactly one reader. (This is why the spec's suggested `RELAY_ALLOWLIST` import into `relayPolicy.ts` turned out to be unused — see Lessons.)

## Lessons learned

*Lifted from the PR body's "Lessons learned" section.*

- **Delegation made the spec's `RELAY_ALLOWLIST` import unnecessary.** Because `loopbackDevRelayPolicy` delegates its scheme+host verdict to `productionRelayPolicy`, the dev policy never re-checks the allowlist — so the spec's suggested `RELAY_ALLOWLIST` import into `relayPolicy.ts` would have been an *unused* import. Dropped it rather than `void`-ing it: the allowlist stays single-sourced in `pairingPayload.ts` with exactly one reader.
- **WHATWG `URL` canonicalizes numeric IPv4 hosts, so an exact string match is correct — no dotted-quad parsing.** `ws://2130706433/`, `ws://0x7f000001/`, `ws://127.1/` all yield `hostname === '127.0.0.1'`, so `=== '127.0.0.1'` accepts those (genuinely loopback) while still rejecting `localhost` (a name) and `[::1]` (a different address, not normalized to `127.0.0.1`). The AC's "not `localhost`, not `::1`" falls out of exact-string matching for free.

## Testing

- **The seam, proven without the dev policy (`pairingPayload.test.ts`).** Default 2nd param rejects `ws://127.0.0.1:5555/…` with `relay-scheme-not-wss` (AC4a); an injected accept-all policy parses a loopback relay into the four fields; an injected reject policy surfaces its chosen reason; a non-URL relay is `relay-not-url` even under accept-all (url-parse runs before the policy); embedded userinfo is `relay-has-credentials` even under accept-loopback (AC2, credentials run after); the injected-policy call is in the console-spy sweep (log-free).
- **The affordance, through `selectRelayPolicy` (`relayPolicy.test.ts`).** Production-default (`{isPackaged:false, env:{}}`) rejects loopback `ws://`, accepts the prod `wss://` host (AC4a); affordance-on (`env:{[FLAG]:'1'}`) accepts `ws://127.0.0.1` on ports `1`/`5555`/`65535`, accepts the IPv4-canonical `ws://2130706433/`, rejects `localhost`/`[::1]`/`evil.example` (scheme-first) and `wss://evil.example/` (host-first) (AC2/AC4b); credentials + non-url still rejected via `parsePairingPayload` on the dev path; **packaged (`isPackaged:true`) rejects loopback even with the flag set** (AC4c); opt-in exact — `'0'`/`''`/`'true'`/`' 1'`/`'1 '`/unset all fall back to production.
- **Dial coverage not re-tested here** — `relayConnection.test.ts` already dials `ws://127.0.0.1:${port}` verbatim; the full dev-path pair→dial integration is #93's e2e.
