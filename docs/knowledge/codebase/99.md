# #99 — Main-process test/dev-only affordance: injectable keychain-free secret-encryption backend, inert in packaged builds

**Shipped:** 2026-07-07 · **Size:** S · **Labels:** `enhancement`, `security-sensitive` (it disables real OS-keychain encryption on a code path, so it was audited in isolation — the reason it was split from #93). · **Scope:** one new module `src/main/secretBackend.ts` (80 LOC) + its test (168 LOC), and a ~15-LOC modify to `src/main/index.ts`. **No renderer/preload change, no wire-type drift, no new dependency**; `secureStore.ts`, `electronSecretEncryption.ts`, and the persistence layer are untouched.
**Spec:** `docs/specs/architecture/99-keychain-free-secret-backend-dev-affordance.md` · **PR:** [#100](https://github.com/pyrycode/pyrycode-desktop/pull/100). Split from [#93](https://github.com/pyrycode/pyrycode-desktop/issues/93); chain is **#99 → #93 (pair→connected through the UI) → #94 (send/stream)**.

Delivers a deterministic gate that swaps the [secure store](../features/secure-store.md)'s `SecretEncryption` backend to a keychain-free one **only** on the non-packaged, explicitly-opted-in dev path, so the pair → device-key → connect path can run in a headless keychain-less environment (#93 consumes it) without `secureStore.set` failing closed — while a packaged build's secret backend stays **byte-identical to today** (the real fail-closed OS-keychain backend). This is the exact **twin of [#97](97.md)** for the secret chain: same false-first gate, same quarantined-module shape, same security posture. See the [secret-backend dev affordance feature doc](../features/secret-backend-affordance.md) for the evergreen contract, and the [secure store doc](../features/secure-store.md) (updated) for how the injected `encryption` seam is now chosen.

## Design in one paragraph

One idea, expressed as **dependency injection at a single choice point**, exactly mirroring #97. `SecretEncryption` is *already* an injected interface on `createSecureStore({ encryption, … })`, so — unlike #97, which had to add an injected param to `parsePairingPayload` — this ticket needs **no edit to any existing chain file**. It is purely additive: a new pure/synchronous `secretBackend.ts` owns the "which backend?" decision, and the composition root makes the one effectful `app.isPackaged` + `process.env` choice. The selector is `isPackaged`-**false-first**, so a packaged build never even reads the env flag. The real backend is **injected as an uncalled factory** (`real: () => SecretEncryption`), so `secretBackend.ts` never statically imports `electron` (which `electronSecretEncryption.ts` alone does) and the keychain-free dev path never even constructs the real backend. `secureStore.ts`'s fail-closed logic is untouched — the affordance only changes *which* `SecretEncryption` instance is injected on the one dev path.

## Patterns established

- **Swap a whole backend at an existing DI seam — no edit to the consumer.** Because `createSecureStore` already takes `encryption` as an injected interface, relaxing the fail-closed behavior on the dev path needs **zero** change to `secureStore.ts`, `electronSecretEncryption.ts`, or the persistence layer. The reusable move: when a security property is enforced by an injected collaborator (here, `SecretEncryption.isAvailable()` gating `set`), you relax it by *selecting a different collaborator at the composition root*, never by branching inside the gate. Contrast #97, which had to *add* the seam (`RelayPolicy`) first because the check was inline.
- **Inject the real backend as an uncalled factory to keep the selector Electron-free.** `electronSecretEncryption.ts` is the only module that imports `electron`; a static import into `secretBackend.ts` would drag `electron` into every unit test. Passing `real: () => SecretEncryption` **uncalled** both keeps the selector's tests in plain Node **and** means the real backend is never even constructed on the dev path — a property the test asserts directly (call-count `=== 0`). Same injected-seam posture as #97's `selectRelayPolicy`, applied to make the module test-loadable without a runtime.
- **`isPackaged`-false-first is the belt-and-suspenders "different fabric."** "Inert in a packaged build" is a **deterministic code gate** — `if (opts.isPackaged) return opts.real()` as the first statement — checked before any env is consulted, not a config convention. A packaged build's secret backend is byte-identical to today *regardless of environment*, pinned by a test that sets the flag AND `isPackaged: true` and asserts the real (fail-closed, `isAvailable() === false`) backend is still returned.
- **Single-source the effectful read + the env-flag name.** `app.isPackaged`/`process.env` are read in exactly one place (`index.ts`); the opt-in var name is a single exported const `TEST_SECRET_BACKEND_ENV_FLAG` so #93 sets the exact string with a one-edit rename cost. Mirrors #97's `LOOPBACK_RELAY_ENV_FLAG`.
- **A dev-only weak transform must not resemble the deliberately-rejected weak path.** The keychain-free backend is marker-byte + XOR (mirroring the `secureStore.test.ts` `fakeEncryption` idiom), a separate module reachable only through the gate — deliberately **not** the Linux `basic_text` fallback that `electronSecretEncryption` rejects. `basic_text` is dangerous because it *masquerades as available in production*; this backend is unreachable in any shipped build, so it carries the trade-off honestly instead of hiding it behind a "backend" that the real one has to defend against.

## Lessons learned

*Lifted from the PR body's "Lessons learned" section.*

- **The injected `real: () => SecretEncryption` factory is passed uncalled** so `secretBackend.ts` never statically imports `electron` (which `electronSecretEncryption.ts` alone does) — keeping the whole unit-test file runnable in plain Node, and letting a test assert the real factory is *not* invoked on the dev path.
- **When a test fake's factory carries a call-count, expose the returned sentinel object separately.** An identity probe written as `.toBe(real())` silently bumps the count. The test stores the `sentinel` once and asserts `.toBe(sentinel)`, so the call-count stays a clean measure of how many times the code-under-test actually constructed the real backend (`1` on production paths, `0` on the dev path).

## Testing

- **The selector, through `selectSecretEncryption` (`secretBackend.test.ts`).** Default (`{ isPackaged: false, env: {} }`) returns the exact injected `real()` sentinel, still `isAvailable() === false`, factory called once (AC4a); packaged + flag set returns the sentinel anyway (`isPackaged` wins, still fail-closed) (AC4c); unpackaged + flag returns a **different** backend with `isAvailable() === true` and the real factory **never invoked** (AC4b); opt-in is exact — `'0'`/`''`/`'true'`/`'yes'`/`' 1'`/`'1 '`/unset all fall back to the real sentinel.
- **The keychain-free backend round-trips byte-blind (AC4b, AC2).** `decrypt(encrypt(x))` deep-equals `x` for a non-trivial blob, an empty `Uint8Array(0)`, and a tricky `[0x00, 0x80, 0xFF, 0x7F]` blob; the ciphertext differs from the plaintext (a transform actually ran, raw plaintext is never stored). A separate case proves statelessness — a blob encrypted by one selection decrypts on an **independently-selected** backend.
- **End-to-end through the real consumer (AC2).** The affordance-on backend wired into `createSecureStore` with a `Map`-backed fake persistence: `set('device-key', secret)` then `get('device-key')` round-trips instead of throwing `EncryptionUnavailableError` — closing "reads back correctly within that run" against `secureStore` itself, not the backend alone.
- **Dev-path pair→connect integration not tested here** — that is #93's e2e, which sets `PYRY_TEST_SECRET_BACKEND=1` when driving the built app headless.
