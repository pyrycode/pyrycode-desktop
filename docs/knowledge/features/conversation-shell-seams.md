# Conversation shell — seams

The seams this screen exposes, both the ones a later ticket bound and the ones still open.

Part of [Conversation shell](conversation-shell.md); see that document for what the screen does, its edge cases and its links.

## Seams (bound + still open)

- **`onBack?: () => void`** — **bound in [#140](../codebase/140.md).** Optional, gated exactly like `onUnpaired?`; wired by the [paired shell](paired-shell.md) when this screen is mounted as its `thread` view, absent for a bare `<ConversationScreen />`. See [Back control](conversation-shell-chrome.md#back-control-140) above.
- **`MessageThread({ messages })`** — **bound in [#69](../codebase/69.md); unmounted (retired to dead-but-tested residue) in [#179](../codebase/179.md).** `ConversationScreen` fed this prop from `useSessionStore(selectMessages).map(toMessageViewModel)` from #69 through #178; #179 removed the mount and the read. `MessageThread` itself is untouched and still server-render-tested as a pure `Message[]`-in view, but nothing in production calls it.
- **`Composer`** — **bound in [#66](../codebase/66.md); echo retargeted in [#179](../codebase/179.md).** A thin controlled container: `useState` input, an `onChange`/`onKeyDown` on the `<textarea>`, and an `onClick` on the send button, all delegating to the pure `submitMessage` in `composerSend.ts` (submit mints a `message_id` for the wire command, and dispatches an optimistic `userText` echo into the timeline store since #179 — previously a `messageSent` action into the session store). The submit logic lives in its own `.ts` file (the pairing container/pure-logic split); `Composer` itself stayed in-file. Auto-grows to a five-line ceiling since [#1056](https://github.com/pyrycode/pyrycode-desktop/issues/1056) (`field-sizing: content` on `.composer__input`, no change to this container). See [Composer send](composer-send.md) and [Composer message box](conversation-shell-composer-message-box.md#the-box-grows-with-the-draft-to-a-five-line-ceiling-1056).
- **`UnpairControl`** — **bound in [#166](../codebase/166.md).** A screen-local confirm-phase container delegating its decision logic to the pure `runUnpair` in `unpairAction.ts`, the same pattern as `Composer`/`composerSend.ts`. See [Unpair control](conversation-shell-chrome.md#unpair-control-166) above.
- **`RepairPrompt` / `RepairControl`** — retired by #963; Re-pair now lives in `TopOverlay` with the existing `shouldOfferRepair` predicate. `TopOverlayControl` rechecks the current host at click time and delegates to `onRepairHost`; it never calls `runUnpair`. See [recovery routing](conversation-shell-composer-repair-button.md#click-time-host-routing).
- **`ConnectionBanner` / `ConnectionBannerControl` / `SavedTimelineNotice`** — retired by #2076. `TopOverlay` receives `connectionStatus`, visible host-qualified `savedMessages` and independent `loadingSavedMessages` inputs instead. One atomic polite Error pill combines these facts. See [connection feedback](conversation-shell-chrome.md#connection-banner-279).
- **`StatusRow({ onExpand })` / `StatusSheet({ onClose, children })`** — **shell landed in [#177](../codebase/177.md); the `children` seam bound its first section in [#72](../codebase/72.md); the headless data path in [#187](../codebase/187.md); the Model/Effort/YOLO render in [#188](../codebase/188.md); the Context window render in [#192](../codebase/192.md); the summary slot's first content in [#330](../codebase/330.md); `StatusRow` retired in [#962](https://github.com/pyrycode/pyrycode-desktop/issues/962).** `StatusSheet` itself is untouched and still renders `<RunConfigData/>` (holds data, no markup), then `<RunConfigSections/>` (all four read-only sections, reading the store #187/#192 populate), then `<LogDataSection/>` — the full read-only surface the sheet needed. Only the trigger changed: `StatusRow` and the two-dot connection indicator it hosted (#330) are deleted, and the sheet now opens from the thread overflow menu's `Run configuration` item instead. See [Run configuration sheet](conversation-shell-run-configuration.md#run-configuration-sheet-177), [Run configuration data path](conversation-shell-run-configuration.md#run-configuration-data-path-187), [Run configuration Model/Effort/YOLO sections](conversation-shell-run-configuration.md#run-configuration-modeleffortyolo-sections-188), [Run configuration Context window section](conversation-shell-run-configuration.md#run-configuration-context-window-section-192), and [Run-configuration row and background-task trigger retired](conversation-shell-chrome.md#run-configuration-row-and-background-task-trigger-retired-overflow-menu-grows-to-three-items-962) above.
- **`ConnectionStatusIndicator({ relay, daemon })` / `ConnectionStatusIndicatorControl`** — **bound in [#330](../codebase/330.md); retired in [#962](https://github.com/pyrycode/pyrycode-desktop/issues/962).** `ConnectionStatusIndicator` was the exported pure view (both legs as props, matrix proven by direct server-render); `ConnectionStatusIndicatorControl` was the in-file container reading `useRelayLinkStore(selectRelayLinkStatus)` and `useSessionStore(selectStatus)`, mounted inside `StatusRow`'s summary slot. Both are deleted along with `StatusRow`; the leg-mapping functions they called (`relayLeg`/`daemonLeg`/`ConnectionLeg`) survive, exported for `channels/ChannelList.tsx`'s `HostConnectionDots` (#718), the app's only remaining two-dot connection surface. See [Two-dot Relay/Pyrycode connection-status leg mapping](conversation-shell-chrome.md#two-dot-relaypyrycode-connection-status-leg-mapping-330-its-render-retired-from-this-screen-by-962) above.
- **`ThreadOverflowMenuView({ open, onToggle, onSelectChannelInfo, onSelectRunConfiguration, onSelectBackgroundTasks, triggerRef })` / `ThreadOverflowMenu`** — **grown from one hardcoded item (`onSelect`, #276) to three required action props in [#962](https://github.com/pyrycode/pyrycode-desktop/issues/962).** The pure view maps a local `{ label, onSelect }[]` literal — `Channel info`, `Run configuration`, `Background tasks`, in that order — so the unit tier (which never fires a click, `renderToStaticMarkup` only) can still see the shipped copy and order; the container's single `select` became a factory shared by all three items. `onRunConfiguration`/`onBackgroundTasks` wire to `setSheetOpen(true)`/`setPanelOpen(true)` — exactly what the retired `StatusRow`/`BackgroundTaskTrigger` called from their own mounts. See [Run-configuration row and background-task trigger retired](conversation-shell-chrome.md#run-configuration-row-and-background-task-trigger-retired-overflow-menu-grows-to-three-items-962) above.
- **`ThreadItemsTimeline({ snapshot, ... })` / `TimelineRow`** — production uses supplied daemon items through the [thread runtime](thread-runtime.md). `ThreadItemsView` adapts supplied order, ancestry and activity into shared rows; exported `TimelineRow` also supports direct static assertions. The legacy `Timeline({ items })` and its numeric presentation bookkeeping were deleted in #2023. See [supplied item presentation](conversation-shell-timeline-render.md#supplied-daemon-item-presentation).
- **`ThinkingIndicator({ state, toolName, retry, ... })`** — shared working/status view, now supplied by the [thread runtime](thread-runtime.md)'s session-scoped live readings and local send state. It retains retry, compaction, stall/reset and tool naming independently of conversation row reconstruction. The legacy `Timeline` and its open-bubble inference no longer supply it. See [Thinking / working indicator](conversation-shell-working-indicator.md) and [turn status](conversation-shell-turn-status.md#session-scoped-live-presentation).
- **`ComposerStatusArea({ isRunning, children, trailing })`** — **bound in [#796](https://github.com/pyrycode/pyrycode-desktop/issues/796); gained the optional `trailing` slot in [#797](https://github.com/pyrycode/pyrycode-desktop/issues/797).** In-file `ConversationScreen.tsx` function; the container supplies `isRunning={isTurnRunning(phase)}`, mounts `<ThinkingIndicator/>` as `children`, and — since [#963](https://github.com/pyrycode/pyrycode-desktop/issues/963) (was `<ComposerErrorChipControl/>` through #797) — `<ComposerErrorSlotControl/>` as `trailing`, the row's own sibling slot rendered bare. See [Composer status row](conversation-shell-composer-status-row.md#composer-status-row-796) and [Actionable-error button](conversation-shell-composer-repair-button.md#actionable-error-button-and-the-row-that-grows-to-fit-it-963) above.
- **`ComposerErrorChip` / `ComposerErrorChipControl`** — retired; #2076 removed the view and chip-copy constants after connection feedback moved to `TopOverlay`. Shared error styling remains for other occupants. See [chip retirement](conversation-shell-composer-error-chip.md#composer-error-chip-797).
- **`ComposerErrorSlot({ status, recovery, refusal, notice, history, mcpFailure, taskCount })` / `ComposerErrorSlotControl`** — pure view plus store-bound container, mounted as `ComposerStatusArea`’s trailing slot. The view returns `recovery ?? refusal ?? notice ?? history ?? mcpFailure ?? taskCount ?? null` only while connected; all other statuses return `null`. It has no Reconnect or Re-pair callback. Both actions are owned by `TopOverlayControl`. See [current slot precedence](conversation-shell-composer-status.md#model-settings-rejection).
- **`StallIndicator({ isStalled })`** — **bound in [#317](../codebase/317.md); source moved to the open conversation's own slice in [#758](https://github.com/pyrycode/pyrycode-desktop/issues/758); retired, folded into `ThinkingIndicator`'s `state` union, in [#967](https://github.com/pyrycode/pyrycode-desktop/issues/967).** The symbol no longer exists; the seam it exposed (the `stalled` field, and the error-role colour a stall renders in) lives on inside `ThinkingIndicator`/`workingIndicatorState` below. See [Thinking / working indicator § Retired by #967](conversation-shell-working-indicator.md#thinking--working-indicator-215-held-for-the-whole-running-turn-since-648-tool-named-since-649-opens-on-send-since-650-folds-in-retry-compacting-and-stall-since-967-splits-the-local-send-window-into-sending-and-waiting-for-claude-since-1725) and [The open-conversation reader cutover](conversation-shell-actions-menu-and-reader-cutover.md#the-open-conversation-reader-cutover-758) above.
- **`ApiRetryIndicator({ retry })`** — **bound in [#493](../codebase/493.md); source moved to the open conversation's own slice in [#758](https://github.com/pyrycode/pyrycode-desktop/issues/758); retired, folded into `ThinkingIndicator`'s `state`/`retry` props, in [#967](https://github.com/pyrycode/pyrycode-desktop/issues/967).** The symbol no longer exists; the seam it exposed (the `apiRetry` field feeding both the supersede gate and the counter) lives on inside `ThinkingIndicator`/`workingIndicatorState` below. See [Thinking / working indicator § Retired by #967](conversation-shell-working-indicator.md#thinking--working-indicator-215-held-for-the-whole-running-turn-since-648-tool-named-since-649-opens-on-send-since-650-folds-in-retry-compacting-and-stall-since-967-splits-the-local-send-window-into-sending-and-waiting-for-claude-since-1725) and [The open-conversation reader cutover](conversation-shell-actions-menu-and-reader-cutover.md#the-open-conversation-reader-cutover-758) above.
- **`CompactingIndicator({ isCompacting })`** — **bound in [#496](../codebase/496.md); source moved to the open conversation's own slice in [#758](https://github.com/pyrycode/pyrycode-desktop/issues/758); retired, folded into `ThinkingIndicator`'s `state` union, in [#967](https://github.com/pyrycode/pyrycode-desktop/issues/967).** The symbol no longer exists; the seam it exposed (the `compacting` field feeding both the supersede gate and the label) lives on inside `ThinkingIndicator`/`workingIndicatorState` below. See [Thinking / working indicator § Retired by #967](conversation-shell-working-indicator.md#thinking--working-indicator-215-held-for-the-whole-running-turn-since-648-tool-named-since-649-opens-on-send-since-650-folds-in-retry-compacting-and-stall-since-967-splits-the-local-send-window-into-sending-and-waiting-for-claude-since-1725) and [The open-conversation reader cutover](conversation-shell-actions-menu-and-reader-cutover.md#the-open-conversation-reader-cutover-758) above.
- **`PermissionModal()`** — **bound in [#224](../codebase/224.md); made answerable in [#237](../codebase/237.md); gained a second-confirm gate in [#226](../codebase/226.md); gained a rejection surface in [#249](../codebase/249.md); its second-confirm marker was re-keyed from a bare option id to `{modalId, optionId}` in [#511](../codebase/511.md).** Reads the [modal store](modal-store-bridge.md)'s `selectOutstanding`, `selectRejections`, and `dispatch`, mounted as the last child of `.conversation`. `null` only when both the outstanding prompt and the rejection list are empty; the default option and Cancel dispatch a command and clear the prompt locally immediately, any other option holds pending a `Back`/`Confirm` sub-step first scoped to the prompt it was selected on, and a round-tripped rejection renders a dismissible banner independent of the prompt. See [Permission modal](conversation-shell-permission-modal.md#permission-modal-224-answerable-since-237-second-confirm-since-226-rejection-surface-since-249-confirm-marker-scoped-to-its-prompt-since-511) above.
- **`TimelineRow`'s `case 'sessionBoundary'`** — **bound in [#286](../codebase/286.md); redrawn as one hairline/label/hairline row and re-copied in [#690](https://github.com/pyrycode/pyrycode-desktop/issues/690).** Reads the fifth `ThreadItem` kind [thread timeline](thread-timeline.md) gained, deriving its label from the exhaustive `sessionBoundaryTitle(item)` in `sessionBoundaryViewModel.ts` — no `now` input since #690 dropped the row's relative time. See [Session-boundary delimiter](conversation-shell-session-and-channel-info.md#session-boundary-delimiter-286-redrawn-690) above.
- **Queued row actions** — `TimelineRow` retains `QueuedRowHandle` and the shared Cancel/Send now controls. `ThreadItemsView` derives handles from supplied queued user items; it does not read the queue store or call the deleted `foldQueuedRows`. See [queue authority](conversation-shell.md#what-it-does).
- **`ScreenSnapshotView({ snapshot, canRequest, onRequest })` / `ScreenSnapshotControl`** — **bound in [#324](../codebase/324.md); removed in [#618](../codebase/618.md).** Read `useSessionStore(selectStatus)` and the [screen-snapshot store](screen-snapshot-store.md)'s `selectScreenSnapshot`, and mounted between `StatusRow` and `InterruptControl`, until #618 took the view, its container and `requestScreenSnapshot.ts` out; the store itself was then deleted outright by [#619](../codebase/619.md). See [Screen-snapshot action & display](conversation-shell-conversation-and-modals.md#screen-snapshot-action--display-324-removed-618) above.
- **`WorkspacePickerSheetView({ workspaces, activeCwd, now?, onClose, onChoose?, onCreateFolder? })` /
  `WorkspacePickerSheet`** — **bound in [#383](../codebase/383.md); its `WorkspaceChip` entry point
  deleted outright, and the `WorkspacePickerSheet` container left dormant with no caller, in
  [#1486](https://github.com/pyrycode/pyrycode-desktop/issues/1486).** `WorkspacePickerSheetView` is the
  exported pure view and is still live: Settings' `DefaultWorkspaceRow.tsx` mounts it through its own
  container (`DefaultWorkspacePickerSheet`), not this one. `WorkspacePickerSheet` — the in-file container
  this bullet originally described, mounting `RecentWorkspacesData` (#382), reading
  `useRecentWorkspacesStore(selectRecentWorkspaces)`, deriving `activeCwd` from `activeConversationStore`,
  and supplying `onChoose`/`onCreateFolder` only for a non-null active conversation — has no caller left in
  `ConversationScreen`; `WorkspaceChip` and its `onChange={() => setPickerOpen(true)}` wiring are deleted,
  not merely unwired. See [Workspace Picker
  sheet](conversation-shell-workspace-chip-and-picker.md#workspace-picker-sheet-383) above.
- **`BackgroundTaskPanelView({ suppliedTasks, onClose, onStopTask?, turnRunning? })`** — requires a readonly supplied-task array; empty input retains an empty groups body. `ThreadItemsTimeline` supplies scoped task facts and raw Stop callbacks. The view owns capture Escape/IME/composer arbitration and listener cleanup. The roster-connected `BackgroundTaskPanel`, `entry`/finished/pending sets, agent default and roster reading/cap copy were removed in #2023; roster producers remain until #2024. The menu, count toggle and Close share shell-owned visibility. See [Background-task panel](conversation-shell-background-tasks.md).
- **`ChannelInfoSheetView({ conversation, now?, onClose })` / `ChannelInfoSheet`** — **shell + About detail bound in [#365](../codebase/365.md).** `ChannelInfoSheetView` is the exported pure view (`conversation` as a prop, sourced from `activeConversationStore`); `ChannelInfoSheet` is the in-file container owning only the Escape effect. The `ThreadOverflowMenu`'s `onChannelInfo` now calls `() => setChannelInfoOpen(true)` — the speculative `ConversationScreenProps.onChannelInfo?` prop #276 reserved is **retired**, not bound; see [Channel Info sheet](conversation-shell-session-and-channel-info.md#channel-info-sheet-365) above. **Rename bound in [#368](../codebase/368.md):** the `.channel-info__actions` slot's first filler, an `onRename?` prop supplied by the container only in the `conversation !== null` branch, opening the reused [Rename dialog](rename-conversation-dialog.md) (#360) — see [Channel Info sheet](conversation-shell-session-and-channel-info.md#channel-info-sheet-365) above. **Archive bound in [#366](../codebase/366.md):** the slot's second filler, an `onArchive?` prop under the same null-guard, dispatching the already-shipped [`archiveConversation` command](conversation-archive.md) (#363) then closing the sheet — see [Channel Info sheet](conversation-shell-session-and-channel-info.md#channel-info-sheet-365) above. **Delete bound in [#377](../codebase/377.md), completing the slot:** the third and final filler, gated the same way (`onDelete?` supplied only for a non-null active conversation) but dispatch is two-step — `onDelete` opens an inline confirm (a client-owned invention, no Figma node, the #226 second-confirm posture) that swaps in for the pill; confirming dispatches the already-shipped [`deleteConversation` command](conversation-delete.md) (#364) via a new `requestDeleteConversation` helper then closes the sheet, cancelling returns to the pill with no wire effect. The pill and confirm's destructive styling is a new `.channel-info__action--danger` modifier (error-tinted outline via `box-shadow: inset`, since desktop has no error-container fill token). `window.pyry` is dereferenced only inside the confirm handler; the confirm's own open state (`deleteConfirmOpen`) is screen-local `useState`, the `renameOpen` twin.
