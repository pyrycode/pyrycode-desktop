# #670 — Two-pane desktop shell with a fixed sidebar

**Size:** S — 3 production files, ~60 production lines, ~90 test lines.
**Security review:** not run — the ticket carries no `security-sensitive` label. PO's rationale (window
geometry touches no keys, sockets, or untrusted input; the `webPreferences` adjacency is handled by a
deterministic AC instead) is sound and consistent with the #204/#215 transport-vs-render precedent.

## Design source

**Figma:** https://www.figma.com/design/g2HIq2UyPhslEoHRokQmHG?node-id=102-4

A 1280×1024 frame laid out as one flex row (`Container` `103:2963`: `padding: 20px`, `gap: 20px`) over a
`#101418` backdrop — exactly `--color-surface`. Inside it, `Sidebar` `103:736` is `width: 400px;
flex-shrink: 0` holding the channels/chats trees, and `Chat` `103:2955` is `flex: 1 0 0; min-width: 0`
holding the thread and composer footer. Both panes are drawn as rounded cards with an `rgba(0,0,0,0.3)`

The geometry is self-checking: `20 + 400 + 20 + 820 + 20 = 1280`. The ticket's own "chat pane is 820 wide"
figure is only reachable *with* the outer gutter and the inter-pane gap, which is why they are in scope
here even though no AC names them.

## 1. Context

`PairedShellView` today is a five-arm switch in which `list` and `thread` are **mutually exclusive** — the
mobile design widened to fill a window. This slice makes them **simultaneous**, which is the foundation
every later ticket in the board-#7 series hangs off.

The whole change is a wrapper around two arms of an existing switch plus one Electron window option. There
is no transport, IPC, store, or wire change.

## 2. Design — the route model does not change

Keep `thread` a `PairedRoute` member and render the two-pane shell in **both** the `list` and `thread`
arms. Consequences, all of them free:

- `nextPairedRoute` and `pairedRoute.test.ts` are untouched. `open` still lands on `thread`, `back` still
  lands on `list`.
- The `settings` / `archive` / `pairServer` arms already return a full-screen `<section>` that replaces the
  whole shell — **AC5 costs zero production lines.**
- `PairedShellView`'s props signature is unchanged, so its 7 call sites (1 production, 6 in
  `PairedShell.test.tsx`) need no edit. There is no consumer cascade.
- `assertNever(props.route)` still narrows to `never`: combining `case 'list': case 'thread':` with no
  statement between them is not a fallthrough, and all five members remain handled.

The rejected alternative — collapse to one `shell` route and drive the pane off `activeConversationStore`
— would make `PairedShell` a store subscriber and forfeit the server-renderable invariant the file asserts
twice (`:39`, `:52`). Driving off the existing route gives up nothing.

**Element tree** (both arms return this; only the pane's child forks):

- `div.paired-shell`
  - `div.paired-shell__sidebar` → `<ChannelList onOpen onOpenSettings onOpenArchive />` (all three props
    forwarded exactly as the current `list` arm does)
  - `div.paired-shell__pane` → `<ConversationScreen onUnpaired onBack />` when `props.route === 'thread'`,
    otherwise `null`

Because both arms render the same element at the same position, React **preserves the `ChannelList`
subtree across the `list`↔`thread` flip**. That is safe and desirable: `ChannelList` is bound to
`useConversationListStore` (`ChannelList.tsx:43`), a live store subscription — it has no mount-time fetch
that a remount was refreshing. Its scroll position now survives selecting a conversation.

### AC4 — "empty" means *unmounted*

The pane renders `null`, never a mounted-but-blank `ConversationScreen`. Four e2e assertions use
`expect(page.locator('.conversation')).toHaveCount(0)` as their load-bearing "left the thread" proof
(`conversation-archive-lifecycle.spec.ts:112,174` and the real-daemon twin at `:127,192`); a mounted-blank
pane times out all four. `smoke.spec.ts:95` is the *unpaired* state and is unaffected.

"Never a stale thread" follows with no new code: `back` unmounts `ConversationScreen` (destroying its local
state), and `activateConversation` already clears the timeline and session id when the conversation id
changes (`activateConversation.ts:73-77`).

Per the operator's instruction, the pane is **genuinely empty** — no placeholder, illustration, or CTA. The
`div.paired-shell__pane` itself remains as the layout slot; only its children are absent.

## 3. Design — the stylesheet

New file `src/renderer/src/pairedShell.css`, imported bare at the top of `PairedShell.tsx` — the
co-location idiom (`ChannelList.tsx:1`, `ConversationScreen.tsx:13`). A CSS import is safe in the node-env
vitest run: `ChannelList.tsx` already does exactly this and `ChannelList.test.tsx` server-renders it.

```css
.paired-shell {
  display: flex;
  height: 100%;
  /* index.css sets no global box-sizing, so content-box would add the 40px of padding
     ON TOP of height:100% and overflow the window vertically. */
  box-sizing: border-box;
  gap: var(--space-5);      /* Figma Container 103:2963 gap-[20px] */
  padding: var(--space-5);  /* Figma Container 103:2963 p-[20px] */
  background: var(--color-surface);
}

.paired-shell__sidebar {
  flex: 0 0 400px;          /* Figma Sidebar 103:736 w-[400px] shrink-0 — AC2 */
  height: 100%;
}

.paired-shell__pane {
  flex: 1 1 0;              /* Figma Chat 103:2955 flex-[1_0_0] — absorbs remaining width */
  min-width: 0;             /* Figma Chat 103:2955 min-w-px: lets the pane shrink below its
                               content width instead of pushing the sidebar or overflowing */
  height: 100%;
}
```

`min-width: 0` on the pane is load-bearing, not defensive — the Figma sets it, and without it a wide
descendant (a long `<pre>`, an unbreakable tool-result line) would grow the flex item past its share and
break AC2. `height: 100%` on the two wrappers is belt-and-braces: a stretched flex item already has a
definite cross size, but stating it removes any doubt about `.channel-list`/`.conversation` resolving their
own `height: 100%`.

**No stylesheet outside this new file is edited.** In particular the three `position: fixed` overlay rules
(`channels.css:327`, `:524`, `conversation.css:2316`) stay as they are: `overflow` does not create a
containing block for fixed elements, so they still cover the whole window, which remains correct. The
sticky FAB and actions cluster still position against `.channel-list`'s own scroll box.

## 4. Design — the Electron window

Add `minWidth: 800` to the `BrowserWindow` options literal at `src/main/index.ts:36-49`, as a sibling of
`width`/`height`/`show`/`title`. **Do not touch the `webPreferences` block** — AC3 requires it byte-identical.
Do not add `minHeight`; the ticket specifies width only.

## 5. ⭐ The regression this ticket introduces — duplicate accessible names

Mounting both screens at once breaks **Playwright strict mode** at three sites. `conversation-create-rename.spec.ts:84-86`
states the invariant being destroyed in its own comment:

> "The list is unmounted while the thread + sheet are up, so no `.channel-list__rename` competes."

That is no longer true. On the `thread` route the sidebar is mounted, so:

| Site | Selector | Matches today | Matches after | Tier |
|---|---|---|---|---|
| `conversation-archive-lifecycle.spec.ts:106` | `getByRole('button', { name: 'Archive', exact: true })` | 1 (Channel-info sheet) | **2** — plus the always-mounted `ArchiveButton` (`ChannelList.tsx:186`) | default → goes red |
| `conversation-create-rename.spec.ts:87` | `getByRole('button', { name: 'Rename', exact: true })` | 1 (sheet pill) | **1 + N** — one `.channel-list__rename` per list row (`ChannelList.tsx:331`) | default → goes red |
| `real-daemon-conversation-lifecycle.spec.ts:120` | `getByRole('button', { name: 'Archive', exact: true })` | 1 | **2** | `real-*`, **skipped by default** → silent |

**Fix: scope each of the three to the pane**, e.g.
`page.locator('.conversation').getByRole('button', { name: 'Archive', exact: true })`. The Channel-info
sheet renders *inside* `ConversationScreen` (`conversation-archive-lifecycle.spec.ts:97-98`), so
`.conversation` is a valid scoping root. Also correct the now-false comment at
`conversation-create-rename.spec.ts:84-86`.

The third row is the dangerous one: it is a `real-*` spec, gated out of the default config, so it stays
green locally and only fails on `npm run e2e:real:gate`. **Fix all three in the same pass** — this is the
same silent-green compound that split #658.

The rest of the suite was swept and is clean. `'Archive'` (non-exact) at `paired-shell-navigation.spec.ts:78`
runs on the `list` route where the pane is empty → still 1 match. `'Settings'`, `'New discussion'`,
`'Delete'`, `'Confirm'`, `'Cancel'`, `'Close'`, `'Dismiss'`, `'Send'`, `'Unpair'`, `'Re-pair'`,
`'Change workspace'`, `'Run configuration'`, `'Stop the running turn'`, `'Drop queued message'` and the two
`switch` names have no cross-screen duplicate. `'Save as channel'` is selected by class, not role-name.

## 6. Deliberately not in this slice

**The pane card treatment** — the `rgba(0,0,0,0.3)` wash and rounded corners the Figma draws on both panes.
Two reasons, and they agree:

1. `.channel-list` and `.conversation` each paint `background: var(--color-surface)` on themselves, which
   is the *same* colour as the backdrop. A wash applied to the shell wrappers would be painted over and
   invisible; making it visible means deleting a declaration from each screen stylesheet.
2. That would put the ticket at **5 production files** (`PairedShell.tsx`, `pairedShell.css`,
   `main/index.ts`, `channels.css`, `conversation.css`) — the architect scope red line, forcing a split for
   a purely cosmetic gain.

The ticket's own Technical Notes assert "neither screen stylesheet should need touching"; this honours that.
The gutter and gap **are** built (§ 3) because the pane geometry depends on them; the visual differentiation
lands with the sidebar-tree and composer tickets, which own each pane's interior.

Also out: renaming `.conversation__back` or the `list`/`thread` route members; the sidebar's host/workspace
tree, status dots, and composer row; a sidebar Archive entry.

## 7. Error handling

None. This slice adds no failure mode: no async work, no I/O, no parsing, no new state. The only new
runtime branch is a ternary on an existing, exhaustively-typed route value.

## 8. Testing strategy

### Unit — `src/renderer/src/PairedShell.test.tsx` (`npm test`, node env, server-render only)

- **`route='thread'` — add `expect(markup).toContain(LIST_MARKER)`.** This is the AC1 proof: the sidebar is
  present *alongside* the thread. The existing `CONVERSATION_MARKER` / `BACK_MARKER` assertions still hold
  and stay.
- **`route='list'`** — the existing `not.toContain(CONVERSATION_MARKER)` becomes the unit-level AC4 proof
  (empty pane mounts no `ConversationScreen`). No change needed; update the comment to say so.
- **`route='settings'` / `'archive'` / `'pairServer'`** — the existing `not.toContain(LIST_MARKER)` and
  `not.toContain(CONVERSATION_MARKER)` assertions now carry **AC5** (full screen *over both panes*). No
  code change; update the comments to record the new meaning, so a future reader does not delete them as
  redundant.
- **`PairedShell` container** — "enters at the list view" is unchanged and still passes.

Layout cannot be asserted here: the node environment has no layout engine. Every geometric AC belongs in e2e.

### e2e — `npm run e2e`

Fold the AC2/AC3 assertions into the **existing single drive** in `e2e/paired-shell-navigation.spec.ts`
(destructure `{ page, app }`, not just `{ page }` — the fixture already returns `app` at
`launchPairedApp.ts:118`). Do **not** add a second `test()` block; that file's doctrine is one launch, and
each launch pays a full handshake.

Scenarios to add, at step 1 where the fixture has already landed on the thread:

- **AC1** — both panes at once: `.channel-list` and `.conversation` are each visible in the same assertion pass.
- **AC2** — `.paired-shell__sidebar` bounding box width is exactly `400`. Then resize via
  `app.evaluate(({ BrowserWindow }) => BrowserWindow.getAllWindows()[0].setSize(w, h))` to a second, wider
  size and assert `400` again, while the pane's width grows by the full delta. Poll the bounding box rather
  than reading it once — the resize is asynchronous.
- **AC3** — `app.evaluate(({ BrowserWindow }) => BrowserWindow.getAllWindows()[0].getMinimumSize())` returns
  a width of `800`.

Note: `boundingBox()` and `setSize`/`getMinimumSize` have **no precedent in this suite** — there is nothing
to copy. The `app.evaluate(({ BrowserWindow }) => …)` shape itself does exist, at
`window-reopen-converges.spec.ts:58` and `assistant-link-opens-externally.spec.ts:135`.

**Re-point the three assertions that go vacuous** — each asserts the list is visible immediately after a
back click, which is now always true and proves nothing. Replace with the real signal,
`expect(page.locator('.conversation')).toHaveCount(0)`:

- `e2e/paired-shell-navigation.spec.ts:55` (step 2, thread → list)
- `e2e/push-toggle-persist-relaunch.spec.ts:36`
- `e2e/thread-scroll-pin.spec.ts:428` — **this one is not merely cosmetic.** The assertion is used as an
  *unmount gate* before the spec re-enters the same row; its comment at `:424-426` says "Awaiting the list
  is the unmount gate — the thread's DOM node is gone once the list is on screen." Once the list is always
  visible that gate passes immediately, and the re-entry can race the unmount. Re-pointing restores the
  gate. Also correct the stale prose at `:424` ("a DIFFERENT component type at that same position"): the
  subtree is still destroyed, but now because the element becomes `null`, not because the type changes.

Plus the three strict-mode fixes in § 5.

Type coverage: `npm run typecheck` (both sides). Salvage/QA gate: `npm run build`.

## 9. Open questions

- **At the 800px minimum the chat pane is 340px wide** (`800 − 20 − 400 − 20 − 20`). `.conversation`'s
  composer sets `min-width: 0` (`conversation.css:1129`) and bubbles are `max-width`-bounded, so it should
  hold — but 340px is narrow for a thread. This is the arithmetic the ticket's own numbers produce; flagging
  it rather than changing either constant. If it reads badly in the running app, the fix is a follow-up
  ticket adjusting `minWidth`, not a deviation here.
- **Duplicate accessible names are now a live-UI a11y smell, not just a test problem.** A screen-reader user
  on the thread hears two "Archive" buttons (sidebar entry, thread action). The Figma moves the gear and
  archive glyphs to the sidebar's bottom rail, so the sidebar-chrome ticket is the right place to
  disambiguate. Out of scope here — noted so it is not lost.
