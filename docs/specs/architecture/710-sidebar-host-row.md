## Design

### 1. Placement — inside each existing gate, directly after the header

`renderBody` keeps its exact shape. One element joins each of the two `length > 0` blocks, between the `<header>` and the rows:

```tsx
{channels.length > 0 && (
  <>
    <header className="channel-list__section-header">Channels</header>
    <HostRow />
    {channels.map(…)}
  </>
)}
```

…and the identical insertion in the `discussions` block after `:270`. Nothing else in `renderBody` changes: the `conversations === null` early return, the all-empty guard, the three gates and the divider are untouched.

That placement satisfies AC1 and AC3 together, for free and by construction: the host row lives *inside* the gate that already decides whether a section label renders, so "a tree with zero rows renders neither" needs no new condition. **Do not hoist the row out of the gate** — an always-present host row is exactly what dissolves the promote specs' "a zero-row section renders no header" proof.

The component is module-local and nullary:

```tsx
function HostRow(): JSX.Element
// <div class="channel-list__host">
//   <svg class="channel-list__host-icon" aria-hidden="true" …/>
//   <span class="channel-list__host-label">{HOST_ROW_LABEL}</span>
// </div>
```

Not exported (the `SettingsButton` / `ArchiveButton` posture) — it is proven through `ChannelListView`, not directly. Not interactive: a plain `<div>`, no `<button>`, no `onClick`, no `aria-label`. Collapse is #704's ticket; nothing here is clickable yet.

### 2. The two selector hazards — what actually decides the class name

AC4 and AC5 are one failure mode at two blast radii. Playwright runs locators in strict mode, so an added element that *joins an existing locator's match set* raises a strict-mode violation rather than an assertion failure — a different, louder, harder-to-read error, and in AC5's case one that fires at fixture launch across 28 specs (`launchPairedApp.ts:224` clicks an unfiltered `.channel-list__row-open`). This is not hypothetical: `save-as-channel-promote.spec.ts:16` records that a two-row seed already trips exactly this.

Both are closed by construction, and the guards are independent:

**Class-token guard.** CSS/Playwright class selectors match whole class *tokens*, not substrings. `channel-list__host` shares no token with any existing selector in the file: `channel-list__row`, `__row-open`, `__save`, `__rename`, `__title`, `__time`, `__section-header`, `__divider`, `__archive`, `__settings`, `__fab`, `__empty`. It also shares no *substring* with `channel-list__row`, so even a hypothetical `[class*="channel-list__row"]` selector misses it. The child classes `__host-icon` / `__host-label` inherit the same property.

**Text guard.** The visible label must contain neither "Channels" nor "Chats" — `hasText` with a string argument matches substrings, case-insensitively. `'Server'` (§ 3) contains neither, in either direction, case-folded. Independently, the row does not carry `channel-list__section-header`, so the promote specs' locators cannot reach it at all. Either guard alone closes AC4; both are free.

**Text-collision check (done, no action).** Several specs use `page.locator('.channel-list').getByText('<fixture title>', { exact: true })` under strict-checked matchers (`save-as-channel-promote.spec.ts:125,143,157,180`; `conversation-create-rename.spec.ts:63,112,115`; `conversation-state-fake.spec.ts:71,76`; `conversation-archive-lifecycle.spec.ts:190`). The word "Server" occurs **0×** in `e2e/` (grep, case-sensitive and -insensitive), so the new label collides with no fixture title, in neither direction.

**The invariant this ticket must leave standing:** `e2e/` is not edited. Not one file, not one comment. The existing default-tier suite passing unchanged *is* AC4 + AC5's proof. If implementing this makes an e2e edit look necessary, the class name or the label text is wrong — fix the new code, do not adjust the spec's locators.

### 3. The copy — `'Server'`, a module-level constant

```tsx
const HOST_ROW_LABEL = 'Server'
```

Module-level, alongside the component, with a comment naming it as the #688 placeholder.

**Why "Server" and not the daemon's identifier.** `serverInfoStore` exposes `{ serverId, relayUrl }` one import away, and `ServerRow.tsx:37` renders `serverId` in Settings. Do not wire that store in here. Settings is a details surface with a "Server" label beside the value; the sidebar row is a *name* slot, so an opaque identifier in it reads as the machine's name — precisely AC2's prohibition. No store, no IPC, no props: the row takes nothing.

**Why "Server" and not "Host".** The ticket leaves the word to the architect but forbids inventing a third. Both candidates are defensible; "Server" wins on user-facing consistency — it is already the app's own word for this machine in Settings (`SERVER_ROW_LABEL`, "Pair another server"), so a user reading "Server" in the sidebar and "Server" in Settings → Connection connects the two surfaces. "Host" would be a second user-visible word for one concept.

**Deliberate asymmetry, so review reads it as intentional:** the *structural* naming stays "host" — `HostRow`, `.channel-list__host`, `HOST_ROW_LABEL` — because the design and all three tickets that stack onto this level (#672 dots, #688 label, #703 workspace) call it the host. Class names are selectors, not copy. The one word the user sees is "Server".

### 5. Styles — `channels.css`, three rules

Append after the `.channel-list__section-header` rule, since that is the element it heads (keep the file's "read top-down as the list reads" order). Every value is a token; the only Figma value with no token is the icon's 12px box, which is structural component geometry (the `.channel-list__fab` 56px-square precedent).

| Selector | Property | Value | Source |
|---|---|---|---|
| `.channel-list__host` | `display` / `align-items` | `flex` / `center` | Figma row; centering the 12px glyph against the 20px line box replaces the design's `Row icon` wrapper frame, so no wrapper element is needed |
| | `gap` | `var(--space-3)` | Figma `gap: 12px` |
| | `padding` | `var(--space-1) var(--space-4)` | Figma `py-4 px-16`; the 16px left edge aligns the row with the section label and the conversation rows above/below it |
| `.channel-list__host-icon` | `display` | `block` | the `__save-icon` / `__fab-icon` idiom |
| | `flex` | `0 0 auto` | never shrink the glyph |
| | `color` | inherited (`currentColor` on the `<svg>`) | — |
| `.channel-list__host-label` | the four `--text-label-large-*` | size / line / tracking / weight | Figma M3 title-small is `14 / 20 / 0.1 / 500` — an **exact** match for the theme's label-large set (`tokens.css:89-92`). Same type as the section header |

No `border-radius` (the Figma's 6px corner has nothing to clip — no background, no hover state in this slice), no background, no hover, no focus rule: the row is not interactive.

### 6. State, concurrency, error handling

None. `HostRow` is a nullary pure function of nothing; `renderBody` stays a pure function of `(conversations, now, handlers)`. No store slice, no selector, no `useEffect`, no async work, no IPC, no new failure mode, no re-render seam (a component that reads nothing cannot re-render on its own). The label is a compile-time constant with no daemon provenance, so no escaping or length-bounding question arises — which is exactly why AC2 forbids the store wiring that would create one.

## Testing strategy

`npm test` (vitest) is the whole liveness proof; `npm run build` is the gate. New tests go in `ChannelList.test.tsx`, using its existing `render()` harness and `row()` fixture. The string-based harness is enough for all of it: `renderToStaticMarkup` emits no comment markers, so exact-substring counting is a precise structural assertion. Add one small local helper that counts occurrences of a needle in the markup — the three structural tests below all lean on it.

Scenarios to cover:

- **Both trees present, one host row each (AC1).** Two promoted + one non-promoted row → `class="channel-list__host"` occurs exactly **2×**, and `channel-list__host-icon` is present. This is the test that pins the deliberate repetition; a "deduplicated" implementation fails here at 1.
- **One tree present, one host row (AC1).** Channels-only, then discussions-only → exactly **1×** each.
- **Order within a tree (AC1).** In the both-trees markup, `indexOf('>Channels<')` < `indexOf('class="channel-list__host"')` < `indexOf('class="channel-list__row"')` — the row sits below the section label and above the conversation rows.
- **Empty and not-yet-loaded render no host row (AC3).** `render([])` and `render(null)` → `channel-list__host` occurs **0×**. Pair it with the already-covered "no section header" assertions at `:60-72`, which stay as they are.
- **Section labels stay singly selectable (AC4).** In the both-trees markup, `class="channel-list__section-header"` occurs exactly **2×** — the invariant #709's spec parked for this ticket (`709-chats-section-label.md:139`) — and the host label contains neither "Channels" nor "Chats" (assert on the rendered label, e.g. `>Server<`, plus a direct check that the label string is not a substring match of either header word).
- **Conversation-row queries match the same set as before (AC5).** With one row per tree: `class="channel-list__row"` occurs exactly **2×** and `class="channel-list__row-open"` exactly **2×** — the counts they had before this ticket. This is the unit-level mirror of the 28-spec fixture hazard.
- **Also run the default-tier e2e unchanged:** `npm run e2e`. Not a new spec — the *unchanged* suite going green is AC4 + AC5's real proof, in particular `save-as-channel-promote.spec.ts` (the two `hasText` header locators) and every spec riding `launchPairedApp`'s unfiltered row click. Zero files under `e2e/` may be edited.

No new e2e spec. No changes to `PairedShell.test.tsx` — its `ChannelList` renders with the store's initial `null`, so `renderBody` returns before any host row exists.
