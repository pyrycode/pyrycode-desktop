## Context

The wire's `StallPayload` has exactly one field, `conversation_id`, and the decoder already requires it as a string. The emit then deliberately throws it away, so `stallDetected` reaches the renderer as a nullary arm carrying nothing at all.

That drop encodes the single-active-conversation assumption the desktop sidebar retires: a chat must keep working while the operator looks at another one, and the list must show each chat's state (operator ruling, 2026-08-21). Phase landed in #724; liveness is this one.

Client-side only — no daemon work, no wire change, no new capability. `backgroundTaskStarted`, `queueState` and (since #724) `turnState` are the shape precedents.

### What makes this arm different from #724

`stallDetected` is the one arm whose doc comments turn the drop into a **security argument**: no token, key, raw frame or conversation content *can* ride an arm with no payload — true by construction, because there is no field to ride. Adding `conversationId` makes that argument false as written. It is not patched; it is replaced by the real one, which #724 has already written for `turnState` at `events.ts:119-124` — a daemon-asserted routing key is not untrusted text, plus what it may and may not be used for.

**Over-deletion is the stated risk.** Eight of this ticket's 22 bare-token sites are true and must survive. § The classification table is the authority.

## Design

Two production line edits. Everything else is prose and test fixtures.

### 1. The IPC arm — `src/shared/ipc/events.ts:132`

The arm gains one required field:

```ts
| { type: 'stallDetected'; conversationId: string }
```

**Required, never optional.** An optional routing key invites `?? activeConversation` fallbacks in later consumers, which is the exact misattribution this work exists to remove. Settled at #728's split; identical to #724's ruling.

### 2. The emit — `src/main/daemonConnection.ts:627`

The fresh literal gains one named copy from the already-decoded payload:

```ts
emitDaemonEvent(sink, {
  type: 'stallDetected',
  conversationId: inbound.stall.conversation_id
})
```

**By name, never `...inbound.stall`.** This is the house idiom at every emit in the file (`turn-state` `:615-619`, `api-retry` `:638-643`) and is what stops a decoder that later grows a field from smuggling it across IPC. snake→camel at the boundary, as everywhere else.

### 3. Where the id stops

`translateTimelineEvent` (`timelineBridge.ts:96-101`) keeps returning a fresh `{ type: 'stallDetected' }` — a filter + fresh literal, never a pass-through. `ThreadEvent.stallDetected` (`threadTimeline.ts:136`) stays nullary. The reducer is untouched.

**The seam gets a free deterministic guard, and it is already written.** `timelineBridge.test.ts:193` (`expect(translated).toEqual({ type: 'stallDetected' })`) fails on an extra own enumerable property, so a bridge that ever spread the event turns that line red. **Leaving `:193` alone IS the test for AC3.** Do not add a new test for it, and do not "update" it to match the widened arm — widening the arm does not make it a type error (`toEqual` is loosely typed), so it stays green or goes red purely on runtime behaviour. That is what makes it a real assertion rather than a restatement of the type.

### 4. Edge semantics are unchanged and must stay that way

Stall is onset-only. The transport holds no dedup and no timer state; the self-clear on next turn activity belongs to the reducer (#317). Adding a field must not tempt anyone into adding state at the emit.

## Security review

**Verdict:** PASS

**Findings:**

Walked in the order of `architect/security-review.md` § Categories.

- **[1. Trust boundaries]** No findings. Two boundaries are in play and this ticket adds neither. The untrusted→trusted one is `parseStallPayload` (`inboundMessage.ts:589-599`), a single named function that `requireString`s `conversation_id` and returns only that known field — unknown server keys are tolerated but not copied through, pinned independently by `inboundMessage.test.ts:1564`. The boundary is explicit and typed (`StallPayload`), not scattered. The second is main→renderer, and note the direction: this leg is **trusted→untrusted**, a *disclosure*, not a validation gap. What is disclosed is a conversation id — a class of value the renderer already receives on `turnState`, `queueState` and `backgroundTaskStarted`, so no new category of data reaches the web layer. Nothing flows renderer→main here. The copy is by name from a narrowed payload, never a spread, so a decoder that later grows a field cannot smuggle it across IPC.
- **[2. Tokens, secrets, credentials]** Not applicable — `conversationId` is a daemon-asserted routing identifier, not a credential. It grants nothing, is never compared against a secret (so the `timingSafeEqual` rule has no site here), is not generated by this code, and is not persisted. No storage, rotation, revocation or expiry surface is introduced.
- **[3. File / storage operations]** Not applicable — nothing here touches the filesystem, and the spec forbids the field ever being used as a path component, filename or cache key. That keeps the path-traversal and TOCTOU surfaces closed *by construction* rather than by a check that a later refactor could drop. No renderer-side web storage is written.
- **[4. Inter-process / Electron attack surface]** No findings. No new IPC channel, no new `contextBridge` API, no new `ipcMain.handle`/`on` — the field rides the existing `DAEMON_EVENT_CHANNEL`, whose payload type is pinned to `DaemonEvent` at `emitDaemonEvent.ts:22`, so no non-event payload can reach it. No `webPreferences`, navigation, `setWindowOpenHandler` or custom-protocol surface is touched, and no remote content is loaded. Process placement is unchanged and is the MUST-FIX category here: keys, socket and Noise handshake stay in main, and what crosses is one additional daemon-supplied string on an arm that already crosses. The destroyed-window guard (`emitDaemonEvent.ts:44`) covers this call site as it covers the other 31.
- **[5. Cryptographic primitives]** Not applicable — no randomness, no key material, no key/nonce lifecycle, no comparison against a secret, and no change to the Noise session or its framing. The field is read out of an already-authenticated, already-decrypted frame.
- **[6. Network & I/O]** Not applicable, with one thing checked rather than assumed. No socket, relay URL, TLS, timeout, backoff or `maxPayload` decision changes — the frame already carried this field on every occurrence and was already size-capped upstream, so the arm gains no unbounded input.
