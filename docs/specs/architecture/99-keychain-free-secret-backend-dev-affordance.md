## Context

Every long-lived secret the desktop client holds — the device static private key (#43), the paired-server record (#44) — funnels through one auditable surface: `createSecureStore` (`src/main/secureStore.ts`). Its `set()` is **fail-closed**: it throws `EncryptionUnavailableError` *before touching persistence* whenever the injected `SecretEncryption.isAvailable()` is false (`secureStore.ts:87`). The real backend, `electronSecretEncryption()`, reports available **only** when a real OS keychain is present, and explicitly treats the Linux `basic_text` fallback as unavailable. So in any keychain-less environment (headless CI, a runner with no unlocked keychain) every secret write fails closed.

Two mandatory writes on the pair → connect path hit this gate:
1. **Persisting the pasted pairing record** (`pairingHandler` → `pairingConfirmation` → `pairedServerStore` → `secureStore.set`). On the throw the handler returns `persist-failed`, `onPaired` never fires, `connection.reconnect()` never runs, and the window never routes to `.conversation`.
2. **Generating/persisting the device static keypair** on connect (`daemonConnection` → `deviceKeypair.ensure()` → `secureStore.set`), same gate.

For an automated scenario (#93, which consumes this ticket) to run the built app's main process in a headless keychain-less environment, `secureStore.set` must stop failing closed **only** on that test/dev path. `SecretEncryption` is **already an injected interface** (`createSecureStore({ encryption, … })`), so the seam fully exists — unlike #97 (which had to add an injected param to `parsePairingPayload`), this ticket needs **no edit to any existing chain file**. It is purely additive: one new quarantined module selects a keychain-free backend on the test/dev path, and the composition root makes the one effectful choice.

This is **security-sensitive**: the affordance disables real OS-keychain encryption on a code path. It is the twin of #97 for the secret chain, audited here in isolation, not tangled with #93's e2e plumbing. The property the security review must confirm is that it is **provably unreachable in a packaged build** — a deterministic code guarantee, not a config convention.

## Design

The relaxation is expressed as **dependency injection at a single choice point**, exactly mirroring #97. A new pure/synchronous module owns the "which `SecretEncryption` backend?" decision. The real backend is **injected as a lazily-constructed factory** so the module — and therefore its unit tests — never imports `electron`. The effectful inputs (`app.isPackaged`, `process.env`) are read **once**, at the composition root. `secureStore.ts`, `electronSecretEncryption.ts`, and the persistence layer are **untouched**.

### Module layout (1 new production file + 1 composition-root line)

| File | Change | Role |
|---|---|---|
| `src/main/secretBackend.ts` | **new** (~45 LOC) | Quarantines the affordance: the module-private `keychainFreeSecretEncryption()`, the exported `selectSecretEncryption(...)` selector, and the `TEST_SECRET_BACKEND_ENV_FLAG` const. Imports only the `SecretEncryption` **type** from `./secureStore` — **no `electron` import**, so it unit-tests in plain Node. |
| `src/main/index.ts` | **modify** (~3-4 LOC) | The effectful gate: pass `app.isPackaged`, `process.env`, and `electronSecretEncryption` (the factory, **uncalled**) into `selectSecretEncryption`; use the result as `createSecureStore`'s `encryption`. |

`secureStore.ts`, `electronSecretEncryption.ts`, `fileSecretPersistence.ts`, `pairedServerStore.ts`, `deviceKeypair.ts`, `pairingHandler.ts`: **no change**. The chosen backend flows into `createSecureStore` through the seam that already exists.

### Why inject the real backend as a factory (the Electron-free constraint)

`electronSecretEncryption.ts` is the only module that imports `electron` (`import { safeStorage } from 'electron'`). It is deliberately **not** unit-tested, because it needs the Electron runtime. If `secretBackend.ts` statically imported it, then importing `secretBackend.ts` from a vitest test would transitively load `electron` and fail. So the real backend **must** be injected, and `secretBackend.ts` must have no static import of it.

The injected shape is a **factory** `real: () => SecretEncryption`, not a constructed instance, so that on the affordance-on (dev) path the real backend is **never even constructed** (satisfying the ticket's "production branch does not eagerly force `electron` to load"). This also lets the unit test pass a fake factory and assert the real factory is **not called** on the dev path — a direct proof that selecting the fake backend does not touch the real one. `electronSecretEncryption` is already a `() => SecretEncryption` factory, so the composition root passes the bare reference with no wrapper and no cast.

### The selector + affordance (in `secretBackend.ts`)

Contract sketches (signatures + behavior; the developer writes the bodies):

```ts
/** Single-sourced opt-in flag name. #93 sets this exact var when driving the built app.
 *  Analog of #97's LOOPBACK_RELAY_ENV_FLAG. */
export const TEST_SECRET_BACKEND_ENV_FLAG = 'PYRY_TEST_SECRET_BACKEND'

/** Module-private — the affordance's guts are not importable elsewhere (mirrors
 *  loopbackDevRelayPolicy). A deterministic, reversible, byte-blind transform with
 *  isAvailable() === true. NOT crypto; NOT the Linux basic_text fallback. */
const keychainFreeSecretEncryption = (): SecretEncryption => /* … */

/** The deterministic, isPackaged-false-first gate. Returns the injected real backend on
 *  every path EXCEPT (!isPackaged && env flag === '1'), where it returns the keychain-free
 *  backend. When packaged, the env flag is NEVER read. */
export function selectSecretEncryption(opts: {
  isPackaged: boolean
  env: Record<string, string | undefined>
  real: () => SecretEncryption
}): SecretEncryption
```

Behavior of `selectSecretEncryption`, false-first (identical control-flow shape to `selectRelayPolicy`):
1. `if (opts.isPackaged) return opts.real()` — **the gate**: a packaged build never consults the env flag; its backend is byte-identical to today (AC3).
2. `if (opts.env[TEST_SECRET_BACKEND_ENV_FLAG] === '1') return keychainFreeSecretEncryption()` — the only path that selects the fake backend. Opt-in is **exact** `=== '1'`; an unset var, `''`, `'0'`, `'true'` all fall through.
3. `return opts.real()` — default/production for unpackaged-without-flag.

**The keychain-free backend contract** (`keychainFreeSecretEncryption`):
- `isAvailable()` → always `true`, so `secureStore.set` no longer fails closed (AC2).
- `encrypt(plaintext: Uint8Array)` → a **deterministic, reversible** transform returning a **fresh** `Uint8Array` whose bytes differ from the plaintext (never store raw plaintext — mirror the real backend, and read honestly). Mirror the `secureStore.test.ts` `fakeEncryption` idiom (a marker byte + a fixed XOR) — reuse the codebase's established shape.
- `decrypt(ciphertext: Uint8Array)` → the **exact inverse**, so any blob written earlier **in the same run** reads back byte-for-byte (AC2). Byte-blind: must round-trip empty input and arbitrary bytes (`0x00`, `0x80`, `0xFF`) with no text/encoding assumptions.
- **Stateless / pure** — no per-instance or module-level mutable state, so the round-trip does not depend on retaining one instance. It needs **no** format compatibility with the real backend: the backend is chosen once per run and the e2e run's `userData` is a fresh per-run directory, so no cross-backend blob is ever read. It carries **no** cryptographic strength and must **not** resemble or reuse the Linux `basic_text` path.

### The effectful gate (in `index.ts`)

The only place `app.isPackaged` / `process.env` are read for this decision, replacing the current `encryption: electronSecretEncryption()` at L108-111:

```ts
const secureStore = createSecureStore({
  encryption: selectSecretEncryption({
    isPackaged: app.isPackaged,
    env: process.env,                 // structurally satisfies Record<string, string | undefined>
    real: electronSecretEncryption    // the factory, uncalled — constructed only if selected
  }),
  persistence: fileSecretPersistence(join(app.getPath('userData'), 'secrets'))
})
```

`persistence` is unchanged. This mirrors the #97 `selectRelayPolicy({ isPackaged: app.isPackaged, env: process.env })` call at L154 and the `app.isPackaged ? … : process.env[…]` idiom at L56-61. `electronSecretEncryption` moves from being *called* here to being *passed*; its import stays.

### Data flow

**Dev path, affordance-on** (`!app.isPackaged` AND `PYRY_TEST_SECRET_BACKEND=1`):
```
selectSecretEncryption → keychainFreeSecretEncryption()   [isAvailable() === true]
  → createSecureStore({ encryption: <keychain-free> })
  → pairedServerStore.save / deviceKeypair.ensure → secureStore.set   [encrypts, persists — no throw]
  → onPaired fires → connection.reconnect → routes to .conversation
```

**Packaged (any env), or dev without the flag:**
```
selectSecretEncryption → real()  =  electronSecretEncryption()   [OS-keychain, fail-closed without a keychain]
  → byte-identical to today
```

## State + concurrency model

None introduced. `keychainFreeSecretEncryption` and `selectSecretEncryption` are pure and synchronous. `selectSecretEncryption` runs **once**, at composition time (inside the existing `app.whenReady().then(...)` callback that completes in one tick), producing the immutable `encryption` object captured by `secureStore`. No async, no timers, no listeners, no shared mutable state, no teardown. The keychain-free transform holds no state, so concurrent `set`/`get` on the store behave exactly as with the real backend.

## Error handling

- **Fail-closed contract unchanged for the real backend** (AC5). `selectSecretEncryption` returns `real()` on every path except the single dev-affordance path; the real backend's `isAvailable()` still gates `secureStore.set` closed without a keychain. The affordance does not edit, wrap, or weaken `secureStore.ts`'s fail-closed logic — it only changes *which* `SecretEncryption` instance is injected on the one dev path.
- **Fail-closed only bypassed intentionally, only on the dev path.** The keychain-free backend's `isAvailable() === true` is the deliberate mechanism that lets writes succeed headless. It is reachable **only** through the false-first gate; `secureStore`'s throw-before-persist behavior is otherwise untouched.
- **Log-free preserved** — no `console.*` added to any file. `secureStore.ts`'s log-free-by-construction property (no secret to stdout) is unchanged; `secretBackend.ts` logs nothing (selecting a backend is silent, exactly like `selectRelayPolicy`).
- **`decrypt` on a foreign/corrupt blob** — within an isolated per-run `userData` no foreign blob exists, but if the developer mirrors the `fakeEncryption` marker check, `decrypt` throws on a non-matching blob, which `secureStore.get` propagates (never masked as absence) — same contract as the real backend. This is optional; the load-bearing requirement is same-run round-trip.

## Testing strategy

`npm test` (vitest) + `npm run typecheck`. One new test file, `src/main/secretBackend.test.ts`, mirroring `relayPolicy.test.ts` (drive the affordance **through the exported `selectSecretEncryption`**, never the module-private `keychainFreeSecretEncryption`). Because `secretBackend.ts` imports no `electron`, the whole file runs in plain Node. Each scenario is one `it(...)`.

Use a trivial fake for the injected `real` factory — a `() => SecretEncryption` returning a sentinel object whose `isAvailable()` returns `false` (a stand-in for "the real keychain-less backend") and a call-count so tests can assert whether it was invoked. This keeps the test Electron-free and lets it prove identity (`selectSecretEncryption(...) === <the sentinel>` on production paths).

Scenarios (bullet-pointed inputs → expected behavior):

- **Default/production selection returns the real backend (AC4a)** — `selectSecretEncryption({ isPackaged: false, env: {}, real })` returns the exact `real()` sentinel (identity check), and the keychain-free backend was **not** constructed.
- **Packaged short-circuits before the flag (AC4c)** — `selectSecretEncryption({ isPackaged: true, env: { [TEST_SECRET_BACKEND_ENV_FLAG]: '1' }, real })` returns the `real()` sentinel even with the opt-in set, proving `isPackaged` wins and the packaged backend is byte-identical to today. Assert the returned backend's `isAvailable()` is the real one's (`false`), i.e. still fail-closed.
- **Affordance-on selects the keychain-free backend (AC4b)** — `selectSecretEncryption({ isPackaged: false, env: { [TEST_SECRET_BACKEND_ENV_FLAG]: '1' }, real })` returns a backend whose `isAvailable()` is `true` and is **not** the `real()` sentinel; the real factory was **not** invoked.
- **Keychain-free backend round-trips a byte payload (AC4b, AC2)** — on the affordance-on backend, `decrypt(encrypt(x)) deep-equals x` for a non-trivial blob, and the ciphertext (`encrypt(x)`) is **not** equal to `x` (a transform actually ran). Include an empty `Uint8Array(0)` and a tricky `[0x00, 0x80, 0xFF, 0x7F]` blob (byte-blindness, no encoding assumptions).
- **Opt-in is exact** — env values `'0'`, `''`, `'true'`, `'yes'`, `' 1'`, `'1 '`, and unset all return the `real()` sentinel (only the exact string `'1'` enables), mirroring `relayPolicy.test.ts`'s exact-opt-in test.
- **End-to-end through `createSecureStore` (optional, high-value)** — wire the affordance-on backend into `createSecureStore` with a `Map`-backed fake persistence (the `fakePersistence` shape in `secureStore.test.ts`) and assert `set('device-key', secret)` then `get('device-key')` round-trips, i.e. `secureStore.set` no longer throws `EncryptionUnavailableError` on the dev path. This closes AC2's "reads back correctly within that run" against the real consumer rather than the backend alone.

### Type-level (`npm run typecheck`)

- `selectSecretEncryption` returns `SecretEncryption`; `keychainFreeSecretEncryption` and the injected `real()` both satisfy the same interface — a backend cannot omit `isAvailable`/`encrypt`/`decrypt`.
- `electronSecretEncryption` (a `() => SecretEncryption`) structurally satisfies the `real: () => SecretEncryption` param, and `process.env` structurally satisfies `env: Record<string, string | undefined>` — both with no cast in `index.ts`.

## Open questions

- **Env flag name** — spec picks `PYRY_TEST_SECRET_BACKEND` (the ticket's suggestion; honest — it names exactly what it does). Single-sourced as `TEST_SECRET_BACKEND_ENV_FLAG` so a rename is one edit. **#93 must set this exact var** when driving the built app headless.
- **Module name** — `secretBackend.ts` (analog of `relayPolicy.ts`). If the developer prefers `secretEncryptionPolicy.ts` for closer symmetry with `relayPolicy.ts`, that's fine — the exported `selectSecretEncryption` + `TEST_SECRET_BACKEND_ENV_FLAG` are the load-bearing names.
- **Transform choice** — marker-byte + XOR (mirroring `secureStore.test.ts`) is the recommended default. Any self-consistent deterministic reversible transform is acceptable; identity is discouraged (storing raw plaintext reads as "no transform" and is less honest, though functionally harmless in an isolated per-run dir).

## Security review

**Verdict:** PASS

Adversarial re-read per the architect security-review pass (label: `security-sensitive`). The affordance disables real OS-keychain encryption on a code path, so it got the sharpest scrutiny; the load-bearing property is *provable unreachability in a packaged build*.

**Findings:**

- **[Trust boundaries]** No findings. The untrusted→trusted boundary — untrusted input flowing into a secret write — is unchanged; the affordance changes only *which* `SecretEncryption` implements the write, chosen at one composition-root point. The fail-closed decision still lives entirely in `secureStore.set` (untouched). The selection is a pure function of three explicit inputs; it holds no state and reads no ambient global itself (`app.isPackaged`/`process.env` are read only at the composition root and passed in).
- **[Packaged-build unreachability — the core property]** The affordance is bounded on **two independent axes**, both required: (1) `!app.isPackaged` — a deterministic code gate checked **false-first**, so a packaged build returns `real()` *before* the env flag is ever read (AC3); (2) explicit env opt-in `=== '1'`. Because the gate is `if (opts.isPackaged) return opts.real()` as the first statement, no environment variable — set to anything — can reach the keychain-free branch in a packaged build. This is a code guarantee, not a config convention (belt-and-suspenders "different fabric" — deterministic code, matching #97). The unit test AC4c pins it: packaged + flag-set still returns the real, fail-closed backend. **Residual risk:** on a developer machine that is both unpackaged AND has the flag set, secrets are written under a non-cryptographic reversible transform in that run's `userData`. But that path is dev-only, opt-in, and the e2e `userData` is an isolated per-run directory; it grants no capability in any shipped build. Acceptable.
- **[Fail-closed contract integrity]** No findings. `secureStore.ts`'s throw-before-persist logic is not edited, wrapped, or bypassed. On every path except the single dev-affordance path, `selectSecretEncryption` returns `real()`, whose `isAvailable()` still gates the store closed without a keychain. The keychain-free backend's `isAvailable() === true` is a property of a *separate, module-private* function selected only by the gate — it cannot alter the real backend's behavior on any other path (AC5).
- **[Secret-at-rest strength on the dev path]** Acknowledged and bounded. On the affordance-on path, secrets at rest are protected only by a reversible transform (no real strength). This is the intended, ticket-sanctioned trade for headless testability, and is confined to an unpackaged, opt-in, isolated-`userData` run. It deliberately does **not** reuse or resemble the Linux `basic_text` fallback (which the real backend rejects precisely because it *masquerades* as available in production); this is a distinct dev-only module reachable only through the gate, never in a shipped build.
- **[Electron attack surface]** No findings. The affordance adds no IPC channel, no `contextBridge` API, no preload/renderer/window change; it lives entirely in `src/main` (AC5). `app.isPackaged` and `process.env` are read only at the composition root. `secretBackend.ts` imports **no** `electron`, so it adds nothing to the main process's Electron surface beyond a pure function.
- **[Inter-process / process placement]** No findings. Keys, tokens, and ciphertext stay in the main process. The dev path changes only *how* a secret is encrypted at rest within main, never *where* the secret lives or whether it crosses to the renderer. Nothing leaks into the renderer, preload bridge, or wire types.
- **[Error messages, logs, telemetry]** No findings. No `console.*` added. `secureStore`'s log-free-by-construction property is preserved; the new module logs nothing (selecting a backend is silent). No secret — plaintext, ciphertext, or transform key — is ever named in a logged struct or thrown-error message.
- **[Cryptographic primitives]** N/A by design. The keychain-free backend is explicitly non-cryptographic and never selected in a packaged build. It touches only secret-at-rest encoding on the dev path; the Noise_IK session, the wire types, and the pairing gate are all upstream/orthogonal and unchanged. A wrong `server_static_pubkey` still fails the handshake closed regardless of which secret backend is selected.
- **[Concurrency]** N/A — all added code is pure and synchronous; `selectSecretEncryption` runs once at composition time producing an immutable object. The keychain-free transform is stateless, so no data race is possible across concurrent store operations. No async, timers, listeners, or shared mutable state introduced.
